# Agent Script implementation status

This note tracks the implementation of `arcweft-agent-script-final-2026-06-18.zip`.
It is implementation state, not the stable language specification.

## Current cut point

- `.awfagent` is represented as an Arcweft Agent dialect, not a separate line-command language.
- The syntax parser exposes `SourceDialect`, `ParseOptions`, `parse_document`, and `parse_fragment`.
- `SourceDialect::Agent` accepts top-level `agent` items and rejects raw top-level fallback, so legacy forms such as bare `observe` do not parse as Agent Script.
- `agent @agent.id name(...) effects { ... } { ... }` is preserved as `Item::Agent`.
- HIR preserves Agent controllers in `HirModule::agents()` as `HirAgent`.
- `arcweft-compiler` exposes `parse_agent_source_text` and `compile_agent_source`, which parse Agent dialect source and lower it through the shared HIR path.
- `arcweft-lang-sema` exposes `project_index`, including `ProjectSemanticIndex`, typed entity payload metadata, Agent intrinsic lowering tags, HIR-to-project-index projection for checked native sources, Agent action signatures projected from typed inline presentation image calls, and an Agent Prelude projection into `TypeCheckEnv`.
- `ProjectSemanticIndex::debug_queries` now feeds typed Agent debug paths into `TypeCheckEnv`: entries named `state.foo` or `observation.foo` make `state("foo")` / `observation("foo")` return `Probe<T>` using the registered query return type, so `Probe<T>.eq/ge/...` validates the compared value type instead of treating every registered debug path as untyped JSON.
- `TypeKind::Ref` now carries `EntityType`, preserving an entity family and optional payload type through project-index projection into `TypeCheckEnv`.
- The type checker now visits Agent item bodies and can check Agent Prelude calls such as `choose(@choice...)` against project-index entity types and declared Agent effects.
- Agent dialect headers preserve multiline contract-list forms such as `effects { ... }` as structured contract expressions instead of raw recovery expressions.
- Agent intrinsic typing includes `expect(condition, message?)`, `deny(condition, message?)`, `signal(ref) -> Probe<T>`, `metric(ref) -> Probe<T>`, `state_path(String) -> DebugStatePath`, `observation_path(String) -> ObservationFieldPath`, `state(DebugStatePath|String) -> Probe<T>` and `observation(ObservationFieldPath|String) -> Probe<T>` for project-registered debug paths, dynamic unregistered paths as `Probe<AgentValue>`, `diagnostics() -> Diagnostics`, `Diagnostics.has_error() -> Predicate`, `Probe<T>.eq/ne/gt/ge/lt/le(T) -> Predicate`, `exists(Probe<T>)`, `action_enabled(ActionTarget) -> Predicate`, `all(...)`, `any(...)`, bracket-list predicate forms such as `any([predicate, ...])`, `not(...)`, `wait(predicate, timeout=...) -> Result<Observation, WaitError>` with timeout required and literal `stable_frames`/`poll_frames` values required to be at least 1, `observe() -> Result<Observation, AgentError>`, `advance_text() -> Result<ActionResult, AgentError>`, `choose(Ref<ChoiceOption>) -> Result<ActionResult, AgentError>`, `choice_action(Ref<ChoiceOption>) -> ActionTarget`, `Observation.actions -> Vec<ActionTarget>`, `Observation.signals -> Map<AgentValue, AgentValue>`, `contains(...)` for typed sequences, `get(...)` for typed maps, `invoke(target, action, args?) -> Result<ActionResult, AgentError>` against project-index Agent action signatures with named payload parameter validation, including typed inline `image(... target=..., action/actions=...)` presentation actions, `viewport_point(x, y) -> ViewportPoint`, explicit `pointer.click(point, button=.primary) -> Result<ActionResult, AgentError>` requiring `agent.act.physical`, `capture(viewport|layer|object, ...) -> Result<CaptureRef, AgentError>`, `read_resource(String|uri=String) -> Result<AgentResource, AgentError>` with typed `uri`/`kind`/`mime_type`/`hash` field projection and nested `body.kind`/`body.json`/`body.text`/`body.base64`/`body.encoding` string projections plus typed `body.value` payload projection, `attach(CaptureRef|AgentResource)`, `checkpoint(String)`, `note(DisplayText)`, and `rag.query(String, roots=Vec<Ref<AnyEntity>>, graph_depth=..., limit=...) -> Result<RagContextPack, RagError>` with `RagContextPack.summary() -> DisplayText`. The protocol/runner representation now carries debug paths as `DebugStatePath` and `ObservationFieldPath` newtypes instead of raw `String` fields while preserving the existing flat JSON wire shape.
- `ActionTarget` field projection is typed for `id`, `target`, `action`, `kind`, and `enabled`. Runtime expression lowering now supports indexed sequence access such as `frame.actions[0]` through the core VM and pure evaluator, so Agent scripts can inspect observed action target fields instead of only comparing complete `ActionTarget` records with `contains(...)`.
- `Observation.objects -> Vec<ObservedObject>` is typed for visual-regression Agent scripts. `ObservedObject` exposes `id`, `parent_id`, `entity`, `layer`, `role`, `visible`, `enabled`, `text`, and `bbox`; `bbox` exposes `space`, `x`, `y`, `width`, and `height`. `Vec<ObservedObject>.require_role(String) -> Result<ObservedObject, AgentError>` is type-checked and evaluated by the core VM/pure evaluator, and `object(textbox.id)` is accepted as an object-scoped capture target. `ObserveRequest::default()` now includes objects so `let frame = try observe(); let textbox = try frame.objects.require_role("dialogue_textbox")` matches the package visual-regression sample without requiring an explicit `include_objects = true` argument.
- `arcweft-compiler` exposes `compile_agent_source_with_project`, which resolves `.awfagent` entity references against the module plus `ProjectSemanticIndex` and returns a `TypeCheckReport`.
- `arcweft-runtime-plan` can lower a typed single Agent controller body into the shared runtime-plan shape, and `arcweft-compiler` exposes `compile_agent_bundle_with_project` to produce an Agent controller `.awfb` data object with bytecode, embedded source, and `AgentArtifactManifest`. The compiler now lowers `#[budget(...)]` attributes into the manifest `AgentBudget`, including `timeout`, `steps`, `host_calls`, `observations`, `captures`, `rag_queries`, `stored_bytes`, and `context_bytes`; malformed or unknown budget entries fail compilation instead of silently falling back to defaults.
- `arcweft-agent-protocol` owns Agent controller contract modules for artifact manifests, stable IDs, predicates, host requests/responses, traces, and typed values. Large host request/response enum payloads are boxed so the Rust protocol API does not carry oversized enum variants while preserving the same serde JSON shape.
- `arcweft-debug-model` provides Sans-I/O debug events, chunks, embedding records, RAG query models, and debug sink boundaries.
- `arcweft-rag` provides deterministic exact vector ranking and reciprocal-rank fusion primitives.
- `arcweft-agent-runner` provides the `AgentSession` host boundary, deterministic runtime policy checks, bounded wait polling with stable-frame confirmation, debug event emission, and a RAG service boundary for controller host calls. It can now run Agent controller bytecode through the shared core bytecode VM, dispatch effect-form Agent calls such as `observe(...)`, `checkpoint(...)`, `attach(...)`, `advance_text()`, `choose(...)`, `invoke(...)`, explicit `pointer.click(...)`, `capture(...)`, `read_resource(...)`, and `rag.query(...)`, evaluate structured wait predicates including `Compare`, `Exists`, `ActionEnabled`, `DiagnosticsHasError`, `All`, `Any`, and `Not` against signal, metric, state-payload, observation-field, action-target, and diagnostic payload probes, and bridge Agent `HostTaskRequest::Custom` suspend/resume tasks back into the VM so expressions such as `let shot = capture(...)` can bind the returned capture record and continue execution. Observation VM payloads now include action target records, observed object records with bbox metadata, and signal maps so expressions such as `frame.actions.contains(choice_action(@choice...))`, `frame.objects.require_role("dialogue_textbox").bbox.width`, and `frame.signals.get(@signal...)` can execute against host observations. RAG host responses resume the VM with a structured context record that includes `summary`, `item_count`, `truncated`, and the raw JSON string so `note(context.summary())` executes without a secondary interpreter. Semantic actions use the `agent.act.semantic` runtime capability, physical pointer actions require the separate `agent.act.physical` runtime capability, and debug records require `debug.record`. Agent controller bundle runs now combine the artifact budget with the runtime default cap and CLI step cap, then enforce VM step, host-call, observation, capture-count, capture-byte, RAG-query, RAG-context-byte, and wait logical-timeout limits with structured `ControllerResourceBudgetExceeded` errors.
- `arcweft-agent-runner` validates decoded Agent controller bundle project bindings before starting the controller VM. `ProjectBindingMode::Strict` rejects a runtime `AgentSessionInfo.program_hash` mismatch, and `ProjectBindingMode::Compatible` compares each manifest `required_entities` entry against the runtime `AgentSessionInfo.project_entities` snapshot by public ID, kind, and type fingerprint. Mismatches return a typed `ProjectBindingMismatch` runner error before any host calls or debug events are emitted.
- `arcweft-bundle` can now encode `.awfb` bundles as `bundle_kind = agent_controller` with an embedded `AgentArtifactManifest`, while ordinary game bundles remain the default. The game `arcweft-runtime-host` bundle runner rejects Agent controller bundles instead of executing them as game bytecode.
- `arcweft-debug-sqlite` provides the rebuildable `SQLite`/FTS5 debug index, event sink adapter, Japanese lexical smoke coverage, little-endian f32 vector blob storage without unsafe casts, and typed Agent REPL cell persistence/readback through the `repl_cells` table.
- `arcw agent script check <file.awfagent>` validates Agent dialect parsing/HIR lowering without requiring the `native-capture` feature.
- `arcw agent script build <file.awfagent> --output <file.awfb>` compiles a single Agent controller through the typed project-index path and writes the shared `.awfb` bundle JSON with `bundle_kind = agent_controller` and the embedded `AgentArtifactManifest`. It does not create a separate Agent-only artifact container.
- `arcw agent script run <file.awfagent|file.awfb>` executes one Agent controller through `arcweft-agent-runner`. By default it uses the deterministic CLI session adapter; with `--native-source <file.arcw>` or `--profile <id>` under the `native-capture` feature, it uses the native game observation/capture/resource path as an `AgentSession`. Source input is compiled to the shared Agent `.awfb` bundle shape first; bundle input is decoded through `ArcweftBundle` and must carry `bundle_kind = agent_controller`. When source input is run against a native source/profile, the Agent compiler builds its `ProjectSemanticIndex` from the checked native HIR, so `.awfagent` references such as `@flow.opening` and `@signal.current_flow` resolve against the real project declarations instead of a CLI-only stub. CLI `--signal id=value` entries fill missing signal symbols for non-native sessions, but they do not overwrite typed signal declarations already present in the native project index. CLI `--state path=value` entries populate deterministic debug state payload values for `state("path")` probes in non-native sessions. CLI/native `--blob-dir <dir>` writes capture bytes under `blake3/<hex>` content-addressed paths and reports the stored byte count. Native observation signals are normalized from `@signal.id`/`@flow.id` surface spelling to Agent protocol keys and `Entity` values. Native Agent Script sessions keep the native runtime executor alive across observe/action/wait/capture/resource host calls. `choose(@choice...)` now dispatches as a semantic `SelectChoice` runtime input rather than a physical click fallback, and subsequent waits observe the advanced native runtime state. `advance_text()` now lowers to `AgentAction::AdvanceText`; the native session converts it to an `advance` runtime input only when the latest observation exposes an enabled semantic `AdvanceText` target. `invoke(target, action, args?)` now lowers to `AgentAction::Invoke`; the native session requires a matching enabled semantic `Invoke` action target from the latest observation and dispatches an `invoke` runtime input with the action id, preserving semantic action dispatch without falling back to coordinates. `--trace-out <file.arcwx>` writes a JSON `AgentTraceRecord` stream derived from the runner debug events, with deterministic `blake3:` payload hashes, explicit run/session IDs, `resource_read_completed` records for `read_resource(...)` responses, and capture `blob_refs` copied from `CaptureResult.content_hash`.
- Agent statement-form Prelude calls lower through runtime-evaluated Agent host tasks when they appear as standalone statements or as the final agent body expression. `expect(condition, message?)` and `deny(condition, message?)` therefore receive the VM-evaluated `bool` condition instead of a stringified expression label. The shared runner emits `DebugEventKind::Assertion`, CLI traces map it to `assertion_evaluated`, and failing assertions return a structured `AgentRunError::AssertionFailed` after recording `{ kind, condition, passed, message }`.
- Shared Agent wait evaluation now handles `Predicate::ActionEnabled` against observed action targets, matching the native MCP wait path instead of treating the protocol variant as an always-false stub.
- `arcw agent script trace <file.arcwx>` reads a trace through the shared `AgentTraceRecord` protocol type and validates the `.arcwx` extension, JSON shape, schema version, payload hash, run-id consistency, first/last record kinds, strictly increasing sequence numbers, and capture-record blob refs. With `--blob-dir <dir>`, it also validates byte-backed capture blobs by resolving each capture `content_hash` to `blake3/<hex>`, recomputing the stored bytes' hash, and comparing the stored byte length with the trace payload. It is a read-only validation surface for future replay/MCP trace resources, not a second runner.
- `arcw agent script replay <file.arcwx> [--expect <file.arcwx>]` performs read-only logical replay of validated trace records. The replay sequence records each event's sequence number, kind, tick, payload hash, and blob refs. `--expect` compares two traces by replay-relevant logical fields rather than byte-for-byte file identity, so it can verify that source-run and bundle-run traces produce the same logical sequence.
- `arcweft-agent-runner::ReplayAgentSession` is the Sans I/O read-only `AgentSession` for validated trace records. It replays recorded observation/action/capture/resource-read host responses in trace order, rejects out-of-order controller requests, and leaves file loading/hash validation to CLI/tooling.
- `arcweft-agent-protocol` and `arcweft-agent-mcp` now expose Agent trace resources as typed MCP-compatible resources. `AgentResourceKind::Trace` plus `arcweft_agent_mcp::trace_resource` map validated `AgentTraceRecord` arrays to `arcweft://run/{run_id}/trace.arcwx` with `application/vnd.arcweft.agent-trace+json`, and `resources/templates/list` includes the trace URI pattern.
- `arcw agent mcp` exposes `arcweft.trace.read` in the stdio MCP transport. It validates a `.arcwx` file through the same trace reader used by CLI replay, caches the resulting trace resource in the current MCP session, and serves it through `resources/list`, direct MCP `resources/read`, and privacy-gated `arcweft.resource.read` without requiring a prior native observation. The MCP resource list also exposes `arcweft://session/{session_id}/context.json` as a path-redacted JSON session context resource for the latest observation, cached captures, trace resources, and cached RAG query state; trace-only sessions use `arcweft://session/mcp/context.json`. `arcweft.resource.read` accepts `max_privacy`, defaults to `project`, treats image/capture blobs as `sensitive`, treats the session context as `project`, and derives trace JSON privacy from explicit record privacy fields when present.
- `arcw agent mcp` exposes `arcweft.action` for enabled semantic Agent actions from the latest native observation, or after observing a supplied `source`/`profile` first. It keeps the native runtime executor alive across observe/action calls, dispatches `AdvanceText`, `SelectChoice`, and `Invoke` through semantic runtime inputs, accepts optional JSON object `args` for direct invoke calls, and returns accepted before/after ticks and state hashes plus the post-action frame summary. It does not synthesize physical pointer actions.
- `arcw agent mcp` exposes `arcweft.wait` for typed Agent protocol predicates against the active native runtime session, or after observing a supplied `source`/`profile` first. It steps the retained runtime by `poll_frames`, evaluates `Compare`, `Exists`, `All`, `Any`, `Not`, and observed action-enabled predicates against signals, metrics, state/report JSON, and observation fields, requires a logical `timeout_millis`, and returns the matching observation summary or a structured tool error on timeout.
- `arcw agent mcp` exposes `arcweft.script.run`, which calls the shared Agent Script runner for `.awfagent` sources or `.awfb` Agent controller bundles instead of embedding a second script interpreter in the MCP server. It accepts deterministic CLI-session `signals` and `state` JSON object arguments, native runtime `values`, and the same executor/pure/math/native stepping arguments as `arcw agent script run`, using the existing CLI parsers for typed values rather than a transport-local parser. It returns the same structured run report as `arcw agent script run`, including host calls, final status, trace output, blob write counts, and host responses.
- `arcw agent mcp` exposes read-only debug tools `arcweft.get_state`, `arcweft.signal_get`, and `arcweft.log_query`. They read the latest cached Agent observation, or run `arcweft.observe` first when `source` or `profile` arguments are supplied, and return structured JSON text blocks without mutating runtime state. Observation-derived state, signal, and log reads are treated as `project` privacy by default and enforce optional `max_privacy` before returning payload data.
- `arcw agent mcp` exposes read-only `arcweft.rag.query`, `arcweft.rag.explain`, and `arcweft.rag.context.read`. `arcweft.rag.query` builds an explainable `RagContextPack` from cached observation state/actions/objects/signals/metrics/logs/diagnostics, cached `.arcwx` trace records, and source/project chunks. It can observe a supplied `source`/`profile` first; a supplied `source` is also parsed/lowered into source/project RAG chunks, while `sources` accepts a string or array of `.arcw` files/directories to index without observing. Directory inputs recursively expand to `.arcw` files in deterministic path order. The query ranks candidates with deterministic reciprocal-rank fusion from `arcweft-rag`, preserves `roots`, `graph_depth`, `limit`, `max_context_bytes`, `max_privacy`, channels, chunk IDs, and context item bodies in the returned JSON, and caches the pack in the MCP session. RAG candidates above `max_privacy` are filtered before ranking; observation-derived candidates default to `project`, source/project chunks default to `project`, and trace records can override that with `privacy_class` or `privacy` fields at the record or nested payload level. When `path` is supplied, `arcweft.rag.query` also upserts MCP-derived context chunks into the debug SQLite store and records the selected `RagContextPack` through `rag_queries`/`rag_query_hits`; persisted source chunks are then visible to `arcweft.debug.search`. `arcweft.rag.explain` returns cached query/item metadata without inlining large bodies, and falls back to a debug SQLite audit readback by `query_id` plus optional `path` when the query is not cached. `arcweft.rag.context.read` reads one selected cached or persisted context item by `chunk_id` under an explicit byte cap, with persisted rows re-filtered against `chunks.privacy_class` before query-limit and byte-limit application. `arcw debug db rag --query-id <id>` exposes the same persisted audit readback to CLI clients, reconstructing the stored `RagContextPack` with the requested `max_privacy`.
- `arcweft-debug-sqlite` now records and reconstructs selected `RagContextPack` audits through the existing `rag_queries` and `rag_query_hits` tables. `record_rag_context_pack` stores query policy metadata and selected chunk/channel scores, while `rag_query_audit_with_max_privacy` joins back to `chunks`, rehydrates typed `RagQuery`/`RagContextItem` values, and applies privacy filtering before returning selected context.
- `arcw agent mcp` exposes read-only `arcweft.debug.search`, `arcweft.debug.script.runs`, `arcweft.debug.session.timeline`, and `arcweft.debug.repl.cells`. `arcweft.debug.search` opens the supplied rebuildable debug SQLite database path, or `.arcweft/cache/agent-debug.sqlite3` by default, accepts exactly one of `query`, `query_vector` with `model_id`/`model_revision`, `graph_query` with optional `graph_depth`, or `history_query`, dispatches through the shared `arcweft-debug-sqlite` lexical/vector/graph/history search APIs, applies `max_privacy` before channel-specific limiting/ranking, and returns chunk IDs, source metadata, privacy class, search channel, rank, score, title, and body without requiring a native observation or cached trace. `arcweft.debug.script.runs` reads `script_runs` lifecycle rows with optional `session_id` filtering and exposes Agent id, source hash, project binding mode, sequence range, trace URI, outcome, effectfulness, error, and metadata readback. `arcweft.debug.session.timeline` reads `debug_events` timeline rows with optional `session_id`/`run_id` filters and applies JSON payload privacy filtering before `limit`. `arcweft.debug.repl.cells` reads persisted `repl_cells` rows for one required `session_id`, exposing source hashes, status, display JSON, diagnostics, and effectfulness. `arcweft-debug-model` now owns the typed persisted `DebugSession` and `DebugScriptRun` lifecycle models, `arcweft-debug-sqlite` can upsert/read/list/finish `sessions` and `script_runs` rows through those models, `arcw debug db sessions` exposes recent product/debug sessions with profile, transport, lifecycle status, timing, program hash, and metadata readback, `arcw debug db runs [--session-id ID]` exposes persisted Agent controller runs with the same run lifecycle fields for CLI clients, and `arcw debug db timeline [--session-id ID] [--run-id ID]` exposes privacy-filtered persisted debug-event timelines for CLI clients.
- `attach(resource)` and `checkpoint(name)` execute through the same Agent host boundary as other controller effects and persist as debug-record timeline payloads when `arcw agent script run --debug-db` is supplied. `samples/agent-script/cli-attach-resource-smoke.awfagent` reads an `AgentResource`, attaches it, checkpoints after the attach, and `samples/agent-script/cli-attach-capture-smoke.awfagent` captures a `CaptureRef`, attaches it, and checkpoints after the attach. `arcw debug db timeline --session-id session.cli --run-id run.cli` can read those records back. This covers the `AgentResource` and `CaptureRef` debug-record paths without introducing a second debug-record evaluator.
- `arcw agent repl <file.arcw|--profile <id>> --input <session.txt> [--debug-db <path>] [--trace <file.arcwx> [--read-only]] --json` reads scripted cells from a file or stdin, keeps meta commands under the `:` namespace, uses the shared Agent fragment parser to classify non-meta cells, and delegates `:observe` / `:actions` to the native Agent observation/action-target surface. `:type EXPR`, `:ast EXPR_OR_STMT`, `:hir EXPR_OR_STMT`, and `:bytecode EXPR_OR_STMT` reuse the shared parser/compiler/type-check/runtime-plan/bytecode path for inspection rather than adding a REPL evaluator. `:capture [viewport|layer ID|object ID]` reuses the native observation image-capture path and returns the produced Agent image metadata plus resource summary. `:connect source PATH`, `:connect profile ID [--manifest PATH]`, and `:connect current` switch or restore the native observation target for later `:observe`/`:capture` cells; unsupported `stdio:`/`mcp:` remote endpoints fail explicitly instead of pretending to connect. `--trace <file.arcwx>` validates a saved trace through the shared `.arcwx` reader, caches it as the same Agent trace resource used by MCP, and exposes its resource descriptor and record count through `:trace`. `--read-only` requires `--trace`, rejects non-meta cells and target/session/binding mutation commands, and allows parser/compiler inspection, highlighting, `:history`, `:bindings`, `:trace`, and trace-backed `:query TEXT`. `arcweft-tooling::agent_repl` now provides Sans I/O cell completeness classification through the shared Agent fragment parser, including explicit expected boundary tokens for unclosed `(`, `[`, `{`, and string literals; it also provides completion candidates for Agent Prelude calls, named parameters, live REPL bindings, observed action targets, layer IDs, object IDs, effect capability names, and kind-filtered entity IDs such as `choose(@...)` returning only choice options. CLI `:classify SOURCE` and `:complete SOURCE_BEFORE_CURSOR` expose those same reports for scripted validation before a real terminal editor is wired in. The same module also exposes Sans I/O byte-range highlight tokens for meta commands, keywords, Prelude calls, entity IDs, effect selectors, literals, comments, punctuation, and lexical errors; CLI `:highlight SOURCE` returns those tokens for scripted validation. `:query TEXT` reuses the same observation/trace-derived `RagContextPack` builder as Agent MCP RAG query, while `:history` records prior REPL cell outcomes. `:drop NAME` removes a committed REPL binding, `:save FILE.awfagent` writes successful cell sources back as a normal Agent controller file that passes `agent script check`, and `:load FILE.awfagent` validates an Agent source through the shared compiler before registering it as a loaded binding. Non-meta cells are now compiled by wrapping the fragment in a one-cell Agent controller and running it through the existing `arcweft-compiler` plus `arcweft-agent-runner` deterministic CLI session path; successful cells are recorded as in-session `cell.N` binding artifacts visible through `:bindings`, and successful `let` statement cells expose VM-local binding names extracted from their parsed patterns as local binding artifacts tied to the executed cell. Serializable primitive/string/absolute entity-ref/bracket-sequence literal locals are stored with `serialized_source`; self-contained `observe(...)` and `read_resource(...)` let-bindings are stored as `observation` or `resource` snapshot expressions with original source and reintroduced as explicit `let` bindings before later cells. Unsupported snapshot values are rejected as snapshot escape errors instead of being committed or silently reused. When `--debug-db` is supplied, non-meta cells are persisted to SQLite `repl_cells` with typed readback through `arcweft-debug-sqlite`; failed runtime cells persist `partially_effectful` from actual host-call debug events instead of treating every runtime error as target-mutating. `arcw debug db repl-cells --session-id ID` exposes those persisted cell rows for CLI readback, including source hashes, status, display JSON, diagnostics, and effectfulness. This avoids faking REPL state with a second evaluator.
- `arcw agent repl --connect <target>` now seeds the same REPL target connection accepted by `:connect` before scripted input is evaluated. Startup `--connect` accepts `current`, `source PATH`, direct `.arcw` paths, and profile IDs; `stdio:`/`mcp:` endpoints continue to fail explicitly until a real retained remote REPL transport is implemented.
- Agent REPL `--debug-db` now closes its typed persisted `sessions` row as `finished` or `failed` after scripted input evaluation and records deterministic lifecycle metadata such as evaluated cell count, persisted cell count, read-only mode, final tick, and target connection.
- Agent REPL serializable local replay now covers self-contained `try rag.query(...)` bindings as `rag_context` snapshot expressions, so a later cell can reuse the context and call `context.summary()` without a second evaluator.
- Agent REPL snapshot boundaries now reject otherwise successful `let` cells when their newly exposed locals cannot be represented as supported snapshots. Those cells persist as failed cells, retain `partially_effectful` when host calls already ran, and do not commit unsupported locals into later `:bindings`.
- `arcw agent rag query [--trace <file.arcwx>] [--source <file-or-dir> ...] --query <text>` exposes the same `RagContextPack` JSON shape for standalone CLI use. It validates traces through the shared `.arcwx` reader, chunks the trace summary and individual `AgentTraceRecord` payloads, parses and lowers source files into the Agent project semantic index, chunks source text with byte-range anchors, emits `symbol` chunks for project entities and debug queries, emits a `graph_summary` chunk for the project semantic summary, applies deterministic reciprocal-rank fusion from `arcweft-rag`, and supports `--root`, `--graph-depth`, `--limit`, `--max-context-bytes`, `--max-privacy`, `--debug-db`, and `--json`. At least one of `--trace` or `--source` is required, `--source` can be repeated or point at a directory, and trace/source/project context can be fused in one pack. The default `--max-privacy project` excludes `sensitive` and `secret` chunks from the selected context; `--max-privacy public` only returns records or chunks explicitly marked public. When `--debug-db <path>` is supplied, the command upserts trace-derived and source/project-derived chunks into the rebuildable debug SQLite store and records the selected `RagContextPack` through `rag_queries`/`rag_query_hits`, so later MCP `arcweft.rag.explain` / `arcweft.rag.context.read` and CLI `arcw debug db rag --query-id <id>` calls can read the query by `query_id`.
- `arcw debug db status|migrate` opens and migrates the rebuildable Agent debug `SQLite` database at `.arcweft/cache/agent-debug.sqlite3` by default and reports row counts for core Agent debug tables.
- `arcw debug db validate` runs SQLite integrity checks, foreign-key checks, capture-to-blob reference validation, and embedding vector blob length validation. With `--blob-dir <dir>`, it also validates indexed blob `relative_path` values against byte-backed files, rejecting unsafe paths, missing files, and byte-length mismatches. `arcw debug db reindex` rebuilds and optimizes the derived chunk FTS index. `arcw debug db vacuum` compacts the SQLite cache and reports page/freelist counts before and after the operation. `arcw debug db rag --query-id <id> [--max-privacy public|project|sensitive|secret]` reconstructs a persisted `RagContextPack` audit from `rag_queries` and `rag_query_hits`, reapplying chunk privacy filtering before returning selected context items. `arcw debug db timeline [--session-id ID] [--run-id ID] [--max-privacy public|project|sensitive|secret]` reads persisted `debug_events` timeline rows with JSON payload privacy filtering before `--limit`, mirroring `arcweft.debug.session.timeline`. `arcw debug db search --query <text> [--max-privacy public|project|sensitive|secret]` exposes the rebuildable debug index's literal FTS5 lexical search with privacy filtering inside the SQL query before `--limit` is applied. `arcw debug db search --query-vector <f32,...> --model-id <id> --model-revision <rev>` loads normalized stored embeddings for the matching model descriptor, filters chunks by `max_privacy` before ranking, and ranks candidates with deterministic cosine similarity through `arcweft-rag`'s pure vector ranker. ## Deliberate boundaries

- Agent Script reuses the existing expression, statement, block, attribute, contract/effect, and HIR lowering path.
- No transition layer for the old line-command syntax is present.
- `compile_agent_source` remains the parser/HIR-only entry point for lightweight syntax checks; `compile_agent_source_with_project` is the typed project-index entry point; `compile_agent_bundle_with_project` is the typed artifact entry point. Controller VM execution and host-call dispatch are owned by `arcweft-agent-runner`; the CLI native game adapter path currently supports observe, wait polling, capture, resource read, semantic `SelectChoice`, enabled-observation-gated `AdvanceText` including native Game-mode E2E validation, semantic `Invoke`, privacy-filtered standalone trace/source/project-backed CLI RAG query, privacy-filtered standalone debug DB lexical, stored-vector, graph expansion, history search, SQLite-backed REPL cell persistence, deterministic REPL observe/actions/query/history/bindings meta commands including VM-local binding extraction from parsed `let` patterns and serializable literal/observation/resource live-binding replay, read-only REPL trace loading/query through the same Agent trace resource path as MCP, compiler-backed deterministic REPL cell execution for complete Agent fragments, and MCP observe/action/wait/script-run/capture/resource/state/signal/log/debug-search/debug-session-timeline/trace/session-context/RAG-query/RAG-explain/RAG-context-read tools through the existing native Agent resource/runtime builders. MCP RAG query audit readback can now fall back to the debug SQLite store by `query_id` plus `path`; the remaining follow-up is a persisted product session model plus broader project indexing beyond single-source CLI indexing and MCP-derived observation/trace chunks.
- Agent source defaults such as omitted signature return type are preserved as syntax/HIR shape for later semantic/compiler resolution rather than being string-rewritten in the parser.
- `invoke` is checked as a semantic action contract on a typed project entity. It does not accept string target IDs, does not fall back to physical actions, and validates payload record keys and values against named project-index Agent action parameters.
- `arcweft-agent-contract-reference` was not added as a production crate. Its concepts were merged into `arcweft-agent-protocol` modules to avoid duplicate protocol surfaces.
- `arcweft-debug-model` and `arcweft-rag` are Sans-I/O crates. They do not open databases, read files, call embedding services, or inspect runtime state directly.
- `arcweft-agent-runner` executes typed host requests and can step Agent controller bytecode for both effect-form calls and suspended Agent host-call expressions. It bridges `agent` custom host tasks to the same `AgentHostRequest` boundary and resumes the VM with a typed record payload. `wait(...)` expression tasks and Agent statement-form `wait(predicate, timeout=...)` lower typed probe comparisons and boolean predicate combinators to structured predicate records and execute through the same host wait boundary as `capture(...)`.
- Parser dialect dispatch keeps Agent `wait(...)` as an intrinsic call expression even when it appears as a bare statement. Game dialect line-task `wait(...)` remains the legacy dialogue/runtime wait statement path.
- `arcweft-debug-sqlite` is the only new I/O crate in this slice. It owns `rusqlite`, lifecycle validation, derived index rebuild, and debug-store record deletion while keeping database access out of syntax, HIR, compiler, runner, protocol, debug-model, and RAG crates.
