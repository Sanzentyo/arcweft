# Agent Script implementation status

This note tracks the implementation of `arcweft-agent-script-final-2026-06-18.zip`.
It is implementation state, not the stable language specification.

## Current cut point

- `.awfagent` uses the same Arcweft grammar and parser as `.arcw`; the extension selects the Agent Script CLI workflow, not a source dialect.
- The syntax parser exposes the identity-preserving
  `parse_document_with_source` full-document entrypoint and `parse_fragment`;
  it has no raw-text full-document facade and no path- or extension-selected
  grammar mode.
- Agent source declares an ordinary zero-parameter `fn` plus an explicit `entry agent @entry.* { controller = function_name }`.
- HIR preserves the controller as an ordinary `HirFunction` and the role selection as `HirEntryDecl`; there is no Agent-specific top-level declaration family.
- Project compilation resolves and type-checks the exact `entry agent`, and `compile_agent_project_bundle` lowers only its accepted ordinary controller declaration.
- `arcweft-lang-sema` exposes `project_index`, including `ProjectSemanticIndex`, typed entity payload metadata, Agent intrinsic lowering tags, HIR-to-project-index projection for checked native sources, Agent action signatures projected from typed inline presentation image calls, and an Agent Prelude projection into `TypeCheckEnv`.
- `ProjectSemanticIndex::debug_queries` now feeds typed Agent debug paths into `TypeCheckEnv`: entries named `state.foo` or `observation.foo` make `state("foo")` / `observation("foo")` return `Probe<T>` using the registered query return type, so `Probe<T>.eq/ge/...` validates the compared value type instead of treating every registered debug path as untyped JSON.
- `TypeKind::Ref` now carries `EntityType`, preserving an entity family and optional payload type through project-index projection into `TypeCheckEnv`.
- Agent project entity references expose executable metadata fields for the
  parts that can be derived without a compatibility side table:
  `Ref<T>.id`, `Ref<T>.family`, and `Ref<T>.name` type-check as strings and
  evaluate from `RuntimeValue::EntityRef` in the shared core VM. Source must
  use ordinary field syntax such as `(@flow.opening).id`; `@flow.opening.id`
  remains a single entity id.
- The type checker visits ordinary function bodies selected by Agent entries and checks Agent Prelude calls such as `choose(@choice...)` against project-index entity types and the controller's declared effects.
- Ordinary function headers preserve multiline contract-list forms such as `effects { ... }` as structured contract expressions instead of raw recovery expressions.
- Agent intrinsic typing includes `expect(condition, message?)`, `deny(condition, message?)`, `signal(ref) -> Probe<T>`, `metric(ref) -> Probe<T>`, `state_path(String) -> DebugStatePath`, `observation_path(String) -> ObservationFieldPath`, `state(DebugStatePath|String) -> Probe<T>` and `observation(ObservationFieldPath|String) -> Probe<T>` for project-registered debug paths, dynamic unregistered paths as `Probe<AgentValue>`, `diagnostics() -> Diagnostics`, `Diagnostics.has_error() -> Predicate`, `Probe<T>.eq/ne/gt/ge/lt/le(T) -> Predicate`, `exists(Probe<T>)`, `action_enabled(ActionTarget) -> Predicate`, `all(...)`, `any(...)`, bracket-list predicate forms such as `any([predicate, ...])`, `not(...)`, `wait(predicate, timeout=...) -> Result<Observation, WaitError>` with timeout required and literal `stable_frames`/`poll_frames` values required to be at least 1, `observe() -> Result<Observation, AgentError>`, `advance_text() -> Result<ActionResult, AgentError>`, `choose(Ref<ChoiceOption>) -> Result<ActionResult, AgentError>`, `choice_action(Ref<ChoiceOption>) -> ActionTarget`, `Observation.actions -> Vec<ActionTarget>`, `Observation.signals -> Map<AgentValue, AgentValue>`, `contains(...)` for typed sequences, `get(...)` for typed maps, `invoke(target, action, args?) -> Result<ActionResult, AgentError>` against project-index Agent action signatures with named payload parameter validation, including typed inline `image(... target=..., action/actions=...)` presentation actions, `viewport_point(x, y) -> ViewportPoint`, explicit `pointer.click(point, button=.primary) -> Result<ActionResult, AgentError>` requiring `agent.act.physical`, `capture(viewport|layer|object, format=.png|.raw_rgba, ...) -> Result<CaptureRef, AgentError>`, `read_resource(String|uri=String) -> Result<AgentResource, AgentError>` with typed `uri`/`kind`/`mime_type`/`hash` field projection and nested `body.kind`/`body.json`/`body.text`/`body.base64`/`body.encoding` string projections plus typed `body.value` payload projection, `attach(CaptureRef|AgentResource)`, `checkpoint(String)`, `note(DisplayText)`, and `rag.query(String, roots=Vec<Ref<AnyEntity>>, graph_depth=..., limit=...) -> Result<RagContextPack, RagError>` with `RagContextPack.summary() -> DisplayText`. Agent Script capture is intentionally raster-only (`png` or `raw_rgba`); CLI overlay SVG remains the separate `agent observe --image overlay` debug surface. The protocol/runner representation now carries debug paths as `DebugStatePath` and `ObservationFieldPath` newtypes instead of raw `String` fields while preserving the existing flat JSON wire shape.
- `ActionTarget` field projection is typed for `id`, `target`, `action`, `kind`, and `enabled`; `action` now projects as the dedicated `ActionName` type while remaining comparable with action-name string literals. Runtime expression lowering now supports indexed sequence access such as `frame.actions[0]` through the core VM and pure evaluator, so Agent scripts can inspect observed action target fields instead of only comparing complete `ActionTarget` records with `contains(...)`.
- `Observation.objects -> Vec<ObservedObject>` is typed for visual-regression Agent scripts. `ObservedObject` exposes `id`, `parent_id`, `entity`, `layer`, `role`, `visible`, `enabled`, `text`, and `bbox`; `bbox` exposes `space`, `x`, `y`, `width`, and `height`. `Vec<ObservedObject>.require_role(String) -> Result<ObservedObject, AgentError>` is type-checked and evaluated by the core VM/pure evaluator, and `object(textbox.id)` is accepted as an object-scoped capture target. `ObserveRequest::default()` now includes objects so `let frame = try observe(); let textbox = try frame.objects.require_role("dialogue_textbox")` matches the package visual-regression sample without requiring an explicit `include_objects = true` argument.
- Standard project compilation resolves `.awfagent` entity references through the same checked project/HIR plus `ProjectSemanticIndex` path as `.arcw`.
- `arcweft-runtime-plan` lowers the exact ordinary controller selected by a checked Agent entry into the shared runtime-plan shape, and `arcweft-compiler::agent::compile_agent_project_bundle` produces an Agent controller `.awfb` data object with bytecode, embedded source, and `AgentArtifactManifest`. The compiler lowers `#[budget(...)]` only on the selected controller into the manifest `AgentBudget`, including `timeout`, `steps`, `host_calls`, `observations`, `captures`, `rag_queries`, `stored_bytes`, and `context_bytes`; malformed, unknown, or unbound budget entries fail compilation instead of silently falling back to defaults.
- `arcweft-agent-protocol` owns Agent controller contract modules for artifact manifests, stable IDs, predicates, host requests/responses, traces, and typed values. Large host request/response enum payloads are boxed so the Rust protocol API does not carry oversized enum variants while preserving the same serde JSON shape.
- `arcweft-debug-model` provides Sans-I/O debug events, chunks, embedding records, RAG query models, and debug sink boundaries.
- `arcweft-rag` provides deterministic exact vector ranking and reciprocal-rank fusion primitives.
- `arcweft-agent-runner` provides the `AgentSession` host boundary, deterministic runtime policy checks, bounded wait polling with stable-frame confirmation, debug event emission, and a RAG service boundary for controller host calls. It can now run Agent controller bytecode through the shared core bytecode VM, dispatch effect-form Agent calls such as `observe(...)`, `checkpoint(...)`, `attach(...)`, `advance_text()`, `choose(...)`, `invoke(...)`, explicit `pointer.click(...)`, `capture(...)`, `read_resource(...)`, and `rag.query(...)`, evaluate structured wait predicates including `Compare`, `Exists`, `ActionEnabled`, `DiagnosticsHasError`, `All`, `Any`, and `Not` against signal, metric, state-payload, observation-field, action-target, and diagnostic payload probes, and bridge Agent `HostTaskRequest::Custom` suspend/resume tasks back into the VM so expressions such as `let shot = capture(...)` can bind the returned capture record and continue execution. Observation VM payloads now include action target records, observed object records with bbox metadata, and signal maps so expressions such as `frame.actions.contains(choice_action(@choice...))`, `frame.objects.require_role("dialogue_textbox").bbox.width`, and `frame.signals.get(@signal...)` can execute against host observations. RAG host responses resume the VM with a structured context record that includes `summary`, `item_count`, `truncated`, and the raw JSON string so `note(context.summary())` executes without a secondary interpreter. Semantic actions use the `agent.act.semantic` runtime capability, physical pointer actions require the separate `agent.act.physical` runtime capability, and debug records require `debug.record`. Agent controller bundle runs now combine the artifact budget with the runtime default cap and CLI step cap, then enforce VM step, host-call, observation, capture-count, capture-byte, RAG-query, RAG-context-byte, and wait logical-timeout limits with structured `ControllerResourceBudgetExceeded` errors.
- `arcweft-agent-runner` validates decoded Agent controller bundle project bindings before starting the controller VM. `ProjectBindingMode::Strict` rejects a runtime `AgentSessionInfo.program_hash` mismatch, and `ProjectBindingMode::Compatible` compares each manifest `required_entities` entry against the runtime `AgentSessionInfo.project_entities` snapshot by public ID, kind, and semantic hash. Mismatches return a typed `ProjectBindingMismatch` runner error before any host calls or debug events are emitted.
- Agent artifact and session project-entity snapshots now carry optional typed
  source anchors for HIR-derived entities. `RequiredEntity.source_anchor`
  records the source path, byte range, and optional line/column positions when
  they are available; generated or remote entities keep this field empty rather
  than receiving a fake path. Compatible project binding intentionally does not
  reject on source-anchor differences, because source locations are
  debug/readback metadata while public id, kind, and semantic hash remain the
  runtime compatibility contract.
- Agent controllers can request project-index metadata through the typed
  `entity_meta(ref) -> Result<AgentEntityMetadata, AgentError>` Prelude
  intrinsic under the `debug.read` effect. The runner services this request from
  `AgentSessionInfo.project_entities`, returning `id`, exact `kind`,
  `semantic_hash`, and a typed `source` record with `has_source`, path, byte
  range, and optional line/column fields. The same `debug.read` boundary now
  exposes `project_neighbors(ref, depth = N)` as
  `Result<ProjectGraphNeighborhood, AgentError>` backed by
  `AgentSessionInfo.project_graph`, returning typed graph symbols and edges
  around the requested entity. `ProjectSemanticIndex` now also owns typed
  entity-to-entity relations for entry start/run/route targets, flow-contained
  dialogue and choice entities, choice-contained option entities, and
  choice-option goto targets. Static statement-level `goto @flow...` and
  `include @...` references are indexed as `flow_goto` and `flow_include`
  relations; static entity references in ordinary flow/fragment expressions,
  dialogue arguments, and choice option conditions/values/actions are indexed
  as `references_entity` data-dependency relations. Dynamic goto expressions
  are intentionally not projected as graph edges; instead, flow graph symbols
  expose typed `has_flow_control`, `has_dynamic_control`, and static/dynamic
  control counter fields through `project_neighbors(...)`. Those relations and
  counters are projected into both Agent Script
  `project_neighbors(...)` readback and CLI/RAG debug graph inventory. Project
  summary graph symbols and RAG summaries now expose domain-specific aggregate
  shape, including entity-kind counts, relation-kind counts, callable
  dependency edge-kind counts, Agent action counts, and aggregate flow-control
  counters, so product graph clients do not have to infer the project shape by
  re-scanning every individual graph symbol and edge. The Agent runtime
  project-graph protocol also carries typed project-summary counters on the
  `project_summary` symbol, and `project_neighbors(...)` exposes them through
  ordinary Agent Script fields such as `entity_count`, `relation_count`, and
  `dynamic_control_flow_count`.
  This keeps project-only metadata out of `RuntimeValue::EntityRef` and avoids
  deriving source, semantic hashes, or graph neighborhoods from entity-id
  strings.
- `arcweft-bundle` can now encode `.awfb` bundles as `bundle_kind = agent_controller` with an embedded `AgentArtifactManifest`, while ordinary game bundles remain the default. The game `arcweft-runtime-host` bundle runner rejects Agent controller bundles instead of executing them as game bytecode.
- `arcweft-debug-sqlite` provides the rebuildable `SQLite`/FTS5 debug index, event sink adapter, Japanese lexical smoke coverage, little-endian f32 vector blob storage without unsafe casts, and typed Agent REPL cell persistence/readback through the `repl_cells` table.
- `arcw agent script check <file.awfagent> [--controller-entry entry.agent.*]` validates canonical parsing, project HIR/sema, exact Agent-entry binding, and artifact lowering without requiring the `native-capture` feature.
- `arcw agent script build <file.awfagent> --output <file.awfb>` compiles a single Agent controller through the typed project-index path and writes the shared `.awfb` bundle JSON with `bundle_kind = agent_controller` and the embedded `AgentArtifactManifest`. It does not create a separate Agent-only artifact container.
- `arcw agent script run <file.awfagent|file.awfb>` executes one Agent controller through `arcweft-agent-runner`. By default it uses the deterministic CLI session adapter; with `--native-source <file.arcw>` or `--profile <id>` under the `native-capture` feature, it uses the native game observation/capture/resource path as an `AgentSession`. Source input is compiled to the shared Agent `.awfb` bundle shape first; bundle input is decoded through `ArcweftBundle` and must carry `bundle_kind = agent_controller`. When source input is run against a native source/profile, the Agent compiler builds its `ProjectSemanticIndex` from the checked native HIR, so `.awfagent` references such as `@flow.opening` and `@signal.current_flow` resolve against the real project declarations instead of a CLI-only stub. CLI `--signal id=value` entries fill missing signal symbols for non-native sessions, but they do not overwrite typed signal declarations already present in the native project index. CLI `--state path=value` entries populate deterministic debug state payload values for `state("path")` probes in non-native sessions. CLI/native `--blob-dir <dir>` writes capture bytes under `blake3/<hex>` content-addressed paths and reports the stored byte count. Native observation signals are normalized from `@signal.id`/`@flow.id` surface spelling to Agent protocol keys and `Entity` values. Native Agent Script sessions keep the native runtime executor alive across observe/action/wait/capture/resource host calls. `choose(@choice...)` now dispatches as a semantic `SelectChoice` runtime input rather than a physical click fallback, and subsequent waits observe the advanced native runtime state. `advance_text()` now lowers to `AgentAction::AdvanceText`; the native session converts it to an `advance` runtime input only when the latest observation exposes an enabled semantic `AdvanceText` target. `invoke(target, action, args?)` now lowers to `AgentAction::Invoke`; the native session requires a matching enabled semantic `Invoke` action target from the latest observation and dispatches an `invoke` runtime input with the action id, preserving semantic action dispatch without falling back to coordinates. `--trace-out <file.arcwx>` writes a JSON `AgentTraceRecord` stream derived from the runner debug events, with deterministic `blake3:` payload hashes, explicit run/session IDs, `resource_read_completed` records for `read_resource(...)` responses, and capture `blob_refs` copied from `CaptureResult.content_hash`.
- Agent Script debug DB session and script-run metadata now preserve compact project shape summaries at both start and finish. The persisted metadata includes project-entity count/kind histograms plus project-graph symbol/edge counts, symbol/edge-kind histograms, the `project:summary` symbol id, and typed project-summary counters. `arcw debug db sessions`, `arcw debug db runs`, and MCP `arcweft.debug.script.runs` also lift those lifecycle metadata fields into a top-level `project` readback summary when `max_privacy` permits project metadata, so product graph/scheduler consumers can read counts and aggregate project-summary counters without re-running the compiler, scanning every graph row, or parsing raw metadata internals. With `max_privacy = public`, lifecycle rows remain visible but project-private raw `metadata` and the lifted `project` summary are omitted.
- `pointer.click(viewport_point(...), button=...)` lowers to `AgentAction::PointerClick`. Deterministic CLI/native Agent Script runs grant `agent.act.physical` only when the compiled Agent artifact declares that effect, keeping explicit physical input separate from semantic `agent.act.semantic`. `samples/agent-script/cli-pointer-click-smoke.awfagent` covers the CLI session path.
- Agent statement-form Prelude calls lower through runtime-evaluated Agent host tasks when they appear as standalone statements or as the final agent body expression. `expect(condition, message?)` and `deny(condition, message?)` therefore receive the VM-evaluated `bool` condition instead of a stringified expression label. The shared runner emits `DebugEventKind::Assertion`, CLI traces map it to `assertion_evaluated`, and failing assertions return a structured `AgentRunError::AssertionFailed` after recording `{ kind, condition, passed, message }`.
- Shared Agent wait evaluation now handles `Predicate::ActionEnabled` against observed action targets, matching the native MCP wait path instead of treating the protocol variant as an always-false stub.
- `arcw agent script trace <file.arcwx>` reads a trace through the shared `AgentTraceRecord` protocol type and validates the `.arcwx` extension, JSON shape, schema version, payload hash, run-id consistency, first/last record kinds, strictly increasing sequence numbers, and capture-record blob refs. With `--blob-dir <dir>`, it also validates byte-backed capture blobs by resolving each capture `content_hash` to `blake3/<hex>`, recomputing the stored bytes' hash, and comparing the stored byte length with the trace payload. It is a read-only validation surface for future replay/MCP trace resources, not a second runner.
- `arcw agent script replay <file.arcwx> [--expect <file.arcwx>]` performs read-only logical replay of validated trace records. The replay sequence records each event's sequence number, kind, tick, payload hash, and blob refs. `--expect` compares two traces by replay-relevant logical fields rather than byte-for-byte file identity, so it can verify that source-run and bundle-run traces produce the same logical sequence.
- `arcweft-agent-runner::ReplayAgentSession` is the Sans I/O read-only `AgentSession` for validated trace records. It replays recorded observation/action/capture/resource-read host responses in trace order, rejects out-of-order controller requests, and leaves file loading/hash validation to CLI/tooling.
- `arcweft-agent-protocol` and `arcweft-agent-mcp` now expose Agent trace resources as typed MCP-compatible resources. `AgentResourceKind::Trace` plus `arcweft_agent_mcp::trace_resource` map validated `AgentTraceRecord` arrays to `arcweft://run/{run_id}/trace.arcwx` with `application/vnd.arcweft.agent-trace+json`, and `resources/templates/list` includes the trace URI pattern.
- `arcw agent mcp` exposes `arcweft.trace.read` in the stdio MCP transport. It validates a `.arcwx` file through the same trace reader used by CLI replay, caches the resulting trace resource in the current MCP session, and serves it through `resources/list`, direct MCP `resources/read`, and privacy-gated `arcweft.resource.read` without requiring a prior native observation. The MCP resource list also exposes `arcweft://session/{session_id}/context.json` as a path-redacted JSON session context resource for the latest observation, cached captures, trace resources, cached RAG query state, and the compact native project graph summary when the session was opened from a source/profile; trace-only sessions use `arcweft://session/mcp/context.json`. `arcweft.session.info` exposes the same project context for live observed sessions. `arcweft.resource.read` and direct MCP `resources/read` accept `max_privacy`, default to `project`, treat image/capture blobs as `sensitive`, treat the session context as `project`, and derive trace JSON privacy from explicit record privacy fields when present. When `arcweft.resource.read` receives a debug SQLite `path`, it records allowed and blocked read decisions as `resource_read` debug events with URI, resource kind, privacy ceiling, and outcome payloads for audit readback through `debug db timeline` / `arcweft.debug.session.timeline`.
- `arcw agent mcp` exposes `arcweft.action` for enabled semantic Agent actions from the latest native observation, or after observing a supplied `source`/`profile` first. It keeps the native runtime executor alive across observe/action calls, dispatches `AdvanceText`, `SelectChoice`, and `Invoke` through semantic runtime inputs, accepts optional JSON object `args` for direct invoke calls, and returns accepted before/after ticks and state hashes plus the post-action frame summary. It does not synthesize physical pointer actions.
- `arcw agent mcp` exposes `arcweft.wait` for typed Agent protocol predicates against the active native runtime session, or after observing a supplied `source`/`profile` first. It steps the retained runtime by `poll_frames`, evaluates `Compare`, `Exists`, `All`, `Any`, `Not`, and observed action-enabled predicates against signals, metrics, state/report JSON, and observation fields, requires a logical `timeout_millis`, and returns the matching observation summary or a structured tool error on timeout.
- `arcw agent mcp` exposes `arcweft.script.run`, which calls the shared Agent Script runner for `.awfagent` sources or `.awfb` Agent controller bundles instead of embedding a second script interpreter in the MCP server. It accepts deterministic CLI-session `signals` and `state` JSON object arguments, native runtime `values`, and the same executor/pure/math/native stepping arguments as `arcw agent script run`, using the existing CLI parsers for typed values rather than a transport-local parser. It returns the same structured run report as `arcw agent script run`, including host calls, final status, trace output, blob write counts, and host responses.
- `arcw agent mcp` exposes read-only debug tools `arcweft.get_state`, `arcweft.signal_get`, and `arcweft.log_query`. They read the latest cached Agent observation, or run `arcweft.observe` first when `source` or `profile` arguments are supplied, and return structured JSON text blocks without mutating runtime state. Observation-derived state, signal, and log reads are treated as `project` privacy by default and enforce optional `max_privacy` before returning payload data.
- `arcw agent mcp` exposes read-only `arcweft.rag.query`, `arcweft.rag.explain`, and `arcweft.rag.context.read`. `arcweft.rag.query` builds an explainable `RagContextPack` from cached observation state/actions/objects/signals/metrics/logs/diagnostics, cached `.arcwx` trace records, source/project chunks, and privacy-allowed pre-indexed chunks in a supplied debug SQLite `path`. It can observe a supplied `source`/`profile` first; a supplied `source` is also parsed/lowered into source/project RAG chunks, while `sources` accepts a string or array of `.arcw` files/directories to index without observing. Directory inputs recursively expand to `.arcw` files in deterministic path order. When `path` is supplied, the query searches existing debug-store chunks with the query text plus explicit roots before ranking, so a prior `arcw agent rag index` run can feed MCP RAG without re-supplying source files. With `local_embedding = true`, it also hashes the query text through the deterministic local embedding adapter and fuses matching stored-vector hits from `path` before the normal lexical/graph/history/diagnostic/test-result fallback channels are selected. If that local vector channel produces no hits, it records an `AGENT_RAG_EMBEDDING_FALLBACK` warning diagnostic in the same debug store before continuing with fallback channels. The query ranks candidates with deterministic reciprocal-rank fusion from `arcweft-rag`, preserves `roots`, `graph_depth`, `limit`, `max_context_bytes`, `max_privacy`, channels, chunk IDs, and context item bodies in the returned JSON, deduplicates candidates by chunk id, deduplicates selected context by `semantic_hash` and overlapping source spans before spending the byte budget, and caches the pack in the MCP session. RAG candidates above `max_privacy` are filtered before ranking; observation-derived candidates default to `project`, source/project chunks default to `project`, and trace records can override that with `privacy_class` or `privacy` fields at the record or nested payload level. When `path` is supplied, `arcweft.rag.query` also upserts MCP-derived context chunks into the debug SQLite store, records the selected `RagContextPack` through `rag_queries`/`rag_query_hits`, and attaches the audit to a typed finished `sessions` row with `profile = rag` and `transport = mcp`; persisted source chunks are then visible to `arcweft.debug.search`. `arcweft.rag.explain` returns cached query/item metadata without inlining large bodies, and falls back to a debug SQLite audit readback by `query_id` plus optional `path` when the query is not cached; persisted audit explanations include the stored `session_id`/`run_id`. `arcweft.rag.context.read` reads one selected cached or persisted context item by `chunk_id` under an explicit byte cap, with persisted rows re-filtered against `chunks.privacy_class` before query-limit and byte-limit application. `arcw debug db rag --query-id <id>` exposes the same persisted audit readback to CLI clients, reconstructing the stored `RagContextPack` with the requested `max_privacy`.
- `arcweft-debug-sqlite` now records and reconstructs selected `RagContextPack` audits through the existing `rag_queries` and `rag_query_hits` tables. `record_rag_context_pack` stores query policy metadata and selected chunk/channel scores, while `rag_query_audit_with_max_privacy` joins back to `chunks`, rehydrates typed `RagQuery`/`RagContextItem` values, and applies privacy filtering before returning selected context.
- `arcw agent mcp` exposes read-only `arcweft.debug.search`, `arcweft.debug.script.runs`, `arcweft.debug.session.timeline`, `arcweft.debug.repl.cells`, `arcweft.debug.source.files`, and `arcweft.debug.graph.inventory`. `arcweft.debug.search` opens the supplied rebuildable debug SQLite database path, or `.arcweft/cache/agent-debug.sqlite3` by default, accepts exactly one of `query`, `query_vector` with `model_id`/`model_revision`, `graph_query` with optional `graph_depth`, `history_query`, `diagnostic_query`, or `test_query`, dispatches through the shared `arcweft-debug-sqlite` lexical/vector/graph/history/diagnostic/test search APIs, applies `max_privacy` before channel-specific limiting/ranking, and returns chunk IDs, source metadata, privacy class, search channel, rank, score, title, and body without requiring a native observation or cached trace. `arcweft.debug.script.runs` reads `script_runs` lifecycle rows with optional `session_id` filtering, applies `max_privacy` to lifecycle metadata readback, and exposes Agent id, source hash, project binding mode, sequence range, trace URI, outcome, effectfulness, error, and allowed metadata readback. `arcweft.debug.session.timeline` reads `debug_events` timeline rows with optional `session_id`/`run_id` filters and applies JSON payload privacy filtering before `limit`. `arcweft.debug.repl.cells` reads persisted `repl_cells` rows for one required `session_id`, exposing source hashes, status, display JSON, diagnostics, and effectfulness. `arcweft.debug.source.files` reads program-owned `source_files` inventory rows for a required `program_hash`, exposing source path, language, content hash, byte length, and metadata without re-reading files from disk. `arcweft.debug.graph.inventory` reads program-owned graph symbols and edges for a required `program_hash`, exposing symbol ids, public/qualified names, kinds, source-file links, byte spans, semantic hashes, summaries, edge kinds, weights, and metadata without forcing a text query; indexed programs are represented as `program` graph symbols with `contains_source_file` edges to `source_file` graph symbols, and each source file has a `contains_project_graph` edge to its per-source project graph summary. Multi-source persisted graph symbols keep source-scoped public ids while preserving the original source public id in metadata. `arcweft-debug-model` now owns the typed persisted `DebugSession`, `DebugScriptRun`, `DebugSourceFile`, `DebugGraphSymbol`, and `DebugGraphEdge` lifecycle/inventory models, `arcweft-debug-sqlite` can upsert/read/list/finish `sessions` and `script_runs` rows plus read/write program-owned `source_files`, `symbols`, and `graph_edges` rows through those models, `arcw debug db sessions` exposes recent product/debug sessions with profile, transport, lifecycle status, timing, program hash, and privacy-gated metadata readback, `arcw debug db runs [--session-id ID]` exposes persisted Agent controller runs with the same run lifecycle fields for CLI clients, `arcw debug db sources --program-hash HASH` exposes persisted source-file inventory rows for CLI clients, `arcw debug db graph --program-hash HASH` exposes persisted graph inventory rows for CLI clients, and `arcw debug db timeline [--session-id ID] [--run-id ID]` exposes privacy-filtered persisted debug-event timelines for CLI clients.
- `attach(resource)` and `checkpoint(name)` execute through the same Agent host boundary as other controller effects and persist as debug-record timeline payloads when `arcw agent script run --debug-db` is supplied. `samples/agent-script/cli-attach-resource-smoke.awfagent` reads an `AgentResource`, attaches it, checkpoints after the attach, and `samples/agent-script/cli-attach-capture-smoke.awfagent` captures a `CaptureRef`, attaches it, and checkpoints after the attach. `arcw debug db timeline --session-id session.cli --run-id run.cli` can read those records back. This covers the `AgentResource` and `CaptureRef` debug-record paths without introducing a second debug-record evaluator.
- Debug source-file and graph-inventory readback is privacy-gated on both CLI
  and MCP. `arcw debug db sources --program-hash HASH` /
  `arcw debug db graph --program-hash HASH` and
  `arcweft.debug.source.files` / `arcweft.debug.graph.inventory` accept

## Deliberate boundaries

- Agent Script reuses the existing expression, statement, block, attribute, contract/effect, and HIR lowering path.
- No transition layer for the old line-command syntax is present.
- Canonical project compilation is the only typed source entry point; `compile_agent_project_bundle` is the typed artifact boundary after exact `entry agent` selection. Controller VM execution and host-call dispatch are owned by `arcweft-agent-runner`; the CLI native game adapter path currently supports observe, wait polling, capture, resource read, semantic `SelectChoice`, enabled-observation-gated `AdvanceText` including native Game-mode E2E validation, semantic `Invoke`, privacy-filtered standalone trace/source/project-backed CLI RAG query, privacy-filtered standalone debug DB lexical, stored-vector, graph expansion, history, diagnostic, test-result, source-file-inventory, and graph-inventory readback, SQLite-backed REPL cell persistence, deterministic REPL observe/actions/query/history/bindings meta commands including VM-local binding extraction from parsed `let` patterns and serializable literal/observation/resource live-binding replay, read-only REPL trace loading/query through the same Agent trace resource path as MCP, compiler-backed deterministic REPL cell execution for complete Arcweft fragments, runtime-start triggered stale-session cleanup for Agent Script/REPL debug DB sessions, and MCP observe/action/wait/script-run/capture/resource/state/signal/log/debug-search/debug-session-timeline/debug-sessions-close-stale/debug-source-files/debug-graph-inventory/trace/session-context/RAG-query/RAG-explain/RAG-context-read tools through the existing native Agent resource/runtime builders. CLI and MCP RAG query now read persisted debug-store lexical chunks, graph edges, history entries, diagnostics, and test results before RRF fusion, persist selected audits with typed `sessions` ownership, and MCP RAG query audit readback can fall back to the debug SQLite store by `query_id` plus `path`; the remaining follow-up is broader product-owned project graph indexing plus product player/native daemon scheduling beyond the current CLI runtime-start trigger.
- Agent source defaults such as omitted signature return type are preserved as syntax/HIR shape for later semantic/compiler resolution rather than being string-rewritten in the parser.
- `invoke` is checked as a semantic action contract on a typed project entity. It does not accept string target IDs, does not fall back to physical actions, and validates payload record keys and values against named project-index Agent action parameters.
- `arcweft-agent-contract-reference` was not added as a production crate. Its concepts were merged into `arcweft-agent-protocol` modules to avoid duplicate protocol surfaces.
- `arcweft-debug-model` and `arcweft-rag` are Sans-I/O crates. They do not open databases, read files, call embedding services, or inspect runtime state directly.
- `arcweft-debug-model::embedding` owns the Sans-I/O embedding provider boundary and now builds `EmbeddingInput` values from `DebugChunk` only through an explicit `EmbeddingInputPolicy`. `Secret` chunks are never emitted to any provider input, and `Sensitive` chunks are withheld from remote providers even if a broader max-privacy ceiling is requested. `arcweft-debug-sqlite` exposes `embedding_inputs_with_policy(...)` so adapter crates can load provider inputs from persisted chunks only after SQL max-privacy filtering plus the provider-scope privacy gate. Provider adapters therefore receive text only after privacy filtering and retain the input `content_hash`/privacy needed to construct audited `StoredEmbedding` rows. The CLI's `debug db embed` command has two concrete adapters: a local, deterministic hash provider used to populate the debug store for offline vector-search validation without pretending to be a semantic embedding model, and an explicit remote command adapter that writes a versioned JSON request to `--remote-command` stdin and reads provider vectors from stdout. The command adapter is the provider-SDK bridge boundary: Arcweft validates returned chunk ids, dimensions, finite values, and non-zero norms before storing normalized vectors with the original chunk `content_hash`, while SDK/HTTP credentials remain outside the Sans I/O debug/RAG crates. Remote provider selection without `--remote-command` still records an explicit provider-unavailable diagnostic and exits instead of installing a transitional placeholder path.
- `arcweft-agent-runner` executes typed host requests and can step Agent controller bytecode for both effect-form calls and suspended Agent host-call expressions. It bridges `agent` custom host tasks to the same `AgentHostRequest` boundary and resumes the VM with a typed record payload. `wait(...)` expression tasks and Agent statement-form `wait(predicate, timeout=...)` lower typed probe comparisons and boolean predicate combinators to structured predicate records and execute through the same host wait boundary as `capture(...)`.
- Function-body value scopes parse `wait(...)` as an ordinary intrinsic call expression even when it appears as a bare statement. Flow and line-plan scopes retain their typed runtime wait statement path; no source dialect selects between them.
- `arcweft-debug-sqlite` is the only new I/O crate in this slice. It owns `rusqlite`, lifecycle validation, derived index rebuild, and debug-store record deletion while keeping database access out of syntax, HIR, compiler, runner, protocol, debug-model, and RAG crates.
