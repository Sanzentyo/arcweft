# Component text input unification

This cut applies the component/View text-control unification note from
`target/codex-notes/component-text-input-unification.md`.

## Implemented

- `TextField`, `TextArea`, and `SecureField` component/View heads now accept
  explicit input identity through `id: @input:.name` or `input: @input:.name`.
  The existing positional `TextField(@input:.name)` spelling still parses as
  the same canonical input identity.
- Component/View lowering now emits `UiInputResource`, `UiTextResource`,
  `UiProgramResource` semantic targets, and action button resources from the
  component source without a separate top-level `ui text_input` side
  declaration.
- Component text controls support authored label, value, placeholder, purpose,
  enter-key hint, submit handler, change handler, multiline override, and
  secure policy through typed props and existing modifiers.
- Button `text_submit @input:.name` actions and flow
  `let value = text_submit @input.name` now share the same canonical target
  generated by the component text control.
- `EntityRefSyntax` owns canonical family-relative entity conversion so bundle
  lowering, sema resolution, and project indexing use the same ID rule.
- Sema name resolution and project indexing now register component/View text
  controls as `EntityKind::Input`.
- Top-level `ui text_input`, `ui text_area`, and `ui secure_field` now produce
  structured removed-syntax diagnostics instead of acting as compatibility
  declarations.
- `samples/text-submit-flow`, `samples/modern-feedback-ui`, and
  `samples/native-text-input` no longer rely on top-level text-control
  declarations.
- Runtime submit button fallback bounds now derive from the target text-control
  slot. Single-line targets place submit buttons to the right of the field;
  multiline targets place submit buttons below the text area. This fixes the
  modern feedback UI overlap where the first button defaulted onto the
  following text area's stacked slot.

## Modern feedback UI debug notes

- `samples/modern-feedback-ui` bundles cleanly after the placement fix.
- The CSS/Takumi/WGPU substrate for opacity and CSS `box-shadow` is present:
  focused box-shadow lowering and renderer plan tests pass, and opacity is
  treated as a paint-only property in the Takumi adapter path.
- The visible modern component path still does not apply `UiStyleResource`
  rules to player-rendered `RenderTextInputControl` /
  `RenderActionButton` instances. Those renderer types currently carry bounds,
  labels, enabled state, and actions, but not resolved authored style or
  box-shadow data. This is a style-resolution/runtime-control contract gap, not
  a CSS parser or shadow renderer failure.

## Non-goals

- No compatibility layer for top-level `ui text_input` resources.
- No platform-widget fallback for submit buttons.
- No new layout-bounds resource contract; current runtime text-control bounds
  remain the existing stacked/default resource behavior.
- No end-to-end authored style resolution for player-rendered runtime text
  controls and action buttons in this cut.
