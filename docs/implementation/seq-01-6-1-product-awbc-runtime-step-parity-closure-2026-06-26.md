## Goal

Close the product adapter contract for every compact family generated by the
ordinary product lowerer without restoring structured product fallback. The
implementation is intentionally concentrated at these boundaries:

1. AWBC schema/fiber/VM own compact ABI and state;
2. `awbc::product_step` owns projection into `RuntimeStepResult`;
3. `RuntimeStepInput`/`HostRequestBatch` own typed host handshakes;
4. `awbc_lower` owns source-aware construction of executable tables;
5. runtime-driver/host/player remain consumers of the shared executor facade.

## Implemented overlay

### Input and compact ABI

- Transactional entry argument binding supports empty, positional, and
  named-equivalent root bindings.
- Missing, duplicate, unknown, and type-invalid bindings have stable error
  variants and leave registers retryable.
- Call and tail-call frames bind verified positional arguments.
- `AwbcTaskPlan` now stores stable `need_id`; AWBC codec version advances from 1
  to 2, with string remapping and structural verification updated.

### VM and traps

- VM observations retain dynamic effect/task/fiber arguments rather than
  discarding them at the compact boundary.
- call-function and goto paths preserve argument vectors.
- source and stream close operations are idempotent in compact state.
- verifier-safe runtime failures become typed `FiberTrap` values carrying the
  active source-map ID.
- non-boolean branches produce a runtime type trap rather than an unstructured
  adapter error.

### Shared runtime contracts

- `FlowFiberStatus::Dialogue` represents explicit line progression.
- input consumption is no longer destructive before the active suspension
  decides whether an event is applicable.
- `RuntimeStepInput` carries host-call results.
- `HostRequestBatch` carries ensure-content and host-call requests.
- host-call IDs, modes, requests, results, and typed errors are explicit data.
- runtime diagnostics carry category and optional source label/range/anchor.
- pure-call statistics can be combined with a saturating owned method.
- routed-input inspection helpers live on the shared step/input boundary rather
  than in a product-only extension trait.

### Product AWBC adapter

- supplied `RuntimeCallBackend` reaches intrinsic and pure-helper execution;
- compact helper identity is exposed without reconstructing structured AST;
- dialogue presents once and waits for explicit advance;
- line-task start/cancel/cleanup scheduling is deterministic;
- choice presents all filtered options, waits, validates explicit selection,
  and resumes once;
- await handles stable task/need IDs, progress, ready, error, and cancellation;
- await-many tracks source order, limit, in-flight tasks, partial results, and
  deterministic completion;
- immediate and suspending host calls use typed request/result correlation;
- every effect kind is explicitly mapped or emits a typed capability diagnostic;
- ensure-content, source, and stream observations are projected without silent
  drops;
- source policy conversion is an inherent method on `AwbcSourcePolicy`;
- stream/source sequences are monotonic and close is idempotent;
- child fibers are scheduled deterministically;
- VM quantum and host `max_ops` are kept distinct;
- one-op/output/blocked/done/failed/budget-exhausted stop reasons are selected
  from host-visible state;
- source-mapped traps preserve partial output and fail the facade fiber;
- facade environment, observations, source states, stream states, and all step
  counters are synchronized before return.

### Lowering

- flow IDs are reserved before body lowering so forward choice/goto targets use
  canonical function IDs;
- flow lowering emits multiple blocks and resume points for dialogue, choice,
  await, await-many, host/budget suspension, and control transfer;
- task signatures and task arguments share one inventory contract;
- await-many policy construction belongs to `AwbcInventory` rather than a
  free-standing endpoint conversion helper.

## Blocker disposition

The historical blocker enum remains discoverable for audits, while instruction
and terminator inherent methods now return no blocker for implemented canonical
families. This is not by itself proof of parity. The merge/completion gate is the
differential matrix in the companion test document.

The overlay must not be declared complete merely because
`product_step_parity_blockers()` is empty. It is complete only after every family
has passing raw and normalized `RuntimeStepResult` comparison and the decoded
product source gates remain green.

## Structural audit

The change materially alters public contracts, codec shape, statistics mapping,
and runtime orchestration, so a structural audit is mandatory before merge.
The product adapter is currently above the 1,200-LOC warning threshold. The
package keeps mapping in `product_step/mapping.rs`; a follow-up decomposition of
suspension families is recommended if the final integrated file remains above
the preferred 300-800 LOC responsibility range.

Recommended responsibility split, preserving the same public facade:

- `product_step/input.rs`: entry and explicit progression input;
- `product_step/dialogue_choice.rs`;
- `product_step/awaiting.rs`;
- `product_step/host_effect.rs`;
- `product_step/source_stream.rs`;
- `product_step/status.rs`;
- `product_step/mapping.rs`.

This split is a maintainability gate, not permission to create public helper
shims. Cross-module behavior should remain private or `pub(super)` methods on the
owned executor/type.
