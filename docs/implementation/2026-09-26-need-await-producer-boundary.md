# Need producer and Await runtime boundary — 2026-09-26

Initially inspected `main` at `d16040d0196e1e3b37302c30ce1ab4753e228821`; the follow-up review inspected `d9f840c0a83bccb94a7b3412359d51016aaba50b`. The working tree was dirty with concurrent 049/053 source and fixture work at both inspections. This is a design consultation, not implementation evidence: no Cargo check or runtime replay was run for this note. It elaborates the open Need/Await boundary recorded in the [convergence goal plan](2026-09-08-convergence-goal-plan.md); it does not supersede the maintained [`await : Need<T> -> T` contract](../01-language/await-need-result.md).

## Observed mismatch

- `asset.image` and `voice.load` are ordinary registered functions returning `Need<Result<...>>` (`arcweft-lang-sema/src/env/base.rs:1138–1163`). Their selected calls become `RuntimeResolvedStaticCallTarget::Registered` (`arcweft-compiler/src/lower.rs:8414–8427`). `final_flow.rs::lower_await_operation` and `final_expr.rs::lower_host_call_target` instead require an immediate `Static(Host)` call. `RuntimeAwaitFact` already admits *any* `Need<T>` operand and requires the Await result to be exactly `T` (`semantic_facts.rs:6740–6772`); lowering narrows that accepted rule.
- Turning a registered function into `Host` alone is insufficient. `FlowOp::HostCall` asks the host for the declared result type, currently `Need<T>` (`arcweft-core/src/engine/flow.rs:348–390`), while a suspended adapter contract publishes `T` (`arcweft-host-adapter/src/lib.rs:371–379`). The direct Await path avoids this only by constructing a task with `T` as `TaskOutcomeContract`. It cannot execute `let n = asset.image(...); await n`, an argument of type `Need<T>`, or a derived Need.
- Core already has `RuntimeValue::Need(NeedId)`, `NeedProducerSpec`/`NeedProducerFamily`, `HostOperationIdentity`/`BuiltinHostOperationId::AssetLoad`, `RuntimeNeedState`, and exact `TaskOutcomeContract` (`arcweft-core/src/task.rs`). Sema's `checked_need_producer_admission_for_call` certifies the source-ordered retained arguments of a selected direct producer call (`arcweft-lang-sema/src/producer_admission.rs:142–241`). These substrates are not connected to compiler producer lowering. `NeedProducerSpec::instance_key` is identity substrate, not yet a task/Need execution pipeline.
- Native `FlowFiberStatus::NeedWaiting` has no resume implementation (`engine/suspend.rs:80–83`). AWBC can await a typed Need register and read `RuntimeStepInput.need_states` (`awbc/vm.rs:2630–2657`, `awbc/product_step/suspension.rs:132–168`), but its flow lowerer emits `StartTask` into a dynamic register (`arcweft-runtime-plan/src/awbc_lower/flow.rs:1380–1423`); VM returns a String task ID and verifier admits only Task/Dynamic for that instruction (`arcweft-core/src/awbc/vm.rs:1543–1561`, `awbc/verify/code.rs:1385–1407`). The existing Need path is therefore not used by compiled Await. AWBC `resume_need` also needs an exact Ready-payload check against the admitted `T` before binding.
- Native task request projection maps asset/voice operations to `HostTaskRequest::AssetLoad` (`engine/suspend.rs:934–1005`), while AWBC task projection always creates `Custom` (`awbc/product_step/mapping.rs:338–402`). A shared typed request contract must determine the host request in both engines.

## One typed execution model

Give a selected callable that *produces* `Need<T>` an explicit semantic producer role, separate from an immediate host call. `callable/schema.rs::CallableValidator` is a suitable selected-schema owner: it already distinguishes executable standard families such as `StandardMap` and `Format`. In `env/base.rs`, register the standard producers with a typed host operation/request projection (built-in `AssetLoad` plus the selected asset kind for image/voice), checked start semantics, task policy, and restart policy. Include the role's complete fields in `callable/digest.rs::validator`; keep the selected `CheckedCallApplication` and its source-ordered operands authoritative. Derive payload `T` from the *instantiated selected result* `Need<T>` and validate it against the request contract. Do not copy `T` into a second static role identity, especially for generic or extern calls. For an extern capability returning `Need<T>`, project its selected manifest-owned host-call contract, `Suspend` mode, operation/argument binding, and manifest item type into the same downstream producer target. A `Need<T>` return type alone is not a producer executable, and an ordinary registered call without the explicit role must fail closed.

The host request route is part of that typed authority. `HostTaskRequest::AssetLoad(AssetRequest { kind: "image", .. })` routes under `asset.image`; kind `"voice"` routes under `asset.voice` (`arcweft-core/src/task.rs:1498–1513`), even though the source callable is `voice.load`. The standard role or host operation catalog must commit this route and the actual adapter registration must match it; source-callable spelling is not a fallback. Extern producers use their manifest-selected custom request. The current `arcweft-runtime-host/src/native_task.rs::complete_host_call` verifies manifest digest, suspended mode, and exact result item against the installed adapter, but ordinary `TaskSpec` dispatch does not perform those same checks. Carry the selected extern contract into the producer task admission and enforce an equivalent registry check before task submission, or migrating extern Need calls to `TaskSpec` silently weakens the host ABI.

In `compiler/lower.rs::runtime_call_target`, project that selected role to one `RuntimeResolvedNeedProducer` carrying typed operation/request, policy, admitted `T`, and checked argument evidence; retain normal `Host` only for immediate results. In `runtime-plan/semantic_facts.rs`, validate the producer result as `Need<T>` and the Await operand as `Need<T>` with output `T`. Replace the direct-call-only `RuntimeAwaitTargetSeed {need,task,request,...}` with a typed Need-value source and an independent producer-start seed/flow op. `final_flow.rs::lower_flow_value_source_with_overrides` should evaluate producer arguments in checked source order, bind the produced `RuntimeValue::Need` once, then lower Await against that value. A direct `await producer(...)` takes this same route; an existing Need local/parameter needs no producer start. Pending observer fallthrough retains the evaluated handle and never re-evaluates the operand. `final_expr.rs` should reject producer calls from pure expression lowering.

The Core producer-start operation derives Need/task identity from the admitted producer spec, plan/site, payload type, and evaluated-argument digest. Use `NeedProducerSpec` and one logical producer family (for example, `HostAdapterTask` for host-backed work) for native and AWBC; do not reuse the current static `owner.await.ordinal` IDs as the authority for repeated calls, or use engine-specific families for the same logical operation. Identical site/arguments produce the same instance key, so `JoinSameKey` uses `TaskLaunchOrdinal::JOIN` while each `AlwaysStart` invocation needs a distinct, deterministic launch ordinal in its Need/Task identity. Persist the ordinal cursor per `(GenerationId, NeedProducerInstanceKey)`, independent of unrelated producer interleaving, and reject reuse of an identity with a different complete spec, request, outcome, policy, or scope. The operation yields a typed Need handle and schedules or registers its `TaskSpec` according to the checked start semantics. A producer registry links its `NeedId` to task events; externally supplied Need handles continue to consume `RuntimeStepInput.need_states`. Both paths publish `NotStarted/Pending/Ready(T)/Cancelled` through the same Await observer and resume semantics. A task failure is a runtime fault; cancellation is non-returning; only `Ready(Result::Err(e))` is a domain error value. A shared Core request projector should produce the same typed `HostTaskRequest` from the selected operation and evaluated arguments in native and AWBC.

## Integration order

1. Seal the Sema producer role and admission, then project a closed runtime producer target in compiler/semantic facts. Validate `Need<T>` payload and host request argument contract there, including the extern manifest path. Keep unsupported registered Need-returning calls rejected with a typed missing-executable error.
2. Replace the direct Host Await path in `final_flow.rs` with producer-start plus Await-over-Need, preserving the existing Compose/source-order machinery and `RuntimeAwaitFact` observers. Migrate Core plan seeds, construction validation, `FlowOp`, and native engine together; implement `NeedWaiting` resume, exact Ready-payload validation, publication cursor, observer re-entry, and producer task-event mapping. A standalone producer call must yield a usable Need value.
3. Lower the same flow into a Need-typed AWBC register. The current `StartTask` has one production lowering site (Await); replace its unreleased task-string contract with the Need-producing instruction/observation, updating `awbc/schema.rs`, `codec/code.rs`, `verify/code.rs`, `vm.rs`, `awbc_lower/{flow,inventory}.rs`, product-step mapping, and codegen opcode consumers in one cut. The Await terminator then uses its already implemented `FiberAwaitTarget::Need` branch. Verify the register's `Need<T>` item matches the task-plan payload. `FiberAwaitTarget::Need` and its save DTO currently retain only `NeedId` (`awbc/fiber.rs:235–241,934–949`); retain the selected payload type identity in the suspension so each Ready publication and restored Await can be checked before binding.
4. Extend `AwbcProductExecutorSaveSnapshot` and its live counterpart (`awbc/product_step/snapshot.rs:513–560`) with one authoritative producer record per locally produced live Need: selected spec/owner, NeedId–TaskId linkage, exact `TaskSpec` including the already evaluated request arguments and outcome, task/restart policy, launch ordinal, state, and publication cursor. Encode retained runtime arguments through the existing AWBC save-value DTO, not a raw live `RuntimeValue`. On restore, validate program/artifact owner, payload type, unique linkage, task specification, per-producer ordinal cursor, and cursor ordering against the verified AWBC plan before resuming the fiber. For a `Restartable` in-flight task, re-register that exact request with `ensure_task` once; `started_tasks` alone would suppress re-submission after load. For `MustBeQuiescent`, a save request waits or defers deterministically until the task is terminal and then saves/restores the resulting Need state. This policy is not an exemption from mandatory save/restore acceptance. External Need parameters may lack a local producer record; retain their NeedId, expected `T`, and cursor, then require the external provider's normalized state on continuation. Evolve the unreleased version-1 codec shape in place and remove redundant task-string Await handling after migration.

   Native `FlowFiberStatus::NeedWaiting` must retain equivalent state across ordinary step/resume. `ArcweftRuntimeExecutor::snapshot/restore_snapshot` currently returns `UnsupportedTier` for native `RuntimePlanVm` and `StructuredAot` (`arcweft-core/src/executor.rs:411–445`); do not claim native save/restore parity from native step tests. Product AWBC owns the required persisted Need save/restore evidence in this cut.
5. The separate `Need<Result<T,E>>.context(...)` pre-Await composition is a derived Need transformation, not a pure `Result.context` call on the handle. It maps only `Ready(Result::Err(e))` through the selected context frame and forwards Pending/cancellation without restarting the source. Admit it as a typed producer/combinator after the base Need handle path; the current 049 post-Await context example does not prove this case.

- Compile and execute `try (await asset.image(asset)).context("opening")`, a voice-load Await with a Pending observer, `let n = asset.image(asset); let r = await n`, and a function taking `Need<Result<ImageHandle, AssetError>>` and awaiting it. Compare native and decoded AWBC task requests, status transitions, and return values.
- Test one producer evaluation and one task launch across repeated Pending publications/observer fallthrough; source-ordered side-effectful arguments; Ready success, `Ready(Result::Err)`, task failure, cancellation, and malformed Ready payload. Preserve a Need parameter's identity without fabricating a task.
- Round-trip the AWBC instruction, verifier rejection cases, suspended Need snapshot/restore, and publication cursor. Restore a pending `Restartable` producer and prove one exact task re-registration; request save during a live `MustBeQuiescent` producer, reach quiescence, then save and restore its terminal Need without losing the Await continuation. Reject a forged producer/task link, changed manifest contract or payload type, stale cursor, duplicate launch ordinal, and a `Ready` value outside `T`. Run the focused 049 fixture followed by applicable runtime-plan/Core/compiler checks and the goal's native/decoded AWBC fixture gate. Until those pass, `Need<T>` general Await and 049 execution remain unverified.
