### Preserved View identity boundary

[The dialogue View ID acceptance boundary](dialogue-view-id-acceptance-boundary-2026-07-19.md)

- `ViewId(PublicId)` is stable semantic/public ownership;
- `ViewRegistryId(u32)` is an opaque process-local dense registry key;
- `ViewDefinitionIndex(u32)` is crate-private to the accepted runtime catalog;

  across save/restore and replacement.

The original AW-AH-009.4.1 direction uses `ViewId` at public and wire
boundaries and does not require a compatibility layer. Dense keys and accepted

## Accepted design pieces

The following original AW-AH-009.4.1 decisions are retained as fixed direction
for the correction:

- `DialoguePresentationCharacter` is exactly:

  ```rust
  pub struct DialoguePresentationCharacter {
      pub id: CharacterId,
      pub display_name: String,
  }
  ```

- `CharacterId` remains the stable narrative identity and is never a source
  callee string.
- The source View projection is nested under
  `dialogue.character.{id, display_name}`.
- `dialogue.content`, `dialogue.occurrence`, `dialogue.stage`,
  `dialogue.reveal`, and `dialogue.primary_action` remain typed projections.
- Display-name override is Character metadata policy, not a line/config patch.
- Custom Views may omit rendering the character name.
- Character name and content use authored View Style and the shared
  prepared-text path.
- The speaker-only horizontal writing override and content-style inheritance
  are removed.
- Prepared text gains a closed character-display-name/content role.
- Agent, MCP, accessibility, hit test, and capture use the same prepared item
  and semantic owner.
- The standard dialogue View retains `std.view.dialogue`; old flat part/source
  IDs are directly replaced without aliases.
- No flat speaker field, deprecated variant, dual reader, source gate, CSS, or
  Takumi path survives.

These accepted pieces are direction, not evidence that their dependent wire
and runtime cuts are already implementable.

## Intake defects requiring correction

### Contradictory value-projection inventory

The nested type document omits `DialogueValueProjection::Content`, while the
bundle/wire document includes it. This affects closed enum coordinates,
serialized discriminants, duplicate validation, evaluator behavior, and
tamper tests.

AW-AH-009.4.1.1 must select one exact inventory and state how generic value
projection relates to `DialogueTextProjection::Content`.

### Missing localization catalog implementation contract

Current production has only a locale-catalog section identity. It has no
Character display-name catalog record, canonical codec, accepted revision,
semantic digest, locale-policy digest, strict decoder, or runtime lookup owner.

The original package names these concepts but does not define their exact wire
or identity. Therefore its duplicate/noncanonical/stale/oversized/tamper rows
do not yet have one implementable API.

### Character body ownership overlaps Proof

[Proof 01.1.1.2](../reviews/requests/2026-07-20-seq-proof-01.1.1.2-retained-global-identity-declaration-grammar-reconciliation.md)
owns the final typed Character declaration body, including display-label
metadata and source-versus-manifest ownership. Current Character declarations
still use the provisional generic entity body.

AW-AH-009.4.1 must consume that final typed owner. It must not add a
Character-specific raw-body reparser or preserve the legacy entity body as a
second reader.

### Locale roles are conflated

AW-AH-009.4 Cut 1 already has
`CharacterDialogueConfig::source_locale`. The projection package separately
uses a Character display-name source locale and an active session locale.
Because per-line/config display-name override is forbidden, those concepts
must receive separate typed names, owners, digest participation, and saved
behavior.

### Runtime and save prerequisites are absent

AW-AH-009.4.2, AW-AH-009.4.3, sema, AWBC ABI 2/codec 8, typed runtime frame, and
bundle-session schema 2 must exist before the final projection can execute and
persist. Current save remains schema 1.

The corrected contract must define one atomic switch order. It may not add the
schema-2 reader beside schema 1 or stage a successful nested projection beside
the flat speaker projection.

### TTS is a new subsystem, not a rename

Current production has no `arcweft-audio-tts` crate or matching provider
speaker catalog/adapter protocol. The original TTS rows cannot be a completion
gate for dialogue View projection.

AW-AH-009.4.1.2 independently decides whether and how a typed TTS subsystem is
implemented. Character projection proceeds without it.
