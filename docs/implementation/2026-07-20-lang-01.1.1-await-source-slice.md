# Lang-01.1.1 typed await source slice

The normal checker still lacks an authoritative project-aware nominal type
resolution product needed by Lang-01.1.1.1 TM-072/RD-084, TM-080, and TM-083. Those
excluded generic-alias and unknown-type prerequisites are specified
independently in
[Lang-01.1.1.2 project nominal type resolution production reconciliation](../reviews/requests/2026-07-20-lang-01.1.1.2-project-nominal-type-resolution-production-reconciliation.md).

## Scope

This cut implements the non-Stream, non-wire portion of
`Lang-01.1.1-direct-style-suspension-generator-final-contract.zip` that can
land independently of the pending Lang-01.3.1.2.1 Stream runtime/wire
correction and the ongoing AW-AH-009.3 callable-catalog migration.

The cut replaces the stringly/boolean expression shape
`Expr::Await { expr, applies_try }` with one typed `AwaitExpr` containing:

- the typed operand;
- `AwaitPropagation::{PreserveResult, PropagateError}`;
- exact ranges for the whole await, the `await` keyword, and its operand; and
- the distinct authored propagation sources `try await` and `await?`.

The parser owns these ranges directly. Expression traversal, semantic
checking, project indexing, runtime-plan rejection, verification, CLI, and
Agent projections consume the typed node and do not reconstruct await
semantics from source spelling.

## Preserved behavior

- `await need` retains `Result<T, E>`.
- `try await need` and `await? need` retain the existing `T` behavior.
- `await need?` keeps postfix `?` inside the await operand.
- `(await need)?` keeps postfix `?` outside the await node; the await-owned
  range excludes the outer question mark.
- malformed `await` reports the zero-width end-of-input insertion point
  through ordinary expression parsing.
- flow-owned `await ... with` remains a separate flow contract and is not
  changed by this expression-AST cut.

## Package deviation and remaining boundary

The package assumes that an existing typed `TryExpr` source record already
owns exact `whole`, `operand`, and `question` ranges. Current production does
not have that record: one `Expr::Try { expr }` shape currently represents both
the canonical general prefix `try expr` surface and postfix `expr?`. Prefix
`try expr` is also used by current Agent and CLI surfaces, while the returned
package only specifies `TryExpr = Expr "?"`.

This cut therefore does not redesign `Expr::Try`, remove prefix `try expr`, or
add propagation diagnostics by implementation judgment. In the package test
matrix:

- A001-A009 and the await-owned half of A010 are implemented;
- A010's outer postfix-Try exact source record remains open; and
- A015-A016's propagation-boundary and error-compatibility diagnostics remain
  open.

The independently throwable correction request is:

- [`2026-07-20-lang-01.1.1.1-prefix-postfix-try-source-and-propagation-contract-correction.md`](../reviews/requests/2026-07-20-lang-01.1.1.1-prefix-postfix-try-source-and-propagation-contract-correction.md)

That request must consume the typed `AwaitExpr` introduced here and must not
redesign it without evidence of a concrete defect.

## Explicit non-goals

- direct-frame AWBC lowering for ordinary suspending functions;
- generator classification or Stream producer execution;
- RuntimePlan Stream definitions, handles, events, host wire, bundle, save,
  ABI, or codec version changes;
- `FunctionKind` or author-role deletion;
- callable execution facts, project-index execution projections, or LSP/Agent
  callable publication; and
- repository source-text gates. Removal evidence must use parser/compiler
  rejection and typed public behavior.
