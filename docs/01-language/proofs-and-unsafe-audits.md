# Proofs and Unsafe Lifetime Audits

Arcweft prefers statically checked lifetime, thread, and drop rules. When the
compiler cannot prove an operation automatically, the author must choose one of
two explicit mechanisms:

```text
formal proof:
  verifier discharges generated obligations

audited unsafe:
  human-audited escape hatch with mandatory metadata and SAFETY docs
```

Both mechanisms are visible to tooling, diagnostics, manifests, review, and
release policy. They must not bypass Sans I/O crate boundaries.

## Formal proof items

Formal proofs are top-level items identified by an entity ID.

```awft
proof @proof.line_summary_to_flow {
    requires summary.lifetime >= 'line
    ensures summary.lifetime >= 'flow

    check no_lifetime_below(LineSummary, 'flow)
}
```

Proof items build on the contract vocabulary:

```text
requires
ensures
invariant
assert
check
assume
```

`assume` is allowed in proof/debug contexts, but every assumption must carry a
reason or trusted axiom reference. Production policy may reject undisclosed
assumptions.

## Proof references

Operations that need non-local justification reference a proof explicitly.

```awft
let summary =
    line.summary()
        |> promote('flow, proof = @proof.line_summary_to_flow)
```

The compiler generates proof obligations such as:

```text
no_lifetime_below(LineSummary, 'flow)
must_drop_discharged(handle)
thread_capture_safe(capture, target_thread)
```

The verifier accepts the operation only when the referenced proof discharges
the required obligations, unless the project policy explicitly allows
unverified proof stubs.

## Trusted axioms

Trusted axioms are declarations of facts outside Arcweft's verifier.

```awft
trusted axiom @axiom.resource_manifest_hashes {
    reason = "resource manifest hashes are generated by signed build tooling"
}
```

Proofs may depend on trusted axioms:

```awft
proof @proof.voice_manifest_safe {
    use @axiom.resource_manifest_hashes
    check voice_manifest_hashes_match()
}
```

Trusted axioms are review-sensitive and should appear in generated manifests.

## Unsafe lifetime blocks

`unsafe lifetime` is the manual audit escape hatch for lifetime promotion or
borrow proof cases that the compiler cannot verify.

```awft
unsafe lifetime @unsafe.cache_last_line
reason = "temporary debug cache until formal proof is added"
{
    /// SAFETY:
    /// The cached summary is cloned from owned line data before the line scope
    /// exits. No borrowed text cluster or presentation handle escapes.
    cache.last_line = line.summary().promote_unchecked('session)
}
```

Rules:

```text
- an unsafe lifetime block requires an @unsafe.* id
- a human-readable reason is required
- a doc comment containing SAFETY is required
- the block creates audit obligations
- it does not grant filesystem, network, device, GPU, or OS capabilities
```

Diagnostics should point at the operation and the required proof/audit path:

```text
error: lifetime promotion from 'line to 'flow is not proven
help: use promote('flow, proof = @proof.id)
help: or use promote_unchecked('flow) inside unsafe lifetime @unsafe.id
```

## Release policy

Projects choose a proof mode.

```text
dev:
  parse and record proof/audit metadata, but allow incomplete proofs

test:
  verify required proofs; audited unsafe allowed by policy

release:
  reject undisclosed audited unsafe; require formal proofs or trusted axioms for
  non-trivial lifetime promotion, thread capture, global mutation, and MustDrop
  overrides
```

The CLI owns policy enforcement:

```bash
arcw verify game/main.awft --mode test
arcw verify game/main.awft --mode release
arcw verify game/main.awft --emit-obligations out/proofs
```

## Implementation Status

Phase 1.5 now has a first verifier pass:

```text
arcweft-lang-hir
  public HIR facade consumed by verifier/tooling

arcweft-verify
  Sans I/O proof obligations, audit summaries, policy diagnostics, SMT problems

arcweft-verify-z3
  external Z3 process adapter

arcweft-verify-oxiz
  pure Rust OxiZ adapter boundary
```

The semantic verifier generates obligations for lifetime promotion, unsafe
lifetime audits, upper-lifetime registry writes, thread capture, thread join
typing, trusted assumptions, raw syntax that reaches semantic analysis, sibling
thread or line child task write conflicts, and MustDrop registry values such as
`'line.focus`.

The current pass is CFG-aware for blocks, branches, line plans, cancellation
rules, and scoped `defer` outcomes. Completed-only cleanup does not discharge a
cancelled path; cancellation cleanup must use `defer on cancelled` or an
unqualified `defer`. Full proof body checking, fixed-point loop analysis, and
type-directed proof discharge remain future semantic work. CLI/LSP already
consume the verifier report schema, so future proof discharge improvements
should be added to `arcweft-verify` rather than duplicated in tools.
