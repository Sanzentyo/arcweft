# Proofs and Unsafe Lifetime Audits

Arcweft prefers statically checked lifetime, thread, and drop rules. When the
compiler cannot prove an operation automatically, the author must choose one of
two explicit mechanisms:

```text
formal proof:
  verifier discharges generated obligations

audited unsafe:
  human-audited escape hatch with mandatory metadata and SAFETY docs
```

Both mechanisms are visible to tooling, diagnostics, manifests, review, and
release policy. They must not bypass Sans I/O crate boundaries.

## Formal proof items

Formal proofs are top-level items identified by an ordinary local name. Proof
calls inside their bodies use ordinary callable names, such as `lemma(value)`.
The canonical declaration header is `proof name(...)`; a generated or fully
elaborated header such as `proof @proof:.name name(...)` (or
`proof @proof.name name(...)`) is accepted and emits the
`style::redundant_decl_identity` warning for hand-written source. The short
relative form `proof @.name name(...)` is accepted and normalized to the same
typed `proof.name` identity. `#[generated]` emits the generated-surface
information instead, and `#[allow(style::redundant_decl_identity)]` suppresses
only the redundant-identity warning.

Exactly one fixed parameter group is required, including `()` for no parameters.
Generic parameters, an explicit return type, and a `where` clause use the callable
header grammar. `requires` and `ensures` are typed header contracts before the
body. A body is an expression introduced by `=` or a typed proof block. An
omitted return type is Unit; a non-Unit result requires a corresponding body
value. See [contracts](contracts.md).

```arcw
proof nonnegative(value: i64)
requires value >= 0i64
ensures value >= 0i64
= ()
```

Type checking a proof body does not establish formal proof discharge. A
precondition alone also does not prove the body:

```arcw
proof requires_only() requires true = ()
```

The current verifier reports this accepted declaration as a `proof_body`
obligation with missing discharge. Test and release policy reject that missing
evidence. The source span and registered proof identity remain in the report.

## Proof references

Proof blocks call registered proof declarations through the same typed call
authority used by semantic analysis:

```arcw
proof lemma() = ()

proof dependent() {
    lemma();
}
```

An unknown callable is a semantic rejection, with the original call-target
diagnostic and source span. It does not publish an accepted verifier generation.
Well-typed calls retain their selected declaration and result facts; those facts
do not by themselves discharge either proof body. Public `proof.name` identities
remain available for tooling and reports. Proof dependencies are not authored
as body-local `use`, `check`, or `assume` clauses.

## Trusted proof metadata

A fact outside Arcweft's verifier is represented by a normal proof with explicit
typed trust metadata. There is no separate trusted-axiom declaration family.

```arcw
#[verify.trusted(reason = "resource manifest hashes are generated by signed build tooling")]
proof resource_manifest_hashes() = ()
```

The `reason` argument is mandatory and must be one non-interpolated string
literal whose decoded value contains non-whitespace text. Escape sequences are
decoded once, then the exact decoded value—including leading and trailing
whitespace—is retained in declaration metadata.
`verify.trusted` is rejected on every non-proof declaration. Proofs depend on
proofs:

```arcw
proof voice_manifest_safe() {
    resource_manifest_hashes();
}
```

The attribute records the external trust declaration. It does not bypass typed
call checking or turn a missing proof-body discharge into accepted evidence.
The current proof collector reports pending body obligations for these
declarations as well. Release policy and formal discharge remain separate from
parsing the trust metadata.

## Unsafe lifetime blocks

`unsafe lifetime` is the manual audit escape hatch for lifetime promotion or
borrow proof cases that the compiler cannot verify.

```arcw
unsafe lifetime @unsafe.cache_last_line
reason = "temporary debug cache until formal proof is added"
{
    /// SAFETY:
    /// The cached summary is cloned from owned line data before the line scope
    /// exits. No borrowed text cluster or presentation handle escapes.
    cache.last_line = line.summary().promote_unchecked('session)
}
```

Rules:

```text
- an unsafe lifetime block requires an @unsafe.* id
- a human-readable reason is required
- a doc comment containing SAFETY is required
- the block creates audit obligations
- it does not grant filesystem, network, device, GPU, or OS capabilities
```

Diagnostics should point at the operation and the required proof/audit path:

```text
error: lifetime promotion from 'line to 'flow is not proven
help: use promote('flow, proof = @proof.id)
help: or use promote_unchecked('flow) inside unsafe lifetime @unsafe.id
```

## Release policy

Projects choose a proof mode.

```text
dev:
  parse and record proof/audit metadata, but allow incomplete proofs

test:
  verify required proofs; audited unsafe allowed by policy

release:
  reject undisclosed audited unsafe and trusted proof evidence unless policy
  explicitly allows it; require formal evidence for non-trivial lifetime
  promotion, thread capture, global mutation, and MustDrop overrides
```

The CLI owns policy enforcement:

```bash
arcw verify game/main.arcw --mode test
arcw verify game/main.arcw --mode release
arcw verify game/main.arcw --emit-obligations out/proofs
```

## Verifier ownership

```text
arcweft-lang-hir
  public HIR facade consumed by verifier/tooling

arcweft-verify
  Sans I/O proof obligations, audit summaries, policy diagnostics, SMT problems

arcweft-verify-z3
  external Z3 process adapter

arcweft-verify-oxiz
  pure Rust OxiZ adapter boundary
```

The semantic verifier generates obligations for lifetime promotion, unsafe
lifetime audits, upper-lifetime registry writes, effect capability writes,
thread capture, thread join typing, trusted assumptions, raw syntax that reaches
semantic analysis, sibling thread or line child task write conflicts, and
MustDrop registry values such as `'line.focus`.

Effect capability obligations are backed by semantic facts rather than ordinary
symbol lookup. A flow or function contract such as
`effects { signal.write, state.write('flow) }` grants those capabilities inside
the body. This
discharges corresponding write obligations such as `signal.set(...)` and
upper-lifetime registry writes like `'flow.flags.seen <- true`. Unknown or
missing capability facts remain visible in verifier output.

The current pass is CFG-aware for blocks, branches, line plans, cancellation
rules, bounded loop fixed points, and scoped `defer` outcomes. Completed-only
cleanup does not discharge a cancelled path; cancellation cleanup must use
`defer on cancelled` or an unqualified `defer`. Proof declarations, header
contracts, bodies, and calls must have accepted HIR and checker-owned facts
before the verifier collects their pending `proof_body` obligations. An unknown
proof call is rejected at that admission boundary. An `unsafe lifetime` block
must contain the unchecked promotion it
justifies. Region checking rejects borrowed values that escape through block
final values, `return`, line-plan `out`, or upper-lifetime registry writes, and
tracks direct local borrow drops through path-sensitive branch merges. A
well-typed callable proof is not currently treated as a completed formal proof.
CLI/LSP consume the verifier report schema through `arcweft-verify`.
