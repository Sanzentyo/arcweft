# Request: seq-06.14 responsive stage placement package

## Sequence position

Seq06.14 follows seq06.9 through seq06.13. It focuses on responsive placement
for stage/image/character presentation objects across viewport sizes.

This request can be designed in parallel with seq06.15, but production
integration must leave one shared placement contract that both flat image
objects and `.awchar` character-stage objects can use.

## Problem

`samples/zundamon-stand-switch/main.arcw` renders consistently in PNG and
observe JSON, but larger viewport evidence shows that the standing character is
authored with absolute pixel coordinates:

```arcw
x = 930px
y = 20px
width = 250px
height = 430px
```

At 1920x1080 and 2560x1440, the dialogue panel expands with viewport width, but
the character remains at the same absolute 1280x720-era position and size. This
makes large-window output visibly wrong even though observe metadata matches the
pixels.

Arcweft needs a deterministic, typed stage placement model that works for native,
web, offscreen observe, and visual goldens.

## Goal

Design and implement a production responsive placement contract for presentation
image objects and character-stage objects.

The same contract must drive:

- runtime/player frame planning;
- wgpu rendering;
- native/web player output;
- `agent observe` bbox/layer/object metadata;
- capture crop metadata;
- visual smoke/golden fixtures.

## Required decisions

- Define coordinate spaces:
  - source/canvas space;
  - design viewport space;
  - resolved viewport space;
  - physical output space.
- Define placement primitives:
  - anchor to viewport edges/corners/center;
  - margins/insets;
  - scale policy;
  - fit policy;
  - safe-area awareness;
  - min/max size behavior;
  - optional baseline/ground anchor for characters.
- Decide authoring syntax for responsive placement:
  - whether to extend `image @... { ... }`;
  - whether to introduce `position = anchor(...)`;
  - how this composes with existing `x/y/width/height`;
  - whether old absolute fields remain only as the explicit absolute mode.
- Define scale semantics:
  - design-size scale from 1280x720 to larger outputs;
  - independent width/height scaling rejection or support;
  - letterbox/crop behavior;
  - high-DPI behavior.
- Define structured diagnostics for ambiguous placement:
  - mixed absolute and anchored constraints;
  - missing size;
  - conflicting fit/scale constraints;
  - object exceeding viewport or safe area.
- Define how observe reports resolved placement:
  - original authored placement;
  - resolved bbox;
  - transform from design to output;
  - layer/object capture crop basis.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, fixtures, and
  validation notes.
- Keep placement deterministic and backend-independent.
- Do not use browser DOM/CSS layout, canvas 2D fallback, or platform-specific
  window layout to solve presentation placement.
- Keep native and web on the same player-prepared frame path.
- Do not add compatibility shims for removed/ambiguous placement syntax.
- Existing absolute `x/y/width/height` may remain as an explicit absolute mode,
  but responsive placement must be the intended stage/character path.

## Tests to specify and implement

- A standing image anchored near top-right keeps the same visual relation at:
  - 1280x720;
  - 1920x1080;
  - 2560x1440.
- Observe JSON bbox matches rendered PNG pixels at each viewport.
- Layer capture and object capture crop the same resolved image area.
- Native/web/offscreen visual evidence uses the same resolved placement.
- Conflicting placement constraints produce typed diagnostics.
- Large viewport and high-DPI scale evidence are recorded in validation output.

## Expected output

Return a zip named like:

```text
arcweft-seq06.14-responsive-stage-placement-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- Rust overlay edits;
- updated or new samples/fixtures;
- focused unit/integration tests;
- observe output comparison evidence for multiple viewport sizes;
- native/web validation instructions;
- explicit non-goals and deferred placement features.

## Non-goals

- Do not solve PSD/.awchar character composition here except for ensuring the
  placement contract can mount such objects.
- Do not redesign the full CSS layout/cascade system.
- Do not implement animation/keyframes here.
