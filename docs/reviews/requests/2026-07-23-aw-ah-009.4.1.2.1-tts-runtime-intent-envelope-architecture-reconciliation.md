## Why this correction is required

The AW-AH-009.4.1.2 package specifies a direct
`arcweft-core -> arcweft-audio-tts` dependency and a TTS-specific variant in
the core task model. Repository-wide architecture instead requires
`arcweft-core` to remain runtime/data core only and explicitly forbids it from
depending on audio or other domain subsystems.

The implemented lower model already preserves this repository invariant:

- `arcweft-audio-tts` owns nominal TTS intent/request/result/error types;
- `arcweft-runtime-driver::tts` can prepare an accepted selected request;
- `arcweft-core` has no audio dependency;
- generic task and host failures carry typed `RuntimePayload`, not strings.

What remains unresolved is the final typed path by which an ordinary authored
TTS function creates a schedulable intent and reaches
`BundleSession::dispatch_requested_tasks` without:

- adding the forbidden core dependency;
- serializing a Rust type name or ad hoc JSON/string payload;
- creating a TTS-specific parallel scheduler;
- allowing an unprepared intent to cross the host/replay boundary; or
- introducing a temporary compatibility envelope or alias.

## Required decisions

Produce one exact final model that decides all of the following.

1. **Typed executable representation**
   - Select the owner and exact type for a lowered TTS intent before provider
     selection.
   - State whether it is a nominal `RuntimePayload`, a domain task table keyed
     by a typed handle, an upper-layer task-template enum, or another closed
     representation.
   - Define its exact field ordinals/layout identity and bounded codec if it
     crosses AWBC or bundle boundaries.

2. **Dependency direction**
   - Give the final Cargo edge graph for syntax/HIR/sema/runtime-plan/compiler,
     `arcweft-core`, `arcweft-audio-tts`, runtime-driver, scheduler, host
     adapter, bundle, save, and replay.
   - Preserve the repository rule that `arcweft-core` has no audio dependency.
   - Do not solve the edge with a local extension trait, string tag, downcast,
     `Any`, broad facade dependency, or reverse dependency.

3. **Preparation boundary**
   - Define the exact owner/API that consumes the typed intent plus one pinned
     accepted catalog generation and availability snapshot.
   - Preparation must occur before scheduler publication, generation-pin
     publication, `HostTaskDispatch`, save/replay capture, or provider I/O.
   - Define the typed failure transaction: same logical task/Need observer,
     exact `TtsError`, no host dispatch, and no partial registry publication.

4. **Task identity and joining**
   - Preserve the selected-request fingerprint and
     `tts.v1.<64 lowercase hex>` task key.
   - State where `TaskClass::TtsSynthesis`, `JoinSameKey`, priority, epoch,
     sequence, cancellation scope, and generation pin are attached.
   - Prove that intent fields cannot be used as the final join key before
     provider/catalog selection.

5. **Host visibility**
   - Make `TtsSynthesisIntent` unconstructible at the host adapter boundary.
   - Only the fully selected `TtsSynthesisRequest` and credential-slot-only
     provider request may reach privileged host code.
   - Define the one typed adapter registration/dispatch path for
     `tts.synthesize`; no generic string operation branch may be restored.

6. **Result, progress, and error mapping**
   - Specify how exact TTS progress, `TtsAudioAsset`, and `TtsError` become the
     ordinary scheduler/Need state without string projection.
   - Preserve typed `RuntimePayload` for generic cross-domain task carriers.
   - Define layout validation and wrong-nominal rejection at every generic
     payload boundary.

7. **AWBC, save, replay, and reload**
   - Decide which pre-selection intent facts are executable program data and
     which selected-request facts exist only at runtime.
   - Preserve replay schema 1 and the existing `HostTasks` /
     `TaskGenerationPins` save blockers; do not create a second TTS task log.
   - Define queued reload compatibility and active old-generation completion
     without serializing an unprepared intent to host/replay state.

8. **Source and standard-callable integration**
   - Bind the three final ordinary functions from AW-AH-009.4.1.2 to the chosen
     typed intent representation through the shared callable registry.
   - Preserve ordinary `fn -> Need<TtsAudioAsset, TtsError>` suspension; add no
     TTS keyword, source statement, raw provider function, or compatibility
     spelling.

## Required implementation order

1. Freeze the dependency graph and exact typed intent/envelope/API.
2. Add direct codec/layout/visibility tests for that representation.
3. Connect ordinary callable lowering to the representation.
4. Prepare the selected request at the runtime-driver boundary atomically.
5. Publish the final task key/class/policy and generation pin.
6. Connect typed host outcomes to Need state and replay schema 1.
7. Add cancellation/save/reload/non-dispatch negative tests.
8. Delete any provisional local bridge introduced during implementation before
   the cut is complete.

- Exact ordinary-call lowering to one typed intent; no string operation name or
  JSON/TOML payload.
- Wrong nominal layout, missing field, extra field, malformed nested identity,
  truncation, trailing bytes, exact limit, and one-over limit.
- Preparation success and every catalog/availability failure with atomic
  no-dispatch behavior.
- Two identical selected requests join once; every identity/catalog/provider/
  option/text coordinate change separates them.
- Compile-fail or visibility evidence that core and host cannot construct or
  consume the wrong TTS stage.
- Typed progress/result/error end-to-end through ordinary Need observers.
- Save blocker, recorded success injection, typed failure replay, omitted-byte
  replay failure, queued reload compatibility, and active generation pinning.
- Cargo metadata evidence for the final allowed/forbidden dependency graph.
- Applicable Tier 2 native/Web/headless/Agent checks for the completed broad
  runtime cut.
