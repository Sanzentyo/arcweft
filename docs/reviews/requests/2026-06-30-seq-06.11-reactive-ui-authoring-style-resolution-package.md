# Request: seq-06.11 reactive UI authoring style resolution package

## Sequence position

Seq06.11 follows the seq06.9 UI compositor work and the reactive UI style sample
added in `samples/reactive-ui-style`.

Treat these as already implemented substrate:

- compact product UI resource codecs from seq02.4.1;
- runtime text-control emission from seq06.4k.1.x;
- Takumi-to-direct wgpu lowering from seq06.2 and seq06.9;
- renderer-owned interaction style resolution in `arcweft-ui` and
  `arcweft-render-wgpu`.

Do not redesign the product AWFB section model, text input bridge, or compositor
scene contract unless current evidence shows a concrete flaw.

## Problem

Arcweft can store product UI style resources with both Arcweft-style and
CSS-style source identities. The retained UI crates can resolve hover/focus/
pressed style rules once a `UiStyleTable` and `InteractionState` exist.

The missing production path is the middle: native and web players do not yet
instantiate `UiProgramResource` / `UiStyleResource` into a frame-owned
`UiLayerOutput`, resolve authored Arcweft and CSS style layers together, and
feed that retained UI frame into the same renderer path as other player UI.

Because of that, `samples/reactive-ui-style` can carry the product resource
contract and show renderer interaction states separately, but it is not yet a
fully player-owned retained UI sample.

## Goal

Design and implement end-to-end product UI authoring style resolution for a
minimal retained UI frame:

- product `UiProgramResource` builds a retained UI fragment with semantics and
  event bindings;
- product `UiStyleResource` resolves ordered Arcweft-style and CSS-style layers
  into a typed `UiStyleTable`;
- live player interaction state drives `hover`, `active`, `focus_visible`, and
  `disabled` style selectors;
- native and web players consume the same frame data and render through the
  shared wgpu path, without DOM overlays or backend-specific style branches.

## Required decisions

- Define the owner of product-UI-to-retained-UI lowering:
  - likely a runtime/player adapter module, not `arcweft-bundle`;
  - keep `arcweft-bundle` Sans I/O and codec-only.
- Decide how `UiProgramInstruction` maps to `arcweft-ui::ViewFragment`:
  - element kind to fragment/container kind;
  - `style` string to stable `StyleId`;
  - `part` to exported/part metadata;
  - `BindHandler` to `EventBinding`;
  - semantic targets to `UiSemanticFragment`.
- Decide the first supported authoring style subset:
  - Arcweft style declarations already represented by `UiStyleResource` rules;
  - CSS selectors for element, part, descendant/child where representable;
  - interaction selectors for `:hover`, `:active`, `:disabled`;
  - element state selector for `:focus-visible`.
- Define cascade order when Arcweft and CSS layers both set the same property.
  The order must be deterministic and visible in evidence.
- Define diagnostics for unsupported selectors/properties. Unsupported values
  must fail or produce structured diagnostics; do not silently fall back to
  browser CSS, DOM text, canvas 2D, or Takumi raster output.
- Decide how player input routing updates retained UI `InteractionState` for
  native and web through the same source of truth.
- Decide whether disabled controls are non-interactive in this cut or only
  visual. If visual-only, document it as a non-goal and cut the behavior.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes,
  matching prior Arcweft sequence package style.
- Update `samples/reactive-ui-style` so the visible native/web sample uses the
  retained product UI path, not only dialogue choice UI.
- Native and web must share the same retained frame output and renderer path.
- Do not introduce hidden DOM UI, HTML controls, browser CSS rendering, canvas
  2D fallback, image snapshot fallback, or compatibility shims.
- Preserve `arcweft-bundle` as deterministic data/codec only.
- Keep authored CSS parsing/lowering behind the Takumi/adapter boundary.
- Keep stateful input routing in player/runtime-host layers, not in codecs.

## Tests to specify and implement

- Product UI resource fixture lowers to a deterministic retained fragment.
- Arcweft-style and CSS-style source layers both apply to the same button.
- Hover changes the same button background in native and web.
- Pressed state applies after hover in deterministic cascade order.
- Focus-visible adds outline without changing layout unexpectedly.
- Disabled selector applies and, if behavior is in scope, suppresses activation.
- Unsupported selector/property diagnostics are structured and test-covered.
- `samples/reactive-ui-style` builds to AWFB and has native/web visual smoke
  artifacts.
- No DOM overlay text/control appears in the web player sample.
