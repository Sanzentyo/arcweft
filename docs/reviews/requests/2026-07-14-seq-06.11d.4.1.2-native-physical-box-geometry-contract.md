# Request: seq-06.11d.4.1.2 native physical box geometry contract

Date: 2026-07-14

## Sequence position and reason for the split

This request follows seq-06.11d.4.1 core and the host/provider contract. The
core already resolves logical values into `ViewPhysicalBoxStyle`, but current
layout behavior intentionally consumes only the previously supported width,
height, translation, scale, and overflow subset.

The package did not define the box-sizing model, negative/auto constraints,
containing-block rules, edge interaction with gaps, inset positioning, clip
bounds, or geometry overflow policy. Those choices affect layout, input,
focus, scroll, rendering, and captures together and therefore require one
physical geometry contract before implementation.

This request is independently throwable. It must not redesign verified d.4.1
axis mapping or canonical computed slots unless evidence identifies a defect.

## Fixed substrate

- Logical sizes, min/max, padding, margin, inset, translations, and overflow
  resolve once into canonical physical slots.
- `ViewPhysicalBoxStyle` carries axes, physical sizes/edges/insets,
  translations, and X/Y overflow.
- Runtime projection and current player/renderer paths consume canonical
  physical values; consumer-local logical fallbacks are removed.
- Row, Column, flex direction, row-gap, and column-gap remain physical concepts.

## Required decisions

1. Exact physical box model and order for width/height, min/max, intrinsic
   measure, padding, border, margin, and scale.
2. Allowed signedness and behavior for negative sizes, padding, margins,
   insets, translations, and overflow arithmetic.
3. Containing-block selection and static/relative/absolute/fixed inset rules.
4. Margin behavior, including collapse or the explicit absence of collapse.
5. How gaps combine with margins and how subtree bounds include every edge.
6. Clip/paint/hit/focus/avoidance/scroll geometry and rounding/overflow policy.
7. Which fields are supported now versus represented-only, with typed
   unsupported-consumer diagnostics and no silent drop.
8. Revision/cache keys for measured and final physical geometry.

## Implementation order to specify

1. Freeze normative physical examples and arithmetic invariants.
2. Define typed intermediate/final box records and error policy.
3. Implement layout measure, constraints, edges, insets, and subtree bounds.
4. Route clip, render, pointer, focus, avoidance, and scroll through final bounds.
5. Add headless/native captures and cache/invalidation integration.

## Required tests

- Each physical field alone and in asymmetric combinations across all axis modes.
- Min/max conflicts, negative and overflow boundaries, nested boxes, gaps plus
  margins, positioned children, scale/translation, and clipped descendants.
- Pointer, focus ring, scroll-into-view, avoidance, and paint bounds agree.
- Exact fixed-point limits, deterministic rounding, cache hits, and invalidation.
- Unsupported represented-only fields fail explicitly until implemented.
- Native/headless/web typed geometry and capture parity.

## Constraints and non-goals

- No logical remapping outside the existing property owner/resolver.
- No browser/CSS box model by implication, no Takumi adapter, and no second
  layout engine or compatibility behavior.
- Do not reinterpret Row/Column/flex through box axes.
- Logical scroll-start anchoring is a separate request.

## Expected output

Produce a standalone design with exact Rust types and ownership, normative
geometry tables/examples, algorithms and overflow rules, typed errors,
dependency/cache/invalidation contracts, implementation sequence, and complete
layout/render/input/focus/scroll/capture tests.
