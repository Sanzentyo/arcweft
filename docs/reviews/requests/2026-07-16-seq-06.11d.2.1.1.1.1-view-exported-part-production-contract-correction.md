## Reproduced contradictions

### 1. Runtime `ViewId` versus the existing View registry

The package requires `ViewDefinitionRef(PublicId) -> ViewId(PublicId)` and a
private dense definition index. At the inspected basis, `arcweft-view::ViewId`
is the public dense key for `ViewRegistry`, entity ownership, anonymous
host-registered Rust Views, fragments, and Arcweft View calls. A Rust
`ViewDescriptor` may intentionally have no `PublicId`. Replacing that type with
`ViewId(PublicId)` cannot represent every current registry entry, while keeping
the numeric type violates the package's exact API and owner-stability tests.

Choose exactly one final type split and migration. If the answer introduces a
private/public registry index distinct from the semantic runtime owner, specify
which type is used by `ViewRegistry`, entities, `ViewCall`, `ViewProgram`,
product definitions, mounts, save snapshots, and public evidence. Anonymous
Rust Views and public Rust Views both need an explicit outcome.

### 2. SourceMap API versus the declared dependency budget

The package requires
`arcweft_bundle::SourceMapSection::try_from_documents(&SourceDocument)` but the
inspected `arcweft-bundle` manifest has no `arcweft-source` dependency. The same
package states that the only crate dependency addition is
`arcweft-view -> blake3`. Rust cannot name `SourceDocument` at the proposed
bundle API without a direct dependency, and a compiler-owned wrapper would no
longer be the exact declared API.

Choose one owner and dependency graph. Specify whether `arcweft-bundle` gains
the path dependency, whether a lower product-source input type is owned by the
bundle and constructed from `SourceDocument` in the compiler, or whether the
constructor moves. Preserve one canonical multi-source binary section, exact
byte identity, complete-product validation, Sans I/O, and no adapter registry.

### 3. Removed syntax diagnostics versus repository policy

The package requires permanent spelling-specific diagnostics and exact tests
for `part = ...`, `.export_part(...)`, shorthand, `exportparts`, and other
removed/unreleased forms. Current `AGENTS.md` requires a final parser removal to
retain no dedicated old-spelling recognizer, diagnostic, CST/AST kind, or
spelling-specific test. Those historical forms must instead fail through
ordinary current-grammar parsing/recovery, with only absence of an executable
typed node retained as behavioral evidence.

Correct GRA-017 through GRA-021, the parser error inventory, deletion state,
and completion accounting to obey repository policy. Do not ask production to
restore a temporary recognizer after removal has already been demonstrated.
