# Seq-02.5 Patch v2 Compatibility and Target Materialization

## Sequence Position

This request follows the core product resource codec requests, especially
seq-02.1 and seq-02.2. It may begin after enough section-family fingerprints
exist to classify runtime-facing changes, but it must not finalize patch v2
compatibility labels without the migrated section schemas it references.

This request supersedes only the under-specified patch-v2 portion of
`2026-06-24-seq-02-product-artifact-patch-signing.md`; it must preserve the
seq-02 first-cut behavior for raw section-kind preservation and artifact
identity unless current evidence proves a flaw.

## Why This Split Is Needed

The current patch artifact implementation supports local/dev materialization,
embedded changed-section payloads, metadata-only external descriptor changes,
and target content-root validation. Product patch v2 needs stronger typed
compatibility fingerprints, manifest rewrite rules, target materialization
state, and rollback/error behavior before seq3 live-patch work can rely on it.

## Required Decisions

1. Define the patch v2 artifact schema and version negotiation policy.
2. Define section-family compatibility fingerprints and how they are derived
   from compact resource codecs, AWBC functions, external descriptors, and
   manifest fields.
3. Define the compatibility classification rules for `content-only`,
   `code-compatible`, `code-generational`, and `restart-required`.
4. Define target materialization state transitions, including descriptor merge,
   embedded payload replacement, external descriptor mutation, manifest rewrite,
   target root validation, and failure rollback.
5. Define how patch v2 references base artifact identity, target artifact
   identity, base content root, target content root, and raw section-kind codes.
6. Define how patch v2 handles unknown optional section kinds, unknown required
   section kinds, and section families not yet migrated to compact codecs.
7. Define adapter boundaries for applying, inspecting, storing, and rolling
   back materialized targets.
8. Define how seq3 generation/windowed live patch should consume patch v2
   compatibility labels without re-deriving them ad hoc.

## Implementation Order To Specify

1. Add patch v2 data model and codec while preserving current patch v1 tests.
2. Add compatibility fingerprint derivation for AWBC and migrated resource
   section families.
3. Add target materialization state machine with manifest rewrite hooks, but
   keep signing-key access out of Sans I/O crates.
4. Add compatibility labels to runtime-driver/session patch inspection.
5. Add rollback/error tests at adapter boundaries.
6. Add CLI/native-player smoke paths for patch v2 inspection and local apply.
7. Define deprecation or coexistence policy for patch v1 artifacts.

## Tests To Specify

- deterministic patch v2 bytes;
- patch v2 decode rejects malformed or unsupported required fields;
- patch classification for AWBC body-only, AWBC interface, runtime type,
  entrypoint, adapter requirement, content, presentation, asset, and external
  descriptor changes;
- materialized target descriptor and content-root correctness;
- raw unknown optional section-kind preservation through patch v2;
- metadata-only external descriptor behavior when allowed;
- rollback after missing payload or validation failure;
- runtime-driver consumes compatibility labels instead of local heuristics;
- source gates against ad hoc compatibility recomputation in players.

## Constraints

- Keep `arcweft-bundle` Sans I/O.
- Do not perform filesystem, network, cache, clock, or signing-key operations
  inside patch v2 core materialization.
- Do not imply that changed target bytes keep the base signature valid.
- Do not block local dev patch inspection on release signing.
- Preserve deterministic content roots and artifact identities.

## Non-Goals

- AWFR release archive format and fetch-cache policy, except for fields patch
  v2 must expose to seq-02.6.
- Signing-policy redesign, except for signature invalidation hooks.
- Completing every resource family codec if some are explicitly marked future
  by seq-02.4.
- Seq3 live-patch runtime implementation.

## Expected Output

Return a package with:

- patch v2 schema;
- compatibility fingerprint rules;
- materialization state machine;
- crate ownership map;
- implementation cuts;
- exact tests and CLI/runtime smoke commands;
- clear relationship to seq3 live-patch consumption.
