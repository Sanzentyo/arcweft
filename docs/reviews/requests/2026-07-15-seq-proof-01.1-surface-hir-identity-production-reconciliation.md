## Fixed language decisions

- Remove `borrow EXPR as NAME: TYPE { ... }` completely. There is no parser,
  CST, AST, HIR, lint, formatter, or tooling compatibility branch.
- Ordinary lexical scopes use prefix `&expr`, `&mut expr`, and `*expr`.
- `let mut x` controls binding reassignment; `&mut T` controls referent
  mutation. Shadowing creates a distinct generation-stable local identity.
- Reference types carry owned `BorrowKind::{Shared, Mutable}`. Lifetime/region
  syntax remains typed and must not be recovered by parsing display strings.
- Statement-position `assert.prove(...)`, `assert.check(...)`, and
  `assert.debug(...)` lower to one explicit typed AST/HIR assertion node.
- `assert.prove` has no runtime instruction; `assert.check` is a deterministic
  runtime guard whose facts exist only on its success edge; `assert.debug`
  cannot discharge release safety.
- Add typed `predicate` declarations and ordinary-name `proof` declarations.
  Hand-authored names are ordinary symbols; artifact IDs are derived.
- `calc` is not language syntax and removed borrow/proof forms fail through
  structured parser recovery.
- No string reparsing survives HIR lowering.

## Current seams that the contract must replace

Latest main still has `FlowItem::BorrowBlock`, `BorrowBlock`, `HirBorrow`,
`HirFlowItem::Borrow`, CST borrow classification, parser/lint/source-range
branches, and stable language documentation showing the removed block.
Expression parsing already has infix operators whose `&` and `*` tokens overlap
the new prefix forms. Line-plan syntax also has an unrelated `Assert` item.
Current HIR project/id contexts do not expose the complete LocalId/ScopeId/
expression-ID and source-generation contract required by later dataflow cuts.

These are evidence and deletion inventory, not compatibility requirements.

## Required decisions

Every section below must choose one exact Rust API, owning module, visibility,
source-range rule, recovery rule, deletion point, and direct test. `TBD`,
alternatives, or implementation-selected behavior make the result incomplete.

### 1. Prefix and infix grammar

Freeze tokenization, precedence, associativity, whitespace/newline behavior,
and CST/AST shape for prefix `&`, `&mut`, and `*` against multiplication,
bitwise/logical operators, postfix call/index/field chains, unary operators,
casts, ranges, assignments, closures, patterns, and reference types. State
exact malformed-input recovery and ranges for missing operands and split
`& mut`/`&mut` forms.

### 2. Owned reference representation

Define syntax and HIR reference-type and borrow-expression types using the one
owned `BorrowKind`. Decide where lifetimes/regions live, how omitted regions are
represented, and how dereference and borrow expressions retain exact ranges and
child IDs. No local extension trait or string tag is allowed.

### 3. Stable identity model

Define typed `LocalId`, `ScopeId`, expression/statement/item IDs, and any
source-name generation type. Specify allocation owner, equality/order/hash,
shadow generations, nested scopes, closure parameters/captures, pattern
bindings, desugaring, recovery nodes, module revisions, incremental reparse,
cache keys, serialization status, overflow, and stale-ID rejection. State which
IDs are source-stable and which are compilation-session-only.

### 4. Removed borrow-block deletion and recovery

Inventory and delete CST classification, syntax AST, parser entrypoints, range
walkers, pipe-scope logic, lints, HIR types/lowering/project walkers, sema and
runtime-plan consumers, docs, fixtures, formatter/tooling nodes, and exports.
Define one structured diagnostic code/range/recovery shape. Do not silently
interpret the removed block as a call, label, or generic malformed block.

### 5. Typed assertion surface

Define `AssertionMode`, AST/HIR assertion nodes, condition list/arity, trailing
comma rules, statement-only contexts, range ownership, and lowering. Resolve
the name and ownership conflict with line-plan `Assert`. Freeze proof-body,
ordinary-body, compile-time/runtime, release/debug, short-circuit, failure,
diagnostic, and later CFG fact-edge behavior without implementing the proof
kernel in this cut.

### 6. Predicate and proof declarations

Freeze grammar and typed AST/HIR for names, generics, parameters, return/value
form, `requires`/`ensures`, expression versus block bodies, visibility,
qualification/imports, recursion, overload/collision behavior, attributes,
source ranges, and recovery. Define direct replacement of current authored
`proof @...` and other provisional forms with no dual reader or alias period.

### 7. Lowering and caller migration

Give the exact syntax-to-HIR context API and atomic failure model. Inventory all
parser facades, AST visitors, CST tools, source-range walkers, HIR lowerers and
walkers, project/module constructors, cache facts, formatter, CLI/LSP tooling,
tests, examples, and stable design docs. State the one cut where obsolete
types and root re-exports disappear.

### 8. Limits and structure

Set hard limits for prefix depth, expression/statement/item count, scopes,
locals per scope/module, proof clauses, assertion conditions, predicate/proof
parameters, diagnostics, and identity generations. Exact succeeds and one-over
fails deterministically. Remeasure changed/largest Rust files and prescribe
responsibility modules before any threshold error; do not append the whole
surface and ID system to a large parser, `lib.rs`, or model file.

## Direct test matrix

- Prefix borrow/deref nested with call, index, field, unary, infix `&`/`*`,
  comparisons, ranges, assignment, closure, and multiline expressions.
- Shared/mutable reference types with explicit/omitted regions and malformed
  `&mut`; AST/HIR round-trip preserves kind, IDs, and exact ranges.
- Removed borrow blocks and `calc` return stable structured diagnostics and
  recovery spans, including nested/missing-close forms.
- Shadowed names, destructuring, nested scopes, closure parameters/captures,
  recovery nodes, and incremental unchanged/replaced subtrees obey the chosen
  LocalId/ScopeId/source-generation rules; stale and overflow IDs fail typed.
- All three assertion modes in every allowed/disallowed context; zero/one/many
  conditions, trailing comma, malformed call, release/debug policy, and the
  line-plan Assert distinction.
- Predicate/proof declarations cover qualification, generics, clauses,
  expression/block bodies, duplicates, visibility/imports, recursion, malformed
  headers/bodies, and ordinary-name collisions.
- Exact and one-over every limit, deterministic diagnostic ordering, and no
  partial HIR/cache mutation after a failed lower.
- Tests use parser/HIR/tooling APIs and compile evidence. No test searches
  implementation or documentation source text.
