## Split rationale

The parent request selected the attached application source/HIR owner. This
correction owns the missing callee-side declaration and ABI. It is separate
from CharacterDialogue line identity, but it cannot be split into independent
syntax, schema, and runtime questions: the selected declaration spelling
determines the binding identity, presence semantics, schema digest, call-site
mapping, ABI type, default owner, and runtime content fragment.

## Concrete contradiction

The maintained language admits project/user content callables through
`DeclaredRole`, while production has no typed producer for that role. Allowing
`#call(...)[body]` by inspecting only a `ContentCall` site, a return type, a
callee name, or the surrounding body role would create an undeclared success
path. Rejecting all generic bodies would leave the maintained surface
unimplemented. Adding a copied registration side table or an attribute-name
scan would create a second declaration authority.

Two implementation-time contradictions are part of this same request and are
not deferrable follow-up work:

- an ordinary checked expression transcript commits referenced callable
  interface digests, so using that digest for a declaration-owned default that
  is itself committed by the callable interface creates a self/mutual digest
  cycle; banning calls or recursion and publishing a preliminary interface
  digest are prohibited resolutions; and
- the core content carrier can store `RuntimeFunctionValue` and the structured
  `RuntimeFunctionSite` is evolving to expression/executable bodies, but
  ordinary project calls still reserve `RuntimePureHelper`, lower to
  `PureCall`, and select support from raw HIR effect-clause spelling. Native
  executable-site activation is reveal-only and has no typed result
  continuation. An effectful default therefore has no legitimate callee
  execution path even though its checked effects are accepted. A carrier or
  default ABI without one ordinary native/AWBC executable-call authority is
  incomplete.

The returned contract must close default equivalence for self/mutual
recursion, generic instantiation, effects, and cross-module calls, and must
connect reveal callbacks to an effectful function/scheduler authority without
a content-specific interpreter. Exact callback effect sets, AWBC
`ApplyFunction`/save reuse, and atomic reveal activation are required.
The same result must place the conditional default prologue and authored body
in one group-aware `RuntimeFunctionSite` execution chain, define typed
same-fiber call/return continuation for effectful or suspending project calls,
and delete project-function `RuntimePureHelper`/`PureCall` authority. Banning,
dropping, or inferring default effects is prohibited.

Curried runtime execution must not encode nonterminal groups as concrete
function sites. The final boundary is a typed `ProjectContinuation` carrying
one stable declaration/prefix lineage plus once-evaluated prefix values. Each
checked later call owns the only typed transition:
`Continue(result_abi, next_group)` for another partial group or
`Invoke(closed_instance)` at the terminal group. A closed instance is keyed
only by `(RuntimeCallableId, CallableInstantiationDigest,
CallableGroupIndex)` and owns a flattened prefix/current ABI plus a
substitution-backed body/local/type projection. That projection must consume
the exact HIR executable-owner partition and exclude nested closure bodies;
scope-descendant approximation, callee-value inference, runtime registry
lookup, application digest, and first-call adoption are prohibited.

Implementation audit also established the following non-optional boundaries:

- `Direct` is a unit input. A stable continuation identity does not exist
  until a checked nonterminal outcome issues it. Each continuation input owns
  the exact callee expression and expected lineage/function/prefix ABI; each
  `Continue` owns the complete next ABI and `next_group`.
- One source-ordered physical operand row retains each checked ABI
  destination. Construction validates the ABI permutation without sorting or
  dropping that row. Logical parameter materialization indexes the source row,
  not ABI positions; RestPositional packs its physical sources into one
  `Vec<T>` binding. Target-specific structural calls must ANF-materialize this
  same row before interpreting operands by semantic role.
- A pure, non-suspending project call still requires the Flow control algebra.
  Final sema seals an executable control role independently from effects and
  suspension for ordinary functions, closures, and attached defaults.
  `ExpressionFunctionSite` is legal only for an expression-compatible,
  non-suspending, empty-effect executable; every project-call-containing body
  selects `ExecutableFunctionSite`.
- Ordinary parameters with authored defaults remain rejected by the current
  language contract. Attached defaults alone own a declaration-scoped default
  FunctionSite, exact effects/suspension/control role, and exact logical
  capture sources from continuation-prefix/current-group values. Arbitrary
  parameter patterns bind through the common function input-pattern prologue;
  a simple-local-only restriction is prohibited.
- `ProjectCall` is a suspension-capable Flow/AWBC terminator with no
  synchronous expression or AOT-linear fallback. Return completes the nearest
  function-call frame; break/continue cannot cross it; nonlocal Goto unwinds
  frames and cleanups once; function fallthrough is invalid.

## Required decisions

### 1. One canonical declaration surface

Compare and choose exactly one source form:

- an item attribute that introduces a body binding;
- an ordinary `DialogueContent` value parameter annotated as attached; or
- a dedicated attached-content parameter owned by the callable signature.

Specify exact tokens, CST/attachment types, recovery, formatter output,
source roles, allowed callable owners, curried-group placement, binding rules,
role spellings, duplicate handling, and whether removed or alternate spellings
exist. No parser-name or attribute-string fallback is permitted.

### 2. Presence and default semantics

Define required, optional, and defaulted declarations. Decide the callee-local
type, call-site omission behavior, default-expression owner and scope,
evaluation order, effects, captures, and whether trait requirements, impl
methods, inherent methods, and extern capabilities admit each presence.

### 3. Exact HIR and callable schema owner

Define final Rust shapes for the HIR declaration, role and presence enums,
binding `LocalId`, default `ExprId`, source roles, callable-symbol projection,
schema group coordinate, and schema execution policy. The project callable
builder must issue the only `RuntimeContent + Declared(role)` schema row; no
consumer may derive it from a result type or call site.

### 4. Prepared and checked call mapping

Define the exact attached operand algebra for absent, present, and defaulted
cases. Specify the raw HIR content identity, accepted stable coordinate,
terminal callable group, collision rules, candidate rejection versus invariant
failure, C1/C2 seal order, atomicity, and how body-role admission joins the
selected schema without a second projection.

Also distinguish this attached-body channel from `DialogueLine`: a line owns a
separate semantic content operand. The resolution must state the typed
site-family/HIR-owner validation and routing boundary so an exact line is not
misclassified as malformed attached metadata.

### 5. Runtime ABI destination

Choose the exact ABI position and runtime type for required, optional, and
defaulted attached content. Decide whether the attached operand appears in the
ordinary runtime-operand iterator, how its distinct source family is retained,
how caller and callee independently derive the same position, and how partial
applications avoid applying the terminal attached contract early.

### 6. Runtime content fragment and effects

Define one runtime fragment fact carrying the content template, value-binding
programs, reveal-time effect programs, and their capture bindings. Specify
Content-result nesting, stable fragment identities, recursive sealing,
evaluation order, plan/value/AWBC carriers, VM behavior, and deletion of every
split template/value/effect scan that the final fact replaces.

### 7. Digests, validation, and diagnostics

Specify every v1 transcript field. Snapshot-local raw IDs must not enter stable
digests. Provide declaration, schema, checked-call, checked-content, runtime
fragment, callable-interface, plan, and AWBC validation. User-authored role or
presence failures must produce structured diagnostics, not internal invariant
errors.

### 8. Closed matrices and implementation order

Return an owner/presence/role/site/result/ABI validator matrix, an executable
acceptance matrix, and a deletion-driven implementation order that never
commits a temporary generic-body reject, fallback, or dual authority.
