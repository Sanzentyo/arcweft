# Request: Trusted-axiom surface final decision

## Sequence position

This is Lang-01.6, split from the 2026-07-16 top-level declaration reduction.
It resolves one direct contradiction between that direction and
proof-concurrency v6.1.1. All proof syntax/HIR/runtime work that is independent
of trusted axioms may continue while this request is designed.

## Why this split is needed

The language audit retained `proof` and `trusted axiom` because explicit trust
boundaries should remain visible and auditable. The active proof-concurrency
v6.1.1 contract instead states that `TrustedAxiomItem` is not part of the final
typed inventory and requires its provisional types, parser, tests, and docs to
be deleted in Stage 4. Both cannot be final.

## Required decisions

1. Decide whether authored Arcweft source may declare a trusted axiom.
2. If yes, specify why an ordinary proposition plus signed/trusted manifest
   evidence cannot express the boundary, and give the exact typed syntax, HIR,
   verifier, trust-policy, bundle, inspection, and release behavior.
3. If no, specify the sole external owner for trusted assumptions (for example
   signed verifier policy or host capability metadata) and how source proofs
   reference accepted assumptions without an author declaration.
4. Define provenance, package signature, visibility, import/reexport,
   revocation, versioning, audit output, and release-policy failure behavior.
5. Distinguish logical propositions, proved theorems, admitted assumptions,
   host facts, and capability contracts; do not collapse them into strings.
6. State the exact effect on proof-concurrency Stage 4 inventory and deletion
   gates.

## Implementation order to specify

1. Final trust/provenance model and attack analysis.
2. Author-source versus manifest ownership decision.
3. Typed HIR/verifier/bundle/audit contract.
4. Release and revocation behavior.
5. Direct implementation or deletion of `TrustedAxiomItem` and all callers.
6. Tooling and documentation migration.

## Tests to specify

- Untrusted source cannot create trusted proof evidence accidentally.
- Provenance/signature/revocation/version faults fail closed.
- Imports and reexports cannot launder an admitted assumption into a theorem.
- Runtime and public audit output distinguish proved and externally trusted
  facts.
- If removed, `trusted axiom` has no CST/AST/HIR kind, compatibility parser,
  dedicated removal diagnostic, or source gate.
- If retained, its typed trust boundary is exercised end to end rather than
  merely preserved in syntax.

## Constraints

- Do not stop unrelated proof Stage 1-3 work while this decision is pending.
- No compatibility aliases, dual trust paths, hidden string assumptions, or
  source-spelling scanners.
- Keep verifier and release policy deterministic and fail-closed.
- Do not redesign typed proposition/proof identity without concrete evidence.

## Expected output

- One final keep/remove decision with threat-model rationale.
- Exact source/manifest syntax and typed ownership.
- HIR/verifier/bundle/release/tooling contracts.
- A direct implementation/deletion order and negative security tests.
