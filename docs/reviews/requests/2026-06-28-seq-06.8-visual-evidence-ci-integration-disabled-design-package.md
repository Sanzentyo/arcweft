# Seq-06.8 Request: Visual Evidence CI Integration Disabled Design Package

## Sequence Position

This follows seq06.5 selected capture metadata, seq06.6 visual smoke/golden
fixtures, and seq06.7 exact native golden drift stabilization.

Seq06.8 should design the CI integration boundary for visual evidence without
turning on GitHub CI jobs by default.

## Important CI Constraint

If "CI" means GitHub Actions, this request is design-only and disabled by
default.

Do not add an active `.github/workflows/*.yml` file. Do not add `push`,
`pull_request`, `schedule`, or active `workflow_dispatch` triggers. If a
workflow draft is useful, place it under a non-active location such as:

```text
docs/implementation/ci-drafts/visual-evidence.disabled.yml
```

or inside the returned package under:

```text
ci-drafts/visual-evidence.disabled.yml
```

The package must include an explicit activation checklist for a future human
change, but seq06.8 itself must not enable GitHub CI.

## Problem

Arcweft now has visual smoke fixtures, selected capture metadata, exact native
golden drift classification, and artifact retention rules. The repository still
needs a coherent visual-evidence CI design so future milestone/release jobs can
run the right tiers, upload useful artifacts, and avoid conflating environment
blockers with rendering regressions.

## Request

Produce a final zip package containing a disabled CI integration design for
Arcweft visual evidence.

The package may include docs, disabled workflow drafts, Justfile command maps,
artifact schemas, and validation notes. It must not enable CI execution in the
repository.

## Required Inputs

- Current Arcweft `main`.
- `docs/implementation/seq-06.5-selected-capture-resource-metadata-2026-06-28.md`.
- `docs/implementation/seq-06.6-visual-smoke-golden-fixtures-2026-06-28.md`.
- `docs/implementation/seq-06.7-exact-native-golden-drift-stabilization-2026-06-28.md`.
- `docs/implementation/test-execution-policy.md`.
- `fixtures/visual-smoke-goldens/exact-native-golden-policy.json`.
- `fixtures/native-golden-drift/`.
- Existing `just` recipes for visual smoke/golden/artifact generation.
- Current repository GitHub/CI conventions, if any.

## Required Decisions

1. Which visual evidence jobs belong to fast PR checks, milestone/release
   checks, and manual evidence runs.
2. Which commands produce smoke metadata only versus exact pixel comparisons.
3. How selected object/layer capture metadata should be uploaded and reviewed.
4. How exact native golden status classes map to future CI results:
   `expected_skip`, `environment_not_pinned`, `environment_blocker`,
   `baseline_drift`, and `hard_visual_regression`.
5. Which Windows environment requirements are mandatory before an exact native
   golden job can count as milestone evidence.
6. What artifacts must be retained for each visual tier.
7. How to name artifact bundles so a single fixture drift can be reviewed.
8. How disabled GitHub workflow drafts should be stored without activation.
9. What activation checklist a maintainer must follow later.
10. Whether any local `just` aliases or docs are needed now without enabling CI.

## Acceptance Criteria

- No active GitHub Actions workflow is added or modified.
- The design clearly separates fast local/workspace validation from Tier 2
  exact native golden validation.
- The disabled workflow draft, if included, cannot run from GitHub as checked
  in.
- Artifact paths, upload groups, status classes, and review expectations are
  specified.
- Exact native golden CI remains Windows/pinned/font/`imq` gated.
- The design works whether seq06.7.1 promotes a new PNG baseline or defers it.
- Future activation steps are explicit and require a separate human-reviewed
  change.

## Validation To Run Or Specify

- `git diff --check`.
- Source scan proving no active `.github/workflows/*.yml` file was added or
  modified by this package.
- If docs/Justfile drafts are included, run formatting/source checks applicable
  to those files.

## Non-Goals

- Enabling GitHub Actions.
- Changing exact native golden thresholds.
- Promoting PNG baselines; that is seq06.7.1.
- Moving exact native goldens into default `just test-workspace`.
- Implementing new capture fixtures.

## Parallelization Guidance

This can be designed in parallel with seq06.7.1. Do not make seq06.8 depend on
a specific baseline-promotion decision. The CI design should consume the stable
seq06.7 status taxonomy and artifact retention contract.
