# Request: seq-06.13d CSS box-shadow lowering package

## Sequence Position

Seq06.13d follows seq06.13b. Seq06.13b added the renderer/compositor substrate:
`UiBoxShadow`, `UiBoxShadowList`, `UiBoxShadowPassPlan`, and the shared WGSL
`PASS_BOX_SHADOW` path.

This request must not redesign that renderer substrate unless current
implementation evidence shows a concrete flaw.

## Problem

The renderer can now draw Arcweft-owned box-shadow passes, but the Takumi CSS
adapter still does not extract CSS `box-shadow` values into
`UiCompositingEffects::box_shadows`.

Current adapter behavior:

- `box-shadow` invalidates as compositing, not paint-only;
- `compositing_effects_from_takumi` emits `UiBoxShadowList::default()`;
- CSS coverage still reports `box-shadow` as not fully supported because no
  typed value lowering exists.

Therefore authored CSS can mention `box-shadow`, but it will not yet appear in
the `UiScene` compositor graph.

## Goal

Design and implement typed CSS/Takumi `box-shadow` lowering into
`UiBoxShadowList` without adding any DOM, browser CSS, canvas, CPU raster, SVG
filter, or bitmap fallback path.

## Required Decisions

- Identify whether Takumi exposes parsed/computed `box-shadow` in
  `ComputedStyle`. If it does, lower that typed model directly.
- If Takumi does not expose it yet, specify the smallest Takumi-facing typed
  computed-style extension needed for:
  - outer shadows;
  - inset shadows;
  - multiple shadows;
  - spread radius;
  - blur radius;
  - per-shadow color;
  - rounded border radius source.
- Define how border radius is selected for each shadow when CSS supplies
  per-corner radii but `UiBoxShadow` currently carries one scalar radius.
- Define coverage/diagnostic behavior for unsupported forms such as malformed
  shadow lists, unsupported color functions, and inset shadows.
- Define whether `box-shadow` should graduate to direct CSS ready status only
  after end-to-end lowering and compositor plan tests pass.

## Implementation Requirements

- Keep CSS parsing/cascade in Takumi or typed Takumi adapter code; do not parse
  production CSS with ad hoc string scanning in render code.
- Lower computed values into `UiCompositingEffects::box_shadows`.
- Keep `filter: drop-shadow(...)` as a distinct `UiFilter::DropShadow` path.
- Preserve seq06.13b's renderer pass order: box-shadow before children, then
  filters/clip/mask/blend.
- Add typed diagnostics for unsupported `box-shadow` values instead of silently
  dropping non-empty shadows.
- Update CSS coverage so `box-shadow` no longer reports as a gap once lowering
  is complete.

## Tests To Specify And Implement

- CSS with one outer shadow lowers to a `UiBoxShadowList` with matching offset,
  blur, spread, color, and radius.
- Multiple shadows preserve CSS list order in `UiBoxShadowList`, and the
  compositor plan paints them back-to-front.
- Negative spread lowers and plans deterministically.
- Transparent shadow is canonicalized to an empty list or no pass.
- Inset shadow emits the seq06.13b typed diagnostic unless this package also
  implements inset rendering.
- `filter: drop-shadow(...)` still lowers to `UiFilter::DropShadow` and does not
  populate `box_shadows`.
- CSS coverage/direct support status changes only when lowering is truly
  end-to-end.
- Native/web visual smoke fixture demonstrates authored CSS `box-shadow` through
  the normal player path.

## Expected Output

Return a zip package named like:

```text
arcweft-seq06.13d-css-box-shadow-lowering-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- Takumi/Takumi-adapter overlay edits;
- focused Rust tests;
- CSS/native/web smoke fixtures;
- validation notes with commands and known platform limits.

## Non-goals

- Do not change the seq06.13b WGSL box-shadow shader unless evidence shows a
  renderer bug.
- Do not implement transitions, animations, advanced clip paths, or advanced
  masks here.
- Do not add source-string fallback gates; use typed tests and implementation
  notes for the no-fallback rule.
