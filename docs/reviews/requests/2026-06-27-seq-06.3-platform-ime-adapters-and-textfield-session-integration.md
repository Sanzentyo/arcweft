# Request 06.3: Platform IME Adapters and TextField Session Integration

## Sequence Position

This follows the seq06.1 Sans I/O text-input session model. It can proceed in
parallel with seq06.2 renderer lowering once TextField layout/caret geometry is
available. It does not depend on seq02.4.1 product View resource codecs.

## Request

Implement Japanese-capable text input for `TextField`, `TextArea`, and
`SecureField` across platform adapters using the Arcweft text-input session
protocol. This request covers composition/preedit display, surrounding text,
candidate geometry, focus transactions, secure redaction, and platform-specific
IME constraints.

## Required Decisions

1. How each platform adapter maps native IME events to `TextInputOperation`
   batches and `TextInputSessionId`.
2. How stale-session commits, delayed composition updates, and focus-generation
   mismatches are rejected.
3. How platform APIs request surrounding text, character bounds, selection, and
   candidate/caret rectangles.
4. How composition-on-blur policies commit/cancel/platform-default composition
   during focus transitions.
5. How keyboard shortcuts are suppressed while IME consumes keys.
6. How secure fields disable or redact surrounding text, reconversion, clipboard,
   Agent observe, replay, and capture metadata.
7. How vertical writing and transformed/scrolled TextField geometry converts from
   text-local to viewport/screen coordinates.
8. How Web uses standards-based EditContext or another explicit platform text
   API path without a hidden textarea fallback in this request.
9. How mobile Android/iOS batch edits, surrogate pairs, and delete-surrounding
   requests preserve grapheme and UTF-16/UTF-8 index correctness.

## Required Implementation Order

1. Replace committed-string `TextInput` routing with session-scoped text-input
   batches in presentation and runtime-host dispatch.
2. Add TextField editor core: committed document, selection, composition overlay,
   visual buffer, revision, undo grouping, and Binding commit policy.
3. Add candidate anchor and character-bound snapshot updates from text layout.
4. Add native desktop baseline adapter hooks:
   - Windows TSF text store or equivalent adapter;
   - macOS `NSTextInputClient` adapter;
   - Wayland text-input-v3 adapter where available.
5. Add mobile adapter hooks:
   - Android `InputConnection`;
   - iOS `UITextInput` traits and selection/caret geometry.
6. Add Web text-input adapter path using explicit browser editing APIs; if the
   platform cannot support IME without fallback, report unsupported capability
   rather than silently adding a hidden DOM textarea fallback in this request.
7. Wire secure-field redaction into Agent observe/capture/replay.
8. Add visual and protocol tests.

## Tests To Specify

- Japanese `nihongo` -> `にほんご` -> `日本語` composition/commit trace;
- candidate updates do not mutate Binding before commit;
- preedit arrow navigation and backspace;
- Escape cancel and Enter/Space commit;
- stale session delayed commit rejection;
- focus-preserving toolbar click;
- modal forced blur composition policy;
- window deactivation commit/cancel policy;
- delete-surrounding around emoji and combining marks;
- secure-field redaction for value and composition;
- candidate rectangle after scroll/transform;
- platform fixture traces for TSF/AppKit/Wayland/Android/Web.

## Constraints

- Do not insert characters from `keydown` directly.
- Do not store OS handles in Sans I/O crates.
- Do not mutate Binding for preedit updates.
- Do not add a hidden textarea fallback in this request.
- Do not expose secure text or preedit in Agent/replay/capture.

## Non-Goals

- Implementing Takumi CSS layout/wgpu primitive lowering.
- Product resource codecs.
- Rich document editing beyond TextField/TextArea text editing semantics.
