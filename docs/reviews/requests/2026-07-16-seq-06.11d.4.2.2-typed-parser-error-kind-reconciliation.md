# seq-06.11d.4.2.2 — typed parser error-kind reconciliation

## Sequence position

This request follows `seq-06.11d.4.2.1` native environment Style-condition
production reconciliation. It is independently throwable and must not redesign
the environment grammar, its range-backed AST, HIR recovery records, or the
checked presentation/view environment substrate unless current implementation
evidence demonstrates a concrete defect.

## Why this split is required

The d.4.2.1 package assumes that `arcweft-lang-syntax` already owns a
repository-wide `ParseErrorKind` enum with inherent `code()` and `label()`
methods. The current parser instead owns:

```rust
pub struct ParseError {
    code: String,
    range: TextRange,
    expected: Vec<String>,
    found: Option<String>,
    message: String,
    recovery: Vec<RecoverySuggestion>,
}
```

Parser sites construct errors through `ParseError::coded`, `with_code`, and
ordinary `ParseError::new`. There is no `ParseErrorKind` symbol or existing
typed-kind migration to extend. Introducing the package's proposed enum only
for Style environment errors would create two incompatible diagnostic ownership
models; migrating every parser site inside d.4.2.1 would materially expand that
feature package and make its completion depend on an unrelated repository-wide
redesign.

The d.4.2.1 implementation therefore uses stable
`syntax.parse.style_environment.*` codes and exact typed ranges through the
current `ParseError` owner. This request decides the repository-wide final
diagnostic model.

## Required decisions

Choose exactly one final direction:

1. **Introduce a repository-owned `ParseErrorKind`.** Specify every existing
   parser diagnostic family that becomes a variant, how open-ended payloads are
   represented, the complete `code()`/`label()` mapping, whether `ParseError`
   stores the kind instead of `String`, and the atomic migration order for CLI,
   LSP, Agent, tests, and diagnostic serialization.
2. **Keep the current coded `ParseError`.** State that stable code strings are
   the canonical typed transport discriminator, specify an owned constructor or
   code type if raw strings are too permissive, and remove assumptions that an
   enum already exists from later design packages.

The answer must compare at least:

- exhaustiveness and discoverability for producers and consumers;
- plugin/feature-specific diagnostics and forward compatibility;
- allocation/serialization impact of the current owned `String`;
- migration churn across all parser modules and exact-code tests;
- whether labels are transport data or renderer-owned presentation;
- how structured payloads remain accessible without parsing messages or codes.

## Implementation order to specify

1. Inventory current `ParseError` constructors, code spellings, diagnostic
   adapters, and exact-code assertions from the current checkout.
2. Define the final owner and public API without an extension trait, local
   wrapper, compatibility alias, or dual representation.
3. Migrate producers in reviewable parser-family cuts while keeping the
   workspace compiling.
4. Migrate CLI/LSP/Agent and structured-diagnostic consumers.
5. Delete the discarded representation and all transitional adapters.
6. Run focused parser/diagnostic tests, workspace check/clippy, and the
   structural audit.

## Tests the contract must specify

- exhaustive code mapping for every final typed variant or code constant;
- exact range, expected/found, recovery edits, and structured payload retention;
- diagnostic serialization and CLI/LSP/Agent projection parity;
- unknown/future-code behavior if the coded model remains extensible;
- compile-fail or visibility evidence for constructor restrictions where
  appropriate;
- environment errors covering every
  `syntax.parse.style_environment.*` spelling without source-text gates;
- absence of message parsing and of a simultaneous legacy/new reader.

## Constraints

- No source gates, source spelling scans, extension traits, deprecated aliases,
  dual readers, compatibility modules, or string-to-enum fallback tables.
- Do not change the accepted native environment grammar or reintroduce CSS,
  Takumi, media queries, or general-expression parsing for environment values.
- Preserve current exact range and recovery behavior throughout migration.
- Treat this unreleased internal parser contract as directly replaceable once a
  final repository-wide direction is selected.

## Expected output

Return an implementation-ready final contract containing the chosen ownership
model, complete public type/API definitions, migration inventory and order,
diagnostic code/label table, consumer adaptations, test matrix, verification
commands, explicit non-goals, and a statement that no compatibility layer
remains at completion.
