# Seq05.4.3 request: LSP REPL command-result adapter owner boundary

Date: 2026-06-29

## Problem

Seq05.4.1 intentionally does not add a production LSP REPL command execution endpoint because `arcweft-lsp` currently owns document/LSP request state only. It has no stable REPL command session, command host, or runtime-driver `RuntimeTaskOwner` boundary.

## Required design before implementation

1. Define whether an LSP workspace session may own a `ReplSession` or only borrow one from a native runtime/debug host.
2. Define the exact custom request method, likely `arcweft/replCommand`, and request/response DTOs.
3. Define how an LSP request obtains a runtime-driver `RuntimeTaskOwner` without a scheduler registry.
4. Define whether LSP diagnostics should mirror `ReplCommandDiagnostic` directly or map to editor diagnostics separately.
5. Define whether cell execution is out of scope for the LSP command endpoint, matching the MCP meta-command endpoint.

## Non-goals

- Do not add task state to the LSP adapter.
- Do not introduce a global scheduler registry.
- Do not duplicate CLI human formatting.
- Do not dispatch from stringly command tables.
