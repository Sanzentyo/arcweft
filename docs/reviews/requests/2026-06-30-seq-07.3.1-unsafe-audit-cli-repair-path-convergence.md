# Seq-07.3.1 Request: Unsafe Audit CLI Repair Path Convergence

## Sequence Position

Seq07.3 added exact verifier insertion spans for proof stubs and unsafe audit metadata. This follow-up is only about the remaining CLI/full-pipeline gap for unsafe audit repairs.

Do not redesign seq07.1 project-wide diagnostics, seq07.2 typed verifier actions, or seq07.3 `VerifierInsertionTarget` unless current implementation evidence shows a concrete flaw.

## Current Evidence

- `crates/arcweft-verify` can produce `GenerateUnsafeAudit` with a typed `SourceEdit` when an exact braced `unsafe lifetime` opening brace range is available.
- `crates/arcweft-verify-lsp` can convert that typed source edit into a workspace edit.
- `arcw verify fixtures/diagnostics/verifier-actions/missing-unsafe-audit.arcw` currently stops during `sema.typecheck` because missing `reason` and missing `/// SAFETY:` are hard typecheck errors.
- Because `arcw verify` uses `load_and_check_selection`, verifier repair actions are not displayed for that full CLI fixture even though the verifier layer has the insertion target.

## Problem

Unsafe audit metadata is currently checked in two places:

- typecheck reports hard errors for missing `reason` and missing `/// SAFETY:`;
- verifier reports `UnsafeLifetimeAudit` obligations and can now provide typed repair edits.

This split prevents the most useful CLI path from showing the seq07.3 repair edit. The final design should make one layer clearly own the user-facing repair path without adding compatibility shims or parsing rendered diagnostics.

## Goal

Design and implement the cleanest convergence so missing unsafe audit metadata reaches a typed repair action in CLI and LSP while preserving safety gates for build/run/release flows.

The preferred outcome is not predetermined. Evaluate at least:

- moving missing audit metadata from typecheck hard errors into verifier obligations;
- keeping typecheck validation but emitting structured typecheck diagnostics with typed source edits from the parser-owned `UnsafeAuditInsertion`;
- adding a verifier-specific loading path that can continue past audit-metadata typecheck errors without continuing past unrelated type errors.

Choose the smallest model that is architecturally final, not a transitional allow-list.

## Required Decisions

1. Which layer owns missing unsafe audit metadata as a blocking condition.
2. Whether typecheck should reject missing audit metadata or defer it to verifier policy.
3. How build/run/compile paths remain safe if `arcw verify` can surface repair actions.
4. Whether typecheck diagnostics need their own typed source-edit carrier or should reuse `arcweft_source::DiagnosticSuggestion`.
5. How to avoid string matching on error messages or rendered CLI output.
6. Which tests prove unrelated type errors still stop before verifier repair actions.

## Required Implementation Scope

- Make `arcw verify fixtures/diagnostics/verifier-actions/missing-unsafe-audit.arcw` print an actionable unsafe audit repair suggestion or a typed equivalent diagnostic suggestion.
- Preserve `GenerateUnsafeAudit` as the verifier action kind for verifier-owned obligations.
- Do not create hidden compatibility paths for old action shapes.
- Do not parse CLI output to recover edit ranges.
- Keep syntax/HIR/sema/verifier crate boundaries one-way and Sans I/O.
- Update `docs/implementation/verifier-obligation-insertion-spans-2026-06-29.md` or add a seq07.3.1 implementation note with the final ownership decision.
