# Seq-05.4 Request: REPL Host Adapter Integration Package

## Sequence Position

This follows the accepted seq05.0 through seq05.3 cuts:

- seq05.0 introduced Agent REPL runtime tiers and dispatch boundaries.
- seq05.1 introduced overlay cell transactions, snapshots, generations, and invalidation tokens.
- seq05.2 introduced typed REPL commands, command results, and Agent runner hooks.
- seq05.2.1 added typed adapter formatting and host adapter follow-up substrate.
- seq05.2.2 added the runtime-driver-owned task projection and cancellation API.
- seq05.3 added VM-first tiering status, `:warm`, and `:codegen` command behavior.

Seq05.4 is the host integration cut. It must wire concrete CLI/MCP/LSP or equivalent host surfaces to the typed command/result and runtime-driver task adapter model that already exists. It must not redesign the REPL command model, transaction model, tiering manager, or runtime-driver task registry.

## Problem

Seq05.2 through seq05.3 made the command model typed, but a typed command model is not enough if process-facing surfaces still use separate stringly tables, stub hosts, or local task/cancel state. Arcweft needs concrete host integration so an actual user-facing REPL session uses:

```text
REPL input
  -> parse_repl_input / parse_repl_command
  -> typed ReplCommandResult
  -> host-owned formatter
  -> CLI/MCP/LSP output surface

:tasks / :cancel
  -> ReplCommandHost
  -> RuntimeTaskReplCommandHost
  -> runtime-driver RuntimeTaskOwner / BundleSession
  -> typed ReplCommandResult evidence
```

The package must close that integration gap without moving terminal, filesystem, MCP, LSP, runtime-driver, or process I/O into low-level REPL command model modules.

## Request

Produce a zip package that designs and implements seq05.4 REPL host adapter integration.

The package must wire concrete host surfaces to the already accepted typed REPL command, formatting, runtime task/cancel, and tiering evidence APIs. It should delete or replace any obsolete stringly command output paths it supersedes. It must not preserve compatibility wrappers solely to avoid updating call sites.

## Required Decisions

1. Which concrete CLI REPL entrypoint should own terminal-facing command formatting.
2. Whether the existing formatter from seq05.2.1 is sufficient, or whether it needs a small owned option/value type extension for host integration.
3. Where the CLI REPL host should construct `RuntimeTaskReplCommandHost` from the active `BundleSession` or runtime-driver owner.
4. How `:tasks` and `:cancel` behave when no runtime session is active.
5. How read-only trace mode rejects `:cancel` before host mutation and how that evidence is formatted.
6. How `:warm` and `:codegen` status evidence from seq05.3 appears in CLI text and JSON output.
7. Which MCP/LSP surfaces currently exist and should be wired in this package.
8. Which MCP/LSP surfaces are not present or not stable enough, and what precise follow-up request is needed if they are deferred.
9. How adapter errors become typed `ReplCommandDiagnostic` or equivalent evidence rather than ad hoc strings.
10. Which obsolete parser/dispatch/formatting branches can be deleted after the concrete host integration is complete.

## Required Implementation Scope

Implement the sufficiently designed host integration end to end. At minimum:

- Wire the CLI REPL path so command input is parsed through the accepted typed command parser and displayed from `ReplCommandResult`.
- Ensure all accepted `ReplCommandEvidence` variants format deterministically in CLI text mode, including:
  - cells and submit rejection;
  - observe and step;
  - tasks and cancel;
  - load and reload;
  - undo and reset;
  - capabilities, generations, bindings, and tiers;
  - warm and codegen evidence;
  - diagnostics, host-unavailable, and read-only rejection.
- Preserve JSON output as typed structured data wherever the CLI already exposes JSON. Do not serialize formatted human text and parse it back.
- Construct `RuntimeTaskReplCommandHost` or the current equivalent from the active runtime-driver owner at the CLI host boundary.
- Add concrete behavior for `:tasks` and `:cancel` when a session exists and when no session exists.
- Add MCP/LSP adapters only if current crates expose a stable Agent REPL command output surface. Otherwise, add explicit repository-visible implementation notes and a narrow follow-up request.
- Remove superseded stringly formatter/dispatch branches that no longer have a current production responsibility.
- Add source gates or tests preventing `:tasks` / `:cancel` from using a parallel scheduler registry inside `arcweft-agent-repl` or `arcweft-cli`.
- Add implementation documentation under `docs/implementation/`.

## Acceptance Criteria

- CLI REPL command execution uses the typed parser/result path from seq05.2 rather than a separate stringly command table.
- CLI text formatting covers every current `ReplCommandEvidence` variant, including seq05.3 warm/codegen evidence.
- CLI JSON output remains structured, deterministic, and typed.
- `:tasks` and `:cancel` are backed by runtime-driver-owned task state through `RuntimeTaskReplCommandHost` or the current equivalent.
- `:tasks` without an active runtime session returns typed host-unavailable evidence, not a panic, placeholder string, or empty fake list.
- `:cancel` without an active runtime session returns typed host-unavailable or rejected evidence.
- Read-only trace mode rejects `:cancel` before runtime-driver mutation.
- `arcweft-agent-repl` does not own scheduler state, terminal formatting, MCP/LSP formatting, filesystem, or process I/O.
- Product player crates do not depend on REPL, CLI, MCP, or LSP crates.
- MCP/LSP adapter status is either implemented with tests or explicitly deferred with a concrete follow-up request.
- Source gates/tests prove no parallel task registry is introduced in CLI or REPL crates.

## Constraints

- Do not redesign seq05.1 transaction/session APIs.
- Do not redesign seq05.2 command parsing or evidence ownership.
- Do not redesign seq05.3 tiering/warm/codegen behavior.
- Do not add a new scheduler registry to `arcweft-agent-repl` or `arcweft-cli`.
- Do not put runtime-driver, terminal, MCP, LSP, filesystem, or process I/O into low-level REPL command model modules.
- Do not introduce compatibility aliases, deprecated wrappers, or migration shims.
- Prefer owned enum behavior, typed contexts, and inherent methods on Arcweft boundary types over ad hoc helper functions.
- Keep product player crates free of REPL/tooling dependencies.

## Non-Goals

- Implementing a new REPL protocol.
- Adding JIT/AOT execution beyond seq05.3's existing tiering status behavior.
- Implementing persistent compiled artifact caches.
- Redesigning Agent runner execution policy.
- Building new MCP/LSP server features where no stable surface currently exists.

## Parallelization Guidance

Seq05.4 can be designed and implemented in parallel with seq04.6 and seq06.4k.1/seq06.4k.2 because it is confined to REPL host/tooling boundaries.

Do not implement seq05.4 in parallel with another package that rewrites `arcweft-agent-repl::command`, `ReplCommandResult`, `ReplCommandEvidence`, or `BundleSession` task ownership. If such a package exists, seq05.4 should consume that result after it lands.

Recommended application order among current work:

1. seq05.4 may land independently after current seq05.2.2 and seq05.3.
2. If it returns MCP/LSP follow-up requests, apply CLI integration first and MCP/LSP integration after the concrete surfaces are verified.
