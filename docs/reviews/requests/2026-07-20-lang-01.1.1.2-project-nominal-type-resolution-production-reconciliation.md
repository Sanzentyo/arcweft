## Goal and dispatch contract

Freeze one authoritative, project-aware nominal type-resolution contract that
lets normal semantic checking distinguish:

- a declared, imported, or re-exported project type;
- a generic, built-in, `Self`, or projection type;
- an accepted external, environment, character, or adapter type;
- an intentionally open nominal type; and
- a genuinely unknown source type.

The result must make Lang-01.1.1.1 TM-072/RD-084, TM-080, and TM-083 implementable
without an `ArcResult` or `Unknown` name special case, without treating every
`TypeKind::Named` as a source declaration, and without adding another
project/import resolver. In particular, it must preserve generic alias
parameters and define arity checking, substitution, chains, cycles, imports,
and re-exports through the same nominal-resolution authority.

Send this file by itself to exactly one assignee together with current Arcweft
`main`, root `AGENTS.md`, the Rust skill, and:

Return one implementation-ready contract with exact Rust shapes, ownership,

## Sequence position and preserved substrate

This request splits underspecified prerequisites out of Lang-01.1.1.1
TM-072/RD-084, TM-080, and TM-083. TM-072/RD-084 and TM-083 require ordinary
generic alias expansion for result-shaped return boundaries without
recognizing the spelling `ArcResult`; TM-080 requires:

```arcw
fn f() -> Unknown { result_t_e? }
```

to retain the authoritative unknown-type diagnostic while its checked return
boundary is `Unresolved`, without a follow-on propagation diagnostic. The
package does not define how normal project checking proves that `Unknown` is
unknown.

Do not redesign implemented Lang-01.1.1.1 substrate unless current production
evidence proves a concrete flaw. Preserve:

- typed prefix/postfix Try and Await syntax with exact source evidence;
- `CheckedReturnTarget::{Known, InferredClosure, Unresolved}`;
- nearest-boundary selection and operand-success recovery;
- alias-normalized anonymous-choice checking;
- ordinary generic substitution;
- the AW-AH-009.3 shared callable catalog/resolver; and
- current callable identities.

This request supplies the missing nominal-resolution authority. It is not a
propagation or callable redesign.

## Production evidence and unresolved seam

The request was prepared from `main` at
`c56c82240dacc0d254c7d32e17359d4be0f04b41`. Re-audit current `main` before
designing.

1. `arcweft-lang-syntax::types::TypeRef` preserves ordinary paths and generic
   bases as strings, but carries no resolved declaration identity or
   import-resolution result.
2. Context-free `TypeRef` to `TypeKind` conversion maps an unrecognized path to
   `TypeKind::Named`, so normal checking cannot distinguish a typo from an
   intentionally open or adapter-owned name.
3. `arcweft-lang-hir::symbol::ProjectSymbolTargetId` currently covers callable,
   external, and module targets, but not project struct, enum, or type-alias
   declarations.
4. `HirProject::linked_module()` flattens module HIR. Normal checking can
   receive project symbols, but no shared source-backed nominal declaration
   record reaches ordinary signature checks.
5. `TypeCheckEnv` separately owns legitimate open named facts, including enum
   inventories, nominal records, domain types, and accepted Rust exports.
   Absence from project declarations is therefore not sufficient evidence for
   an unknown-type diagnostic.
6. `arcweft-lang-sema::entry::checker::nominal::NominalSchemaResolver`
   privately inventories project structs/enums/type aliases, reconstructs
   import visibility, expands aliases, and detects recursion for entry schemas.
   Copying it into the ordinary checker would retain two successful
   project/import resolution authorities.
7. TM-080 needs exact source evidence and must poison only the affected checked
   boundary. Literal-name checks, source scans, or propagation-local lookup are
   forbidden.
8. TM-072/RD-084 and TM-083 place `?` behind a generic result alias. Current
   source/HIR alias records discard generic parameters and the checker has no
   declaration-identity-based arity/substitution product, so these rows cannot
   be completed by recognizing the fixture spelling `ArcResult`.

## Required decisions

The final contract must decide all of the following.

### 1. Authoritative owner and exact types

Define exact Rust types for project nominal declaration identity, kind, source
record, resolved reference, open/external result, unresolved/poisoned result,
constructors, accessors, equality/hash/order, and visibility. State the owning
crate and prove the dependency direction.

### 2. Identity tuple

Fix package, canonical module, declaration family (`struct`, `enum`, or
`type alias`), owner path if any, local name, and revision/world components.
Define whether aliases retain identity distinct from their normalized targets.
Qualified, imported, and re-exported spellings must resolve to one identity.

### 3. Atomic publication

Specify how source nominal declarations are collected from module-preserving
HIR, validated, source-indexed, and published in the same accepted project
transaction as module/callable/external symbols. Decide duplicates,
cross-family collisions, visibility, private imports, globs, re-exports,
inaccessible targets, cycles, deterministic ordering, and limits.

### 4. Resolution input and product

Define one bounded operation over a typed source `TypeRef`, current module,
generic scope, impl `Self` scope, accepted project world/revision, environment
facts, and source evidence. Freeze outcomes for built-ins, generics, `Self`,
projections, project declarations and aliases, accepted external/Rust/domain
types, intentionally open names, unknown names, ambiguous names,
inaccessible names, and already-poisoned recovery nodes.

### 5. Open-nominal policy

Decide where open named types are allowed and represent that permission as
typed policy or accepted environment evidence. Preserve legitimate
adapter/domain/test use without making arbitrary source spelling valid. Do not
scatter hard-coded allow lists through checker branches.

### 6. Recursive checking

Define resolution for type paths nested in tuples, function types/effect rows,
choices, generic arguments, trait bounds, associated bindings, projections,
references, slices, function/method/flow signatures, closure return
annotations, aliases, fields, enum payloads, impl targets, and where clauses.
Specify error accumulation and poison propagation.

### 7. Alias and generic normalization

Fix alias arity, substitution, chains, cycles, imports/re-exports, normalization
order, and interaction with anonymous-choice duplicate detection. Normalizing
must not erase identity or source evidence required by diagnostics.

### 8. Source and detached evidence

Define exact UTF-8 ranges and `SourceSpan` ownership for declarations, authored
references, imports/re-exports, and alias targets. Detached HIR must retain
typed local ranges when available, never fabricate project document/revision
identity, and explicitly state which project validations are unavailable.

### 9. Structured diagnostics

Select stable codes and typed payloads for unknown, ambiguous, inaccessible,
duplicate, wrong-kind, wrong-arity, and cyclic nominal references. Define
primary/secondary labels, ordering, deduplication, caps, and the rule by which
one authoritative type error suppresses downstream return/propagation errors.

### 10. Checker integration

Define how checked resolution replaces context-free successful nominal
conversion, how `CheckedReturnTarget::Unresolved` can arise only from a prior
authoritative type failure, and how body contextual checking avoids cascades.
TM-072/RD-084, TM-074, TM-080, and TM-083 must share one typed resolution and
poison discipline.

### 11. Entry resolver reconciliation

Inventory every behavior in `NominalSchemaResolver`. State which shared facts
replace its project/import/alias lookup, which schema-shape logic remains
entry-specific, and the exact narrowing/deletion order. The final state may not
contain two successful project nominal resolvers.

### 12. External/environment integration

Define participation and precedence for `TypeCheckEnv` nominal records, enum
inventories, standard/domain names, Rust exports, character nominal identity,
adapter registrations, and other accepted external types without projecting
them into fake project declaration IDs.

### 13. Limits, revision, and caching

Bound declaration collection, import/glob expansion, alias normalization,
generic recursion, diagnostics, and total work. Define stale world/revision
behavior and which checked facts compiler/LSP requests may reuse.

### 14. Consumers

Define the minimum intentional APIs for sema, entry checking, compiler,
project index, LSP diagnostics/hover/definition/completion/rename, and tests.
Broad root re-exports and display-string parsing are not acceptable.

## Preferred architecture direction to evaluate

Prefer extending the existing unified `arcweft-lang-hir::symbol` declaration
and target world with typed project nominal records, published during the same
bounded accepted-project transaction. Normal sema and entry schema checking
then consume one immutable resolution product; entry-specific schema expansion
may remain a consumer.

An adjacent accepted nominal table is acceptable only if it shares the same
world/revision, module/import bindings, collision transaction, source
identities, limits, and one resolution operation, and if the contract gives a
direct deletion path for the current specialized lookup. It may not become a
parallel catalog that can disagree with `ProjectSymbolTable`.

## Required implementation order

1. Add final typed nominal IDs, records, resolution outcomes, errors, source
   evidence, and invariant tests.
2. Publish declarations and import/re-export bindings in the accepted project
   world with deterministic collisions, limits, and revision.
3. Migrate the entry resolver's project/import/alias lookup to shared facts,
   retaining only entry-specific schema expansion.
4. Implement bounded recursive checked type-reference resolution,
   generic/`Self`/projection policy, aliases, external/open policy, and poison
   facts.
5. Migrate ordinary function, method, flow, closure, struct/enum/alias, and
   other normal-checker consumers, then delete successful paths that can
   disagree.
6. Connect structured diagnostics and compiler/LSP consumers to shared typed
   source facts.
7. Run focused tests, workspace check/Clippy/tests, applicable Tier 2, Cargo
   metadata dependency evidence, diff check, and structural audit.

## Mandatory direct tests

The contract must specify tests for:

- local, child, parent, qualified, imported, aliased, globbed, and re-exported
  structs, enums, and aliases resolving to one identity;
- duplicate/cross-family collisions, ambiguity, inaccessible/private imports,
  visibility escalation, unknown modules, and insertion-order independence;
- Rust exports, domain names, nominal records, enum inventories, characters,
  adapter-only types, and deliberate open names remaining valid;
- genuinely unknown paths in return, parameter, closure, alias target, generic,
  tuple/function type, field, enum payload, impl target, trait bound,
  associated binding, projection, reference, slice, and where-clause
  positions;
- generic/project-name collisions, nested generics, `Self`, projections, alias
  arity/chains/cycles/imports, and generic substitution through aliases;
- TM-074: alias-normalized duplicate anonymous choices produce only the prior
  choice error;
- TM-080: an unknown return type produces only the authoritative unknown-type
  diagnostic, marks the checked return boundary unresolved, retains Try
  success type for recovery, and emits no `sema.try.*` cascade;
- TM-083: a generic result alias around the checked return boundary expands by
  declaration identity and substituted type arguments, never by alias name;
- the same discipline for prefix Try and propagating Await;
- exact UTF-8 ranges, repeated spellings, multi-document modules, related
  import/declaration labels, detached HIR, stale revisions, work limits,
  diagnostic caps, and deterministic ordering;
- entry and normal checking selecting the same declaration/alias facts;
- compiler/LSP diagnostic, hover, definition, completion, and rename consumers;
  and
- dependency/visibility evidence through APIs and Cargo metadata, never source
  gates.

## Constraints and non-goals

- Do not redesign Try, Await, callable resolution, direct suspension, Stream
  generators, runtime lowering, AWBC, save/load, host wire, cancellation,
  rendering, CSS, or Takumi.
- Do not special-case `Unknown`, `ArcResult`, one enum, one alias, or one
  fixture.
- Do not reject every unregistered `TypeKind::Named`; represent accepted open
  policy explicitly.
- Do not create another project symbol table, import resolver, alias resolver,
  checker-only nominal catalog, entry-only successful lookup, or LSP-only
  resolver.
- Do not parse diagnostic/display/source text into identity.
- Do not add source gates, spelling deny lists, compatibility aliases,
  deprecated fields, dual readers, extension-trait shims, migration AST, or
  permanent removed-syntax diagnostics.
- Keep syntax parser-only, HIR/data-format layers Sans I/O, `arcweft-core`
  uninvolved, and dependencies aligned with repository architecture.
