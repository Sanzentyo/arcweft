# Seq-04.5 Request: Interface, Runtime-Plan, Bytecode, and Link Reuse Package

## Sequence Position

This is the later seq04 slice. It must wait until seq04.1-04.4 have established
the deterministic object codecs, read-through/write-through policy, snapshot
evidence, and explain output.

## Request

Design the safe expansion path for persistent compiler query reuse beyond
parse/HIR objects: interface summaries first, then runtime-plan units, bytecode
units, and link plans only where identities are stable. Implement only the
subsets that are concrete and sound in the current repository.

Return the final work as a zip package. If some families remain design-only or
conservative misses, document that explicitly and do not fake reuse.

## Required Scope

- Define stable interface summary object schema and validation inputs.
- Decide whether runtime-plan unit, bytecode unit, and link-plan reuse are
  implementation-ready with current AWBC/runtime identities.
- Explicitly report typecheck and linked-HIR conservative misses until
  module-aware sema exists.
- Preserve deterministic output content roots and logical descriptors.
- Add tests proving reused and rebuilt paths produce equivalent build outputs.

## Non-Goals

- No fine-grained semantic reuse before module-aware sema exists.
- No direct serialization of `HirModule`, `CompiledProjectModule`, or transient
  compiler internals.
- No broad cache hit claims without validation evidence.
- No release/trust/publish behavior.

## Expected Zip Contents

- `overlay/` implementation for the ready subset.
- Design docs for any intentionally deferred subset.
- Tests for interface reuse and conservative misses.
- `docs/implementation/seq-04-5-interface-runtime-bytecode-link-reuse-2026-06-28.md`
- `VALIDATION.md`.
- `README.md` with a clear ready/deferred matrix.
