# Design request: AW-AH-009.2.2 character nominal rename and atomic-edit contract

- Date: 2026-07-16
- Sequence: AW-AH-009.2.2, after accepted AW-AH-009.2.1 definition/source-index
- Kind: independently throwable final-design task with one explicit prerequisite
- Production changes: prohibited
- Output language: English

## Goal and dispatch contract

Produce one decision-complete, implementation-ready contract for character
rename, prepareRename, bounded reference discovery, atomic preflight, and
deterministic WorkspaceEdit construction.

Dispatch this request only after
[AW-AH-009.2.1 definition/source-index](2026-07-16-aw-ah-009.2.1-character-nominal-definition-source-index-contract.md)
has returned an accepted final contract. Send exactly this request, the
accepted AW-AH-009.2.1 final-contract archive and status artifacts, and access
to the current Arcweft checkout to one assignee. Do not attach the superseded
combined AW-AH-009.2 request or ask the assignee to redesign definition,
descriptor identity, cursor resolution, or declaration provenance.

The assignee must inspect current main, applicable AGENTS.md files, the Rust
skill, the landed AW-AH-009.1.1 implementation, and the accepted AW-AH-009.2.1
contract. It must record exact Git and Jujutsu identities.

This is design only. It must not edit Rust, Cargo manifests, tests, schemas,
fixtures, stable design chapters, or LSP implementation and must not include a
patch or repository overlay.

Ready output must select one normative policy for every rename category,
failure, client capability, source class, and limit. “TBD”, unresolved
alternatives, and implementation-selected behavior are not acceptable.

## Fixed prerequisites and substrate

- AW-AH-009.1.1 has landed one complete-world CharacterRegistrar,
  ProjectSymbolTable, RegisteredSemanticWorld, revision-bound source facts,
  immutable RegisteredTypeCheckEnv, and accepted LSP environment generation.
- The accepted AW-AH-009.2.1 contract owns the canonical
  CharacterSymbolDescriptor, descriptor/declaration source index, typed cursor
  query, URI adaptation, identity checks, definition behavior, and the exact
  read-only occurrence/query boundary exposed to this task.
- SourceDocumentIdentity binds exact content. SourceSnapshotId remains a
  distinct session-local incremental-lineage type owned by
  arcweft-source::identity and allocated/advanced by SyntaxDatabase. This
  request may consume the accepted identity path but may not define another
  one.
- Renaming an import/source alias does not change nominal identity.
- Renaming CharacterId, CharacterLookId, CharacterPartId, or
  CharacterVariantId changes public semantic identity. No compatibility alias,
  dual reader, redirect, migration shim, or deprecated spelling may remain.
- source_label() and Display remain presentation-only and must not be parsed.
- Character manifests already retain structural token spans for owner, look,
  part, variant, default-look, and selection references. The accepted
  definition/source index establishes how documents and declaration spans
  remain reachable.
- Filesystem writes, URI conversion, and LSP WorkspaceEdit construction belong
  to adapters/tooling. Character, source, HIR, and sema data remain Sans I/O.

## Design objective

Define one bounded typed reference inventory and one fail-closed rename
transaction. The transaction must resolve the selected
CharacterSymbolDescriptor, classify the requested rename policy, validate the
replacement, inventory every required editable occurrence, detect stale or
unavailable coverage, preflight collisions and client capabilities, construct
one deterministic WorkspaceEdit, and publish no semantic state until the
client applies and the project successfully rebuilds.

Any preflight failure must return no partial edit. A successful edit must never
be based on global text replacement, source_label() parsing, repository source
search, or unchecked filename/string heuristics.

## Required decisions

### 1. Rename categories and public policy

Select one explicit policy for each:

- module/import/source alias;
- public CharacterId;
- CharacterLookId;
- CharacterPartId; and
- CharacterVariantId scoped by owning part.

For every category, state prepareRename behavior, ordinary LSP rename behavior,
whether an explicit breaking-operation capability or command is required, and
the stable refusal result when the category is unavailable. Public/member ID
changes may not silently behave like alias rename.

### 2. Typed reference inventory

Define exact Rust shapes, owner crate/module, constructor visibility, identity,
ordering, and limits for declaration and use occurrences. Each occurrence must
retain:

- canonical CharacterSymbolDescriptor;
- occurrence role, such as declaration, owner use, expected-type member use,
  manifest cross-reference, alias binding, or launch/profile selection where
  applicable;
- exact SourceSpan and owning SourceDocumentIdentity;
- project world, symbol revision, accepted generation, and open-document
  version evidence required by the accepted contracts;
- editability/source-class metadata supplied by adapters; and
- the exact authored replacement range, excluding quotes or punctuation when
  the selected grammar requires that.

The inventory must consume the AW-AH-009.2.1 query/index boundary and may not
create a second character resolver or alias map.

### 3. Exhaustive edit-coverage matrix

For each rename category, enumerate every source carrier that must be edited or
preflighted:

- .arcw canonical, compact, qualified, and arbitrary alias spellings;
- manifest owner, look, part, and variant declarations;
- manifest default_look and look-selection part/variant references;
- launch/profile references and imports where the selected identity is
  actually represented;
- generated files, dependency manifests, read-only files, non-file documents,
  unopened disk files, and open unsaved overlays; and
- simultaneous profiles and workspace roots.

If a carrier is intentionally not editable, select whether it blocks the
rename, makes the category unavailable, or is outside semantic coverage. No
required occurrence may be silently skipped.

### 4. Replacement validation

Define exact checked constructors and diagnostic ranges for replacement IDs
and aliases. Cover empty input, Unicode policy, control characters, reserved
names, separators/qualification, invalid PublicId domains, same-name
replacement, and length limits.

State whether the client-supplied replacement includes only the local ID or a
qualified spelling and how canonical formatting is produced without parsing a
display label.

### 5. Collision and ambiguity preflight

Specify collision rules for local aliases, imports, canonical/compact owner
bindings, CharacterId values, look/part IDs within one owner, variant IDs
within one part, and same-spelling members in other owners/parts.

Define how ProjectSymbolTable and registered character inventories provide
collision evidence, deterministic diagnostic ordering, primary/related
ranges, and the distinction between a real collision and an unrelated
same-spelling nominal identity.

### 6. Atomic transaction algorithm

Specify one ordered preflight algorithm from prepareRename through WorkspaceEdit
construction. Freeze when the operation captures document versions,
SourceDocumentIdentity values, SourceSnapshotId where required, project world
and symbol revision, AcceptedEnvironmentGeneration, file metadata, client
capabilities, and resource budgets.

Define overlap detection, duplicate-edit coalescing, edit ordering within a
document, URI ordering, arithmetic overflow, cancellation, timeout, and
concurrent rebuild behavior. No failure may return a partial WorkspaceEdit.

### 7. Open documents, disk files, and adapter I/O

Consume AW-AH-009.2.1’s selected open-overlay authority. Define how unopened
files are read and versioned, how changed-on-disk evidence is detected before
returning an edit, and how filesystem/read-only/generated classification enters
preflight without adding I/O to lower-level crates.

State behavior when an open manifest differs from the accepted semantic world,
when a client changes a document during preflight, and when the client cannot
represent a version for an unopened file.

### 8. LSP capability and WorkspaceEdit shape

Select exact behavior with and without:

- prepareRename support;
- versioned documentChanges;
- resource operations;
- change annotations;
- failure-handling capabilities; and
- a client-specific command for explicitly gated breaking rename, if chosen.

Choose TextEdit versus AnnotatedTextEdit, documentChanges versus changes, and
version/null-version policy. If safe atomic semantics cannot be represented,
the operation must fail before returning edits.

### 9. Multi-root, multi-profile, dependency, and partial coverage

Define the rename scope key and how one operation proves complete coverage.
Cover identical CharacterId values in isolated worlds, one manifest selected
by multiple profiles, dependency-owned manifests, missing roots, partially
loaded workspaces, and references outside the current LSP process.

Select whether incomplete coverage rejects a breaking rename or requires an
explicit externally coordinated migration mode. Ordinary rename may not claim
atomicity over unknown files.

### 10. Post-apply rebuild and invalidation

Define what state changes only after the client applies edits and a complete
registration rebuild succeeds. Cover accepted-generation replacement,
definition/reference/signature caches, old-world query cancellation, failed
rebuild preserving or invalidating prior state, file watcher races, and
shutdown.

The design must distinguish returning a WorkspaceEdit from observing its
successful application. It may not mutate RegisteredSemanticWorld in advance.

### 11. Structured results and errors

Define stable typed prepareRename and rename results for invalid replacement,
same-name replacement, unsupported category, explicit-breaking consent
required, collision, ambiguity, stale document, stale world/revision/
generation, missing provenance, missing/unreadable/changed file,
generated/read-only/dependency-owned source, partial multi-root coverage,
unsupported client capability, cancellation, timeout, limit exhaustion,
overlapping edits, and arithmetic overflow.

Each error needs a stable identity, structured fields, tight primary range,
optional related ranges, deterministic ordering, and a documented LSP mapping.

### 12. Inclusive hard limits

Select exact production maxima for roots, profiles, documents, URIs,
occurrences, edits, replacement bytes, source bytes read, diagnostics, work,
and output bytes. Exact limit succeeds; one-over and overflow fail before a
WorkspaceEdit is returned.

State how limits compose with AW-AH-009.1.1 and AW-AH-009.2.1 limits without
double charging or bypass.

## Required implementation order to specify

The final contract must prescribe compiling, reviewable cuts in this order:

1. Freeze rename category policy, typed occurrence inventory, errors, limits,
   and adapter boundaries.
2. Build reference inventory queries on the accepted AW-AH-009.2.1 index and
   definition resolver, with no mutation.
3. Implement prepareRename and alias-only rename with full stale/collision/
   limit preflight.
4. Add explicitly selected breaking owner/member rename categories one at a
   time, reusing the same atomic transaction.
5. Add open/disk coordination, client capability adaptation, deterministic
   WorkspaceEdit construction, and post-apply rebuild/invalidation.
6. Remove the rename placeholder and every bypass only after the typed path is
   complete.
7. Run focused tests, workspace check/Clippy/formatting, applicable just
   validation, and the canonical structural audit.

The plan must name exact crate/module changes and deletion points. It must
preserve definition behavior before implementing mutation.

## Mandatory direct test matrix

For every rename category, specify prepareRename result, rename result, error
identity, exact edit set, and mutation/publication behavior for:

- canonical, compact, qualified, and arbitrary alias uses;
- owner, look, part, and per-part variant declarations and references;
- default-look and look-selection manifest cross-references;
- same local member spelling in another owner or part;
- alias-only rename preserving nominal identity;
- each accepted breaking rename changing nominal identity without an alias;
- invalid, empty, same-name, overlong, reserved, and control-character
  replacements;
- local/alias/public-ID/member collisions and semantic ambiguity;
- stale LSP version, SourceDocumentIdentity, SourceSnapshotId when used,
  project symbol revision, accepted environment generation, profile, and
  inventory;
- open unsaved overlay, disk change during preflight, missing/unreadable file,
  generated/read-only/dependency-owned/non-file source;
- multi-root, simultaneous-profile, isolated-world, and partial-coverage cases;
- clients with and without versioned documentChanges and every required
  capability;
- duplicate/overlapping occurrences and deterministic reverse-order edits;
- cancellation/timeout before and during inventory;
- exact and one-over every document/occurrence/edit/byte/work/diagnostic limit,
  plus arithmetic overflow;
- no partial WorkspaceEdit or semantic publication after any failure;
- successful client application followed by successful rebuild and fresh
  generation/cache; and
- client application followed by failed rebuild under the selected recovery
  policy.

Tests must call public or crate-owned symbol, source-index, registration,
rename, adapter, and LSP APIs. Automated source gates are prohibited. No test
or script may pass/fail by searching checked-in source or documentation for
symbols, paths, module locations, or spellings.
