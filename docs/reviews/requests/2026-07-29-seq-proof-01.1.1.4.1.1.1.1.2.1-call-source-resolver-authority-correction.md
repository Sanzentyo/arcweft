## Preserved useful decisions

Preserve these decisions unless direct predecessor evidence proves a concrete
conflict:

1. Known Call syntax retains `HirExprKind::Call` with typed poison rather than
   collapsing to generic Error.
2. Every authored argument slot remains in authored order and retains its
   positional, named, or spread form through HIR, checking, diagnostics, and
   signature projection.
3. Missing or invalid names never fabricate `HirName`; missing expression
   values never fabricate or sentinel an `ExprId`.
4. Missing callee/value expressions use real root-owned poison children with
   `RecoveryOperand` ordinal zero and `1 + argument ordinal`.
5. Dot syntax retains same-revision value and nominal evidence until
   value-first/nominal-second classification is final; explicit `::` remains
   nominal-only.
6. Explicit call type applications have one ordered qualified final owner and
   remain distinct from generic arguments inside an associated receiver.
7. The migration is deletion-driven and leaves no compatibility reader.

## Why another correction is required

The rejected return was mechanically valid and claimed
`READY_FOR_IMPLEMENTATION`, but it did not read any of the three required
predecessor archives and introduced result-changing conflicts:

- a parallel `HirCallSourceSurface` map/read API replaced the accepted sole
  `HirModule::source_site` authority;
- named/spread fixtures used `name: value` and `...value` instead of Arcweft's
  `name = value` and `value...`;
- comma/open/close active-slot boundaries contradicted current typed behavior;
- the payload could not distinguish missing callee from unresolved dot, retain
  invalid associated receiver/arity poison, or bind multiple issues to root
  `HirPoisonState`;
- invalid-present type arguments discarded their qualified poisoned `TypeId`;
- new argument-index and limit types duplicated accepted owners;
- a reduced new checker fact and resolver entry discarded current semantic
  facts and conflicted with AW-AH work accounting; and
- no attached Call/argument/type-application/source projection could replace
  the detached readers that the package ordered deleted.

The replacement must close, rather than work around, those conflicts.
