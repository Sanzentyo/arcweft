# Request: Function suspension role unification final contract

## Sequence position

This is Lang-01.1, split from the 2026-07-16 top-level declaration reduction.
It supersedes the constraint in
`2026-07-08-seq-07.8.1-task-dialogue-stream-callable-effect-abi.md` that assumed
`task fn`, `dialogue fn`, and `stream fn` must remain separate callable kinds.
It must not redesign the verified ordinary-function, closure, currying, or
open-effect-row substrate unless production evidence shows a concrete defect.

## Why this split is needed

The target language should not create a separate top-level function grammar
for every execution role. Production currently has one typed `FunctionItem`
with `FunctionKind::{Function, Task, Dialogue, Stream}`. `await` is an existing
expression and flow suspension surface, but there is no canonical `async fn`.
`stream fn` already lowers into runtime and AWBC stream plans, while task and
dialogue callable execution are materially less complete. Choosing attributes,
return-type inference, or an async marker without an execution table would
freeze accidental semantics.

## Required decisions

1. Decide the one canonical ordinary-function surface for synchronous,
   task/suspending, dialogue-safe, and stream-producing functions.
2. Compare at least these models and select one final model:
   - ordinary `fn` plus typed attributes such as `#[task]` / `#[stream]`;
   - `async fn` plus ordinary return types and a separate stream marker;
   - ordinary `fn` with execution role inferred from a nominal return type;
   - a smaller hybrid, with a precise reason for every retained marker.
3. Specify whether an attribute affects callable identity or only verified
   execution policy. Do not represent the selected role as an unvalidated
   string after syntax lowering.
4. Define creation, partial application, final call-group completion, start,
   suspend, resume, yield, error, cancellation, and drop timing for each role.
5. Define where `await`, `try await`, postfix `?`, `yield`, and flow `await
   ... with` are legal and what each returns.
6. Specify whether `await` in an ordinary function makes the function
   suspending, is rejected, or requires an explicit typed marker.
7. Preserve the useful internal `StreamPlan`/AWBC model unless evidence calls
   for a replacement; author-surface unification does not imply erasing runtime
   execution kinds.
8. Decide whether `dialogue fn` has any execution behavior beyond a normal
   function with a dialogue-callability/effect constraint. Remove the role if
   it does not.
9. Define LSP hover, signature help, completion, formatter, and diagnostic
   presentation for the selected model.

## Implementation order to specify

1. Normative source-to-execution timing table.
2. Typed syntax/HIR role representation on the ordinary function substrate.
3. Sema/effect/cancellation rules.
4. Runtime-plan and AWBC mapping, retaining existing stream behavior during a
   direct compile-breaking replacement rather than a compatibility phase.
5. Tooling and maintained documentation migration.
6. Removal of old keywords, enum variants, recognizers, and exact-spelling
   tests.

## Tests to specify

- Ordinary, suspending, and stream functions share the same typed signature
  and symbol resolution path.
- Await legality and result typing are covered in every function/flow context.
- Creation, start, resume, yield, cancellation, and error effects occur at the
  specified stage.
- Currying does not start deferred work before the final group.
- Stream RuntimePlan/AWBC round trips and tamper rejection remain covered.
- Removed callable spellings fail through ordinary grammar recovery with no
  historical AST/CST kind or dedicated removal diagnostic.
- LSP signature help and hover use the shared callable catalog.

## Constraints

- Prefer one ordinary `fn` grammar and typed role metadata; retain a distinct
  keyword only if the execution table proves an attribute cannot express the
  boundary safely.
- No compatibility aliases, dual readers, or migration-only AST nodes.
- No source gates.
- Keep sema graph internals out of RuntimePlan, AWBC, core, and save formats.
- Keep flow suspension distinct from function syntax where its pending-view
  contract requires it.

## Expected output

- A final grammar and examples.
- A normative execution/effect/cancellation table.
- Typed AST/HIR/RuntimePlan/AWBC contracts.
- A deletion and implementation sequence with exact tests.
- An explicit list of old syntax and documentation to remove.
