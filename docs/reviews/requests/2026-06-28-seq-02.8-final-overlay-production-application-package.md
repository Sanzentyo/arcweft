# Request 02.8: Final Seq-02 Overlay Production Application Package

## Sequence Position

This is the final seq-02 cleanup gate. It follows seq-02.1 through seq-02.7 and
the applied seq-02.4.1 View resource codec follow-up. It exists to audit any
generated seq-02 overlay or package patch as production code after the
underlying contracts are implemented or explicitly split out.

This request can be thrown independently from the seq-02.6 / seq-02.7 adapter
follow-up. If it finds release-publish, HTTP(S) payload fetch, target signing, or
trust-verifier gaps, classify them as belonging to the seq-02.6 / seq-02.7
adapter package instead of implementing them here.

## Request

Produce a final zip package that classifies every remaining seq-02 overlay hunk
or generated package patch, translates only the hunks that still match completed
seq-02 contracts into an implementation overlay, rejects obsolete or unsafe
hunks with rationale, and records a final seq-02 completion decision.

The requested deliverable is the design-and-implementation package itself, in
the same style as prior Arcweft zip packages. Do not directly modify, commit, or
push to the requester repository as part of this request. Put all accepted
implementation work under `overlay/` and `patches/` so a separate application
step can review and apply it.

The result may contain no source overlay changes if every remaining hunk is
already implemented, superseded, unsafe, speculative, or assigned to another
request. In that case, the package must still provide the complete
classification table, validation evidence, and final seq-02 status note.

## Required Decisions

1. What exact overlay/package files are in scope, and where they came from.
2. How each hunk is classified:
   - already implemented;
   - still valid and should be translated into source-shaped overlay edits;
   - superseded by seq-02.x design;
   - unsafe or layering-violating;
   - speculative;
   - obsolete;
   - belongs to seq-02.6/02.7 adapter follow-up;
   - belongs to seq3 or later.
3. Whether any overlay fixture should become a golden fixture, smoke fixture,
   review-only example, or discarded scratch artifact.
4. Whether any generated code reintroduces product JSON fallback, codec probing,
   compatibility shims, raw signature passthrough, ad hoc fingerprinting,
   stringly policy helpers, broad root re-exports, or Sans I/O violations.
5. Whether any accepted hunk needs a focused test, source gate, fixture update,
   or documentation update.
6. Whether seq-02 can be declared complete after this package, or which
   remaining items block that declaration.
7. Which remaining items are explicitly non-goals for seq-02 and belong to
   seq3 or later.

## Required Implementation Order

1. Extract or locate the original overlay/package material in a scratch
   directory that cannot be mistaken for active workspace source.
2. Record the scratch path, archive hashes, and overlay inventory in
   `SOURCE_INVENTORY.md`.
3. Produce a complete hunk classification table before authoring any source
   overlay.
4. Compare every candidate hunk against current source and the implemented
   seq-02.x contracts.
5. Translate only valid production edits into normal source-shaped overlay
   files, not blind overlay copy.
6. Add or update focused tests and source gates in the overlay for every
   accepted hunk.
7. Keep scratch output inside the package only; do not make it look like active
   workspace-external `crates/`, `tests/`, or fixtures.
8. Run formatting, focused tests, workspace validation, clippy, and structural
   audit when the packaging environment has the repository/toolchain. Otherwise
   record exact blockers.
9. Add or update
   `docs/implementation/seq-02-final-production-application-YYYY-MM-DD.md` in
   the overlay with final status, validation, deviations, and remaining TODOs.

## Acceptance Criteria

- Every overlay/package file and hunk in scope is classified exactly once.
- No generated overlay code is applied blindly.
- Accepted hunks are translated into production-shaped overlay edits that follow
  current ownership and crate boundaries.
- Rejected hunks have concrete rationale tied to implemented seq-02 contracts or
  explicit future-owner requests.
- The package proves that it did not reintroduce migrated product JSON fallback,
  codec probing, compatibility shims, raw signature passthrough, ad hoc
  section-family fingerprinting, stringly signing policy helpers, or Sans I/O
  violations.
- All accepted overlay code edits have focused tests or a documented reason why
  source gates are the appropriate coverage.
- Scratch overlay material is contained only inside the package and is clearly
  separated from source-shaped accepted overlay files.
- The final status says clearly whether seq-02 is complete, complete except
  seq-02.6/02.7 adapter follow-up, or not complete.

## Tests To Specify And Run

- All focused seq-02.1 through seq-02.7 and seq-02.4.1 tests relevant to
  accepted hunks.
- Source gates against migrated product JSON fallback, codec probing, and
  compatibility shims.
- `cargo fmt --all -- --check`.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
- `just test-workspace`.
- `cargo +nightly -Zscript tools/structure-audit.rs --root .`.
- `git diff --check`.
- If no production code is accepted, still run classification validation and
  source-gate checks, and explain why code tests were not needed.

## Constraints

- Do not design new resource codec, patch v2, AWFR, external payload, or signing
  policy contracts in this request.
- Do not implement seq3 generation runtime or windowed live patch behavior.
- Do not preserve historical overlay code merely because it existed in a
  package.
- Do not create compatibility aliases, migration shims, codec probing, or
  fallback decode paths for migrated product families.
- Keep data-format crates Sans I/O.
- Prefer owned type methods, `From`/`TryFrom`, or named contexts over scattered
  conversion helpers.
- Use stable Rust features; no MSRV restriction is required for this sequence.
- Do not let scratch overlay directories look like active workspace code.

## Non-Goals

- Closing the seq-02.6 / seq-02.7 HTTP(S) fetch, publish adapter, target signing,
  or trust-verifier follow-up unless those changes are already present as valid
  production hunks in the overlay and do not require new design.
- Implementing seq3.
- Keeping generated overlay files as historical artifacts outside the final zip.
