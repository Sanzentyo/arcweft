# Seq 06.16.6.3 Legacy UI crate component-to-view rename

Date: 2026-07-07

## Implementation status

Implemented in the 2026-07-07 retained UI View boundary rename slice recorded
in `docs/implementation/scoped-presentation-handles-final-ui-syntax-2026-07-06.md`.
The retained substrate was kept and renamed directly; no compatibility alias,
deprecated re-export, duplicate module, parser branch, or serde field alias was
added.

## Sequence position

This request follows the final View syntax rename and the scoped capture cleanup
that moved the active authoring surface, Agent protocol, CLI observe/capture,
and layout capture scope to `view`.

## Why this split is needed

The active syntax/runtime path no longer accepts `component(...)`, `@component`,
`components.json`, `--component`, or `kind = "component"` for scoped UI
presentation. However, the older retained UI substrate still contains
`arcweft-ui::ComponentId`, `ComponentRegistry`, `ComponentDescriptor`,
`RustComponentId`, `EntityStore::component`, and Takumi metadata fields named
`component`.

Those names are not authoring compatibility shims, but leaving them in the
workspace makes the final `view` model ambiguous and will keep producing
cross-crate terminology drift. The rename is broad enough to require its own
cut so callers, tests, serde contracts, docs, and Takumi adapter metadata are
migrated together rather than patched piecemeal.

This request must not redesign the verified final View syntax, action routing,
presentation handle lifecycle, scoped capture behavior, or save/load substrate
unless current implementation evidence shows a concrete flaw.

## Required decisions

- Decide whether `arcweft-ui` remains as a retained View substrate crate or is
  removed/replaced by the newer compact UI resource path.
- If retained, define the exact new names:
  - `ComponentId` -> `ViewId` or another typed retained-view id;
  - `ComponentRegistry` -> `ViewRegistry`;
  - `ComponentDescriptor` -> `ViewDescriptor`;
  - `ComponentImplementation::Rust(RustComponentId)` -> the final Rust-backed
    View implementation naming;
  - `EntityStore::component` and metadata accessors -> `view`.
- Decide serde field names for Takumi metadata and whether existing fixtures
  are regenerated or rejected as stale. Do not add compatibility aliases unless
  this request explicitly justifies an external persisted-data boundary.
- Decide whether crate/module filenames (`component.rs`) should be renamed to
  `view.rs` in the same cut.

## Implementation order

1. Audit `arcweft-ui`, `arcweft-takumi-adapter`, and direct dependents
   (`arcweft-cli`, `arcweft-character-ui`, `arcweft-render-native`,
   `arcweft-render-wgpu`, `arcweft-runtime-host`) for all `Component*` symbols.
2. Either remove the obsolete crate path if unused by production, or rename the
   owned boundary types in one compiling slice.
3. Update Takumi adapter metadata and tests to use `view` terminology.
4. Update crate docs and stable design docs to avoid retained UI `component`
   vocabulary, while leaving unrelated path components and WebAssembly
   component terminology untouched.
5. Run focused tests for `arcweft-ui`, `arcweft-takumi-adapter`, and affected
   renderer/runtime crates before workspace clippy.

## Tests to specify

- `cargo test -p arcweft-ui --all-features`

- Focused renderer/runtime tests that construct retained UI fragments.
- A search gate proving no UI-retained `ComponentId`, `ComponentRegistry`,

## Constraints

- No compatibility shim modules, aliases, deprecated re-exports, or parser
  branches for removed authoring syntax.
- Preserve typed ids; do not replace the rename with stringly typed ids.
- Keep unrelated uses of “component” for filesystem path components,
  WebAssembly components, and graph strongly connected components.
- Do not update checked-in PNG visual baselines from this request.

## Expected output

- A coherent implementation patch or an explicit removal patch for the legacy
  retained UI substrate.
- Updated docs and implementation notes with exact remaining non-goals.
- Validation output showing affected crates compile and tests pass with
  `--all-features`.
