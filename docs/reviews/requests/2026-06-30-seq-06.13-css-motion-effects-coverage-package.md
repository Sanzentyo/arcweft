# Request: seq-06.13 CSS motion and advanced effects coverage package

## Sequence position

Seq06.13 follows seq06.9 compositor effects and should be designed in parallel
with seq06.12 if desired. Production sample integration should wait for the
seq06.11 retained UI frame path when interaction-state styling is involved.

## Problem

Arcweft has direct wgpu primitives and a compositor contract for filters,
backdrop filters, masks, clip paths, and blend modes. It also has explicit gaps
that matter for modern CSS-like UI styling:

- transitions and keyframe animations;
- easing and reduced-motion handling;
- transform-origin and animation composition;
- full `box-shadow` parity;
- CSS `clip-path: path(...)` tessellation;
- `clip-path: url(...)` and `filter: url(...)`;
- `mask: element(...)` and gradient masks;
- HSL-family blend modes such as `hue`, `saturation`, `color`, and
  `luminosity`.

These should not be papered over with CPU raster fallback or browser-specific
rendering.

## Goal

Design and implement a coherent first cut for CSS motion and advanced visual
effects in Arcweft UI.

The package should decide which effects become production-supported now, which
remain explicit diagnostics, and which need separate later requests.

## Required decisions

- Define motion model:
  - transitionable property set;
  - keyframe representation;
  - timeline source;
  - easing functions;
  - interruption/reversal behavior;
  - reduced-motion policy.
- Define renderer ownership:
  - which motion evaluation happens in runtime/player;
  - which effect planning happens in `arcweft-render-wgpu`;
  - which CSS value parsing remains in Takumi adapter boundaries.
- Define animation evidence:
  - sampled timestamps;
  - property values before/after interpolation;
  - visual golden/drift packet expectations.
- Define advanced effect support:
  - `box-shadow` direct/compositor route;
  - `clip-path: path(...)` tessellation strategy;
  - URL-based filter/clip policies;
  - mask gradient support;
  - remaining blend modes and their color-space rules.
- Define diagnostics for unsupported values. Unsupported effects must not be
  silently dropped.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes.
- Keep all rendering in Arcweft-owned wgpu/native-web shared paths.
- Do not use browser DOM/CSS rendering, canvas 2D fallback, screenshots as
  layout input, or CPU-rasterized Takumi output.
- Gate any platform-specific GPU validation behind deterministic smoke or
  disabled CI design if necessary.

## Tests to specify and implement

- Transition interpolation for background color, opacity, transform/scale, and
  outline width if in scope.
- Reduced-motion disables or shortens motion according to the chosen policy.
- Unsupported URL filter/clip values produce structured diagnostics.
- Implemented effect values produce deterministic pass plans.
- Native/web visual smoke captures at multiple timestamps.
- Existing seq06.9 compositor tests continue to pass.

## Expected output

Return a zip named like:

```text
arcweft-seq06.13-css-motion-effects-coverage-YYYY-MM-DD.zip
```

The zip should contain:

- motion/effects design;
- implemented coverage matrix;
- overlay source edits;
- fixtures and visual smoke/golden instructions;
- diagnostics tests;
- validation notes.

## Non-goals

- Do not design CSS layout/cascade support here; seq06.12 owns that.
- Do not connect product UI resources into player frames here; seq06.11 owns
  that unless this package explicitly builds on it after it lands.
