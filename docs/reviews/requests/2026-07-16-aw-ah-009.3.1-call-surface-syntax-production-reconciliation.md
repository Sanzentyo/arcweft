## Basis and contradiction

The production audit was performed at Git commit
`76d39983ad8770a87d6e81745785b6b362a381b4`. The audited AW-AH-009.3 archive is:

```text
arcweft-aw-ah-009.3-character-nominal-signature-help-final-contract.zip
sha256 cdd1d7b764da238a6e4e8f3e774a3384017c8da5ffaea1969f2af279102a7cd5
```

The archive requires every existing call to become:

```rust
Expr::Call {
    callee: Box<Expr>,
    args: Vec<CallArg>,
    syntax: CallExpressionSyntax,
}
```

Its required `CallExpressionSyntax` contains a non-optional
`ArgumentListSyntax`. That list records an opening `(`, optional closing `)`,
comma separators, argument ranges, and parenthesis-specific recovery behavior.

Current production has two call producers that cannot satisfy that invariant:

1. postfix callback-block sugar such as `items.map { item => item.label }`
   lowers directly to `Expr::Call` with one closure argument but has no `(`,
   `)`, or comma-delimited argument list;
2. public constructors and direct synthetic/test construction create
   `Expr::Call` values without any source document or ranges.

Callback-block calls are covered by direct parser and View tests and are not
removed syntax. Treating `{ ... }` as `ArgumentListSyntax` would contradict the
delimiter and cursor rules frozen by AW-AH-009.3. Inventing zero ranges or an
`Option` solely to keep old constructors compiling would violate exact-range and
no-compatibility requirements.

## Required decisions

Select one final owned syntax model and specify exact Rust shapes, private-field
invariants, constructors, accessors, and migration order. At minimum decide:

1. whether parenthesized calls and postfix callback-block applications remain
   one `Expr` variant, become distinct variants, or share a generalized typed
   call-surface enum;
2. which owned type carries exact parenthesized `ArgumentListSyntax`, and how a
   callback block carries its exact brace and closure ranges without pretending
   to be a parenthesized argument list;
3. whether signature help is inapplicable to the callback-block surface or has
   a separately defined cursor/active-parameter contract;
4. whether source AST call construction becomes parser-only, and how genuinely
   generated expressions are represented without fake authored ranges;
5. how current parser recovery retains a typed parenthesized call after a
   missing `)` while preserving the owning construct boundary;
6. how the selected shapes clone through HIR and remain consumable by the one
   AW-AH-009.3 sema resolver; and
7. the exact direct migration for all exhaustive matches and constructors,
   with no compatibility interval.

The final model must distinguish authored source syntax from semantic call
meaning. Do not make every semantic application claim that it has an authored
parenthesized list.

## Required implementation order

Specify compiling cuts in this order:

1. introduce the final syntax-owned range types and their validation;
2. migrate the Pratt parser, callback-block parser, dialogue/speaker surfaces,
   and recovery paths;
3. remove or replace source-less public call construction and migrate direct
   callers;
4. migrate all exhaustive syntax/HIR/sema/tooling matches in one direct model
   replacement;
5. resume AW-AH-009.3 cuts 1 through 6 using only the selected parenthesized
   argument-list carrier; and
6. run focused parser/HIR/sema tests, workspace check/clippy/test, and the
   canonical structural audit.

## Mandatory direct tests

The contract must define observable tests for:

- empty, positional, named, spread, trailing-comma, and nested parenthesized
  calls with exact UTF-8 ranges;
- missing `)` and isolated malformed arguments with exact recovery boundaries;
- postfix callback blocks with zero, one, multiple, and typed closure
  parameters, including multi-statement bodies;
- a parenthesized call followed by a selected callback block;
- generated or programmatically constructed expressions under the selected
  non-authored representation;
- HIR preservation of each authored call-surface kind;
- signature-help applicability inside parentheses and the selected explicit
  behavior inside callback braces; and
- ordinary current-grammar rejection for malformed syntax, without a removed
  spelling recognizer or source scan.

## Fixed constraints and non-goals

- Do not redesign `CharacterNominalType`, accepted semantic-world publication,
  checked LSP position conversion, or the final AW-AH-009.3 resolver/cache
  policies unless this contradiction proves one exact dependent clause
  impossible.
- Do not add a legacy `Expr::Call`, compatibility constructor, deprecated
  accessor, dual AST, extension trait, stringly delimiter kind, or fake range.
- Do not use source gates, after-the-fact source searching, or signature-specific
  node identities.
- Do not restore CSS/Takumi or removed borrow-block syntax/diagnostics.
- Proof-concurrency 01.1.1 is not a prerequisite unless current production
  evidence proves exact ranges cannot satisfy the selected model.
