# Design request: seq-06.11d.2.1.1.3 View-part runtime authority contract

- Date: 2026-07-15
- Kind: independently throwable final-design correction
- Production changes: prohibited
- Prerequisite: final d.2.1.1.2 source/link contract

## Goal

Define the one canonical product-to-runtime validation and identity authority
for exported View parts. The current partial implementation validates an
immutable `AcceptedViewProgram` and derives a capability table, but runtime
lookups still adapt some product strings and the owner/program/part/occurrence
identity mapping is not final.

## Required decisions

1. Freeze the sole validated resource-to-runtime conversion boundary and prove
   invalid products cannot mount or create a second mutable export table.
2. Define deterministic checked/product `ViewDefinitionRef` to runtime
   `ViewId`/`ViewProgramId` mapping across source order, merge, load, and reload.
3. Define owner-local `ViewPartId` allocation and overflow behavior, with no
   runtime string reparsing, suffix lookup, instruction-order public identity,
   or adapter-owned duplicate registry.
4. Define internal occurrence identity for zero/one/many conditional, await,
   keyed-repeat, reorder, nested-repeat, and multi-mount occurrences while
   retaining public non-enumerability.
5. Replace boolean boundary facts with one typed capability/decision model, or
   identify the already-landed equivalent. Preserve one-boundary privacy and
   non-leaking trace evidence.
6. Define ownership and invalidation hooks needed by later replacement without
   designing the replacement transaction itself.
7. Consume d.4.2 environment revision/evidence types if they have landed; do
   not combine independent revision domains.

## Required tests to specify

- deterministic owner/program/part mappings under input reversal and merge;
- overflow and malformed identity fail before mount with empty runtime state;
- private equal-text part, sibling, ancestor, descendant, `CallView`, and two
  boundaries never gain a capability;
- direct child root and explicit export match;
- conditional/repeat occurrence removal clears the exact internal facts;
- inheritance does not grant traversal; and
- trace/evidence exposes only public owner/capability and rejection reason.

## Constraints and expected output

Do not redesign source linking, Style cascade, tokens, rendering, public trace
transport, or hot reload. Do not retain the current string-adaptation path as a
compatibility API. Return one self-contained decision-complete design package
with exact APIs, ownership diagram, conversion/deletion inventory, tests,
implementation order, structural plan, and no open result-changing question.
