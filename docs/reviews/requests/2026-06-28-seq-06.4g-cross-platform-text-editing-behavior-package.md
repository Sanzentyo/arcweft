# Request 06.4g: Cross-Platform Text Editing Behavior Package

> **Superseded (2026-07-13):** Arcweft Style is now native-only. The CSS authoring and Takumi product-path premises in this request were removed; see [Native-only typed Style path](../../implementation/native-only-style-path-2026-07-13.md). Do not use this request to reintroduce or reimplement CSS/Takumi Style behavior.

## Sequence Position

This follows the seq06.3 common text-input contract and should be designed in
parallel with platform window-integration work:

- seq06.4a.2 Web EditContext caret/geometry/selection.
- seq06.4b.1 Windows TSF COM bootstrap and window integration.
- seq06.4c.1 macOS AppKit window integration.
- seq06.4d Wayland text-input-v3 adapter.
- seq06.4e Android InputConnection adapter.
- seq06.4f iOS UITextInput adapter.

It should not replace platform adapters. It defines the shared editor behavior
that all adapters must feed and validate: caret movement, selection ranges,
edit commands, deletion, composition painting, secure redaction, and geometry
refresh.

## Problem

The common protocol has `TextEditCommand`, selection, composition, and geometry
types, but the product behavior for an editable TextField/TextArea is not yet
complete enough to make Web and native IME samples behave like real text
controls. Without a shared editor behavior owner, every platform adapter risks
implementing arrow movement, mouse selection, deletion, shortcut handling,
composition replacement, and caret geometry differently.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for the cross-platform
Arcweft text editing behavior layer.

The package must define and implement the editor-side state transition owner
that receives normalized `TextInputOperation` and non-IME key/pointer commands,
updates text/selection/composition/revision, and emits fresh
`TextInputClientSnapshot` and `TextInputGeometrySnapshot` values for platform
adapters.

## Required Decisions

1. Which crate/module owns the cross-platform editor state machine.
2. The canonical text model:
   - committed text;
   - selection range and affinity;
   - active composition range;
   - preedit text and segments;
   - revision counter;
   - secure/plain policy.
3. How byte, UTF-16, scalar, and grapheme movement are resolved. Movement should
   use a shared text-index/grapheme owner, not per-platform helper code.
4. How `TextEditCommand` is applied:
   - left/right;
   - word left/right;
   - line start/end;
   - backspace/delete;
   - select-all;
   - copy/cut/paste;
   - submit/cancel.
5. How pointer hit-testing and drag selection map rendered glyph positions to
   canonical text ranges.
6. How selected-text replacement and delete-surrounding interact with active
   composition.
7. How composition update, commit, cancel, and focus loss modify the model.
8. How geometry snapshots are generated after every edit, selection move,
   scroll, transform, style change, font fallback change, or layout reflow.
9. How secure fields redact text, clipboard, selection-derived geometry,
   observation, replay, and capture metadata.
10. How Web/native platform adapters receive updated snapshots without owning
    editor semantics.

## Required Implementation

- Add or complete a shared text editor state module for TextField/TextArea.
- Implement `TextInputOperation` application against that state.
- Implement non-IME key and pointer routing into editor commands and selection
  updates.
- Implement collapsed caret and ranged selection geometry generation.
- Implement composition visual state:
  - preedit;
  - selected composition segment;
  - converted/target converted segments where available;
  - committed text after composition end.
- Integrate the editor state with Web player-owned glue and native window owner
  boundaries by typed snapshots, not platform object handles.
- Add secure-field redaction tests and source gates.
- Add deterministic fixtures for text movement, replacement, deletion,
  selection, composition, and geometry.
- Add implementation documentation under `docs/implementation/`.

## Platform Acceptance Hooks

Each platform adapter package must be able to consume this layer without
duplicating editor behavior:

- Web EditContext: receives refreshed text/selection and candidate geometry;
  browser/native caret does not render independently of Arcweft caret.
- Windows TSF: `ITextStoreACP` reads/writes through the shared editor state;
  layout callbacks use the shared geometry snapshot.
- macOS AppKit: `NSTextInputClient` callbacks normalize through shared state;
  `firstRectForCharacterRange`/caret queries use shared geometry.
- Wayland text-input-v3: `done` batches feed shared state and receive updated
  surrounding text/cursor rectangle.
- Android InputConnection: batch edits feed shared state; extracted/surrounding
  text and cursor-anchor info come from shared snapshots.
- iOS UITextInput: marked text, selected text range, and caret rect queries use
  shared state and geometry.

## Acceptance Criteria

- The same editor state machine handles Web and native text operations.
- Arrow-key and pointer caret movement update the canonical selection.
- Ranged selection supports replacement, delete, cut/copy/paste policy, and
  select-all.
- IME preedit, commit, cancel, and composition selection are deterministic.
- Candidate/caret geometry updates after edits, selection moves, scroll,
  transform, and font/layout changes.
- Secure fields redact text and selection-derived sensitive metadata.
- Platform adapters do not duplicate editor movement/deletion semantics.
- Tests cover ASCII, Japanese text, surrogate pairs, combining sequences, and
  mixed-font layout.

## Tests To Specify And Run

- Pure editor-state tests for movement, selection, deletion, replacement,
  composition, and secure redaction.
- Geometry tests for collapsed caret, ranged selection, composition range,
  scroll/transform, vertical writing where supported, and font fallback.
- Web integration smoke after seq06.4a.2.
- Native adapter contract tests for TSF/AppKit/Wayland/Android/iOS fixture
  traces where platform runtime validation is unavailable.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test`/`cargo clippy` for changed crates.
- Platform-specific validation commands documented for Windows, macOS, Wayland,
  Android, and iOS.
- Structural audit when module/crate boundaries or public contracts change.

## Constraints

- Do not move platform object identity into Sans I/O editor state.
- Do not implement separate movement/deletion semantics per platform.
- Do not hide native text entry controls behind fallback textareas or
  contenteditable surfaces.
- Do not weaken secure redaction to make geometry or clipboard tests easier.
- Do not redesign seq06.3 contracts unless a concrete defect is documented and
  fixed with tests.

## Non-Goals

- Implementing each platform's OS bootstrap in this package.
- General rich document editing beyond TextField/TextArea/SecureField.
- Replacing Takumi lowering or renderer ownership.
