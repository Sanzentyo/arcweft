# Request: Function Stack Spread Partial and Data-Last Fallback Contract

Status: current-milestone contract closed. Inline fixed-length literal spread
is accepted for function-value calls, direct fixed-parameter signature calls,
and data-last method fallback. Variable-length spread remains rejected in
partial-call construction and data-last fallback by language contract; it is
not an implementation TODO for this goal.

## Sequence Position

Split from `2026-07-07-seq-07.2-function-stack-placeholder-inference-and-method-fallback.md`
after the fixed positional/named partial-call and method-fallback cuts.

## Why This Split Is Needed

Arcweft now supports partial-call abstraction for known fixed signatures,
including positional placeholders, fixed named placeholders, named
missing-input partial calls, and helper-backed top-level signature partials.
Spread arguments are still deliberately excluded from those paths:

- `CallArg::Spread` may expand to zero, one, or many runtime arguments.
- Rest parameters have sequence-item semantics, while fixed missing inputs have
  positional slot semantics.
- Data-last fallback needs deterministic runtime argument order and currently
  records a fixed call-argument/receiver order in typed lowering evidence.
- Runtime helper lowering can reorder fixed named inputs by helper input name,
  but it does not have a contract for mixing runtime spread expansion with
  missing-input function construction.

Implementing spread support without a contract would either silently choose an
argument expansion model or emit runtime calls whose arity cannot be proven by
sema. This request defines the missing design work before implementation.

## Required Decisions

1. Decided: partial-call abstraction allows spread only when the spread source
   is an inline fixed-length bracket sequence or compact numeric bracket
   sequence literal. Variable-length spread remains rejected with structured
   diagnostics.
2. Decided: fixed-length literal spread maps to fixed parameter slots by
   expanding the known literal length during type checking while preserving one
   runtime `SpreadArg` in lowering. Variable-length spread may target ordinary
   exact-call rest parameters through the existing signature-call rules, but it
   does not participate in fixed missing-input function construction.
3. Define whether `_` placeholders may appear inside spread source expressions,
   for example `add(values.map(_ + 1)...)`, and whether those placeholders
   belong to the outer partial-call abstraction or to the spread expression
   itself.
4. Decided for this milestone: `RuntimeExpr::Apply` already expands
   `RuntimeExpr::SpreadArg` at evaluation time for exact, partial, and curried
   runtime function application, and function-value calls may now lower an
   inline fixed-length bracket sequence literal spread to that substrate.
   Direct fixed-parameter signature calls may also use inline fixed-length
   literal spread for exact and missing-input partial calls. No
   variable-length source-level spread subset lowers to that substrate for
   partial-call construction in this goal.
5. Decided: typed lowering evidence for data-last method fallback records an
   inline fixed-length source spread argument once at the first covered
   parameter slot, and runtime-plan preserves it as one `RuntimeExpr::SpreadArg`
   in the proven data-last order. Variable-length spread is rejected before
   fallback selection records chosen-order evidence.
6. Done: structured diagnostics cover unsupported combinations:
   fixed parameter after spread, named argument after spread, multiple spreads,
   spread into non-rest parameters, spread plus missing named inputs, and
   ambiguous callable candidates.
7. Decided: source-level fixed-length literal spread may finish the current
   call group, and runtime `Apply` may continue across curried runtime function
   boundaries after expansion. Variable-length spread in source-level
   partial-call construction remains rejected rather than crossing group
   boundaries.

## Implementation Order

1. Specify the accepted and rejected spread shapes in language docs and tests.
   The current milestone accepts inline fixed-length literal spread and rejects
   variable-length spread in partial-call construction and data-last fallback.
2. Add sema diagnostics for rejected spread partial/fallback combinations
   before adding executable lowering. Implemented coverage currently includes
   plain fixed-signature spread partials, `_` placeholder spread partials,
   named missing-input spread partials, spread followed by positional/named
   fixed partial-call arguments, multiple-spread partial-call construction,
   data-last method fallback spread, data-last spread followed by named fixed
   fallback arguments, multiple-spread data-last fallback, and a curried
   function first group plus later function-value call group with spread.
3. Extend typed lowering evidence only for accepted deterministic source-order
   shapes.
4. Done for low-level runtime substrate, fixed-length function-value calls,
   fixed-signature calls, and data-last method fallback: VM pure evaluation
   applies spread-expanded args to runtime functions, checked runtime-plan
   lowering preserves `RuntimeExpr::SpreadArg` for accepted inline fixed-length
   literal spreads in function-value calls, direct fixed-parameter signature
   calls, and evidence-backed data-last method fallback calls.
   Variable-length source-level spread partial/fallback remains rejected by
   contract.
5. Add compiler/runtime-plan tests for both sema-only rejected cases and
   executable accepted cases.

## Tests To Specify

- Fixed signature partial with spread rejected or accepted by contract:
  `let f = add(values...)` remains a structured rejection in
  `rejects_fixed_signature_partial_call_with_spread` when the spread source is
  variable-length. Inline fixed-length literal spread is accepted in
  `fixed_literal_spread_signature_call_typechecks_as_exact_and_partial_application`.
- Placeholder partial with spread source:
  `let f = add(_, values...)`. Implemented as structured rejection in
  `rejects_partial_call_placeholder_mixed_with_spread`.
- Named missing input mixed with spread:
  `let f = add(right = 1i64, values...)`. Implemented as structured rejection
  in `rejects_named_missing_input_partial_call_mixed_with_spread`.
- Spread before a fixed positional argument:
  `let f = add(values..., 1i64)`. Implemented as structured rejection in
  `rejects_partial_call_spread_before_positional_fixed_arg` for variable
  spread. The fixed literal shape `add([1i64]..., 2i64)` is accepted in
  `fixed_literal_spread_signature_call_typechecks_as_exact_and_partial_application`.
- Spread before a fixed named argument:
  `let f = add(values..., right = 1i64)`. Implemented as structured rejection
  in `rejects_partial_call_spread_before_named_fixed_arg`.
- Multiple spreads in partial-call construction:
  `let f = add(lefts..., rights...)`. Implemented as structured rejection in
  `rejects_partial_call_multiple_spreads_with_structured_diagnostic` for
  variable spread sources. Multiple inline fixed-length literal spreads are
  covered by the same fixed-slot expansion contract.
- Rest parameter spread:
  `fn log(prefix: String, fields: ...String) -> Unit` with
  `let later = log("prefix", fields...)`.
- Data-last method fallback with spread:
  `score.above(thresholds...)`. Variable spread remains a structured rejection
  in `method_chain_reports_spread_data_last_fallback_as_unsupported`. Inline
  fixed-length literal spread is accepted in
  `method_chain_accepts_fixed_literal_spread_data_last_fallback`.
- Data-last method fallback with spread followed by a named fixed argument:
  `score.between(thresholds..., max = 99i64)`. Implemented as structured
  rejection in
  `method_chain_reports_spread_then_named_data_last_fallback_as_unsupported`.
- Data-last method fallback with multiple spreads:
  `score.between(lows..., highs...)`. Implemented as structured rejection in
  `method_chain_reports_multiple_spread_data_last_fallback_as_unsupported`.
- Curried callable with spread in the first and later call groups.
  First call groups are covered by
  `curried_function_rejects_first_group_spread_partial_with_structured_diagnostic`.
  Later function-value call groups are covered by
  `curried_function_value_rejects_later_spread_group_with_structured_diagnostic`;
  inline fixed-length literal spread in a later function-value group is covered
  by `curried_function_value_accepts_fixed_literal_spread_group`, while
  variable-length source spread remains rejected by the current contract.
- Checked runtime-plan lowering for accepted inline fixed-length function-value
  spread apply. Implemented in
  `checked_runtime_plan_lowers_function_value_fixed_literal_spread_apply`.
- Checked runtime-plan lowering for accepted inline fixed-length signature
  exact and partial spread apply. Implemented in
  `checked_runtime_plan_lowers_signature_fixed_literal_spread_apply`.
- Checked runtime-plan lowering for accepted inline fixed-length data-last
  method fallback spread. Implemented in
  `runtime_plan_lowers_fixed_literal_spread_data_last_method_fallback`.
- Runtime function apply with spread-expanded args. Implemented for the
  runtime substrate in
  `vm_pure_backend_applies_runtime_function_with_spread_args`,
  `vm_pure_backend_partially_applies_runtime_function_with_spread_prefix`, and
  `vm_pure_backend_applies_curried_runtime_function_with_spread_args`.
- Ambiguous spread fallback candidates that must report every candidate rather
  than selecting by environment merge order.
  Implemented as structured ambiguity in
  `method_chain_reports_ambiguous_spread_data_last_fallback_candidates`.

## Constraints

- Do not redesign fixed positional/named partial-call behavior already
  implemented and verified.
- Do not weaken real method priority over data-last fallback.
- Do not introduce compatibility syntax or formatter normalization shims.
- Keep runtime-plan evidence deterministic and source-order auditable.
- Keep data-format crates Sans I/O.

## Expected Output

- Updated syntax/sema/runtime-plan design notes for spread partials.
- Sema diagnostics and tests for every rejected spread shape.
- Runtime-plan and compiler tests for any accepted executable spread shape.
- Implementation evidence under `docs/implementation/` linking back to this
  request.
