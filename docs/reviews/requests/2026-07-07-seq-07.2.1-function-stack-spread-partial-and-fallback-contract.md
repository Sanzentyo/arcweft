# Request: Function Stack Spread Partial and Data-Last Fallback Contract

## Sequence Position

Split from `2026-07-07-seq-07.2-function-stack-placeholder-inference-and-method-fallback.md`
after the fixed positional/named partial-call and method-fallback cuts.

## Why This Split Is Needed

Arcweft now supports partial-call abstraction for known fixed signatures,
including positional placeholders, fixed named placeholders, named
missing-input partial calls, and helper-backed top-level signature partials.
Spread arguments are still deliberately excluded from those paths:

- `CallArg::Spread` may expand to zero, one, or many runtime arguments.
- Rest parameters have sequence-item semantics, while fixed missing inputs have
  positional slot semantics.
- Data-last fallback needs deterministic runtime argument order and currently
  records a fixed call-argument/receiver order in typed lowering evidence.
- Runtime helper lowering can reorder fixed named inputs by helper input name,
  but it does not have a contract for mixing runtime spread expansion with
  missing-input function construction.

Implementing spread support without a contract would either silently choose an
argument expansion model or emit runtime calls whose arity cannot be proven by
sema. This request defines the missing design work before implementation.

## Required Decisions

1. Decide whether spread arguments are allowed in partial-call abstraction at
   all, or whether spread remains rejected with structured diagnostics.
2. If allowed, define how a spread expression maps onto fixed parameters,
   rest parameters, and missing-input function parameters.
3. Define whether `_` placeholders may appear inside spread source expressions,
   for example `add(values.map(_ + 1)...)`, and whether those placeholders
   belong to the outer partial-call abstraction or to the spread expression
   itself.
4. Define the runtime lowering shape for spread partials:
   `RuntimeExpr::Function` body with spread expansion, dedicated apply form, or
   rejection until an executable spread-call ABI exists.
5. Define typed lowering evidence for data-last method fallback with spread
   arguments. The current `DataLastMethodFallbackArg::{CallArg, Receiver}`
   contract is fixed-order and does not encode runtime-expanded argument
   ranges.
6. Define diagnostics for unsupported combinations:
   fixed parameter after spread, named argument after spread, multiple spreads,
   spread into non-rest parameters, spread plus missing named inputs, and
   ambiguous callable candidates.
7. Define how curried call groups interact with spread: whether spread may
   finish only the current group, cross group boundaries, or be rejected.

## Implementation Order

1. Specify the accepted and rejected spread shapes in language docs and tests.
   The current implemented boundary rejects spread inside fixed-signature
   partial-call construction and data-last fallback until the runtime spread
   expansion contract is designed.
2. Add sema diagnostics for rejected spread partial/fallback combinations
   before adding executable lowering. Implemented coverage currently includes
   plain fixed-signature spread partials, `_` placeholder spread partials,
   named missing-input spread partials, data-last method fallback spread, and a
   curried function first group plus later function-value call group with
   spread.
3. Extend typed lowering evidence only after the runtime order/range contract is
   fixed.
4. Implement runtime-plan lowering for the accepted subset.
5. Add compiler/runtime-plan tests for both sema-only rejected cases and
   executable accepted cases.

## Tests To Specify

- Fixed signature partial with spread rejected or accepted by contract:
  `let f = add(values...)`. Implemented as structured rejection in
  `rejects_fixed_signature_partial_call_with_spread`.
- Placeholder partial with spread source:
  `let f = add(_, values...)`. Implemented as structured rejection in
  `rejects_partial_call_placeholder_mixed_with_spread`.
- Named missing input mixed with spread:
  `let f = add(right = 1i64, values...)`. Implemented as structured rejection
  in `rejects_named_missing_input_partial_call_mixed_with_spread`.
- Rest parameter spread:
  `fn log(prefix: String, fields: ...String) -> Unit` with
  `let later = log("prefix", fields...)`.
- Data-last method fallback with spread:
  `score.above(thresholds...)`. Implemented as structured rejection in
  `method_chain_reports_spread_data_last_fallback_as_unsupported`.
- Curried callable with spread in the first and later call groups.
  First call groups are covered by
  `curried_function_rejects_first_group_spread_partial_with_structured_diagnostic`.
  Later function-value call groups are covered by
  `curried_function_value_rejects_later_spread_group_with_structured_diagnostic`;
  executable runtime spread partial semantics remain pending the accepted
  spread contract.
- Ambiguous spread fallback candidates that must report every candidate rather
  than selecting by environment merge order.
  Implemented as structured ambiguity in
  `method_chain_reports_ambiguous_spread_data_last_fallback_candidates`.

## Constraints

- Do not redesign fixed positional/named partial-call behavior already
  implemented and verified.
- Do not weaken real method priority over data-last fallback.
- Do not introduce compatibility syntax or formatter normalization shims.
- Keep runtime-plan evidence deterministic and source-order auditable.
- Keep data-format crates Sans I/O.

## Expected Output

- Updated syntax/sema/runtime-plan design notes for spread partials.
- Sema diagnostics and tests for every rejected spread shape.
- Runtime-plan and compiler tests for any accepted executable spread shape.
- Implementation evidence under `docs/implementation/` linking back to this
  request.
