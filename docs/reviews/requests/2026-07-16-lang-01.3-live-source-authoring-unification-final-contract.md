# Request: Live source authoring unification final contract

## Sequence position

This is Lang-01.3, split from the 2026-07-16 top-level declaration reduction.
It may proceed independently of function suspension syntax and typed resource
syntax. It must not redesign the existing Sans I/O source runtime merely to
remove an author keyword.

## Why this split is needed

The current `source` declaration is not an empty scaffold. It owns a stable
source ID, `Source<T, E>`, a `from` expression, backpressure, replay and privacy
policies, event handlers, RuntimePlan/AWBC tables, runtime stepping, and
snapshot state. At the same time, an author-facing dedicated top-level keyword
may be unnecessary if an ordinary function plus a typed descriptor or manifest
binding can express the same contract without hiding policy.

## Required decisions

1. Decide whether the canonical author surface is:
   - an ordinary function returning a typed `SourceDescriptor<T, E>`;
   - an ordinary function with one typed `#[source(...)]` attribute;
   - a typed manifest binding to an ordinary constructor/handler set;
   - or a retained `source` declaration, only if the alternatives create a
     concrete semantic or tooling defect.
2. Preserve explicit stable identity, backpressure, replay, privacy, handler,
   capability, and adapter ownership in the selected model.
3. Define which fields are const/build-time metadata and which expressions run
   at open, event, resume, or close time.
4. Define handler typing and effect/cancellation rules without storing handler
   source as raw strings.
5. Specify source construction, subscription/open, item/progress/error,
   disconnect, permission revocation, end, close, and restart timing.
6. Define save/replay/hot-reload identity and snapshot compatibility for the
   unreleased final format.
7. Map the author model into the existing internal `SourcePlan` and AWBC source
   table, or provide evidence for a replacement.
8. Define tooling discovery, navigation, hover, completion, and diagnostics.

## Implementation order to specify

1. Source lifecycle and policy timing table.
2. Final author grammar and typed AST/HIR representation.
3. Sema/effect/capability validation.
4. Direct RuntimePlan/AWBC lowering and snapshot mapping.
5. Tooling and documentation migration.
6. Deletion of the old source parser and syntax kinds if the keyword is not
   retained.

## Tests to specify

- Every policy and lifecycle event round-trips through RuntimePlan/AWBC.
- Backpressure, replay, privacy, permission, cancellation, and restart are
  deterministic and directly observable.
- Handler input/output/effects are type checked on the ordinary callable path
  where applicable.
- Save/load and hot reload preserve or reject source snapshot identity as
  specified.
- Tooling resolves constructor/handler declarations rather than a string
  spelling.
- If `source` is removed, its old spelling has no AST/CST/HIR compatibility
  node or dedicated removal diagnostic.

## Constraints

- Do not collapse live external sources into ordinary in-memory `Stream<T, E>`
  values if doing so loses replay, privacy, backpressure, or stable identity.
- No dual author surfaces, compatibility aliases, source gates, or stringly
  policy bags.
- Keep core/source plans Sans I/O; adapter opening remains outside core.

## Expected output

- A final keep/remove decision for the `source` keyword.
- Canonical syntax and examples.
- Typed lifecycle, policy, HIR, RuntimePlan, AWBC, and snapshot contracts.
- A direct implementation/deletion plan and tests.
