# Request: Function Stack Placeholder Inference and Method Fallback

## Context

Expected-type `_` is implemented for explicit function annotations and the
collection `map`/`filter` optimization paths. No-expected-type inference,
partial-call abstraction, and method-chain fallback now exist for the
constrained cases recorded below.

Method-chain fallback is implemented for typed fixed data-last callables: real
methods win first, and unresolved method syntax can fall back when a callable
signature takes the receiver as its last parameter. Spread fallback remains a
separate contract request.

Implementation progress on 2026-07-07:

- Sema now infers no-expected `_` abstraction for unambiguous binary expressions
  where the non-placeholder operand has a static/local type, such as
  `let high = _ > 80i64` and `let high = (_ > 80i64)`.
- Sema now infers partial-call abstraction for known positional function
  signatures, such as `let add_one = add(_, 1i64)`.
- Sema now accepts named missing-input partial application for checked
  top-level function signatures, such as `let add_to_one = add(right = 1i64)`,
  returning a function over the missing helper input(s). Runtime-plan lowering
  emits a `RuntimeExpr::Function` that calls the annotated or inferred helper
  with provided named inputs in helper input order.
- Direct top-level signature partial calls now export
  `SignaturePartialCall` typed lowering evidence. Checked runtime-plan lowering
  rejects such calls when no executable helper can be produced, so unsupported
  top-level partial callables cannot silently lower as incomplete adapter
  calls.
- Runtime-plan lowering consumes the inferred function evidence and lowers both
  forms to `RuntimeExpr::Function`.
- Sema now resolves data-last method fallback when no real method
  matches and a callable signature exists with the receiver as its last
  parameter, such as `score.above(80i64)` lowering as `above(80i64, score)`.
  The decision is exported as typed lowering evidence, and runtime-plan lowering
  consumes that evidence before emitting a helper call. Named method arguments
  are recorded in signature parameter order, so `score.above(min = 80i64)`
  lowers as `above(80i64, score)` rather than source order. Real
  env/inherent/trait methods keep priority and do not emit fallback evidence.
- Sema still reports data-last fallback candidates that use spread arguments
  with a structured `UnsupportedDataLastMethodFallback` diagnostic instead of
  falling through to `unknown method`.

## Required Decisions

- Extend inference rules for `_` regions without an expected function type
  beyond the implemented unambiguous binary and known callable-signature cases.
- Define multi-placeholder behavior beyond the implemented "repeated `_` means
  the same generated parameter when all inferred parameter types agree" rule.
- Extend partial call abstraction lowering beyond known positional signatures.
  Done for fixed named arguments backed by a known function signature and
  annotated/inferred helper input names, including top-level named missing
  inputs. Spread arguments are split to
  `2026-07-07-seq-07.2.1-function-stack-spread-partial-and-fallback-contract.md`
  because their argument expansion and runtime evidence contract is still
  underspecified.
- Method-chain resolution order is implemented for fixed data-last fallback:
  1. inherent method;
  2. trait method;
  3. data-last callable fallback.
- Ambiguity diagnostics are implemented for module/environment fallback
  overlap. Spread fallback candidates are rejected or diagnosed according to
  the split spread contract.

## Implementation Order

1. Extend sema inference for no-expected `_` regions. Done for unambiguous
   binary expressions with a static/local non-placeholder operand.
2. Implement partial call abstraction as function values. Done for known
   positional callable signatures and fixed named arguments backed by known
   signatures.
3. Parenthesized partial expressions now use the same inferred body expression
   path as unparenthesized partial expressions.
4. Method-chain fallback uses typed callable evidence for data-last signatures
   whose receiver is the final parameter, including named method arguments via
   recorded runtime argument order. Spread fallback candidates still produce
   structured unsupported diagnostics. Real env/inherent/trait methods remain
   authoritative, and viable fallback candidates hidden by those methods now
   surface as shadowing warnings. Executable spread fallback lowering and
   curried call-group runtime metadata remain open; the spread contract is
   split to seq-07.2.1.
5. Add diagnostics for ambiguous fallback cases. Done for multiple viable
   module/environment data-last fallback candidates.

## Tests To Specify

- `let is_high = _ > 80i64`. Covered by
  `infers_partial_placeholder_function_without_expected_type`.
- `let is_high = (_ > 80i64)`. Covered by
  `infers_parenthesized_partial_placeholder_function_without_expected_type` and
  `runtime_plan_lowers_inferred_partial_placeholder_functions`.
- `let add_one = add(_, 1i64)`. Covered by
  `infers_partial_call_abstraction_without_expected_type` and
  `runtime_plan_lowers_inferred_partial_placeholder_functions`.
- Repeated `_` in one abstraction region with compatible inferred parameter
  types. Covered by
  `infers_repeated_partial_call_placeholders_as_one_parameter` and
  `runtime_plan_lowers_inferred_partial_placeholder_functions`.
- `let add_to_one = add(right = _, left = 1i64)`. Covered by
  `infers_named_partial_call_placeholder_from_signature_parameter`,
  `strict_runtime_reorders_named_pure_helper_args_by_input_name`, and
  `runtime_plan_lowers_inferred_partial_placeholder_functions`.
- `let add_to_one = add(right = 1i64)`. Covered by
  `non_annotated_function_named_missing_input_typechecks_as_partial_application`,
  `strict_runtime_lowers_named_missing_pure_helper_input_to_function`, and
  `runtime_plan_lowers_named_missing_inferred_helper_input`.
- Non-helper top-level signature partial calls are rejected by checked runtime
  lowering instead of lowering as adapter calls. Covered by
  `checked_runtime_plan_rejects_non_helper_signature_partial_call`.
- Inherent/env method wins over data-last fallback. Covered by
  `method_chain_prefers_real_method_over_data_last_callable_fallback`.
- Trait method wins over data-last fallback. Covered by
  `method_chain_prefers_trait_method_over_data_last_callable_fallback`.
- Ambiguous fallback reports all candidates. Covered for module/environment
  fallback overlap by
  `method_chain_reports_ambiguous_data_last_fallback_candidates`.
- Named data-last fallback records deterministic runtime argument order.
  Covered by
  `method_chain_accepts_named_data_last_fallback_and_records_arg_order` and
  `runtime_plan_lowers_typed_data_last_method_fallback`.
- Spread data-last fallback candidates report structured unsupported diagnostics
  instead of generic unknown-method errors. Covered by
  `method_chain_reports_spread_data_last_fallback_as_unsupported`.
- `score.above(80i64)` where `above(min: i64, value: i64) -> bool`. Covered by
  `method_chain_falls_back_to_data_last_callable_when_no_method_matches` and
  `runtime_plan_lowers_typed_data_last_method_fallback`.
- Real method priority over fallback also emits
  `sema.typecheck.shadowed_data_last_method_fallback` when a fallback would
  otherwise be viable.

## Constraints

- Do not accept removed syntax.
- Do not add formatter normalization shims.
- Do not special-case a single callable such as `add`.

## Expected Output

- Sema inference tests.
- Runtime-plan function/apply lowering tests.
- Structured diagnostics and docs updates.
