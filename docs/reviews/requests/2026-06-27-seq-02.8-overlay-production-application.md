# Seq-02.8 Seq-02 Overlay Production Application

## Sequence Position

This request is the final seq-02 cleanup gate. It follows seq-02.1 through
seq-02.7 and exists to review any generated seq-02 overlay or package patch as
production code after the underlying contracts are designed.

Do not apply a generated overlay directly to production before the relevant
resource codec, patch v2, AWFR, external payload, and signing-policy decisions
are complete.

## Why This Split Is Needed

The seq-02 package contained overlay material, but the first-cut implementation
note explicitly records that no generated overlay from `apply_seq_02.py` was
applied as a production patch. The overlay can still be useful as source
material, fixture inspiration, or a checklist, but production application must
be audited file-by-file against the implemented seq-02.x contracts.

## Required Decisions

1. Classify every overlay hunk as already implemented, still valid, superseded
   by seq-02.x design, unsafe, speculative, or obsolete.
2. Decide which overlay hunks should be translated into production patches and
   which should be discarded.
3. Decide whether overlay fixtures should become golden fixtures, smoke tests,
   review-only examples, or deleted scratch material.
4. Verify that overlay code does not reintroduce JSON product fallback,
   compatibility shims, codec probing, raw signature passthrough, ad hoc
   section-family fingerprinting, or Sans I/O violations.
5. Verify crate layering and ownership against AGENTS.md and the seq-02.x
   designs.
6. Define the exact commit/push cut points for production application.
7. Define final seq-02 completion criteria and remaining non-goals, if any.

## Implementation Order To Specify

1. Extract or locate the overlay in a scratch area outside active production
   modules.
2. Produce an overlay classification table with file/hunk/status/rationale.
3. Apply only the hunks that match completed seq-02.x contracts, using normal
   production edits.
4. Add or update focused tests for each accepted hunk.
5. Remove scratch output and obsolete generated files.
6. Run formatting, focused tests, workspace validation, and structural audit.
7. Update `docs/implementation/` with final seq-02 status, deviations, and
   remaining TODOs.

## Tests To Specify

- all seq-02.1 through seq-02.7 focused tests remain passing;
- `just test-workspace`;
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`;
- `cargo +nightly -Zscript tools/structure-audit.rs --root .`;
- source gates against product JSON fallback and removed compatibility shims;
- overlay classification table is complete and references every hunk/file;
- no workspace-external active `crates/`, `tests/`, or fixture directories are
  left behind.

## Constraints

- Do not apply generated overlay code blindly.
- Do not preserve temporary compatibility layers from overlay code.
- Do not let scratch overlay directories look like active workspace code.
- Do not reopen already implemented and verified seq-02.x substrate unless the
  overlay exposes a concrete flaw.
- Keep repository structure part of the deliverable, not an afterthought.

## Non-Goals

- Designing new resource codec, patch v2, AWFR, external payload, or signing
  policy contracts that were intentionally left to seq-02.1 through seq-02.7.
- Implementing seq3 generation/windowed live patch behavior.
- Preserving historical overlay code merely because it existed in a package.

## Expected Output

Produce a final seq-02 production-application package with:

- overlay classification table;
- accepted/rejected hunk rationale;
- production change summary;
- validation commands and results;
- structural audit summary;
- final seq-02 implementation note update;
- explicit remaining TODOs or a statement that seq-02 is complete.
