# Request: seq-06.13a clip-path and mask render closure package

## Sequence position

Seq06.13a is split out of the broader seq06.13 CSS motion/effects request. It
focuses only on clip-path and mask rendering closure.

It should build on seq06.9a/06.9b compositor contracts and should integrate with
seq06.11b's player path once that path lands.

## Problem

Arcweft has typed clip and mask contracts:

- `ViewClipPath`;
- `ViewMask`;
- `ViewMaskChainPlan`;
- clip/mask capture metadata;
- Takumi lowering for many compositing fields.

However, the evidence suggests these are not yet fully applied as final pixel
constraints in the normal compositor execution path:

- `clip-path: inset(...)`, circle/ellipse, and polygon have plan-level support
  but need renderer application evidence;
- CSS `path()` is explicitly unsupported until a vector tessellator is chosen;
- `clip-path: url(...)` remains unsupported;
- `mask-size`, `mask-position`, `mask-repeat`, and mask channel behavior need
  exact shader/resource evidence;
- gradient masks and `mask: element(...)` are not supported.

## Goal

Design and implement a first production closure for clip-path and mask rendering
in Arcweft View.

The implemented subset should produce actual clipped/masked pixels in native
and web through the shared wgpu compositor path.

## Required decisions

- Define the supported clip-path subset for this cut:
  - inset;
  - circle;
  - ellipse;
  - polygon;
  - explicit non-goal or follow-up for `path()`.
- Decide clip implementation strategy:
  - analytic mask;
  - stencil;
  - generated coverage texture;
  - or another deterministic wgpu route.
- Define mask geometry behavior:
  - `mask-size`;
  - `mask-position`;
  - `mask-repeat`;
  - alpha vs luminance;
  - multiple masks and ordering.
- Define external mask resource provider contract across native/web.
- Decide how unsupported mask images are diagnosed:
  - gradient masks;
  - `element(...)`;
  - invalid URL references.
- Define visual/capture evidence:
  - local bounds;
  - visual bounds;
  - mask bounds;
  - pixel-level smoke/golden thresholds.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes.
- Keep all rendering in Arcweft-owned wgpu paths.
- Do not use browser CSS clipping, DOM masks, SVG filters, canvas 2D fallback,
  or CPU-rasterized Takumi output.
- Keep file/network loading outside data-format crates.
- Unsupported values must produce structured diagnostics, not silent no-ops.

## Tests to specify and implement

- Inset clip changes visible pixels in a deterministic fixture.
- Circle/ellipse clip changes visible pixels and reports correct bounds.
- Polygon clip renders with deterministic winding/fill rules.
- `path()` clip emits a typed unsupported diagnostic unless implemented.
- `mask-size` / `mask-position` / `mask-repeat` produce expected mask sampling
  behavior.
- Alpha and luminance mask modes differ in a testable way.
- External mask resource missing/provider failure produces typed diagnostics.
- Native/web visual smoke captures compare within documented thresholds.

## Expected output

Return a zip named like:

```text
arcweft-seq06.13a-clip-path-and-mask-render-closure-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- renderer/compositor overlay edits;
- mask/clip fixtures;
- focused tests;
- native/web validation instructions;
- deferred list for `path()`, URL clip paths, gradient masks, and
  `element(...)`.

## Non-goals

- Do not implement CSS transitions/keyframes here.
- Do not implement full CSS layout/cascade here.
- Do not solve box-shadow or color-family blend modes here unless needed for a
  local clip/mask fixture.
