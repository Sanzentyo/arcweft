# Design request: seq-06.11d.4.1.2.1 native physical geometry production reconciliation

- Date: 2026-07-16
- Kind: independently throwable final-design correction
- Output language: English
- Production changes: prohibited in this design task

## Task mode and sequence position

Produce one corrected, implementation-ready contract that reconciles native
physical box geometry with the current retained View runtime. Inspect the latest
`main`, every applicable `AGENTS.md`, the current Rust owners, and the accepted
d.4.1/d.4.1.1 implementation before writing the contract. Record the exact Git
commit and Jujutsu change identifier when available. If the checkout or a
required current owner cannot be inspected, return a blocked status and no
final ZIP.

This is d.4.1.2.1, immediately after the safe pure geometry/style substrate of
d.4.1.2 and before production runtime integration, d.4.1.3, d.4.3, and public
style-trace work. The request is self-contained. The prior
`arcweft-seq-06.11d.4.1.2-native-physical-box-geometry-final-contract.zip` may
be consulted as rejected evidence, but it is not a prerequisite or source of
truth.

The correction exists because the prior package makes a runtime identity from
only mount plus instruction, although current production permits repeated or
called occurrences of one instruction and identifies a style node by mount,
repeat/call path, and instruction. It also gives contradictory zero-size edge
expectations and leaves several runtime ownership choices implicit. Those
choices must not be guessed during production integration.

## Fixed substrate that must not be redesigned

- Keep one native typed Style pipeline. There is no CSS, Takumi, browser layout
  engine, dual reader, legacy geometry path, or compatibility wrapper.
- Preserve the landed d.4.1 logical-axis model, host seed/provider
  invalidation, canonical physical computed values, and the existing
  `ViewStyleNodeKey` repeat/call path semantics.
- Preserve integer milli-pixels as authoritative geometry, checked arithmetic,
  outward raster rounding, signed margins and scroll ranges, border-box sizing,
  per-axis overflow, inner-to-outer transforms, and direct typed failures.
- Preserve the pure `arcweft-view::geometry` responsibility split for checked
  primitives, box measurement/placement, consumer calculations, and revision
  keys. Correct a demonstrable flaw but do not replace it with a second kernel.
- Preserve `ViewPhysicalBoxStyle`, `ViewPhysicalContainerStyle`,
  `ViewPhysicalFlow`, the exhaustive property geometry-support inventory, and
  physical-geometry invalidation as the canonical Style-owned input boundary.
- Keep represented-but-not-executable properties explicit. Do not silently
  approximate flex distribution, wrap, alignment, rotation, non-rectangular
  clip/mask, or paint-effect bounds.
- Preserve current crate direction. `arcweft-view` remains Sans I/O;
  bundle/product codecs remain data-only; runtime/player owns retained state;
  rendering and platform conversion remain downstream adapters.
- Do not redesign d.4.2 environment conditions, d.4.3 container conditions,
  d.5 trace transport, Character, RichText, exported parts, or proof blocks.

## Required reconciliation decisions

Every item needs one exact answer, owning type/module, public or crate-visible
Rust API, deterministic failure behavior, cache/revision effect, and direct
tests. `TBD`, alternatives, and implementation-selected behavior are not
acceptable.

### 1. Canonical occurrence identity

Select the exact geometry node identity for retained runtime occurrences. It
must preserve mount, the complete repeat/call path, and instruction. Prefer
reusing or losslessly wrapping `ViewStyleNodeKey`; if a separate type is
necessary, define total conversions and explain why there is not one mutable
identity authority. Specify hashing, ordering, trace exposure, codec policy,
mount replacement, repeat reorder/removal, and stale prepared-frame behavior.
Prove two occurrences of the same instruction never share geometry or cache
entries.

### 2. Zero-size border-box and edges

Resolve the prior package's BX-016 contradiction. DESIGN section 7, D-015, and
BX-006/BX-007 require padding plus border to fit the used border box, while
BX-016 says an explicit zero size with nonzero edges produces empty content.
The recommended final rule is uniform: explicit zero with any positive
padding/border on that axis fails with `EdgesExceedUsedBorderBox`; zero with
zero edges is valid and empty. Freeze the exact error fields and all
min/max/intrinsic interactions.

### 3. Transform order wording and ownership

State unambiguously that a transform chain is supplied and evaluated from the
node's innermost transform toward its outer ancestors. Define whether each
uniform scale is centered on the translated local border box, how child
geometry enters a parent transform, when paint outsets are applied, and which
revision changes for translation versus scale versus ancestor transform.

### 4. Empty, bounded, and unbounded clip axes

Freeze the public typed shape for a clip that distinguishes an entirely empty
clip, an unbounded axis, and a bounded half-open span without sentinel
coordinates or `Option<Option<T>>`. Define intersection, edge-touch,
zero-extent, overflow-visible/hidden/clip/auto/scroll behavior, viewport
seeding, serialization policy if any, and exact consumer visibility behavior.
Reconcile that final shape with the safe kernel already present instead of
creating parallel clip state.

### 5. Container projection and element ownership

Define the exact boundary through which `ViewElementKind` reaches
`ComputedViewStyle::physical_container` and then bundle/runtime state. Decide
whether the bundle projection receives the element as an argument, projects a
combined node packet, or uses another single typed owner. Freeze handling for
`display: none`, block, inline, stack, flex, and the default element-owned
Row/Column/Stack flows. Define leaf-with-children, represented-only flex
features, gap shorthands, and mismatched product records as typed errors rather
than silent fallback.

### 6. Runtime tree walk and containing blocks

Specify the exact owner and API for deterministic measure, placement, final
geometry, and child aggregation. Define traversal order; static flow versus
absolute/fixed descendants; containing-block selection; root viewport; reverse
flow; overlay; intrinsic callbacks; child outer revisions; previous-sibling
dependency; scroll state; mount/repeat unmount; and leaf/container validation.
State how one failed node aborts prepared work without partially publishing a
frame.

### 7. Cache and revision transaction

Reconcile the pure measure/place/final revision keys with production cache
owners. Freeze key equality, hash use, generation ownership, dependency
ordering, cache population, failure atomicity, replacement, invalidation, and
eviction. Define exactly which Style invalidation bits reach which cache tier.
Do not use a digest collision as key equality and do not omit repeat/call path
or ordered child identity.

### 8. Bundle and runtime packet shape

Define whether geometry inputs are transient projections or serialized bundle
data. Enumerate every final field and deletion point for duplicate layout,
composite, clip, and scale reads. Specify checked decoding/tamper behavior if a
wire shape changes. Keep logical aliases out of runtime packets and use the
canonical physical scale instead of rereading composite Style.

### 9. Consumer replacement

Inventory and replace every current ad hoc geometry consumer, including
player-scene bounds mutation, render-wgpu paint lowering, hit testing, focus,
avoidance, scroll, capture, and Agent-visible geometry. Current saturating
addition/multiplication, negative-size clamping, and `unwrap_or(MAX)` behavior
must be removed from the authoritative path. Select exact checked conversion
errors and prove all consumers observe one committed `ViewFinalGeometry`.

### 10. Error propagation and prepared-frame atomicity

Define the exact error variants and conversions from `ViewGeometryError`
through runtime driver, player frame planning, native/web/headless adapters,
and observation. Preserve node, axis, field, operation, range/rect, and
consumer context. Specify whether malformed source, unsupported represented
features, arithmetic overflow, and stale generation are compile-, load-, or
frame-time failures. No partial resource mutation or mixed old/new frame may
escape.

### 11. Structural ownership and current evidence

Reinspect all call sites and measure exact bytes/physical LOC for changed Rust
files and the largest related workspace files. Preserve the responsibility
modules already introduced under `arcweft-view/src/geometry/`. Split any
runtime or bundle owner before crossing repository thresholds. Include
dependency fan-in/fan-out and classify production, unit test, integration test,
facade, and generated files. Run the canonical structural audit.

### 12. Corrected acceptance matrix

Produce one internally consistent matrix. Correct BX-016 and any transform-order
wording. Map every normative rule to named positive, negative, overflow,
boundary, cache, repeat/call occurrence, rollback, consumer-parity, and
platform-conversion tests. Distinguish tests that exist in the pure substrate
from tests production integration must add.

## Required implementation order in the corrected handoff

1. Reinspect latest `main`, all applicable instructions, exact owners, callers,
   package evidence, current tests, and structural metrics.
2. Freeze occurrence identity, zero-size semantics, clip shape, container
   projection, and error propagation before changing runtime code.
3. Reconcile the existing pure geometry types and tests in one compiling cut;
   delete superseded provisional shapes directly.
4. Project one canonical physical node packet through bundle/runtime with
   complete element identity and represented-feature rejection.
5. Add the retained tree walker and exact measure/place/final caches using
   path-aware identity and failure-atomic prepared work.
6. Replace player, renderer, hit, focus, avoidance, scroll, capture, and
   observation consumers in reviewable dependency-safe cuts; remove the old
   saturating/clamping authority in the same cuts.
7. Add native/web/headless conversion tests and transaction/replacement tests.
8. Run focused tests, workspace validation, relevant `just` entrypoints, and
   the structural audit. Record actual results without fabricating coverage.

  arithmetic failure, conversion failure, and no partial frame publication;

## Constraints and non-goals

- Do not preserve an unpublished provisional shape with aliases, deprecated
  fields, wrappers, migrations, or dual readers.
- Do not add CSS/Takumi syntax, diagnostics, data, dependencies, or adapters.
- Keep `unsafe` out of the geometry path and use `thiserror` for typed errors.

  concurrency work into the returned contract.
- Use behavior, type, codec, dependency, and transaction evidence. Do not add

## Acceptance criteria

The correction is accepted only when an implementation agent can replace the
remaining production geometry path without choosing an occurrence identity,
interpreting contradictory edge semantics, inventing clip/container packets,
designing cache transactions, or deciding how failures reach consumers. It
must preserve the landed pure checked substrate, cover every current consumer,
and leave no second saturating/clamping geometry authority behind.
