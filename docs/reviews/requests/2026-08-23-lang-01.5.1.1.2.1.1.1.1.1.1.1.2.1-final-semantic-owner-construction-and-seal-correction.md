## Result-changing repository evidence

The returned design must account for all of the following current facts.

1. `FinalSemanticCatalogs` contains the registered semantic world and callable
   limits, but not `CheckedEntryCatalog`. The compiler constructs and validates
   the checked Entry catalog only after final semantic analysis and
   verification. Therefore `CheckedEntryReference` cannot currently retain its
   required `CheckedEntryBindingDigest` during its one-pass construction.
2. project nominal fields have an existing canonical
   `RuntimeProjectNominalProjection`, semantic identity, layout, and schema,
   but environment nominal-record fields are stored in nested `HashMap`s and
   do not retain declaration order or a checked field identity.
3. a View modifier currently accepts an arbitrary unresolved-dot `HirName` on
   `ViewValue`; no accepted modifier catalog exists, and compiler View lowering
   rejects every modifier row.
4. `PostfixBracketResolution` retains the selected candidate `ExprId`.
   `arcweft-compiler/src/lower.rs` projects that lookup into compiler-owned
   runtime-plan lowering, while `arcweft-compiler/src/lower/reachability.rs`
   uses the same selected child for runtime reachability. Removing it from the
   generation-local lookup fact in C2 would change execution. This is not a
   direct runtime-plan semantic consumer of the sema resolution.
5. the current `ViewSpecifiedValue` owner has 26 variants, not 27. Final sema
   currently produces only the `Color` variant through `rgba`, although the
   lower owner must remain exhaustive over its full enum.
6. `CheckedSelectResolution::RecordElement` has no producer. A repository-wide
   typed search also finds no final-sema producer for `TupleElement`, even
   though it has validation, transcript, and compiler readers.
7. current rich-text facts retain typed semantic rows together with raw HIR
   IDs and source locations. A complete rich-text digest requires stable
   checked expression-child digests, which belong to C3 transcript closure.
8. the canonical project runtime nominal projection is currently callable only
   on a sealed `FinalSemanticAnalysis`. C2 owner construction needs nominal
   field/case evidence before that seal, so calling the public post-seal API
   from the construction phase would create a phase cycle.

## Precedence

The design must apply this precedence:

1. current production typed ownership and accepted maintained contracts;
2. the accepted C1 topology/path substrate;
3. this correction for C2 construction and sealing;
4. conflicting sketches in the parent C2 schema; and
5. filenames, source spellings, historical package text, or proposed helper
   names.

No implementation may start until the decisions below are closed in this
order. A later decision must consume the earlier owner rather than introducing
a parallel catalog, digest, lookup table, or reconstruction path.

## Required decisions, in order

### 1. Private two-phase final-analysis and Entry seal

Define one private two-phase construction that can check final semantic facts
and checked Entry bindings without publishing either partial result.

The return must specify:

- the private unsealed inputs and sealed output;
- which phase may inspect callable, nominal, Entry, expression, pattern, and
  project-symbol facts;
- how Entry references acquire the exact `CheckedEntryBindingDigest` and value
  type without rescanning source or accepting caller rows;
- how final analysis, verification, checked Entry selection, compiler project
  assembly, and tooling receive one atomically published generation;
- cancellation, duplicate, poison, missing-owner, work-limit, and validation
  error precedence;
- exact-limit/one-over accounting before allocation or publication; and
- proof that every error publishes neither a final analysis nor an Entry
  catalog and that retries are deterministic.

Do not solve this with a public builder, optional late patch, second final
analysis, mutable post-publication enrichment, or compiler-owned copied fact
table.

### 2. One private runtime nominal projection context

Define a single private `RuntimeNominalProjectionContext`-equivalent owner that
joins the checked project nominal, its declaration, semantic type identity,
canonical `RuntimeNominalTypeId`, `TypeLayoutHash`, runtime schema, field rows,
and variant rows exactly once.

The existing `FinalSemanticAnalysis::project_checked_runtime_nominal` path is
the substrate to converge, not an invitation to add a second projection. The
return must define construction visibility, generation validation, memoization
if any, cycle/limit handling, first-error order, and the narrow projections
consumed by ownership, Match, compiler runtime lowering, Entry checking, and
diagnostics.

### 3. Ordered typed environment record authority or explicit scope removal

Choose exactly one:

- replace the nested environment record maps in place with one accepted,
  declaration-ordered typed field authority carrying field semantic identity,
  ordinal, and type; or
- explicitly remove environment record patterns and environment
  `CheckedFieldSelection` from this parent contract, with executable rejection
  evidence and a separately throwable successor request.

Do not sort a `HashMap`, hash source names, infer declaration order at a reader,
or retain both map and typed-row authorities.

### 4. View modifier authority

Choose exactly one:

- recommended: delete the current unchecked modifier success path and fail
  closed until a real accepted modifier catalog exists; or
- define the real catalog, its owner, registration inputs, callable join,
  semantic identity, limits, compiler behavior, and tests in this contract.

A digest of `HirName`, a list local to final sema, or continued compiler
rejection after semantic success is not acceptable.

### 5. Exact shared types and accessors

Correct the parent sketches to reuse the existing owners:

- use `DeclarationIdentityFamily`; do not add
  `CheckedProjectItemFamily`;
- use `CallableReceiverMode`; do not add `CheckedReceiverMode`;
- put the method-selection callable digest on the existing checked callable
  join owner, with one opaque typed digest rather than a copied byte array or a
  second callable identity;
- define one shared checked field semantic identity consumed by project and
  environment field selection and record-pattern rows; do not create parallel
  field-ID enums per consumer;
- retain one source-ordered variant-case table in `CheckedVariantOwner`; and
- store the selected variant as owner plus checked ordinal, exposing a borrowed
  selected-case accessor. Do not clone an independently constructible selected
  case into `CheckedVariantResolution`.

The return must give exact Rust-shaped fields, constructor visibility,
borrowing/lifetime behavior where relevant, digest domains fixed at version
`1`, and validation invariants.

For every same-cut opaque identity, the return must additionally define one
owner-local constructor and its exact transcript:

- `AcceptedProjectItemSemanticId`: exact accepted project identity,
  `DeclarationIdentityFamily`, value type digest, and the accepted
  `CallableDeclarationDigest` for Flow where applicable; a call-site callable
  join is not an input;
- `AcceptedVariantCaseSemanticId`: exact owner semantic type, checked source
  ordinal, payload-presence tag, payload type digest, and project layout input
  where applicable;
- the one shared project/environment field semantic identity: exact owner
  semantic type, declaration ordinal, field type digest, and project runtime
  field/layout inputs where applicable; and
- `AcceptedCharacterLookSemanticId`: the exact accepted manifest join of
  `CharacterId` and `CharacterLookId` from the current registered Character
  definition authority.

For each constructor, specify the complete BLAKE3 domain byte literal including
its trailing NUL, field order, tags, lengths, constructor visibility, and exact
generation/world/revision validation. Construction is private to the legitimate
checked owner. Public/external raw constructors, source-spelling inputs,
open-name fallback, caller-provided bytes, and post-hoc revalidation are
forbidden. In particular, `CheckedStageLook` must be minted from the accepted
manifest `CharacterId` + `CharacterLookId` join; the current arbitrary
`HirName` success fallback is deleted.

### 6. C2 fact construction versus C3 recursive digests

Keep this boundary exact:

- C2 constructs and validates project item, Entry, variant case, record field,
  typed binding, method/field, StageLook, Effect, Agent/Progress, View element,
  Style, and the chosen View modifier facts.
- C2 may retain the selected Postfix family tag and its selected `ExprId` only
  as private generation-local lookup evidence required by execution.
- C2 does not claim a complete `CheckedRichTextSemanticDigest` or selected
  Postfix child semantic digest.
- C3 computes rich-text and Postfix semantic digests from the stable typed
  child paths and checked expression digests. Raw `ExprId`, tag IDs, spans, and
  source spellings never enter those digests.

For rich text, C3 must derive stable token ordinals and open/close pairing
coordinates from the accepted token order. An accepted close references the
stable ordinal/coordinate of its accepted open, not a
`HirRichTextTagId`. Missing, duplicate, or foreign open/pairing evidence fails
closed before digest publication. `HirRichTextTagId` may remain lookup or
diagnostic evidence only and is never hashed.

State the exact private lookup fields that survive C2 and their deletion or
continued nonsemantic role after C3. Do not move executable child selection
into a digest or publish HIR IDs.

### 7. Subcuts, deletion order, and acceptance tests

Return a compile-clean subcut sequence that follows decisions 1 through 6 and
identifies the first cut where each old field, variant, constructor, reader,
and fallback is deleted. Each subcut must have one final owner, executable
tests, and no compatibility bridge.

## Style correction

Do not encode a literal expected variant count in production or in a source
gate. The current owner has 26 variants. Add one owner-defined exhaustive
semantic encoder on `ViewSpecifiedValue`; Rust exhaustiveness must expose an
added variant at compile time. Tests must prove pairwise tag uniqueness and
semantic sensitivity across every enum variant produced by an exhaustive test
fixture. A debug string, Serde encoding, discriminant cast, wildcard arm, or
sema-owned copied inventory is forbidden.

## Numeric and digest-domain gate

At design time, the return must audit every proposed new BLAKE3 domain as its
exact byte sequence, including the trailing NUL, for byte equality against all
existing Arcweft-owned domains in the repository. Every proposed new domain
must be distinct in that repository-wide audit.

The executable production/test gate is narrower: one C2-owned structured
registry covers C2 semantic and opaque-ID domains and their tags. It validates
domain uniqueness inside that C2 registry, pairwise tag uniqueness within each
domain, and the `0x0405`/`0x0406` reservations. It must not introduce an
unrelated-subsystem central domain registry, search production source, or
assert an enum variant count. Equal numeric tags in distinct, explicitly
domain-separated transcripts are permitted; a repository-global numeric-tag
uniqueness rule is not.

## Postfix and removed Select tag decisions

`PostfixBracketResolution` may retain the selected `ExprId` only as private
lookup evidence. C3 adds the selected checked child digest and excludes both
physical candidate IDs from semantic identity.

Delete `CheckedSelectResolution::RecordElement`, but reserve its existing
semantic constructor tag `0x0406`. The tag must not be reassigned. The return
must also decide whether the currently unproduced `TupleElement` is completed
with a real producer or removed while reserving `0x0405`.
