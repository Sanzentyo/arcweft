# Seq 06.16.6.4 View Resource Naming Taxonomy And CSS Scroll Policy

Date: 2026-07-07

## Implementation status

Implemented in the 2026-07-07 View-owned resource type rename, scroll
containment field rename, View style-rule taxonomy, and retained View program
substrate rename slices. The compact View program/resource/runtime boundary now
uses `View*` names for the View-owned types listed in this request, without
compatibility aliases. View-targeting style rule payloads also use
`ViewStyleRule`, `ViewStyleSelector`, `ViewStyleDeclaration`,
`ViewStyleValue`, `ViewElementKind`, and related `View*` names. The retained
`arcweft-ui` program substrate now uses `ViewProgram`, `ViewInstruction`,
`ViewPartId`, `ViewProgramId`, and related `View*` records for authored View
program data consumed by the Takumi adapter; Takumi scene cache keys now use
`ViewProgramRevision`.

`UiStyleResource`, `UiThemeResource`, `UiTextResource`, `UiInputResource`,
`UiError`, retained semantic fragment names, image/text source tables, and
shared control/text-control runtime style types remain `Ui*` because they are
still product-level UI catalog, shared UI-layer, or shared runtime-control
concepts rather than a single retained View-tree boundary.

Leaf-side scroll containment now uses `containing_scroll_region` on image
objects, text controls, retained View text blocks, action buttons, and
renderer-facing control/image structs. `clip_chain` remains a deferred broader
contract for future nested scroll, clip, mask, and transform composition.

CSS overflow diagnostics are now implemented for the current typed Scroll
contract: `overflow-x` on `Scroll` lowers to horizontal scroll behavior, while
interactive `overflow`, `overflow-x`, or `overflow-y` on non-Scroll View
elements emits `AWF0617 view::interactive_overflow_requires_scroll`.

## Source review

This request records the 2026-07-07 review that restated the final public
language model around `view` declarations and structural `Scroll` elements.
The review's core policy is now repository-visible here so it is not lost in
thread-local notes:

- `component` is not a public Arcweft UI term. Public syntax, diagnostics,
  tests, docs, Agent observe/capture, and layout capture should use
  `view`, `@view`, and `root_view`.
- `Scroll` is a View-tree structural element, not an `Image`, `Text`, `Button`,
  or input-field attribute. Authors write `Scroll { Image(...) Text(...) }`.
- CSS integration targets Arcweft-owned View elements and typed style
  resources, not browser DOM/CSSOM fallback.
- `overflow-x`, `overflow-y`, `max-height`, scrollbar, and scroll-padding
  declarations may configure a `Scroll` element's runtime behavior. They
  should not silently promote arbitrary leaf elements into scroll containers.
- Runtime/rendering may flatten the View tree, so leaf resources may carry
  containment metadata such as `containing_scroll_region` or a future
  `clip_chain`. That metadata means "clipped/offset by an ancestor Scroll",
  not "the leaf owns scrolling".

## Sequence position

This request follows:

- the final `component` to `view` public-surface rename;
- retained scroll region lowering and runtime/render integration;
- retained View images and text blocks inside `Scroll`;
- `2026-07-07-seq-06.16.6.3-legacy-ui-crate-view-rename.md`, which covers
  older `Component*` names in the retained UI/Takumi substrate.

This request covers the remaining naming taxonomy question: whether internal
Rust boundary types named `Ui*` should become `View*` when they represent
View-authored or View-owned resources.

## Required decisions

- Treat `view` as the public authoring and observation term. Do not reintroduce
  `component` as a parser, diagnostic, serde alias, CLI option, or Agent
  protocol compatibility path.
- Rename View-authored and View-owned resource/runtime types from generic
  `Ui*` names to `View*` names unless the type genuinely describes a broader
  UI subsystem. The first implementation slice renamed:
  - `ViewProgramResource`;
  - `ViewLayoutBoundsResource`;
  - `ViewScrollRegionResource`;
  - `ViewTextBlockResource`;
  - `ViewActionButtonResource`;
  - `ViewFocusGroupResource`;
  - `ViewFocusNavigationResource`;
  - matching runtime structs whose fields already use `view` or `root_view`.
- Keep or separately redesign names such as `UiStyleResource`,
  `UiThemeResource`, `UiInputResource`, and `UiTextResource` only if they are
  documented as product-level UI catalogs rather than retained View nodes.
- Decide whether compact sidecar filenames such as `ui.program.json` remain UI
  subsystem files while the Rust type becomes `ViewProgramResource`, or whether
  filenames/JSON section names are also renamed in the same cut. If persisted
  file names are changed, regenerate fixtures instead of adding serde aliases.
- Use the immediate conservative containment field name
  `containing_scroll_region` for the current single ancestor Scroll contract.
  A generalized `clip_chain` remains deferred until nested scroll, clip, mask,
  and transform composition are designed together.
- Define CSS overflow diagnostics:
  - `Scroll { ... }` plus `overflow-y: auto` / `overflow-x: auto` is valid;
  - `Box { ... }` plus `overflow: hidden` may lower to a clip container;
  - `Box`, `Image`, `Text`, `Button`, `TextField`, and other non-Scroll
    elements with interactive `overflow-*: auto|scroll` should emit a
    diagnostic that asks the author to use `Scroll { ... }`.

## Implementation order

1. Audit current `Ui*` resource/runtime structs and group them into:
   View-owned retained resources, product-level UI catalogs, renderer-prepared
   UI scene data, and unrelated UI-layer infrastructure.
2. Rename only the View-owned boundary types in one compiling slice. Do not
   add compatibility aliases, deprecated re-exports, duplicate modules, or
   serde fallback names.
3. Rename fields that still imply a leaf owns scrolling to containment terms.
   This is implemented as `containing_scroll_region`; broader `clip_chain`
   design remains deferred.
4. Add parser/lowering/style-resolution diagnostics for invalid CSS overflow
   usage on non-Scroll interactive scroll containers.
5. Update docs, samples, fixtures, Agent schemas, and tests so public-facing
   text consistently says `view`.
6. Run focused bundle/runtime/player tests and then the normal workspace
   all-features check/clippy cut.

## Constraints

- No compatibility shims, compatibility aliases, deprecated APIs, or parser
  branches for removed `component` authoring forms.
- Do not mechanically rename every `Ui*` occurrence. Keep `Ui*` only when the
  name is documented as a broader UI subsystem concept and not a retained
  View-owned boundary.
- Do not use CSS syntax as an excuse to introduce browser DOM/CSSOM fallback or
  platform-specific hidden DOM behavior.
- Do not update checked-in PNG visual baselines from this request.
