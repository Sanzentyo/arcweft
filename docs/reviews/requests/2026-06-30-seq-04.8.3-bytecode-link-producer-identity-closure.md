# Seq-04.8.3 Request: Bytecode/Link Producer Identity Closure

## Sequence Position

This follows seq04.8.1 and may be designed in parallel with seq04.8.2. It
should consume seq04.8.2 implementation evidence before replacing any producer
that seq04.8.2 leaves conservative.

Seq04.8.1 established actual reusable bytecode/link object shapes. Seq04.8.2
connects the ready full-build path to actual builders. This request closes the
remaining producer identity gaps and keeps conservative continuation explicit
where a producer is still not sound to reuse.

Do not redesign seq04.1 through seq04.8.2 substrate unless current evidence
shows a concrete flaw.

## Request

Inventory every Arcweft producer that creates bytecode, product AWBC, link-plan
facts, bundle bytes, patch input, or cache evidence related to bytecode/link
reuse. Classify each producer as:

- `actual-reusable-ready`
- `actual-reusable-after-identity-work`
- `conservative-required`
- `not-a-bytecode-link-producer`

Then implement the identity work needed to move ready producers from
conservative payloads to actual reusable payloads. Producers that remain
conservative must emit typed, inspectable evidence explaining exactly which
identity or consumer boundary is missing.

Conservative continuation is a soundness boundary, not a compatibility shim.
It must not hide missing implementation work behind broad fallback behavior.

## Producer Families To Audit

At minimum, audit these families:

- ordinary `arcw build`
- `arcw build --watch`
- direct bundle/package creation
- rustc-like single-source `arcw compile`
- patch bundle creation and patch target materialization inputs
- agent script compilation paths
- runtime-driver or player paths that package or consume product bytecode
- fixture regeneration commands that synthesize AWFB/AWBC bytes
- test-only builders used by persistent-cache tests

If a family is not actually a bytecode/link producer, record why it is excluded.

## Required Decisions

1. Which owned type provides the stable identity for each producer family.
2. Which identity fields are producer-specific and which are shared across
   full-build, bundle, patch, and agent-script routes.
3. How conservative reasons are represented in typed data and cache explain
   output.
4. Whether remaining conservative producers should continue to write
   `ConservativeRebuild` payloads or skip writing bytecode/link records until
   their identity is available.
5. Which test-only builders are allowed to construct synthetic actual payloads,
   and how those builders are prevented from leaking into production paths.

## Required Implementation

- Add a repository-visible producer identity matrix under
  `docs/implementation/`.
- Move producer identity behavior onto owning boundary types or named builder
  contexts. Avoid scattered local `foo_to_bar` helpers or stringly producer
  names.
- Replace conservative bytecode/link payloads with actual payloads for
  producers whose identities are complete.
- Add typed conservative evidence for every producer that still cannot reuse.
- Remove or narrow any fixture-only identity shortcuts that can be reached from
  production code.
- Ensure `cache explain` can identify the producer family and conservative
  reason for bytecode/link records.

## Tests To Specify

- Producer inventory test or source-level audit that fails when a new
  bytecode/link producer is added without an identity classification.
- Focused tests for each newly actual-reusable producer.
- Tests that conservative producers report a stable typed reason.
- Tests that production code cannot create `VerifiedReusable` payloads with any
  conservative digest field.
- Cache explain JSON tests covering producer family, reuse policy, and
  conservative reason.

## Acceptance Criteria

- Every bytecode/link producer in the repository is classified.
- Every ready producer uses actual reusable payloads built from real identities.
- Every not-yet-ready producer remains conservative with an explicit typed
  reason and a follow-up path.
- No producer silently falls back to conservative behavior without evidence.
- No production path marks a bytecode/link record `VerifiedReusable` while using
  placeholder, conservative, path-only, or fixture-only identity.
