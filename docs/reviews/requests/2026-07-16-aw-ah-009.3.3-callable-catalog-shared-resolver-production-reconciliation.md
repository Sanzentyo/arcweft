# Design request: AW-AH-009.3.3 callable catalog and shared resolver production reconciliation

- Date: 2026-07-16
- Sequence: AW-AH-009.3.3, after AW-AH-009.3 and parallel-designable with AW-AH-009.3.1/.2
- Kind: independently throwable final production-reconciliation contract
- Production changes: prohibited
- Output language: English

## Goal and dispatch contract

Freeze the complete typed callable catalog, candidate identities, schema
records, and one shared resolver needed to replace current checker-local call
dispatch without changing any currently accepted call or method behavior.

Send this file by itself to exactly one assignee with current Arcweft `main`,
the root `AGENTS.md`, the Rust skill, and the original AW-AH-009.3 final-contract
ZIP. It may be designed in parallel with AW-AH-009.3.1 and AW-AH-009.3.2. It
must not select their syntax-range or accepted-HIR carrier decisions.

Return one decision-complete contract with exact Rust types, fields,
constructors, accessors, visibility, lookup keys, insertion errors, resolver
inputs/products, precedence, and checker/query consumption. Do not leave opaque
IDs, schema shapes, or target-fact behavior for the implementer to invent.

## Basis and unresolved production seam

The re-audit basis is Git commit
`328e362f811896ebf866002c458fe0b970976654`, Jujutsu change `wopypppm`. The
original package is:

```text
arcweft-aw-ah-009.3-character-nominal-signature-help-final-contract.zip
sha256 cdd1d7b764da238a6e4e8f3e774a3384017c8da5ffaea1969f2af279102a7cd5
```

The original contract fixes a high-level `ResolvedCallTarget` and resolver
precedence, but current production requires result-changing details that are
not defined:

1. `SignatureOrigin`, `ResolvedCallable`, and `ResolvedFunctionValue` have no
   specified Rust shape.
2. `BuiltinCallableId`, `EnumVariantSignatureId`, `FxCallableSignatureId`,
   `AgentIntrinsicSignatureId`, and `FunctionValueSignatureId` are described as
   opaque, but their exact owned identity fields, constructors, and accessors
   are not selected.
3. `PresentationCallableId::resolve/signature_schema` and
   `DialogueCallableId::resolve/signature_schema` have no exact function
   signatures or schema/result types, so the checker cannot migrate to them
   without inventing an API.
4. `RegisteredTypeCheckEnv` currently retains one base `TypeCheckEnv`, character
   facts, and external-owner facts. It has no selected project/environment
   callable-record type, ordered overload set, authority rank, duplicate error,
   documentation provenance, or method lookup key.
5. Adapter application currently adds functions/methods to `TypeCheckEnv`; the
   contract does not select which accepted manifest field forms
   `AdapterPackageId` or how package identity, Rust provenance, parameter docs,
   and duplicate authorities survive normalization.
6. Current selected-call checking resolves environment methods, builtin
   collection methods, Arcweft domain methods, presentation-handle methods,
   integer methods, trait methods, data-last callable fallback, and untyped
   capacity methods. The original resolver list mentions project and accepted
   environment methods but does not classify these production families or give
   them typed candidate IDs/schemas.
7. Current call checking also has expected-type-dependent result/enum
   constructors, FX validation, virtual paths, local functions, curried values,
   higher-order effects, and non-callable project shadowing. The target-fact
   checker protocol and the exact facts shared with signature help are not
   specified.

Implementing only the listed high-level precedence would either drop current
checker behavior or leave two successful resolvers. Both violate the original
contract.

## Required decisions

The final contract must decide all of the following.

1. **Complete public model.** Define exact Rust shapes and visibility for every
   type referenced but not defined by AW-AH-009.3, including
   `SignatureOrigin`, all candidate-ID payloads, `ResolvedCallable`,
   `ResolvedFunctionValue`, documentation provenance, and any schema record.
2. **Catalog record and key.** Define one immutable callable record, parameter
   groups/defaults/rest/names/effects/docs/source spans, free-function key,
   receiver/method key, authority rank, ordered candidate-set representation,
   and duplicate/collision error.
3. **Project publication.** Specify how `CallableDeclarationId`, canonical path,
   source signature, docs, source spans, curried groups, and effects are
   collected from `HirProject` during the same registered-world transaction,
   including modules with no callables and non-callable shadowing.
4. **Adapter identity.** Select the exact accepted manifest field(s) that form
   validated `AdapterPackageId`; define standard ownership; preserve typed Rust
   metadata and documentation without parsing display paths.
5. **Every resolver family.** Exhaustively inventory current free-call and
   selected-call branches. For each FX, enum/Result, builtin, Agent,
   presentation, project, environment, inherent/domain/collection,
   presentation-handle, integer, trait, data-last, capacity, dialogue, local
   function, curried function, and function-value family, define candidate ID,
   signature source, applicability, precedence, and checker behavior.
6. **Presentation/dialogue schemas.** Define exact inherent method signatures
   and schema types. Freeze dynamic character-owner acquisition, the
   `show.look` and dialogue `look` expected `CharacterNominalType`, unknown
   owner/part behavior, open-named behavior, and checker diagnostics.
7. **Resolver input and product.** Define the exact borrowed context needed for
   lexical scope, expected type, receiver type, project/world facts, current
   module, source span, call-group index, and cancellation/work accounting.
   `ResolvedCallTarget::Candidates` must be non-empty by construction.
8. **Checker target-fact mode.** Specify how one checker invocation records the
   selected call's target, per-argument inferred types, function-value type,
   current curried group, and poisoned facts without re-resolving names or
   mutating accepted world state.
9. **Argument checking ownership.** Decide which validation remains family
   specific after target resolution and how checker and query share parameter
   mapping, overload viability, return type, and effects without duplicate
   successful resolution.
10. **Ambiguity and collisions.** Freeze standard-vs-adapter ordering,
    same-rank rejection, exact duplicate coalescing, project non-callable
    shadowing, trait ambiguity, data-last fallback shadowing, and defensive
    corrupt-world behavior using typed errors.
11. **Limits.** Map every catalog/resolver loop to the AW-AH-009.3 overload,
    parameter, candidate, nesting, recovery, and work limits. Define failures
    during accepted-world construction separately from query failures.
12. **Public result invariants.** Supply exact constructors/accessors for
    `SemanticSignature`, `SemanticSignatureHelp`, diagnostics, work counters,
    and limits, including how active indices and source identities are checked.

## Required implementation order

Specify compiling cuts in this order:

1. introduce the complete typed IDs, records, schema model, errors, and direct
   invariant tests;
2. publish project and standard/adapter callable catalogs atomically in
   `RegisteredTypeCheckEnv`, rejecting collisions before publication;
3. migrate one current resolver family at a time to the shared target product,
   preserving checker behavior and proving the old branch unreachable before
   deletion;
4. migrate every current selected/method family, not only environment methods;
5. make presentation and dialogue schemas drive structural character nominal
   expected-type checking;
6. add checker target-fact mode and public semantic result construction;
7. connect exact call ranges only after AW-AH-009.3.1 lands and accepted HIR
   only after AW-AH-009.3.2 lands; and
8. run focused sema/registration/adapter tests, workspace check/clippy/test, and
   the canonical structural audit.

## Mandatory direct tests

The contract must define typed tests for:

- every current free-call and selected/method family retaining its checker
  result, errors, effects, and precedence after migration;
- project callable, project non-callable shadow, standard callable,
  adapter-only callable, standard/adapter overloads, duplicate typed ID, and
  same-rank collision;
- project docs, adapter tooling docs, Rust provenance, missing docs, curried
  groups, rest/default/named parameters, and parameter source spans;
- `show` and dialogue look expectations for canonical, compact, qualified, and
  aliased character owners, plus missing/non-character/unknown-part cases;
- exact same local nominal spelling across characters, families, and parts;
- enum/Result expected-type disambiguation, function values, local functions,
  and partial/curried call groups;
- environment, builtin, trait, data-last, and capacity method precedence;
- reversed insertion order producing identical typed candidate order;
- checker and signature target facts containing the same candidate ID; and
- dependency/visibility evidence through public APIs and Cargo metadata, never
  implementation source scans.

## Fixed constraints and non-goals

- Do not redesign `CharacterNominalType`, source identity, accepted publication,
  or the AW-AH-009.3.1/.2 carriers.
- Do not preserve old checker branches as compatibility fallbacks after a
  family migrates, and do not add a signature-only resolver.
- Do not synthesize source `impl` method publication unless this contract
  explicitly proves a current canonical project method catalog.
- Do not parse labels, aliases, Rust display strings, comments, or source text
  into identity.
- Do not add source gates, extension traits, compatibility wrappers, deprecated
  APIs, CSS/Takumi, or removed-syntax diagnostics.
