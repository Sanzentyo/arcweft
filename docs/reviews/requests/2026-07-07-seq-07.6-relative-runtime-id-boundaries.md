# Request: Relative Runtime ID Boundaries

## Context

The function/closure/pipeline stack still uses runtime identifiers such as
`FlowRuntimeId(String)` in places where examples and tests sometimes store
qualified-looking labels such as `flow.main`. This blurs three different
domains:

- relative language IDs authored in source;
- canonical runtime entity IDs used for lookup and entry targets;
- public/debug labels used in AWBC strings, display maps, logs, and diagnostics.

New closure/AWBC tests now avoid adding more `flow.*` assumptions by using
`main`, but the underlying ID boundary remains stringly typed.

## Required Decisions

- Define the typed boundary between source-relative IDs, canonical runtime IDs,
  and public/debug labels.
- Decide where namespace family information such as `flow`, `view`, `asset`,
  or `pure` belongs: in the ID type, in the declaration table, or only in
  display/debug labels.
- Specify how relative references resolve from nested declarations, imported
  modules, request-generated samples, and runtime-plan lowering.
- Specify AWBC string table emission so canonical IDs and debug/public labels
  do not accidentally alias each other.
- Specify diagnostics for ambiguous or malformed relative IDs without adding
  compatibility aliases.

## Implementation Order

1. Audit current `*RuntimeId(String)` newtypes and classify each use as source
   relative ID, canonical runtime ID, or debug/public label.
2. Introduce typed ID wrappers or structured fields only where ownership
   boundaries require them.
3. Update parser/HIR/sema/runtime-plan lowering to carry the chosen ID shape.
4. Update AWBC lowering and entries to emit canonical IDs and labels
   deliberately.
5. Update samples and tests to avoid qualified-looking strings unless the
   qualified form is part of the final ID contract.

## Tests To Specify

- `flow main` and references to `main` lower to one canonical flow target.
- A debug/public label containing a dot does not become a namespace selector.
- Relative references from nested scopes resolve deterministically.
- Ambiguous relative references produce structured diagnostics.
- AWBC entries and source/display maps preserve the canonical ID/label split.

## Constraints

- Do not add compatibility aliases or formatter normalization shims for old
  `flow.*` strings.
- Do not redesign already verified function/closure/pipeline expression
  semantics unless the ID audit finds a concrete dependency.
- Keep lower-level data-format crates Sans I/O and avoid parser/tooling
  branches that silently accept removed syntax.

## Expected Output

- Typed ID boundary design.
- Minimal implementation plan with migration order.
- Updated tests/samples and implementation evidence under `docs/implementation/`.
