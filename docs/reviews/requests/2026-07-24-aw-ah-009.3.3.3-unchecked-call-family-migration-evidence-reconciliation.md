## Why this correction is required

AW-AH-009.3.3 `TEST_MATRIX.md` section 19 requires one representative accepted
and rejected call from every inventory family through the public checker and
signature query. The same accepted package explicitly preserves these current
semantics:

- `Drop::Drop`: every argument is recovery-checked, the result is `Unit`, and
  no typed argument schema rejects the call;
- `Promotion`: the selected promotion/unchecked/assumption paths retain their
  current unchecked argument behavior; and
- `Speaker`: current arguments are intentionally untyped and produce the
  speaker/preset result.

The implemented typed inventory contains all 23 `CallableFamily` values
exactly once. Twenty families have truthful accepted and rejected/poisoned
cases. Drop, Promotion, and Speaker instead have exact-once clean-recovery
cases because their production validators are `variadic_unchecked`; unresolved
recovery arguments remain selected and clean. Manufacturing a rejected case
would require either changing accepted language semantics or asserting a
candidate/result state that production cannot produce.

## Required decisions

1. Define the exact normative meaning of "accepted" and "rejected" in final
   migration evidence. Distinguish at least candidate selection, argument
   diagnostic/poison, clean recovery under an intentionally unchecked schema,
   unknown/non-callable target, unsupported surface, and terminal query error.
2. Select one closed typed case taxonomy for the 23-family table. State which
   case kinds are mandatory for a family with a typed rejecting schema and
   which are mandatory for a family whose accepted schema deliberately cannot
   reject its arguments.
3. Decide the final evidence for Drop, Promotion, and Speaker without adding a
   semantic error solely to satisfy a test row. If a genuine existing negative
   path belongs to one of these families, identify its exact production input,
   candidate identity, diagnostic/result, and why it is a family case rather
   than an unknown target or different family.
4. Correct section 19's quantifier and exact counter assertions. Preserve:

   ```text
   shared_resolver_invocations == number_of_call_expressions
   old_dispatch_calls == 0
   checker.primary_candidate == signature.primary_candidate
   argument_expression_checks == exactly_once_per_committed_or_recovery_argument
   ```

   State how each assertion applies to clean recovery and to a rejected or
   poisoned case.
5. Define completion evidence proving every `CallableFamily::ALL` entry is
   classified exactly once, no family is omitted or duplicated, and an
   intentionally unchecked family cannot silently become typed/rejecting
   without updating its production contract and matrix.
6. Reconcile the corrected row with the package's `SURFACE_INVENTORY.md`,
   `FINAL_CONTRACT.md`, and requirements traceability. State exact normative
