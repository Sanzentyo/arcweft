# Request: Function Stack AWBC Closure and Apply Semantics

## Context

Runtime `Function` and `Apply` now execute in the core VM/pure evaluator.
AWBC also has a first executable closure/apply cut for non-suspending
expression closures: `RuntimeExpr::Function` lowers to synthetic AWBC functions
allocated with `MakeFunction`, and `RuntimeExpr::Apply` lowers to
`ApplyFunction` instead of a `function.apply` intrinsic placeholder.

This request was closed on 2026-07-10 by the same-Fiber dynamic-call and
validated AWBC-function snapshot implementation. Evidence is recorded in
`docs/implementation/function-stack-awbc-resume-function-snapshot-2026-07-10.md`.

## Resolved Decisions

- `ApplyFunction` remains an instruction and transfers control by pushing a
  frame with an exact caller cursor.
- Safe points, dialogue, await, await-many, host calls, and budget yield use the
  ordinary Fiber suspension state while the dynamic callee frame is active.
- Known exact pure calls may still use `PureCall`; once a pure helper is used as
  a value it follows the same AWBC-backed function representation and apply
  semantics as any other callable.
- The unpublished session-save payload directly serializes AWBC-backed function
  values and validates them against the generation-pinned artifact. No legacy
  rejection/version branch is retained.

## Implemented Boundary for This Cut

- AWBC codec version 7 adds `MakeFunction` and `ApplyFunction` instruction
  payloads.
- `MakeFunction` stores parameter names, capture names, capture registers, and
  an AWBC function pointer. Closure body code is represented as a synthetic
  function table entry rather than a nested structured expression.
- Runtime-plan lowering reserves synthetic function slots while lowering the
  enclosing expression, emits `MakeFunction`, and lowers pending closure bodies
  after the enclosing functions are closed. This keeps global AWBC block ranges
  contiguous and prevents closures from being counted as blocks owned by the
  enclosing flow/helper.
- `ApplyFunction` is executed by the AWBC VM for AWBC-backed
  `RuntimeValue::Function` values. Exact application, partial application, and
  chained application use the ordinary Fiber call stack.
- Synthetic functions can contain value-position `if`,
  `if let`, and `match` bodies. These lower to real AWBC branch blocks,
  pattern tests, pattern scopes, jumps, returns, and pattern-mismatch traps
  instead of eager selector intrinsics. This is the product AWBC execution path
  for destructuring closure parameters, because those parameters lower through
  `RuntimeExpr::Match`.
- Expression-level AWBC function apply pushes an ordinary call frame on the
  current Fiber. Await, host call, explicit budget yield, and automatic budget
  preemption preserve and resume that frame.
- Product AWBC session save/load accepts validated AWBC-backed function values,
  including captures and partially applied bindings. Structured-expression
  bodies and stale/malformed AWBC identities are structured validation errors.
- The validator walks fiber frames, root/scope cleanup args, suspension and
  await-many payloads, source/stream queues, terminal values, child fibers, and
  nested tuple/sequence/record/variant/iterator/function values. Function ids,
  binding order, signature/frame shape, and capture types are checked against
  the owning AWBC program before restore.
