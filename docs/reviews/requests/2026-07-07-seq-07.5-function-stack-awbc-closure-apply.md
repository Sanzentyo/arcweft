# Request: Function Stack AWBC Closure and Apply Semantics

## Context

Runtime `Function` and `Apply` now execute in the core VM/pure evaluator.
AWBC also has a first executable closure/apply cut for non-suspending
expression closures: `RuntimeExpr::Function` lowers to synthetic AWBC functions
allocated with `MakeFunction`, and `RuntimeExpr::Apply` lowers to
`ApplyFunction` instead of a `function.apply` intrinsic placeholder.

This request remains open only for the parts that are still larger design work:
suspension-aware dynamic apply/resume semantics and persisted closure snapshot
contracts.

## Required Decisions

- Decide whether expression-level function apply that may suspend should become
  an AWBC terminator, a lowered call block sequence, or a dedicated resume-aware
  dynamic-call form.
- Specify how `ApplyFunction` should compose with safe points, host calls,
  dialogue, await, await-many, and budget yield.
- Specify how pure-helper-backed function values interact with existing pure
  helper tables and accelerator-friendly `PureCall`.
- Specify serialization/versioning for save snapshots that may contain
  function values, or explicitly reject persisted closures with a structured
  diagnostic for this cut.

## Implemented Boundary for This Cut

- AWBC codec version 7 adds `MakeFunction` and `ApplyFunction` instruction
  payloads.
- `MakeFunction` stores parameter names, capture names, capture registers, and
  an AWBC function pointer. Closure body code is represented as a synthetic
  function table entry rather than a nested structured expression.
- Runtime-plan lowering reserves synthetic function slots while lowering the
  enclosing expression, emits `MakeFunction`, and lowers pending closure bodies
  after the enclosing functions are closed. This keeps global AWBC block ranges
  contiguous and prevents closures from being counted as blocks owned by the
  enclosing flow/helper.
- `ApplyFunction` is executed by the AWBC VM for AWBC-backed
  `RuntimeValue::Function` values. Exact application, partial application, and
  chained application are implemented for non-suspending synthetic functions.
- If an expression-level AWBC function apply suspends or budget-yields, the VM
  reports a runtime error rather than pretending the expression instruction has
  a resumable safe point.
- Product AWBC session save/load now takes the explicit-rejection path for
  persisted closures. `RuntimeValue::Function` is rejected as
  `BundleSessionSaveError::UnsupportedRuntimeValue { kind: "function", path }`
  before a Product AWBC snapshot can be exported, directly restored, or
  accepted through encoded save import.
- The validator walks fiber frames, root/scope cleanup args, suspension and
  await-many payloads, source/stream queues, terminal values, child fibers, and
  nested tuple/sequence/record/variant/iterator values. This does not design
  AWBC closure allocation; it prevents accidental snapshot compatibility claims
  until the requested closure representation and versioning work exists.

## Implementation Order

1. Done: add AWBC schema/table design for non-suspending expression function
   values.
2. Done: implement bytecode verification for closure/apply instructions.
3. Done: implement AWBC product VM execution for function apply, partial apply,
   and chained apply for AWBC-backed function values that do not suspend.
4. Done: add focused codec/verifier/VM and runtime-plan lowering execution
   tests.
5. Remaining: design suspension-aware dynamic apply lowering with explicit
   resume points.
6. Remaining: update save/load policy for function values. Done for this cut as explicit
   structured rejection; serializable closure state remains part of the AWBC
   schema/code design work above.

  concrete bug.
- Preserve deterministic capture ordering.
- Keep data-format crates Sans I/O.
