# Request: seq-06.11d.4.1.4 native axis-provider revision motion contract

Date: 2026-07-14

## Sequence position and reason for the split

This request follows the d.4.1 core, provider propagation, and physical geometry
contracts. The core canonicalizes transition targets against one axis snapshot,
but does not change motion behavior when the effective mode or provider
revision changes.

The package states cancel-and-snap intent but leaves the transition identity,
event ordering, equal-mode/new-provider case, simultaneous value change,
reduced-motion interaction, and runtime owner underspecified. Implementing that
behavior now would guess at the public motion contract.

This request is independently throwable. It must consume the implemented
`ComputedViewTransition`, `ComputedViewAxes`, and canonical values rather than
redesign them unless a reproducible defect is proven.

## Fixed substrate

- Transition targets retain authored property, canonical resolved property,
  axis snapshot, duration, and delay.
- Axis-dependent usage is typed; `box-axes` itself is discrete.
- Canonical values switch atomically after axis resolution.
- Existing motion interpolation remains owned by `arcweft-view`.

## Required decisions

1. Exact transition epoch identity, including mode and provider revision.
2. Disposition for mode change, equal-mode provider change, source-only change,
   axis-neutral targets, and physical targets.
3. Ordering for simultaneous axis, target value, transition list, mount, and
   reduced-motion changes.
4. Cancel/snap/restart event payloads, provenance, trace integration, and
   deterministic node/property ordering.
5. Delayed and completed transition behavior, interruption, cache state, and
   lifecycle cleanup.
6. Typed errors and impossible-state handling without player-local branches.

## Implementation order to specify

1. Freeze transition epoch and disposition types on the owning motion types.
2. Define event ordering and simultaneous-change truth tables.
3. Implement axis-neutral continuation and axis-dependent cancel/snap.
4. Integrate provider revisions, reduced motion, traces, and cleanup.
5. Validate every mode pair and backend parity.

## Required tests

- Same-mode value changes for logical and physical targets.
- Every ordered pair of the four modes for size, edge, translation, and overflow
  targets; equal-mode/new-provider barriers.
- Simultaneous axis/value/spec changes, delay, interruption, completion, node
  removal, remount, and reduced-motion toggles.
- Axis-neutral transitions continue; axis-dependent transitions cancel and
  snap exactly once in stable order.
- Cache/tamper/budget tests and native/headless/web event parity.

## Constraints and non-goals

- No player-local property special case, duplicate alias mapping, blended
  `box-axes`, compatibility motion event, or CSS transition model.
- Do not redesign provider propagation, physical layout, or trace transport.
- Scroll anchoring and scroll animation use their own finalized contract.

## Expected output

Produce a standalone final design with exact Rust APIs on owned motion types,
epoch/disposition truth tables, event and trace schemas, algorithms, budgets,
errors, implementation sequence, and exhaustive mode-pair/lifecycle/parity tests.
