# Follow-up request: seq06.4k.1 real text-control schema to `PreparedFrame`

Date: 2026-06-29
Parent request: seq06.4k player text-input/windowed path convergence

## Blocker

`PreparedFrame::focused_text_input_target()` currently has the target return type but no production source of actual text-control state. Current `SemanticNode` exposes `TextField` and `TextArea` roles, but it carries label/bounds/actions only, not editable value, session id, selection, options, or renderer-backed text layout. `TextEditorState` and `TextEditorGeometryPump` can produce snapshots/geometry once the product/runtime schema supplies a real text control, but no normal player path does that today.

## Ownership decision

- Product/runtime View schema owns declarative text-control identity and initial value.
- Runtime/player owns live `TextEditorState` for focused Arcweft text controls.
- Renderer owns layout-to-geometry conversion through `TextEditorGeometryPump`.
- `PreparedFrame` is the single native/web focus-target source and must return only real controls lowered from runtime state.

## Required implementation order

1. Add a typed text-control input model to the frame scene input, with at least:
   - `InteractionTarget`;
   - `TextInputSessionId`;
   - current text value;
   - selection/caret;
   - `TextInputOptions`;
   - semantic role `TextField`, `TextArea`, or secure field equivalent.
2. Add player-owned focused text editor state that applies validated `TextInput` edits and refreshes snapshots.
3. In renderer planning, layout focused text controls and call `TextEditorGeometryPump::layout_from_laid_out_text`.
4. Produce `PreparedTextInputTarget` from the resulting `TextEditorState::snapshots`.
5. Change `PreparedFrame::focused_text_input_target()` to return the real focused target, not a fixture and not a hidden host object.
6. Add tests proving:
   - a real focused text field produces `PreparedTextInputTarget`;
   - secure fields redact value/character geometry;
   - browser client transform and native screen transform use the same `TextInputGeometrySnapshot` source;
   - no sample-owned or hidden textarea path is introduced.

## Acceptance

- `PreparedFrame::focused_text_input_target()` no longer contains the hardcoded `None` implementation.
- Normal native and Web players both call it as their only focus-target source.
- No hidden DOM fallback, sample snapshot path, or platform object identity is used to fabricate a target.
