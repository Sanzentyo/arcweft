# Request: Task, Dialogue, and Stream Callable Effect ABI

## Sequence Position

This request follows
`2026-07-08-seq-07.8-function-stack-closure-effect-row-final-contract.md`.
Ordinary source `fn` values and closures already have open inferred semantic
rows, closed report projection, and final-call-group effect timing. This
request must not redesign that verified substrate unless implementation
evidence demonstrates a concrete defect.

## Why This Split Is Needed

`task fn`, `dialogue fn`, and `stream fn` preserve curried parameter groups in
syntax and HIR, but their value-creation, invocation, suspension, and produced
value semantics are not sufficiently specified to assign effects to call
groups or serialize a stable callable ABI. Guessing those rules in sema would
freeze an accidental runtime contract.

## Current Implementation Boundary

Until this request is resolved, semantic checking deliberately does not assign
ordinary-function open rows or final-call-group effect timing to these three
callable kinds. Their first-class function types retain `Unknown` rows, while
the existing closed effect graph keeps its eager call approximation. That
behavior is a conservative implementation boundary, not the normative ABI to
preserve. Syntax/HIR parameter-group preservation remains implemented.

## Required Decisions

1. For each callable kind, distinguish effects performed when creating the
   value, completing its final parameter group, starting execution, and
   resuming after suspension.
2. Specify `task fn` spawn versus await behavior, including cancellation and
   effects of a returned callable value.
3. Specify dialogue yield/resume and cancellation behavior, including which
   effects belong to line production rather than the caller.
4. Specify stream construction, subscription/open, poll/resume, item yield,
   termination, error, and cancellation effects.
5. Define how curried groups delay execution for each kind and whether partial
   values can cross save/load or suspension boundaries.
6. Define the typed runtime-plan and AWBC callable descriptors needed to
   preserve kind, group stage, row identity, captures, and resume state.
7. Define verifier rules and diagnostics for forbidden, escaping, ambiguous,
   or unrepresentable rows at these boundaries.

## Implementation Order

1. Write the source-to-runtime execution table for all three callable kinds.
2. Define the runtime-plan/AWBC boundary types without sema-internal graph
   details.
3. Extend semantic timing using the existing ordinary-function open-row and
   pending-callback machinery where the table says the body is invoked.
4. Implement lowering, verification, save/load behavior, and LSP presentation.
5. Add end-to-end tests before accepting the ABI as stable.

## Tests To Specify

- Creation, partial application, final-group completion, start, and resume are
  tested separately for each callable kind.
- Task spawn and await effects are distinguishable.
- Dialogue and stream yields do not accidentally charge deferred work to value
  creation.
- Cancellation and errors retain deterministic effect traces.
- Returned callable values keep their own rows and invocation timing.
- Curried higher-order callbacks supplied before suspension compose only when
  their invocation point is reached.
- AWBC round trips preserve callable kind, curry stage, effect-row identity,
  captures, and resume state; tampered descriptors are rejected.

## Constraints

- Do not add compatibility aliases or migrations for the unreleased provisional
  representation.
- Do not collapse these kinds into ordinary `fn` merely to reuse its ABI.
- Keep sema graph internals out of runtime-plan, AWBC, core, and save formats.
- Keep `flow` parameter groups non-curried as already specified.

## Expected Output

- A normative execution/effect timing table.
- Typed runtime-plan and AWBC callable contracts.
- Sema, verifier, runtime, save/load, and LSP implementation guidance.
- Positive, forbidden-row, suspension, cancellation, round-trip, and tamper
  tests.
