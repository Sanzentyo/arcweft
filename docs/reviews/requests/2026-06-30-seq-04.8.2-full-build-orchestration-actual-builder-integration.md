# Seq-04.8.2 Request: Full Build Orchestration Actual Builder Integration

## Sequence Position

This follows seq04.8 conservative bytecode/link gates and seq04.8.1 actual
bytecode/link reusable object support.

Seq04.8.1 added actual `VerifiedReusable` payload builders and read-through
validation for `BytecodeUnitObject` and `LinkPlanObject`. The ordinary full
project build path still needs to connect those builders to real build outputs
instead of continuing to emit conservative bytecode/link payloads from the
`arcw build` orchestration.

Do not redesign seq04.1 through seq04.8.1 persistent object, query, cache
explain, or soft-miss substrate unless current source evidence shows a concrete
flaw. This request is about wiring the ready actual builder path into normal
build orchestration.

## Current Evidence

- `docs/implementation/seq-04-8-1-bytecode-link-actual-reuse-boundary-2026-06-30.md`
  records that actual reusable objects and read-through validation exist.
- `crates/arcweft-compiler/src/persistent.rs` owns
  `actual_bytecode_unit_payload` and `actual_link_plan_payload`.
- The normal `arcw build` write-through path in
  `crates/arcweft-cli/src/app/project_commands.rs` still calls the conservative
  bytecode/link payload builders for project modules.
- `cache explain` can distinguish actual reusable hits from conservative gates,
  but the ordinary build route must prove it can produce and consume those
  actual hits.

## Request

Design and implement the full build orchestration connection from ordinary
project builds to actual bytecode/link builders.

The implemented path must use real runtime-plan, AWBC, codegen, verifier,
target, feature, relocation/import, resource, entrypoint, adapter-requirement,
patch-compatibility, and product-option identities. Do not install placeholder
digests, path-derived identities, or fixture-only shortcuts to force
`VerifiedReusable`.

If a specific producer call site cannot supply one of those identities, keep
that call site conservative and emit typed evidence explaining the missing
identity. Do not claim actual reuse for that call site.

## Required Decisions

1. Which full-build data structure owns the actual bytecode/link build context
   after project compilation but before persistent cache write-through.
2. How the ordinary project build route obtains the canonical runtime-plan-unit
   digest for each bytecode unit.
3. How the route obtains canonical AWBC bytes for each reusable unit, and
   whether current product AWBC is sufficient for the covered project-unit
   shape or a narrower unit AWBC artifact is required.
4. Which owned types provide verifier policy, codegen policy, target profile,
   feature-set, and relocation/import table identity.
5. Which owned type builds the link descriptor from ordered unit identities,
   entrypoints, resource sections, adapter requirements, patch compatibility,
   and product build options.
6. Whether a cache hit can skip rebuilding immediately, or whether this cut
   must first run shadow validation while still rebuilding. If rebuilding
   remains required, the status must stay explicit and must not be reported as
   a source-skipping hit.

## Required Implementation

- Add a typed full-build persistent artifact context instead of passing loose
  digests through local helper functions.
- Replace conservative `BytecodeUnit` payload creation with
  `actual_bytecode_unit_payload` only when the current build has all required
  identities and canonical AWBC bytes.
- Replace conservative `LinkPlan` payload creation with
  `actual_link_plan_payload` only when the current build has a stable ordered
  link descriptor.
- Add prebuild read-through wiring only where the full build can actually
  consume the cached bytecode/link artifact without rebuilding the same stage.
- Keep soft-miss behavior for missing, stale, corrupt, wrong-policy,
  wrong-target, wrong-feature-set, and descriptor-mismatch records.
- Keep compiler/data-format crates Sans I/O. Filesystem cache reads and writes
  remain in project-loader or CLI/build adapters.
- Keep product players and runtime drivers free of compiler persistent-cache
  dependencies.

## Tests To Specify

- Two ordinary `arcw build` invocations against the same project produce
  `VerifiedReusable` bytecode/link records for covered project modules.
- Reused and rebuilt AWFB/AWBC bytes are identical for the covered project.
- Stale or mismatched actual bytecode/link records become typed soft misses and
  rebuild.
- Conservative producers remain `HitThenRebuilt` or rebuilt with explicit
  conservative evidence instead of being promoted.
- `cache explain` reports actual hits separately from conservative gates for
  the ordinary build route.
- Watch mode and non-watch mode agree on output bytes for the covered build
  route, even if watch mode still rebuilds some producers conservatively.

## Acceptance Criteria

- Normal `arcw build` can produce actual reusable bytecode/link payloads from
  real build outputs for the covered producer family.
- A repeated normal build can either consume those actual payloads or emit a
  documented shadow-validation status. It must not silently rebuild while
  reporting source-skipping reuse.
- Product bytes and content roots remain stable between cached and rebuilt
  executions.
- No placeholder conservative digest is used inside a payload marked
  `VerifiedReusable`.
- Remaining conservative call sites are documented as seq04.8.3 input, not
  treated as complete.
