# Request 06.4k: Player Text Input / Windowed Path Convergence Package

## Sequence Position

This follows the already-applied text-input and windowed-runtime substrate:

- seq03.5 windowed runtime owner scene integration.
- seq03.7 windowed live-patch smoke fixtures.
- seq03.8 windowed live-patch ingress adapter and closure audit.
- seq06.3 platform text-input contract integration.
- seq06.4a.3 Web player runtime text-input bridge.
- seq06.4j native player platform text-input bridge.
- seq06.4i renderer-backed text-editor geometry.

This request exists because native and web are now close to the same text-input
contract, but the player-level ownership paths are still not cleanly aligned.
It also covers the old native `windowed.rs` path: removing it is desirable under
Arcweft's no-compat-shim policy, but only after its remaining owned-window and
native-task responsibilities are migrated into the current `scene_windowed`
runtime path.

  but still contains old owned-window/native-task adapter wiring that must not

- `arcweft_player_native::run_bundle_adapter_windowed` is a legacy public export
  candidate and should be treated as suspect unless a current, non-compatibility
  responsibility is proven.

## Problem

Arcweft should have one player-level text-input ownership model:

```text
PreparedFrame focused text target
  -> player text-input bridge core
  -> platform host adapter command sink
  -> platform callback/event source
  -> TextInputDispatchState validation
  -> InputController::text_input / keyboard_with_ime
```

The platform-specific ends differ by necessity: web uses `EditContext`, Windows
uses TSF, macOS uses `NSTextInputClient`, and future platforms use their own
native APIs. But focus lifecycle, snapshot/geometry publication, serial
validation, blur policy, key-disposition policy, secure redaction, trace
evidence, and player routing should not be separately invented by web and
native bridges.

The old native `windowed.rs` path makes this harder to audit. It looks like a
compatibility path because normal native player exports now come from
`scene_windowed.rs`, but deleting it immediately risks losing the owned-window
driver and native task pumping behavior that it still contains. The package must
therefore consolidate the remaining real responsibilities into the current
scene/window owner before removing the old path.

## Request

Produce a zip package that designs and implements the next cleanup cut for
player text-input convergence and native windowed path retirement.

The package must not merely rename APIs or add compatibility aliases. It should
move the implementation toward the final model, delete obsolete paths when their
responsibilities have been migrated, and document any platform validation that
cannot be performed in the package environment.

## Required Decisions

1. Where should the shared player text-input bridge core live?
   Candidate locations include `arcweft-player-scene`, `arcweft-runtime-host`,
   or a narrow module in one player crate with duplicated host-specific shells.
   Choose based on crate boundaries, Sans I/O rules, and whether browser/native
   object identity would leak.
2. Should the shared bridge core own `TextInputDispatchState` directly, with
   web/native only implementing host command sinks and platform event sources?
   If not, justify why web's current adapter-owned dispatch state is the better
   final boundary.
3. What exact player-level trait, owned enum, or context object should model:
   host command application, platform capability reporting, key filtering,
   platform event draining, blur behavior, and trace evidence?
4. How should `PreparedFrame::focused_text_input_target()` become the single
   native/web focus-target source for real text controls?
5. How should renderer-backed geometry and browser/client screen transforms be
   represented without duplicating coordinate logic or leaking DOM/native window
   handles into shared crates?
6. What is the common key-disposition/shortcut suppression rule? Decide whether
   `TextInputDispatchState::shortcuts_allowed` should be the single player-level
   decision point or whether another owned type should expose that policy.
7. What is the common blur/composition policy surface for native and web?
8. Which responsibilities in `windowed.rs` are still real production behavior?
   At minimum audit owned-window/cursor adapter registration, native main-thread
   task pumping, audio command/event handling, and presentation advance behavior.
9. How should those `windowed.rs` responsibilities move into `scene_windowed.rs`,
   `WindowedRuntimeOwner`, or a more appropriate adapter owner?
10. When can `run_bundle_adapter_windowed`, `mod windowed`, and
    `crates/arcweft-player-native/src/windowed.rs` be removed without behavior
    loss?
11. Which source gates should prevent future reintroduction of legacy windowed
    compatibility paths or sample-owned IME paths?

## Required Implementation Scope

Implement the sufficiently designed items end to end. At minimum, the package
must include:

- A shared player text-input bridge core or an explicitly justified equivalent
  that makes native and web follow the same focus, dispatch, blur, shortcut, and
  edit-drain model.
- Native and web host-specific shells that adapt the shared bridge model to:
  - web `EditContext` command/event glue;
  - native Windows TSF / macOS AppKit backend boundary;
  - unavailable/future platform backends.
- A real `PreparedFrame::focused_text_input_target()` implementation path, or a
  precise smaller follow-up request if current View/resource schema still blocks
  it. Do not fabricate focus targets from samples or hidden host objects.
- Migration of any still-required behavior from `windowed.rs` into the current
  `scene_windowed.rs` / `WindowedRuntimeOwner` path.
- Removal of obsolete compatibility exports and modules after migration:
  - remove `run_bundle_adapter_windowed` if no current non-compatibility caller
    remains;
  - remove `mod windowed`;
  - delete `crates/arcweft-player-native/src/windowed.rs`.
- Source gates proving that:
  - normal native runs use `scene_windowed.rs`/`WindowedRuntimeOwner`;
  - the old adapter-windowed path cannot be called through public exports;
  - native/web text input uses the shared player bridge model;
  - sample-owned or hidden text-entry paths are not reintroduced.
- Implementation notes under `docs/implementation/` explaining the migration,
  deleted path, and any validation gap.

If the package discovers that `windowed.rs` cannot yet be removed safely, it
must not leave that as an implicit TODO. It must produce a smaller follow-up
request with the exact blocker, ownership decision, implementation order, and
tests needed to remove it.

## Acceptance Criteria

- Native and web text-input bridges use the same player-level lifecycle model
  for focus, snapshot update, geometry update, blur, platform event dispatch,
  key-disposition, and edit draining.
- Platform-specific object identity remains only in platform/host adapter
  modules. Sans I/O crates must see only Arcweft-owned typed values.
- `PreparedFrame::focused_text_input_target()` no longer blocks real text-input
  acceptance by returning `None` for actual Arcweft text controls, unless the
  package produces an explicit, separately throwable follow-up proving why this
  is still schema-blocked.
- Normal native player runs preserve desktop owned-window/cursor behavior from
  `samples/desktop-owned-window-demo.arcw` and close behavior from
  `samples/desktop-owned-window-close.arcw`.
- `windowed.rs` is removed after its remaining behavior is migrated, or the
  package explicitly proves why removal is not yet safe and provides a concrete
  removal request.
- `run_bundle_adapter_windowed` and any equivalent compatibility export are
  removed unless a current production caller and non-shim responsibility are
  documented.
- Web must not require user-authored glue for normal player text input beyond
  the intended bootstrap surface. JS should own browser object identity and
  event listener plumbing only.
- Native must not require platform-specific sample binaries as final
  acceptance. Diagnostic binaries may remain only if clearly documented as
  diagnostics.
- No hidden textarea/contenteditable fallback, sample snapshot path, DOM mirror
  production model, or platform-specific direct player hook is introduced.
- Existing seq03 live-patch ingress behavior continues to run through
  `WindowedRuntimeOwner`.

## Constraints

- Do not add compatibility aliases, deprecated wrappers, or migration shims.
- Do not preserve the old windowed API only to avoid call-site updates.
- Do not move DOM, COM, AppKit, winit handles, filesystem, network, or platform
  object identity into Sans I/O crates.
- Do not solve the shared text-input path by hard-coding Windows TSF or Web
  EditContext in a common player module.
- Do not fabricate `PreparedTextInputTarget` values from samples or static test
  fixtures.
- Do not silently drop owned-window/cursor/native-task behavior while deleting
  `windowed.rs`.
- Prefer owned enum behavior, typed contexts, and inherent methods on Arcweft
  boundary types over ad hoc helper functions.
- Run structural audit because this package changes player/platform ownership
  and likely removes a public export/module boundary.

## Non-Goals

- Completing every future platform backend.
- Redesigning seq06.3 text-input data types without concrete evidence of a flaw.
- Redesigning seq03 patch compatibility or release trust policy.
- Replacing the renderer or the View compositor.
- Keeping `windowed.rs` alive as a compatibility path.

## Parallelization Guidance

This request should be designed as one contract because native/web text-input
convergence and `windowed.rs` retirement both touch the native player ownership
boundary. After the shared bridge and scene-window owner decisions are frozen,
implementation can split into parallel tracks:

1. Shared player text-input bridge core and parity tests.
2. Web shell adaptation and JS runtime command tests.
3. Native shell adaptation, Windows/macOS backend fit, and trace evidence.
4. `windowed.rs` responsibility migration and deletion/source gates.

Do not let track 4 delete `windowed.rs` before the owned-window/native-task
behavior audit is complete.
