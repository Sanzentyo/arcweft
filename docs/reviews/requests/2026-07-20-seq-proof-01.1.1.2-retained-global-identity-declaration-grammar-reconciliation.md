## Goal and dispatch contract

typed declaration grammar and ownership of these retained Arcweft top-level


   reference rules;
4. its non-overlap with the accepted `res` declaration;
5. recovery, ambiguity, limits, and parser-transaction behavior;
6. the ordered public AST and HIR migration after the private grammar gate; and
7. direct tests and deletion of the current generic/stringly declaration path.

Send this request by itself to exactly one design assignee with access to the
latest Arcweft `main`, current repository `AGENTS.md`, and the applicable Rust
skill. The assignee must inspect current production and record exact Git and

This is a design-only request. Do not implement, patch, format, or modify
production Rust or stable language documentation. Return no implementation

The returned contract must contain no result-changing `TBD`, alternatives

## Sequence position and why this request is separate

Proof-concurrency v6.1.1 Stage 1 builds a private, one-pass, lossless grammar
before Stage 2 assigns syntax database identity and attaches the public typed
AST. Most retained declaration rows already have typed private descendants.
The eight families in this request do not.

They must be designed together because they currently share one provisional
public `EntityDeclItem`, overlapping identity/reference conventions, and common
project-symbol consumers. Designing only one family could accidentally:

- make `asset` a configured `res`;
- give one declaration family a different ID or visibility authority;
- preserve `signature_tail: String` for action, signal, metric, or View;
- create two View declaration/callable owners;
- leave concrete Activity adapter binding in source;
- assign Stage 2 identity to the current generic top-level wrapper; or
- make malformed input fall back to executable top-level statements.

This request is nevertheless narrower than the complete proof-concurrency
v6.1.1 package. It does not redesign syntax database identity, typed attachment,
predicate/proof grammar, HIR arenas, runtime assertion faults, or proof
semantics. It supplies the missing final declaration inventory required before
those accepted later stages can begin.

## Current production evidence to reconcile

Inspect and re-confirm these facts against latest `main`. If production has
changed, cite the exact replacement rather than silently designing against an
old shape.

### Private grammar gap

The crate-private full-source grammar owns typed declaration kinds for module,
use, flow, ordinary function, predicate, proof, nominal types, trait/impl,
`res`, entry, extern capability, test/bench, and Style.

It does not own item kinds or declaration parsers for the eight retained
families in this request. `parser/item.rs` therefore does not classify their
heads as declarations. They fall through to generic `ErrorItem` recovery
instead of receiving a typed declaration descendant.

This is not only a missing enum row. The final body grammar, identity head,
family modifiers, and recovery boundary for each declaration are not yet
settled in the private grammar.

### Provisional public declaration

The current public syntax path groups many unrelated families into:

```rust
pub struct EntityDeclItem {
    attrs: Vec<Attribute>,
    kind: EntityDeclKind,
    visibility: Option<Visibility>,
    id: EntityRef,
    name: Option<String>,
    surface_alias: Option<String>,
    signature_tail: String,
    body: Option<String>,
    structured_body: Option<EntityDeclBody>,
    body_range: Option<TextRange>,
    range: TextRange,
}
```

Only content, image, and View currently have selected structured-body variants.
The other bodies or headers remain stringly. HIR currently clones
`EntityDeclItem`, while sema, project indexing, runtime-plan, CLI, LSP, and
tooling interpret selected strings or family tags downstream.

That shape is deletion inventory, not a compatibility contract. The final
design must not preserve it merely because callers exist.

### Accepted `res` grammar

Lang-01.4 already selected `res` as the sole declaration for configured
runtime resources. Its private grammar owns:

```text
outer docs/attributes
visibility
optional explicit entity reference
local name definition
:
typed nominal resource head
braced typed field initializers
```

It replaces the old configured-resource family keywords for image, voice,
voice profile, se, bgm, audio bus, mixer snapshot, ducking, motion, and rig.
It explicitly does not replace packaged byte assets, actions, or other
unrelated stable global identities.

The eight declarations in this request must not be represented as aliases,
special nominal types, or spelling-dispatched branches of `res`. Shared
expression, type, attribute, documentation, delimiter, or field grammar may be
reused where semantically appropriate, but item identity and body ownership
must remain explicit.

### Later top-level reduction

The final language direction removes or relocates the following source forms:

```text
content
extern mod
dialogue defaults
source
old configured-resource family keywords
regular-project top-level statements
```

Concrete Rust/WASM/process Activity implementation selection belongs to typed
manifest/adapter metadata. The retained `activity` declaration is only the
abstract, stable Activity interface and identity.

Do not restore any removed family as a generic entity row, compatibility
reader, historical grammar kind, or dedicated removed-spelling diagnostic.

## Required decisions

Every subsection must choose one exact grammar/API/owner/recovery rule. Merely
restating the current examples or saying that a family is "typed" is
insufficient.

### 1. Final family inventory and declaration heads

Freeze the exact canonical grammar for all eight declaration heads. Define:

- accepted keyword and multi-word modifier tokens;
- whether visibility precedes the family keyword;
- whether each declaration requires an ordinary local name, an explicit
  entity reference, or both;
- ordering and optionality of name, ID, type/signature, alias, policy, and body;
- one-line, braced, and indented forms, if any;
- delimiter and logical-line termination;
- whether a declaration may be bodyless;
- whether generic parameters, fixed parameters, return types, where clauses,
  or contracts are meaningful for that family; and
- exact rejection of family-inappropriate header components.

Resolve current spelling variants rather than accepting all of them. Examples
in the repository currently mix forms such as:

```arcw
pub character @character.alice Alice as alice { ... }
pub character alice { ... }
pub view MainDialogue(dialogue: DialogueView) { ... }
pub action feedback.submit(value: String)
pub signal @signal.current_flow: Watch<Ref<Flow>>
pub metric gauge @metric.frame_time_ms: f32
pub layer @layer.world.background: World { ... }
pub activity @activity.game MiniGame { ... }
```

The final contract must select one deterministic parse for each family and
explicitly reject superseded alternatives. Do not add a broad "entity"
declaration or another generic public keyword to avoid making these decisions.

### 2. Shared identity, name, visibility, and reference contract

Define one coherent identity contract across the eight families:

- the exact declaration-name type and source node;
- when a `PublicId`/entity ID is explicit and when it is derived;
- permitted absolute, module-relative, family-relative, or local reference
  forms;
- family validation of an explicit ID;
- canonical fully qualified identity derivation;
- equality, hashing, import, re-export, rename, and alias behavior;
- namespace/collision policy against ordinary callables, `res`, other entity
  families, and same-family declarations;
- visibility forms and their module/package meaning;
- whether private declarations receive stable semantic IDs;
- the distinction among semantic identity, authored display name, Character
  surface alias, and tooling symbol name;
- exact source ranges for every identity/name/alias component;
- unknown, wrong-family, relative, malformed, and duplicate reference
  diagnostics; and
- how later Stage 2 attachment binds the declaration and each reference to its
  exact lossless node without range or source-text searching.

Consume the existing owned ID/reference types when they fit. If a missing
behavior belongs on an Arcweft-owned ID enum or newtype and dependency
direction permits it, specify an inherent owned API rather than a free
`foo_to_bar` helper, local extension trait, or string wrapper.

Do not create a second project-symbol, Character-registration, View-catalog,
source-name, module-path, or public-ID authority.

### 3. Documentation, attributes, and declaration metadata

Freeze:

- outer documentation and outer attribute attachment;
- visibility-node ownership;
- attribute order and duplicate handling;
- valid attribute targets by family;
- whether inner attributes exist in any family body;
- exact ranges for docs, attributes, declaration, header, and body;
- how blank lines and comments affect attachment;
- recovery when an attribute is malformed or separated from its declaration;
  and
- how public AST/HIR exposes typed attributes without copying their source as
  strings.

Reuse the accepted common attribute/documentation grammar. Do not invent a
family-specific attribute parser or silently reinterpret an unknown attribute
as a raw field.

### 4. Packaged `asset` declaration

Define the final typed `asset` header and body separately from configured
`res`. Decide:

- whether asset identity is path-derived, source-declared, manifest-derived, or
  an exact combination;
- which authored metadata, if any, belongs in source rather than the build
  manifest;
- typed body fields and their value types;
- virtual path/content-hash/media-type/build-dependency ownership;
- bodyless declaration behavior;
- references from `res` and other declarations;
- package inclusion and duplicate-path diagnostics; and
- whether source `asset` remains necessary when an asset is discovered only
  through the asset root.

The result must not use `asset` to mean a configured image/audio/motion object,
and must not use `res` to mean packaged bytes. If current build/profile
contracts make an authored asset declaration unnecessary, the contract must
choose direct removal and update this Stage 1 inventory rather than retaining
an empty identity shell.

### 5. `character` declaration body

Define the exact typed Character declaration body and header while preserving
the accepted Character nominal/runtime contracts. Decide:

- authored identity, ordinary/surface alias, and display-label ownership;
- typed fields, values, references, defaults, and duplicate-field behavior;
- how presentation, voice, style, dialogue defaults, or other Character
  metadata refer to typed `res`, View, or manifest-owned values;
- which fields are source-owned versus registry/manifest-owned;
- whether field order is semantically relevant;
- extension/override policy, if any;
- the boundary with `CharacterDialogue` construction and ordinary call
  syntax; and
- exact malformed field and wrong-reference recovery.

Do not restore `.say`, speaker-line syntax, source `dialogue defaults`, raw
field bags, Character-specific call syntax, or a second Character registry.

### 6. `view` declaration signature and body ownership

Define the final private grammar node for the already retained authored View
surface. It must cover:

- ordinary name and stable View identity;
- fixed parameter group, typed parameters/patterns, defaults if allowed, and

- generics, where clauses, visibility, attributes, and contracts if allowed;
- the existing typed View body, tree/instruction children, exported parts,
  Style patches, dialogue parameter roles, and exact ranges;
- View callable projection and the one accepted callable owner;
- recovery for malformed signatures, body entries, exported parts, and
  missing delimiters; and
- the relationship among public semantic `ViewId(PublicId)`, dense

  conflating those identities.

Do not recreate `CallableItem::View` as a second source declaration, copy the
View body into a generic function body, or redesign accepted exported-part,
Style, mount, catalog, or dialogue-View contracts without cited failure.

### 7. `action` declaration signature

Replace the current string signature tail with an exact typed declaration
contract. Define:

- name/ID ownership;
- fixed parameters, patterns, types, default values, generics, and return type

- whether actions are bodyless typed channels or own a body;
- effect/capability metadata, if any;
- ordinary callable/catalog relationship;
- event emission/receive payload identity;
- duplicate/overload rules; and
- malformed parameter/signature recovery.

Reuse ordinary parameter/type grammar and the unified callable/project symbol
catalog where appropriate. Do not introduce a second action-only signature

### 8. Abstract `activity` declaration

Define only the retained abstract Activity identity/interface. Freeze:

- header, name/ID, visibility, attributes, and interface type information;
- typed input/output/mode/contract/lifecycle members;
- member order, duplication, defaults, and extensibility;
- references from layer, entry, flow, runtime, and manifest;
- source-owned interface identity versus manifest-owned implementation origin;
- diagnostics for a missing or incompatible external implementation binding;
  and
- recovery for malformed interface members.

Concrete `from rust`, `from wasm`, process paths, crate names, adapter names,
or implementation selection must not return to authored source. The final
grammar must make that separation structurally impossible rather than relying
on later string validation.

### 9. `signal` and `metric` declaration contracts

Define separate typed nodes even if they share lower-level type children.
Decide:

- signal payload/observable type syntax and initializer policy;
- signal lifetime, mutability/write, observation, replay, or persistence

- metric kind vocabulary such as counter/gauge, whether it is a closed enum,

- metric value type, units, labels/tags, aggregation metadata, and defaults;
- semantic IDs used by statements, Agent observation, test, trace, and runtime;
- visibility/import/reference rules;
- duplicate and wrong-family behavior; and
- malformed type/modifier/body recovery.

Do not parse signal or metric type/signature tails downstream as strings. Do
not let the statement heads `signal ...` or metric API calls steal a
declaration, and do not preserve arbitrary metric-kind words as unchecked
text.

### 10. `layer` declaration contract

Define the final typed Layer declaration and its stable render/input/Agent

- header ID/name, optional nominal layer kind, phase, z/order, and policy

- which properties belong in the header versus a typed body;
- typed child/reference/body members;
- render, hit-test, input propagation, accessibility, capture, View, Activity,

- defaulting and deterministic ordering;
- duplicate/conflicting policy behavior; and
- malformed header/member/recovery ranges.

Reuse accepted native View/Style/environment and Layer runtime owners. Do not

### 11. Lossless private grammar node and event inventory

Provide the exact crate-private `SyntaxKind` additions and parser event/tree

- one item node per retained family;
- typed header component nodes;
- family-specific body/member nodes;

- malformed outer attributes/docs;
- wrong-family references;
- an obsolete removed declaration followed by a retained declaration; and

Specify exact reuse or narrow extension of current:

- item/member/parameter/type/expression/pattern/diagnostic budgets;
- event and depth budgets;
- checked range arithmetic;
- exact-limit success and one-over failure;

## Mandatory direct test matrix

The returned contract must name exact test owners/APIs, inputs, typed outputs,
diagnostics, ranges, and rollback evidence.

### Success and losslessness

- One canonical declaration for each of the eight families produces its exact
  typed private item and body descendants.
- One document containing all eight families plus `res`, ordinary function,
  proof, and Style preserves declaration order and never classifies a retained
  family as top-level flow.
- Docs, comments, attributes, visibility, explicit/derived identity, aliases,
  types, parameters, body members, delimiters, and trailing trivia remain
  lossless.
- LF, CRLF, Unicode names/content where permitted, blank lines, and comments
  have exact ranges.
- Shared expression/type/pattern/parameter nodes use the common grammar rather
  than family-local raw text.
- Asset and `res` declarations have distinct typed item kinds and reference
  domains.
- View retains its dedicated body/exported-part/Style descendants and one
  callable owner.
- Abstract Activity contains no concrete implementation-origin child.

### Malformed and recovery cases

- Missing or malformed name, identity, alias, type, parameter, modifier,
  assignment, body opener/member/close, and trailing delimiter produce the
  selected typed recovery nodes and exact ranges.
- A malformed declaration preserves the following declaration as a sibling.
- An unclosed body does not absorb a following declaration at the same
  declaration boundary.
- Malformed docs/attributes do not attach to the wrong declaration.
- Wrong-family absolute/relative references remain typed and receive the
  selected diagnostic owner.
- Recovered declarations are inspectable by tooling but cannot become
  executable HIR/project symbols when the final contract marks them poisoned.
- Fatal budget or identity/event exhaustion commits no partial event tree,
  diagnostic state, generation, or later attached node.

### Ambiguity and classification

- `signal` statement versus signal declaration is decided without downstream
  string reparsing.
- Action/View/Activity expressions do not become declarations merely because
  the leading identifier matches a family spelling.
- Multi-word metric modifiers have one deterministic tokenization and unknown
  modifiers are not silently accepted.
- `asset` never parses as `res`, and old configured resource family heads
  never parse as retained identity declarations.
- Removed `content`, concrete Activity-origin, `source`, `extern mod`,
  `dialogue defaults`, and regular-project top-level statements receive
  ordinary current-grammar recovery and never produce a retained executable
  node.
- A following valid retained declaration remains available after each removed
  or malformed item.

### Public AST, HIR, and project migration

- Attached public declaration handles round-trip to their exact Rowan node and
  source range without source/range search.
- Every declaration and typed child lowers to the selected HIR ID/kind without
  cloning syntax values or parsing display/source strings.
- Public ID, module-relative references, visibility, re-exports, aliases, and
  cross-family collisions use the one project symbol authority.
- Character registration, View callable registration, action payload
  signatures, signal/metric types, Layer policies, Activity interface, asset
  payload, and `res` references retain their accepted observable behavior.
- Compile-fail or direct API tests prove the generic `EntityDeclItem`/raw body/
  signature path and public source-less constructors are absent.
- No test opens checked-in source or documentation and searches for symbols,
  spellings, snippets, or file placement.

### Limits and structure

- Exact-limit inputs succeed and one-over inputs fail deterministically for
  every applicable shared and family-specific bound.
- The next valid parse after a fatal transaction receives the same state/IDs
  it would have received without the failure.
- Structural evidence records current bytes, physical LOC, embedded test LOC,
  responsibilities, and relevant dependency fan-in/fan-out before and after
  implementation.
