# Lang-01.4.1 — Resource-reference and retained-identity schema contract correction

## Sequence position

This is a result-changing correction branch from Lang-01.4. It follows the
accepted `res` surface and private shadow grammar, and it must be decided before
the built-in descriptor set, resource-body type checker, or extension
`ResourceValueType` wire shape is frozen. Generic resource identity and
registry work that does not encode the affected fields may proceed in
parallel.

## Why this correction is required

Lang-01.4 defines `ResourceRef<T>` as a reference to an accepted `res`
declaration with exact `ResourceTypeId`. It separately keeps `asset` and its
`AssetRef<P>` distinct. The same final package nevertheless assigns
`ResourceRef<T>` to fields whose targets are not configured resources:

- `Image.target`, `Image.layer`, `Image.view`,
  `Image.containing_scroll_region`, and `Image.actions`;
- `VoiceProfile.character` and `Voice.character`;
- `RigParameterSource.Signal.signal`; and
- `RigHitArea.action`.

Character, View, Action, Layer, and Signal are retained global-identity
declarations, not Lang-01.4 `res` families. Presentation targets and scroll
regions likewise have existing typed presentation/View ownership and are not
made resource declarations by Lang-01.4. The current
`ResourceValueType` inventory contains `AssetRef` and `ResourceRef` but no
typed category for these retained identities.

Encoding the listed fields as `ResourceRef<T>` would therefore create one of
two invalid outcomes:

1. the semantic checker would accept only a `res` declaration where the
   runtime owner requires a retained entity identity; or
2. `ResourceRef<T>` would silently become a generic entity reference, contrary
   to its definition, save contract, bundle directory, and exact
   `ResourceTypeId` checks.

This is a type-model contradiction, not a naming preference. It cannot be
repaired with a local alias, string family check, or family-specific parser
branch.

## Required decisions

1. Define the exact semantic reference category for every affected field.
   Compare and select between:
   - existing owner-specific IDs/reference types such as Character, View,
     Action, Layer, and Signal identities;
   - one generic but typed retained-entity reference carrying an exact closed
     entity-family/type identity; or
   - another existing accepted-project reference product that preserves the
     same identity and visibility guarantees.
2. Keep `ResourceRef<T>` restricted to an exact accepted `res` declaration and
   `AssetRef<P>` restricted to packaged payloads.
3. Extend the closed `ResourceValueType` and extension-manifest value-type
   schema with the selected retained-identity representation. Specify its
   canonical typed constant value and deterministic digest/wire form.
4. Specify source resolution, visibility, import/reexport behavior,
   cross-family diagnostics, dependency edges, and source ranges for retained
   identity references inside a resource body.
5. Correct each built-in Image, VoiceProfile, Voice, and Rig field schema,
   including whether optional/list/map wrappers remain unchanged.
6. Specify bundle-lowering input without adding retained entities to
   `BundleResourceDirectory` or `SavedResourceRef`. A resource definition may
   depend on a retained entity, but that target does not thereby become a
   resource-directory entry.
7. Coordinate `VoiceProfile`/`Voice` character and provider decisions with
   AW-AH-009.4.1.2. Do not duplicate or pre-empt the TTS provider/speaker
   identity and adapter contract.
8. State whether `PresentationTarget` and `ScrollRegion` are declaration
   identities, scoped presentation identities, or another existing typed
   owner at the current production revision. Do not invent a resource
   declaration solely to make the old field spelling type-check.

## Exact fields that must be reconciled

| Resource field | Lang-01.4 package type | Required target category |
| --- | --- | --- |
| `Image.target` | `Option<ResourceRef<PresentationTarget>>` | existing typed presentation-target owner |
| `Image.layer` | `Option<ResourceRef<Layer>>` | retained Layer identity |
| `Image.view` | `Option<ResourceRef<View>>` | retained View identity |
| `Image.containing_scroll_region` | `Option<ResourceRef<ScrollRegion>>` | existing typed scroll-region owner |
| `Image.actions` | `Vec<ResourceRef<Action>>` | retained Action identity |
| `VoiceProfile.character` | `Option<ResourceRef<Character>>` | retained Character identity |
| `Voice.character` | `Option<ResourceRef<Character>>` | retained Character identity |
| `RigParameterSource.Signal.signal` | `ResourceRef<Signal>` | retained Signal identity |
| `RigHitArea.action` | `Option<ResourceRef<Action>>` | retained Action identity |

The correction must also audit nested descriptor records for the same category
mistake before declaring the list closed.

## Implementation order to specify

1. Reconcile the current production owners and select the reference taxonomy.
2. Correct `ResourceValueType`, typed constant values, manifest records, and
   deterministic validation/digest rules.
3. Correct built-in descriptors and resource-body expected-type checking.
4. Add accepted-project resolution and visibility/dependency edges.
5. Connect existing family lowerers using their typed owner IDs.
6. Add bundle/Agent/save/hot-reload tests proving that only actual resources
   enter resource-specific directories and references.

## Tests to specify

- `ResourceRef<Image>` accepts an Image `res` and rejects an asset, View,
  Character, and Action.
- `AssetRef<ImagePayload>` accepts only a compatible asset.
- every corrected Image/Voice/Rig field accepts its exact retained identity
  and rejects both a resource of the same public-ID family and a different
  retained family;
- imports, aliases, and reexports preserve the original retained identity and
  visibility;
- a resource semantic hash changes when a referenced retained `EntityId`
  changes and does not depend on an alias spelling;
- extension manifest decoding accepts the selected typed retained-reference
  shape and rejects raw type labels or unknown families;
- resource-directory and `SavedResourceRef` round trips contain only actual
  resources, while family payloads retain typed dependencies on other entity
  owners; and
- Character/TTS tests use the final AW-AH-009.4.1.2 speaker/provider contract.

## Constraints

- Do not widen `ResourceRef<T>` into a generic entity reference.
- Do not move Character, View, Action, Layer, Signal, PresentationTarget, or
  ScrollRegion under `res`.
- Do not introduce a stringly family field, raw type label, keyword-specific
  branch, compatibility alias, dual reader, source gate, or dedicated removed
  syntax diagnostic.
- Do not redesign the implemented `res` grammar, resource identity triple, or
  verified image/audio/View runtime owners unless current production evidence
  demonstrates a concrete flaw.
- Keep CSS and Takumi routes deleted.

## Expected output

Return one independently implementable final contract correction containing:

- the selected reference taxonomy and rejected alternatives;
- exact Rust and neutral manifest data shapes;
- corrected built-in field schemas;
- deterministic validation, digest, bundle, Agent, save, and hot-reload rules;
- diagnostic codes and exact primary/related source ownership;
- implementation order and a complete behavior-test matrix; and
- explicit coordination boundaries with AW-AH-009.4.1.2.
