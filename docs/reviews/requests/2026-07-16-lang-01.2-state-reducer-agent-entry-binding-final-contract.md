# Request: State, reducer, and Agent entry binding final contract

## Sequence position

This is Lang-01.2, split from the 2026-07-16 top-level declaration reduction.
It is independent of Lang-01.1: it may refer to an ordinary callable role but
must not choose task/stream suspension syntax on Lang-01.1's behalf.

## Why this split is needed

Root-state transition and Agent-controller roles are real runtime boundaries,
but their current author syntax duplicates ordinary type/function machinery.
`state` duplicates a typed struct plus defaults; `reducer` uses a separate
string signature tail and does not have a completed root runtime binding;
Agent controllers duplicate much of `FunctionItem` while receiving dedicated
compilation treatment. Removing their keywords requires one typed place that
selects roles for each launch entry.

## Required decisions

1. Define root state as an ordinary nominal type plus an ordinary initializer
   function or const value.
2. Define a reducer as an ordinary typed function, including the canonical
   parameter and return contracts and whether failure is permitted.
3. Define the only authority that binds state type, initializer, event type,
   reducer, and initial flow: typed `entry` source, project manifest, or a
   precisely justified split.
4. Specify multiple game/editor/test entries and prevent ambiguous implicit
   reducer selection.
5. Define state commit, command ordering, rollback/error, save/replay identity,
   hot reload, and verifier rules.
6. Decide how Agent controllers use the ordinary function substrate and where
   Agent entry discovery/binding lives.
7. Specify whether `#[agent]` or another typed marker is necessary, or whether
   manifest/entry binding alone supplies the role.
8. Define how project index, signature help, rename, and source navigation
   expose bound functions without separate callable families.
9. Give a direct migration from `StateItem`, `CallableItem::Reducer`, and
   `AgentItem`; do not retain a second reader or alias.

## Implementation order to specify

1. Typed entry/manifest binding model and deterministic identity.
2. Binding-time type/effect validation over ordinary structs/functions.
3. RuntimePlan, save/replay, and hot-reload contract.
4. Agent compiler/runtime integration on the shared function model.
5. Source migration and deletion of the old syntax/HIR families.
6. Tooling and documentation migration.

## Tests to specify

- Multiple entries bind independent typed state/event/reducer sets.
- Wrong parameter, return, initializer, effect, or state identity is rejected.
- Reducer state commit and command order are deterministic across replay.
- Failure cannot partially commit state or commands.
- Save/load and hot reload validate the selected identities and schemas.
- Agent entry discovery and execution survive ordinary-function unification.
- Rename/signature-help/navigation resolve the original function declaration.
- Old `state`, `reducer`, and `agent` declarations leave no AST/HIR kind and are
  rejected by ordinary grammar recovery.

## Constraints

- Root-state mutation must have one authority; do not let flow, handlers, and
  reducer mutate the same durable state independently.
- No compatibility syntax, aliases, dual registration, or source gates.
- Do not make core or data-format crates depend on project I/O.
- Do not redesign ordinary nominal types or callable symbol identity without a
  demonstrated defect.

## Expected output

- Final source and manifest grammar/examples.
- Typed binding, runtime, save/replay, and hot-reload contracts.
- Exact AST/HIR/sema/compiler/tooling replacement plan.
- Positive, negative, replay, and migration-deletion tests.
