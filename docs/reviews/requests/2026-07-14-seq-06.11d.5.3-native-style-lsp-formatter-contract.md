# Request: seq-06.11d.5.3 native Style LSP and formatter contract

Date: 2026-07-14

## Sequence position and independence

This source-tooling cut follows seq-06.11d.5.1. Source-only features need no
live runtime; runtime winner explanation must map to 5.1's portable trace DTO,
not invent an LSP-specific cascade trace.

This is self-contained and independently throwable. Produce a completely new
standalone design, not an update to older tooling/Style/CSS requests. No other
request is required; map any final 5.1 name changes explicitly.

## Goal

Define canonical formatting and LSP behavior for all native Style source forms,
with exact typed APIs, wire shapes, maps/revisions, budgets, caches, redaction,
and diagnostics—never textual inference of language rules.

Formatting must preserve semantics, especially authored order that participates
in the cascade. LSP semantic features must use syntax/HIR/sema metadata and the
checked native Style catalog. Runtime explainability, when a session is
available, must consume the 5.1 trace rather than reimplement resolution.

## Fixed native-only substrate

The following is implemented and not open for redesign:

- `.arcw` has one native typed Style syntax. It lowers through explicit syntax
  nodes and ranges, native HIR, and `CheckedViewStyleCatalog`.
- `ViewStyleProgram` owns typed sheets/tokens/rules/patches; static View
  producers retain authored-order `ViewStyleApplicationTarget` values.
- `arcweft-view::style` owns typed metadata, inheritance, invalidation,
  resolution, computed results, and trace metadata.
- Rule, declaration, application, and inline-patch order can change winners.
  A formatter must never sort or deduplicate those inventories merely for
  visual consistency.
- Compiler lowering retains Style source identities and half-open byte ranges;
  bundle source maps may be merged and rebased through typed references.
- Removed `.Css`, `.Arcweft`, `.style(.Css)`, raw CSS bodies, and colon-style
  declarations use ordinary structured `syntax.parse` recovery. There is no
  dedicated removal diagnostic or accepted legacy branch.
- `arcweft-lsp` owns protocol projection and existing language features; it
  must not become a parser, formatter core, or resolver.
- No released native Style formatter contract requires compatibility. Move
  directly to one final model.
- The 5.1 dependency is a transport-neutral typed trace with deterministic
  evidence, source identity, budgets, redaction, cache status, and errors.

Do not redesign parser grammar, checked Style ownership, cascade semantics,
runtime application materialization, or the resolver unless a reproducible
defect blocks the tooling contract.

## Required source corpus

The design package must begin with complete `.arcw` examples and expected
canonical output for:

- a named Style with tokens, ordered rules/selectors/states/environment, and
  append/replace assignment;
- View/root/node applications and an inline typed patch;
- all value families currently accepted by native Style metadata;
- comments and blank lines at every Style syntax boundary;
- LF and CRLF input, non-ASCII identifiers/content, tabs, trailing whitespace,
  final-newline absence, and range formatting;
- incomplete and malformed syntax at every recoverable boundary.

State which trivia is preserved, normalized, attached, or left untouched during
recovery. Examples are normative and must agree with the syntax-tree API.

## Required formatter decisions

Provide exact transport-neutral Rust types and ownership for formatter input,
options, output edits, diagnostics, and errors. Decide:

1. Formatter ownership and allowed syntax/metadata dependencies.
2. Whole/range formatting and safe syntax-boundary expansion.
3. Indentation, braces, spaces around assignment/operators, selector wrapping,
   value/list wrapping, blank lines, comments, line endings, and final newline.
4. Canonical spelling for typed properties, states, elements, values, units,
   colors, tokens, and append/replace assignment without string normalization
   outside the owning metadata types.
5. Safe format/preserve/decline behavior for recovered nodes.
6. UTF-8 edit ranges and LSP UTF-16 projection.
7. Semantic preservation of source order and byte-idempotence.

If a CLI formatter is proposed, it and LSP formatting must call the same core
and return equivalent text. Do not define a second pretty-printer in the LSP.

## Required LSP feature matrix

For each native Style syntax family, decide exact behavior for:

- document and range formatting;
- syntax and semantic diagnostics;
- completion for typed elements/parts/states/properties/operations/tokens,
  values, units, functions, and environment predicates;
- hover for property/value type, inheritance, invalidation, token ownership,
  selector specificity, and checked identity;
- definition/references for sheets, applications, tokens, exported parts when
  available, and source-backed winner provenance;
- rename eligibility and collision checks for sheets and tokens;
- semantic tokens, symbols, folding/selection ranges, and typed inlay hints;
- code actions for fixable native diagnostics without offering removed syntax;
- an optional runtime Style-explain request mapped exactly to the 5.1 query and
  result, including stale-document/session handling.

State explicitly which features are initially unsupported. A missing feature
must not be simulated by raw-source search or broad textual replacement.

## Required typed APIs and dependency direction

Provide exact Rust definitions for:

- formatter options/input/edit/decline/budget/diagnostic types;
- a checked document index keyed by all typed Style/source identities;
- typed completion/hover/navigation/rename query results before LSP conversion;
- document and semantic revision keys used by incremental caches;
- runtime explain request/result adaptation to 5.1, when included;
- errors for invalid ranges, stale/unavailable semantics, budget, source-map,
  and redaction failures.

Keep parsing in `arcweft-lang-syntax`, semantic checking in sema, portable
tooling models in an appropriate lower tooling crate, and protocol adaptation
in `arcweft-lsp`. Do not add local extension traits or widely reused
`foo_to_bar` helpers around incomplete owned APIs.

## Required LSP wire schema

Specify exact standard LSP capabilities and mappings for edits, diagnostics,
completion, hover, locations, tokens, rename, and symbols, including UTF-8 to
UTF-16 rules, versions, cancellation, and partial results.

If runtime explanation needs a custom method, define exactly one, with complete
request/response/error/progress/cancellation JSON. Losslessly envelope 5.1;
never rename events or flatten typed values. Include all outcome examples.

The contract is unreleased. Unknown fields/method versions and malformed enum
tags must follow one explicit policy. Do not define legacy method aliases,
deprecated fields, dual readers, or provisional version negotiation.

## Diagnostics and code actions

Define stable codes, severity, labels, and fix applicability for invalid or
duplicate Style identity, selector/property/value/assignment/declaration,
application/export target, and budgeted/unavailable semantics.

Parser recovery diagnostics remain `syntax.parse`. Removed CSS-like syntax gets
no dedicated code, migration action, compatibility parser, or CSS-to-native
conversion action. A code action may only emit syntax represented by the
canonical native AST/HIR/sema contract.

Specify conflict and stale-edit checks. Multi-file rename/code actions must be
typed by resolved identity, preserve application/rule/declaration order, and
either apply atomically to the validated document versions or fail.

## Source maps, revisions, cache, and redaction

Relate document, syntax, HIR/sema, compiled `SourceRangeRef`, runtime trace, and
merged-map ranges. Distinguish current/stale/generated/missing/withheld/tampered
locations; winner navigation must honor sheet and revision identity.

Specify bounded parse, index, semantic, format, and trace caches. Keys cover
source/document/profile/dependencies/maps and runtime frame/node/query/privacy.
Define cancellation, eviction, and invalidation for every state change.

Workspace features use authorized text. Runtime values, paths, snippets, secure
state, and diagnostics obey 5.1/Agent policy. Redact before serialization/cache
without leaks through content, locations, hashes, lengths, or cache behavior.

## Budgets

Define defaults and hard maxima for document bytes, syntax nodes, recovery
nodes, Style rules/declarations/tokens, completion candidates, references,
rename edits/files, formatting edits/output bytes, semantic tokens, source-map
lookups, runtime trace events/source bytes, and request time/work units.

Budget exhaustion must be typed and deterministic. Formatting must not return a
partial edit set that corrupts a document. Read-only LSP features may return a
clearly marked bounded partial result only when standard/custom protocol
semantics support it. Cancellation must not publish stale diagnostics or cache
an incomplete semantic result as complete.

## Constraints and non-goals

- No CSS/Takumi syntax/tooling/carrier/diagnostic/migration/cascade/compatibility
  path, and no LSP-owned parser, sema, matcher, token resolver, or cascade.
- Do not reorder rules, declarations, applications, tokens with order-sensitive
  references, or comments in ways that change native semantics.
- Do not redesign the native resolver or property/value metadata without
  concrete implementation evidence.
- Do not infer identity from text/path/labels/ordinals or reopen bundle source.
- No aliases, deprecated methods, dual formatters/readers, or source gates.
- General `.arcw` formatting outside the minimum context needed to format Style,
  live Style mutation, visual editors, pixel inspection, and CSS migration are
  non-goals.

## Implementation order to specify

1. Freeze normative source examples, trivia ownership, and semantic-preserving
   canonical formatting rules.
2. Implement/test the syntax-owned formatter core and typed document index.
3. Add source-only diagnostics, completion, hover, navigation, symbols, and
   semantic tokens through typed query APIs.
4. Add rename and code actions only after identity and stale-edit tests pass.
5. Add LSP document/range formatting as a thin projection of the core.
6. Adapt optional runtime explain to the finalized 5.1 DTO without changing it.
7. Add bounded caches, cancellation, and multi-backend/session integration.

## Required test matrix

- Formatter: all native families/trivia/line endings/Unicode/ranges are
  idempotent; recovery, invalid ranges, stale/cancel/budget never corrupt text.
- Preservation: before/after typed inventories, source order, and representative
  computed winners are identical.
- LSP positive: every feature in the matrix returns tight ranges and resolves
  by typed identity across files and same-named tokens in different sheets.
- LSP negative: malformed/ambiguous/missing/stale/unsupported/unauthorized/no-
  session cases have exact typed outcomes.
- Tamper: malformed JSON/enums/fields/positions/IDs/cursors/progress/integers
  are rejected without panic.
- Budget/cache: exact-limit and one-over tests for every limit, deterministic
  ordering/eviction, edit/profile invalidation, cancellation isolation, and no
  incomplete-result cache poisoning.
- Redaction: hover, diagnostics, navigation, custom explain responses, progress,
  and caches do not leak values, paths, snippets, hashes, lengths, or identity.
- Backend: in-process/stdio payloads and optional CLI/LSP format match; equal
  native/web/headless snapshots return equal 5.1 traces.
- Removed syntax: CSS-like forms receive ordinary parser recovery only and no
  formatter acceptance, migration action, special diagnostic, or completion.

## Expected design output and acceptance

Produce a new standalone design document or package containing:

- normative before/after source corpus and complete formatting/trivia rules;
- exact Rust formatter/index/query/error types and crate dependency diagram;
- a feature-by-syntax LSP matrix with exact standard/custom wire examples;
- source-map/revision, budget, cancellation, cache, redaction, diagnostic, edit
  conflict, and backend-parity contracts;
- an implementation sequence and complete positive, negative, semantic,
  tamper, budget, cache, redaction, removed-syntax, and backend tests.

Acceptance requires deterministic idempotent formatting that preserves native
Style semantics, typed LSP features with no raw-source identity heuristics, an
exact lossless 5.1 mapping for runtime explanation, and enough detail for an
implementation agent to proceed without reading another request or reopening
the verified native Style architecture.
