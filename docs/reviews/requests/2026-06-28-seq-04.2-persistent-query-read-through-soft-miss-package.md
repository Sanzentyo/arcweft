# Seq-04.2 Request: Persistent Query Read-Through Soft-Miss Package

## Sequence Position

This follows seq04.1. It consumes deterministic `.awbo` parse/HIR object codecs
and adds read-through validation, but does not write persistent compiler query
objects yet.

## Request

Design and implement adapter-owned persistent query read-through for safe
parse/HIR objects. Stale, corrupt, missing, or mismatched records must be soft
misses with typed evidence, not build-poisoning hard errors.

Return the final work as a zip package with implementation, tests, docs, and
validation.

## Required Scope

- Add typed read-through APIs in the filesystem/cache adapter layer, not in
  Sans I/O project data crates.
- Validate record schema, object digest, object length, source digest, compiler
  identity, query kind, payload schema, and dependency inputs.
- Return typed hit/miss evidence suitable for later `BuildSnapshot` recording.
- Treat missing object, corrupt record, corrupt object, digest mismatch, length
  mismatch, compiler identity mismatch, source digest mismatch, schema mismatch,
  and dependency mismatch as recoverable soft misses.
- Keep the compiler able to rebuild from source after any soft miss.

## Non-Goals

- No write-through cache persistence.
- No `arcw cache explain` UI changes beyond internal evidence data if needed.
- No typecheck/runtime-plan/bytecode/link-plan reuse.
- No hard error policy for corrupt local cache unless the existing cache verify
  command explicitly requests validation.

## Expected Zip Contents

- `overlay/` implementation files.
- Tests for each soft-miss class.
- `docs/implementation/seq-04-2-persistent-query-read-through-soft-miss-2026-06-28.md`
- `VALIDATION.md`.
- `README.md` with assumptions, apply order, and non-goals.
