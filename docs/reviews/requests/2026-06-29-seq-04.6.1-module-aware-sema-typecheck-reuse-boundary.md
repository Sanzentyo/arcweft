# Seq-04.6.1 Request: Module-Aware Sema Typecheck Reuse Boundary

## Sequence Position

This follows seq04.6. Seq04.6 introduced a stable typecheck gate object and
explicit valid-but-rebuilt evidence. It did not implement actual typecheck reuse
because current project compilation still typechecks linked HIR.

## Request

Design and implement the smallest module-aware semantic/typecheck boundary that
allows a cached typecheck result to replace source rebuild.

Do not redesign seq04.1 through seq04.6 unless current source evidence proves a
concrete flaw.

## Required Decisions

1. What dependency interface facts are sufficient for module-local name
   resolution, readiness, type checking, capability/effect validation, lifetime
   obligations, and diagnostics.
2. How current `TypeCheckReport` and semantic/effect reports can be projected to
   stable persistent facts without serializing compiler-private Rust internals.
3. What exact query key inputs distinguish a sound typecheck hit from a
   conservative gate hit.
4. How diagnostics and source ranges are reproduced identically between cached
   hit and source rebuild.
5. How downstream runtime-plan reuse consumes typechecked inputs without needing
   linked HIR.

## Expected Output

A package with design, implementation overlay, tests, validation notes, and a
clear migration path from `TypecheckGateObject` to actual `TypecheckReportObject`.
