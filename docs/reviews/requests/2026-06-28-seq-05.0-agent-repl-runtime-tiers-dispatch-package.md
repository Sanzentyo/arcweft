# Seq-05.0 Request: Agent REPL Runtime Tiers Dispatch Package

## Sequence Position

This is a dispatch request for splitting the original seq05 request:

- `docs/reviews/requests/2026-06-24-seq-05-agent-repl-runtime-tiers.md`

Seq05 follows seq01 executable runtime core and seq03 generation runtime
semantics. It may reference seq04 persistent cache behavior, but it must not
depend on seq04 implementation to work. It is independent of the currently
parallel seq03.7, seq04.2, seq06.4x, seq06.5, and seq06.6 design work.

## Request

Review the proposed seq05 split below and either:

1. confirm the split as-is; or
2. propose a better split with concrete reasons, dependency edges, and package
   boundaries.

The reviewer/designer is expected to be capable of improving the split. Do not
blindly accept the provisional numbering if a cleaner ownership boundary exists.
However, the final result must still be returned as independently applicable zip
packages, not as one large monolithic seq05 overlay.

## Provisional Split

### Seq05.1: REPL Overlay And Cell Transaction Package

Owns the base project snapshot, REPL overlay module model, cell representation,
transactional parse/HIR/sema/effect/verifier pipeline, rollback rules, and the
first committed-cell VM execution path.

Request file:

- `docs/reviews/requests/2026-06-28-seq-05.1-repl-overlay-cell-transaction-package.md`

### Seq05.2: REPL Commands And Agent Runner Package

Owns user-visible REPL command semantics, Agent runner/session integration,
read-only trace mode, cell listing, undo, reset, step/task/cancel/observe
commands, and deterministic command evidence.

Request file:

- `docs/reviews/requests/2026-06-28-seq-05.2-repl-commands-agent-runner-package.md`

### Seq05.3: REPL Executor Tiering, Warm, And Codegen Package

Owns VM-first executor tier policy, `AgentControllerExecutorFactory` selection,
background `:warm` and `:codegen` requests, optional JIT/AOT warming, and
non-blocking tier status reporting.

Request file:

- `docs/reviews/requests/2026-06-28-seq-05.3-repl-executor-tiering-warm-codegen-package.md`

## Required Dispatch Decisions

Please answer:

1. Is the 05.1/05.2/05.3 split correct, or should any boundary move?
2. Should committed-cell VM execution belong to 05.1 or 05.2?
3. Should `:undo` / `:reset` belong to the transaction owner or command owner?
4. Which API must 05.1 expose so 05.2 can implement commands without peeking
   into transaction internals?
5. Which API must 05.1/05.2 expose so 05.3 can add executor tiering without
   redesigning the REPL state machine?
6. Which parts can be designed in parallel, and which must be implemented
   sequentially?
7. What should be explicitly excluded from seq05 because it belongs to a later
   compiler/cache/codegen slice?

## Constraints

- Do not reintroduce source-level `jit`, `aot`, `lazy use`, or `eager use`.
- `:warm` and `:codegen` are REPL commands, not Arcweft source syntax.
- Product policy remains bytecode-VM-first.
- Product players must remain free of compiler, REPL, JIT, AOT, and tooling
  dependencies.
- Persistent query cache may be referenced but cannot be required.
- Keep the immediate execution path deterministic and VM-first.
- Prefer typed owner APIs over stringly command dispatch.
