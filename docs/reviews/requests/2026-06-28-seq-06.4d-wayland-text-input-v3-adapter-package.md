# Request 06.4d: Wayland text-input-v3 Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the Wayland platform adapter package and should not
redesign the shared capability, range, batch/serial, or geometry substrate
unless current implementation evidence proves a concrete flaw.

This request can be run independently from the Web, Windows, macOS, Android,
and iOS adapter requests. Wayland protocol XML evidence is a first-class gate
for this package.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for a
Wayland `text-input-v3` adapter for Arcweft text input.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints.
- Checked-out official Wayland `text-input-unstable-v3` protocol XML and any
  compositor-binding evidence needed for the current Arcweft native host.

## Platform Scope

Implement the Wayland adapter inside the native desktop boundary, expected to
include `crates/arcweft-desktop-native` and any existing Linux/Wayland host
module. If the current checkout has a different Wayland owner, document it in
`SOURCE_INVENTORY.md`.

The adapter must:

- detect `zwp_text_input_manager_v3`;
- return PlatformDisabled or typed unsupported capability facts when unavailable;
- avoid hidden, X11, GTK, or toolkit fallback text-entry paths in this request;
- keep Wayland objects, seats, surfaces, native `done(serial)` values, protocol
  handles, and compositor metadata adapter-local;
- use UTF-8 byte source units for surrounding-text delete operations;
- boundary-check byte offsets/counts before emitting Arcweft events;
- coalesce pending `preedit_string`, `commit_string`,
  `delete_surrounding_text`, cursor/selection state, and related operations
  until `done`;
- map one Wayland `done` to one Arcweft batch/serial;
- keep native `done(serial)` fixture-local only and never use it as
  `TextInputSerial`;
- compute surface-local cursor rectangles from Arcweft viewport/screen geometry
  plus native surface state and send `set_cursor_rectangle` before protocol
  commit;
- report standard text-input-v3 character bounds and reconversion as unsupported
  unless current protocol evidence proves otherwise;
- omit all character bounds for secure fields and report them as
  `SecureRedacted`, not plain platform unsupported.

## Required Decisions

1. The Wayland crate/module ownership, feature flags, and protocol binding
   approach.
2. The official XML version pinned for implementation and fixtures.
3. The runtime detection path for text-input manager, seat, and focused surface.
4. The UTF-8 byte range conversion path, including invalid byte boundaries,
   multibyte scalars, stale snapshots, and explicit reject/no-clamp behavior.
5. The exact ordering of optional PreClear, DeleteSurrounding, Commit,
   SetComposition, and final selection/cursor placement in one Arcweft batch.
6. The `done` transaction boundary that creates one Arcweft serial.
7. The geometry path from Arcweft viewport/screen rectangles into Wayland
   surface-local cursor rectangles.
8. The secure-field policy for surrounding text, cursor rectangle, diagnostics,
   Agent observe, replay, and capture output.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include:

- Wayland-only adapter modules and any feature/Cargo dependency edits.
- A checked protocol XML fixture or pinned source reference.
- Typed capability detection and activation diagnostics.
- Wayland event coalescing into `PlatformTextInputEvent`.
- UTF-8 byte range conversion through shared text-index APIs.
- Geometry adapter code for `set_cursor_rectangle` ordering and surface-local
  conversion.
- Wayland fixture traces for:
  - protocol XML/version pinning;
  - text-input manager present and absent;
  - UTF-8 byte delete around a multibyte scalar;
  - invalid byte boundary rejection;
  - preedit/commit/delete coalescing until `done`;
  - native `done(serial)` mismatch or focus reset;
  - `set_cursor_rectangle` before protocol commit;
  - secure field redaction.
- Cross-platform compile gates so non-Wayland hosts do not require Wayland
  runtime objects.
- `docs/implementation/seq06-4d-wayland-text-input-v3-adapter.md`.

## Acceptance Criteria

- Wayland activation uses typed capability facts and diagnostics.
- Absence of `zwp_text_input_manager_v3` is represented explicitly and does not
  install a fallback path.
- Native Wayland metadata remains adapter-local or fixture-local only.
- All normalized text operations carry canonical byte ranges only.
- UTF-8 byte boundaries are checked before event emission.
- One Wayland `done` maps to one Arcweft serial.
- Geometry revisions are separate from input serials and native `done(serial)`.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, selected-range-derived anchor, or native object
  identity.

## Tests To Specify And Run

- Focused Wayland adapter tests for detection, byte range conversion, done
  coalescing, operation ordering, geometry, focus reset, and secure redaction.
- Non-Wayland compile/source-gate tests proving Wayland code is correctly gated.
- Shared presentation/runtime-host tests that the Wayland adapter relies on, if
  not already present in main.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- `cargo clippy` for changed crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not put Wayland handles, seats, surfaces, or native serials in Sans I/O
  payloads.
- Do not use native `done(serial)` as `TextInputSerial`.
- Do not store source units in normalized operations or geometry snapshots.
- Do not add a toolkit fallback in this request.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Web, Windows, macOS, Android, or iOS implementation.
- X11 or toolkit-specific IME implementation.
- Replacing the seq06.3 common contract.
