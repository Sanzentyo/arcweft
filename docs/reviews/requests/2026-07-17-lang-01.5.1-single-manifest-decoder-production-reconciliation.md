# Lang-01.5.1 — single manifest decoder production reconciliation

## Sequence position

This request follows Lang-01.5 Phase 1's neutral identity/hash/adapter-metadata
substrate and precedes source ownership migration, verified adapter loading, and
tooling deletion.

## Why this split is required

The final schema removes active launch fields before their replacement owners
are wired. At `39d487a0f8e7`, those fields still feed runtime and tooling. A final
decoder added beside the old project/launch decoders would violate the one-reader
contract; deleting the old decoders without migrating consumers would lose
behavior.

## Required decisions

1. Define the smallest atomic production cut allowed to cross the package's
   nominal phase boundaries so every active old launch field either has its final
   typed replacement or is proven unused before deletion.
2. Confirm how the existing `InlineFailurePolicy`, `InlineFallback`, and
   `FallbackStylePolicy` receive strict manifest serde at their current owner
   without introducing a second enum owner or a dependency cycle.
3. Specify the final owner and migration of the current `[resources]` authored
   asset/content roots, which are absent from the final root schema.
4. Specify the exact `ArcweftManifestDocument` to `ResolvedLaunchProfile`
   lowering required while generated module verification is not yet published.
5. Define the one-transaction call-site migration for project-loader, compiler,
   CLI, LSP, tests, samples, and overlays.

## Implementation order to specify

1. Extend the existing owning policy types with exact final serde.
2. Implement one Taplo-style span-preserving TOML syntax tree and typed decode
   from that same tree, including first/later duplicate ranges.
3. Migrate all consumers to `SourceBackedManifest` without reparsing text.
4. Delete `SourceBackedLaunchManifest`, `LaunchManifestSourceMap`, `TomlScanner`,
   `ProjectManifest::parse_toml`, `LaunchProfileManifest::parse_toml`, and every
   independent `toml::from_str` manifest route in the same cut.
5. Migrate maintained schema-1 fixtures and assert overlay revision identity.

## Tests to specify

- missing/unsupported schema, unknown root/table/field, and malformed typed IDs;
- duplicate root key, table, quoted/unquoted map ID, and activity binding with
  both source ranges;
- scalar, table-key, and array-element source-map coverage bound to one document
  revision;
- no parser or decoder call after accepted `SourceBackedManifest` publication;
- all old runtime/tooling inputs either map to final typed facts or fail with a
  documented removal diagnostic before the old reader is deleted;
- overlay failure remains atomic and never publishes a partial accepted graph.

## Constraints

- do not redesign the implemented Lang-01.5 identity, digest, canonical JSON, or
  neutral adapter metadata substrate without a concrete defect;
- no compatibility aliases, dual readers, legacy schema, deprecated fields,
  source gates, CSS/Takumi route, or last-known-good fallback;
- the final data path remains Sans I/O and loader containment remains a separate
  filesystem boundary.

## Expected output

Return an implementation-ready reconciliation contract with the exact atomic
scope, owner/dependency graph, final Rust shapes, call-site deletion list,
diagnostics, tests, and a proof that no transient dual-reader state is committed.
