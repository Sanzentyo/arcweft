# Request 06.4h: Web EditContext Real IME Validation Package

## Sequence Position

This follows the applied seq06.4g shared text editor and seq06.4a.2 Web
EditContext player-owned glue.

It must not redesign the common seq06.3 text-input contract, the shared
`TextEditorState`, or the player-owned Web glue unless real browser evidence
shows a concrete defect.

## Problem

The local automated smoke can prove source ownership, unsupported-browser
behavior, keyboard selection, and non-origin synthetic geometry. It cannot prove
the real Japanese IME candidate window path when the available Playwright
browser reports no usable `EditContext`.

The remaining Web risk is evidence-driven:

- candidate windows must anchor near the Arcweft caret or composition range;
- the browser/native caret must be hidden or synchronized with Arcweft's caret;
- selection, pointer movement, delete/backspace, and shortcut handling must work
  while a real IME is active;
- application authors must not write sample-local IME glue.

## Request

Produce a final zip package containing design notes, any needed implementation
overlay, real-browser test harnesses, fixtures, validation evidence, and apply
instructions for Web `EditContext` real IME validation.

The package should use an `EditContext`-capable Chrome/Edge build or document
the exact stable/browser-channel requirement. If implementation changes are
needed after real validation, include them as narrow production patches.

## Required Decisions

1. Which browser channel and feature flags are required for real `EditContext`
   validation.
2. Whether the test should be fully Playwright-driven, partially manual with a
   structured trace recorder, or both.
3. The trace schema for real IME sessions:
   - focus;
   - composition start/update/end;
   - selection changes;
   - geometry calls;
   - key/pointer commands;
   - screenshot or video evidence.
4. How to assert candidate placement without relying only on visual inspection.
5. How to prove the browser/native caret is hidden or synchronized.
6. How to capture Japanese IME preedit and commit in a repeatable way.
7. Which secure-field facts must be redacted in the trace.
8. What counts as unsupported-browser success versus validation blocked.

## Required Implementation

- Add a real-browser Web IME validation harness under `web/tests/` or
  `tools/` that can target an installed EditContext-capable browser channel.
- Add trace fixture files under `fixtures/web-editcontext-real-ime/`.
- Capture at least one Japanese IME preedit-to-commit trace.
- Capture geometry evidence proving candidate/caret bounds are non-origin and
  track the current selection or composition range.
- Capture one keyboard movement case and one pointer selection case against the
  real `EditContext` path.
- Capture an unsupported-browser path proving no hidden textarea or
  contenteditable fallback is installed.
- If real validation finds a production defect, patch the player-owned glue or
  Rust Web adapter instead of changing the sample to own IME events.
- Add `docs/implementation/seq06-4h-web-editcontext-real-ime-validation.md`.

## Acceptance Criteria

- A real EditContext-capable browser accepts Japanese IME preedit and commit in
  the Arcweft Web sample.
- Candidate geometry anchors near the current caret or composition range, not
  the viewport origin.
- Exactly one visible Arcweft caret is present, or a documented browser
  limitation proves native caret synchronization instead of hidden fallback.
- Arrow movement, pointer placement, ranged selection, delete/backspace, and
  select-all remain synchronized with `EditContext` selection.
- Application authors do not write custom IME conversion glue.
- Unsupported browsers report typed unsupported state and install no hidden DOM
  text-entry fallback.
- Secure fields redact surrounding text, selection-derived sensitive geometry,
  clipboard text, and trace details.

## Tests To Specify And Run

- `npm run test:ime`.
- Real browser IME harness with an EditContext-capable browser.
- Source gates for forbidden hidden fallback and sample-owned IME glue.
- Focused Rust tests for Web adapter dispatch and secure redaction.
- Screenshot/video or trace validation for candidate placement and caret policy.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test`/`cargo clippy` for changed crates.

## Constraints

- Do not use hidden `textarea` or `contenteditable` fallback.
- Do not move DOM or browser object identity into Sans I/O crates.
- Do not make the sample own IME event conversion.
- Do not treat unsupported Playwright Chromium as proof that real IME validation
  passed.

## Non-Goals

- Windows, macOS, Wayland, Android, or iOS native implementation.
- Replacing renderer glyph layout; that is seq06.4i.
- Redesigning the text-input contract without evidence.
