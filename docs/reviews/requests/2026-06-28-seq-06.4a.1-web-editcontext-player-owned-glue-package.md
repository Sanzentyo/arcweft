# Request 06.4a.1: Web EditContext Player-Owned Glue Package

> **Superseded (2026-07-13):** Arcweft Style is now native-only. The CSS authoring and Takumi product-path premises in this request were removed; see [Native-only typed Style path](../../implementation/native-only-style-path-2026-07-13.md). Do not use this request to reintroduce or reimplement CSS/Takumi Style behavior.

## Sequence Position

This follows seq06.4a and the current applied implementation recorded in:

- `docs/implementation/seq06-4abc-platform-text-input-adapters.md`
- `docs/implementation/seq06-ime-css-font-sample-2026-06-28.md`

Seq06.4a added the Web `EditContext` adapter core and a sample. This request is
not a redesign of the shared seq06.3 text-input contract. It is the missing Web
player integration slice that makes Arcweft own the browser glue and event
handling so application authors do not need to write custom JS to get IME
behavior.

Seq06.4a.2 extends this request with the observed production gaps around
candidate-window geometry, native/browser caret suppression or synchronization,
selection rendering, pointer hit-testing, keyboard movement, deletion, and
shortcut handling. If both requests are sent together, one package may satisfy
both only if it explicitly covers the acceptance criteria from each request.

## Problem

The current Web IME sample proves that `EditContext` can work, but
`web/ime-sample.js` owns DOM lookup, `EditContext` construction, text update
handling, composition state, model text, and rendering. That is acceptable as a
temporary sample, but it is not an acceptable product architecture: Arcweft
users should not have to hand-write glue JS for focus, `EditContext` events,
geometry, composition, secure redaction, or unsupported-browser handling.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for player-owned Web
`EditContext` integration.

The final result must move the browser event glue into the Arcweft Web player
boundary. User-authored pages may provide a host element/canvas and choose
runtime options, but they must not need to manually:

- instantiate `EditContext`;
- attach `textupdate`, `compositionend`, or geometry listeners;
- maintain preedit/commit document state;
- convert UTF-16 offsets;
- decide whether a hidden fallback is allowed;
- forward text events into runtime-host dispatch.

## Required Decisions

1. The public Web player API shape for enabling text input:
   - automatic canvas/host installation;
   - explicit `start_arcweft_player` options;
   - or a dedicated exported setup function.
2. Which code owns DOM element association with `EditContext`.
3. How player-owned glue discovers the focused Arcweft TextField/TextArea and
   requests activation snapshots.
4. How `EditContext` event listeners map to `WebEditContextAdapter` without
   exposing JS-native events to Sans I/O code.
5. How the player updates `EditContext` text/selection after runtime/editor
   state changes.
6. How geometry updates are pumped from rendered TextField layout to
   `EditContext` candidate/character rectangles.
7. How unsupported browsers report typed capability errors without installing
   hidden textarea/contenteditable fallbacks.
8. How secure fields narrow capabilities and redact surrounding text,
   character bounds, composition, Agent observe, replay, and capture metadata.
9. How the sample page becomes a thin consumer of Arcweft player-owned
   behavior rather than the owner of the IME state machine.

## Required Implementation

The package must provide implementation-ready code, not only prose. It should
include concrete edits for the current repository:

- Web player-owned text-input bridge module, either in Rust/WASM, JS host glue,
  or both, with ownership documented.
- A public setup/export path so the app page can opt into text input without
  per-project glue.
- Removal or demotion of `web/ime-sample.js` manual event ownership. The sample
  may remain, but it should call the player-owned setup and only display status.
- Event mapping for activation, text update, composition end/cancel, selection,
  geometry update, and deactivation.
- Source gates proving no hidden textarea/contenteditable fallback is present.
- Browser smoke tests proving the sample page works with player-owned glue.
- Unsupported-browser fixture or test path proving a typed unsupported result.
- Documentation under `docs/implementation/`.

## Acceptance Criteria

- A normal Arcweft Web embed does not require user-authored IME glue JS.
- `EditContext` object ownership and event listeners live in the Arcweft Web
  player boundary.
- The sample page uses the player-owned path.
- No hidden textarea/contenteditable fallback is introduced.
- Keyboard events do not directly insert characters.
- Text update ranges are normalized through `TextIndexSnapshot`.
- Secure text never leaks through Web status, observation, replay, or fixtures.
- Browser and Rust tests cover ready and unsupported paths.
- Candidate geometry, visible caret, and selection behavior may be completed by
  seq06.4a.2 if they are not included in this package.

## Tests To Specify And Run

- Browser smoke for the sample page.
- Source gate rejecting hidden fallback strings in Web player source.
- Focused Rust tests for `WebEditContextAdapter`.
- JS/wasm integration smoke proving player-owned setup installs listeners.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test`/`cargo clippy` for changed crates.
- `node` or `npm` Web tests for changed browser glue.
- Structural audit if public crate boundaries or module sizes change.

## Constraints

- Do not redesign the shared seq06.3 text-input contract.
- Do not make users write event conversion glue.
- Do not add hidden textarea/contenteditable fallback.
- Do not store JS object identity in Sans I/O crates.
- Do not place browser API assumptions in fixture-only code without product
  source gates.

## Non-Goals

- Windows, macOS, Wayland, Android, or iOS implementation.
- Replacing the renderer or Takumi lowering.
- Rich document editing beyond current TextField/TextArea/SecureField scope.
