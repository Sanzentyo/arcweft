# Request: seq06.9b wgpu UI Compositor Effects Package

> **Superseded (2026-07-13):** Arcweft Style is now native-only. The CSS authoring and Takumi product-path premises in this request were removed; see [Native-only typed Style path](../../implementation/native-only-style-path-2026-07-13.md). Do not use this request to reintroduce or reimplement CSS/Takumi Style behavior.

## Goal

Implement the wgpu compositor substrate for the seq06.9a UI compositing graph:
offscreen group rendering, filter passes, backdrop-filter, mask composition,
clip-path geometry, opacity, and mix-blend-mode. This must render through GPU
passes rather than CPU-rasterizing Takumi output.

## Dependency

This request depends on the seq06.9a scene contract. If seq06.9a is not yet
implemented, design against its request as the upstream contract and do not
redefine the same types in a conflicting way.

## Scope

- Add responsibility modules such as `view_compositor.rs`, `view_effects.rs`,
  `view_mask.rs`, and `view_blend.rs` under the renderer crate, or the nearest
  existing equivalent if the current code has already split these boundaries.
- Render compositing groups into offscreen textures and composite them into the
  parent target.
- Implement color-matrix filter effects first:
  brightness, contrast, grayscale, sepia, saturate, hue-rotate, invert, and
  opacity.
- Implement blur using a deterministic separable or Kawase blur path with bounds
  expansion from the seq06.9a filter-outset contract.
- Implement drop-shadow by deriving source alpha, blurring, offsetting, tinting,
  and compositing under the original source.
- Implement backdrop-filter by copying/sampling already-rendered backdrop
  pixels through an intermediate texture. Do not sample from the active render
  attachment.
- Implement mask composition using mask alpha/luminance texture semantics.
- Implement initial clip-path lowering/rendering for supported shapes while
  preserving explicit diagnostics for unsupported path forms.
- Implement mix-blend-mode through shader-based blend/composite passes for the
  initial supported blend modes.
- Use texture pools and deterministic allocation bounds to avoid resizing
  churn.

## Non-Goals

- Do not add platform/window event-loop logic to the renderer crate.
- Do not make the renderer read files or fetch resources directly.
- Do not turn the entire UI into a CPU bitmap upload.
- Do not silently ignore unsupported CSS values.

## Implementation Order To Specify

1. Audit current `SharedRenderer` render order and texture ownership.
2. Introduce offscreen scene/group target allocation.
3. Move direct primitive rendering behind a reusable group render path.
4. Add filter shader pipelines and deterministic test hooks.
5. Add backdrop copy/filter/composite path.
6. Add mask and clip-path passes.
7. Add blend-mode pass.
8. Add source gates against CPU fallback and platform leakage.
9. Run structural audit if renderer files cross responsibility thresholds.

## Tests To Include

- Unit tests for filter pass planning and texture bounds.
- Golden or deterministic smoke fixtures for blur, drop-shadow, mask,
  clip-path, backdrop-filter, and mix-blend-mode.
- Tests proving direct primitive rendering still works without compositing.
- Source gate preventing full UI CPU raster fallback.
- Cross-platform check targets at least for non-native tests; native/golden tests
  may be marked ignored if they require pinned GPU environments.

## Expected Output

Return a zip package containing:

- renderer implementation overlay and tests;
- shader source or WGSL modules if needed;
- `docs/design/seq-06.9b-wgpu-ui-compositor-effects-design.md`;
- `docs/implementation/seq-06.9b-wgpu-ui-compositor-effects-2026-06-29.md`;
- validation notes, known platform/GPU limitations, and fixture instructions;
- overlay manifest and checksums.

Validation commands must include fmt, focused renderer tests, clippy for changed
crates, and structural audit.
