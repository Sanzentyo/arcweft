# Request: seq-06.13b box-shadow and blend render closure package

## Sequence position

Seq06.13b is split out of the broader seq06.13 CSS motion/effects request. It
focuses on CSS `box-shadow` and the remaining blend-mode rendering closure.

It can be designed in parallel with seq06.13a, but normal player integration
should use seq06.11b's `UiScene` / `UiCompositor` path.

## Problem

The renderer already has filter `drop-shadow(...)` planning, and
`mix-blend-mode` supports many separable modes. But CSS `box-shadow` is only
classified as paint-only and does not appear to be implemented as a direct or
composited primitive. Also, HSL/luminosity-family blend modes remain first-cut
unsupported.

This leaves common UI styling gaps for cards, buttons, popovers, and layered
panels.

## Goal

Design and implement a deterministic first production cut for:

- CSS `box-shadow` rendering for rectangular and rounded-rect UI boxes;
- exact interaction between shadows, opacity, transforms, and clipping;
- remaining or explicitly deferred `mix-blend-mode` values:
  - `hue`;
  - `saturation`;
  - `color`;
  - `luminosity`.

## Required decisions

- Decide whether `box-shadow` is:
  - a direct primitive;
  - a compositor group effect;
  - or lowered to a shadow primitive plus optional offscreen blur.
- Define support for:
  - outer shadow;
  - inset shadow;
  - spread radius;
  - multiple shadows;
  - rounded corners;
  - negative spread;
  - transparent colors.
- Define deterministic blur/spread bounds and allocation rules.
- Define how `box-shadow` interacts with clip/mask/effects from seq06.13a.
- Decide color-space rules for HSL/luminosity blend modes, or explicitly defer
  them with typed diagnostics.
- Define visual evidence and thresholds for native/web parity.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes.
- Keep all rendering in Arcweft-owned wgpu paths.
- Do not emulate `box-shadow` with browser CSS, DOM elements, canvas 2D, or
  bitmap snapshots.
- Preserve existing `filter: drop-shadow(...)` behavior and distinguish it from
  `box-shadow`.
- Unsupported shadow/blend values must emit structured diagnostics.

## Tests to specify and implement

- Outer box-shadow renders around a solid rounded rect.
- Inset shadow either renders correctly or emits an explicit unsupported
  diagnostic.
- Multiple shadows preserve CSS order.
- Spread radius changes visual bounds deterministically.
- Shadow plus transform/opacity produces stable pass planning.
- Existing supported blend modes continue to pass.
- HSL/luminosity-family blend modes pass if implemented or emit typed
  diagnostics if deferred.
- Native/web visual smoke captures compare within documented thresholds.

## Expected output

Return a zip named like:

```text
arcweft-seq06.13b-box-shadow-and-blend-render-closure-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- renderer/compositor overlay edits;
- CSS fixtures;
- focused tests;
- validation instructions;
- explicit support matrix.

## Non-goals

- Do not implement transitions/keyframes here.
- Do not implement clip-path/mask closure here; seq06.13a owns that.
- Do not implement broad CSS layout/cascade support here.
