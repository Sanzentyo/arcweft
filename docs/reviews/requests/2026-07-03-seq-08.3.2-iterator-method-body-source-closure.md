# Request: seq-08.3.2 Iterator Method Body Source Closure

## Sequence Position

This follows seq08.3 and can run in parallel with seq08.3.1 only if it does not
touch AWBC schema, codec, verifier, or VM execution. It should close the DSL
source-to-runtime gaps exposed by the full iterator witness fixture.

## Problem

Seq08.3 can lower and execute runtime trait method callables, and it can lower a
source-defined `IntoIterator` / `Iterator` pair when `next(&mut self)` has a
simple supported body. The full package fixture still needs the source pipeline
to accept and lower a realistic iterator body:

```arcw
fn next(&mut self) -> Option<i64> {
    if self.current < self.end {
        let value = self.current
        self.current = self.current + 1
        Some(value)
    } else {
        None
    }
}
```

The runtime expression layer already has the needed concepts: field reads,
binary comparisons, `if`, `let`, direct record-field assignment, and
`Some`/`None` variants. The gap is making this full source shape parse,
type-check, lower, and execute through the same trait method body path.

## Required Design

Specify the source-to-runtime closure for trait method bodies:

- final grammar for assignment statements inside function and impl method
  bodies;
- whether assignment is expression-valued or statement-only;
- typed lvalue rules for direct record fields and future nested lvalues;
- source spans and diagnostics for invalid assignment targets;
- type-checking of `if` tail expressions whose branches contain prefix
  statements and a tail value;
- typed lowering from `Stmt::Assign` to runtime field mutation without
  compatibility syntax;
- how `&mut self` method bodies expose mutable receiver state to assignment;
- regression strategy for the exact user-defined iterator fixture.

## Required Implementation

- Make the full `user-defined.arcw` iterator witness fixture parse without raw
  expression fallback.
- Type-check `self.current < self.end`, `let value = self.current`, direct
  `self.current = self.current + 1`, `Some(value)`, and `None` under the method
  return type `Option<i64>`.
- Lower the method body into a `RuntimeTraitMethod` containing deterministic
  runtime expressions.
- Execute a source-defined `Counter` / `CounterIter` loop and prove it yields
  the expected sequence, not just a single manually constructed runtime call.
- Add structured diagnostics for unsupported nested assignment targets rather
  than silently accepting removed or raw syntax.

## Constraints

- Do not introduce compatibility shims or alternate iterator syntax.
- Do not hard-code `Counter`, `CounterIter`, `current`, `end`, `Some`, or
  `None`; use general expression, lvalue, and expected-type rules.
- Do not use raw expression fallback to make the fixture pass.
- Do not redesign trait catalog or AWBC; keep this package focused on
  source/HIR/sema/runtime-plan/runtime-engine closure.

## Tests To Specify

- Parser/HIR test for assignment statements in function bodies.
- Type-check test for the full iterator fixture.
- Runtime-plan test proving two trait methods are lowered and linked by witness
  evidence.
- Engine/compiler integration test proving `Counter { start: 0, end: 3 }`
  yields `0, 1, 2` through user-authored `next(&mut self)`.
- Negative tests for invalid assignment targets and branch type mismatch.
