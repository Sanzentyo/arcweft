# Request: seq-06.15 `.awchar` character-stage runtime and LSP package

## Sequence position

Seq06.15 follows the existing character substrate and the seq06 presentation
work. It should build on:

- `arcweft-character`;
- `arcweft-character-psd`;
- `arcweft-presentation::character::CharacterRenderSpec`;
- `arcweft-character-ui`;
- `docs/schemas/character-manifest.md`;
- seq06.14 responsive stage placement when production placement is needed.

This request can be designed in parallel with seq06.14, but final production
integration must share the placement contract from seq06.14.

## Problem

The Zundamon sample currently imports PSD material and then writes flat PNGs
such as `normal.png` and `smile.png`. This loses the PSD layer structure and
relative positioning. It also makes pose/expression changes unstable: a pose
change can shift the cropped PNG, so the standing character appears to jump even
when the intended PSD canvas anchor is stable.

Arcweft already has a typed `.awchar` character manifest format and PSD importer,
but that substrate is not yet wired as the normal product/player/LSP path for
standing characters.

## Goal

Design and implement production `.awchar` character-stage integration.

The final Zundamon-style sample should use a typed character package and select
look/pose/expression data through Arcweft source, not through manually flattened
PNG swaps.

## Required decisions

- Define product/bundle representation:
  - `.awchar` package resource;
  - manifest bytes;
  - package-relative layer PNG payloads;
  - compact resource codec ownership if required;
  - AWFB/AWFR publication behavior.
- Define source authoring:
  - how a character manifest is declared or referenced;
  - how `look`, `pose`, `expression`, `mouth`, and other selectable axes appear
    in `.arcw`;
  - whether existing dialogue `look=.normal` should resolve against `.awchar`
    looks;
  - how stage methods such as `character.stage.show(...)` relate to image
    presentation objects.
- Define runtime/player representation:
  - `CharacterRenderSpec` as the runtime truth for a selected character look;
  - layer stack resolution;
  - canvas anchor preservation;
  - per-layer source rectangles and z ordering;
  - blend mode and clipping support policy;
  - unresolved/unsupported layer diagnostics.
- Define renderer path:
  - native/web shared wgpu rendering;
  - no browser DOM;
  - no pre-flattened runtime PNG fallback;
  - optional retained UI lowering through `arcweft-character-ui` if that remains
    the best path.
- Define Agent observe output:
  - character object;
  - per-layer object metadata or nested presentation tree nodes;
  - selected look/pose/expression;
  - stable bbox from source canvas anchor;
  - capture refs for whole character and, if supported, individual layers.
- Define LSP/tooling:
  - completions for character ids;
  - completions for looks;
  - completions for parts/variants where exposed;
  - hover information with source PSD layer names;
  - diagnostics for missing looks or invalid variant selections;
  - project profile loading through `character_manifests`.
- Define import tooling:
  - `arcw import psd-character` or existing import command behavior;
  - zundamon sample preparation without flattening to `normal.png`/`smile.png`;
  - validation of PSD group naming contracts.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, fixtures, and
  validation notes.
- Preserve `.awchar` as typed character data. Do not convert the final runtime
  path into flat pose PNGs.
- Do not use compatibility shims or accept legacy flattened character samples as
  the production path.
- Keep data-format crates Sans I/O. File reads, PSD import, and publication must
  stay in adapter/tooling layers.
- Keep native and web rendering on the same prepared-frame path.
- Unsupported PSD blend/clipping behavior must be represented by typed
  diagnostics or explicit preserved metadata, not silent approximation.

## Tests to specify and implement

- PSD import writes a `.awchar` package with manifest, parts, variants, source
  layer names, canvas, anchor, and package-relative layer PNGs.
- `CharacterRenderSpec` resolves a look deterministically and preserves canvas
  anchor and layer rectangles.
- Product bundle includes character package resources and rejects missing layer
  payloads.
- Runtime/player can show a selected look without flattened PNG swaps.
- Switching expression/pose keeps stable stage anchoring.
- Native and web render the same resolved character layer stack.
- Agent observe reports selected character look and stable bbox.
- LSP completions include available looks/parts/variants from loaded
  `character_manifests`.
- Zundamon sample uses `.awchar` and has visual evidence for normal/smile or
  equivalent look switching.

## Expected output

Return a zip named like:

```text
arcweft-seq06.15-awchar-character-stage-runtime-lsp-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- Rust overlay edits;
- zundamon sample migration plan and implementation;
- fixture or synthetic `.awchar` package for tests;
- focused unit/integration tests;
- LSP completion/diagnostic tests;
- native/web/observe validation instructions;
- explicit deferred list for unsupported PSD features.

## Non-goals

- Do not implement a full PSD editor.
- Do not require the runtime to parse PSD files directly.
- Do not solve every Photoshop blend mode in the first production cut.
- Do not redesign all dialogue character APIs unless the current API blocks
  typed look/pose/expression resolution.
