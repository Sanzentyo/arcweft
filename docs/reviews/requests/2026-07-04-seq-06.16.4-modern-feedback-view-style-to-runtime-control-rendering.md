Do not use this request to reintroduce or reimplement CSS/Takumi Style behavior.

## Why This Split Exists

`samples/modern-feedback-view` now bundles with component-authored text controls
and non-overlapping submit button fallback bounds. Its authored style still does
not appear in the actual player-rendered text-control/button path because
`ViewStyleResource` is not resolved into `RenderTextInputControl` or
`RenderActionButton`.

Focused CSS tests show that opacity and `box-shadow` are available below the
product View boundary. The missing work is the product View style resolution and
runtime-control rendering contract, not another CSS parser or shadow renderer
package.

## Goal

Make the modern feedback View visibly honor its authored style for player-owned
runtime controls:

- background alpha / opacity;
- border and focus-ring colors;
- hover, pressed, focused, and disabled button states;
- CSS or Arcweft-authored `box-shadow` where the existing renderer substrate
  supports it;
- deterministic native and web behavior through the same player-owned data
  path.

## Required Decisions

- Decide whether this is implemented as a focused slice of seq06.11 retained View
  style resolution or as a narrow runtime-control visual style bridge that is
  later replaced by seq06.11.
- Define the typed style payload that reaches runtime controls:
  - resolved fill/text/border/focus colors;
  - opacity;
  - radius;
  - shadow list;
  - disabled/hover/pressed/focus-visible state resolution.
- Decide whether `RenderTextInputControl` and `RenderActionButton` gain style
  fields directly or consume retained View fragments produced from
  `ViewProgramResource`.
- Define diagnostics for style properties that are stored in `ViewStyleResource`
  but cannot affect player-rendered runtime controls yet.
- Decide how authored Arcweft style rules and inline CSS style patches cascade
  when both apply to the same runtime control.

## Implementation Order

1. Audit current modern feedback View bundle resources and player-scene lowering
   for text controls and action buttons.
2. Reuse seq06.11 product View style-resolution design wherever possible.
3. Add the smallest typed style contract that can carry alpha, border/focus
   colors, radius, and box-shadow from product View resources into player-rendered
   controls.
4. Wire native and web player rendering through the same resolved style data.
5. Update `samples/modern-feedback-view` only after the runtime path can actually
   render the authored effects.
6. Add focused tests and visual smoke artifacts.

## Tests To Specify And Implement

- Modern feedback View text controls resolve authored background alpha and border
  color.
- Hover/pressed/disabled button selectors resolve deterministically.
- Focus-visible ring style resolves for text controls and action buttons.
- A supported `box-shadow` declaration reaches the renderer shadow plan.
- Unsupported style properties produce structured diagnostics instead of silent
  no-ops.
- Native and web visual smoke artifacts show the same control bounds and style
  state for the pinned sample.
- Existing View text submit and action button activation tests still pass.

## Constraints

- Do not restore removed top-level text-control declarations.
- Do not use DOM overlays, browser CSS rendering, canvas fallback, image
  snapshots, or sample-specific geometry to fake the result.
- Do not duplicate the Takumi box-shadow renderer; use the existing seq06.13e
  substrate.
- Keep `arcweft-bundle` codec/data-only and Sans I/O.
- Preserve deterministic runtime behavior and shared native/web contracts.
