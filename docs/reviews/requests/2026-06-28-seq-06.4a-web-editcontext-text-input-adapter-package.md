# Request 06.4a: Web EditContext Text Input Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the first platform-specific adapter package and should
not redesign the shared capability, range, batch/serial, or geometry substrate
unless current implementation evidence proves a concrete flaw.

This request can be run independently from the Windows, macOS, Wayland,
Android, and iOS adapter requests. If it discovers a shared contract defect,
the result package must isolate that finding in a separate integration note
instead of silently changing platform semantics.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for the
Arcweft Web text-input adapter using the standards-based Web `EditContext`
surface. Hidden textarea, contenteditable, or DOM-input fallback paths are
forbidden for this request.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints:
  capability owner is 06.3.1, range owner is 06.3.2, batch/serial owner is
  06.3.3, and geometry owner is 06.3.4.
- Official API evidence for `EditContext`, including the W3C EditContext draft
  and current MDN/browser compatibility notes.

## Platform Scope

Implement the Web adapter path in the existing Web player boundary, expected to
include `crates/arcweft-player-web` and any existing host/JS glue used by that
crate. If the current checkout has moved the Web host code, the package must
document the actual owner path in `SOURCE_INVENTORY.md`.

The adapter must:

- feature-detect `EditContext` before activation;
- return a typed unsupported capability diagnostic such as
  `WebEditContextUnavailable` when unavailable;
- call the runtime-host activation path that accepts already narrowed
  capabilities;
- keep browser objects, DOM nodes, JS object identity, and native event objects
  adapter-local;
- treat `EditContext` text, selection, and update offsets as UTF-16 source units
  unless current API evidence proves a more specific rule;
- convert all platform-originated ranges through `TextIndexSnapshot` before
  emitting canonical `TextRange<TextByteOffset>`;
- emit one strictly increasing `TextInputSerial` per Arcweft event, with one
  EditContext event or tightly associated same-context update group becoming one
  serial;
- send geometry via `TextInputHostCommand::UpdateGeometry`, never as a text
  batch;
- use viewport/client CSS-pixel-equivalent coordinates for EditContext geometry;
- omit all character bounds for secure fields and report them as
  `SecureRedacted`, not plain platform unsupported.

## Required Decisions

1. The exact feature-detection and unsupported diagnostic shape for browsers
   without `EditContext`.
2. The JS/WASM boundary owner for native events, offsets, and geometry updates.
3. The mapping from `textupdate`, selection changes, composition-related
   updates, and associated update groups into Arcweft batches.
4. The UTF-16 to canonical byte conversion path, including surrogate pairs,
   invalid update ranges, and stale text snapshots.
5. The transaction boundary that determines one Arcweft serial.
6. The geometry conversion path from Arcweft viewport/client rectangles into
   EditContext control, caret, character-bound, and candidate placement data.
7. The secure-field policy for surrounding text, character bounds, composition
   segment metadata, diagnostics, Agent observe, replay, and capture output.
8. Whether Web tests run through existing Rust integration tests, wasm tests,
   browser automation, or a combination, and how unsupported-browser fixtures
   prove that no fallback was installed.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include the narrowest concrete edits needed for the current repository:

- Web adapter source and host/JS glue under the current Web player owner.
- Capability detection and typed activation diagnostics.
- Event conversion from `EditContext` updates into `PlatformTextInputEvent`.
- Range conversion through shared text-index APIs.
- Geometry update production and secure redaction.
- Web fixture traces for:
  - EditContext present activation;
  - EditContext absent unsupported activation;
  - UTF-16 surrogate replacement and deletion;
  - invalid range rejection with no silent clamp;
  - composition/preedit to commit flow;
  - candidate/caret geometry after scroll or transform;
  - secure field redaction;
  - proof that hidden textarea/contenteditable fallback is absent.
- Focused tests and any source gates required to prevent reintroducing fallback
  code.
- `docs/implementation/seq06-4a-web-editcontext-text-input-adapter.md` with
  completion status, validation evidence, and remaining gaps.

## Acceptance Criteria

- Web activation succeeds only when `EditContext` is available and required
  capabilities are satisfied.
- Browser lack of `EditContext` produces a typed unsupported diagnostic and no
  fallback DOM text entry path.
- All normalized text operations carry canonical byte ranges only.
- Native/browser metadata appears only in adapter-local code or fixture metadata,
  never in Sans I/O payloads.
- Invalid ranges reject at the earliest layer with enough context and do not
  partially mutate editor state.
- Geometry revisions are separate from input serials.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, or selected-range-derived anchor.
- The package builds or documents exact environment blockers and leaves no broad
  compatibility shim.

## Tests To Specify And Run

- Focused Web player tests for activation, unsupported activation, composition,
  selection, geometry, and secure redaction.
- Shared presentation/runtime-host tests that the Web adapter relies on, if not
  already present in main.
- A source gate rejecting hidden textarea/contenteditable fallback in this
  adapter path.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- `cargo clippy` for changed crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not add a hidden textarea, contenteditable, or DOM input compatibility
  fallback.
- Do not insert characters from `keydown`.
- Do not put browser object identity or JS-native handles into Sans I/O crates.
- Do not store source units in normalized operations or geometry snapshots.
- Do not widen capabilities by assumption; upgrade only from runtime facts.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Windows TSF, macOS AppKit, Wayland, Android, or iOS implementation.
- Rich document editing beyond current TextField/TextArea/SecureField semantics.
- Replacing the seq06.3 common contract.
