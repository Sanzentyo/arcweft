# Request: seq06.9a UI Compositing Scene Contract Package

## Goal

Design and implement the Arcweft-owned View scene compositing contract needed for
CSS `filter`, `backdrop-filter`, `mask`, `clip-path`, and `mix-blend-mode`
without CPU-rasterizing Takumi output. Takumi must remain the CSS
cascade/layout/stacking source; Arcweft must lower its paint/stacking data into
a wgpu-ready compositing scene graph.

## Why This Split Exists

The current direct Takumi lowering can represent ordinary primitives, opacity,
transform, rounded clips, images, gradients, and placeholder text. The five CSS
features in this request are subtree compositing features: they apply to a
stacking context or backdrop, not to one primitive. Adding them as ad hoc
`ViewPrimitive` variants would make later renderer work incompatible.

## Scope

- Add a compositing graph substrate to the Arcweft View scene contract.
- Preserve existing primitive/direct paint behavior.
- Add Arcweft-owned types such as `ViewPaintNode`, `ViewCompositingGroup`,
  `ViewCompositingEffects`, `ViewFilter`, `ViewFilterList`, `ViewMask`, `ViewClipPath`,
  `ViewBlendMode`, and `ViewIsolation` where the current crate ownership indicates.
- Add inherent behavior on the owned types for bounds/outset and deterministic
  classification, for example `ViewFilter::visual_outset_px()` and
  `ViewFilterList::visual_outset_px()`.
- Update `arcweft-takumi-adapter` property classification so the following are
  no longer treated as generic direct-paint unsupported values:
  `filter`, `backdrop-filter`, `mask-image`, mask size/position fields,
  `clip-path`, and `mix-blend-mode`.
- Add classifications equivalent to `Compositing`, `BackdropCompositing`,
  `MaskCompositing`, `ClipGeometry`, and `Resource` where needed.
- Teach the Takumi lowerer to recover computed style from the Takumi render node
  path, not only from direct paint buckets.
- Keep resource-revision implications explicit for mask images.

## Non-Goals

- Do not implement the wgpu filter/mask/blend shaders in this request.
- Do not CPU-rasterize a full Takumi View surface and upload it as an image.
- Do not put GPU, window, filesystem, or platform dependencies into lower-level
  Sans I/O crates.
- Do not redesign already verified seq06.2 direct paint behavior unless a
  concrete flaw is found.

## Implementation Order To Specify

1. Audit the current `ViewScene`, `ViewSceneContext`, Takumi lowerer, and direct CSS
   support tables.
2. Add the compositing scene types behind clear responsibility modules.
3. Add canonical bounds/effect-outset behavior on owned types.
4. Add Takumi CSS property classifications for the five feature families.
5. Lower Takumi stacking context/computed style into `ViewCompositingGroup`
   nodes while preserving deterministic paint order.
6. Keep unsupported values explicit when a CSS value cannot yet be represented.
7. Add source gates preventing CPU full-surface fallback.

## Tests To Include

- Unit tests for filter list canonicalization and visual outset.
- Tests that Takumi property classification returns compositing-specific classes
  for the five feature families.
- Lowering tests that preserve child order inside compositing groups.
- Resource-revision tests for `mask-image: url(...)`.
- Source gate proving no CPU raster fallback path was introduced.

## Expected Output

Return a zip package containing:

- `overlay/` with Rust implementation and tests;
- `docs/design/seq-06.9a-ui-compositing-scene-contract-design.md`;
- `docs/implementation/seq-06.9a-ui-compositing-scene-contract-2026-06-29.md`;
- request/validation notes;
- an overlay manifest and checksums;
- explicit validation commands for fmt, check, focused tests, clippy, and
  structural audit.

The package must be independently applicable after seq06.2 and the current
seq06.4-06.8 cuts.
