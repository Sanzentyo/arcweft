# Request: Function Stack Non-Helper Callable Allocation Contract

## Sequence Position

This request follows the implemented function-stack cuts and the AWBC
non-suspending closure/apply cut:

- `2026-07-07-seq-07-function-closure-runtime-apply-capture-and-method-sugar.md`
- `2026-07-07-seq-07.5-function-stack-awbc-closure-apply.md`
- `2026-07-07-seq-07.6-relative-runtime-id-boundaries.md`

It splits the remaining "general non-helper/effectful/suspending top-level
callable allocation" item out of the broad function-stack goal.

## Why This Split Is Needed

Arcweft now has executable function values for:

- expression-local closures;
- local aliases to function values;
- helper-backed top-level function values;
- the first narrow non-helper source-local top-level `fn` family: ordinary
  functions with simple identifier parameters and lowerable expression bodies
  that contain no calls, pipes, `await`, `try`, or other effect/suspension-
  capable syntax. Multiple curried `ParamGroup`s in this family lower to
  nested runtime functions, and returned simple closure literals are accepted
  when their bodies recursively satisfy the same no-call/no-suspension
  contract. Direct calls to function-typed parameters are also accepted and
  lower as local `RuntimeExpr::Apply` rather than adapter/top-level calls.
  Function-valued `let` aliases and callback partial calls are tracked inside
  the same accepted body. Closure literals assigned to those function-valued
  local bindings may use destructuring parameter patterns via the shared
  synthetic runtime argument plus `RuntimeExpr::Match` lowering path. Exact
  calls to already-lowered pure helpers inside this accepted family are also
  supported and lower as `RuntimeExpr::PureCall`. Pure value-position `if`,
  `if let`, and `match` expressions inside this accepted family are also
  supported when their child expressions remain inside the same accepted
  subset. Candidate discovery is now a deterministic fixed point, so exact
  calls to already-accepted source-local `fn` candidates are accepted inside
  later source-function candidates and lower as runtime `Apply` expressions
  with named arguments emitted in declaration order;
- partial and curried runtime application for implemented non-suspending paths.

Checked runtime-plan lowering also rejects bare top-level source-function value
references outside those executable families with
`source_function_value_without_runtime_candidate`, rather than lowering them as
ordinary locals.
This structured rejection is also covered for bare `task fn`, `dialogue fn`,
and `stream fn` value references in
`docs/implementation/function-stack-non-helper-callable-kind-rejection-2026-07-09.md`.
Data-last pipe partials through source functions outside those executable
families are rejected with `signature_partial_without_helper`, rather than
lowering incomplete direct runtime calls.
The same data-last partial rejection is covered for unsupported `task fn`,
`dialogue fn`, and `stream fn` values.
Value-position environment, inherent, and trait/impl method references are now
rejected with structured `UnsupportedMethodValueReference` diagnostics, rather
than being confused with ordinary field selection. This keeps receiver binding
semantics explicit until first-class method values are designed.

The remaining callable-allocation gap is not just another lowering case.
Top-level callables may be pure helpers, regular functions, task/dialogue/stream
functions, trait/impl methods, adapter-facing calls, effectful functions,
suspending functions, or declarations that only have a runtime-plan call shape.
Allocating all of them as first-class runtime function values requires a stable
contract for callable identity, captured environment, effects, suspension, AWBC
resume behavior, and save/load policy.

The current implementation correctly rejects unsupported non-helper partial
callables when no accepted representation exists instead of lowering incomplete
adapter calls. This request remains open for the broader callable families
below.

## Required Decisions

1. Define which non-helper declarations may be materialized as runtime
   function values:
   - regular `fn`;
   - `task fn`;
   - `dialogue fn`;
   - `stream fn`;
   - trait/impl methods;
   - adapter or host-call-backed callable declarations.
2. Define the runtime representation for a materialized top-level callable:
   `RuntimeExpr::Function`, a new callable descriptor, a function table handle,
   or an adapter-call thunk.
3. Define whether function values for effectful or suspending callables may be
   created effect-free, and when their effects compose into the caller.
4. Define how callable allocation interacts with curried `ParamGroup`
   boundaries and partial application evidence.
5. Define AWBC lowering for accepted callable values:
   - direct function-table reference;
   - generated wrapper function;
   - host-call adapter thunk;
   - rejection until resumable dynamic apply from 07.5 is designed.
6. Define diagnostics for unsupported callables, including ABI-backed,
   suspending, effectful, async/task/dialogue, trait method, or adapter call
   shapes that are not yet representable.
7. Define save/load behavior for allocated callable values. If runtime
   function values can escape into persistent state, coordinate with the
   persisted-closure contract in 07.5.

## Implementation Order

1. Inventory existing callable families in sema and runtime-plan lowering, and
   classify each as:
   - already executable as a function value;
   - explicitly rejected;
   - adapter-facing only;
   - blocked on resumable AWBC apply;
   - blocked on save/load representation.
2. Done for the first cut: accept the simple source-local `fn` family documented
   in
   `docs/implementation/function-stack-non-helper-source-function-values-2026-07-09.md`.
3. Done for the first cut: reuse existing sema signature partial-call evidence
   for accepted source functions.
4. Done for the first cut: add runtime-plan lowering for the accepted subset,
   preserving existing
   helper-backed behavior.
5. Done for the first cut through existing `RuntimeExpr::Function` /
   `RuntimeExpr::Apply` and non-suspending AWBC `MakeFunction` /
   `ApplyFunction` lowering.
6. Keep structured diagnostics for every rejected family.
7. Done for bare unsupported source `fn` value references: propagate sema
   `FunctionValueReference` evidence into runtime-plan lowering and reject the
   path when no pure helper or accepted source-function candidate exists.
8. Done for unsupported data-last source `fn` partials: record
   `SignaturePartialCall` evidence on authored pipe expressions and reject the
   pipe path when no pure helper or accepted source-function candidate exists.
9. Done for bare task/dialogue/stream function value references: checked
   runtime-plan lowering rejects them as
   `source_function_value_without_runtime_candidate` when no accepted runtime
   function candidate exists.
10. Done for value-position method references: sema rejects environment,
    inherent, and trait/impl method values as
    `sema.typecheck.unsupported_method_value_reference` until receiver-binding
    semantics have a stable callable representation.
11. Done for positional prefix partial calls to unsupported source `fn`
    candidates: checked runtime-plan lowering rejects them as
    `signature_partial_without_helper` when the source function body remains
    outside the accepted runtime-function subset.
12. Done for data-last partial calls to unsupported `task fn`, `dialogue fn`,
    and `stream fn` declarations: checked runtime-plan lowering rejects them as
    `signature_partial_without_helper` rather than lowering incomplete callable
    values.
13. Done for source-local `fn` bodies that exact-call an unaccepted
    source-local function: the wrapper function is not materialized as a
    runtime function-value candidate, and checked runtime-plan lowering rejects
    both its missing-input partial construction and bare value reference with
    the existing structured unsupported callable families.

Remaining implementation-order items are the host/adapter call-bearing,
effectful, or suspending source function bodies, source functions that call
unaccepted source-local candidates as accepted function values,
task/dialogue/stream functions, accepted method values, adapter thunks, and
persistence.

## Tests To Specify

- Done for first cut: bare or partial top-level non-helper `fn` materializes as
  a function value when it is in the simple accepted source-local family.
- Done for first cut: named missing-input partial calls preserve declaration
  argument order by synthesizing a wrapper function.
- Done for first cut: curried `ParamGroup`s in the accepted source-local `fn`
  family lower to nested runtime functions and preserve staged application
  semantics.
- Done for first cut: returned simple closure literals in the accepted
  source-local `fn` family lower to nested runtime functions.
- Done for first cut: direct calls to function-typed parameters in the
  accepted source-local `fn` family lower as local runtime apply.
- Done for first cut: function-valued `let` aliases and partial calls in the
  accepted source-local `fn` family can be invoked later in that body.
- Done for first cut: closure literals bound as local function values in the
  accepted source-local `fn` family may use destructuring parameter patterns
  and still lower through local runtime apply.
- Done for first cut: exact calls to already-lowered pure helpers inside the
  accepted source-local `fn` family lower to `RuntimeExpr::PureCall`, including
  named helper arguments emitted in helper input order.
- Done for first cut: pure value-position `if`, `if let`, and `match`
  expressions inside the accepted source-local `fn` family retain executable
  `RuntimeExpr` control-expression bodies, and value `if let` guards can see
  the pattern locals they guard.
- Done for first cut: exact calls to already-accepted source-local `fn`
  candidates inside the accepted source-local `fn` family lower through the
  materialized runtime function value path, including named argument
  declaration-order preservation.
- Done for current rejection boundary: exact calls to source-local `fn`
  declarations that are not accepted source-function candidates keep the caller
  outside the runtime function-value family, so missing-input partials report
  `signature_partial_without_helper` and bare value references report
  `source_function_value_without_runtime_candidate`.
- Done for current rejection boundary: prefix partial call to a non-helper
  `fn` outside the accepted family reports structured unsupported callable
  family `signature_partial_without_helper`.
- Done for first cut: bare source `fn` value references outside the accepted
  family report unsupported callable family
  `source_function_value_without_runtime_candidate`.
- Done for current rejection boundary: bare `task fn`, `dialogue fn`, and
  `stream fn` value references report unsupported callable family
  `source_function_value_without_runtime_candidate`.
- Done for first cut: data-last pipe partials through source `fn` values
  outside the accepted family report unsupported callable family
  `signature_partial_without_helper`.
- Effectful callable creation does not perform effects; calling the value
  composes effects according to the accepted effect-row contract.
- Suspending callable values are rejected until 07.5 defines resumable dynamic
  apply, or lower to a resumable AWBC call form if that design is accepted.
- Done for current rejection boundary: trait/impl method values keep receiver
  binding semantics explicit by reporting
  `sema.typecheck.unsupported_method_value_reference`; accepting method values
  still needs a callable representation.
- Data-last pipe through a non-helper callable either lowers through the new
  callable representation or reports a structured unsupported diagnostic.
  Unsupported partial source-function data-last pipes are covered, including
  task/dialogue/stream callable kinds; broader effectful/suspending/
  adapter-backed data-last callable values remain under this request.
- Save/export rejects escaped function values unless a versioned persistence
  representation has been designed.

## Constraints

- Do not redesign helper-backed function values, local aliases, expression
  closures, or fixed partial-call behavior already implemented and verified.
- Do not add compatibility shims or fallback adapter calls that bypass sema
  typed evidence.
- Do not make `arcweft-core` depend on syntax, sema, LSP, CLI, OS adapters, or
  filesystem I/O.
- Preserve deterministic argument order and curried call-group boundaries.
- Coordinate with 07.5 for any suspending or persisted callable value.

- Implementation evidence under `docs/implementation/` linking back to this
