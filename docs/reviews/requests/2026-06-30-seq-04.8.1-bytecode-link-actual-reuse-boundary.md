# Seq-04.8.1 Request: Bytecode and Link Actual Reuse Boundary

## Sequence Position

This follows seq04.8 conservative bytecode/link gate support and must wait until
seq04.7 runtime-plan-unit identity is applied and validated.

## Request

Convert the conservative `BytecodeUnitObject` and `LinkPlanObject` gates into
actual persistent reuse for the ready subset.

Do not redesign the seq04.8 conservative gate substrate unless current
implementation evidence shows a concrete flaw. The seq04.8 gates are the
compatibility boundary for this request: this cut replaces sentinel facts with
verified reusable bytecode/link facts only after the missing identities exist.

## Required Inputs

- Applied seq04.7 runtime-plan-unit identity and object schema.
- Canonical AWBC bytecode unit encoding and decode/verify API.
- Stable verifier policy identity.
- Stable codegen policy identity.
- Stable target profile and feature-set identity.
- Stable relocation/import table identity.
- Stable link descriptor identity containing ordered unit identities,
  entrypoints, resource sections, adapter requirements, patch compatibility, and
  product build options.
- Existing seq04.8 gate read/write-through and soft-miss evidence.

## Required Implementation

- Replace conservative bytecode sentinel facts with actual canonical bytecode
  facts and AWBC bytes only after decode/verify round-trip.
- Replace conservative link sentinel facts with an actual stable link descriptor.
- Keep stale/corrupt/mismatched records typed soft misses.
- Prove reused and rebuilt product bytes are identical for covered fixtures.
- Keep signing, release publish, remote upload, and product players out of scope.

## Required Decisions

- Whether `RuntimePlanUnit` is a separate `.awbo` payload required by
  `BytecodeUnitObject`, or whether bytecode can record a stable runtime-plan
  unit digest without storing the runtime-plan payload itself.
- The exact owning type for AWBC/verifier/codegen policy identities.
- The exact owning type for link descriptors and relocation/import table
  identities.
- Whether actual bytecode/link hits remain `HitThenRebuilt` during a narrow
  shadow-validation period or graduate directly to reusable `Hit`.

## Implementation Order

1. Add or verify the stable runtime-plan-unit identity substrate from seq04.7.
2. Replace bytecode sentinel digests with typed AWBC/verifier/codegen/target
   identities and canonical bytecode bytes.
3. Add decode/verify round-trip validation before accepting a cached bytecode
   unit as reusable.
4. Replace link sentinel digests with a typed link descriptor containing ordered
   unit identities, entrypoints, resource sections, adapter requirements, patch
   compatibility, and product build options.
5. Add adapter read-through/write-through wiring that can distinguish
   conservative gates from actual reusable hits.
6. Add product byte equivalence fixtures proving reused and rebuilt outputs are
   identical for the covered cases.

## Tests To Specify

- Deterministic bytecode and link descriptor encoding.
- Bytecode cache hit accepted only after decode/verify round-trip.
- Link-plan cache hit accepted only when all ordered unit/resource identities
  match.
- Stale, corrupt, wrong-policy, wrong-target, wrong-feature-set, and missing
  dependency records become typed soft misses.
- Reused and rebuilt AWFB/AWBC bytes are identical for fixtures.
- `cache explain` reports actual reusable hits separately from conservative
  seq04.8 gates.

## Acceptance Criteria

- Bytecode reuse is based on runtime-plan unit identity plus AWBC/verifier/codegen
  policy, not filenames or timestamps.
- Link-plan reuse is based on stable ordered unit/resource identities, not the
  old whole-build artifact path.
- Reused bytecode/link records produce identical AWFB/AWBC product bytes to a
  source rebuild.
- Cache explain distinguishes actual reusable hits from conservative gates.

## Expected Output

Return a zip design/implementation package in the existing Arcweft overlay
format. It should include:

- design and implementation markdown;
- narrow overlay patches or an applicator script;
- Rust source changes;
- fixtures proving product byte equivalence;
- focused tests and validation commands;
- a remaining-work note if some bytecode/link family remains conservative.
