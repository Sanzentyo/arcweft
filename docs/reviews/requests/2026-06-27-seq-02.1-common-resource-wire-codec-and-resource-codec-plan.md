# Seq-02.1 Common Resource Wire Codec and Product Resource Codec Plan

## Sequence Position

This request splits the first implementation-ready design slice out of
`2026-06-24-seq-02-product-artifact-patch-signing.md`.

Run this before any individual compact product resource section migration. It
must define the common wire primitives that later section-family codecs reuse,
and it must turn the broad "compact product resource section codecs" request
into a prioritized migration plan.

Do not redesign the seq-02 first-cut substrate that is already implemented and
verified unless current repository evidence shows a concrete flaw. In
particular, preserve AWFB v1 section descriptors, raw unknown optional
section-kind preservation, artifact identity, and current product AWBC payload
contracts.

## Why This Split Is Needed

Seq-02 currently has a safe AWFB container and product AWBC path, but broad
resource-section migration is not implementation-ready. The repository still
needs one shared compact resource wire contract before individual section
families can move away from typed JSON without inventing one-off codecs.

This request owns the common product resource wire codec, resource codec
ownership rules, migration order, and cross-family invariants. Later seq-02.x
requests must depend on this contract instead of defining private table,
string, reference, or budget formats.

## Required Decisions

1. Define the common compact resource wire envelope used inside AWFB product
   resource sections, including magic or schema discriminator policy if any,
   section-family versioning, table layout, length encoding, alignment, and
   canonical ordering.
2. Define shared string, public-id, stable-id, enum registry, digest reference,
   source-range, and cross-section reference encodings.
3. Define optional-field, unknown-field, required-field, and forward-version
   behavior for product resource sections.
4. Define decoder budget categories that all section-family codecs must expose:
   byte length, item count, string length, nesting depth, reference count, and
   table fan-out.
5. Decide which common validation belongs in `arcweft-bundle` and which
   semantic validation must remain in compiler/runtime/player adapters.
6. Define inspection/export behavior so JSON can remain a human-facing export
   format without becoming an alternate product codec.
7. Produce the prioritized migration plan for all resource families:
   runtime-types, entrypoints, adapter requirements, content, presentation,
   shader, UI, entity, source maps, locale/text, audio, debug, contracts, and
   graph indexes.
8. Define how migrated and unmigrated resource sections coexist during the
   transition without codec probing or silent fallback.
9. Define golden fixture conventions that later seq-02.x requests must reuse.

## Implementation Order To Specify

1. Inventory current product resource sections and mark each as compact-first,
   JSON-temporary, inspection-only, or future.
2. Freeze the shared wire primitives and budget types.
3. Add common codec tests with tiny fixture sections that are not tied to a
   domain-specific schema.
4. Add source gates that prevent new section-family codecs from defining
   private string/public-id/reference table formats.
5. Update implementation docs with the seq-02.x migration matrix and explicit
   non-goals.

## Tests To Specify

- deterministic bytes for common table ordering;
- duplicate string/public-id table entry handling;
- unknown optional field skip and unknown required field rejection;
- budget failures for byte, count, string, depth, and reference limits;
- canonical digest stability for equivalent logical resources;
- inspection/export round-trip from compact bytes to JSON view and back through
  the owning typed API, not through product JSON fallback;
- source gates for no ad hoc resource wire table formats in later codecs.

## Constraints

- Keep `arcweft-bundle` Sans I/O.
- Do not add filesystem, network, clocks, signing keys, or cache access to data
  format crates.
- Do not introduce codec probing for product `.awfb` sections.
- Do not preserve typed JSON as a product resource fallback once a section
  family is migrated.
- Prefer owned typed APIs and codec contexts over free-standing
  `{source}_to_{target}` helpers.
- Preserve deterministic content roots, artifact identity, and patch diffs.

## Non-Goals

- Implementing all section-family codecs in this slice.
- Redesigning AWBC product executable encoding.
- Designing patch v2, AWFR release archives, external payload carriers, or
  signing policy beyond the resource identity fields they must consume.
- Applying generated seq-02 overlay code directly to production.

## Expected Output

Produce a markdown design package that includes:

- current repository evidence and revision/change inspected;
- common resource wire schema;
- shared decoder budget model;
- crate/module ownership map;
- migration matrix for every product resource section family;
- inspection/export policy;
- implementation cuts and test matrix;
- explicit dependencies for seq-02.2 through seq-02.8.
