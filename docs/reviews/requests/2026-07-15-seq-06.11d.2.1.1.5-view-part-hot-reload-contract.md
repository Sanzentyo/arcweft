# Design request: seq-06.11d.2.1.1.5 View-part hot-reload contract

- Date: 2026-07-15
- Kind: independently throwable final-design correction
- Production changes: prohibited
- Prerequisites: final d.2.1.1.3 and d.2.1.1.4 contracts; consume landed d.4.2

## Goal

Define transactional accepted-program replacement, semantic fingerprints,
mounted occurrence reconciliation, and targeted invalidation for exported View
parts. The current runtime has no final replacement transaction. Compilation
success alone cannot choose frame atomicity, revision ownership, rollback, or
cache invalidation.

## Required decisions

1. Define owners and exact bytes for local-inventory and export-interface
   fingerprints, plus monotonic program/application revisions and overflow.
2. Define the accepted-program replacement transaction from candidate
   validation through mount reconciliation and frame publication.
3. Freeze rollback for parser, HIR, sema, compiler, codec, conversion,
   reconciliation, stale-generation, shutdown, and revision-overflow failure.
4. Define add/remove export, public rename, local rename, target move,
   unexported local edit, owner removal, equal semantic replacement, and
   provenance-only edit outcomes.
5. Define exact invalidation edges for owner programs, direct callers,
   contextual Style bindings, mounted local/public facts, inherited descendants,
   computed style, trace/index cursors, and source/LSP metadata.
6. Define repeat-key/branch/nested-unmount/multi-mount reconciliation and prove
   old/new public names cannot appear in one completed frame.
7. Define replacement concurrent with frame preparation and deterministic stale
   prepared-frame rejection.
8. Reuse any d.4.2 environment revision/evidence domain without merging it into
   View export fingerprints.

## Required tests to specify

- every edit family above with exact changed and unchanged caches/identities;
- invalid candidate leaves accepted program, revisions, mounts, caches, trace,
  and published frame byte-for-byte unchanged;
- public-name swap is frame-atomic;
- branch/repeat/nested removal prunes exactly stale occurrence facts;
- unrelated owners, call edges, sheets, tokens, renderer resources, and mounts
  retain identity/cache state;
- equal/provenance-only replacements follow the chosen no-churn policy; and
- stale frame, concurrent update, shutdown, and overflow are deterministic.

## Constraints and expected output

No runtime export mutation API, duplicate revision owner, global cache flush,
compatibility transaction, or source-text lookup is permitted. Do not redesign
the already-final source/link, runtime identity, contextual tooling, Style
cascade, or d.4.2 contracts. Return a decision-complete design package with
state machine, ownership/invalidation graph, exact APIs, rollback table,
implementation cuts, tests, verification, and no open result-changing question.
