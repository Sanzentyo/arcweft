# Design request: seq-06.11d.4.3 native container Style-condition and invalidation contract

- Date: 2026-07-14
- Kind: independently throwable design request
- Output language: English

## Sequence position and dependency boundary

This container-adaptive cut follows the implemented seq-06.11d.1 native typed
Style, d.2 sheet-owned product, and d.3 single resolver. It follows logical-axis
work because container sizes require a typed axis snapshot, but this request is
self-contained.

The minimum axis dependency is stated here in full:

- every mounted query container has a typed axis snapshot mapping measured
  bounds to nonnegative inline and block sizes;
- queries use the container snapshot, never the subject axis or RichText mode;
- the snapshot has a stable revision and deterministic native/headless default;
- changing it invalidates container facts derived from the previous mapping.

Before that contract is implemented, authoring, product, graph, codec,
diagnostic, tooling, and non-layout work may proceed, but runtime matching must
not guess that inline means x. Record the axis work as a runtime prerequisite.

Environment conditions are not a dependency. If both feature families appear
on one rule, they are conjoined activation gates under the existing native
cascade, but each keeps its own fact and revision owner.

The output must be a final implementation contract, not an exploration.

## Problem and background

Native Style represents typed container predicates, but the resolver rejects
them because runtime facts are absent. Authoring, ancestor selection, lowering,
and threshold-scoped invalidation are also undefined.

Naive style/layout iteration can oscillate or let a subject determine the size
it queries. The contract needs explicit containment, measurement, dependencies,
threshold indexing, work bounds, and deterministic invalidation.

## Confirmed substrate that must be preserved

- Style has one native typed syntax-to-`ViewStyleProgram`-to-resolver path. CSS,
  Takumi, raw stylesheets, and browser fallback are removed.
- `ViewContainerAxis` already identifies inline-size and block-size facts.
  `ViewContainerPredicate` already owns a typed axis, comparison, and fixed-
  point length threshold, and `ViewStylePredicate` can carry it.
- The resolver reports `ContainerFactsUnavailable`; container revision input,
  trace rejection, cache/work budgets, and computed invalidation already exist.
- Runtime nodes have stable mounted keys, ancestry, View-boundary facts, ordered
  Style applications, and retained geometry.
- The resolver preserves private nested-View boundaries and only exposes a
  direct child root or explicitly exported part to a caller Style scope.
- Typed logical size properties exist, but their final physical mapping requires
  the minimum axis contract described above.
- Product codecs are deterministic, validate typed Style records, and do not
  reopen `.arcw` source. Runtime/data layers remain Sans I/O where required.

Supplying facts and an owned dependency/invalidation graph is the missing
feature, not grounds for a second resolver or View evaluator.

## Required decisions

1. Define one canonical `.arcw` declaration for an explicit query container.
   Decide whether it is a typed Style property, a View modifier, or View
   metadata; include exact formatter output and reject equivalent alternate
   spellings.
2. Define the first-cut container capability: inline-size only or both inline
   and block size, and whether size containment is mandatory. State how the
   declaration prevents descendant query results from feeding the measured
   dimension.
3. Define one canonical condition grammar for comparison against a container
   size. Specify legal operators, threshold units/ranges, grouping, nesting,
   and conjunction with element/state/environment predicates.
4. Choose nearest-ancestor-only or typed named selection. For names, define
   identity, namespace, View visibility, duplicates, and mounted occurrences;
   otherwise reject them. Define ancestry/self-query and nested-View/exported-
   part boundaries without exposing private containers.
7. Define the measurement snapshot: exact layout phase, border/content/padding
   box, transforms excluded or included, clipping/scrollbars, fixed-point
   rounding, zero/unlaid-out behavior, and the container-owned logical-axis
   mapping.
8. Define style/layout scheduling that is guaranteed to terminate. Specify the
   pre-query base style, containment invariant, measurement pass, predicate
   evaluation, recomputation pass, and whether any bounded second pass is
   legal. Do not leave "iterate until stable" as an algorithm.
9. Define occurrence/threshold dependency edges for repeats, branches, nested
   containers, mount/unmount, and hot reload.
10. Define threshold indexing and crossing semantics for `==`, `!=`, `<`, `<=`,
    `>`, and `>=`, including exact boundary equality and rounding. Specify when
    a size change that does not change any predicate truth value avoids Style
    recomputation.
11. Define typed facts: selected occurrence, measured values, fact revision,
    resolver input, and bounded cache identity. Define exact invalidation for
    fact/computed/inherited/layout/paint/hit/focus/scroll changes; scene-wide
    invalidation is not an acceptable default.
13. Define work and memory budgets for number of containers, dependency edges,
    thresholds, affected nodes, re-evaluations per frame, and cache entries.
    State the typed failure/degradation policy when a budget is exceeded.
14. Define AST, HIR, sema, compiler, product, codec, runtime, and trace types
    with exact provenance; no source strings or general expressions survive.
15. Define specificity and cascade behavior. Container conditions are activation
    gates unless the design explicitly proves another rule; do not accidentally
    increase selector specificity merely by adding a predicate record.
16. Define codec/merge validation for declarations, names, axes, comparisons,
    thresholds, references, ranges, and metadata. Measurements stay runtime-only.
17. Define diagnostics, trace/explain, formatter, and LSP behavior for malformed,
    unsupported, unknown, self-query, unlaid-out, boundary, cycle, and budget
    cases, including name definition/references/rename and incremental edits.

## Constraints

- Native-only: no CSS queries/source, Takumi, DOM/CSSOM measurement, browser
  fallback, or hidden evaluator.
- Preserve the implemented d.1-d.3 sheet ownership, typed properties/values,
  selector/cascade order, resolver, View boundaries, and runtime mounting absent
  a concrete blocking defect.
- Only explicit query containers are eligible. Do not infer containment from a
  layout node, element kind, overflow, size, or browser convention.
- A query must not depend on the styled element's own post-query size, and the
  scheduling contract must be finite by construction.
- Use the container's typed logical-axis snapshot; never infer inline/block from
  x/y, locale, or RichText writing mode.
- Keep identities typed and mounted-occurrence aware. Do not resolve named
  containers by suffix matching or unowned strings.
- Runtime-derived geometry stays runtime data. Canonical product/codecs carry
  declarations and predicates, not cached measurements.
- The contract is unreleased: no aliases, dual parsers, deprecated fields,
  migration readers, or legacy branches.
- Do not add source gates. Test typed graphs, codecs, runtime truth values,
  invalidation, and observable output.
- Preserve fixed-point determinism, resource budgets, source provenance, Sans-
  I/O crate boundaries, and current dependency direction.

## Non-goals

- CSS style/scroll-state, arbitrary boolean/range, viewport/media, or device
  feature queries.
- Implicit containers, general layout containment, grid implementation, or a
  replacement layout engine.
- Querying transformed/rendered pixel bounds, glyph boxes, or a styled node's
  own post-query result.
- Cross-boundary inspection of private nested-View containers.
- Browser parity/oracles or a global unbounded style/layout fixed-point solver.
- Environment-condition authoring beyond the minimal conjunction rule stated
  in this file.

## Required implementation order

1. Freeze declaration, selection, axes, containment, condition grammar, and
   formatter form.
2. Specify the typed axis snapshot dependency and exhaustive measurement
   semantics without implementing an x/y fallback.
3. Specify AST/HIR/sema types, name resolution if any, source ranges, and
   diagnostics.
4. Specify compiler/product/codec types, canonical validation, merge, and
   tamper behavior.
5. Specify the finite style-layout schedule and prove why descendant query
   results cannot change the measured dimension in an unbounded loop.
6. Build the mounted container/threshold dependency graph and budget model.
7. Feed typed facts/revisions into the existing resolver and implement exact-
   subtree invalidation and trace behavior.
8. Add formatter/LSP functionality and incremental edit invalidation.
9. Validate source, semantic, codec, graph, threshold, boundary, layout, and
   end-to-end behavior before enabling the feature.

## Required test specification

### Parser, HIR, sema, diagnostics, and tooling

- Canonical declarations and conditions parse with exact ranges, lower to typed
  HIR/check records, and format idempotently.
- Unknown/duplicate names, bad axes/operators/units/ranges, unsupported grouping,
  self-query, placement, and CSS-like syntax produce structured diagnostics.
- Completion is context/type aware; named-container definition/references/rename
  obey ownership and View-boundary rules; edits remove stale dependency facts.

### Measurement and threshold truth

- Exhaustive comparison tests cover below, exactly equal, and above every
  threshold with fixed-point rounding at the selected box edge.
- Inline/block values use the container's axis snapshot in horizontal LTR/RTL
  and every supported vertical context; the subject's axis and RichText mode do
  not affect the result.
- Unlaid-out, zero-size, clipped, scrolled, transformed, and removed containers
  follow the selected measurement policy exactly.

### Dependency graph and invalidation

- Nearest/named selection resolves deterministically for nested containers,
  repeated branches, nested calls, mount/unmount, and hot reload.
- A threshold crossing invalidates exactly the dependent scope/subtree plus
  inherited descendants whose computed winners change.
- Non-crossing size changes reuse unaffected entries without layout/style churn.
- Axis revision changes rebuild only affected container facts and dependencies.
- Budget exhaustion produces the selected typed error/degradation and never an
  unbounded traversal.

### Termination and feedback safety

- Adversarial rules that would oscillate under naive iteration terminate under
  the specified containment/scheduling contract with deterministic output or a
  typed rejection.
- A node cannot query its own post-query size, directly or through a name alias.
- Descendant intrinsic changes cannot feed a contained measured dimension in a
  way that causes repeated style/layout passes.

### Boundaries and cascade

- Conditions preserve private View ancestry and existing root/export visibility.
- Container activation has the selected zero/nonzero specificity behavior and
  combines deterministically with state and environment gates.
- Inheritance, applications, tokens, and source order remain owned by the
  existing resolver.

### Codec and end-to-end behavior

- Canonical codecs round-trip declarations, names, axes, comparisons, thresholds,
  and provenance deterministically.
- Unknown tags, invalid pairs/ranges, malformed IDs, dangling names,
  cross-section mismatches, and oversized inventories fail within budgets.
- Native and headless runs produce identical computed styles and geometry on
  both sides of thresholds; render, hit-test, focus, and scroll geometry agree.
- Runtime measurements are absent from the authored bundle and are rebuilt from
  mounted geometry.

No test may inspect repository source spellings or file placement as correctness
evidence.

## Expected output

Deliver a self-contained design package containing:

- grammar/formatter and eligibility/selection/containment/measurement tables;
- exact pipeline, runtime-fact, and dependency-graph types;
- finite scheduling proof plus threshold/cache/revision/budget/invalidation rules;
- codec/tamper, diagnostics, trace, formatter, and LSP contracts;
- file plan, tests/validation, non-goals, and the axis prerequisite.

## Acceptance criteria

The design is implementation-ready only when an explicit container can be
authored and resolved without strings, every query uses a precisely measured
container-owned logical size, selection and nested boundaries are unambiguous,
the scheduling algorithm terminates by construction, threshold changes produce
bounded exact invalidation, and codecs/tooling/diagnostics are fully specified.
It must preserve the native-only single-resolver d.1-d.3 substrate, add no CSS or
Takumi path, compatibility machinery, unbounded iteration, or source gate, and
must be usable without consulting any other request.
