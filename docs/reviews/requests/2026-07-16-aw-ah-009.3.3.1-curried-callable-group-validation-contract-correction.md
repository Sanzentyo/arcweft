# AW-AH-009.3.3.1 — Curried callable group-validation contract correction

## Sequence position

This is a design-correction branch from AW-AH-009.3.3. It follows the Cut 1
typed identity substrate and must be decided before the shared resolver begins
constructing curried candidates. It does not block unrelated catalog
publication or family-schema work.

## Why this split is required

The current final contract fixes this exact public API:

```rust
pub fn CurriedCallableId::try_new(
    base: CallableCandidateId,
    next_group: CallableGroupIndex,
) -> Result<CurriedCallableId, CallableIdentityError>;
```

The same contract prose and test matrix require that constructor to reject a
`next_group` which does not exist in the base callable schema. A project or
environment candidate ID does not own or provide its schema, so that condition
cannot be evaluated from the two fixed inputs. Adding an implicit global
catalog lookup would make identity construction world-dependent and would
violate the accepted-world borrowing boundary.

Cut 1 therefore implements only context-free identity invariants in this
constructor: group zero is not a next group, and `Curried`/`DataLast` wrappers
cannot be recursively wrapped. Schema existence must be checked before a
successful resolver product is published.

## Required decisions

Choose and specify one ownership model:

1. **Recommended — context-free ID plus resolver validation.** Keep the exact
   two-argument constructor. Move `next_group` existence and one-over rejection
   to the shared resolver or a schema-owning resolved-callable constructor.
   `ResolvedCallable::try_new` (or a dedicated resolver context method) must
   reject a `CallableInstantiation::Curried` whose group is absent.
2. Add `&CallableSignatureSchema` to `CurriedCallableId::try_new`. This gives
   the constructor enough evidence but changes the exact public API and makes
   an identity type depend on catalog policy.
3. Introduce a separate validated curried resolver product while leaving the
   ID structurally constructible. This is acceptable only if it does not create
   two competing successful curried-call representations.

The design must explicitly state whether `CallableIdentityError::MissingGroup`
remains an identity-construction error or moves to `ResolveCallError`, and must
fix the affected public API/error mapping accordingly.

## Contract and test corrections

If the recommended model is selected:

- revise `FINAL_CONTRACT.md` so `CurriedCallableId::try_new` promises only the
  context-free group-zero and wrapper-growth checks;
- revise the paragraph that currently claims the constructor validates a base
  schema group;
- replace the Cut 1 test-matrix row
  `curried_id_requires_existing_group` with constructor tests for group zero
  and recursive wrappers;
- add shared-resolver negative tests for an absent/one-over `next_group` on
  project, standard, and adapter candidates;
- add a positive multi-group resolution test proving the accepted group is the
  exact schema group published in the resolved product;
- verify corrupt catalogs cannot bypass the same check.

If another model is selected, provide the exact replacement Rust signatures,
error variants/codes, and migration order for Cut 1 callers and later resolver
cuts.

## Implementation order

1. Correct the final contract and test matrix.
2. Preserve the already implemented context-free Cut 1 identity substrate
   unless the selected design demonstrates a concrete safety flaw.
3. Add the schema-aware check at the one successful shared-resolver boundary.
4. Add direct typed positive, one-over, and corrupt-world tests.
5. Only then delete any temporary duplicate check during old-resolver removal.

## Constraints

- Do not add a global catalog lookup or thread-local accepted world to an ID
  constructor.
- Do not store a schema, catalog pointer, world lease, or formatted signature
  inside `CurriedCallableId`.
- Do not add a compatibility constructor, alias, dual reader, or deprecated
  spelling.
- Do not create a second successful resolver or bypass AW-AH-009.3.2 accepted
  request/world validation.
- Do not redesign already implemented and verified Cut 1 substrate unless
  current implementation evidence shows a concrete flaw.
- Tests must use typed constructors and resolver outcomes; source gates are
  prohibited.

## Expected output

Return a self-contained final contract correction containing:

- the selected ownership decision and rejected alternatives;
- exact Rust APIs and typed errors/codes;
- corrected invariant prose;
- corrected Cut 1 and shared-resolver test-matrix rows;
- implementation order and deletion rule;
- confirmation that no second resolver or compatibility path is introduced.
