# Seq-02.6 AWFR Release Archive and External Payload Carrier Redesign

## Sequence Position

This request follows seq-02.5 because AWFR archives and external payload
carriers must consume stable artifact identity, patch v2 target identity, and
section-family descriptor rules.

It may be designed in parallel with seq-02.7 signing policy, but neither should
finalize release trust behavior without the other.

## Why This Split Is Needed

Seq-02 first cut preserves embedded and external descriptors, but it does not
define product-grade external payload carriers, AWFR release archives, release
manifest mutation, fetch adapter behavior, or publication policy. Those
contracts are too large to hide inside patch materialization.

This request designs how release archives bind AWFB artifacts, patch artifacts,
external payload bytes, mirrors, cache entries, and publication metadata.

## Required Decisions

1. Define the AWFR release archive format and its relationship to AWFB bundles,
   patch artifacts, external payloads, release manifests, and signatures.
2. Define the external payload carrier model, including descriptor id, media
   type, decoded size, compressed size, digest, content root binding, mirror
   list, cache key, and required/optional residency.
3. Define when materialization requires payload bytes and when metadata-only
   descriptor updates are allowed.
4. Define release manifest rewrite rules when patch materialization changes,
   removes, or adds external sections.
5. Define fetch adapter boundaries for local files, HTTP(S), cache, offline
   inspection, and test fixtures.
6. Define cache validation rules for digest, content root, size, compression,
   bundle kind, artifact identity, and key epoch fields consumed by signing
   policy.
7. Define error and rollback behavior when payload fetch, cache validation, or
   release manifest rewrite fails.
8. Define CLI and project-loader responsibilities for publish, fetch, inspect,
   verify, and local-dev flows.

## Implementation Order To Specify

1. Freeze AWFR archive and external payload descriptor schemas.
2. Add Sans I/O encode/decode and validation types to the appropriate data
   format crate.
3. Add project-loader cache/fetch adapter implementation against the typed
   descriptors.
4. Add CLI inspect/fetch/publish smoke commands.
5. Add patch materialization integration for external payload requirements.
6. Add release manifest rewrite and validation tests.
7. Add offline inspection behavior that does not require payload bytes unless
   policy demands them.

## Tests To Specify

- deterministic AWFR/release manifest bytes;
- descriptor digest/size/content-root validation;
- local file and cache fetch success;
- missing payload and digest mismatch failures;
- metadata-only materialization acceptance where policy allows it;
- release manifest rewrite after external section add/replace/remove;
- rollback after fetch or validation failure;
- offline inspection of descriptor metadata;
- CLI smoke for inspect/fetch/verify/publish paths;
- source gates that keep network/filesystem out of Sans I/O crates.

## Constraints

- Keep data-format crates Sans I/O.
- Keep fetch, cache, filesystem, network, clock, and mirror policy in adapters.
- Do not weaken signature policy to make external payload fetching convenient.
- Do not make embedded payloads mandatory for all product release flows.
- Preserve deterministic artifact identity and content roots.

## Non-Goals

- Patch v2 compatibility derivation beyond consuming patch v2 identity fields.
- Signing-policy redesign beyond exposing typed fields needed by seq-02.7.
- Shader/View/audio/content codec schema design.
- Seq3 live update transport.

## Expected Output

Produce a design or implementation package with:

- AWFR archive schema;
- external payload carrier schema;
- release manifest rewrite rules;
- fetch/cache adapter ownership;
- materialization integration points;
- test matrix and CLI smoke commands;
- explicit dependency notes for signing policy.
