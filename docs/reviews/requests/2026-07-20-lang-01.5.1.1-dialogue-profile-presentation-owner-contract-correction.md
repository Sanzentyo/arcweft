## Problem

The accepted top-level reduction removes the author-facing
`dialogue defaults` declaration. The retained dialogue model is
`CharacterDialogue`, projected into an authored View and the common prepared
text/rendering path. Dialogue presentation policy may be selected by a typed
launch profile, but source `dialogue defaults` must not survive as a hidden
compatibility owner.

The returned Lang-01.5.1 single-manifest decoder contract nevertheless defines:

```toml
[profiles.dev.dialogue]
defaults = "@dialogue.mobile"
```

and requires that value to be an `EntityIdRef` in the `@dialogue.*` family.
The same contract orders deletion of the source `dialogue defaults`
declaration. It does not define any replacement declaration, manifest record,
style resource, View resource, or registry entry that owns
`@dialogue.mobile`.

That leaves a reference with no final declaration or catalog owner. Merely
retaining `DialogueDefaultsItem` until later would create the forbidden
dual/compatibility path and would contradict the final top-level vocabulary.
Silently treating the string as a Style or View ID would be a wrong-family,
stringly conversion.

## Established substrate that must be preserved

Reconfirm current production and cite exact revisions, but do not redesign the
following without a concrete defect:

1. one span-preserving schema-1 manifest decode and revision-bound
   `ManifestSourceMap`;
2. immutable accepted topology publication and the no-dual-reader migration;
3. `CharacterDialogue` as the first-class dialogue runtime value;
4. Character nominal identity, registration, alias diagnostics, source index,
   and callable resolution;
5. authored View identity, View catalog/mount identity, dialogue parameter
   projection, exported parts, and Style patching;
6. the unified
   `ResolvedTextDocument -> TextLayout -> PreparedTextBatch -> ViewPrimitive`
   rendering/capture path;
7. dialogue runtime ownership of reveal, stage, advance, and interaction state;
8. typed `res` declarations for configured resources and the separate retained
   global identity families;
9. manifest ownership of launch/profile selection; and
10. direct removal of source `dialogue defaults`, with ordinary current-grammar
    rejection and no spelling-specific diagnostic, CST/AST/HIR node, alias, or
    compatibility reader.

The correction must coexist with the pending AW-AH-009.4.1.1
dialogue-View Character projection correction and AW-AH-009.4.1.2 TTS provider
contract. It must not create a second Character, View, Style, text, or voice
registry.

## Required decisions

### 1. Final owner of dialogue presentation defaults

Choose exactly one typed owner for every current defaults concern, including:

- selected dialogue View;
- typography and rich-text base Style;
- dialogue window/layout presentation configuration;
- inline interpolation failure policy;
- voice/TTS presentation defaults, if any;
- reveal/read-state presentation policy; and
- profile-specific overrides.

Separate data that belongs to an authored `view`, typed `res`, Character
metadata, or the launch profile itself. Do not preserve a monolithic
`DialogueDefaultsItem` under another name merely to keep the old model alive.

If a compact typed manifest record is the correct owner for some policy,
specify its exact fields and types. If the manifest selects existing authored
View/Style/resource identities, specify their exact nominal reference types and
catalog validation. Do not use a generic `EntityIdRef` plus string-prefix
checks where an owned `ViewId`, Style ID, resource reference, or policy enum is
available or should be introduced.

### 2. Final manifest schema

Replace or remove:

```text
profiles.<id>.dialogue.defaults: Option<EntityIdRef(@dialogue.*)
```

with one exact schema. Define:

- TOML field names and nesting;
- required versus optional fields;
- defaults and inheritance;
- exact typed Rust shapes and owning crates;
- source-map paths and ranges;
- unknown, missing, duplicate, malformed, and wrong-family diagnostics;
- profile overlay/replacement semantics;
- canonical serialization, if serialization remains public; and
- whether dialogue policy is copied into the resolved launch profile or
  retained by immutable shared ownership.

The result must not add a second manifest decoder, a detached source reader, a
raw TOML value, or a text-slicing path.

### 3. Selection, cascade, and precedence

Freeze the precedence across:

- standard engine fallback;
- project launch profile;
- selected authored dialogue View;
- Character-local presentation metadata;
- line-local or `CharacterDialogue` instance overrides; and
- explicit View Style patches.

Define which layers are permitted to override which fields and whether
selection is replacement or field-wise composition. Preserve deterministic
ordering and make missing referenced objects fail at the earliest owner that
has the accepted catalog.

Do not reintroduce a global source declaration only to host the cascade.

### 4. Compiler, runtime, and tooling data flow

Specify the complete typed path from the accepted manifest through:

- project loader and contained project;
- compiler/project index;
- runtime-plan dialogue input;
- View catalog and dialogue View projection;
- Character presentation and TTS integration;
- CLI run/serve/bundle/watch;
- LSP hover/completion/go-to-definition/source mapping;
- Agent observation and MCP; and
- save/reload and overlay candidate publication.

Identify the exact catalog that validates every referenced View, Style, or
resource. Define the accepted revision identity used to prevent a manifest
selection from being paired with a stale source/catalog revision.

### 5. Direct migration and deletion

Provide one ordered migration that:

1. introduces the final typed dialogue-profile fields;
2. migrates all maintained manifests and in-memory consumers;
3. migrates runtime-plan, CLI, LSP, Agent/MCP, samples, and tests;
4. removes `@dialogue.*` selection if no final `@dialogue` owner is selected;
5. deletes `DialogueDefaultsItem`, its parser/CST/AST/HIR/sema/lowering paths,
   selection helpers, examples, and source-owned defaults registry;
6. deletes obsolete DTOs and source-map paths; and
7. publishes the single manifest decoder only after the whole transaction
   compiles and tests.

No deprecated field, alias, dual reader, wrapper facade, migration shim,
removed-spelling recognizer, or compatibility diagnostic may remain.

## Constraints

- Do not restore source `dialogue defaults`, `.say`, speaker-line sugar, CSS,
  Takumi, source `content`, `source`, `extern mod`, or another removed
  top-level family.
- Do not redesign `CharacterDialogue`, accepted Character identity, View
  identity/catalog/mount, prepared text, typed Style, the sole manifest decoder,
  or accepted topology identity without a cited production defect.
- Do not make dialogue lifecycle state a Style/View field; reveal, stage,
  advance, and input-wait state remain runtime-owned.
- Do not make every text producer a View merely for uniformity.
- Do not use raw strings, basename conversion, source reparsing, source gates,
  local extension traits, or free-standing endpoint conversion helpers.
- Do not create a second public selector whose only purpose is to preserve
  `@dialogue.*`.
