# Request 06.4c: macOS NSTextInputClient Text Input Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the macOS platform adapter package and should not redesign
the shared capability, range, batch/serial, or geometry substrate unless current
implementation evidence proves a concrete flaw.

This request can be run independently from the Web, Windows, Wayland, Android,
and iOS adapter requests. Apple API evidence is a first-class gate for this
package because the integration review identified unresolved range, callback,
and coordinate questions.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for a macOS
AppKit `NSTextInputClient` adapter for Arcweft text input.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints.
- Apple SDK, header, and DocC evidence for `NSTextInputClient`,
  `NSTextInputContext`, `NSRange`, marked text, selected ranges, first-rect
  coordinate conventions, and callback ordering.

## Platform Scope

Implement the macOS adapter inside the native desktop boundary, expected to
include `crates/arcweft-desktop-native` and any existing macOS host module. If
the current checkout has a different macOS owner, document it in
`SOURCE_INVENTORY.md`.

The adapter must:

- pin SDK/header/DocC evidence before upgrading any HostDependent or Limited
  capability;
- keep Objective-C objects, AppKit view/input context objects, attributed
  strings, `NSRange`, native positions, and native object identity adapter-local;
- resolve native ranges through an adapter-local resolver and `TextIndexSnapshot`
  before emitting canonical byte ranges;
- treat range-like APIs as UTF-16/NSString-like unless pinned evidence proves a
  different rule;
- map one `NSTextInputClient` callback to one Arcweft serial unless a callback
  atomically contains marked text plus replacement/selection normalization;
- use batches only for a native atomic callback group;
- consume Arcweft screen-space geometry and convert to AppKit coordinates in the
  adapter;
- keep reconversion and composition-segment capability HostDependent until
  platform evidence plus fixture coverage proves an upgrade;
- omit all character bounds for secure fields and report them as
  `SecureRedacted`, not plain platform unsupported.

## Required Decisions

1. The macOS crate/module ownership, `cfg(target_os = "macos")` gating, and
   binding approach.
2. The exact SDK/header evidence for range units, invalid range behavior,
   callback ordering, coordinate conventions, and stale range behavior.
3. The owner object that implements or bridges `NSTextInputClient`.
4. The native range resolver and conversion path for `NSRange`,
   `replacementRange`, `selectedRange`, marked ranges, and invalid/`NSNotFound`
   cases.
5. The callback boundary that creates one Arcweft serial.
6. The mapping of marked text, committed insert, unmark/cancel, selection, and
   replacement into Arcweft operations and capabilities.
7. The geometry conversion from Arcweft screen rectangles into AppKit first rect,
   caret, selection, and candidate placement queries.
8. The secure-field policy for surrounding text, marked text metadata, geometry,
   diagnostics, Agent observe, replay, and capture output.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include:

- macOS-only adapter modules and any feature/Cargo dependency edits.
- SDK/header evidence fixtures or notes sufficient to unblock implementation.
- Typed capability detection and activation diagnostics.
- `NSTextInputClient` event conversion into `PlatformTextInputEvent`.
- Range conversion through shared text-index APIs.
- Geometry adapter code for AppKit coordinate conversion and availability.
- macOS fixture traces for:
  - marked text update;
  - committed insert;
  - unmark/cancel;
  - `replacementRange` and `selectedRange` behavior;
  - invalid range or `NSNotFound` handling;
  - delayed callback after focus generation change;
  - first-rect coordinate convention;
  - secure field redaction.
- Cross-platform compile gates so non-macOS hosts do not require AppKit.
- `docs/implementation/seq06-4c-macos-nstextinputclient-text-input-adapter.md`.

## Acceptance Criteria

- SDK/header evidence answers the AppKit range-unit, invalid-range,
  callback-ordering, and coordinate-convention questions.
- macOS activation uses typed capability facts and diagnostics.
- Native AppKit metadata remains adapter-local or fixture-local only.
- All normalized text operations carry canonical byte ranges only.
- Invalid native ranges reject without silent clamp.
- One callback or proven native atomic callback group maps to one Arcweft serial.
- Geometry revisions are separate from input serials.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, selected-range-derived anchor, or native object
  identity.

## Tests To Specify And Run

- Focused macOS adapter tests for range conversion, marked text, commit,
  unmark/cancel, replacement ranges, callback grouping, geometry, focus
  generation, and secure redaction.
- Non-macOS compile/source-gate tests proving macOS code is correctly gated.
- Shared presentation/runtime-host tests that the macOS adapter relies on, if
  not already present in main.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- `cargo clippy` for changed crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not put Objective-C objects, AppKit object identity, `NSRange`, or native
  positions in Sans I/O payloads.
- Do not upgrade HostDependent capabilities by assumption.
- Do not store source units in normalized operations or geometry snapshots.
- Do not add a compatibility shim around the common text-input contract.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Web, Windows, Wayland, Android, or iOS implementation.
- UIKit/iOS implementation; that is seq06.4f.
- Replacing the seq06.3 common contract.
