## Split reason and concrete source evidence

The parent requires `RuntimeVariantIdentity::Nominal` and nominal
`AwbcVariantIdentity` to retain layout. It leaves Character/base-environment
owners described as existing cases, without a complete layout-producing
contract for them or the external Dialogue/data producers. Making the field
mandatory exposes mutually constraining schema and producer decisions:

1. Project projection already owns `RuntimeResolvedNominal::layout` and
   `RuntimeProjectNominalProjection::layout`. Those existing values can be
   propagated through normalized owners, variant domains, checked types,
   values, AWBC and resource fingerprints. They must not be independently
   re-derived at a consumer.
2. `RuntimeResolvedVariant::{character,builtin_closed}` receive semantic and
   nominal identity plus complete normalized cases, but the accepted baseline
   receives no layout or canonical graph. Character cases are payload-free.
   Base-environment cases are not: `StandardDropPolicyCase::Stop` declares the
   record payload `fade: TypeKind::Duration` in `lang-sema/src/env/base.rs`.
   The core schema algebra, including the parent's five additions, has no
   Duration schema. The existing checked/runtime-plan vocabularies admit it.
   The public environment enum-payload input also requires a complete policy
   for all its admitted payload types, rather than a fix for DropPolicy alone.
3. `DialogueRuntimeVariantOwner::identity` freezes owner identities for Voice,
   InlineFailure, InlineFallback and FallbackStyle. Voice owns String data;
   the failure/fallback policies reference one another. Crucially,
   `encode_fallback_style` serializes `Apply` as the sequence of
   `style.typed().value()` values. Its current owner has no complete active
   descriptor for those external nominal values. A fixed label digest cannot
   become their transitive layout, and the record-external-admission design
   cannot be assumed to answer this Variant boundary without reconciliation.
4. `runtime_data_enum_identity` in runtime-accelerator owns a real `TypeShape`
   and derives a semantic identity from its complete semantic transcript. It
   has no layout. The existing `project_runtime_type_schema` conversion is
   sema-owned and used for Entry/project schemas. The runtime adapter cannot
   acquire a dependency upward on sema or copy that mapping as a second
   authority. Reconcile data names, exact instance identities, nested shapes
   and any legitimate common projection owner.
5. `RuntimeVariantDomainSeed`/`RuntimeVariantDomain` formerly drop layout.
   Their source types may be ProjectNominal or a current opaque-overlay owner.
   Close canonical evidence and the aggregate type/domain admission relation;
   matching two independently claimed scalars is not final graph authority.

These are repository-resolvable design decisions, not an external blocker.
Existing constructor/fingerprint propagation and core graph value-validation
work must not be discarded to make this request easier. A partial production
bridge, zero hash, semantic-hash-as-layout, new nominal spelling resolver,
layout-only substitute schema, or rejection of otherwise supported cases is
not an acceptable closure.

### Additional data-boundary evidence — 2026-09-12

Inspected `main == origin/main` at
`a8f7af1d6d003db3a527a10ed57f8aaf906a46e5`, preserving 125 dirty Rust/Cargo
paths. This audit extends the existing request; it does not create a separate
data correction or claim that the producer design is closed.

The missing data Variant layout is downstream of conflicting declaration and
value contracts. A layout-only implementation cannot settle them:

- The maintained [parsing chapter](../../01-language/parsing.md) specifies a
  typed codec call using `try data.decode(bytes, .Json, data.shape<Config>())`.
  The current base environment instead declares `data.encode(AgentValue,
  DataFormat) -> Bytes`, `data.decode(Bytes, DataFormat, DataShape?) ->
  AgentValue`, and `data.shape(AgentValue) -> DataShape`. The final design must
  reconcile typed versus dynamic results, descriptor acquisition and ordinary
  error results across the actual source and runtime calls. Neither the
  narrower current declaration nor the example alone excuses missing
  producer/consumer work.
- The accelerator's shaped decoder constructs Char, Option and nominal Enum
  runtime values, as well as numeric widths beyond I64/U64/F64. Its unshaped
  decoder constructs I128/U128 for integer data numbers. These are outside the closed
  AgentValue predicate (including the accepted core predicate and the pending
  shared schema visitor). Do not claim return-type validity from successful
  codec decoding, or silently change integer precision or erase typed enums
  to make a declared return type pass.
- `type_shape_to_runtime_value` drops enum payloads, Rust names, tag strategy,
  discriminants and repr. Its enum reader accepts a sequence of names and
  recreates unit cases. Record transport drops default/skip/rename/byte-format
  policies, and explicit runtime shape decoding rejects Named, Option and Map.
  A full TypeShape semantic transcript computed after that transport cannot
  restore the lost declaration. Close the complete descriptor transport and
  its consumers, using the existing core reflection projection where it
  applies, before issuing identities or layouts.
- `ArcweftReflect` emits the unqualified declaration identifier as a shape
  name and reflects instantiated fields/payloads, but TypeShape has no ordered
  generic-argument owner or nominal declaration identity. Distinct qualified
  declarations and instances with unused parameters therefore cannot be
  identified by shape-name spelling plus payload inspection. The required
  exact Rust/Arcweft join must establish these identities and arguments;
  inventing a runtime name resolver is not a substitute.
- Data Named nodes have no declaration table in the current TypeShape API;
  the raw data codec and accelerator reject them. The final recursive graph
  contract must supply and validate the actual definitions, not imply that
  the accepted context-free core projection already resolves them.
- Data Maps carry string-keyed entries; the accelerator currently ignores the
  declared key shape and returns a runtime Record. The canonical runtime Map
  schema expects a sequence of key/value tuples. In addition, enum encoding
  currently discards nominal owner and ordinal and infers a one-case shape
  from the observed value. Close both encode/decode directions against the
  selected full descriptor, with key representation, complete case metadata
  and runtime layout correlation specified together.

The implementation acceptance must exercise these actual public call paths,
not only a direct conversion helper. Include a shaped enum with a renamed
payload case, distinct integer widths and overflow, Option/Map, repeated and
recursive definitions, distinct qualified declaration identities and ordered
generic arguments including unused parameters. Verify the declared source
result, native/AWBC runtime value, codec round trip, descriptor identity and
failure without publication. Existing shape-required format round trips
remain required. These are repository-resolvable design and implementation
obligations within this request, not external blockers or new non-goals.
