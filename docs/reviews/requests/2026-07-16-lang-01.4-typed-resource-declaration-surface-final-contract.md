# Request: Typed resource declaration surface final contract

## Sequence position

This is Lang-01.4, split from the 2026-07-16 top-level declaration reduction.
It is independent of live source authoring and build/profile metadata
extraction.

## Why this split is needed

The language currently grows one top-level keyword and enum variant for each
presentation/audio object: `image`, `voice`, `se`, `bgm`, `audio bus`, `mixer
snapshot`, `ducking`, `motion`, and `rig`. Most share a generic entity header
and only a small subset has a typed body. The intended replacement is one typed
resource declaration, but the word `resource` is visually long and a blind
`res` abbreviation may be too cryptic. A final surface must be selected before
removing the useful runtime objects.

## Required decisions

1. Decide whether any new keyword is needed at all. Compare at least:
   - a short `res name: Type { ... }` declaration;
   - `def name: Type { ... }` as a typed named definition;
   - an ordinary typed `const`/`static`-like declaration with derived entity
     identity;
   - a type-led declaration, if it can be parsed and completed without
     ambiguity.
2. Reject ambiguous or misleading candidates explicitly. In particular,
   distinguish packaged byte `asset` identity from a configured runtime
   presentation/audio object.
3. Define the canonical short spelling, formatter expansion behavior if any,
   and generated fully-qualified spelling.
4. Define stable resource identity, nominal type resolution, visibility,
   module imports/reexports, generics if allowed, and body construction.
5. Define which resource families require build-time validation, runtime
   handles, Agent visibility, save references, or hot-reload identity.
6. Specify typed schemas for the currently generic/raw declaration bodies and
   how extension packages register additional resource types without adding
   lexer keywords.
7. Define the boundary between `asset` payloads and typed resources that refer
   to those payloads.
8. Provide a direct migration for image/audio/motion/rig declarations with no
   compatibility reader.

## Implementation order to specify

1. Name/syntax decision and identity model.
2. Typed resource registry and body schema contract.
3. AST/HIR/sema/project-index/tooling representation.
4. Bundle/runtime/Agent/hot-reload mapping.
5. Migrate one complete resource family, then mechanically migrate the rest.
6. Delete individual keyword recognizers, enum variants, and old examples.

## Tests to specify

- Multiple nominal resource types use one declaration grammar.
- Packaged asset and configured resource identities cannot be confused.
- Import/reexport/rename/navigation retain the original resource declaration.
- Bundle/runtime/Agent round trips preserve nominal type and stable ID.
- Extension resource types do not require a lexer/parser code change.
- Unknown types/fields, malformed bodies, and cross-family references report
  typed diagnostics with source ranges.
- Every removed resource keyword leaves no historical AST/CST kind or
  dedicated removal diagnostic.

## Constraints

- Prefer the shortest clear syntax, not the shortest token in isolation.
- Do not use raw string field bags as the final typed resource contract.
- Do not rename `asset` to mean both bytes and configured objects.
- No compatibility aliases, dual readers, source gates, or keyword-by-keyword
  registry special cases.
- Do not redesign verified bundle/runtime resource types without evidence of a
  concrete flaw.

## Expected output

- One final keyword/no-keyword choice with rejected alternatives and rationale.
- Canonical hand-written and generated examples.
- Typed identity/schema/extension/runtime contracts.
- A family-by-family direct migration and deletion plan with tests.
