## Sequence position and split rationale

The CharacterDialogue sequence is:

1. AW-AH-009.4 Cut 1, already implemented, owns the immutable runtime/domain
   value and generic nominal runtime substrate.
2. AW-AH-009.3.1 owns exact ordinary parenthesized and callback-block call
   surfaces.
3. **AW-AH-009.4.2**, this request, owns the missing dialogue-content
   application syntax and typed-HIR expression contract.
4. AW-AH-009.4.3 consumes the typed source owner selected here and owns
   source-site line identity, project-wide collision acceptance, and
   diagnostics.
5. Remaining AW-AH-009.4 sema/runtime/wire/tooling cuts consume those two
   reconciled contracts.

This request is split from line identity because syntax ambiguity, exact source
ranges, parser recovery, and HIR expression ownership must first produce one
typed source site. It must not independently choose project-wide identity or
collision policy. Conversely, it cannot be split further: `DialogueIndentation`,
generic postfix-bracket ambiguity, AST shape, HIR expression ownership, and
relative-ID retention all describe the same source node and must not be
specified by incompatible contracts.

## Production contradictions to resolve

The AW-AH-009.4 package claims zero open questions but leaves the following
contracts unrepresentable or contradictory on current production.

### Undefined colon indentation carrier

`GRAMMAR_HIR_SEMA.md` requires:

```rust
DialogueContentApplicationSurface::Colon {
    head_range: TextRange,
    colon: TextRange,
    content_range: TextRange,
    indentation: DialogueIndentation,
    plan_range: Option<TextRange>,
}
```

It never defines `DialogueIndentation`, its fields, inline-versus-indented
states, UTF-8 range invariants, recovery behavior, construction visibility, or
accessors.

### Assumed generic postfix-bracket substrate

The package says an existing generic postfix-bracket CST is retained and that
ambiguous input lowers to `HirPostfixBracket`. Current production instead
classifies dialogue call versus index during parsing using source-shape
heuristics and has neither a generic retained CST contract nor a defined
`HirPostfixBracket` type.

### Conflicting HIR models

AW-AH-009.4 specifies a standalone:

```rust
HirDialogueContentApplication {
    target: AuthoredExpr,
    ...
}
```

Proof-concurrency v6.1.1 instead specifies typed HIR expression arenas,
`ExprId`, `HirExprKind`, source-backed identities, lexical scopes, function
bodies, and currently names the obsolete `HirExprKind::DialogueCall`. The
packages do not decide how the final application participates in that arena,
which owner holds it in callable bodies, or whether source/range data belongs
in the payload or HIR slot metadata.

### Relative ID syntax is not an ordinary expression carrier

AW-AH-009.4 requires immediate configuration arguments such as:

```arcw
id = @.greeting
id = @say:.greeting
```

to survive as typed `IdRef`. Current `IdRef` supports absolute, relative, and
family-relative forms, but ordinary expression entity references do not retain
unqualified relative `IdRef`. AW-AH-009.3.1 defines exact argument-list ranges
but does not define this value carrier. Re-parsing argument source in HIR would
violate the typed-source and no-source-search rules.

### Superseded dialogue clauses in AW-AH-009.3.1

The general AW-AH-009.3.1 `CallExpr`, `CallSurfaceSyntax`, and
`ArgumentListSyntax` decisions remain authoritative. Its dialogue-specific
`SpeakerLineSurface` and string `ContentCallSurface` handoff is superseded by
AW-AH-009.4, which deletes those nodes. The final contract must state how to
implement the shared ordinary call substrate without implementing the
superseded dialogue adapter as a compatibility interval.

## Established substrate that must not be redesigned

Unless current production evidence proves one exact clause impossible, retain:

- AW-AH-009.4 Cut 1 `RuntimeNominalRecordValue`, `CharacterDialogue`,
  `CharacterDialogueConfig`, patch semantics, role newtypes, limits, and
  runtime schema;
- AW-AH-009.3.1 `Expr::Call(CallExpr)`, exhaustive `CallSurfaceSyntax`,
  parenthesized `ArgumentListSyntax`, callback-block syntax, parser-only
  construction, exact missing-`)` recovery, and deletion of source-less public
  call constructors;
- proof-concurrency v6.1.1 source-backed `ExprId`, typed HIR arenas, lexical
  scope ownership, transactional lowering, and revision-bound source identity;
- AW-AH-009.3.2's single accepted `Arc<HirProject>`, source-to-module
  lifecycle, and no on-demand LSP parser/lowerer;
- existing `DialogueContent`, RichText, interpolation, controls, `LinePlan`,
  and current-grammar recovery semantics where they do not conflict with the
  final typed source node;
- the dependency direction
  `syntax -> HIR -> sema -> runtime-plan/verify -> tooling`.

Do not redesign character registration, alias resolution, callable catalog
precedence, CharacterDialogue runtime value semantics, line identity rules,
project collision policy, runtime wire records, dialogue View projection, or
text rendering in this request.

## Required decisions

### 1. Exact colon indentation model

Define the exact public and crate-private Rust shapes for
`DialogueIndentation` and any supporting enums. At minimum decide:

- inline versus indented representation;
- indentation base, body start/end, line ending, and dedent boundary;
- whether indentation is measured in source bytes, columns, or an existing
  parser-owned indentation unit;
- tab handling and mixed whitespace;
- empty content and recovered/misaligned content representation;
- exact `TextRange` and `SourceSpan` projection rules;
- constructors, field visibility, accessors, derives, validation failures, and
  serialization prohibition if syntax-only;
- how CRLF, Unicode content, comments, blank lines, and trailing trivia affect
  stored ranges.

No field may exist only as formatter display data if parser or HIR behavior
depends on it.

### 2. Generic postfix-bracket CST and AST

Define one exact lossless postfix-bracket node with:

- target child identity and exact target range;
- exact `[` and present/missing `]`;
- payload child/token ownership and exact payload range;
- trivia/comment retention through the existing source document;
- recovery state and owner boundary;
- optional line-plan attachment without stealing an unrelated following
  `with`;
- source node identity suitable for incremental reconciliation.

Specify the exact relationship among:

```text
expression-start collection literal
postfix index candidate
dialogue-content candidate
ambiguous postfix bracket
invalid/no-candidate postfix bracket
```

Parsing and CST construction must not inspect identifier spelling, resolved
type, Character identity, `.say`, or callable names.

### 3. Classification stage and exact AST variants

Decide which interpretations are retained in syntax AST and which are deferred
to HIR/sema. Define exact variants and payloads for:

- unambiguously indexed postfix;
- unambiguously dialogue-content application;
- unresolved generic postfix bracket;
- recovered missing close bracket;
- colon dialogue-content application.

State whether `DialogueContentApplicationExpr` remains the exact package shape
or is adjusted to fit the selected generic carrier. Define private-field
invariants, read-only accessors, crate-private checked constructors, full
range derivation, and ownership of `DialogueContentApplicationSurface`.

Colon and bracket forms must converge to one semantic application meaning
without fabricating bracket tokens for colon source.

### 4. Typed HIR expression ownership

Reconcile the final source node with proof-concurrency v6.1.1. Define:

- the exact `HirExprKind` variants for dialogue application and unresolved
  postfix bracket;
- whether `HirDialogueContentApplication` is a payload and, if so, its exact
  fields;
- `ExprId` ownership for the target and any expression-valued children;
- callable, flow, closure, branch, block, and statement-body containment;
- lexical `ScopeId` behavior;
- source-backed versus synthetic HIR identity;
- source span ownership between HIR slot metadata and payload surface ranges;
- HIR source-map lookup for the whole application, target, delimiters,
  content, plan, and configuration arguments;
- poison/recovered status and executable gating;
- clone/equality/serialization policy.

Do not retain syntax `AuthoredExpr` clones in final typed HIR if the accepted
arena contract requires `ExprId`. Do not add a parallel dialogue expression
arena or a flow-only sidecar that callable bodies cannot use.

### 5. Ordinary call composition and typed ID coordinates

Use AW-AH-009.3.1 as the sole ordinary call-surface owner. Define:

- how a nested parenthesized target such as
  `alice(look=smile)[content]` retains one exact `CallExpr`;
- how `id` and `text_key` are identified only on the immediate outer
  configuration application;
- the exact syntax/HIR representation of absolute, relative, and
  family-relative `IdRef` values inside ordinary named call arguments;
- how an arbitrary runtime expression is distinguished from compile-time
  `IdRef` without source text re-parsing;
- duplicate coordinate retention for later sema diagnostics;
- malformed value recovery and range ownership.

Do not add dialogue-only argument-list parsing, a second call AST, a string
coordinate map, or a public source-less call constructor.

### 6. Recovery, ambiguity, and plan attachment

Specify exact retained nodes, diagnostics, and owning boundaries for:

- missing `)` in a nested target call;
- missing `]`;
- empty `[]`;
- colon head with no inline or indented body;
- malformed or misaligned indented content;
- malformed `with:` and `with {}` plans;
- a `with` belonging to a following statement;
- nested `foo()[content]`;
- bracket payloads containing one ordinary expression;
- payloads containing dialogue controls, RichText tokens, interpolation, or
  line breaks;
- two viable interpretations;
- no viable interpretation;
- bare blocks that must not attach as a plan.

Reuse ordinary grammar/recovery diagnostics. Do not create a `.say`-specific
recognizer or permanent removed-syntax diagnostic.

### 7. Limits, construction, and failure atomicity

State:

- which existing parser, CST, AST, HIR, source-map, and diagnostic budgets are
  charged;
- checked arithmetic requirements for all range/base projections;
- the maximum retained candidate/diagnostic work per postfix bracket;
- whether limit exhaustion is fatal or recovered;
- how parser/HIR transactions avoid publishing a partially constructed node;
- which invariant failures are internal parser/HIR failures rather than user
  diagnostics.

Do not introduce a client-configurable dialogue parser limit or an unbounded
candidate list.

### 8. Direct migration and deletion

Inventory every production and test consumer that must move from:

```text

DialogueCallExpression shadow kind
HirExprKind::DialogueCall
post-parse call/delimiter source search
speaker-derived HIR fields
```

to the final typed model. Specify the direct replacement order and final
deletion gate. Do not leave an alias, deprecated variant, wrapper, dual reader,
source-search fallback, or extension trait.

## Required implementation order

The returned contract must specify compiling/package-frontier cuts in this
order:

1. Implement and validate the general AW-AH-009.3.1 call-surface substrate.
   Dialogue-specific old surface records from that package are not a final
   implementation target.
2. Introduce the final indentation, postfix-bracket, dialogue-application, and
   HIR payload types with private fields and direct invariant tests where that
   can be done without exposing a compatibility API.
3. Replace shadow grammar/CST emission and parser recovery with the final
   generic postfix and colon nodes.
4. Replace source AST variants and eliminate speaker/string content parsing.
5. Reconcile proof-concurrency typed HIR arenas, function/flow bodies, source
   maps, and recovered/poisoned status.
6. Migrate all syntax/HIR/sema/runtime-plan/verify/LSP/CLI/tooling exhaustive
   consumers mechanically to the final accessors.
7. Delete old variants, direct constructors, source reconstruction helpers,
   spelling heuristics, and obsolete tests.
8. Restore workspace compilation and only then commit or merge the public
   direct replacement.

The contract must explicitly use the AW-AH-009.3.1 direct-replacement pattern:
after any independently mergeable substrate cut, public variant replacement
through downstream migration is one unmerged series. A syntax/HIR-only public
cut that knowingly leaves the workspace uncompilable is not a reviewable push
cut.

## Mandatory direct tests

Define exact named tests covering at least:

### Syntax and range tests

- bracket and colon forms produce the same dialogue-application meaning with
  distinct exact surface ranges;
- inline and indented colon content, including blank lines, comments, Unicode,
  tabs according to the selected policy, LF, and CRLF;
- exact missing-`)` and missing-`]` insertion points;
- empty bracket content and missing colon content;
- `with:` and `with {}` attach identically;
- a misaligned or following-statement `with` is not stolen;
- `items[0]` remains an index candidate;
- expression-start `[a, b]` remains a collection;
- dialogue controls/RichText/interpolation make a dialogue candidate;
- an exactly ambiguous postfix is retained without name-based resolution;
- nested `foo()[content]` preserves the complete target;
- a record literal as an ordinary call argument is not reclassified;
- a bare block without `with` is not attached;
- comments and trivia remain recoverable from the source document.

### Typed call and ID tests

- the target call owns the exact AW-AH-009.3.1 `ArgumentListSyntax`;
- named, positional, spread, nested, trailing-comma, and recovered arguments
  retain their existing call contract;
- `id=@say.opening.greeting`, `id=@.greeting`, and
  `id=@say:.greeting` remain typed distinct `IdRef` syntax;
- a runtime expression in `id` remains a runtime expression and is not
  re-parsed or fabricated as `IdRef`;
- duplicate `id`/`text_key` coordinates remain visible to sema.

### HIR ownership tests

- bracket and colon applications allocate the selected source-backed `ExprId`;
- target and nested call children use typed `ExprId` links;
- occurrences in flow, ordinary function, closure, branch, block, and
  expression statement bodies have the correct lexical owner/scope;
- unresolved postfix bracket retains exact target/payload candidates;
- source lookup returns the exact application, target, delimiter, content,
  plan, and coordinate spans;
- recovered syntax commits a recovered/poisoned tooling snapshot but is
  excluded from executable consumers according to the selected substrate;
- source revision and document identity are retained without source display
  string authority;
- no syntax clone, source reparse, or dialogue-only expression arena is
  required.

Use public or crate-owned typed behavior tests. Do not use source gates or
assert implementation file placement/spellings.
