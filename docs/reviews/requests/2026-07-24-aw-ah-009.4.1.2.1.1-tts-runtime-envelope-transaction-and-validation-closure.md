## Why this correction is required

The returned package is mechanically coherent and selects an architecture that
preserves `arcweft-core`'s no-audio dependency. Its archive manifest and
prerequisite hashes verify, `OPEN_QUESTIONS.md` is `none`, and its test matrix
contains 316 unique rows. However, its `READY_FOR_IMPLEMENTATION` status
conflicts with several missing inputs or APIs:

1. replay exposes only `RuntimePayloadContractError`, while nested TTS field,
   semantic-limit, and audio content-digest validation is owned by
   `TtsPayloadDecodeError`;
2. save restore requires pre-publication TTS asset validation but assigns no
   owner or dependency path that can call the bridge decoder;
3. queued reload requires ten old-versus-candidate coordinates, but the
   specified previous request/evidence lacks the old profile semantic digest,
   credential-ref canonical text, and protocol ID;
4. the driver allocates a `TaskSequence`, but the specified `TaskSpec` and
   `RuntimeScheduler::submit_one` API cannot carry it into `TaskObserver`, and
   a fallible submission appears inside an allegedly infallible commit;
5. several required exact outer-canonical-cap success rows cannot be reached
   by any semantically valid value under the smaller field limits; and
6. private cross-crate types have no authority-preserving construction path.

Implementing around any of these gaps would choose architecture, serialized
identity, error behavior, or atomicity on behalf of the designer.

## Required decisions

### 1. Replay-domain payload validation

- Define the exact replay error variant and owning crate that retains a nested
  TTS decode failure, including field ordinal, nested nominal/layout failure,
  semantic limit, and audio content-digest mismatch.
- Define the exact conversion path from generic recorded payload validation to
  bridge-owned TTS validation without adding an audio dependency to core.
- Distinguish replay-control corruption from a valid recorded
  `TtsError::ProtocolFailure`; an invalid recorded success or failure must not
  publish a Need progress/result/error event.
- Reconcile `RootReplayError`, `TtsRuntimeDiagnostic`, `REPLAY-012` through
  `REPLAY-016`, and the generic/non-generic error ownership table.

### 2. Save/restore pre-publication validation

- Select the exact owner and dependency direction for validating restored
  `TtsAudioAsset` nominal identity, layout, ordinals, nested values, limits, and
  content digest before any restored state becomes visible.
- Give the exact public method signature, caller, error type, and transaction
  order. State whether the gate belongs to a runtime-driver restore
  coordinator, a generic save callback/catalog, or another closed typed owner.
- Keep data-format crates Sans I/O and keep `arcweft-core` free of audio/TTS
  dependencies.
- Reconcile `SAVE-010` with the existing HostTasks/TaskGenerationPins blockers
  and with arbitrary non-TTS durable assets; do not add a TTS-only second save
  path.

### 3. Exact queued-reload compatibility evidence

- Define where the old ten-coordinate tuple is retained and how
  `rebind_queued_request` receives it. The model must make all ten old values
  available without recovering them from display text or the candidate
  catalog.
- Select either an exact old-catalog/snapshot input, a sealed typed
  compatibility-evidence value, or another single closed model, and give every
  affected Rust type, field ordinal, codec/layout/fingerprint consequence, and
  constructor.
- Preserve privacy for credential references and restricted digests while
  retaining byte-exact comparison and a typed mismatch coordinate.
- Define availability, selected fingerprint, TaskKey, generation, and
  registration checks separately and reconcile `RELOAD-002` through
  `RELOAD-011`.

### 4. Sequence-bearing atomic scheduler admission

- Define the exact API that transfers the driver-allocated `TaskSequence` into
  the newly scheduled or joined observer retained by the sole scheduler.
- Close the preflight/reservation/commit protocol for scheduler state, observer
  registry state, and the execution generation pin. If P9–P12 remain one
  infallible commit, every capacity, contract, duplicate, and allocation
  failure must be typed before sequence mutation and the commit API must be
  infallible by construction.
- Otherwise select and specify a different atomic order with exact rollback and
  sequence-consumption semantics; do not leave a fallible `submit_one` inside
  prose that declares the commit infallible.
- Preserve one execution, observer-specific identity/sequence/cancel scope,
  first-owner priority, one execution pin, and no partial publication for both
  Scheduled and Joined results.

### 5. Feasible payload-boundary tests

- For each of intent, selected request, progress, audio asset, and error, state
  the largest semantically valid encoded value and whether it can equal the
  declared outer canonical cap.
- Replace impossible exact-cap success rows with a precise distinction between
  a generic codec's raw cap test and a domain payload's largest-valid-value
  test, or change the normative cap to a reachable value with exact rationale.
- Retain one-over rejection at the actual enforcing boundary. Do not add
  meaningless padding, unused fields, or relaxed semantic limits solely to
  manufacture a cap-sized fixture.
- Correct `LAY-011`, `LAY-023`, `LAY-035`, `LAY-047`, `LAY-059`, and every
  dependent traceability row.

### 6. Cross-crate construction and authority

- Define the allocator/checked constructor and visibility for
  `HostAdapterRegistrationId` so an arbitrary caller cannot forge a live
  registration.
- Define the exact runtime-host-to-runtime-driver construction path for

  generation, and generic registration ID.
- Give accessors needed by the driver/host and compile-fail boundaries for

### 7. Generic AWBC verifier linkage

- Define how the core-owned generic verifier rejects wrong TTS intent/outcome

- Select the schema-derived or registered typed contract link, its owner,

- Preserve codec 8 direct replacement and codec 7 rejection; do not add a dual
