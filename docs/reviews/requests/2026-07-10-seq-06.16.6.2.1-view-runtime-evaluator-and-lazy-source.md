# Seq 06.16.6.2.1 typed View evaluator and lazy source activation

Date: 2026-07-10

## Sequence position

This follows seq-06.16.6.2. The exact Sans I/O range planner, per-mount
identity, key-anchor replacement, retained-only range records, session-save
representation, and Agent observation representation are already implemented.
This request must use that substrate and must not replace it with eager child
lowering or a second platform-specific list model.

## Why this is a separate implementation cut

Current CLI View bundle lowering is not a live View evaluator:

- multiple View declarations are flattened into one `ViewProgramResource`;
- props and locals are represented by schema digests rather than executable
  typed expressions;
- branch and repeat bodies are lowered together with static sidecars;
- sidecars exist before a runtime mount occurrence exists;
- off-window children have no evaluator from which to instantiate their body.

Accepting `LazyRow` or `LazyColumn` in that model would only rename an eager
Row/Column and would contradict observable, save, and retained-state behavior.

## Required decisions

1. Define the typed executable representation for View params, locals, props,
   branch conditions, keyed repeat sources, keys, calls, and await branches.
2. Define a multi-program View bundle table and how a runtime call resolves a
   program without collapsing two mount occurrences. Allocate an occurrence-
   specific actionable Scroll identity as part of this contract: the current
   player/Agent string target names an authored Scroll and cannot route two
   mounts of that Scroll independently.
3. Define the mount lifecycle and ownership of props, local state, handler
   captures, semantics, focus, and child retained state.
4. Choose one deterministic primary-axis extent protocol for initially
   off-window items:
   - fixed authored item extent;
   - estimated extent with a specified anchor-correction algorithm; or
   - another protocol that does not require eagerly laying out every child.
5. Define finite-source revision behavior, duplicate-key diagnostics, and what
   happens when the current anchor key is removed.
6. Define focus/capture requests for an off-window key: whether the evaluator
   may materialize it temporarily, and how that affects the saved window.

The public overscan policy, variable-size estimate correction, and temporary
capture materialization must be decided here before source activation. Their
values cannot be inferred from the existing static bundle sidecars.

## Implementation order

1. Move View semantic checking and executable lowering out of CLI-only
   sidecar construction into the language/compiler/runtime-plan layers.
2. Replace the single global program resource with a typed program inventory.
3. Implement a per-mount evaluator for bind/call/branch/await/keyed-repeat.
4. Connect keyed-repeat results and resolved extents to
   `ViewVirtualizationRuntime` and derive only the materialized fragment.
5. Route focus, semantics, input, renderer objects, and capture through that
   fragment while retaining keyed state outside it.
6. Enable `LazyRow` and `LazyColumn` grammar and diagnostics in the same cut;
   delete the unsupported-spelling test rather than adding a compatibility
   parser branch.

## Tests to specify

- Two mounts of one program with different props produce independent windows.
- Player and Agent scroll actions address those two mount occurrences
  independently rather than sharing one authored-global Scroll target.
- Branch and keyed-repeat expressions execute typed values rather than schema
  strings or hashes.
- Duplicate keys fail with a structured source range.
- Insertion before the visible key preserves its key-relative anchor.
- Removing the anchor follows the specified fallback exactly.
- Off-window item state survives scrolling and save/load, then is pruned when
  the key leaves the finite source.
- Focus and selected capture of an off-window key follow the chosen
  materialization policy on native and Web paths.
- Agent observation reports stable item targets for the complete source and
  marks only the actual fragment window as materialized.
- No eager Row/Column fallback and no source-text gate is introduced.
