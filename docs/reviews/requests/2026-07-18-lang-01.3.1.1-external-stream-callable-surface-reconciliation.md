# Request: External Stream callable surface reconciliation

## Sequence position

This is Lang-01.3.1.1. It is a narrow contract correction required before
Lang-01.3.1 Cut 1. It must reconcile Lang-01.3.1 with the already authoritative
Lang-01.1.1 direct-style function/generator contract.

It supersedes only Lang-01.3.1 package decisions `RD-009`, `RD-010`, and
`RD-011` and corresponding tests that assume a source-visible `stream fn`
role. It must not redesign the accepted Source-elimination direction, Stream
runtime semantics, external lifecycle/policy, callable catalog, or
external-capability boundary.

## Why this correction is required

The Lang-01.3.1 package says the canonical external declaration is the exact
external `stream fn` form shown in its `SOURCE_REQUEST.md`, but that request
contains no fenced authored example. The package also requires an ordinary
authored `stream fn`, an external `stream fn`, and rejection of ordinary
`fn -> Stream<T, E>` as a substitute.

Lang-01.1.1 explicitly forbids `stream fn` and defines:

- an ordinary `fn -> Stream<T, E>` with own-scope `yield` as a generator; and
- an ordinary `fn -> Stream<T, E>` without own-scope `yield` as an immediate
  Stream passthrough.

The two contracts cannot both drive one parser/HIR cut. Lang-01.3.1's normative
order prohibits starting its later runtime cut before this surface is fixed.

## Fixed direction to evaluate

Prefer the smallest model that preserves Lang-01.1.1:

```arcw
extern capability capture {
    fn frames(
        request: CaptureRequest,
        policy: StreamPolicy,
    ) -> Stream<VideoFrame, CaptureError>
        effects { capture.read }
}
```

An external capability member has no Arcweft body. Its capability and operation
identity, typed parameters, Stream item/error types, effect row, and source
range are the external-origin definition. A call returns an affine Stream
handle immediately and emits Lang-01.3.1's typed Sans I/O open request.

Authored generator and passthrough functions remain ordinary functions:

```arcw
fn sampled_frames(request: CaptureRequest) -> Stream<VideoFrame, CaptureError> {
    let frames = capture.frames(request, StreamPolicy.latest())
    for await frame in frames {
        yield frame
    }
}

fn direct_frames(request: CaptureRequest) -> Stream<VideoFrame, CaptureError> {
    capture.frames(request, StreamPolicy.latest())
}
```

Do not add `stream fn`, `#[stream]`, `#[source]`, `#[input]`, or a sidecar
string role.

## Required decisions

1. Confirm the exact external capability member grammar, including generics,
   curried parameter groups, named/default arguments, return type, effect row,
   terminator, and whether any external binding metadata is required beyond the
   capability/operation identity.
2. Confirm that an `extern capability` member returning `Stream<T, E>` is the
   external-origin classification and that no separate source-role marker is
   present in AST, HIR, or project index.
3. Define the typed AST/HIR field that distinguishes a bodyless external
   capability operation from an ordinary authored function without restoring a
   source function kind.
4. Confirm generator classification from ordinary `fn -> Stream<T, E>` plus
   own-scope `yield`, and immediate passthrough classification when own-scope
   `yield` is absent.
5. Define how external-origin definition identity is derived from accepted
   module, capability, and operation identity without authored debug strings.
6. Define where runtime-composable `StreamPolicy` enters the call. Prefer an
   ordinary typed parameter/default or typed wrapper function; do not use an
   attribute token bag.
7. Define how deployment-selected provider/profile metadata binds the same
   accepted capability operation without changing authored callable identity.
8. Define the shared callable-catalog classification and checked lowering
   evidence required by Lang-01.3.1, including item/error types, effect row,
   capability/operation identity, and source range.
9. Define parser recovery for a capability member with a body and an authored
   function without a required body. Final rejection must use current grammar,
   not a removed-spelling diagnostic.
10. Reconcile every Lang-01.3.1 test row that refers to an external or authored
    `stream fn` role with the ordinary-function/capability-member model.

## Implementation order

1. Replace Lang-01.3.1 `RD-009` through `RD-011` and affected test rows with
   one exact, fenced grammar contract.
2. Land/rebase Lang-01.1.1 ordinary function and generator classification.
3. Extend the existing external-capability function member only where typed
   external Stream evidence is missing.
4. Delete Source declaration/type AST and HIR paths without accepting a second
   callable spelling.
5. Register external origins in the shared callable catalog and export checked
   evidence to Lang-01.3.1 RuntimePlan lowering.
6. Continue Lang-01.3.1 Cuts 3 through 7 without an alternate author path.

## Tests to specify

- exact positive parsing for the final capability operation syntax;
- malformed generic, parameter, return Stream, effect, and terminator recovery;
- rejection of a body on an external capability operation;
- rejection of a missing body on an authored function;
- generator classification only for own-scope `yield`;
- passthrough classification for ordinary `fn -> Stream<T, E>` without
  own-scope `yield`;
- nested closure/function `yield` does not classify the outer function;
- external origin and ordinary functions share signature, definition,
  references, rename, import/reexport, generics, currying, and named-argument
  resolution through one callable catalog;
- effect checking occurs when the external operation is called, not when the
  Stream type is mentioned;
- capability/operation identity and item/error types survive checked lowering
  without source-text reparsing;
- removed top-level `source`, public `Source<T, E>`, `stream fn`, and role
  attributes have no executable AST/HIR representation; and
- ordinary parser behavior, public/compile-fail API checks, and typed codec
  tests replace any source-spelling gate.

## Constraints

- Do not redesign Lang-01.1.1 suspension, generator, Need, Stream, scheduler,
  or fiber semantics unless current implementation evidence identifies a
  concrete defect.
- Do not redesign Lang-01.3.1 lifecycle, policy, identity, AWBC, save, or
  hot-swap decisions beyond the author/callable surface conflict.
- Do not add a compatibility parser, alias, dual reader, migration node,
  source gate, CSS path, or Takumi path.
- Reuse the owning function, external-capability, callable-catalog, effect-row,
  accepted-project, and source-range types. Do not add a sidecar resolver or
  string role map.
- Keep runtime/data layers Sans I/O.

## Expected output

- one implementation-ready correction with `OPEN_QUESTIONS=0`;
- exact fenced author grammar and examples;
- exact AST/HIR/callable-catalog/checked-evidence shapes;
- a replacement mapping for Lang-01.3.1 `RD-009` through `RD-011`;
- an updated subset of the Lang-01.3.1 test matrix; and
- an explicit statement that all other Lang-01.3.1 decisions remain
  authoritative.
