# Request: seq-06.11d.5.2 Agent native Style observation protocol

Date: 2026-07-14

## Sequence position and independence

This Agent-protocol cut follows seq-06.11d.5.1 and depends on its portable trace
DTO and policy-aware projection. It restates all substrate needed for a new
designer without access to 5.1 or an older request.

Produce a completely new standalone design, not an addendum to Agent or CSS
documents. Map final 5.1 names explicitly instead of competing with its shape.

## Goal

Define an opt-in CLI/MCP/Agent protocol for effective native Style and bounded
property explanations. Correlate Style identity with frame/view/object records,
expose one transport-neutral typed result, and preserve source privacy.

Keep normal observation compact and detailed evidence discoverable separately.
Agent code must not resolve Style again.

## Fixed native and Agent substrate

The following is already implemented and must be treated as fixed:

- Arcweft Style is native-only: source AST to HIR to
  `CheckedViewStyleCatalog` to `ViewStyleProgram` to runtime applications to
  the single `arcweft-view` resolver and `ComputedViewStyle`.
- CSS source, CSS discriminators, external stylesheets, Takumi, compatibility
  readers, and player-facing CSS diagnostics do not exist.
- Resolver inputs include mounted identity, typed facts/ancestry/applications,
  parent Style, environment, revisions, and boundary facts; computed values
  retain typed winner provenance.
- The 5.1 dependency is a deterministic transport-neutral result for a typed
  node/property query, with typed identity/source, completion/redaction, and
  budgets that never change the winner.
- Agent observation is owned by `arcweft-agent-protocol`. CLI and MCP adapters
  expose the same typed JSON rather than reshaping it.
- An observation is bound to a session, tick, frame, state hash, render hash,
  viewport, and typed inventories of views, objects, presentation nodes,
  diagnostics, and discoverable resources.
- Agent resources use discoverable frame-bound `arcweft://` URIs. Clients treat
  discovered URIs as opaque and metadata as authoritative.
- Native Agent observation runs through the shared player frame path. Web and
  headless paths consume the same computed Style contract even when a backend
  cannot provide image or geometry data.
- Existing Agent privacy policy uses explicit privacy ceilings and redacts
  secure text/control data. Style observation must join that policy rather than
  introducing an independent boolean such as `include_secrets`.

Do not redesign the resolver, general frame observation, capture model, or
Agent privacy lattice without a concrete defect required to expose Style.

## Required user scenarios

The final protocol must let a bounded client:

1. discover observed object, View, and structural nodes with Style information;
2. read compact effective properties and request winner/full evidence by
   property;
3. bind evidence to exact session/frame/node and reject stale or ambiguous IDs;
4. navigate authorized winner/rejection evidence to source;
5. distinguish absent, inherited, consumer-unsupported, budget-omitted, and
   privacy-withheld properties without inventing geometry;
6. obtain equal semantic evidence across native, web, and headless snapshots.

## Required request and target model

Provide exact Rust definitions for an Agent Style request. Decide:

- whether selection uses `ObserveRequest`, a tool, a resource, or a minimal
  combination with one authoritative execution path;
- typed targets for object, View, mounted node, and focus/semantic target;
- direct correlation from observed/presentation records to
  `ViewStyleNodeKey`, without parsing strings;
- how repeated/conditional nodes and nested View mounts retain occurrence
  identity across one frame;
- property/mode/source/page/privacy/budget filters;
- how multiple matching nodes are either rejected as ambiguous or returned in
  a deterministically ordered bounded result.

Target selection must not use a free-form selector language that recreates
Style selector matching in the protocol. If human-facing CLI sugar is offered,
define its typed parse result and make the protocol receive only that result.

## Required response and resource model

Specify exact typed protocol records and ownership for:

- a compact per-node summary with node identity, computed revision, property
  availability, and discoverable refs;
- a detailed Style trace resource carrying the 5.1 portable DTO unchanged or
  through one explicitly lossless Agent envelope;
- source-location and optional source-snippet resources with privacy metadata;
- typed diagnostics and completion/truncation metadata;
- resource descriptors with URI, MIME type, frame, privacy, byte estimate, and
  cache/revision identity.

Choose whether compact summaries live in `objects[]`, `views[]`, a separate
`style_nodes[]` table, or references among them. The choice must support
non-rendering structural nodes without duplicating full traces across objects.
Define exact membership and correlation rules for one runtime node represented
by multiple presentation objects.

Define one discoverable URI family for summary and trace resources. State the
lifecycle of `latest` aliases, immutable frame URIs, resource listing, reads,
and frame eviction. A returned URI must never resolve to evidence from a newer
frame under the old identity.

## Required wire schema

Provide one canonical JSON representation owned by
`arcweft-agent-protocol`, including:

- request/target/summary/resource/page/source/redaction/completion/diagnostic
  shapes and exact field/enum/unknown-field behavior;
- integer widths, half-open ranges, deterministic order, and MIME types;
- a full observation fragment showing compact Style discovery;
- winner-only, partial-full, redacted-source, and major error responses;
- exact CLI JSON and MCP tool/resource projection rules proving adapters do not
  rename, flatten, or reinterpret fields.

The first format is unreleased. Define one final initial schema and reject
malformed or unknown contracts. Do not add legacy names, dual readers,
deprecated fields, or wire aliases.

## Budgets and paging

Define request limits and hard maxima for selected targets, properties, nodes,
trace events, source-map lookups, snippets/source bytes, response JSON bytes,
resource count, cached frames, pages, and reads per request. The Agent budget
must compose with, not replace, 5.1 trace budgets and the resolver's correctness
budgets.

Specify deterministic truncation order and a typed completion state. If paging
is used, cursors must bind session, immutable frame, node, query, revisions,
privacy ceiling, and event ordering; validate them as hostile input. A budgeted
response must not silently drop nodes/properties or claim a complete trace.

Normal observation with Style disabled must not collect full traces or add
per-node trace allocation. Compact discovery metadata needs a measured upper
bound and must not scale as nodes times rules.

## Redaction and authorization

Define capabilities and privacy ceilings for:

- typed/token values; resource/node/part/module/source IDs and paths;
- ranges/snippets, environment/interaction facts, and secure-control state;
- diagnostics, hashes, lengths, ordering, cursor contents, and cache behavior.

Apply authorization before source hydration and serialization. Cache keys must
include the effective policy, and a privileged response or cursor must never be
served to a lower-privilege request. Redacted fields must carry typed withheld
status; fake Style values are forbidden.

## Source maps, cache, and consistency

Define how a frame-bound trace source reference is hydrated from canonical
bundle source maps and, for live source sessions, matched to an exact document
revision. Missing, stale, generated, withheld, and tampered mappings must be
distinct outcomes. Source reads must be separate bounded resources if embedding
snippets would make normal observations unbounded.

Specify cache ownership between player session, Agent observation, trace
projection, and resource store. A valid cache key must include immutable frame
identity, Style node and computed revision, query, trace/source-map revision,
and privacy policy. Define eviction, stale-resource behavior, cursor expiry, and
whether repeated reads are byte-identical.

An Agent adapter may request trace collection from the canonical resolver. It
must not infer cascade results from `ComputedViewStyle`, re-run selector/token
logic, or cache mutable references into player state.

## Diagnostics

Define stable typed Agent diagnostic codes and response status for unknown,
ambiguous, non-style, non-rendering, stale, evicted, unauthorized, redacted,
unsupported-property, backend-unavailable, source-unavailable, malformed
cursor, tampered reference, and budget-exceeded cases.

Separate protocol/query errors from native resolver errors, projection support
errors, and partial evidence notices. Preserve underlying typed codes where
safe. Do not create a CSS-removal diagnostic category; removed CSS-like source
continues to fail through ordinary parser recovery before observation exists.

## Constraints and non-goals

- No CSS/Takumi type, parser, payload, source descriptor, runtime branch,
  browser cascade, or diagnostic is permitted.
- Do not add an Agent-owned resolver, selector matcher, property parser, token
  resolver, state-slot cascade, or display-string identity.
- Do not change native cascade, inheritance, token, boundary, application, or
  cache rules without concrete defect evidence.
- Do not make Style traces part of every default observation or persisted AWFB.
- Do not expose secrets merely because a client has debug transport access.
- Style mutation, live editing, code generation, pixel explanation, screenshot
  diffing, arbitrary source reads, and general program tracing are non-goals.
- Do not add compatibility shims, source gates, or tests that inspect source
  spellings/locations as correctness evidence.

## Implementation order to specify

1. Finalize the target/correlation table and map every Agent record to the 5.1
   query and portable trace DTO.
2. Freeze typed request/summary/resource/error types and canonical JSON.
3. Add compact Style-node discovery to the shared player observation path.
4. Add one bounded trace request path and immutable frame resource storage.
5. Add policy-gated source hydration and redaction.
6. Expose identical CLI JSON and MCP tool/list/read projections.
7. Add paging/cache only after complete single-page behavior is deterministic.

## Required test matrix

- Positive: object/View/structural/repeated/nested nodes, inheritance, patch,
  state predicate, and source navigation.
- Negative: unknown/ambiguous target, target without Style, stale frame,
  evicted resource, unsupported property, unavailable backend/source, and
  missing trace capability return exact typed outcomes.
- Tamper: forged IDs/privacy, malformed enums/refs/cursors/fields/integers,
  duplicates, and trailing data are rejected without panic.
- Budget: exact-limit and one-over tests for every target/property/event/source/
  byte/resource/page limit; partial order and cursors are deterministic.
- Redaction: public through highest authorized tiers prove no leakage through
  values, snippets, paths, diagnostics, hashes, lengths, cursors, or caches.
- Cache/lifecycle: reads are byte-stable; old URIs are immutable; revisions,
  eviction, and privilege isolation are explicit.
- Backend: equal snapshots yield equal native/web/headless semantic JSON;
  missing geometry/image support is a typed backend limitation.
- Adapter parity: in-process, CLI JSON, MCP tool/list/read preserve the same
  schema and codes.

## Expected design output and acceptance

Produce a new standalone design document or package containing:

- normative Rust request/response/resource/diagnostic types and an ownership
  diagram from player resolver to Agent protocol to CLI/MCP;
- an identity/correlation table for View nodes, observed views, presentation
  objects, repeats, nested mounts, and structural nodes;
- canonical JSON/URI lifecycle examples and budget, paging, redaction,
  source-map, cache, diagnostic, and backend tables;
- an implementation sequence and the full positive, negative, tamper, budget,
  redaction, cache, lifecycle, backend, and adapter-parity test matrix.

Acceptance requires one authoritative data path, exact mapping to the 5.1
portable trace rather than a second schema, bounded opt-in collection, no
cross-privilege leakage, and enough detail for implementation without reading
another request or reopening the verified native Style architecture.
