# seq-06.10c styled paragraph raster drift closure package request

## Sequence Position

This follows seq-06.10, seq-06.10a, and seq-06.10b. The seq-06.10b cut made native/Web CSS-style parity reports strict and renderer-owned: styled paragraphs now require v3 line/glyph evidence and no longer fall back to span-to-paragraph bounds.

## Why This Split Exists

After applying seq-06.10b locally, `just css-style-parity` generated all default/compact/HiDPI native and Web evidence, then failed because strict text-raster evidence exposes real native/Web drift:

| checkpoint | text runs | failed text runs | max mask xor | max bbox delta px | max centroid delta px | max coverage delta | full-image PSNR | full-image SSIM |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| default | 223 | 223 | 1.000000 | 56 | 56.002 | 1.000000 | 22.360 | 0.461 |
| compact | 127 | 127 | 0.988806 | 45 | 24.255 | 0.977636 | 20.260 | 0.431 |
| hidpi | 104 | 104 | 1.000000 | 54 | 26.724 | 0.925714 | 19.818 | 0.430 |

This request must close the actual drift. Do not weaken seq-06.10b by reintroducing legacy report fallback, hidden DOM text, browser CSS text, canvas 2D text, span-bound expansion, or threshold-only acceptance.

## Required Investigation

- Compare `target/css-style-parity/native-*.frame.json` and `web-*.frame.json` v3 evidence by paragraph, line, source byte range, style, scale factor, line box, and glyph/cluster bounds.
- Determine whether the first mismatch is caused by shaping segmentation, font registration, viewport/scale conversion, glyphon WASM/native differences, CSS-style sample authoring, capture target format, or raster mask extraction.
- Check whether native and Web call the same renderer evidence path with the same font bytes, `RenderViewport`, `visual_time_millis`, paragraph text, span styles, and line-height inputs.
- Check whether comparing runs by sequence index is correct after strict v3 evidence, or whether the verifier should use a typed source key keyed by paragraph index, line index, source range, reveal state, and style. If matching by key is needed, implement it without accepting missing keys silently.
- Keep full-image thresholds as a secondary gross-frame gate. Text layout/raster evidence must be the primary explanation path.

## Implementation Requirements

- Preserve seq-06.10b strictness: styled paragraphs without renderer-owned line/glyph evidence must fail.
- Make native and Web styled-paragraph evidence converge as far as possible by sharing the same typed inputs and renderer-owned measurement path.
- If a platform/backend raster difference remains after typed layout evidence is identical, encode that as an explicit backend raster tolerance with evidence and justification, not as unchecked threshold loosening.
- Keep `arcweft-render-wgpu` Sans I/O. File reads/writes, browser capture, and report emission remain in tools/adapters.
- Keep Web player canvas-only for game text. No DOM mirror or browser-layout text path may be added.
- Update `tools/verify-text-raster-parity.rs` only toward stricter typed matching or clearer diagnostics. Do not add compatibility parsing for old frame report schemas.
- Update `docs/implementation/seq-06.10b-styled-paragraph-raster-evidence-closure-2026-07-01.md` or add a seq-06.10c implementation note with the final cause and closure evidence.
