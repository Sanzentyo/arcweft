## Why this split is required

The accepted 01.1 contract requires `PredicateDecl` and `ProofDecl` to store a
`SyntaxNodeId`, but the current parser constructs the typed tree before the
incremental `SyntaxDatabase` assigns identities to the lossless Rowan tree.
There is no defined typed-node-to-Rowan-node attachment operation from which a
constructor can obtain the required ID without inventing an ID or reparsing
source text.

The same contract names `ProofBody::Block(ProofBlock)` but does not define the
fields, source ranges, tail-value representation, statement ownership, error
children, or constructor invariants of `ProofBlock`. Those choices affect
syntax identity allocation, HIR scope/statement/expression IDs, predicate tail
requirements, and atomic recovery. They must not be improvised independently
in parser and HIR code.

This request must close only those gaps. The implemented and verified
`SourceGeneration`, `SourceSnapshotId`, `SyntaxDatabase`,
`SyntaxIdentityMap`, semantic-shape reconciliation, reference syntax, and
prefix-expression substrate are fixed unless exact implementation evidence
shows a concrete defect.

## Repository policy that supersedes the historical contract

Current `AGENTS.md` does not permit permanent recognizers or diagnostic codes
whose only purpose is to remember an unreleased removed spelling. The final
state must not retain `syntax.removed.*` branches, historical CST/AST nodes, or
spelling-specific tests for `proof @...`, `trusted axiom`, provisional proof
clauses, or `calc`. A temporary recognizer may be used during deletion and must
then be removed. Final negative coverage must exercise ordinary current-grammar
recovery and observable typed parser behavior.

## Required decisions

### 1. Typed AST to syntax identity attachment

Specify one exact, owned API and data flow that binds every source-backed typed
item, statement, expression, pattern, and type to the `SyntaxNodeId` allocated
for its lossless node. Decide:

- whether IDs live directly in typed nodes, in a typed syntax handle, or in a
  snapshot-owned typed-to-syntax table;
- the exact constructor visibility and which phase is allowed to attach IDs;
- how `parse_source` and other non-database parser facades behave without a
  caller-supplied `SourceSnapshotId`;
- how recovery nodes, missing children, desugared nodes, and copied/moved nodes
  receive or resolve identity;
- how ranges and IDs remain aligned after trivia edits and reconciled reparses;
- how callers obtain an ID without integer construction, source searching, or
  a local extension trait;
- what a stale or cross-snapshot typed-node lookup returns.

The answer must include exact Rust type signatures and one end-to-end sequence
from source bytes through lossless parse, identity reconciliation, typed AST,
and HIR lowering. It must preserve atomic failure: fatal parse/identity failure
commits no generation, typed tree, or ID allocation.

### 2. Exact `ProofBlock` contract

Define the concrete Rust type, fields, constructors, accessors, and ranges for
`ProofBlock`. At minimum decide:

- ordered typed statements and optional/required tail expression ownership;
- complete block range and brace ranges, including a missing closing brace;
- identity for the block, each statement, and the tail expression;
- how an expression body differs from a one-expression block;
- predicate requirement for a Boolean tail;
- Unit and non-Unit proof tail rules;
- representation of recovered/poisoned statements and tails;
- the exact point at which the 256-clause and body/diagnostic limits fail;
- whether proof-call expression statements and `assert.prove` are represented
  by existing current typed nodes or a new owned boundary type.

Do not store a source-body string for later reparsing. Do not clone line-plan
assertion types into proof bodies.

### 3. Parser and lowering integration

Specify the exact implementation order and responsibility modules for:

1. current predicate/proof grammar and typed body construction;
2. syntax identity attachment;
3. source-backed HIR ID allocation and proof/predicate lowering;
4. deletion of `ProofItem`, old `ProofClause` variants,
   `TrustedAxiomItem`, and every caller;
5. semantic validation of allowed body shapes without proof discharge.

State how the design consumes the accepted Character `SourceDocumentIdentity`
for content provenance while keeping proof 01.1 `SourceSnapshotId` as the
separate incremental-lineage identity. Do not introduce another source-name,
source-span, or project-symbol authority.

### 4. Direct test matrix

Specify public/API-level tests for:

- initial parse and trivia-only reparse preserving predicate/proof typed-node
  and descendant IDs;
- changed, moved, copied, and recovered proof-body nodes following the accepted
  reconciliation rules;
- expression and block bodies, predicate Boolean tails, Unit/non-Unit proof
  tails, pure lets, proof calls, and `assert.prove`;
- missing name/parameter close/body/block close with exact current-grammar
  ranges and poisoned typed nodes;
- failed identity allocation and limit overflow consuming no generation or ID;
- stale and cross-snapshot typed-node/HIR lookup returning typed errors;
- ordinary rejection of removed provisional spellings without a dedicated
  removed-spelling recognizer or source-text gate;
- no string reparsing from AST through HIR.

Tests must use parser, syntax-database, HIR, and semantic APIs. Do not search
checked-in source or documentation text.
