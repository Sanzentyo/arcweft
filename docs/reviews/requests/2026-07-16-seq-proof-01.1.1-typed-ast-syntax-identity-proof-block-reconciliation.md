## Current production evidence that the design must reconcile

The following facts describe the current verified production starting point.
Inspect and confirm them against latest `main`; if a fact has changed, cite the
exact replacement implementation rather than silently designing against an old
shape.

### Flat lossless CST and separately constructed typed tree

- `arcweft-lang-syntax::cst::SyntaxKind` currently has coarse `Root`, `Line`,
  `Error`, and token kinds, not grammar nodes for declarations, statements,
  expressions, patterns, or types.
- `parse_cst` currently builds `Root -> Line -> token`.
- `parser::parse_source` first builds that flat lossless tree and separately
  constructs `TypedSyntaxTree` from line events and nested fragment parsers.
- `incremental::SyntaxIdentityMap` maps Rowan `SyntaxNode` values to
  `SyntaxNodeId`, so the current map can identify roots and lines but cannot
  provide one distinct lossless-node identity for several same-kind typed
  descendants on one line.
- The current semantic-parent reconciliation layer derives brace/indent parents
  over flat lines. It is verified for its observable trivia, move, copy,
  recovery, and atomicity behavior, but it is not a grammar-level attachment
  path.

An attachment API layered over the unchanged flat tree is therefore not a
valid solution. In particular, assigning one line ID to several expressions
would collide under the source-backed HIR key `(SyntaxNodeId, HirIdKind)`.
Range searching, source-text matching, reparsing, and traversal-order IDs are
also invalid solutions.

### Implemented identity and language substrate

- `arcweft-source` owns `SourceDocument`, `SourceDocumentIdentity`, exact
  revision-bound `SourceSpan`, `SourceGeneration`, and `SourceSnapshotId`.
- `SourceDocumentIdentity` is exact content provenance. `SourceSnapshotId` is
  an in-memory incremental lineage identity. They are different authorities and
  must remain different.
- `SyntaxDatabase` atomically commits initial parses and reparses, retains the
  exact `SourceDocument`, advances generations only for successful byte-changing
  reparses, never reuses syntax IDs, and rolls back on fatal limits or identity
  exhaustion.
- `BorrowKind`, shared/mutable reference types, prefix borrow/dereference,
  current reference semantic behavior, and `AssertionMode` plus typed
  `assert.prove/check/debug` statements are implemented and verified.
- The obsolete borrow block has already been deleted. Production has no
  `BorrowBlock`, `HirBorrow`, removed-syntax recognizer, historical CST/AST/HIR
  node, or executable compatibility path.
- `arcweft-lang-hir::identity` contains private-raw, module-qualified typed ID
  vocabulary and typed stale-ID errors, but production does not yet have the
  final `HirDatabase`, immutable arenas, live intervals, or transaction owner.
- Current `HirModule` is still largely a Vec/clone model that contains syntax
  values. `HirProject::linked_module`, `HirModule::append_module_body`, and
  compiler `linked_hir` callers still form a transitional flattened view.
- The Character reconciliation owns one generalized `ProjectSymbolTable` and
  exact source-backed symbol provenance. Predicate/proof registration must
  extend that authority, not recreate `CallableSymbolTable` or a proof-only
  table.
- `arcweft-core::effect::RuntimeAssertion` is a serialized runtime-data payload
  containing materialized condition/message/profile data. `arcweft-core` must
  not depend on syntax or HIR. Session-only `StmtId` therefore cannot simply be
  inserted into that serialized core payload.
- The provisional proof path still includes source-body strings, authored
  proof artifact IDs, old proof clauses, and trusted axiom syntax. Those are
  deletion inventory, not compatibility requirements.

## Fixed verified substrate

The final design must preserve these public owners and observable invariants
unless exact current implementation evidence proves a concrete defect:

1. `SourceDocumentIdentity` for exact content provenance and
   `SourceSnapshotId` for session-local incremental lineage;
2. `SyntaxDatabase` transaction atomicity, no-op behavior, generation rules,
   never-reused syntax IDs, private raw ID construction, and non-Serde session
   identity;
3. current tested reconciliation results for trivia-only edits, unchanged
   siblings, same-parent reorder, cross-parent moves, copies, recovery changes,
   and deterministic failure rollback;
4. the one owned `BorrowKind`, final reference/prefix grammar and semantics,
   and the current typed assertion modes and purity/context policy;
5. exact revision-bound `SourceSpan` construction through `SourceDocument`;
6. the unified `ProjectSymbolTable`, existing canonical module/package/symbol
   identities, and Character registration/source provenance; and
7. Sans-I/O and dependency direction:
   `source/syntax -> HIR -> sema -> runtime-plan/verify -> tooling`, with
   `arcweft-core` remaining runtime/data core and not depending on compiler
   layers.

Preserve behavior and ownership, not an insufficient internal representation.
The following are explicitly permitted to change where required by the final
contract:

- the flat `Root -> Line -> token` CST shape and `SyntaxKind` inventory;
- the line-only semantic-parent implementation, while preserving its accepted
  observable reconciliation outcomes for the corresponding grammar nodes;
- range-less nested typed enums and parser event plumbing;
- the Vec/clone syntax-as-HIR representation;
- current lowering facade signatures that accept a detached
  `TypedSyntaxTree` without its source snapshot; and
- linked/flattened HIR and callers that depend on it.

Do not redesign already verified reference syntax, borrow-kind semantics,
assertion mode semantics, source provenance, symbol authority, or reconciliation
policy merely because their internal callers must migrate.

## Repository policy that supersedes historical diagnostics

Current `AGENTS.md` prohibits permanent recognizers, diagnostic codes, CST/AST
kinds, and spelling-specific tests whose only purpose is to remember unreleased
removed syntax. The final production state must contain no `syntax.removed.*`
branch or historical node for:

- `borrow EXPR as NAME: TYPE { ... }`;
- `proof @...`;
- `trusted axiom`;
- provisional proof clauses; or
- `calc`.

A temporary recognizer may be used only during implementation to prove that a
removed form no longer lowers or executes, and must be deleted before the cut
completes. Final negative tests must use ordinary current-grammar recovery and
prove the absence of an executable typed node through public or crate-owned
APIs. No test, script, CI rule, or audit may search checked-in source or
documentation for symbol spellings, paths, or snippets.

### 1. Grammar-level lossless tree and identity-bearing node inventory

Define the final Rowan grammar-node model that replaces or enriches the flat

  attributes/doc ownership, recovery nodes, and missing tokens;

## Direct test matrix

The returned contract must specify exact test names/owners, public or
crate-owned APIs called, inputs, outputs, errors, ranges, identity comparisons,
and atomic state evidence for every group below. Tests must not inspect source
or documentation text.

### Lossless and typed attachment

- A declaration containing several same-kind expressions, patterns, and types
  on one physical line gives every identity-bearing grammar node a distinct ID.
- Initial parse and trivia-only reparse preserve predicate/proof items, clauses,
  block, statements, tail, and nested expression/type/pattern IDs while updating
  ranges.
- Changed, same-parent reordered, cross-parent moved, copied, recovered, and
  missing-child nodes follow the accepted deterministic reconciliation rules.
- Rowan-node-to-typed and typed-to-Rowan lookup round trips without range or
  source search.
- Stale generation, wrong snapshot, and two independent databases parsing the
  same `SourceName` and bytes return typed lookup errors rather than resolving a
  colliding counter value.
- Fatal parse/attachment/limit/identity failure consumes no generation,
  diagnostic state, typed tree, or ID; the next valid parse receives the IDs it
  would have received without the failed transaction.
- Bound document parse, unbound fragment parse, and explicit attachment APIs
  cannot be accidentally interchanged at compile time.

### Predicate, proof, and `ProofBlock`

- Complete grammar matrix for visibility, generics, fixed parameters,
  destructuring, where clauses, requires/ensures order, expression/block bodies,
  predicate Boolean tails, Unit/non-Unit proof tails, and ordinary-name
  collisions/imports.
- Pure lets, proof-call expression statements, `assert.prove`, missing tail,
  empty block, one-expression block, and expression body have exact typed shapes
  and ranges.
- Predicate assertion rejection and proof `assert.check/debug` rejection are
  semantic/context errors, not reparsed strings.
- Missing name, malformed generic/header, missing parameter close, missing body,
  missing block close, malformed statement/tail, and poisoned descendants retain
  exact current-grammar ranges and non-executable typed nodes.
- Exact and one-over predicate parameters, proof parameters, total clauses,
  statements, expressions, types, patterns, diagnostics, and identity budgets
  prove inclusive limits and atomic rollback.
- Removed provisional spellings receive only ordinary current-grammar recovery
  and never produce an executable predicate/proof/trusted/borrow/calc node.

### HIR arenas and lowering

- Every source-backed syntax node maps to the correct typed HIR ID/kind; several
  same-kind HIR nodes on one line do not collide.
- Trivia, unchanged, moved, copied, recovered, retired, and synthetic nodes have
  the specified cross-revision identity behavior.
- Old snapshot resolution, current snapshot retirement, not-yet-live IDs,
  wrong-module IDs, wrong-kind corruption hooks, and cross-database input return
  exact typed errors and never panic.
- Root/nested scopes, pre-binding let initializers, destructuring order,
  duplicate/poisoned patterns, `_`, sequential shadow generations, control-flow
  scopes, closure parameters, repeated captures, and inner shadowing match the
  final arena contract.
- Exact and one-over every HIR limit plus seeded module/revision/slot/local
  generation exhaustion prove that failed transactions consume no arena entry,
  tombstone, revision, cache fact, or counter.
- A behavior fixture whose non-authoritative display/source string intentionally
  disagrees with its typed child proves lowering follows the typed child. The
  test uses a crate-owned typed builder or equivalent direct API, never a source
  scan.
- Recovered HIR can be queried by tooling but cannot enter sema/codegen/runtime
  caches as executable.

### Project and symbols

- Per-module HIR IDs remain unchanged through ordered project iteration; no
  linked/flattened module exists.
- Project construction rejects package/path/source mismatches through typed
  errors rather than mutation or panic.
- `ProjectSymbolTable` registers functions, predicates, proofs, and Character
  declarations in one revision-bound table and directly tests duplicate names,
  visibility, imports, aliases, and invalidation.
- Compile-fail tests prove linked/append APIs, provisional proof types, authored
  proof IDs, raw session-ID constructors, and session-ID Serde are absent.

### Runtime assertion fault

- `Check` and enabled `Debug` failure metadata retain the exact `StmtId`, checked
  condition index, `AssertionMode`, and revision-bound `SourceSpan`.
- Multiple assertion conditions map authored order to zero-based condition
  identity exactly; invalid indices fail typed.
- `Prove` has no runtime guard/fault constructor, and release output omits Debug
  condition evaluation and identity entries.
- Persisted core/AWBC/bundle/save/checkpoint/cache codecs round trip without any
  HIR/session identity; a structured dependency-graph test confirms
  `arcweft-core` does not depend on HIR or syntax.
- Runtime/CLI/LSP/Agent/debug projection emits `runtime.assertion_failed` and
  source evidence without parsing message text for identity.
- Reloading persisted data does not claim equality with an old `StmtId`; any
  fresh-session association follows the explicitly designed lookup contract.

### Deletion, tooling, and recovery

- Parser, formatter, LSP, CLI, compiler, sema, verifier, runtime-plan, project,
  and cache tests consume the final typed/arena APIs.
- Ordinary malformed-input recovery preserves following current declarations
  after removed syntax without a spelling-specific production recognizer.
- Direct API/compile-fail tests prove removed public nodes and linked HIR are
  unavailable.
- No test searches checked-in source, paths, symbols, snippets, or
  documentation to prove implementation shape.
