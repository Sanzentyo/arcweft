# Request: seq-06.16.4.1 runtime-control backdrop-filter contract

## Sequence Position

This request is split from seq06.16.4 after translucent runtime-control fills,
`box-shadow`, rounded corners, and style-authored control depth were wired into
the player-rendered TextField/TextArea/Button path.

It must not redesign the already implemented runtime-control visual style
payload unless current evidence shows a concrete flaw.

## Why This Split Exists

`samples/modern-feedback-ui` can now use alpha, opacity, radius, shadow, and
z-index from authored style. CSS-like glass blur is still not a runtime-control
feature: player-owned text controls and buttons are emitted as overlay
rectangles, shadow plans, and text blocks after images/backgrounds, not as UI
compositor nodes with backdrop sampling.

The existing compositor has blur and backdrop concepts for retained UI scenes,
but runtime controls do not currently enter that rendering contract.

## Required Decisions

- Decide whether runtime controls should:
  - lower into retained `UiScene` nodes for visual effects while preserving
    text-input editing, hit-testing, accessibility, and IME semantics; or
  - keep the current overlay renderer and gain a dedicated backdrop-filter pass.
- Define the typed style payload for `backdrop-filter` / `filter` support:
  property names, accepted values, units, diagnostics, and unsupported cases.
- Define paint order with images, UI compositor scenes, runtime-control shadows,
  control fills, selections, carets, and text.
- Define whether backdrop blur samples only prior image/UI content or also
  earlier lower-depth runtime controls.
- Define native and web exact capture expectations before any baseline
  promotion.

## Implementation Order

1. Add parser/resource diagnostics tests for supported and unsupported
   `backdrop-filter` values.
2. Add a typed runtime-control effect payload without changing existing alpha,
   shadow, radius, or depth semantics.
3. Implement either a retained-UI lowering path or a dedicated renderer pass.
4. Preserve text editing, selection, shortcut, tab policy, focus navigation, and
   action-button activation tests.
5. Update `samples/modern-feedback-ui` to use the new blur only after it renders
   in native and web through the same typed data path.
6. Add pinned visual evidence only from the approved exact visual-golden
   environment.

## Tests To Specify

- `backdrop-filter: blur(12px)` resolves into a typed runtime-control effect.
- Unsupported filter functions produce structured diagnostics.
- A translucent control with blur samples the background image deterministically.
- A higher-depth runtime control blurs only the defined prior content.
- Text selection, caret, IME composition, and action-button hit-testing still
  match the non-blur path.
- Native and web captures agree within the exact visual-golden policy.

## Constraints

- Do not fake blur with DOM/CSS overlays, screenshots, or sample-specific image
  baking.
- Do not make `arcweft-core` or data-format crates depend on GPU, platform, or
  filesystem APIs.
- Keep unsupported blur properties diagnosed until the renderer path exists.
- Do not update checked-in PNG baselines from an unpinned environment.

## Expected Output

Return a design package that includes the runtime-control backdrop-filter
contract, renderer ordering model, diagnostics, tests, sample update plan, and
native/web visual evidence requirements.
