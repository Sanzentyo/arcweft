## Why a correction is required

The accepted final payload is exactly:

```rust
pub struct HirCallExpr {
    callee: HirCallCallee,
    arguments: Box<[HirCallArgument]>,
}

pub enum HirCallArgument {
    Positional { value: ExprId },
    Named { name: HirName, value: ExprId },
    Spread { value: ExprId },
}
```

`HirName::try_new` accepts only a valid authored identifier. There is no
recovered name or invalid argument carrier in `HirCallArgument`.

The accepted E12/C01-C03 lowering and test rows simultaneously require all of
the following:

- missing or invalid named-argument names and values keep the known `Call`
  family as typed poison;
- missing positional and spread values keep the same known family and exact
  `CallArgument[n, Whole|Name|Value]` source ownership;
- `SpreadNotLast` and `PositionalAfterNamed` are typed Call poison outcomes;
- a known Call must not collapse to generic `HirExprKind::Error`; and
- no valid name, `ExprId`, range, argument, or sentinel may be fabricated.

The accepted `HirCallExpr::try_new` instead rejects positional-after-named and
spread-not-last with `Err`, while the payload has no place to retain those
invalid arguments. `HirCallIssue` also has no missing/invalid argument name or
value variant. Consequently, an implementation can only fabricate a
`HirName`/`ExprId`, drop or reclassify an argument, discard the known Call
payload, or silently publish a clean payload. Every option contradicts the
accepted package or repository constraints.

There is a second representation gap for dot-member calls. The contract says
that a value lookup owns `receiver.member(...)` when it is present or reports
a terminal value error, and only definitive value absence permits nominal
type fallback. The exact final `HirCallCallee` stores either the value
`ExprId` or the associated receiver `TypeId`, never both. Before semantic
lookup, attached syntax cannot truthfully discard either interpretation;
after choosing `Value`, the generic/alias-preserving type evidence needed for
fallback is gone, while choosing `AssociatedType` loses the value receiver.
Source-text reparsing or fabricating the missing candidate is prohibited.
The correction must therefore identify the exact typed owner and stage that
retains sufficient evidence until value-first classification is final.

The final source-role schema also omits the delimiter and separator facts
needed by the already accepted AW-AH-009.3 signature-focus matrix. Active-slot
selection distinguishes the opening/closing delimiter or recovery end, every
comma, a trailing comma, empty arguments, and one-past positions. A final
`HirCallExpr` plus the accepted source queries cannot distinguish those cursor
surfaces, while Proof requires tooling to consume final typed owners without
falling back to attached syntax. The correction must close this ownership gap
rather than silently preserving a second tooling reader.

## Required decisions

### 1. Exact recovered call and argument representation

Choose and specify one authoritative final representation for every clean and
recovered E12/C01-C03 case. It must cover, without fabrication:

- missing callee;
- missing positional value;
- missing or invalid named-argument name;
- missing named-argument value;
- missing spread value;
- missing or invalid associated member;
- duplicate named argument;
- positional argument after a named argument; and
- spread argument that is not last.

Provide complete Rust schemas, constructor invariants, visibility, accessors,
equality/hash behavior, and exact poison issues. State whether a recovered
argument remains in authored order and whether its valid subcomponents remain
queryable. If the selected model revises the matrix so a malformed case does
not retain `HirExprKind::Call`, give its exact final payload and reconcile it
with the known-family/generic-error rule.

Do not use an empty/invented `HirName`, a sentinel `ExprId`, an argument drop,
a positional rewrite of a malformed named argument, or a wrapper around the
accepted provisional schema.

### 2. Exact semantic child and synthetic ownership

Restate the complete semantic-child order for the callee and every argument
form. For each missing value, specify the exact `SyntheticKey` owner, role,
ordinal, resulting child payload, and poison propagation. Explain whether a
missing/invalid name has a synthetic HIR child; if it does not, specify its
typed non-ID owner.

Ordinals must derive from a closed semantic-role order, not vector position,
diagnostic order, or work scheduling. State exact and one-over behavior for
the accepted `RecoveryOperand` range and for the 128-argument limit.

### 3. Exact source-component manifest and queries

Restate all E12/C01-C03 source rows for:

- `Whole`;
- `Callee`, or `AssociatedReceiver`, `AssociatedSeparator`, and
  `AssociatedMember`;
- `CallArgument { argument, part: Whole|Name|Value }`; and
- every recovery insertion or typed invalid component.

For every clean and malformed argument form, distinguish `Span`, `Insertion`,
`AbsentOptional`, `RoleNotApplicable`, and poisoned-but-present source. State
how a source component remains attached to the accepted source revision when
its semantic value is invalid. Do not put source ranges inside names or
argument payloads.

Also define the sole final typed owner and query surface for signature-focus
cursor selection. It must preserve exactly:

- opening delimiter;
- closing delimiter or missing-close recovery end;
- every argument separator;
- authored trailing comma;
- empty argument-list insertion; and
- the exact active slot at argument boundaries and one-past the last argument.

Restate and reconcile AW-AH-009.3 matrix rows R04, R05, R08, R09, R13, and
R14. State whether these coordinates extend `HirExprSourceRole`, belong to a
typed final call-surface record, or use another single final owner. A tooling
fallback to attached syntax, detached `ArgumentListSyntax`, source text, or a
second cursor scanner is prohibited.

### 4. Constructor, lowering, resolver, and rollback order

Give the exact production order from attached syntax through final HIR and
the one shared callable resolver, including:

- the exact attached/final typed owner of an unresolved dot-member receiver,
  and the exact stage that selects value versus associated-type callee;
- ordinary value callee versus typed associated-type callee after that
  classification, without source reparsing or a parallel call HIR;
- dot value-first/nominal-second fallback and explicit `::` nominal-only
  semantics;
- root/child reservation, recovery generation, source-manifest staging,
  poison binding, candidate/result accounting, and publication;
- exact and one-over charges for arguments, depth 32, candidates 2, and
  results 2; and
- retry identity and diagnostic behavior after rollback.

A hard failure must publish no partial ID, source row, diagnostic, candidate,
result, or work fact. The correction must preserve bare generic arity failure
and must not reintroduce a Capacity-only dispatcher or string receiver parser.

### 5. Complete E12/C01-C03 evidence matrix

Provide standalone `T-E12`, `T-Q-12`, `T-RB-12`, and complete component rows
covering at least:

- clean value and associated-type calls;
- every malformed case listed in Required decision 1;
- exact payload, authored argument order, poison issue, synthetic key, and
  source role;
- stale revision, foreign document/module, retired owner, accepted synthetic

- 128 arguments versus 129, depth 32 versus 33, candidates 2 versus 3, and
  results 2 versus 3;
- registered/non-registered resolver parity and exact single checking of each
  authored or recovered argument slot;
- checker facts and signature-help candidate identity; and

Tests must exercise `ParsedSource -> attached semantic node -> staged final
