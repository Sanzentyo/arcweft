# Seq05.4.2.1 follow-up: MCP/LSP CLI-local command-result adapters

Date: 2026-06-29
Depends on: seq05.4.2 CLI REPL inspection/debug command adapter

## Problem

Seq05.4.2 adds `CliReplCommandResult` for CLI-owned inspection/debug commands. Existing seq05.4.1 follow-up work covers shared `ReplCommandResult` surfaces, but protocol adapters must not accidentally consume terminal-formatted CLI text for CLI-local command families such as `:trace`, `:capture`, `:query`, or `:connect`.

## Request

When a stable MCP or LSP REPL command endpoint exists, add protocol adapters that can serialize both shared `ReplCommandResult` and CLI-local `CliReplCommandResult` as structured JSON evidence. Do not move terminal human formatting into MCP/LSP crates.

## Required decisions

1. Whether CLI-local result JSON remains private to `arcweft-cli` or moves to a small shared tooling adapter crate.
2. Which CLI-local commands are meaningful for remote protocol clients.
3. How protocol requests represent read-only trace policy for CLI-local mutating commands.
4. How protocol adapters avoid depending on filesystem/capture/MCP transport state that only exists in the CLI process.

## Constraints

- Do not redesign `ReplCommand`, `ReplCommandResult`, or `CliReplCommandResult`.
- Do not parse human terminal text.
- Do not add CLI terminal dependencies to MCP or LSP crates.
- Do not add task/capture/debug state to product player crates.

## Acceptance criteria

- Protocol JSON is typed evidence, not formatted text.
- Shared and CLI-local command results have deterministic schema tests.
- Read-only rejection is represented with `read_only_trace_rejected` diagnostics.
- Product player crates do not depend on REPL, CLI, MCP, LSP, or debug inspection adapters.
