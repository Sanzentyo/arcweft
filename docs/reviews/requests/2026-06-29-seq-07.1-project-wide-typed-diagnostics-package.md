# Seq-07.1 Request: Project-Wide Typed Diagnostics Package

## Sequence Position

Seq07 follows the diagnostics renderer foundation applied from
`arcweft-diagnostics-impl.zip` on 2026-06-29. That cut added shared
`arcweft-source::Diagnostic` data, parser/lint suggestions, and a CLI
`annotate-snippets` renderer. Seq07.1 should extend that substrate across the
compiler/project/LSP paths that still carry diagnostics as plain strings or
lossy message collections.

Do not redesign the parser/lint diagnostic substrate or move
`annotate-snippets` below `arcweft-cli`.

## Current Evidence To Audit

Inspect current `main` and at least:

- `docs/implementation/diagnostics-renderer-foundation-2026-06-29.md`
- `crates/arcweft-source/src/lib.rs`
- `crates/arcweft-lang-syntax/src/parser/recovery.rs`
- `crates/arcweft-lang-syntax/src/lint.rs`
- `crates/arcweft-cli/src/app/diagnostics.rs`
- `crates/arcweft-cli/src/app/project.rs`
- project and persistent compiler modules that expose `ProjectCompileDiagnostic`,
  `Vec<String>`, or message-only diagnostic collections
- `crates/arcweft-lsp/` and related LSP diagnostic conversion code

## Problem

The direct-source CLI path now has structured diagnostics, but project-wide
compile/check paths can still lose stable codes, labels, notes, source spans,
and machine-applicable fixes by collapsing errors to strings. That makes CLI,
LSP, Agent, and future IDE surfaces drift.

## Request

Produce a zip package that designs and implements seq07.1 project-wide typed
diagnostics.

## Required Decisions

1. Which project/compiler diagnostic structures should own
   `arcweft_source::Diagnostic` directly.
2. Where source names and source text snapshots are available and how missing
   source text should be represented.
3. How project-level diagnostics preserve stable codes from parser, lint, HIR,
   semantic, typecheck, persistent query, and runtime-plan phases.
4. How LSP diagnostics are derived from the shared type without depending on
   CLI rendering.
5. How CLI project/check commands render multiple source files deterministically.
6. Which legacy string-only fields can be deleted immediately.
7. Which message-only external errors are intentionally left as source-less
   diagnostics and why.

## Required Implementation Scope

- Replace project-wide `Vec<String>` or equivalent compile diagnostic payloads
  with typed `arcweft_source::Diagnostic` where dependency direction permits.
- Preserve source ranges and source names for parser/lint/HIR/sema/typecheck
  diagnostics whenever current data has them.
- Add source-less typed diagnostics for errors that truly have no source span.
- Route CLI project/check output through `DiagnosticEmitter` instead of
  hand-written one-line diagnostic loops.
- Update LSP conversion to consume the shared typed diagnostics, including
  stable codes, severity, labels, notes, and machine-applicable edits where LSP
  supports them.
- Keep `annotate-snippets` confined to `arcweft-cli`.
- Delete superseded stringly diagnostic helpers rather than keeping compatibility
  shims.
- Add regression tests for multi-file project diagnostics and LSP conversion.
- Add an implementation note under `docs/implementation/`.
