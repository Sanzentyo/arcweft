# Design request: seq-06.11d.4.2 native environment Style-condition contract

- Date: 2026-07-14
- Kind: independently throwable design request
- Output language: English

## Sequence position and delivery boundary

This is an independent adaptive-Style design cut after the implemented
seq-06.11d.1 native typed Style, d.2 sheet-owned canonical product, and d.3
single computed-style resolver. It defines source authoring and end-to-end
semantics for closed presentation-environment conditions. It neither depends
on nor designs container queries.

This file is the complete task input. The requested result is one final,
implementation-ready contract. Do not require a previous design request,
package, or external link to resolve a decision.

## Problem and background

The canonical Style model and resolver can represent typed conditions for color
scheme, contrast, reduced motion, and text scale, and runtime already carries a
typed `PresentationEnvironment`. `.arcw` Style authoring, however, has no final
closed grammar for those conditions. Without that contract, parser/lowering
cannot distinguish an environment guard from a general runtime expression,
specificity semantics are unclear, diagnostics and tooling cannot be stable,
and environment revisions may invalidate more or less Style state than intended.

The feature must be declarative and deterministic. It is not a general `if`
expression over runtime state and is not a CSS media-query implementation.

## Confirmed substrate that must be preserved

- Style has one native typed pipeline from syntax through checked catalog,
  compiler-owned `ViewStyleProgram`, runtime applications, and the sole
  `arcweft-view` computed resolver.
- `ViewEnvironmentPredicate` is a closed typed product inventory with reduced-
  motion boolean, color-scheme comparison, contrast comparison, and text-scale
  comparison forms. `ViewStyleComparison` is also typed.
- `PresentationEnvironment` is the runtime authority for `ColorScheme`,
  `ContrastPreference`, reduced motion, text scale, locale, and an explicit
  environment revision. Native, web-hosted, and headless players feed the same
  typed resolver contract.
- The resolver evaluates the existing environment predicate forms and includes
  environment values/revision in computed-style cache identity. Trace rejection
  already distinguishes an environment mismatch.
- Sheet ownership, tokens, source/declaration/application order, inheritance,
  typed invalidation, work budgets, and deterministic cache behavior are
  implemented.
- Canonical product codecs serialize typed Style rules/predicates and validate
  them without reopening source files.
- Source Style rules currently have selector/state authoring but no complete
  environment-condition AST/HIR/sema surface.

One known question must be resolved narrowly: if environment guards are carried
as selector predicates, the implementation must prove whether they contribute
to selector specificity. Activation conditions normally gate a rule rather than
make it more specific. If the current representation gives the wrong priority,
that is a concrete defect eligible for a focused model/resolver correction; it
does not justify a second cascade or broad resolver redesign.

## Required decisions

1. Define the single canonical `.arcw` grammar and placement for an environment
   condition. Show whether it wraps rules, attaches a typed guard to one rule,
   or uses another closed form. Include exact formatter output.
2. Define the complete first-cut field inventory and source names for color
   scheme, contrast, reduced motion, and text scale. Do not leave aliases.
3. Define legal operators per field. Enum/boolean fields should not inherit
   ordered comparisons accidentally; numeric text scale must define equality
   and ordering precisely, including accepted unit and range.
4. Define boolean spelling for reduced motion, including whether a bare positive
   form, explicit equality, and negation are allowed. Select one canonical form
   and specify formatter normalization without retaining multiple semantic
   spellings unnecessarily.
5. Define grouping, conjunction, disjunction, negation, and nesting for the first
   cut. If only one condition or an implicit conjunction is supported, reject
   the rest structurally; do not fall back to the general expression checker.
6. Define AST, HIR, checked-sema, compiler, product, codec, and resolver types
   and source ranges. The checked form must contain typed field/operator/value,
   not expression text.
7. Define cascade semantics. State exactly whether environment conditions affect
   selector specificity (and why), how two active guarded rules compete, and how
   guarded and unguarded rules interact under the existing priority tuple.
8. Define rule normalization when a condition wraps multiple selectors/rules or
   is nested with another accepted condition. Preserve authored rule and
   declaration order deterministically.
9. Define runtime authority and defaults for native, web-hosted, and headless
   execution. Clarify who may update `PresentationEnvironment`, how revisions
   advance, and how equivalent repeated snapshots are handled.
10. Define cache and invalidation behavior for each field change. State whether
    dependency information permits invalidating only rules/nodes that reference
    the changed field, how inherited computed values propagate, and how stale
    transitions are canceled or rebased.
11. Define trace/explain output for active, inactive, malformed-at-build, and
    unavailable environment facts. Provenance must identify the condition and
    source range without storing/reparsing source text at runtime.
12. Define canonical codec validation and tamper behavior for unknown field
    tags, illegal field/operator pairs, out-of-range values, invalid nesting,
    impossible source ranges, and product merge.
13. Define structured parser and semantic diagnostics for unknown fields,
    misspelled enum cases, illegal operators, wrong value kinds, out-of-range
    text scale, unsupported boolean/group syntax, and illegal placement.
14. Define formatter and LSP completion, hover/type display, semantic tokens,
    code actions, definition/reference behavior for enum cases/tokens, and
    incremental diagnostic invalidation.
15. Define how reduced motion affects Style selection versus transition
    execution. A condition may choose declarations; any global transition-
    suppression policy must remain an explicit, separately owned runtime rule.

## Constraints

- Do not introduce CSS media queries, CSS source, Takumi, browser match-media,
  CSSOM, or an adapter-owned condition path.
- Do not permit arbitrary runtime expressions, function calls, state reads,
  user variables, clocks, viewport strings, or host callbacks in a Style
  condition.
- Preserve seq-06.11d.1-d.3 syntax/HIR/sema ownership, sheet-owned product,
  resolver priority, typed values, and one cascade unless the specificity issue
  above is demonstrated as a concrete defect.
- Runtime and codecs must consume typed condition records and
  `PresentationEnvironment`; they must not parse source strings.
- Keep host environment acquisition outside Sans-I/O core/data crates.
- Use a single authoritative environment revision contract across native,
  web-hosted, and headless paths.
- The surface is unreleased. Choose the final form directly; no aliases, dual
  parsers, deprecated fields, migration readers, or compatibility wrappers.
- Do not add a source gate. Validate parser, sema, product, codec, runtime, trace,
  and tooling behavior through their owned APIs.
- Preserve deterministic fixed-point text scale, bounded work, stable source
  provenance, and current crate dependency direction.

## Non-goals

- Container size/style queries, viewport queries, device-class detection, or
  arbitrary feature probes.
- CSS media-query syntax or browser parity.
- A general conditional expression language inside Style.
- OS preference polling inside `arcweft-core`, `arcweft-view`, or bundle codecs.
- New color-scheme, contrast, accessibility, or locale values beyond the closed
  first-cut inventory unless the design explicitly justifies their typed model.
- Redesigning theme palettes, system-color resolution, property values,
  rendering, or the View evaluator.

## Required implementation order

1. Freeze the closed field/operator/value truth table and canonical source
   grammar, including grouping limits and formatter form.
2. Specify AST/HIR checked types, exact ranges, recovery, and the diagnostic
   catalog.
3. Decide activation-versus-specificity semantics and make the smallest typed
   product/resolver correction required by that decision.
4. Specify compiler lowering, deterministic rule normalization, source maps,
   codec validation, and merge behavior.
5. Specify host snapshot/revision authority and dependency-aware runtime
   invalidation across native, web-hosted, and headless players.
6. Add trace/explain, formatter, and LSP behavior.
7. Implement positive, negative, priority, revision, codec, runtime, and tooling
   tests before declaring environment authoring supported.

## Required test specification

### Grammar, HIR, sema, and diagnostics

- Each legal field/operator/value form parses with exact ranges, lowers to a
  closed HIR/check record, and formats idempotently.
- Unknown fields, invalid enum cases, boolean misuse, illegal ordered
  comparisons, malformed operators, wrong units/kinds, out-of-range text scale,
  illegal nesting/grouping, and misplaced guards produce structured recovery
  and semantic diagnostics.
- General expressions, calls, variables, and CSS-like media syntax are rejected
  without a compatibility parser.

### Cascade and resolver

- Truth-table tests cover every field, comparison, boundary value, and false
  case against `PresentationEnvironment`.
- Guard activation has the selected specificity behavior; guarded and
  unguarded rules with equal/different selector priority retain deterministic
  source/application order and trace provenance.
- Multiple accepted conditions normalize without changing authored rule order.
- Inherited values recompute correctly when an ancestor's guarded winner changes.

### Revisions, invalidation, and players

- Changing one environment field advances the authoritative revision according
  to the selected rule and invalidates exactly the required dependent nodes.
- Reapplying an equal snapshot does not create nondeterministic churn.
- Native, web-hosted, and headless players produce the same computed Style for
  the same typed snapshot.
- Reduced-motion condition selection and any transition-suppression policy are
  tested as distinct contracts.

### Codec and tamper resistance

- Canonical encode/decode round-trips all legal predicates, source provenance,
  rule order, and typed values deterministically.
- Unknown tags, illegal field/operator pairs, bad enum/scalar values, invalid
  nesting, impossible ranges, duplicate/malformed records, and merge damage
  fail within configured decode budgets.
- No decode or runtime test requires `.arcw` source or a legacy reader.

### Formatter and LSP

- Completion is field/type/operator aware; hover displays the closed condition
  type; semantic tokens and code actions use exact condition ranges.
- Incremental edits remove stale diagnostics and invalidate only the affected
  Style/condition inventory.

No test may use source-file text searches as correctness evidence.

## Expected output

Deliver a self-contained design package containing:

- the normative grammar, formatter examples, field/operator/value truth table,
  and rejected grammar;
- exact AST, HIR, checked, product, codec, resolver, environment revision, and
  invalidation APIs;
- the activation/specificity and rule-normalization algorithms;
- host/default/headless authority and deterministic update behavior;
- diagnostic codes with ranges, notes, and fixes;
- formatter, LSP, trace, and explain contracts;
- a file-by-file implementation order and complete test/validation matrix;
- explicit non-goals for every omitted condition family.

## Acceptance criteria

The design is implementation-ready only when the grammar is closed, every
field/operator pair has exact semantics, condition activation and specificity
are unambiguous, revisions/invalidation are deterministic, typed records survive
codec and merge, and tooling/diagnostics require no guesswork. It must preserve
the native-only single-resolver d.1-d.3 path, introduce no CSS/Takumi or general
expression escape, and add neither compatibility machinery nor source gates.
