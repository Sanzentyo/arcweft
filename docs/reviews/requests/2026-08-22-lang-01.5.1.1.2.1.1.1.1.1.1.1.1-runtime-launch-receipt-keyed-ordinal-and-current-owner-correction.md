## Mandatory correction 1 — restore the exact MakeNeedHandle policy

The final execution table has this exact row:

| Family | Execution | Policy | Behavior |
|---|---|---|---|
| `MakeNeedHandle` | `Host` | `JoinSameKey` | construct lazy `ReusableJoin`; no scheduler or adapter mutation |

`MakeNeedHandle + Runtime`, `MakeNeedHandle + AlwaysStart`, and eager ensure by
this opcode all reject before mutation. An AlwaysStart producer obtains a
concrete `AcceptedLaunch` handle only as the result of some separately
authorized scheduler launch after its journal and Need rows are atomically
committed. “AlwaysStart can only produce AcceptedLaunch” constrains the handle
state; it does not authorize a new MakeNeedHandle policy or execution route.

Update every truth table, Rust schema, test row, machine row, and deletion cut.
Add negative tests for both forbidden axes and prove adapter/journal counters
are unchanged.

## Mandatory correction 2 — make accepted launch constructible across crates

Do not use a core `pub(crate)` proof whose constructor is private to the
separate scheduler crate. Select this public, validated core boundary:

```rust
pub struct AcceptedTaskLaunchReceipt<'a> {
    journal: &'a TaskJournalRow,
    need: &'a RuntimeNeedCell,
    // fields remain private
}

impl RuntimeGenerationJournal {
    pub fn accepted_launch_receipt(
        &self,
        correlation: &TaskCorrelation,
    ) -> Result<AcceptedTaskLaunchReceipt<'_>,
                RuntimeNeedHandleConstructionError>;
}

impl RuntimeNeedHandle {
    pub fn try_from_accepted_launch(
        accepted: AcceptedTaskLaunchReceipt<'_>,
    ) -> Result<Self, RuntimeNeedHandleConstructionError>;
}
```

The journal method performs exact lookup, requires its journal row and Need row
to exist and share the complete committed correlation, verifies
producer/outcome/spec, launch acceptance, generation, and policy/ordinal
invariants, then returns the public proof with private fields. The handle
constructor rechecks the proof and constructs `AcceptedLaunch`. No public raw
field constructor exists, and an uncommitted staging delta cannot produce the
proof. Both methods have visibility callable by the separate scheduler crate.
The scheduler requests the proof only after atomic apply. Restore requests it
from the privately decoded, fully cross-validated journal before publishing
the restored runtime. Do not return another inaccessible cross-crate proof or
a forgeable DTO.

## Mandatory correction 3 — key AlwaysStart counters by producer instance

One scalar generation counter is forbidden. The final live owner is
semantically:

```rust
pub struct RuntimeGenerationJournal {
    generation: GenerationId,
    next_always_start_ordinals:
        BTreeMap<NeedProducerInstanceKey, NonZeroU64>,
    next_observer_id: NonZeroU64,
    // retained rows
}
```

Absence means the next ordinal is `1`. Allocation is scoped to
`(generation, producer_instance_key)`, returns the current positive value, and
stages the checked successor. Overflow rejects before mutation. An ordinal is
advanced only in the transaction that publishes its exact launch. Failed
single or batch operations do not insert or advance a counter.

The version-1 snapshot contains sorted rows:

```rust
pub struct AlwaysStartOrdinalCounterSnapshotV1 {
    pub producer: NeedProducerInstanceKey,
    pub next: NonZeroU64,
}
```

Keys are unique and ascending. Restore requires `next` to exceed every
persisted AlwaysStart ordinal for that producer in the generation; missing,
duplicate, stale, zero, and overflow rows reject. Batch deltas contain a map of
after-images for only the touched producer keys, not one scalar after-image.

Add a permutation test showing that interleaving producer B does not change
producer A's ordinals, NeedIds, or TaskIds, plus same-producer monotonic,
rollback, snapshot, and restore tests.

## Mandatory correction 4 — return an inspectable adapter launch receipt

An opaque `PreparedLaunch` token cannot supply the capabilities required by
restore, rebind, and cancellation. The lower core protocol owns an inspectable
receipt paired with the adapter-private token:

```rust
pub struct PreparedLaunchBatch<T> {
    receipt: HostTaskLaunchReceipt,
    token: T,
}

pub struct HostTaskLaunchReceipt {
    generation: GenerationId,
    rows: Box<[HostTaskLaunchReceiptRow]>,
}

pub struct HostTaskLaunchReceiptRow {
    source_index: u32,
    correlation: TaskCorrelation,
    operation: HostOperationIdentityV1,
    launch: HostLaunchCapability,
    cancellation: HostCancellationCapability,
}

pub trait TaskLaunchAdapter {
    type PreparedLaunchToken;
    type PrepareLaunchError;

    fn prepare_launch(
        &mut self,
        batch: HostTaskLaunchBatch,
    ) -> Result<PreparedLaunchBatch<Self::PreparedLaunchToken>,
                Self::PrepareLaunchError>;

    fn commit_launch(
        &mut self,
        prepared: PreparedLaunchBatch<Self::PreparedLaunchToken>,
    );

    fn rollback_launch(
        &mut self,
        prepared: PreparedLaunchBatch<Self::PreparedLaunchToken>,
    );
}
```

Equivalent field visibility is allowed only if scheduler can inspect the
receipt and only the adapter can use the token. The receipt has exactly one row
per input row, in canonical source-index order. Before state publication the
scheduler verifies generation, row count, unique source index, exact
correlation and operation equality, nonzero capabilities, and capability
catalog/route ownership. A mismatch rolls the token back and publishes
nothing. Capabilities are staged into the journal and become visible with the
launch; commit returns no additional data.

Define the exact construction API, capability uniqueness/idempotence rules,
snapshot fields, restore/rebind/cancel consumption, and error precedence. Add
tampered/missing/duplicate/reordered receipt negatives and a launch → snapshot
→ restore → cancel round trip.
