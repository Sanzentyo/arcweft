# Request: seq-06.16.6.1 save/load scoped presentation handles

## Sequence Position

This request is split from seq-06.16.6 scoped presentation resource handles
after the runtime presentation-handle table, operation epoch, tombstones,
value-position component/image handle lowering, and AWBC lexical cleanup stacks
were implemented and validated.

It must not redesign the already implemented `presentation.handle.*` operation
surface, `BundlePresentationSnapshot.presentation_handles`, or AWBC cleanup
registration/cancellation substrate unless current implementation evidence
shows a concrete flaw.

## Why This Split Exists

The implemented seq-06.16.6 substrate proves the pieces independently:

- `BundlePresentationSnapshot` serializes presentation handle records,
  operation epochs, and tombstones.
- AWBC `FiberState` serializes root and lexical cleanup stacks.
- Runtime-plan lowering emits scoped cleanup registration and cancellation for
  value-position `component(...)` and `image(...)` handles.

That is not yet an end-to-end save/load contract. A real save snapshot must
store and restore the runtime fiber state and the presentation snapshot together
so loaded sessions preserve visible/hidden/disposed resources, owner cleanup
metadata, and rollback tombstones consistently. This needs its own request
because it touches save schema, runtime-driver session APIs, product AWBC
executor restoration, and later player/CLI save commands.

## Required Decisions

- Define the portable session save schema:
  - schema id and version;
  - active generation identity or content/root fingerprint;
  - execution tier payloads;
  - AWBC product fiber state;
  - presentation snapshot;
  - pending host calls, pending text-control write-backs, waiting action/text
    receive calls, host tasks, and task generation pins.
- Decide whether the first implementation supports only Product AWBC sessions
  or also Structured VM/AOT sessions. If Structured VM/AOT restoration is not
  ready, the snapshot type must make that limitation explicit instead of
  pretending to be executor-neutral.
- Define how `ArcweftRuntimeExecutor` exposes and restores Product AWBC compact
  `FiberState` while keeping the facade `FlowFiber` synchronized for status,
  observations, source/stream state, and display/observe paths.
- Define how the session save schema maps into `arcweft-save`:
  - whether the payload is an Arcweft `Value` shape, a typed JSON payload inside
    the save envelope, or a new deterministic data-codec adapter;
  - checksum, migration, strict decode, and future-version behavior.
- Define restore validation:
  - bundle/generation compatibility checks;
  - entry/function/table bounds validation for restored `FiberState`;
  - rejection behavior for mismatched bundle content, unsupported executor
    tier, stale schema version, missing presentation table, or invalid handle
    tombstones.
- Define rollback semantics:
  - restoring a previous save/checkpoint must restore presentation handle
    tombstones and operation epoch;
  - stale `show`/`hide`/`unmount` operations emitted after rollback must not
    revive released or destroyed handles.

## Implementation Order

1. Add the session-save data model in the correct Sans-I/O boundary. Prefer a
   runtime-driver-owned typed snapshot for live session state and an
   `arcweft-save` envelope adapter only for bytes/codec concerns.
2. Add Product AWBC executor snapshot/restore APIs that expose compact
   `FiberState` and rebuild or synchronize facade state after restore.
3. Add `BundleSession` snapshot/export and restore/import APIs that include the
   runtime fiber snapshot and `BundlePresentationSnapshot`.
4. Preserve pending View/action/text receive state or explicitly reject save
   points where the current runtime cannot restore those pending waits
   deterministically.
5. Integrate the snapshot payload with `arcweft-save` strict decode and schema
   version checks.
6. Add focused runtime-driver tests for save/load and rollback before wiring CLI
   or player commands.
7. Add CLI/player save-load commands only after the Sans-I/O snapshot contract
   is deterministic and tested.

## Tests To Specify

- `presentation_handle_save_load_restores_lifecycle_table`:
  create a component/image handle, hide or release it, serialize the session
  save snapshot, restore it, and verify handle state, operation epoch, filtered
  images/controls, and presentation revision behavior.
- `presentation_handle_rollback_restores_tombstones`:
  restore a prior snapshot and verify a stale `presentation.handle.show` cannot
  revive a released/destroyed handle.
- `awbc_save_load_preserves_cleanup_stacks`:
  restore a Product AWBC fiber with root and lexical cleanup registrations and
  verify scope/return cleanup still emits the expected terminal handle effects.
- `session_restore_rebuilds_facade_fiber`:
  after restoring compact AWBC state, verify `BundleSession::presentation`,
  `step`, status labels, observations, source state, and host-call waits use the
  restored state, not stale facade state.
- `save_decode_rejects_mismatched_bundle_generation`:
  loading a snapshot against a different product AWBC generation fails with a
  structured diagnostic.
- `save_decode_rejects_unsupported_executor_tier`:
  if Structured VM/AOT is not implemented in the first cut, attempts to restore
  those snapshots fail explicitly.
- `save_envelope_strict_decode_rejects_future_or_trailing_payloads`:
  cover the save-envelope route rather than only serde roundtrips.

## Constraints

- Keep `arcweft-core` Sans I/O and presentation-agnostic. Core may expose AWBC
  fiber snapshot/restore primitives, but save envelope bytes, filesystem paths,
  renderer state, and player commands belong outside core.
- Do not store renderer-owned GPU/window resources in save data. Save only
  portable runtime state and presentation resource identities.
- Do not make live scoped handles persistent game-state values. Save the runtime
  handle table and owner cleanup metadata, not arbitrary handle values inside
  user-authored persistent data.
- Do not silently drop pending host calls, text-submit waits, action-receive
  waits, tasks, source queues, stream queues, or presentation tombstones. Either
  restore them or reject the save point with a typed reason.
- Do not treat a `BundlePresentationSnapshot` serde roundtrip alone as
  save/load completion. The session save must include the execution state that
  owns the cleanup stack.
- Do not add native/web visual-golden baseline promotion as part of this
  request. Visual parity evidence belongs to the adapter parity request after
  save/load semantics exist.

## Expected Output

Return an implementation-ready design package and patch plan that includes:

- the save schema and versioning contract;
- Product AWBC fiber snapshot/restore API design;
- `BundleSession` snapshot/export and restore/import API design;
- `arcweft-save` integration details;
- diagnostics and rejection cases;
- focused tests and expected file locations;
- documentation updates to the scoped presentation handles implementation note.
