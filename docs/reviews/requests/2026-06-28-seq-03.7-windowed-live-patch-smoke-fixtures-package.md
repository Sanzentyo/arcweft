# Seq-03.7 Request: Windowed Live Patch Smoke Fixtures Package

## Sequence Position

This follows seq03.5. It should be designed after seq03.1-03.4 are in
production, but its implementation depends on `scene_windowed.rs` consuming
`WindowedRuntimeOwner`.

## Request

Design and implement the validation harness and fixtures for the actual
windowed native live-patch path. The package should prove that a running
windowed player can accept typed patch events at the safe frame boundary and
preserve the correct state by compatibility class.

Return the final work as a zip package with implementation, fixtures,
documentation, and validation results.

## Required Scope

- Generate real `.awfb` bundles and patch artifacts from repository-owned test
  fixtures; do not rely on placeholder JSON examples as runtime fixtures.
- Add content-only and code-generational live-patch smoke coverage through the
  same typed event path used by the windowed scene owner.
- Add invalid/wrong-base patch coverage proving the old session/catalog remains
  active.
- Record whether the test can run headless/offscreen in CI or requires a local
  machine with window/GPU support.
- Provide a fixture regeneration command if new binary fixtures are committed.
- Document platform-specific validation gaps for Windows, macOS, Linux Wayland,
  and headless CI.

## Required Decisions

- Should the first smoke use a headless/offscreen window path, a deterministic
  event-loop test harness, or a manual native player command?
- Which observable proves the window, renderer shell, input controller, and
  visual clock were preserved?
- Which fields from `WindowedPatchReport` or `WindowedRuntimeOutcome` should be
  snapshotted?
- How should fixture regeneration avoid stale binary patch artifacts after AWFB
  schema changes?

## Tests To Specify And Implement

- Content-only patch refreshes presentation/image catalog and preserves window
  and renderer shell.
- Code-generational patch commits a new generation while existing foreground
  fiber/task state follows seq03 runtime semantics.
- Restart-required patch restarts the session while preserving window shell
  state where policy allows.
- Wrong-base or malformed patch records `Rejected` without mutating active
  session/catalog.
- Fixture regeneration command updates all related AWFB/patch/report fixtures
  in one deterministic pass.

## Constraints

- Do not add network, release trust verification, filesystem watchers, or local
  sockets to `arcweft-runtime-driver`.
- Do not use placeholder JSON as acceptance evidence when real AWFB bytes are
  required.
- Do not require manual visual inspection as the only validation path if a
  deterministic headless path is feasible.

## Expected Zip Contents

- `overlay/` implementation and fixtures.
- A deterministic fixture regeneration command, preferably a checked-in Rust
  script or `just` recipe that delegates to Rust.
- `docs/implementation/seq-03-7-windowed-live-patch-smoke-fixtures-2026-06-28.md`
- `VALIDATION.md` with exact commands run, platform used, and blocked platform
  gaps.
- `README.md` with apply order, fixture regeneration instructions, acceptance
  criteria, and non-goals.

## Parallelization Guidance

This can be designed in parallel with seq03.5, but its implementation should
wait until seq03.5 lands because it depends on the scene owner integration
points. It should not block seq03.6 design.
