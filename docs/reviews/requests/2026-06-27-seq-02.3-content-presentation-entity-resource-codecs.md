# Seq-02.3 Content, Presentation, and Entity Resource Codecs

## Sequence Position

This request follows seq-02.2 and depends on seq-02.1 common wire primitives.
It migrates the product resource families that describe narrative content,
presentation catalogs, assets, source maps, and graph/entity indexes.

Do not include shader, UI, audio, debug-symbol, or contract-specific schemas in
this request unless a concrete reference is needed to keep cross-section ids
stable.

## Why This Split Is Needed

Content, presentation, and entity resources are high-volume product data and
are likely to dominate patch diffs. They must have deterministic compact codecs
before patch v2 can classify resource changes precisely. They are also broad
enough to require a separate review from the smaller runtime-facing sections in
seq-02.2.

## Required Decisions

1. Define canonical compact schemas for content catalogs, including dialogue
   lines, text keys, tags, narrative resource ids, and content references.
2. Define canonical compact schemas for presentation/display catalogs,
   including text boxes, layout references, image/display resources, and
   presentation state references that are stable across products.
3. Define canonical compact schemas for asset catalogs and asset descriptors,
   including embedded/external residency references, media type, digest,
   dimensions where applicable, and adapter requirements linkage.
4. Define canonical compact schemas for source maps and source anchors exposed
   by inspection, diagnostics, runtime observations, and patch review.
5. Define canonical compact schemas for graph/entity indexes, including entity
   ids, public ids, graph edges, ownership, and runtime lookup indexes.
6. Define cross-section reference rules among content, presentation, entity,
   runtime types, entrypoints, adapter requirements, and AWBC functions.
7. Define decoder budgets for catalog entries, edges, source spans, strings,
   asset descriptors, and reference fan-out.
8. Define patch compatibility fingerprints and compatibility labels for each
   family.
9. Define inspection/export views and fixture strategy.

## Implementation Order To Specify

1. Add content catalog compact schema and deterministic fixtures.
2. Add presentation/display catalog compact schema and fixtures.
3. Add asset catalog compact schema, including external descriptor references
   without implementing the seq-02.6 carrier redesign.
4. Add source-map compact schema and diagnostics inspection fixtures.
5. Add graph/entity index compact schema and cross-section validation.
6. Wire product AWFB encode/decode section-by-section.
7. Add patch fingerprint classification for migrated families.
8. Remove product JSON fallback for migrated families after parity passes.

## Tests To Specify

- deterministic bytes for each migrated family;
- JSON-to-compact parity from existing fixtures;
- malformed cross-section reference diagnostics;
- duplicate public id and dangling reference rejection;
- budget failures for large catalogs and graph fan-out;
- source-map inspection remains stable;
- patch classifications for text-only, asset-only, display-only, source-map
  only, and entity graph changes;
- runtime/player smoke for a product bundle whose content and presentation
  resources decode from compact sections.

## Constraints

- Keep product codecs deterministic and Sans I/O.
- Do not fetch external assets inside `arcweft-bundle`.
- Do not redesign the language surface or runtime plan unless repository
  evidence proves the compact schema cannot represent current typed data.
- Do not use JSON as a product fallback once a family is migrated.
- Keep broad semantic validation in the owning compiler/runtime/presentation
  layer when it depends on source context or adapter behavior.

## Non-Goals

- Shader, UI, audio, debug-symbol, and contract codecs.
- Patch v2 container format.
- AWFR release archive and external payload carrier redesign.
- Signing-policy redesign.

## Expected Output

Provide:

- compact schemas for content, presentation/display, asset, source-map, and
  graph/entity sections;
- cross-section validation rules;
- patch fingerprint rules;
- implementation cuts and fixture plan;
- exact tests and deletion gates for typed JSON payloads.
