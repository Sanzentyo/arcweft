# Seq-04.7 Request: Runtime-Plan Unit Cache Reuse Package

## Sequence Position

This follows seq04.1 through seq04.6. Seq04.5 deferred runtime-plan reuse
because current runtime-plan artifacts were whole-build outputs with
insufficient stable per-unit identity. Seq04.7 should make that boundary
explicit and implement only the reuse that is sound after the seq04.6
typecheck/sema gate.

Do not redesign parse/HIR/interface/typecheck cache substrate already applied
by seq04.1-04.6 unless current source evidence shows a concrete flaw.

## Request

Design and implement persistent cache support for runtime-plan units.

Return the final work as a zip package with design, Rust implementation
overlay, tests, implementation notes, validation notes, and apply instructions.

## Required Inputs

- Current Arcweft `main`.
- The seq04.6 package result, or the current repository state after applying
  seq04.6.
- `docs/implementation/seq-04-5-interface-runtime-bytecode-link-reuse-2026-06-28.md`.
- Current `arcweft-runtime-plan` data model.
- Current compiler lowering from checked HIR/sema facts to runtime plan.
- Current persistent object/query/cache explain APIs.
- Current build snapshot evidence model.
- Current AWFB/AWBC runtime-plan and bundle content-root identity rules.

## Required Decisions

1. What is a runtime-plan unit in current Arcweft: module, entry, flow, region,
   lowered function, or another stable unit.
2. Which input digests define the runtime-plan unit key:
   source, HIR body, interface, typecheck gate, effect/capability policy,
   compiler identity, runtime-plan lowering options, target profile, and
   dependency summaries.
3. What runtime-plan data is stable enough to persist as `.awbo` without
   serializing transient compiler internals.
4. How runtime-plan diagnostics, source spans, entrypoint identity, public IDs,
   resource references, host capability requirements, and generation-affecting
   facts are represented.
5. How a runtime-plan unit hit is validated before reuse.
6. How a runtime-plan unit miss is surfaced as typed soft-miss evidence.
7. How runtime-plan unit reuse composes into existing whole-build outputs
   without changing AWFB content roots.
8. How `arcw cache explain` presents runtime-plan query evidence.

## Required Implementation

Implement the ready runtime-plan-unit reuse subset. The expected minimum is:

- stable runtime-plan-unit `.awbo` object schema;
- query-kind and artifact-kind enum ownership;
- deterministic encode/decode and malformed payload rejection;
- adapter-owned read/write-through with typed soft misses;
- compiler integration that can reuse validated units or intentionally rebuild
  with explicit evidence;
- `BuildSnapshot` and cache explain evidence;
- tests proving deterministic output identity.

If current runtime-plan identity is still not stable enough for actual reuse,
implement an explicit `RuntimePlanUnitGateObject` with conservative-miss
evidence and return a narrow follow-up request. Do not claim reuse merely
because object bytes round-trip.

## Acceptance Criteria

- Runtime-plan cache keys include the seq04.6 typecheck/sema gate output or a
  conservative blocker proving why reuse is unavailable.
- Runtime-plan unit identity is stable and typed; no stringly one-off stage
  names or field-by-field helper projections are scattered through the
  workspace.
- Reusing a runtime-plan unit and rebuilding from source produce equivalent
  build outputs and unchanged AWFB content roots.
- Corrupt/stale/mismatched runtime-plan records are soft misses.
- Cache explain can inspect runtime-plan query evidence.
- Runtime-driver and player crates remain free of compiler/cache filesystem
  dependencies.

## Tests To Specify And Run

```bash
cargo fmt --all -- --check
cargo test -p arcweft-project persistent_object --all-features
cargo test -p arcweft-project-loader persistent_query --all-features
cargo test -p arcweft-compiler persistent_query --all-features
cargo test -p arcweft-runtime-plan --all-features
cargo test -p arcweft-cli cache --all-features
cargo check -p arcweft-project -p arcweft-project-loader -p arcweft-compiler -p arcweft-runtime-plan -p arcweft-cli --all-targets --all-features
cargo clippy -p arcweft-project -p arcweft-project-loader -p arcweft-compiler -p arcweft-runtime-plan -p arcweft-cli --all-targets --all-features -- -D warnings
cargo +nightly -Zscript tools/structure-audit.rs --root .
git diff --check
```

Focused tests must cover:

- deterministic runtime-plan-unit bytes;
- unit hit after repeated build;
- source/HIR/typecheck/options/environment mismatch soft misses;
- dependency unit mismatch soft miss;
- cache explain runtime-plan hit/miss evidence;
- unchanged AWFB content root for reused versus rebuilt runtime-plan units.

## Non-Goals

- No bytecode-unit reuse.
- No link-plan reuse.
- No JIT/AOT persistent code cache.
- No release/trust/publish behavior.
- No runtime-driver or player dependency on compiler cache adapters.
- No module-aware sema redesign beyond consuming seq04.6 evidence.

## Parallelization Guidance

Seq04.7 can be designed while seq04.6 is under review, but implementation must
consume the final seq04.6 typecheck/gate evidence shape. Seq04.8 should wait
for seq04.7 implementation or treat runtime-plan reuse as a strict dependency.
