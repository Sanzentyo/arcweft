# Lang-01.5 — Typed public-ID family authority and semantic consumer migration

## Request status and evidence

This is an independently throwable design request split from the top-level
declaration identity implementation ledger at
`docs/implementation/2026-08-04-top-level-declaration-identity-canonicalization.md`.
The split reason is that the remaining consumers do not share one closed
family registry or one typed syntax-to-HIR carrier; implementing them one at a
time would create another partial authority and leave duplicate readers.

Evidence snapshot:

- Git commit: `fde3bd0af47ff32c279a9c26d8692cbf12b8d1ff`
- Branch: `main`
- Working tree: dirty, with extensive pre-existing task changes; no staged
  changes are part of this request.
- The accepted declaration contract is: bare authored top-level names are
  canonical, explicit `@` identities remain accepted with shared warning/lint
  policy, `proof @...` is not rejected solely for the marker, and entry/test/
  bench helper invocation behavior remains unchanged.

Do not re-audit whether the remaining ad hoc readers exist. The current
implementation evidence already identifies them and this request is to close
their ownership and migration contract.

## Confirmed remaining consumers

- `crates/arcweft-lang-sema/src/checker/helpers.rs` classifies entity families
  and character literals from raw strings, including aliases and synthetic
  `EntityRef` reconstruction.
- `crates/arcweft-lang-sema/src/checker/symbol_resolution.rs` consumes raw
  `HirDialogue::callee()` strings for character resolution.
- `crates/arcweft-lang-hir/src/dialogue_identity.rs` still parses speaker
  callee spelling (`.say`, `@`, delimiters, and dotted segments). Its durable
  line/text identity duplicate has already been removed in favor of
  `arcweft-id::dialogue`.
- `crates/arcweft-lang-hir/src/lower_ids.rs` now uses the existing typed
  `DeclarationIdentityFamily::Flow` authority for flow construction and
  extraction, but still constructs or strips `choice` and text/choice paths by
  string. Dialogue line/text validation now uses `arcweft-id`; the remaining
  generated-ID families need one coherent authority.
- `crates/arcweft-lang-sema/src/entry/checker.rs` checks `entry.` and `flow.`
  with `starts_with`; `entry` is not currently in
  `DeclarationIdentityFamily`.
- `crates/arcweft-lang-sema/src/character_definition.rs` no longer decides
  owner provenance by stripping `@`; its remaining source-slice reparsing is
  a separate final-HIR carrier issue, not a license to add another reader.

## Required decisions

1. Define a complete lower-layer `PublicIdFamily` authority in `arcweft-id`.
   State which families are durable public-ID families, which are authored
   top-level declaration families, which are dialogue/choice/generated
   families, and which are semantic-only aliases. `DeclarationIdentityFamily`
   must remain a typed declaration-surface subset rather than becoming a
   partial registry of every string namespace.
2. Define exact family-boundary validation. `entry.` must not accept
   `entryish.*`; the same near-prefix rule applies to every family. Define
   wrong-family recovery without fabricating an expected-family ID.
3. Define typed syntax carriers for expression entity references and dialogue
   callees. They must preserve authored provenance, delimited/reference form,
   family root, canonical body, source ranges, and recovery state without
   requiring sema or HIR to reconstruct these facts from source strings.
4. Define the final-HIR representation consumed by sema for dialogue speaker,
   flow, choice, entry, line, and text identities. It must carry a typed
   identity or validated family fact, not merely a `String` plus a convention.
5. Define the boundary that replaces the character checker helper. Family
   aliases such as `anim`, `bus`, `mix`, and `duck` must be represented in the
   registry or owning semantic type, not in a new sema-local match table.
6. Define whether `.say` is still accepted syntax. The maintained dialogue
   contract and older examples disagree; resolve that precedence before
   deleting or retaining `.say` normalization.
7. Define entry/test/bench ownership explicitly. Their helper invocation
   contract remains unchanged and they must not be enrolled accidentally in
   bare top-level declaration canonicalization.
8. Define the public parser/HIR/sema authority switch and delete order. No
   compatibility aliases, dual readers, fallback source reconstruction, or
   partial registry may remain after the switch.
9. Define dependency direction: `arcweft-id` remains lower than syntax/HIR;
   syntax owns lossless surface facts; HIR owns normalized language identity;
   sema owns type and project resolution; tooling/CLI consume those facts.

## Precedence and non-goals

- Preserve the accepted bare declaration and explicit-warning contract from
  the implementation ledger.
- Preserve hierarchical layer IDs when a bare spelling would change their
  public identity.
- Preserve entry/test/bench helper calls exactly as their existing typed
  contract requires.
- Do not expand `DeclarationIdentityFamily` with a few visible prefixes while
  leaving the larger semantic namespace map unowned.
- Do not repair `entry`, `flow`, dialogue, or character readers independently.
- Do not introduce a compatibility wrapper for the old HIR callee string or a
  second family table in sema/HIR.
- Do not change runtime dialogue semantics, character manifests, or unrelated
  resource identity contracts.

## Required implementation order

1. Specify and implement the complete `arcweft-id` family registry and its
   exact-boundary/wrong-family behavior, with round-trip and near-prefix tests.
2. Add syntax-owned typed callee/reference carriers and stable source/recovery
   ranges; thread them through lowering into final HIR.
3. Migrate HIR flow/choice/dialogue ID construction to typed domain operations
   and delete local prefix parsing/fallback extraction.
4. Migrate sema character classification and entry target checks to typed
   family facts and checked-ID constructors; delete raw `@`/`starts_with`
   readers only after their carriers are available.
5. Switch CLI/tooling/LSP consumers to the final HIR/sema authority and delete
   obsolete readers in the same coherent cut.
6. Update maintained docs/examples only where the selected design changes;
   keep implementation evidence and blocker links in `docs/implementation/`.

## Required validation matrix

- Every registry family accepts its exact family and rejects empty tails,
  near-prefix names, wrong-family values, and malformed IDs.
- Syntax preserves bare, explicit, family-relative, short-relative,
  delimited, and recovered reference provenance with exact ranges.
- HIR flow/choice/entry/dialogue line/text matrices cover generated IDs,
  family-relative IDs, wrong-family recovery, nested scopes, and maximum-size
  identities.
- Dialogue callee matrices cover bare speaker, typed entity reference,
  delimited reference, narrator aliases, qualified names, and the selected
  `.say` policy without source-string fallback.
- Sema character and entry matrices cover aliases, imports/reexports,
  shadowing, unknown symbols, near-prefix negatives, and deterministic
  diagnostics.
- Entry/test/bench helper invocation tests remain green and show no accidental
  enrollment in the declaration-name canonicalization path.
- CLI and LSP consume equivalent typed facts; stale or unavailable semantic
  data produces structured diagnostics and never falls back to raw spelling.
- Run focused crate tests, selected Clippy, `git diff --check`, the structural
  audit policy, and the required workspace tiers. Record failures separately
  from dirty-tree or timeout limitations.
