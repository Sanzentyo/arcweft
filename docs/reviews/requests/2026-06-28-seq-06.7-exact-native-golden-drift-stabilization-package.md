# Seq-06.7 Request: Exact Native Golden Drift Stabilization Package

## Sequence Position

This follows seq06.5 selected capture metadata and seq06.6 visual smoke/golden
fixtures.

Seq06.6 added deterministic non-exact visual smoke coverage and improved exact
golden failure reporting. During target-checkout validation, `just
test-visual-golden` produced a real Tier 2 drift on the existing native
`vertical_tutr_golden` fixture:

```text
dimensions: 1280x720
mse: 0.0030918550895167305
mae: 0.004233718228315644
existing bounds: mse <= 0.002, mae <= 0.003
```

Seq06.7 should stabilize the exact native golden workflow before more exact
goldens are added.

## Problem

The exact native golden tier currently detects visual drift, but the repository
does not yet define a complete decision procedure for what to do after a drift:

- whether the drift is caused by renderer behavior, font fallback, Windows text
  stack, capture pipeline, fixture source changes, or stale checked-in PNGs;
- which environment facts must be recorded before accepting or rejecting a new
  baseline;
- whether current MSE/MAE thresholds are still the right gates;
- where candidate PNGs and `.imq.json` reports are retained for review;
- how CI should distinguish "environment not pinned", "expected skip",
  "baseline drift", and "hard visual regression";
- how fixture refresh commands promote reviewed candidates without overwriting
  checked-in PNGs directly.

Without this cut, exact goldens are useful for local discovery but too ambiguous
for repeatable release/milestone validation.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures/metadata if needed, validation notes, and apply instructions for exact
native golden drift stabilization.

The package must make the existing native exact golden tier operationally
repeatable without moving exact comparisons into the default fast path.

## Required Decisions

1. Define the exact native golden environment fingerprint:
   - OS and version family;
   - renderer/backend path;
   - selected font and fallback facts;
   - viewport and device scale;
   - PNG/color format;
   - Arcweft commit/source hash;
   - `imq` version and metric set.
2. Decide whether the current `vertical_tutr_golden` drift is:
   - a checked-in baseline refresh;
   - a renderer/capture regression;
   - a font/environment mismatch;
   - or an intentionally non-actionable local drift.
3. Define baseline refresh rules:
   - candidate generation command;
   - required review artifacts;
   - metric report contents;
   - human review checklist;
   - checked-in PNG replacement procedure.
4. Define threshold policy:
   - keep existing MSE/MAE bounds;
   - adjust per-fixture bounds;
   - add PSNR/SSIM/maxAE gates;
   - or split strict/pinned and relaxed/local modes.
5. Define CI behavior:
   - what exact job is required for milestone validation;
   - what job is optional or artifact-only;
   - how missing font/backend/`imq` should be reported;
   - what must fail hard.
6. Define artifact retention:
   - candidate PNG path;
   - reference path;
   - `.imq.json` metrics path;
   - optional environment fingerprint JSON;
   - CI upload path.
7. Decide whether exact native golden tests should compare all checked-in
   goldens in one test or split them per fixture for clearer failure reporting.
8. Decide whether seq06.7 should update checked-in golden PNGs. If yes, explain
   why each replacement is valid and include metric evidence. If no, leave
   candidates under `target/` and document the required follow-up.

## Required Implementation

- Add an environment fingerprint/reporting layer for exact native visual
  validation.
- Add or update tests so exact golden failures expose:
  - fixture name;
  - reference path;
  - candidate path;
  - metrics JSON path;
  - environment fingerprint path or inline fingerprint summary.
- Add per-fixture metric records or policy metadata if thresholds differ by
  fixture.
- Update `just native-visual-artifacts` or add a sibling target so candidate
  artifacts and fingerprint JSON are produced together.
- Update fixture refresh docs so checked-in exact PNG replacement is a reviewed
  promotion step, not a blind regeneration.
- Update `docs/implementation/test-execution-policy.md` with exact native
  golden pass/fail/skip semantics.
- Add an implementation note under `docs/implementation/`.
- If checked-in PNGs are refreshed, include them in the overlay and document the
  before/after metrics.

## Acceptance Criteria

- Exact native golden drift has a documented decision procedure.
- Exact failure output includes enough paths and environment evidence to review
  the drift without rerunning locally.
- Candidate artifact generation produces PNG, observe JSON, `imq` JSON, and an
  environment fingerprint.
- `test-visual-golden` remains explicit Tier 2 and is not required by
  `just test-workspace`.
- Missing `imq`, missing pinned font, or unsupported backend is reported as a
  structured skip/blocker according to the documented CI policy.
- Any threshold or PNG baseline change is justified with before/after metrics.
- `vertical_tutr_golden` drift is either resolved or explicitly classified as
  remaining environment-gated work with concrete next validation steps.

include the exact failing fixture, metrics, candidate/reference paths, and
environment fingerprint in `verification/VALIDATION.md`.

## Non-Goals

- Do not add exact selected object/layer goldens in this cut.
- Do not move exact native golden validation into `just test-workspace`.
- Do not silently loosen thresholds merely to make the current drift pass.
- Do not make cross-platform font variance a default fast-path failure.
- Do not redesign seq06.5 selected-capture metadata or seq06.6 visual smoke
  coverage.

## Parallelization Guidance

This can be designed in parallel with seq03.7, seq04.3, seq05.1, and seq06.4
platform IME work. Implementation should be applied before adding more exact
native or WebGPU golden fixture families, because those packages should inherit
the stabilized drift/fingerprint policy.
