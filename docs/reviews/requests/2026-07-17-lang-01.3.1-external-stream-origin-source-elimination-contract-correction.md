# Request: External Stream origin and Source elimination contract correction

## Sequence position

This is Lang-01.3.1. It supersedes the final author and runtime model in
`2026-07-16-lang-01.3-live-source-authoring-unification-final-contract.md` and
the returned Lang-01.3 package wherever they retain `Source<T, E>`, `SourcePlan`,
or `#[source]`. It is a new independent request and must be answerable without
the earlier ZIP or conversation.

It depends on the direction fixed by Lang-01.1.1 (ordinary `fn`, `Need`, and
`Stream`) and may reuse Lang-01.4 `res` only for genuinely stable named
singletons. It must preserve the verified source lifecycle, backpressure,
replay, privacy, adapter, snapshot, and deterministic runtime behavior unless
production evidence identifies a defect.

## Fixed direction

- Remove the top-level `source` declaration.
- Do not replace it with `#[source]`, `#[input]`, or another function marker.
- Remove source-visible `Source<T, E>` and unify external inputs under
  `Stream<T, E>`.
- Represent external input as a typed `Stream` origin, not as a plain in-memory
  generator and not as an erased string provider.
- Preserve stable external identity, provider request, queue/backpressure,
  replay, privacy, permissions, deterministic ordering, lifecycle events,
  snapshots, and hot-reload compatibility.
- Parametric external streams are ordinary functions returning `Stream<T, E>`.
- A stable shared singleton may be a typed `res` whose value is a Stream
  descriptor only when package/Agent discovery or stable global identity
  requires it.
- Deployment-specific provider selection and policy may live in typed
  build/profile metadata; runtime-composable policy remains ordinary typed
  `StreamPolicy` data. Attribute token bags are prohibited.

## Why a correction is required

The returned Lang-01.3 contract removes only the author keyword and deliberately
keeps `Source<T, E>` as a separate asynchronous abstraction. The accepted
direction instead recognizes that Source differs from Stream by origin and
policy, not by value cardinality. A safe implementation therefore requires an
end-to-end internal unification, not a surface-only attribute rewrite.

## Required decisions

1. Define one typed `StreamPlan` model with explicit origins equivalent to at
   least generator, external host request, and derived stream. Give each origin
   stable typed identity and prove how it maps to the existing runtime.
2. Define the final `StreamPolicy` split. Backpressure, capacity, overflow,
   replay, privacy, permission, and retention rules must remain closed typed
   data. State exactly which fields may be profile-selected and which may be
   composed in source expressions.
3. Define the host capability/provider API that constructs an external Stream.
   Provider requests, adapter family, capability/effect requirements, and open
   timing must not be hidden in an attribute or raw string.
4. Map the complete current Source lifecycle into Stream events and state:
   create, open request, opened, progress, item, recoverable error, terminal
   error, disconnect, permission revocation, end, close, cancel, restart, and
   provider replacement.
5. Decide whether progress/control notifications are part of the item stream,
   a typed side channel, or runtime observation. Avoid making ordinary
   consumers pattern-match internal scheduler records.
6. Define handler migration. Existing source handlers must become ordinary
   typed stream transformations/consumers or runtime policies; no raw handler
   body, name lookup, or special handler function subset may remain.
7. Define deterministic backpressure and overflow behavior at frame/tick
   boundaries, including queue accounting, replay, redaction, and diagnostic
   privacy.
8. Define `StreamId`, external-origin identity, epoch/restart identity, snapshot
   schema, save/load, replay, and hot-reload compatibility. State precisely how
   former `SourceId` and source epochs map without a compatibility wrapper.
9. Replace `SourcePlan`, `SourceRuntimeState`, `SourceEventKind`, source AWBC
   tables/instructions, bundle records, and cache facts with the final Stream
   model in an atomic data-format cut. Preserve useful behavior; do not retain
   duplicate internal inventories under renamed aliases.
10. Integrate existing source-adapter diagnostics and accepted HIR/query-budget
    substrate through typed owners. Do not reparse source text or duplicate a
    callable/provider resolver.
11. Define formatter, completion, hover, definition, references, semantic index,
    CLI/Agent inspection, trace, and privacy-safe diagnostics for external
    Stream origins.
12. Specify migration of maintained examples and documentation, followed by
    ordinary grammar rejection of `source` with no spelling-specific final
    diagnostic.

## Implementation order to specify

1. Inventory and lifecycle/policy equivalence proof from current Source to the
   final Stream model.
2. Lowest-layer typed Stream origin/policy/runtime state and deterministic tests.
3. RuntimePlan/AWBC/bundle/snapshot direct format replacement.
4. Ordinary capability function and optional typed `res` authoring paths after
   Lang-01.1.1/Lang-01.4 owners are stable.
5. Sema, adapter, callable catalog, project index, tooling, and profile metadata
   integration.
6. Maintained project migration and complete deletion of Source syntax, HIR,
   runtime, wire, and tooling inventories.

The design should identify an independent early runtime cut that can proceed
before author-surface work, but it must not publish a final state with two live
runtime abstractions.

## Tests to specify

- Generator, derived, and external origins share Stream consumption while
  retaining origin-specific validation.
- Every former Source lifecycle event has deterministic positive and negative
  coverage.
- Backpressure capacity/overflow, replay, privacy/redaction, permission,
  disconnect, cancel, restart, and epoch behavior.
- RuntimePlan/AWBC/bundle/snapshot round trip and tampered-input rejection for
  the sole final Stream shape.
- Save/load and hot reload preserve compatible external streams and reject
  incompatible provider/policy/state changes.
- Profile/provider changes invalidate the correct caches and do not change an
  authored stable Stream identity accidentally.
- Ordinary function and `res` navigation uses typed declarations and the shared
  callable/resource catalogs.
- Removed `source` and `Source<T, E>` have no accepted AST/HIR/public/wire
  compatibility representation.
- Architecture tests use typed APIs/Cargo metadata, never repository source
  scans.

## Constraints

- No compatibility shim, dual reader, deprecated alias, migration-only syntax,
  source gate, CSS, or Takumi path.
- Do not lose or weaken replay, privacy, backpressure, permission, stable
  identity, snapshot, or deterministic ordering while unifying types.
- Keep runtime/data layers Sans I/O; provider acquisition remains in adapters.
- Do not add `#[source]` or a policy-heavy attribute.
- Do not redesign verified Stream generator or scheduler behavior unless a
  concrete defect is documented.

## Expected output

- One implementation-ready final contract with `OPEN_QUESTIONS=0`.
- Exact author, type, lifecycle, policy, HIR, RuntimePlan, AWBC, bundle,
  snapshot, cache, and tooling models.
- A Source-to-Stream field/event/state/deletion mapping.
- Ordered compiling cuts and a complete security/privacy/determinism test
  matrix.
- Explicit coordination points with Lang-01.1.1, Lang-01.4, Lang-01.5, and the
  source-adapter diagnostics reconciliation.
