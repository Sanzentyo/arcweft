# Seq-05.2.2 Request: Runtime-Driver Task Ownership Adapter For REPL Commands

## Purpose

Seq05.2.1 found that `arcweft-runtime-driver` exposes deterministic task dispatch and cancel-scope events, but not a stable host-owned registry that can back `:tasks` and `:cancel` without duplicating scheduler state in `arcweft-agent-repl` or `arcweft-cli`.

This follow-up should add the missing runtime-driver-owned task projection and cancellation API, then wire it into `ReplCommandHost::tasks` and `ReplCommandHost::cancel` from an adapter crate or CLI host boundary.

## Required source inspection

- `crates/arcweft-runtime-driver/src/session.rs`
- `crates/arcweft-runtime-driver/src/task.rs`
- existing native/web player task dispatch loops
- `crates/arcweft-agent-repl/src/command/host.rs`
- `crates/arcweft-agent-repl/src/command/types.rs`

## Required API shape

Add a runtime-driver-owned projection equivalent to:

```rust
pub struct RuntimeTaskRecord {
    pub id: String,
    pub status: RuntimeTaskStatus,
    pub generation: Option<u64>,
    pub logical_epoch: Option<u64>,
    pub sequence: Option<u64>,
    pub cancel_scope: Option<String>,
}

pub struct RuntimeTaskListOptions {
    pub include_completed: bool,
}

pub enum RuntimeTaskCancelTarget {
    All,
    Task(String),
    Scope(String),
}

pub struct RuntimeTaskCancelOutcome {
    pub cancelled: usize,
    pub pending_after: usize,
}
```

Exact names may differ, but ownership must remain in runtime-driver or a runtime-host adapter crate that already owns task lifecycle state.

## Acceptance criteria

- `arcweft-agent-repl` does not own scheduler state.
- CLI/MCP/LSP adapters call a host/runtime task owner instead of maintaining a parallel registry.
- `:tasks` can list pending/running tasks and optionally completed tasks.
- `:cancel all`, `:cancel task ID`, and `:cancel scope ID` produce deterministic `ReplCancelOutcome`.
- Read-only trace mode rejects cancel before host mutation.
- Tests cover task listing, cancellation by task, cancellation by scope, cancellation all, and completed-task filtering.

## Non-goals

- No background scheduler redesign.
- No terminal or MCP/LSP formatting in runtime-driver.
- No REPL command parser redesign.
