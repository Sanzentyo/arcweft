# Request: Direct-style suspension and Stream generator contract correction

## Sequence position

This is Lang-01.1.1. It supersedes the author-surface decision in
`2026-07-16-lang-01.1-function-suspension-role-unification-final-contract.md`
and the returned Lang-01.1 package wherever they prescribe `#[task]` or
`#[stream]`. It is a new, independently consumable correction request; the
recipient must inspect current `main` rather than treating the earlier package
baseline as production truth.

The already verified ordinary-function, callable-catalog, closure, currying,
AWBC frame, `Need`, `StreamPlan`, and scheduler substrate must not be redesigned
without a concrete production defect.

## Fixed direction

The final source language has one function declaration, `fn`.

- Do not add `async fn`, `task fn`, `stream fn`, `#[task]`, or `#[stream]`.
- `Need<T, E>` remains the one-shot pending-result value.
- `Stream<T, E>` remains the zero-or-more asynchronous-value protocol.
- An ordinary function may suspend directly when its execution reaches
  `await`; suspension is represented by the `control.suspend` effect and the
  existing resumable call stack.
- A function whose declared return type is `Stream<T, E>` and whose generator
  scope contains `yield` is a Stream generator.
- A function returning an existing `Stream<T, E>` without `yield` is an
  ordinary immediate function.
- Concurrency is selected at the call site through the existing `thread`
  substrate (or a separately designed future spawn/join surface), not by a
  function declaration role.
- Runtime-internal `TaskSpec`, task IDs/events, scheduling, and deterministic
  child-fiber machinery remain. Only source-visible task function identity is
  removed.

## Why a correction is required

The earlier final contract reduced grammar duplication but retained source
role attributes. Those attributes are still redundant with the execution facts
already present in the body, return type, effect row, and AWBC frame model. They
also risk creating cold-task or implicit-spawn call semantics that Arcweft does
not need. This correction must specify direct-style execution fully before old
callable kinds are deleted.

## Required decisions

1. Define the exact syntax and typing of `await` and `try await` over
   `Need<T, E>`, including result types, postfix `?`, evaluation order, and
   source ranges.
2. Define `control.suspend` inference and propagation through direct calls,
   closures, function values, generics, partial application, traits, imports,
   and reexports. Decide when an explicitly authored effect row must mention it
   and diagnose closed rows that omit it.
3. Fix start timing: ordinary calls start normally; only reaching an unresolved
   suspension point suspends the current fiber and its caller stack. Calling a
   function must not create a hidden cold task or implicitly spawn work.
4. Define cancellation, drop, error, snapshot, restore, and hot-reload behavior
   for a stack suspended inside nested ordinary calls.
5. Define generator scope precisely. Cover nested closures/functions, `yield`
   type inference, `return`, fallthrough, error completion, cancellation, and
   whether `yield` may cross a closure boundary.
6. Reject `yield` when the declared return type is not `Stream<T, E>` and reject
   a generator body that mixes yielded production with a final `Stream` value.
   Specify exact typed diagnostics rather than spelling-specific gates.
7. Define how an ordinary non-generator function returning `Stream<T, E>` is
   distinguished in AST/HIR/sema/runtime-plan from a generator while sharing
   one callable identity and signature path.
8. Remove `FunctionKind::Task`, `FunctionKind::Stream`, and `FunctionKind::Dialogue`
   where they only encode author spelling. If an internal execution enum is
   still needed after checking, name and type it by runtime behavior and prove
   that it is not a compatibility copy of the source kinds.
9. Preserve flow-specific pending-view and line-plan suspension contracts. Do
   not infer that a flow is an ordinary function merely because both can wait.
10. Specify the relationship between `thread`, direct suspension, `Need`, and
    any typed join handle. A new public join/spawn syntax is a non-goal unless
    required to make removal safe.
11. Define formatter, hover, signature help, completion, diagnostics, semantic
    tokens, project index, callable catalog, RuntimePlan, AWBC, save, and Agent
    projections from the shared typed model.

## Implementation order to specify

1. Production inventory and normative evaluation/effect/cancellation table.
2. Shared callable-catalog and ordinary-function typed contract.
3. Direct-style suspension inference and AWBC frame verification.
4. Generator classification and existing StreamPlan/AWBC lowering migration.
5. Tooling, index, save/hot-reload, and maintained example migration.
6. Atomic deletion of old keywords, source-role enum variants, parser branches,
   compatibility exports, and old fixtures.

Each cut must compile. The final state must not accept two source surfaces or
retain a dedicated removed-syntax diagnostic.

## Tests to specify

- Pending and ready `Need` values through nested direct calls, closures,
  currying, error propagation, cancellation, snapshot, restore, and hot reload.
- Effect inference and closed-effect-row rejection across direct and indirect
  calls.
- Stream generator yield/return/error/cancel ordering and deterministic
  RuntimePlan/AWBC round trips.
- Ordinary `fn -> Stream<T, E>` passthrough with no generator classification.
- Invalid yield return type, mixed generator/final-Stream body, and nested-scope
  yield diagnostics.
- Callable catalog, LSP, project index, and Agent views use the same declaration
  identity before and after suspension/generator classification.
- Removed `task fn`, `dialogue fn`, and `stream fn` receive ordinary grammar
  recovery and have no CST/AST/HIR compatibility node.
- Runtime-internal task scheduling continues to work and is not exposed as a
  source function kind.

## Constraints

- No compatibility alias, dual parser, migration-only AST, source gate, CSS, or
  Takumi path.
- Do not infer execution role from a hard-coded function name.
- Keep `arcweft-core` and data formats Sans I/O and preserve crate layering.
- Use typed identities and inherent/context-owned conversions rather than
  string role labels or endpoint-named helper functions.

## Expected output

- One implementation-ready final contract with `OPEN_QUESTIONS=0`.
- Normative source examples and evaluation/effect/cancellation tables.
- Exact AST/HIR/sema/callable-catalog/RuntimePlan/AWBC/save/tooling contracts.
- Direct deletion order and complete positive/negative test matrix.
- Explicit production evidence for every retained internal distinction.
