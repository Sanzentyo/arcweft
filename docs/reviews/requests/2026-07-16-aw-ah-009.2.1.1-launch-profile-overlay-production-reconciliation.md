# Design request: AW-AH-009.2.1.1 launch/profile overlay production reconciliation

- Date: 2026-07-16
- Kind: independently throwable final-design correction
- Output language: English
- Production changes: prohibited

## Sequence and objective

This request follows the implemented AW-AH-009.2.1 immutable character source
index, accepted LSP generation, exact source registry, and character-definition
dispatch. It precedes AW-AH-009.2.2 rename. Inspect the latest `main`, applicable
`AGENTS.md`, the Rust skill, and
`docs/implementation/2026-07-16-aw-ah-009-2-1-character-definition-source-index.md`.

Freeze the missing production contract for rebuilding a profile when an open
`arcw.toml` or another profile-topology resource differs from disk. The current
AW-AH-009.2.1 implementation passes source and character-manifest overlays into
the registration load, but the `ResolvedLaunchProfile`, adapter manifest, Rust
metadata, and resource list were resolved from disk before that transaction.
Do not redesign the landed source index, typed character resolution,
`LocationLink`, or accepted-generation candidate.

## Required decisions

Provide one exact Rust shape, owner, visibility, state transition, error rule,
and direct test for each item:

1. The complete set of profile-topology resources that can participate in one
   rebuild: `arcw.toml`, selected Arcweft modules, character manifests, adapter
   manifests, Rust metadata, and any dependency-owned profile resource.
2. How URI/version/logical-ID overlays are rebound before profile discovery,
   parsing, profile selection, path resolution, and adapter selection. No
   display-name parsing or directory scan may reconstruct source authority.
3. One immutable rebuild snapshot and the exact order from overlay capture to
   profile re-resolution, project/HIR assembly, registration, candidate
   validation, and atomic publication.
4. Whether a manifest overlay may add/remove/rename profiles or change resource
   paths, and how the requesting document is reassigned when its former profile
   disappears.
5. Save/close behavior, disk reversion, multi-root isolation, concurrent stale
   completions, duplicate logical IDs, generation overflow, and shutdown.
6. Typed bounded diagnostics for malformed/unresolvable topology resources and
   the rule that a failed rebuild preserves the previous accepted `Arc`, cache,
   world, index, and source registry without serving the new overlay through
   that old generation.
7. Inclusive limits and work charging for topology resources and overlay bytes.
   Reuse existing owners where possible; do not add client-configurable maxima.

## Required tests

Specify direct tests for open/change/save/close of `arcw.toml`; profile
addition/removal and selected-profile changes; character/adapter/Rust-metadata
path changes; invalid overlay preservation; stale completion; multi-root
isolation; exact/one-over resource and byte limits; and pointer-identical prior
accepted state after every failed transaction. Tests must use public or
crate-owned behavior, not source-text gates.

## Constraints

No CSS/Takumi restoration, compatibility reader, world-only publication API,
partial candidate publication, unbounded filesystem discovery, source-name
inverse parsing, or redesign of Style, View, proof, character nominal identity,
the source index, definition response composition, rename, or signature help.
