# Request: seq-06.16.3 component text-input native interactive smoke

## Sequence Position

Seq06.16.3 follows:

- seq06.16 player-rendered text submit button substrate;
- seq06.16.1 component/View text submit button lowering;
- the applied component text-input unification cut documented in
  `docs/implementation/component-text-input-unification-2026-07-04.md`.

The previous cut validated parser, lowering, sema, runtime-driver, bundle, and
sample bundle paths. It did not launch the native interactive window. The
native sample bundles cleanly without top-level input declarations, but the
interactive window path still needs an explicit smoke pass.

## Why This Split Exists

Native window/IME interaction is environment-dependent and should not be
claimed from bundle-only validation. It needs its own evidence packet with
command logs, environment details, and observed behavior, without changing the
language or resource contract unless the smoke run exposes a concrete bug.

## Goal

Run and document the native interactive window smoke for component-authored
text controls, proving that the sample opens without top-level input
declarations and that player-rendered text controls, submit buttons, keyboard
activation, and IME/Enter submit still use the shared player-backed route.

## Required Decisions

- Select the exact sample or samples to launch:
  `samples/native-text-input`, `samples/modern-feedback-view`, and/or
  `samples/text-submit-flow`.
- Define the minimum manual interaction checklist:
  focus, text entry, multiline behavior, secure masking, Enter/IME submit,
  button activation, keyboard focus movement, and close/cancel behavior.
- Define what trace output or observation evidence must be saved.
- Define environment reporting requirements: OS, backend, adapter, DPI,
  keyboard/IME state, and command line.
- Decide whether this smoke remains manual documentation or becomes an
  optional ignored native test/agent observe fixture.

## Implementation Order

1. Confirm the sample bundles/checks still pass without top-level input
   declarations.
2. Launch the native player/window with the selected sample.
3. Execute the manual interaction checklist.
4. Capture command logs, trace output, and any available observation JSON or
   screenshots.
5. If a bug is found, fix only the concrete native/player issue and preserve
   the component/View authoring contract.
6. Update implementation notes with pass/fail evidence and residual blockers.

## Tests To Specify And Implement

- Native sample launch command exits or remains interactive as documented.
- TextField receives focus and accepts text through the native path.
- TextArea accepts multiline editing where supported.
- SecureField renders masked text and does not leak raw value in observation
  output.
- Enter/IME submit reaches the same `text_submit` route as button activation.
- View-authored Button activation still emits a typed submit write-back.
- Removed top-level text-control declarations are not required by the sample.

## Constraints

- Do not reintroduce removed top-level input declarations as a workaround.
- Do not use platform widgets, DOM controls, or hidden native controls in place
  of the player-rendered route.
- Do not broaden this request into a new layout-bounds contract; that is tracked
  separately by seq06.16.2.
- Do not claim cross-platform Web validation from this native-only smoke.

Return a zip package named like:

```text

```

The zip should contain:

- implementation note updates;
- any focused native/player fixes if the smoke exposed a concrete bug;
- explicit remaining gaps.
