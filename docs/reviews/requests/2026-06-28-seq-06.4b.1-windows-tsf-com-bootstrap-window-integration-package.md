# Request 06.4b.1: Windows TSF COM Bootstrap And Window Integration Package

## Sequence Position

This follows seq06.4b and the applied safe Windows TSF adapter core recorded in:

- `docs/implementation/seq06-4abc-platform-text-input-adapters.md`
- `docs/implementation/seq06-ime-css-font-sample-2026-06-28.md`

Seq06.4b currently provides safe range conversion, capability facts,
edit-session grouping, display attribute mapping, geometry conversion, tests,
and fixtures. It does not yet implement the real Windows OS object layer.

## Problem

Arcweft cannot yet show a real native Windows IME sample because the production
window runtime does not instantiate and connect TSF COM objects. The missing
work is not another safe conversion module; it is the audited Windows object
boundary and its integration with focus, TextField snapshots, geometry, and the
window event loop.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for Windows TSF COM bootstrap
and native window integration.

The package must turn the existing safe TSF adapter core into a usable native
Windows IME path for Arcweft TextField/TextArea/SecureField.

## Required Inputs

- Current Arcweft `main`.
- `crates/arcweft-desktop-native/src/text_input/windows_tsf/`.
- `crates/arcweft-player-native/src/windowed*.rs`.
- `crates/arcweft-player-scene` focus/input routing.
- `crates/arcweft-ui` TextField editor and geometry APIs.
- `docs/reviews/requests/2026-06-28-seq-06.4b-windows-tsf-text-input-adapter-package.md`.
- `docs/implementation/seq06-4abc-platform-text-input-adapters.md`.
- Microsoft TSF documentation and Windows SDK evidence for COM apartment,
  `ITfThreadMgr`, `ITfDocumentMgr`, `ITfContext`, `ITextStoreACP`,
  `ITextStoreACPSink`, edit sessions, layout, display attributes, and
  reconversion.

## Required Decisions

1. The exact unsafe boundary module and rationale. Unsafe code must be isolated
   in a clearly named Windows-only module with comments documenting invariants.
2. COM apartment ownership and thread affinity:
   - where `CoInitializeEx`/thread manager activation happens;
   - how shutdown/deactivation is ordered;
   - what must stay on the window/UI thread.
3. The owner type for TSF state:
   - thread manager;
   - client id;
   - document manager/context;
   - text store;
   - sink;
   - edit cookies;
   - focus generation.
4. How the TSF text store reads from and writes to Arcweft TextField snapshots.
5. How native callbacks are converted to `PlatformTextInputEvent` using the
   existing safe core.
6. How Arcweft geometry updates reach TSF layout callbacks and candidate
   windows.
7. How display attributes become composition segments or HostDependent
   diagnostics.
8. How reconversion facts are detected and kept accurate.
9. How secure fields disable/redact surrounding text, reconversion, layout
   details, diagnostics, Agent observe, replay, and capture.
10. How native errors, stale callbacks, focus loss, window deactivation, and
    destroyed TextFields are rejected or cancelled.

## Required Implementation

The package must include implementation-ready code for the current repository:

- Windows-only COM owner and lifecycle module.
- `ITextStoreACP`/sink implementation or a documented equivalent binding layer.
- Integration from native window focus to `TextInputDispatchState` activation.
- TextField snapshot export and TSF text store read path.
- TSF edit-session callback conversion into Arcweft text-input batches.
- Geometry pumping from Arcweft layout to TSF layout query responses.
- Secure-field redaction at both Arcweft and TSF boundary.
- Native sample or player flag that opens a real TextField and accepts Japanese
  IME input on Windows.
- Windows fixture capture instructions for real IME traces.
- Non-Windows gates proving the COM layer is not compiled outside Windows.
- `docs/implementation/seq06-4b-1-windows-tsf-com-bootstrap-window-integration.md`.

## Acceptance Criteria

- A Windows native player/sample can focus an Arcweft TextField and receive real
  Japanese IME preedit and commit through TSF.
- Unsafe code is isolated, justified, and not spread across safe adapter logic.
- COM objects and edit cookies never enter Sans I/O crates.
- One TSF edit session or proven atomic callback group maps to one Arcweft
  serial.
- ACP/WCHAR ranges are converted through shared range logic and reject invalid
  ranges without silent clamp.
- Candidate geometry is driven by Arcweft layout snapshots.
- Secure fields do not expose surrounding text, ranges, character bounds, or
  TSF object identity.
- Non-Windows builds still compile.

## Tests To Specify And Run

- Existing safe TSF unit tests.
- Windows-only COM lifecycle tests where feasible.
- Native sample smoke on Windows with a Japanese IME trace.
- Focus loss and delayed callback rejection tests.
- Geometry/candidate rect fixture tests.
- Secure-field redaction tests.
- Non-Windows compile/source-gate tests.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test`/`cargo clippy`.
- Structural audit because this adds platform I/O and unsafe/object boundary
  code.

## Constraints

- Do not redesign the common seq06.3 text-input contract.
- Do not put COM/native identity in Sans I/O payloads.
- Do not use unsafe outside the audited Windows object boundary.
- Do not create compatibility shims around TSF failures.
- Do not fake real IME success with the existing safe contract sample.

## Non-Goals

- Web, macOS, Wayland, Android, or iOS implementation.
- Replacing the renderer.
- Supporting non-TSF Windows text stacks unless evidence proves TSF alone is
  insufficient.
