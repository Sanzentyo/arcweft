# Request: seq-06.11a CSS computed style direct paint extractor package

## Sequence position

Seq06.11a is split out after the reactive UI sample request because the current
gap is narrower than full CSS layout/cascade support.

Treat these as already implemented substrate:

- `arcweft-takumi-adapter` uses Takumi as the CSS cascade/layout/stacking source;
- `arcweft-render-wgpu::ui_scene` owns direct primitives such as solid rects,
  rounded rects, borders, linear gradients, images, glyph runs, opacity,
  transforms, and clips;
- seq06.9a/06.9b own compositing scene and effect contracts;
- seq06.11 owns product UI resource to retained UI frame integration.

Do not redesign the product UI resource codec, the compositor contract, or the
retained UI interaction-state model.

## Problem

The repository has direct primitive types and Takumi computed style data, but
the current lowering path still receives direct paint through a
`DirectPaintCatalog` supplied from outside the computed CSS style. That means
ordinary CSS such as `background-color`, `border`, `border-radius`,
`background-image: linear-gradient(...)`, and image backgrounds is not yet a
clear end-to-end path from CSS source to Arcweft-owned direct wgpu primitives.

This is the largest missing connection before a practical CSS subset can be
used by real UI samples.

## Goal

Design and implement a deterministic extractor that turns Takumi computed style
for supported paint properties into Arcweft-owned direct paint entries.

The extractor should make this path explicit:

```text
CSS source -> Takumi computed style -> DirectPaintCatalog -> UiScene direct primitives
```

Supported first-cut properties should include, at minimum:

- `background-color`;
- `border-color`, `border-width`, and supported border sides;
- `border-radius`;
- `background-image: linear-gradient(...)`;
- image backgrounds where a resource reference can be represented without file
  or network I/O in the data crate;
- opacity and transform metadata needed by the direct primitive scene.

## Required decisions

- Define the owning module for the extractor. It should likely live in
  `arcweft-takumi-adapter`, not in `arcweft-render-wgpu`, because it consumes
  Takumi computed style.
- Define the exact extractor input:
  - Takumi render node path;
  - computed style;
  - sizing context;
  - resource reference table;
  - Arcweft node metadata.
- Define the output contract:
  - new `DirectPaintCatalog` entries;
  - primitive ranges;
  - diagnostics for unsupported values;
  - capture/evidence records.
- Decide how CSS logical shorthands expand into supported physical sides.
- Decide how conflicting background layers are handled:
  - supported ordered layers;
  - unsupported layer kinds;
  - explicit diagnostics rather than dropped layers.
- Decide how unsupported CSS values are surfaced. Do not silently approximate
  or rely on browser rendering.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes.
- Keep Takumi as cascade/layout source only. Do not use Takumi CPU raster output.
- Keep renderer primitives Arcweft-owned and backend-independent.
- Keep filesystem/network/resource loading in adapter/player layers.
- Do not use DOM, canvas 2D, screenshot analysis, or hidden HTML fallback.
- Preserve seq06.9 compositing contracts for properties that require subtree
  effects.

## Tests to specify and implement

- `background-color` creates one solid rect direct paint entry.
- `border-radius` creates rounded rect/direct clip metadata where supported.
- `border` sides produce deterministic border primitives or a structured
  unsupported diagnostic.
- linear gradient background produces a direct gradient primitive.
- layered background with an unsupported layer emits a diagnostic and preserves
  supported layers according to the chosen policy.
- resource/image background records a typed resource requirement without
  reading files from the adapter crate.
- capture evidence maps Takumi path, Arcweft metadata, local bounds, and
  primitive range.

## Expected output

Return a zip named like:

```text
arcweft-seq06.11a-css-computed-style-direct-paint-extractor-YYYY-MM-DD.zip
```

The zip should contain:

- design markdown;
- implementation note;
- overlay source edits;
- focused tests;
- sample/fixture CSS files;
- validation commands and known unsupported values.

## Non-goals

- Do not connect the extracted direct paint into the normal player render path;
  seq06.11b owns that.
- Do not implement full CSS cascade/layout coverage; seq06.12 owns that.
- Do not implement transitions/keyframes or advanced mask/clip closures;
  seq06.13 and its splits own those.
