# Request: seq-06.10a styled paragraph layout package

## Sequence position

Seq06.10a is split out while seq06.10 cross-backend text raster parity is being
designed.

Seq06.10 focuses on cross-backend glyph raster evidence, font pinning,
antialiasing tolerance, and native/web image metrics. This request focuses on
the layout substrate that must be stable before those raster metrics are
meaningful: styled text must be laid out as one paragraph/text box, not as
independent style-run blocks.

Treat the viewport scale repair recorded in
`docs/implementation/2026-06-30-css-style-parity-startup-scale-profile.md` as
already implemented substrate. Do not redesign `RenderViewport::scale_factor`,
native/web capture plumbing, or the existing CSS-style sample unless current
implementation evidence shows a concrete flaw.

## Problem

Current dialogue text planning splits `RichTextTextRun` values into separate
`RenderTextBlock` values. Each block is shaped and wrapped independently by the
renderer. The next run's x-position is advanced with `estimated_text_width`,
not with the actual shaped glyph/run layout.

That means styled text cannot wrap as one paragraph. Bold/color/font-size spans
can cause line breaks, clipping, or offsets that differ from CSS-like paragraph
layout. It also makes seq06.10 raster parity harder to interpret because a
native/web mismatch may actually be a paragraph-layout bug.

## Goal

Design and implement a renderer-owned styled paragraph layout path for dialogue
text so all inline styles in one dialogue body are shaped and wrapped together
inside one text box.

The final model should preserve typed style spans and effects, but the wrapping
decision must be paragraph-wide. Style changes must not reset line layout unless
the source text actually contains a paragraph/line break boundary.

## Required decisions

- Define the new renderer-facing text model:
  - keep `RenderTextBlock` for single-style labels and controls, and add a new
    `RenderStyledParagraph`; or
  - replace `RenderTextBlock` with an enum such as `RenderTextItem::Block` /
    `RenderTextItem::Paragraph`; or
  - evolve `RenderTextBlock` to hold styled spans where this does not blur label
    and paragraph responsibilities.
- Decide how `RichTextTextRun` maps into renderer spans:
  - byte range vs character range ownership;
  - style inheritance from `base_styles`;
  - line-height and font-size behavior when spans differ within one line.
- Decide how typewriter and glyph-transform effects apply after paragraph
  layout:
  - typewriter should reveal by source/glyph range without changing wrap;
  - wave/shake/jitter should be glyph-position transforms after shaping;
  - effects must not force one glyph per independent layout buffer unless that
    is explicitly isolated behind an effect-specific glyph transform layer.
- Decide whether glyphon/cosmic-text `AttrsList` or an equivalent typed span
  list is the primary implementation route.
- Decide which text surfaces migrate in this cut:
  - dialogue body must migrate;
  - speaker labels, choice labels, and text input controls may remain
    single-style blocks unless they already need paragraph wrapping.
- Decide how layout evidence is exposed to seq06.10:
  - paragraph line boxes;
  - run/span ranges;
  - glyph bounds;
  - optional text mask metadata.

## Implementation requirements

- Produce a zip package with docs, overlay/patches, tests, and validation notes,
  matching prior Arcweft sequence package style.
- Do not parse terminal text, DOM text, CSS browser output, or screenshots to
  reconstruct layout.
- Do not introduce hidden DOM text, HTML overlay text, canvas 2D fallback text,
  or browser-only text layout. Native and web must continue through the shared
  renderer path.
- Do not preserve the current run-per-block behavior as a compatibility shim for
  dialogue body layout. Replace it at the root.
- Keep renderer/data crates Sans I/O. Font file loading, screenshot capture, and
  browser orchestration belong in tools/tests/adapters.
- Keep lower-level crate boundaries intact. Product player crates must not
  depend on CLI, MCP, LSP, debug inspection adapters, or screenshot tooling.
- Avoid ad hoc stringly style projections. If an Arcweft-owned style/effect enum
  needs behavior, add it on the owning type or a named renderer lowering
  context.
- Keep the API shape compatible with future seq06.10 raster evidence. If
  seq06.10 is already in progress, document any assumption that must be shared
  between the two packages.

## Suggested implementation order

1. Audit current dialogue text planning in `arcweft-render-wgpu`:
   `RenderDialogue`, `RenderTextBlock`, `push_dialogue_text_blocks`,
   `push_motion_text_blocks`, and `text_buffer`.
2. Design the new paragraph/span boundary and document ownership:
   prepared-frame data, renderer buffer construction, effects, and test
   evidence.
3. Implement paragraph-wide layout for dialogue body using a single shaped
   buffer with span attributes.
4. Preserve single-style block behavior only for non-paragraph surfaces where it
   remains correct.
5. Move typewriter reveal and glyph-transform effects onto paragraph/glyph range
   semantics. Do not let effects accidentally restore independent style-run
   wrapping.
6. Extend CSS-style parity fixtures with a styled long paragraph that must wrap
   across bold/color/font-size boundaries.
7. Feed any text-layout evidence needed by seq06.10 into the implementation note
   or a stable test fixture.

## Tests and validation to specify

- Unit tests proving a styled paragraph wraps as one paragraph across style-run
  boundaries.
- Regression test showing the old run-per-block estimate path cannot return for
  dialogue body text.
- Tests for typewriter reveal across a line break created by paragraph wrapping.
- Tests for mixed bold/color/font-size spans in one paragraph.
- Existing text input/choice label tests to prove non-dialogue labels did not
  regress.
- `just css-style-parity`
- `just css-style-parity-profile`
- `cargo test -p arcweft-render-wgpu ...` focused tests for text planning and
  renderer buffer construction.
- `cargo check` / `cargo clippy` for touched crates.
- `cargo +nightly -Zscript tools/structure-audit.rs --root .` when public
  renderer contracts or large files change.
- `git diff --check`

## Acceptance criteria

- Dialogue body style runs are no longer emitted as independent layout blocks.
- Inline style changes do not reset wrapping or advance with
  `estimated_text_width`.
- Paragraph wrapping is deterministic and shared by native and web.
- Typewriter and glyph-transform effects are applied by typed range/glyph
  semantics, not by splitting the paragraph into independent buffers for normal
  styling.
- CSS-style parity includes a long styled paragraph fixture that fails under the
  old run-per-block model and passes under the new model.
- Seq06.10 can treat paragraph line/glyph evidence as stable input for raster
  parity design.

## Non-goals

- Do not solve cross-backend font antialiasing or exact pixel identity here;
  that remains seq06.10.
- Do not redesign viewport scale, screenshot capture, or native/web player
  launch paths.
- Do not implement full CSS layout. This request is only inline styled paragraph
  layout for renderer-owned text.
- Do not add LSP/MCP/CLI-facing text layout APIs.
