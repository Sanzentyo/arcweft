# AW-AH-009.3.3.2 — Typed external project-binding path publication

- Date: 2026-07-17
- Sequence: correction branch after AW-AH-009.3.3 Cut 2 catalog publication
- Kind: independently throwable production-reconciliation contract
- Production changes: prohibited
- Output language: English

## Goal and dispatch contract

Freeze the typed path contract by which external project-symbol producers publish
source-visible bindings into `ProjectSymbolTable` and, in the same accepted-world
transaction, into `ProjectCallableCatalog`. The result must let the callable catalog
index every qualified and compact non-callable shadow binding without splitting a
display string or reinterpreting an opaque symbol leaf.

Send this request by itself to exactly one assignee with the current Arcweft `main`,
the root `AGENTS.md`, the Rust skill, and the AW-AH-009.3.3 final-contract ZIP. The
assignee must inspect current syntax/HIR symbol path types, adapter registration
facts, character registration facts, and callable catalog publication before making
the decision. This request must not redesign the already implemented callable IDs,
schemas, catalog record types, adapter callable model, or atomic accepted-world
transaction unless current implementation evidence demonstrates a concrete flaw.

## Production seam that requires correction

AW-AH-009.3.3 fixes `ProjectCallablePath` as a package, module, and segmented
`CallablePath`; each `CallableName` rejects `.` and other path separators. It also
requires a complete `ProjectNameBinding` map and forbids parsing labels, aliases,
display paths, Rust paths, comments, or source text into identity.

Current project-symbol producers do not retain that segment evidence:

- `ProjectDirectBinding` stores `name: String`;
- `ProjectSymbolTable` scopes are keyed by `String` and expose only `&str` spellings;
- `SymbolPath` deliberately permits an opaque external leaf such as
  `character.akane`;
- character registration publishes both `character.akane` and `akane`;
- adapter environment symbols may likewise publish dotted external spellings.

A compact alias such as `akane` can be converted to one `CallableName`. A direct
binding such as `character.akane` cannot: splitting it on `.` would manufacture
identity from an opaque string, while retaining it as one segment violates
`CallableName`. Silently omitting the binding violates the complete-shadow-map
requirement; rejecting the candidate world would reject currently valid character
and adapter registrations.

## Required decisions

Select one owning typed model and provide exact Rust fields, constructors, accessors,
errors, and visibility for it. The recommended direction is to retain a validated
`ProjectSymbolPath` (or a smaller HIR-owned equivalent with typed segments) in each
direct/scope binding and expose that typed path from `ProjectSymbolTable`. If another
model is selected, it must meet the same invariants without adding a string split in
sema.

The final contract must decide:

1. which syntax/HIR type owns the source-visible binding root and ordered segments;
2. whether `ProjectDirectBinding` stores that path directly or stores a new exact
   typed binding-path value;
3. how `ScopeBinding` retains typed paths through direct insertion, import,
   re-export, aliasing, and fixed-point coalescing;
4. how a module-local alias such as `hero` differs from a direct qualified binding
   such as `character.akane` without parsing either after linking;
5. how character and adapter fact producers construct typed paths from their own
   typed identities at the producer boundary;
6. how external canonical identity (`ExternalDeclarationSeed::canonical_path`) and
   source-visible binding identity remain distinct where required;
7. the exact deterministic iterator consumed by callable catalog construction;
8. how project module bindings and non-callable `TypeKind` facts are carried without
   sema depending on adapter types;
9. duplicate, ambiguity, inaccessible import, and invalid-segment behavior;
10. the direct replacement/deletion plan for the string-only API.

## Required implementation order

1. Add the typed binding-path owner and direct constructor/accessor tests.
2. Replace `ProjectDirectBinding` string-only construction and migrate every
   character, adapter, registration-test, and project-linker producer in one cut.
3. Retain typed binding paths through `ProjectSymbolTable` insertion, import,
   re-export, alias, and coalescing.
4. Expose one deterministic typed scope-binding iterator.
5. Make `RegisteredCallableCatalogBuilder` consume that iterator and publish every
   callable and non-callable binding, removing the invalid-name skip.
6. Add accepted-world atomicity tests for malformed or colliding typed paths.
7. Run focused HIR, registration, adapter, sema catalog tests, workspace
   check/clippy, and the canonical structural audit.

## Mandatory direct tests

- `character.akane`, compact `akane`, and authored alias `hero` each retain their
  exact typed path and resolve to the same external declaration;
- an adapter-owned qualified binding such as `adapter.viewport` is published without
  a sema-side string split;
- project non-callable `character.akane` and `hero` bindings terminate fallback to a
  same-spelled environment callable;
- a qualified callable, a module binding, and an external binding in one scope remain
  distinct and deterministic;
- import, re-export, glob, and explicit alias paths preserve typed segments;
- valid external segments containing `-` remain valid without being mistaken for
  module identifiers;
- invalid empty/control/separator segments fail at the owning constructor;
- reversed fact insertion produces identical project binding catalogs;
- a binding collision rejects the candidate world before publication and preserves
  the previous accepted world pointer;
- public/dependency evidence uses typed APIs and Cargo metadata, never source scans.

## Constraints

- Do not split `SymbolPath::leaf()`, `CharacterId::as_str()`, adapter symbol labels,
  or formatted paths inside sema or the callable catalog builder.
- Do not add a dotted-string compatibility constructor, deprecated wrapper, dual
  reader, extension trait, source gate, or second project-symbol resolver.
- Do not collapse a source-visible alias into canonical external identity.
- Do not change current import visibility, ambiguity, alias-budget, or fixed-point
  behavior.
- Do not make HIR depend on sema or adapter-context.
- Do not redesign accepted source/world identity, AW-AH-009.3.1 call ranges, or
  AW-AH-009.3.2 request lifecycle.
- The correction must move directly to the typed final model and delete the
  string-only construction path in the same coherent cut.
