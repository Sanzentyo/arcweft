## Why the TTS split is required

Character display-name projection is accepted metadata rendered through View.
Provider-speaker selection is external adapter configuration and I/O
dispatch. They do not share identity, persistence, capability, wire, or
failure ownership.

Keeping TTS in this correction would make a currently nonexistent provider
subsystem a prerequisite for removing `dialogue.speaker`. It would also tempt
an implementation to equate `CharacterId`, display-name text, and provider
speaker keys. AW-AH-009.4.1.2 therefore owns TTS independently, while this
request owns only the dialogue character/View projection and its accepted
catalog.

## Why this correction is required

The returned package reports `READY_FOR_IMPLEMENTATION` and
`OPEN_QUESTIONS=0`, but current production evidence and the package's own
normative documents leave result-changing decisions unresolved.

### 1. `DialogueValueProjection::Content` contradicts the nested model

`NESTED_VIEW_TYPE_MODEL.md` defines:

```rust

    CharacterId,
    CharacterDisplayName,
    Occurrence,
    Stage,
    Reveal,
    PrimaryAction,

```

`BUNDLE_VIEW_WIRE_CONTRACT.md` instead defines:

```rust
pub enum DialogueValueProjection {
    CharacterId,
    CharacterDisplayName,
    Content,
    Occurrence,
    Stage,
```

This changes the closed accepted schema, serialized discriminants, duplicate
coordinate rules, evaluator behavior, and tamper matrix. It cannot be left to
the implementation agent.

### 2. The claimed existing localization catalog is not implemented

Current production has a `BundleSectionKind::LocaleCatalog` section identity,
but no accepted Character display-name catalog record, canonical codec,
revision type, digest contract, runtime lookup owner, or strict decoder for the
model required by AW-AH-009.4.1.

The original package sketches
`CharacterDisplayNameEntry::{Visible, Hidden}` and refers to
`CharacterPresentationCatalogRevision`, but it does not define the exact
record, accepted catalog, revision identity, digest inputs, canonical wire,
cross-record validation, or mutation boundary. Its stale, duplicate,
noncanonical, oversized, and tamper tests therefore do not yet identify one
implementable owner.

### 3. Character source-body ownership is unresolved

Current Character declarations still pass through the provisional generic
`EntityDeclItem` body. Proof 01.1.1.2 is explicitly responsible for selecting
the final typed Character header and body, including display-label ownership,
source-versus-manifest metadata, field types, duplicate behavior, recovery,
and references to typed resources.

AW-AH-009.4.1 must not introduce a second ad hoc parser for:

```arcw

```

or keep the current raw body alive merely to publish the name catalog.

### 4. Two distinct `source_locale` concepts are not separated

The implemented AW-AH-009.4 Cut 1 `CharacterDialogueConfig` contains
`source_locale`, whose value is line/dialogue configuration. AW-AH-009.4.1
also describes a Character display-name metadata source locale while
prohibiting line/config display-name overrides.

The final contract must give these concepts separate typed owners and names.
It must state unambiguously whether each participates in:

- dialogue content localization;
- character display-name resolution;
- the active session locale;
- fallback-chain construction;
- saved state;
- catalog revision and digest computation.

No implementation may infer a character display-name locale from
`CharacterDialogueConfig::source_locale`.

### 5. AW-AH-009.4 Cuts 2–5 and save schema 2 are prerequisites

Current production has only AW-AH-009.4 Cut 1. It still contains:

- string/callee-based dialogue HIR and line identity;
- `LineDisplaySpec`;
- `LineDisplayFrame::{callee, speaker_label}`;
- `DialogueViewProjection::Speaker`;
- `DialogueTextProjection::Speaker`;

- bundle-session save schema 1.

The corrected contract must not claim that a typed View projection can be
switched independently of the source/HIR, sema, AWBC, runtime-frame, and
schema-2 owners that create the `CharacterDialogue` value and
`DialoguePresentationCharacter`.

### 6. The 268-row test matrix overstates present implementation seams

The original matrix combines valid projection requirements with:

- unspecified localization-catalog codec tests;
- unspecified revision/digest stale tests;
- save-schema-2 tests before that schema is implemented;
- TTS provider tests for a subsystem that does not exist;
