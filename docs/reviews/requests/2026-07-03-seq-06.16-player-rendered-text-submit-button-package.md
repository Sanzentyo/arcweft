# seq-06.16 player-rendered text submit button package

## Sequence Position

This follows seq-06.4k/06.4k.1 text-control convergence and the 2026-07-03 DSL
text-input submit sample. The substrate now has DSL-declared `@input.*`
controls and `let value = text_submit @input.id` for Enter/IME send. What is
missing is a visible Arcweft-rendered submit button that triggers the same
typed submit path.

## Goal

Design and implement a cross-platform, player-rendered submit button contract
for text controls. The button must work on native and web through the same
player/runtime route and must not require HTML button glue, hidden DOM fallback,
or compatibility shims.

## Authoring Surface Correction

Do not implement this request by adding a new top-level `ui action_button`
syntax. That would harden the transitional resource-side UI authoring model.
The stable user-facing authoring surface for buttons belongs to
component/View, with styling coming from the root `style` direction described
by seq-06.11c.

Seq-06.16 may add the product/runtime/player substrate needed by a rendered
submit button. Component/View parser/HIR/sema/bundle lowering for authored
buttons is split to seq-06.16.1.

## Required Design Decisions

- Define the component/View surface for binding a rendered button to a text
  input submit action. Prefer a typed event/action representation over stringly
  handler names.
- Define the product UI resource shape emitted from DSL for this button/action.
- Define the runtime/player event path: pointer/keyboard activation of the
  button must produce the same `RuntimeTextControlWriteBackKind::Submit` that
  Enter/IME send produces.
- Define focus behavior when activating the button while an IME composition is
  active: commit, cancel, or reject with diagnostic, using a typed policy.
- Define accessibility/keyboard traversal expectations for native and web.
- Define how style state applies to the button: idle, hover, pressed, focused,
  disabled.

## Implementation Requirements

- Update the DSL parser/AST/HIR/sema/project-index layers as needed.
- Update bundle UI resource emission from DSL.
- Update player-scene/native/web paths so the button is rendered by Arcweft, not
  by platform DOM/widgets.
- Update `samples/text-submit-flow/` to include a visible submit button in
  addition to Enter/IME send.
- Add focused tests for parser, type checking, bundle emission, and runtime
  submit write-back synthesis.
- Add source gates only for real architectural regressions; prefer behavior
  tests for normal coverage.

## Constraints

- Do not redesign existing text-control geometry/write-back substrate unless
  concrete evidence shows it is flawed.
- Do not add compatibility aliases, hidden DOM controls, or legacy sidecar
  fallback paths.
- Keep lower-level data crates Sans I/O.
- Use the same player-backed path for web and native.

## Expected Output

Return a zip package containing:

- overlay/patch files for implementation;
- request/design markdown with final contracts;
- implementation note with verification results and known platform gaps;
- tests and sample updates;
- validation commands and results.
