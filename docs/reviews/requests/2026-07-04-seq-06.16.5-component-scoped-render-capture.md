# Seq 06.16.5 request: component-scoped render and capture contract

## Sequence position

This follows seq 06.16.2 through 06.16.4, after component text-control layout
bounds, native interactive smoke, and runtime-control styling. It must build on
the existing viewport/layer/object/rich-text-child capture substrate rather than
redesigning those contracts without concrete evidence of a flaw.

## Why this split is needed

Current runtime and Agent capture surfaces can crop the viewport, a layer, or an
observed object. They do not expose a first-class component selector, a stable
component-region resource, or a way to render only one component while preserving
the dependency context needed by child controls.

The missing design decisions cross View lowering, prepared-frame geometry, native
capture selectors, CLI/MCP protocol shape, and tests. They are larger than the
text-control visual-navigation slice and need an explicit contract before
implementation.

## Required decisions

- Define what a component capture scope means when the component expands into
  multiple semantic objects, runtime text controls, action buttons, images, and
  style-generated child elements.
- Decide whether component identity is carried by `ViewProgramInstruction`,
  layout-bounds resources, semantic targets, render objects, or a new prepared
  frame scope table.
- Specify component-region bounds: union of child object bounds, authored layout
  bounds, clipped visible pixels, or selectable alternatives.
- Specify whether component-only rendering may omit siblings while still using
  inherited theme/style/environment resources from the full scene.
- Define selector syntax for CLI and MCP, for example `--component ID`, and how
  it composes or conflicts with `--layer`, `--object`, `--capture object-id`,
  and `--capture mask`.
- Define failure diagnostics for unknown component ids, empty component bounds,
  hidden components, and components whose resources are not renderable without
  parent context.

## Implementation order

1. Extend the UI/component lowering contract so each component can emit a stable
   component scope id and retain the mapping to descendant render objects.
2. Add a prepared-frame component scope table with viewport-space bounds and
   descendant object refs.
3. Extend Agent observation JSON and capture refs to include component scopes.
4. Add native capture selector support for component crop, object-id, and mask
   captures using the same renderer path as layer/object captures.
5. Add CLI and MCP selector support.
6. Add docs and examples showing component capture alongside object capture.

## Tests to specify

- Resource-codec round-trip for component scope ids and bounds.
- Component-view lowering test proving a component with a text input and button
  yields one component scope with both descendants.
- Prepared-frame test proving component bounds union descendant object bounds
  and remain stable across child ordering changes.
- CLI native-capture tests for `--component`, `--capture object-id
  --component`, and `--capture mask --component`.
- MCP capture tests proving component capture refs can be listed and read.
- Negative tests for unknown component, empty bounds, and selector conflicts.

## Constraints

- Do not redesign verified viewport/layer/object capture unless current
  implementation evidence shows a concrete flaw.
- Preserve existing `--layer` and `--object` behavior and capture URI stability.
- Keep low-level presentation/core crates Sans I/O.
- Keep component capture identity typed; do not add stringly ad hoc matching in
  the renderer or CLI.

## Expected output

- A design package or patch set that defines the component scope data contract,
  selector syntax, capture metadata, diagnostics, and validation suite.
- An implementation note under `docs/implementation/` that records any non-goals
  and validation gaps.
