# Request 06.4e: Android InputConnection Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the Android platform adapter package and should not
redesign the shared capability, range, batch/serial, or geometry substrate
unless current implementation evidence proves a concrete flaw.

This request can be run independently from the Web, Windows, macOS, Wayland,
and iOS adapter requests. If the current Arcweft checkout has no Android host
crate, the package must define the narrowest concrete Android adapter boundary
needed for this feature instead of pretending that desktop or Web code owns it.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for an
Android `InputConnection` adapter for Arcweft text input.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints.
- Official Android SDK documentation for `InputConnection`, `EditorInfo`,
  `InputMethodManager`, `CursorAnchorInfo`, batch edits, composing regions,
  UTF-16 `CharSequence` offsets, and API-level behavior.

## Platform Scope

Implement the Android adapter in the current mobile/native host owner if one
exists. If none exists, the zip must include a concrete, feature-gated Android
adapter crate or module plan plus implementation overlay for the Rust/JNI and
Java/Kotlin boundary required by `InputConnection`.

The adapter must:

- keep Java/Kotlin objects, JNI references, `InputConnection` instances, native
  view objects, Android batch depth, API-level objects, and native identity
  adapter-local;
- treat Java `char` and `CharSequence` offsets as UTF-16 code-unit source units;
- map `deleteSurroundingTextInCodePoints` through Unicode scalar source-unit
  conversion;
- allow Android pre-clipping behavior before event creation only when the final
  Arcweft event validates canonical byte ranges;
- record pre-clipped information only as fixture-local diagnostic metadata;
- coalesce the outermost `beginBatchEdit` through `endBatchEdit` into one
  Arcweft batch/serial;
- keep nested batch depth adapter-local;
- map one method call outside a batch to one Arcweft event unless official API
  evidence proves it belongs to the same native atomic group;
- model `commitText` as committing or replacing the current composing region and
  ending current composition;
- upgrade character bounds/text bounds capability only from API-level/runtime
  facts;
- compute view-local rectangles and `CursorAnchorInfo` matrix data from
  Arcweft geometry in the adapter;
- omit all character bounds for secure fields and report them as
  `SecureRedacted`, not plain platform unsupported.

## Required Decisions

1. The Android crate/module ownership, target gating, and Rust/JNI/Java/Kotlin
   source layout.
2. The API-level matrix for `InputConnection`, `CursorAnchorInfo`, text bounds,
   and composing-region behavior.
3. The lifecycle owner for focus, view attachment, `EditorInfo`, and
   `InputConnection` invalidation.
4. The UTF-16 and code-point conversion path, including surrogate pairs,
   invalid ranges, Android clipping, stale snapshots, and reject/no-clamp rules.
5. The outermost batch transaction boundary that creates one Arcweft serial.
6. The mapping of `commitText`, `setComposingText`, `setComposingRegion`,
   `finishComposingText`, selection, delete, close connection, and editor
   actions into Arcweft operations and capabilities.
7. The geometry conversion from Arcweft viewport/screen rectangles into
   View-local rectangles and `CursorAnchorInfo`.
8. The secure-field policy for surrounding text, composing metadata,
   `CursorAnchorInfo`, diagnostics, Agent observe, replay, and capture output.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include:

- Android adapter modules, Java/Kotlin glue, JNI boundary code, and any
  feature/Cargo/build edits.
- Typed capability detection and activation diagnostics.
- `InputConnection` method conversion into `PlatformTextInputEvent`.
- UTF-16/code-point range conversion through shared text-index APIs.
- Batch coalescing and close/focus invalidation behavior.
- Geometry adapter code for `CursorAnchorInfo` and secure redaction.
- Android fixture traces for:
  - surrogate pair delete with no split;
  - code-point delete;
  - composing-region clipping and diagnostic metadata;
  - nested batch coalescing;
  - `commitText` ending composition;
  - `setComposingText` after commit in one outer batch;
  - `finishComposingText`;
  - `closeConnection` invalidation;
  - API-level bounds differences;
  - secure field redaction.
- Cross-target compile gates so non-Android hosts do not require Android SDK
  objects.
- `docs/implementation/seq06-4e-android-inputconnection-adapter.md`.

## Acceptance Criteria

- Android activation uses typed capability facts and diagnostics.
- Android native metadata remains adapter-local or fixture-local only.
- All normalized text operations carry canonical byte ranges only.
- UTF-16 and code-point range conversions handle surrogate pairs correctly.
- One outermost Android batch maps to one Arcweft serial.
- Geometry revisions are separate from input serials and Android batch depth.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, selected-range-derived anchor, or native object
  identity.
- If a new Android adapter boundary is introduced, its crate/layer ownership is
  documented and structurally audited.

## Tests To Specify And Run

- Focused Android adapter tests for conversion, composing behavior, batch
  coalescing, focus invalidation, geometry, API-level capability differences,
  and secure redaction.
- Non-Android compile/source-gate tests proving Android code is correctly gated.
- Shared presentation/runtime-host tests that the Android adapter relies on, if
  not already present in main.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- Android target or host validation where available.
- `cargo clippy` for changed Rust crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not put Java/Kotlin objects, JNI refs, View identity, or Android batch depth
  in Sans I/O payloads.
- Do not store source units in normalized operations or geometry snapshots.
- Do not widen text-bounds capability without API-level/runtime evidence.
- Do not fake Android support through desktop or Web adapter code.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Web, Windows, macOS, Wayland, or iOS implementation.
- Full Android app shell redesign beyond the narrow adapter boundary needed for
  text input.
- Replacing the seq06.3 common contract.
