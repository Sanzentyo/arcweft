# Seq-04.6 Request: Module-Aware Sema and Typecheck Cache Gates Package

## Sequence Position

This follows seq04.1 through seq04.5. The current repository has deterministic
parse/HIR/interface `.awbo` payloads, read-through/write-through, cache explain
evidence, and interface-summary facts. Seq04.5 deliberately keeps typecheck and
linked-HIR reuse conservative because current semantic analysis still operates
over linked project context.

Seq04.6 is the gate that decides and implements the smallest sound
module-aware semantic boundary needed before later runtime-plan, bytecode, or
link-plan persistent reuse can trust typechecked inputs.

Do not redesign the already-applied seq04.1-04.5 substrate unless current
source evidence shows a concrete flaw.

## Request

Design and implement the seq04.6 module-aware sema/typecheck cache gate.

Return the final work as a zip package with design, Rust implementation
overlay, tests, implementation notes, validation notes, and apply instructions.

## Required Decisions

1. What exact module-level semantic facts are stable enough to persist without
   serializing unstable linked-HIR or compiler-private Rust internals.
2. Whether this package can implement actual module-aware typecheck reuse now,
   or whether it must implement explicit conservative-miss evidence and a
   stable prerequisite schema only.
3. How interface summaries, import/export digests, dependency interface
   digests, source digests, compiler identity, options, and environment inputs
   combine into a typecheck query key.
4. What constitutes a sound typecheck hit versus a soft miss.
5. How stale dependency interface changes invalidate dependent module
   typecheck records.
6. How diagnostics, source ranges, type signatures, capability/effect facts,
   and public symbol facts are represented in persisted evidence.
7. How `BuildSnapshot` and `arcw cache explain` report conservative misses,
   valid-but-rebuilt hits, or actual typecheck hits.
8. What must remain private to `arcweft-compiler` and what belongs in
   `arcweft-project` persistent object schemas.

## Required Implementation

Implement the subset that is sound in current `main`.

The expected ready minimum is:

- stable `.awbo` schema for module semantic/typecheck facts or an explicit
  `TypecheckGateObject` that records why reuse remains conservative;
- query-kind and artifact-kind ownership on Arcweft enums rather than stringly
  stage helpers;
- read/write-through for the ready object family;
- `BuildSnapshot` evidence that distinguishes:
  - valid typecheck facts used for evidence but rebuilt conservatively;
  - dependency-interface soft misses;
  - compiler identity/schema/source/options/environment soft misses;
  - actual typecheck reuse if implemented;
- cache explain output for the new query family;
- tests proving unchanged AWFB output and deterministic evidence.

If current source evidence proves actual typecheck reuse is not sound yet, do
not fake it. Implement the stable gate object and conservative evidence, and
return a narrow follow-up request for the missing module-aware sema work.

## Acceptance Criteria

- The package does not serialize linked HIR, `HirModule`, or
  `CompiledProjectModule` as a persistent compatibility promise.
- Any implemented typecheck reuse is backed by module-level dependency digests
  and typed validation, not by a broad project-global cache hit.
- If typecheck reuse remains conservative, that status is explicit in typed
  evidence and cache explain output.
- Dependency interface changes produce typed soft misses.
- Repeated builds preserve deterministic AWFB content roots.
- Later seq04.7 runtime-plan reuse can depend on this package's typecheck gate
  without guessing whether semantic inputs are sound.

## Non-Goals

- No bytecode-unit reuse.

- No product AWFB/AWBC format redesign.
- No semantic compatibility shim for removed language/compiler internals.

  typecheck cache evidence sound.
