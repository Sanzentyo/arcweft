# Request 02.6/02.7 Follow-up: AWFR Publish, External Payload Fetch, and Trust Verifier Package

## Sequence Position

This follows the applied seq-02.6 / seq-02.7 AWFR and signing boundary cut.
The current repository already contains Sans I/O AWFR archive, external payload
carrier, release manifest rewrite, signing policy, transcript, and local/cache
external payload fetch support.

This request closes the adapter-level work that was explicitly cut out of
`docs/implementation/2026-06-28-seq-02-6-02-7-remaining-work.md`. It must not
redesign the already implemented Sans I/O archive or signing policy substrate
unless current source evidence proves a concrete flaw.

This request can be thrown independently from seq-02.8. If it discovers overlay
cleanup work, record it as input for seq-02.8 instead of mixing generated
overlay classification into this package.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and later review/application notes
for the remaining seq-02.6 / seq-02.7 adapter work:

- HTTP(S) external payload fetch adapter;
- release-publish adapter with atomic staging and recoverable failure behavior;
- target signature regeneration after patch materialization;
- shared release-consume trust verifier;
- `ExternalPayloadMaterializationMode` wiring through patch materialization;
- CLI smoke commands for publish, verify, external payload fetch, and target
  signing flows.

The requested deliverable is the design-and-implementation package itself, in
the same style as prior Arcweft zip packages. Do not directly modify, commit, or
push to the requester repository as part of this request. Put all implementation
work under `overlay/` and `patches/` so a separate application step can review
and apply it.

## Required Decisions

1. Which crate owns HTTP(S) external payload fetch policy and which crate owns
   CLI/network adapter orchestration.
2. How HTTP(S), auth profiles, proxy profiles, client profiles, retry budget,
   timeout, cancellation, and mirror ordering reuse the existing release bundle
   fetch boundary.
3. How external payload fetch attempts are reported without leaking credentials
   or platform-local network handles into Sans I/O types.
4. How release publish stages AWFB, patch artifacts, external payload bytes,
   signatures, and AWFR archive bytes before atomic publication.
5. How remote upload, local staging, rollback, and recoverable staging
   directories are represented in adapter-owned state.
6. How target signature regeneration reuses the existing signing adapter without
   treating base signatures as valid for changed target bytes.
7. How the shared release-consume verifier composes:
   - AWFR archive signature validation;
   - release manifest validation;
   - signed base bundle validation;
   - signed patch validation;
   - materialized target validation;
   - external payload digest validation.
8. How `ExternalPayloadMaterializationMode` flows through patch application and
   target materialization without adding metadata-only compatibility fallbacks.
9. Which CLI commands are added or extended, and which arguments are required
   for non-interactive CI/release use.
10. Which validations are local-only, network-mocked, fixture-backed, or
    environment-gated.

## Required Implementation Order

1. Re-read the current AWFR/signing source and record a `SOURCE_INVENTORY.md`
   with exact owner modules and existing CLI entry points.
2. Design the adapter boundary before writing production code. Keep
   deterministic models in `arcweft-bundle`; put filesystem/network/key access,
   clocks, credentials, and remote publication in adapter or CLI layers.
3. Author an implementation overlay for HTTP(S) external payload fetch using the
   same network-policy style as release bundle fetching. Preserve existing
   `file:` and `arcweft-cache:` behavior.
4. Author tests for mirror ordering, skipped/unsupported mirrors, digest
   mismatch, size mismatch, retry/cancellation behavior, and credential
   redaction.
5. Author an overlay that threads `ExternalPayloadMaterializationMode` through
   the patch materialization adapter or a higher-level materialization workflow.
6. Author target signature regeneration using an adapter-owned key source and
   the existing signing policy transcript. Never preserve a base signature for
   changed target bytes under release policies.
7. Author a release-publish adapter that stages all outputs, uploads mirrors,
   signs required subjects, writes the final AWFR archive atomically, and either
   rolls back or leaves an explicitly recoverable staging directory.
8. Author a release-consume verifier that returns typed inspection states and
   payload-cache reports without duplicating signing policy logic in players.
9. Author CLI smoke coverage for external payload fetch, release publish,
   release verify, patch materialization payload modes, and target signing.
10. Author `docs/implementation/` overlay updates with completion status,
    validation evidence, non-goals, and any environment-gated verification.

## Acceptance Criteria

- Existing seq-02.6 / seq-02.7 focused tests are included in the validation
  plan and are run when the packaging environment has the repository/toolchain.
- HTTP(S) external payload fetch verifies compressed and decoded bytes before
  cache record publication.
- Digest mismatch and size mismatch fail before durable cache mutation.
- Credential, auth, proxy, and client-profile data never enter Sans I/O release
  or signing types.
- Release publish is atomic from the caller's perspective or leaves an explicit
  recoverable staging state with typed diagnostics.
- Changed materialized target bytes require a target signature under release
  policy.
- Local-dev unsigned target allowance remains explicit and typed.
- Release-consume verification composes archive, manifest, base bundle, patch,
  materialized target, signature, and external payload states in one typed
  report.
- Patch materialization can choose metadata-only, fetch-required, or
  fully-materialized external payload modes without hidden fallback behavior.
- CLI smoke covers release fetch, external payload fetch, release publish,
  release verify, patch materialization payload mode, and target signing.

## Constraints

- Keep `arcweft-bundle` Sans I/O.
- Do not put network clients, filesystem handles, key material, credentials,
  clocks, remote service objects, or platform trust-store handles into
  deterministic release/signing data types.
- Do not add compatibility shims, raw signature passthrough, or stringly policy
  helpers.
- Prefer owned type methods, `From`/`TryFrom`, or named adapter contexts over
  scattered `{source}_to_{target}` helpers.
- Use stable Rust features; no MSRV restriction is required for this sequence.
- If adding dependencies, verify current crate versions and document why the
  dependency belongs at the selected layer.
- Do not reopen seq-02.1 through seq-02.5 or seq-02.8 unless this package finds
  a concrete source-level blocker.
