# Seq-07.2 Request: Verifier Action Diagnostics Package

## Sequence Position

Seq07.2 follows the diagnostics renderer foundation and may run after or in
parallel with seq07.1 if it does not change the project-wide diagnostic carrier.
It targets verifier/tooling actions and repair guidance: the places where
Arcweft already knows a next action but does not yet expose it as typed
diagnostic suggestions or host actions.

Do not redesign verifier semantics, solver policy, or the shared diagnostic
model from seq07.1 unless current implementation evidence shows a concrete
contract flaw.

## Current Evidence To Audit

Inspect current `main` and at least:

- `docs/implementation/diagnostics-renderer-foundation-2026-06-29.md`
- verifier crates and modules that define or return `ToolAction`
- CLI verify/check commands that print verifier advice
- LSP or tooling crates that expose code actions, quick fixes, or verifier
  evidence
- `crates/arcweft-source/src/lib.rs`
- `crates/arcweft-cli/src/app/diagnostics.rs`

## Problem

Verifier output can include actionable guidance, but process-facing surfaces do
not yet have a single typed path for turning that guidance into CLI suggestions,
LSP code actions, or Agent-visible repair plans. If each surface formats actions
separately, stable diagnostics and fixes will drift.

## Request

Produce a zip package that designs and implements seq07.2 verifier action
diagnostics.

## Required Decisions

1. Which verifier `ToolAction` variants correspond to diagnostic suggestions.
2. Which actions can safely carry `SourceEdit` with
   `MachineApplicable`/`MaybeIncorrect`/`HasPlaceholders` applicability.
3. Which actions are host commands rather than source edits and how they are
   represented without overloading `SourceEdit`.
4. How CLI output displays verifier suggestions through `DiagnosticEmitter`.
5. How LSP code actions are derived from the same typed action data.
6. How Agent-facing tooling should consume verifier actions without parsing CLI
   text.
7. Which verifier outputs remain evidence-only and why.

## Required Implementation Scope

- Add or refine typed conversions from verifier action/evidence output into
  `arcweft_source::DiagnosticSuggestion` or a clearly named adjacent action
  carrier.
- Keep the verifier/data crates Sans I/O and free of CLI renderer dependencies.
- Route CLI verifier/check action output through the shared diagnostic renderer
  when source diagnostics are present.
- Add LSP/tooling conversion tests for source edits and command-like actions.
- Delete superseded ad hoc formatter branches that duplicate action wording.
- Add source gates preventing CLI text from becoming the interchange format for
  verifier actions.
- Add an implementation note under `docs/implementation/`.

## Expected Zip Output

Return a zip named:

```text
arcweft-seq07.2-verifier-action-diagnostics-YYYY-MM-DD.zip
```

The zip must contain:

- `README.md`
- `REQUEST.md`
- `SOURCE_INVENTORY.md`
- `DESIGN.md`
- `IMPLEMENTATION.md`
- `overlay/`
- `patches/`
- `fixtures/diagnostics/verifier-actions/`
- `verification/VALIDATION.md`
