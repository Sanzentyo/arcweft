# Request 06.3.3: Text Input Batch and Serial Contract

## Sequence Position

This is a split-out contract design request from seq06.3. It should be resolved
before platform-specific adapters start emitting multi-operation IME events.

This request may run in parallel with seq06.3.1, seq06.3.2, and seq06.3.4. It
must preserve the existing `TextInputSessionId`, `TextInputFocusGeneration`, and
`TextInputSerial` intent unless evidence shows a concrete flaw.

## Why This Split Is Needed

`PlatformTextInputEvent::Batch` lets an adapter emit several operations under
one context, but the current contract does not fully specify atomicity,
ordering, serial assignment, failure behavior, or interaction with key
disposition and composition state. Different platform APIs have different
transaction shapes: TSF edit sessions, AppKit command callbacks, Wayland `done`
serials, Android batch edits, iOS marked-text updates, and Web EditContext
updates.

Without this design, adapters may disagree about whether a batch is one
platform callback, one committed edit transaction, one frame of input, or one
runtime-host event.

## Required Research

Review native transaction and callback ordering for:

- Web EditContext:
  - MDN `EditContext`: https://developer.mozilla.org/en-US/docs/Web/API/EditContext
  - W3C EditContext draft: https://w3c.github.io/edit-context/
- Windows TSF:
  - Microsoft Text Services Framework: https://learn.microsoft.com/en-us/windows/win32/tsf/text-services-framework
- macOS AppKit:
  - Apple `NSTextInputClient`: https://developer.apple.com/documentation/appkit/nstextinputclient
- Wayland text-input-v3:
  - wayland-protocols XML: https://gitlab.freedesktop.org/wayland/wayland-protocols/-/blob/main/unstable/text-input/text-input-unstable-v3.xml
- Android:
  - Android `InputConnection`: https://developer.android.com/reference/android/view/inputmethod/InputConnection
- iOS:
  - Apple `UITextInput`: https://developer.apple.com/documentation/uikit/uitextinput

The research must identify which APIs provide native serials, edit-session
transactions, commit markers, batch boundaries, or callback ordering guarantees.

## Required Decisions

1. What one `TextInputSerial` represents: native callback order, Arcweft adapter
   event order, transaction order, or frame-local order.
2. Whether every operation inside `PlatformTextInputEvent::Batch` is atomic, and
   what happens when one operation is invalid.
3. Whether `Batch` may include both preedit and commit operations, selection and
   delete operations, or command operations mixed with text mutation.
4. Whether runtime-host dispatch should validate batch invariants before
   converting to `TextInput`.
5. How `TextInputKeyDisposition` is assigned when a batch contains both
   IME-consumed text changes and shortcut-like commands.
6. How composition state is updated across a batch and whether `Commit` always
   ends composition.
7. How focus changes, stale serials, delayed platform callbacks, and native
   transaction cancellation interact.
8. How native serials such as Wayland `done` events should map into Arcweft
   serials without requiring OS handles in Sans I/O data.

## Required Output

Produce an implementation-ready design markdown that contains:

- a platform-by-platform transaction model table;
- exact batch invariants and validation rules;
- serial-generation and stale-event rejection rules;
- atomicity and rollback/failure semantics;
- composition-state transition rules for all operation combinations;
- key-disposition rules for mixed text/key callbacks;
- expected changes to `TextInputDispatchState`, if any;
- tests and fixture trace requirements for all six adapter families.

If code changes are proposed, include the exact files to edit and the expected
public API after the change.

## Implementation Order To Specify

1. Define batch invariants in documentation before changing code.
2. Add runtime-host validation for invalid batch shapes if required.
3. Add tests for stale serials, mixed operation batches, and composition state
   transitions.
4. Add adapter fixture trace format requirements.
5. Update platform-specific request documents to emit only valid batches.

## Tests To Specify

- Duplicate or decreasing serials are rejected.
- A batch with invalid operation ordering is rejected before document mutation.
- A preedit-update-plus-selection batch updates visual state atomically.
- A commit batch ends composition only when the contract says it should.
- Key disposition suppresses shortcuts for IME-consumed batches.
- Delayed callback from a previous focus generation is rejected.
- Wayland-style grouped updates and Android-style batch edits map to stable
  Arcweft serials.

## Constraints

- Do not store native transaction handles in Sans I/O state.
- Do not make serials depend on wall-clock time.
- Do not let partially accepted invalid batches mutate TextField state.
- Keep batch semantics deterministic and replayable.
- Do not add compatibility shims for removed or fallback event paths.

## Non-Goals

- Implementing platform adapters.
- Redesigning raw keyboard routing outside text-input dispatch.
- Adding rich-text edit transactions beyond TextField/TextArea semantics.
