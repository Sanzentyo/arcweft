# Request 06.4c.2: macOS NSTextInputClient Real IME Window Integration Closure Package

## Sequence Position

This follows the applied seq06.4a-c safe adapter cores, seq06.4g shared
`TextEditorState` behavior, and seq06.4i renderer-backed text editor geometry.
It also consumes or subsumes the earlier request:

- `docs/reviews/requests/2026-06-28-seq-06.4c.1-macos-appkit-window-integration-package.md`

The current repository has a gated safe macOS conversion core and Swift
reference material. It still lacks live AppKit window/view lifecycle integration
and real `NSTextInputClient` validation.

## Problem

Arcweft cannot yet demonstrate a native macOS TextField receiving Japanese IME
preedit, candidate placement, selection movement, deletion, and commit through a
live AppKit `NSTextInputClient`. The remaining work is the macOS object
lifecycle, Swift/AppKit bridge build integration, focus activation, geometry
pumping, and validation against the shared Arcweft editor and renderer geometry.

## Request

Produce a final zip package with design, implementation overlay, tests, real
macOS validation notes, fixtures, and apply instructions for closing the macOS
native IME path.

The package must turn the current safe macOS adapter core into a usable macOS
native player/sample path for `TextField`, `TextArea`, and `SecureField`.

## Required Decisions

1. The owner of the live `NSView<NSTextInputClient>` or Swift bridge.
2. How Swift/AppKit code is built, linked, and target-gated from the Rust
   workspace.
3. How focus moves from Arcweft TextField/TextArea/SecureField to AppKit
   `NSTextInputContext`.
4. How marked text, committed insert, replacement range, selected ranges,
   unmark/cancel, and delayed callbacks map to Arcweft operations.
5. Which native callback or callback group creates one Arcweft batch/serial.
6. The definitive range-unit rule and invalid range rejection policy.
7. How renderer-backed caret, character, selection, and composition geometry
   converts to AppKit first-rect/candidate placement.
8. How geometry is refreshed after scroll, transform, scale factor, and window
   movement.
9. How secure fields redact surrounding text, ranges, geometry, diagnostics,
   Agent observe, replay, capture metadata, and AppKit object identity.
10. How non-macOS builds remain clean while macOS-only code is compiled and
    validated on macOS.

## Required Implementation

- macOS-only native bridge module and build/link integration.
- Live AppKit text-input view owner connected to the native window lifecycle.
- Focus activation/deactivation path from Arcweft scene focus to AppKit input
  context.
- Callback conversion into `PlatformTextInputEvent` using the current safe
  macOS core.
- Snapshot read path from `TextEditorState` and mutation write path through
  shared Arcweft editor operations. AppKit must not own independent caret
  movement, deletion, selection, replacement, or composition semantics.
- Geometry pumping from renderer-backed `TextEditorLayout` to AppKit first-rect
  and candidate placement responses.
- Secure-field redaction and capability narrowing at the AppKit boundary.
- A real macOS native sample or player flag that opens an Arcweft TextField and
  accepts Japanese IME input through AppKit.
- Real macOS fixture traces under `fixtures/macos-nstextinputclient-real-ime/`.
- Non-macOS source/compile gates proving AppKit code remains isolated.
- `docs/implementation/seq06-4c-2-macos-nstextinputclient-real-ime-window-integration-closure.md`.

## Acceptance Criteria

- A macOS native player/sample focuses an Arcweft TextField and receives real
  Japanese IME preedit, candidate placement, commit, deletion, and selection
  movement through AppKit.
- AppKit objects, attributed strings, `NSRange`, native selected ranges, and
  object identity remain adapter local.
- One callback or proven atomic callback group maps to one Arcweft serial.
- Ranges convert through shared Arcweft range logic and reject invalid ranges
  without silent clamp.
- Candidate geometry is driven by renderer-backed Arcweft layout snapshots.
- Shared editor behavior owns movement, deletion, selection, replacement,
  clipboard policy, and composition state-machine semantics.
- Secure fields do not expose surrounding text, native ranges, character
  bounds, selected-range anchors, diagnostics, or replay/capture metadata.
- Non-macOS builds still compile and source gates prove the isolation.

## Constraints

- Do not redesign seq06.3 text-input contracts, seq06.4g editor behavior, or
  seq06.4i geometry ownership without concrete evidence of a flaw.
- Do not treat the current Swift reference file as proof of live integration.
- Do not fake real IME success with the existing contract sample.
- Do not introduce compatibility shims or silent range clamping.
- Do not widen `HostDependent` capabilities without SDK evidence and fixtures.

## Non-Goals

- Web, Windows, Wayland, Android, or iOS implementation.
- UIKit/iOS; that remains seq06.4f.
- Replacing renderer-backed text geometry.

## Parallelization Guidance

This can be designed in parallel with seq06.4b.2. Apply order does not need to
be serialized unless both packages change shared `TextEditorState`,
runtime-host activation, or native-player focus APIs. If shared API changes are
needed, extract the shared patch first and make both platform packages consume
it rather than diverging.
