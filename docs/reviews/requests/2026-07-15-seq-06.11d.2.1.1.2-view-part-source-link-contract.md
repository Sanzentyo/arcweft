# Design request: seq-06.11d.2.1.1.2 View-part source and link contract

- Date: 2026-07-15
- Kind: independently throwable final-design correction
- Production changes: prohibited
- Sequence: first residual after proof 01.1

## Goal

Produce one decision-complete contract for authored View-part source identity,
multi-source product provenance, typed instruction targets, and project/module
link rewriting. The contract must be based on the post-proof-01.1 checkout and
must use `HirProjectView` iteration. It must not restore linked-HIR flattening,
`append_module_body`, or a compatibility aggregation API.

The current partial implementation proves the single-module authoring path but
uses one `BundleSource`, an optional semantic source identity, and one compiler
source context. Those choices are insufficient for multi-file products and are
not the final contract.

## Required decisions

1. Select exactly one mandatory source identity carried from each parsed module
   through per-module HIR, checked catalogs, compiler projection, SourceMap,
   formatter/LSP locations, cache hits, and product merge.
2. Define the canonical multi-source SourceMap section/index, including source
   ID construction, normalized UTF-8 extent, digest, duplicate identity,
   missing source, and exact record/reference budgets.
3. Define the compiler input as a source-context map, not one ambient source,
   and specify atomic failures for missing, stale, digest-mismatched, or
   cross-source export ranges.
4. Freeze the complete node-producing instruction target-kind/index model and
   the static target key used internally without exposing instruction ordinals
   as a public part or occurrence identity.
5. Define per-module checked owner/local/export aggregation through
   `HirProjectView` and explicit old-owner/old-part to new-owner/new-part rewrite
   maps. Suffix or source-text resolution is forbidden.
6. Define reversed module-order equivalence, duplicate owner detection, stale
   merge-reference failure, and deterministic product ordering.
7. Enumerate deletion of the current single `ViewPartSourceContext`, optional
   identity branch, and single-source `SourceMapIndex::from_source` shape.

## Required tests to specify

- per-module HIR identity survives `HirProjectView` iteration without a linked
  module;
- two files with equal local/public spellings remain owner/source distinct;
- source identity is exact across cache hit, merge, reverse merge order, and
  provenance-only edit;
- missing/duplicate/stale/digest/extent/cross-source references fail atomically;
- one-at-limit and one-over-limit SourceMap/index work are deterministic;
- every node-producing instruction kind maps once, including conditional,
  unreachable, keyed repeat, nested repeat, and `CallView`; and
- product decode validates from encoded metadata without filesystem source.

## Constraints and expected output

Preserve syntax, checked local/public namespaces, direct-only no-re-export, the
native Style architecture, Sans I/O codecs, and unreleased-format replacement.
Do not add a source gate, second source registry, compatibility reader, or
runtime/LSP policy. Consume proof 01.1 as implemented.

Return a self-contained design package with normative APIs/wire shapes, state
transitions, implementation cuts, caller/deletion inventory, test matrix,
verification plan, exact inspected Git/Jujutsu identity, and `OPEN_QUESTIONS`
equal to `none`. If any result-changing choice remains, return blocked and no
ready package.
