## Position and reason for the split

This is sequence 06.16.9.2 and follows the 2026-07-11 `#[fx] fn ... -> Fx` substrate. The existing
single-module path derives `FxId` from package plus the function's original
module-qualified name. Linked-module imports and re-exports need a compiler-wide
symbol identity design because syntax currently retains `use` trees while HIR
does not preserve a resolved declaration identity for every callable use.

This request must not redesign the existing `FxId`/`FxInstanceId` distinction
or create author-written `@fx` IDs. It may reshape unreleased HIR/linker APIs
directly where needed.

## Required decisions

- Define a typed original-declaration callable identity retained through
  syntax, HIR, project linking, sema, runtime-plan lowering, and bundles.
- Specify `use`, grouped import, glob import, alias, and `pub use` resolution;
  aliases must never mint a new `FxId`.
- Specify duplicate simple names from different modules and the diagnostics for
  ambiguous unqualified calls.
- Define package identity for direct-file builds, project builds, dependencies,
  and external Rust/WASM modules.
- Define rename/module-move behavior explicitly; do not add compatibility IDs
  without evidence of a released external contract.
- Define the exact relationship among original declaration identity, `FxId`,
  `FxInstanceId`, ABI identity, and semantic identity.
- Define transactional accepted-project publication, deterministic ordering,
  and stale/foreign generation behavior.
- Define the deletion boundary for flattened linked-HIR readers, basename or
  display-string reconstruction, and provisional duplicate symbol owners.

## Implementation order

1. Retain/import typed callable declaration identities in HIR/project linking.
2. Make ordinary and Fx call resolution consume the same symbol table.
3. Key Fx catalogs by declaration identity rather than basename.
4. Carry the resolved `FxId` through View and RichText applications.
5. Add ambiguity, visibility, and re-export tests across multiple packages.

## Tests to specify

- direct qualified and imported unqualified Fx calls resolve identically;
- `pub use alias` preserves the original `FxId`;
- two imported functions with the same basename are ambiguous until qualified;
- private functions cannot be applied across package boundaries;
- package identity is deterministic for project and dependency builds;
- View and RichText produce the same resolved ID for the same declaration.
- cross-module Fx composition and cycle detection use typed declaration
  identity rather than basename;
- stale and foreign accepted-project generations cannot publish or execute an
  Fx resolution;
- diagnostics retain exact call-site and candidate declaration document
  identities and ranges; and
- compiler and runtime-plan catalogs consume the same accepted authority.
