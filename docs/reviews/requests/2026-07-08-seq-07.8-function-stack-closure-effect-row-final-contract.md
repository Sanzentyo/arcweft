## Why This Split Is Needed

The current implementation composes closure effects for a broad, useful set of
paths:

- local closure aliases;
- partial aliases;
- immediate closure calls;
- built-in `map` and `filter`;
- selected user-defined higher-order calls;
- later curried callback groups;
- tuple and record destructured callbacks;
- built-in `Option` / `Result` payloads;
- module-local and environment-provided enum payload metadata;
- returned closure callback timing.

This is intentionally not yet the stable final effect-row model. The current
behavior is implemented as checked composition over known callable paths and
synthetic private callables. A final language contract must define how closure
effect rows are represented, inferred, bounded, displayed, persisted in reports,
and consumed by verifier/LSP/runtime-plan layers.

## Required Decisions

1. Define the source-level effect-row syntax and semantics for function values:
   explicit effect rows, inferred effect rows, upper bounds, and no-effect
   constraints.
2. Define the sema representation for closure/function effect rows:
   - open vs closed rows;
   - row variables;
   - synthetic closure callables;
   - returned function values;
   - curried groups;
   - higher-order parameters.
3. Define when effects are performed:
   function-value creation, partial application, exact application, returned
   closure application, and delayed callback invocation.
4. Define capture interaction:
   captured function values, borrowed captures, resource/lifetime captures, and
   effects crossing suspension or save/load boundaries.
5. Define how effect rows flow into runtime-plan evidence and verifier input
   without making lower-level crates depend on sema internals.
6. Define LSP/tooling display policy for inferred effect rows and diagnostics.
7. Define diagnostics for ambiguous, escaping, unsatisfied, or unrepresentable
   effect rows.

## Implementation Order

1. Done: audit the implemented closure-effect composition paths and classify
   them as stable timing behavior, temporary evidence-based composition, or
   diagnostics-only coverage. Evidence:
   `docs/implementation/function-stack-closure-effect-row-audit-2026-07-09.md`.
2. Partially done: the sema `effect_row` data model exists and
   `EffectAnalysisReport::closed_effect_rows()` projects closed inferred,
   upper-bound, and forbidden rows from current analysis. Agent artifact
   verified-effects lowering consumes this projection. Remaining work: specify
   source row syntax, open-row inference/substitution, and first-class
   row-bearing callable values for closures, returned functions, curried
   groups, and higher-order parameters.
3. Thread effect-row evidence into runtime-plan/verifier only through typed
   boundary data.
4. Update existing closure/higher-order effect composition to produce the final
   row evidence rather than ad hoc path-specific edges.
5. Update LSP diagnostics and related information to render the final row
   traces.
6. Partially done for current graph evidence: regression tests prove delayed
   effect timing for closure creation, partial application, returned closures,
   and higher-order invocation. Remaining work: express the same timing through
   the final effect-row model once source row syntax/open rows are designed.

## Tests To Specify

- Closure creation remains effect-free while exact invocation composes effects.
- Done for current graph evidence: partial application remains effect-free
  until the partial value is called, including a `no_effect` regression for the
  eventual call of a partial closure alias. Explicit row-value tests remain
  pending the final row syntax/model.
- Done for current graph evidence: returned closure values delay callback
  effects until the returned function is applied, including a `no_effect`
  regression for the returned function call. Explicit row-value tests remain
  pending the final row syntax/model.
- Done for current graph evidence: curried higher-order calls compose only the
  effects of callbacks actually invoked in the reached call group, including a
  `no_effect` regression for the final call of a partial curried
  higher-order callback. Explicit row-value tests remain pending the final row
  syntax/model.
- Done for current graph evidence: captured function values preserve their
  effect rows through local aliases, including aliases captured by returned
  closures. Explicit row-value tests remain pending the final row syntax/model.
- Done for current graph evidence: borrowed/resource captures that cross
  suspension boundaries report the lifetime/capture issue while preserving the
  relevant closed effect-row evidence. Explicit row-value tests remain pending
  the final row syntax/model.
- Done for current graph evidence: `no_effect` rejects closure values whose
  body effects exceed the bound when the value is invoked. Explicit row-bound
  tests remain pending the final row syntax/model.
- Done for current graph evidence: LSP diagnostics include stable
  `relatedInformation` for callback edges, returned function values, external
  calls, and directly performed effects. Final row-origin rendering remains
  pending the final row syntax/model.

## Constraints

- Do not weaken the already implemented checked closure-effect composition.
- Do not make function-value creation perform body effects.
- Do not encode sema-only effect graph internals directly into `arcweft-core`.
- Preserve existing first-order effect policy and verifier contracts unless the
  audit identifies a concrete incompatibility.
- Coordinate with 07.7 for non-helper callable values and with 07.5 for
  suspending dynamic apply.
