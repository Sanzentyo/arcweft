# Seq-06.6 Request: Visual Smoke And Golden Fixtures Package

## Sequence Position

This follows the seq06 layout/capture contract and should consume seq06.5's
selected capture resource metadata schema when selected object/layer fixtures
are included.

It can be designed in parallel with seq06.5, but image-producing implementation
should wait until the metadata schema and selected capture resource constructors
are stable.

## Problem

Seq06 records visual smoke/golden fixtures as a remaining TODO because the
current checkout has capture commands and some checked-in native visual fixtures,
but not one finalized package that defines:

- which fixtures are metadata smoke tests vs exact visual goldens;
- which renderer/backend/font policy makes exact comparison valid;
- which fixture refresh command owns regeneration;
- where candidate artifacts are written;
- how `imq` metrics and tolerances are interpreted;
- which tests belong in default fast validation vs explicit Tier 2 visual
  validation.

Without this cut, future visual regressions either overfit local GPU/font state
or remain invisible because exact goldens are treated as too unstable.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for seq06 visual smoke and
golden fixtures.

The package must make visual validation repeatable without requiring exact
golden checks in every default local test run.

## Required Inputs

- Current Arcweft `main`.
- `justfile` visual/capture recipes.
- `docs/implementation/test-execution-policy.md`.
- `docs/implementation/seq-06-layout-capture-visual-goldens-2026-06-28.md`.
- Current native capture fixtures under `tests/fixtures/native_capture/`.
- Current WebGPU/native frame capture scripts under `tools/`.
- Current Agent observe native capture tests under
  `crates/arcweft-cli/tests/check/`.
- Seq06.5 selected capture metadata package if selected object/layer visual
  fixtures are implemented.

## Required Decisions

1. Which fixture classes are required:
   - viewport smoke;
   - layer crop smoke;
   - selected object crop smoke;
   - object-id/mask smoke;
   - text-fit/overflow metadata smoke;
   - exact visual golden.
2. Which exact goldens are checked in, and which are generated only as
   artifacts under `target/`.
3. Which fonts, fallback order, backend, viewport size, scale factor, color
   format, and device pixel ratio are pinned for exact comparison.
4. Whether the exact golden tier is native-only, WebGPU-only, or has separate
   native and WebGPU fixture families.
5. Which tolerances are allowed for PSNR/SSIM/MSE/MAE/maxAE through `imq`.
6. How fixture refresh works for checked-in goldens vs candidate artifacts.
7. Which commands belong in `just test-workspace`, `just test-cli-native`,
   `just test-visual-golden`, `just native-visual-artifacts`, and
   `just fixture-refresh-all`.
8. How visual failures should report candidate image paths and metric JSON.
9. How CI should handle environment-sensitive exact visual checks.
10. How selected object/layer capture metadata from seq06.5 is asserted next to
    image comparisons.

## Required Implementation

- Add or update visual fixture sources and expected outputs where deterministic.
- Add smoke tests that verify capture dimensions, metadata, non-empty image
  contents, object-id uniqueness, mask alpha coverage, and crop bounds without
  exact image matching.
- Add exact golden tests only for explicitly pinned environments.
- Add `imq` metric comparison output for exact golden runs.
- Update `justfile` recipes for visual golden testing and fixture refresh if
  needed.
- Update `docs/implementation/test-execution-policy.md` with default vs Tier 2
  visual validation rules.
- Add a package implementation note under `docs/implementation/`.
- Include generated candidate artifacts in the zip only when small and useful;
  otherwise document the exact command that produces them.

## Acceptance Criteria

- Default validation has deterministic non-exact visual smoke coverage.
- Exact visual goldens are explicitly Tier 2 or environment-gated.
- Fixture refresh commands cover all checked-in visual fixtures and write
  candidate artifacts under `target/` before replacing checked-in files.
- `imq` reports are produced for exact comparisons.
- Visual failures expose candidate/reference/metric paths.
- Selected object/layer fixtures assert seq06.5 metadata as well as image
  content when applicable.
- Documentation states when to run each visual command.

## Tests To Specify And Run

```bash
cargo fmt --all -- --check
cargo test -p arcweft-cli --features native-capture --test check visual_smoke -- --nocapture
cargo test -p arcweft-cli --features native-capture --test check native_checked_in_visual_golden_fixtures_are_well_formed --quiet
just test-cli-native
just test-visual-golden
just native-visual-artifacts
just fixture-refresh-all
cargo +nightly -Zscript tools/structure-audit.rs --root .
git diff --check
```

If `just test-visual-golden`, `just native-visual-artifacts`, or
`just fixture-refresh-all` are intentionally not runnable in the package
environment, `verification/VALIDATION.md` must record the exact blocker and the
target machine assumptions.

## Non-Goals

- Do not redesign selected capture resource metadata; consume seq06.5.
- Do not require exact visual goldens in normal `just test-workspace`.
- Do not treat platform font variance as a test failure unless the fixture
  explicitly pins the font/backend environment.
- Do not move renderer or filesystem I/O into `arcweft-layout`.

## Parallelization Guidance

The design can be sent at the same time as seq06.5 if the designer treats
seq06.5's metadata schema as an input boundary. Implementation should start with
metadata-only smoke fixtures and defer selected object/layer exact goldens until
seq06.5 has landed.
