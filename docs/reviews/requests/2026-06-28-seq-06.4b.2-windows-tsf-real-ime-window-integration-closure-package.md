# Request 06.4b.2: Windows TSF Real IME Window Integration Closure Package

## Sequence Position

This follows the applied seq06.4a-c safe adapter cores, seq06.4g shared
`TextEditorState` behavior, and seq06.4i renderer-backed text editor geometry.
It also consumes or subsumes the earlier request:

- `docs/reviews/requests/2026-06-28-seq-06.4b.1-windows-tsf-com-bootstrap-window-integration-package.md`

The current repository has TSF range conversion, capability facts, fixture
traces, and a contract sample. It still lacks the production Windows object
layer needed for a real OS IME window session.

## Problem

Arcweft cannot yet demonstrate a native Windows TextField receiving Japanese IME
preedit, candidate placement, selection movement, deletion, and commit through
real TSF objects. The remaining work is not another string conversion module.
It is the audited Windows COM object boundary, focus/window lifecycle, live
`ITextStoreACP` integration, and validation against the shared Arcweft editor
and renderer geometry.

## Request

Produce a final zip package with design, implementation overlay, tests, real
Windows validation notes, fixtures, and apply instructions for closing the
Windows TSF native IME path.

The package must turn the current safe TSF core into a usable Windows native
player/sample path for `TextField`, `TextArea`, and `SecureField`.

- Current Arcweft `main`.
- `docs/implementation/seq06-4abc-platform-text-input-adapters.md`.
- `docs/implementation/seq06-4g-cross-platform-text-editing-behavior.md`.
- `docs/implementation/seq06-4i-renderer-backed-text-editor-geometry.md`.

- `crates/arcweft-runtime-host` text-input activation/dispatch code.
- `crates/arcweft-player-native` windowed owner/event-loop integration.
- `crates/arcweft-ui` TextField/TextArea focus and geometry surfaces.
- Microsoft Windows SDK/header evidence for TSF COM lifecycle,
  `ITfThreadMgr`, `ITfDocumentMgr`, `ITfContext`, `ITextStoreACP`,
  `ITextStoreACPSink`, edit sessions, display attributes, layout queries, and
  reconversion.

## Required Decisions

1. The exact unsafe Windows-only boundary and its invariants. Unsafe code must
   be isolated in a clearly named module and documented in `UNSAFE_AUDIT.md`.
2. COM apartment/thread ownership and shutdown order.
3. The owner type for thread manager, client id, document manager, context,
   text store, sink, edit cookies, and focus generation.
4. How TSF text reads are answered from `TextEditorState` snapshots without
   exposing native identity to Sans I/O crates.
5. How TSF edit sessions become one Arcweft text-input batch/serial.
6. How candidate/window layout queries consume seq06.4i renderer-backed
   character, selection, composition, and caret bounds.
7. How TSF display attributes map to Arcweft composition segment evidence or
   `HostDependent` diagnostics.
8. How reconversion support is detected and represented without overclaiming.
9. How secure fields redact surrounding text, ranges, geometry, diagnostics,
   Agent observe, replay, capture metadata, and TSF object identity.
10. How stale callbacks, focus loss, destroyed TextFields, window deactivation,
    and invalid edit cookies are rejected or cancelled.

## Required Implementation

- Windows-only COM bootstrap and teardown in `arcweft-desktop-native` or the
  native adapter boundary chosen by the design.
- Live `ITextStoreACP`/sink implementation or an SDK-equivalent binding layer.
- Window focus integration from Arcweft scene focus to TSF document/context
  activation.
- Snapshot read path from `TextEditorState` and mutation write path through
  shared Arcweft editor operations. TSF must not own independent caret movement,
  deletion, selection, replacement, or composition semantics.
- Geometry pumping from renderer-backed `TextEditorLayout` to TSF layout and
  candidate rectangle responses.
- Secure-field redaction and capability narrowing at the Windows boundary.
- A real Windows native sample or player flag that opens an Arcweft TextField
  and accepts Japanese IME input through TSF.
- Real Windows fixture traces under `fixtures/windows-tsf-real-ime/`.
- Non-Windows source/compile gates proving the COM layer is not compiled
  outside Windows.
- `docs/implementation/seq06-4b-2-windows-tsf-real-ime-window-integration-closure.md`.

## Acceptance Criteria

- A Windows native player/sample focuses an Arcweft TextField and receives real
  Japanese IME preedit, candidate placement, commit, deletion, and selection
  movement through TSF.
- Unsafe code is isolated and justified; no unsafe leaks into shared editor,
  runtime-host, UI, or presentation crates.
- COM objects, edit cookies, TSF ranges, and object identity remain adapter
  local.
- TSF ACP/WCHAR ranges convert through shared Arcweft range logic and reject
  invalid ranges without silent clamp.
- Candidate geometry is driven by renderer-backed Arcweft layout snapshots.
- Shared editor behavior owns movement, deletion, selection, replacement,
  clipboard policy, and composition state-machine semantics.
- Secure fields do not expose surrounding text, native ranges, character
  bounds, selected-range anchors, diagnostics, or replay/capture metadata.
- Non-Windows builds still compile and tests/source gates prove the isolation.

## Tests To Specify And Run

- Existing safe TSF adapter tests.
- Windows-only COM lifecycle and stale-callback tests where feasible.
- Real Japanese IME trace capture on Windows.
- Focus activation/deactivation and destroyed TextField rejection tests.
- Geometry/candidate rectangle fixture tests.
- Secure-field redaction tests.
- Non-Windows compile/source-gate tests.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test`/`cargo clippy` for touched crates.
- Structural audit, because this adds platform object and unsafe boundaries.

## Constraints

- Do not redesign seq06.3 text-input contracts, seq06.4g editor behavior, or
  seq06.4i geometry ownership without concrete evidence of a flaw.
- Do not fake real IME success with the existing contract sample.
- Do not introduce hidden DOM-style fallback, compatibility shims, or silent
  range clamping.
- Do not enable unrelated Windows text stacks unless TSF evidence proves they
  are required.

## Non-Goals

- Web, macOS, Wayland, Android, or iOS implementation.
- Replacing renderer-backed text geometry.
- Broad product-player UX redesign.

## Parallelization Guidance

This can be designed in parallel with seq06.4c.2. Apply order does not need to
be serialized unless both packages change shared `TextEditorState`,
runtime-host activation, or native-player focus APIs. If shared API changes are
needed, extract the shared patch first and make both platform packages consume
it rather than diverging.
