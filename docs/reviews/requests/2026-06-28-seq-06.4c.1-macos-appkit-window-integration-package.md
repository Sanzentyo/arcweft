# Request 06.4c.1: macOS AppKit NSTextInputClient Window Integration Package

## Sequence Position

This follows seq06.4c and the applied safe macOS adapter core recorded in:

- `docs/implementation/seq06-4abc-platform-text-input-adapters.md`
- `docs/implementation/seq06-ime-css-font-sample-2026-06-28.md`

Seq06.4c currently provides a target-gated safe adapter core and a Swift
reference owner. It does not yet connect AppKit `NSTextInputClient` to the
actual native window lifecycle.

This package should consume the shared editor behavior requested in
`docs/reviews/requests/2026-06-28-seq-06.4g-cross-platform-text-editing-behavior-package.md`
when available. It must not duplicate Arcweft text movement, deletion,
selection, or composition state-machine semantics inside the AppKit bridge.

## Problem

Arcweft cannot yet show a real native macOS IME sample because no AppKit view is
installed as the live `NSTextInputClient` for an Arcweft TextField/TextArea. The
missing work is the macOS native object lifecycle, Swift/AppKit bridge, focus
activation, geometry pumping, and real callback validation.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for macOS AppKit window
integration for Arcweft text input.

The final result must turn the current safe macOS adapter core into a usable
native macOS IME path for Arcweft TextField/TextArea/SecureField.

## Required Decisions

1. The owner of the live AppKit `NSView<NSTextInputClient>` or Swift bridge.
2. How the Swift/AppKit owner is built and linked from the Rust workspace.
3. How focus moves from Arcweft TextField/TextArea/SecureField to
   `NSTextInputContext`.
4. How marked text, committed insert, replacement range, selected range,
   unmark/cancel, and delayed callbacks map to Arcweft operations.
5. The native callback boundary that creates one Arcweft serial.
6. The definitive range-unit rule and invalid range policy from SDK evidence.
7. How Arcweft screen/viewport/text-local geometry converts to AppKit first
   rect and candidate placement.
8. How the AppKit bridge asks the renderer for updated geometry after scroll,
   transform, DPI, or window movement.
9. How secure fields redact surrounding text, marked text, ranges, geometry,
   diagnostics, Agent observe, replay, and capture.
10. How non-macOS builds remain clean while macOS-only code is compiled and
    validated on macOS.

## Required Implementation

The package must include implementation-ready code for the current repository:

- macOS-only native bridge module and build/link integration.
- Live AppKit text-input view owner connected to the native window.
- Focus activation/deactivation path from Arcweft scene focus to AppKit input
  context.
- Callback conversion into `PlatformTextInputEvent` using the current safe core.
- Snapshot and geometry pumping from Arcweft TextField layout.
- Text mutations and selection changes must go through the shared Arcweft
  editor state when seq06.4g is available; AppKit should not own independent
  caret movement or deletion semantics.
- Secure-field redaction at the AppKit boundary.
- A native macOS sample or player flag that opens a real TextField and accepts
  Japanese IME input.
- macOS fixture capture instructions and real callback traces.
- Non-macOS source gates proving AppKit code remains gated.
- `docs/implementation/seq06-4c-1-macos-appkit-window-integration.md`.

## Acceptance Criteria

- A macOS native player/sample can focus an Arcweft TextField and receive real
  Japanese IME preedit and commit through AppKit.
- AppKit objects, `NSRange`, attributed strings, and native object identity stay
  inside the macOS adapter boundary.
- One callback or proven atomic native callback group maps to one Arcweft
  serial.
- Ranges are converted through shared range logic and reject invalid ranges
  without silent clamp.
- Candidate geometry is driven by Arcweft layout snapshots.
- Caret movement, ranged selection, deletion, replacement, and shortcut
  handling match the shared Arcweft editor behavior.
- Secure fields do not expose surrounding text, ranges, character bounds,
  selected-range-derived anchors, or AppKit object identity.
- Non-macOS builds still compile.

## Tests To Specify And Run

## Constraints

- Do not redesign the common seq06.3 text-input contract.
- Do not put AppKit/native identity in Sans I/O payloads.
- Do not treat the current Swift file as proof of live integration.
- Do not fake real IME success with the existing safe contract sample.
- Do not upgrade HostDependent capabilities without SDK evidence and fixtures.

## Non-Goals

- Web, Windows, Wayland, Android, or iOS implementation.
- UIKit/iOS; that remains seq06.4f.
- Replacing the renderer.
