# Request 06.2: Takumi CSS Scene to Direct wgpu Lowering

## Sequence Position

This follows seq06.1 after the UI/style/TextField data model and `ViewScene`
primitive contract are accepted. It can proceed in parallel with platform IME
adapter work from seq06.3, but it must not require seq02.4.1 product View resource
codecs to be complete.

## Request

Integrate `kane50613/takumi` as Arcweft's CSS cascade/layout/stacking-scene
source for native View components and lower the resulting paint scene to direct
wgpu primitives. The primary path must not render UI to CPU RGBA images or upload
full View surfaces every frame.

## Required Decisions

1. Which Takumi version/commit is pinned for the integration and why.
2. Which Takumi modules are used for CSS parsing, cascade, layout, and stacking
   scene extraction.
3. How Arcweft `ViewProgram`/`ViewFragment` maps to Takumi node metadata without
   losing Component identity, exported parts, handlers, semantics, or Agent ids.
4. How Arcweft text and TextField are represented to Takumi as measured replaced
   / inline layout participants while Arcweft owns final glyph/caret/selection
   rendering.
5. How Takumi paint order, stacking contexts, transforms, opacity, clips, and
   z-index buckets lower into `ViewSceneContext` and ordered `ViewPrimitive` ranges.
6. Which CSS features are implementation-ready for direct wgpu in the first cut:
   solid/rounded rects, borders, images, gradients, clips, opacity, transform,
   text layout placeholders, and shadows if supported by the renderer.
7. How unsupported-but-accepted CSS is diagnosed without falling back to CPU
   raster surfaces.
8. How style invalidation maps to paint-only GPU buffer updates vs layout scene
   rebuilds.
9. How renderer resource caches are keyed by style/program/text/image revisions.
10. How capture/Agent metadata records the same coordinates as rendered wgpu
    primitives.

## Required Implementation Order

1. Add a Takumi adapter crate/module that converts Arcweft View/Style data into
   Takumi node/style inputs while preserving Arcweft metadata.
2. Add a Takumi measurement bridge for Arcweft Text/TextField/inline component
   participants.
3. Lower Takumi stacking contexts into `ViewSceneContext` ranges.
4. Lower box backgrounds, borders, rounded clips, images, gradients, transforms,
   and opacity into `ViewPrimitive` values.
5. Route Arcweft text layout outputs to `ViewGlyphRun` primitives instead of asking
   glyphon to re-layout the text string.
6. Add renderer cache keys and persistent GPU buffer/texture updates.
7. Add capture metadata integration using seq06 coordinate-space contracts.
8. Add diagnostics for unsupported CSS features with no CPU-raster fallback.

## Tests To Specify

- Takumi node metadata round-trip preserves Component/part/semantic ids;
- CSS flex/grid layout produces expected Arcweft layout boxes;
- stacking context order matches Takumi paint scene order;
- transform/opacity update without re-running layout when property invalidation
  is paint-only;
- Text/TextField measurement participates in layout while glyphs render through
  Arcweft text layout;
- unsupported CSS reports deterministic diagnostics and no raster fallback;
- `ViewScene` primitives are stable across equivalent style sources;
- capture metadata matches rendered primitive bounds.

## Constraints

- No CPU RGBA View surface path in the primary renderer.
- Do not edit Takumi internals unless a pinned fork/patch is explicitly adopted.
- Do not duplicate Arcweft text shaping in Takumi for final rendering.
- Do not bypass Arcweft LayerTree, InputRouter, Semantics, or Agent observation.
- Keep product resource serialization out of this request.

## Non-Goals

- Platform IME adapter implementation.
- Product View resource codec implementation.
- HTML/Servo DOM backend.
