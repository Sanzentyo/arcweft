signature help that can expose structural character nominal parameter types,
or close the item as an evidence-backed explicit non-goal after exhaustively
proving that no current callable surface can expose one.

This task is unblocked: AW-AH-009.1.1 has landed on main. Send this file by
itself to exactly one assignee with access to the current Arcweft checkout.
The assignee must inspect current main, applicable AGENTS.md files, the Rust
skill, and the implementation notes named below. The old AW-AH-009.1 archive

the source of truth.

This task must not edit Rust, Cargo manifests, schemas, tests, fixtures, or
stable design chapters and must not include a patch or repository overlay.

The result must select exactly one outcome:

1. READY_FOR_IMPLEMENTATION with one typed native/Rust-adapter signature query,
   final active-argument recovery, cache identity, limits, errors, and tests; or

Absence of an implementation, a source grep, or the lack of a synthetic
character constructor is not sufficient evidence for a non-goal. “TBD”,
unresolved alternatives, and implementation-selected behavior are not
acceptable in either outcome.

## Current evidence and unresolved seam

- Character-aware presentation calls are real. The semantic checker assigns a
  structural CharacterNominalType expectation to look arguments.
- Dialogue and character-stage authoring includes named character/look
  arguments that must be classified explicitly by the surface inventory.
- Project symbols and semantic environments contain typed callable facts.
  AW-AH-009.1.1 now publishes the canonical RegisteredSemanticWorld rather
  than an ad hoc character-augmented TypeCheckEnv.
- LSP publishes one RegisteredSemanticWorld through
  AcceptedProfileEnvironment and identifies each successful replacement with
  AcceptedEnvironmentGeneration. A native query must consume that accepted
  world; it may not rebuild profile.typecheck_env() as a parallel authority.
- Current LSP signature help extracts one word at the cursor and delegates only
  to Rust adapter metadata. The adapter selects by name and does not provide a
  native position-aware callable/argument resolver.
- SourceDocumentIdentity binds exact content provenance.
  SourceSnapshotId identifies a separate session-local incremental syntax
  lineage. LSP DocumentSnapshot currently retains SourceDocument, while proof
  concurrency has introduced SyntaxDatabase without yet completing the typed
  AST to SyntaxNodeId attachment contract.

These facts prove a resolver gap. They do not by themselves decide whether
character presentation arguments belong to ordinary signature help, a
presentation-specific signature family, or no signature-help surface.

## Fixed substrate and non-redesign boundary

- CharacterNominalType remains the sole semantic look/part/variant identity.
  Aliases and display labels never enter equality or hashing.
- CharacterRegistrar, ProjectSymbolTable, RegisteredSemanticWorld,
  RegisteredTypeCheckEnv, and AcceptedEnvironmentGeneration remain the
  canonical registration and publication authorities.
- source_label() and Display are presentation-only and have no inverse parser.
- Existing completion and hover behavior must not be redesigned.
- SourceDocumentIdentity and SourceSnapshotId remain distinct; no signature
  query may forge, serialize, parse, or derive one from the other.
- The current proof 01.1.1 request owns any final stable typed-AST to
  SyntaxNodeId attachment. This task may consume that contract conditionally
  but may not duplicate or preempt it.
- No new callable syntax, synthetic character constructor, stringly signature
  key, or compatibility shim may be added merely to justify signature help.

## Required decisions

### 1. Exhaustive surface inventory and outcome

Inventory every current native expression/call family and identify its syntax,
HIR, semantic owner, callable-signature source, and whether any parameter can
have CharacterNominalType. At minimum classify:

- presentation show/hide/move/character calls and named look arguments;
- dialogue or character-stage callable surfaces;
- source-declared functions, flows, methods, constructors, selected calls,
  partial calls, function values, and overloads;
- adapter/Rust-exported callables; and
- incomplete or recovered call expressions visible to LSP.

Select READY_FOR_IMPLEMENTATION or EXPLICIT_NON_GOAL from semantic evidence.
An implementation outcome must list every applicable surface. A non-goal must
show why each candidate’s semantic owner cannot expose a character nominal
parameter and why ordinary signature help is not the correct feature.

### 2. Canonical semantic query owner

For an implementation outcome, define exact Rust request/result/error types,
owner crate/module, constructor visibility, and dependency direction for one
position-aware signature query.

The query must consume the accepted RegisteredSemanticWorld and
ProjectSymbolTable rather than a separately rebuilt TypeCheckEnv. It must
define how base/adapter callables, project-source callables, presentation
special forms, methods, overloads, and function values adapt to one result
shape without a second resolver.

### 3. Source and syntax identity path

Select one exact input identity:

- SourceDocumentIdentity plus current typed/ranged parse facts; or
- SourceDocumentIdentity plus SourceSnapshotId and stable typed
  SyntaxNodeId attachment.

If stable typed-node identity is required, declare implementation blocked until
the proof 01.1.1 final contract is accepted and its attachment path is landed.
Name the exact consumed API and implementation sequence.

If stable typed-node identity is not required, specify the full
content-identity/range algorithm and stale checks that make the query safe.
Do not create a signature-specific node ID, incremental database, raw integer
constructor, or source search.

The design task itself may complete while this implementation dependency is
conditional, but the final contract must select one branch and expose no open
decision.

### 4. Position and active-argument algorithm

Define UTF-8 byte/LSP position conversion, call selection, nested-call
precedence, argument-list boundaries, active signature and parameter, named
and reordered arguments, positional arguments, spread arguments, partial
calls, cursor-on-comma/delimiter/whitespace behavior, missing close delimiter,
and recovered/poisoned syntax.

Specify how the algorithm obtains exact ranges without reparsing a word or
searching source text and how it reports cursor positions that do not belong
to an argument list.

### 5. Typed expected arguments and character scope

Define how each applicable parameter exposes TypeKind and, when relevant,
CharacterNominalType owner/part. Same-spelling members across characters,
families, and parts must remain scoped by typed identity.

Aliases may affect documented display spelling only under one explicit policy;
they may not alter signature identity or be parsed from labels.

### 6. Labels, documentation, and deterministic presentation

Freeze signature/parameter label construction, documentation source,
activeSignature/activeParameter values, overload ordering, duplicate
coalescing, ambiguity, unavailable documentation, and incomplete-source
presentation.

Choose whether labels use authored aliases, canonical type labels, or both,
and how source ranges map into LSP ParameterInformation. Do not make label text
an identity key.

### 7. Native and Rust-adapter precedence

Define one precedence/merge rule when native semantic and Rust adapter metadata
name the same callable. Select whether adapter metadata is normalized into the
native query result, used only when native resolution proves inapplicable, or
rejected as ambiguous.

Delete the word-only fallback where it can select the wrong callable or nominal
owner. Retain no two competing successful resolvers.

### 8. Accepted environment, cache, and invalidation

Define query/cache keys and invalidation for
AcceptedEnvironmentGeneration, project symbol world/revision,
SourceDocumentIdentity, SourceSnapshotId when selected, LSP document version,
profile replacement, manifest changes with unchanged character digest, failed
rebuild, document close, workspace removal, and shutdown.

Failed profile rebuild must not pair old world facts with a new cache key.

### 9. Recovery, ambiguity, and errors

Define typed outcomes for unknown callee, ambiguous overload, ambiguous native
versus adapter metadata, unknown character owner/part, stale document/world/
revision/generation/snapshot, cursor outside arguments, missing delimiter,
duplicate named argument, unsupported spread, unavailable semantic facts,
cancelled/timeout query, and resource exhaustion.

State which outcomes return None, partial signature help, a request error, or a
structured diagnostic. Error identity must not be a formatted string.

### 10. Hard limits and work accounting

Select exact inclusive production limits for candidate calls, overloads,
parameters, nested calls, recovery nodes, source bytes, diagnostics, and work.
Define deterministic truncation versus fail-closed behavior, arithmetic
overflow, exact-limit success, one-over failure, and cache publication.

### 11. Explicit non-goal evidence, if selected

If EXPLICIT_NON_GOAL is selected, provide a complete matrix of syntax/HIR/sema
call families, callable owner, parameter types, and the reason character
nominal signature help is inapplicable. Explicitly classify the existing
character/look presentation calls rather than omitting them.

The non-goal must state whether generic native signature help remains a
separate feature and must not leave a placeholder, synthetic surface, or
character-specific word fallback.

## Implementation order to specify

For an implementation outcome, prescribe compiling cuts:

1. Freeze applicable surfaces, query/result/error/limit APIs, and selected
   source/syntax identity dependency.
2. Add one sema-backed position query consuming RegisteredSemanticWorld and
   ProjectSymbolTable.
3. Normalize Rust adapter metadata through the same result shape and enforce
   the selected precedence.
4. Add LSP position/recovery mapping, deterministic presentation, and
   AcceptedEnvironmentGeneration-keyed caching.
5. Remove the word-only fallback and any duplicate resolver after all callers
   migrate.
6. Add direct recovery/stale/limit/cross-owner tests and run focused/workspace
   validation plus the canonical structural audit.

If proof 01.1.1 is a prerequisite, place it explicitly before step 2 and name
the consumed typed-node API. For an explicit non-goal outcome, provide the
evidence-review order and the exact placeholder/bypass cleanup, if any, without
inventing implementation work.

## Mandatory direct tests or evidence matrix

For an implementation outcome, map tests to exact typed results for:

- every applicable native call surface and correct active parameter;
- canonical, compact, qualified, and alias owner spellings;
- same local look/part/variant spelling across owners and parts;
- positional, named, reordered, duplicate, and spread arguments;
- nested calls, partial calls, overloads, methods, function values, missing
  closing delimiter, recovered expressions, and cursor boundary positions;
- native-only, adapter-only, and same-name native/adapter precedence;
- stale SourceDocumentIdentity, SourceSnapshotId when selected, LSP version,
  symbol revision, accepted generation, profile, and character facts;
- failed rebuild preserving prior accepted world/cache;
- exact and one-over candidate/parameter/nesting/source-byte/work/diagnostic
  limits and arithmetic overflow;
- deterministic overload/error ordering; and
- no label parsing, word-only wrong-owner selection, source search, or second
  successful resolver.

If EXPLICIT_NON_GOAL is selected, provide the mandatory surface inventory and
semantic evidence for every current call family. Tests may prove public query
non-applicability, but absence must not be enforced by scanning checked-in
source.

Automated source gates are prohibited in either outcome. No test or script may
read checked-in implementation or documentation and pass/fail by searching for
symbols, spellings, snippets, module paths, or file locations.

## Non-goals

- Redesign of CharacterNominalType, CharacterRegistrar,
  ProjectSymbolTable, RegisteredSemanticWorld, accepted profile publication,
  completion, hover, or proof typed-AST identity.
- New callable syntax or synthetic character constructors.
- Broad unrelated LSP feature redesign.
- Stringly signature keys, source_label() parsing, global text search,
  compatibility APIs, dual resolvers, or persisted query formats without a
  proven carrier.
- CSS/Takumi, rendering, rename, or removed-syntax restoration.
