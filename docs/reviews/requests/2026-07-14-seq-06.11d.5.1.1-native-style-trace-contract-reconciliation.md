## Why this split is required

The package `seq-06.11d.5.1-native-style-trace-contract` declared baseline
`acb97452e128b090665b509b95381ef0142fc2d3` and reported that it had inspected
`52d6fadee2a0eee2fc3a565c4a2354e325eb49a1`. The relevant existing Style files
were unchanged between that baseline and the inspected revision. Nevertheless,
the packaged patch did not apply to the declared baseline shape: its
`computed_style.rs` hunk expected trace fields named `declaration_source` and
`rejection`, while the actual baseline fields were `declaration` and `reason`.

More importantly, the package's normative design, Rust model, projection code,
schema, and examples disagree on identity, ordering, paging, redaction, cache,
cursor, and validation behavior. The package was statically inspected without
a Rust toolchain and therefore has no compilation, rustfmt, Clippy, Rust test,
or repository structural-audit evidence.

The complete capability scope above also requires typed environment and
container facts, predicate mismatch/blocking outcomes, and the revisions that
bind those facts into identities, cache keys, pages, and cursors. Those
contracts belong to d.4.2 and d.4.3. Reconciliation before they land would force
the trace layer to invent or duplicate adaptive-Style semantics that it is only
meant to observe.

These are contract decisions rather than mechanical compiler repairs. Do not
select whichever packaged artifact is easiest to compile. Give every conflict
below one explicit final answer, then make the types, prose, schema, examples,
and test oracle agree with that answer.

## Complete capability scope

### Goal and required explanations

Specify one typed, deterministic, bounded, and redactable contract that explains
why a native Style property won, lost, inherited, or failed to apply to one
concrete mounted View node. The boundary must support in-process debugging and
future transport projection without making wire, Agent, LSP, CLI, filesystem,
renderer, or platform concerns part of the resolver.

For a requested node and property set, the final contract must answer whenever
the authorized evidence exists:

1. the effective typed value and its invalidation class;
2. whether it was inherited, supplied by a named sheet, or supplied by an
   inline patch;
3. which application, rule, selector, declaration, and source range produced
   the winner, and which competing contributions lost by which typed priority;
4. why a rule or patch did not contribute, including selector facts, View
   boundary blocking, environment/container outcomes, applicability, and
   correctness-budget failure;
5. how typed token expansion and append/replace operations produced the final
   value without running a second cascade; and
6. whether computed and evidence state came from a cache hit, winner
   reconstruction, real resolver collection, or bypass, and what query mode,
   filter, observability budget, source policy, or redaction omitted.

The contract must preserve a strict distinction among resolver failure, trace-
query failure, valid partial completion, per-event rejection, withheld evidence,
unavailable evidence, and malformed source projection. It must never insert a
fake value into `ComputedViewStyle` to represent an observability status.

### Typed boundary and ownership

Give exact Rust definitions, constructors, accessors, visibility, owning crate
and module, errors, and conversion boundaries for at least:

- a typed query identifying the mounted node, optional property selection,
  evidence mode, inclusion flags, observability budgets, source policy,
  authorization namespace, redaction ceiling, expected revisions, and cursor;
- a response/page envelope carrying query identity, snapshot/revision binding,
  cache disposition, completion state, canonical ordered evidence, structured
  diagnostics, and the next cursor when one is valid;
- opaque typed identities for node, sheet, patch, application, rule,
  declaration, selector step, token, source range, evidence, query, and
  property;
- an internal resolver evidence algebra and a distinct transport-neutral event
  algebra for winner, inheritance, selector facts, token expansion, assignment,
  contribution, rejection, omission, and truncation;
- typed source projection distinguishing available, withheld, unavailable,
  stale, malformed, and generated-without-authored-range outcomes; and
- typed query, identity, revision, range, reference, authorization, redaction,
  paging, cursor, codec, and budget errors.

`arcweft-view` owns the sole resolver and its internal typed evidence.
`arcweft-style-trace-model` owns only transport-neutral DTOs, validation, and
deterministic codecs. `arcweft-style-trace-view` owns policy-aware projection,
identity derivation, source adaptation, redaction, canonical ordering, paging,
cursors, and projected-page caching. Use an inherent conversion, `TryFrom`, or
one named projection context when policy, source maps, allocation, or shared
state is required; do not expose a public field-by-field endpoint helper or let
an adapter own a duplicate semantic registry.

### Canonical wire contract

Define one initial, unreleased canonical wire shape for the portable DTO and
make its Rust types, schema, examples, fixtures, validation, and tests agree
byte for byte. Freeze:

- schema identifier and ordering version;
- exact JSON object, field, enum, tagged-union, integer, range, opaque-ID,
  optional/required, and unknown-field representations;
- duplicate-key behavior, canonical number forms, UTF-8, escaping, whitespace,
  trailing-byte behavior, and canonical serialization;
- completion, omission, truncation, redaction, source, diagnostic, cache, and
  paging representations;
- complete, partial, redacted, and multipage valid examples plus invalid and
  tampered examples; and
- the exact distinction between stateless page validation and validation that
  requires a query, projection snapshot, authorization context, or cursor key.

Opaque identities must not require clients to parse display labels, source
paths, vector ordinals, raw revisions, internal keys, or JSON spelling. The
format has no legacy reader, alias, deprecated field, dual version, probing
branch, or migration shim.

### Budgets, ordering, paging, and completion

Define independent checked defaults and hard maxima for requested properties,
applications/rules/declarations inspected, emitted events, source-map lookups,
hydrated source bytes and snippets, token-chain evidence, ancestor facts,
diagnostics, serialized bytes, pages/cursors, projected-cache entries, and all
adaptive fact evidence added by the landed d.4.2/d.4.3 contracts. Give exact and
one-over-limit behavior and state which failures reject a query versus produce
a deterministic partial result.

Define one canonical total order for properties, applications, rules,
declarations, selector components, token steps, event families, property-less
events, diagnostics, related evidence, omissions, truncation, and pages. Apply
redaction and authorized-sequence collapse before canonical order, sequence
assignment, paging, cursor binding, serialization budgeting, and projected-cache
insertion. Observability budgets must never weaken, raise, or consume the sole
resolver's correctness budgets and must never change a computed winner.

Define page capacity, cross-page references, winner-summary placement, page
offsets, completion markers, last-page cursor behavior, replay behavior, and
cursor authentication. A cursor is untrusted input bound to the complete query,
node, revisions, ceiling, authorization namespace, budgets, source policy, and
ordering version; it is never an internal pointer or raw cache key.

### Source maps and redaction

Define how typed Style source references map through merged bundle inventories
to source identity and half-open UTF-8 byte ranges. Cover absent maps, missing
content, generated records, stale document revisions, owner mismatch, invalid
encoding or UTF-8 boundaries, out-of-bounds ranges, and tampered references.
Source content, path lookup, authorization, and hydration remain injected

Classify every potentially sensitive field, including typed values and tokens,
embedded resource identities, mounted node/part/source names, environment and
container facts, byte ranges, paths, snippets, diagnostics, opaque IDs,
collection lengths, event order, cursors, revisions, and cache status. Assign
one minimum redaction ceiling and stable withheld representation to each field.
A lower-privilege response must not infer hidden data through hashes, lengths,
ordering, diagnostic text, cursor contents, serialized length, cache behavior,
or a hidden-sequence count.

### Cache and diagnostics

Specify separate authorities and lifecycle for computed Style caching and any
projected trace-page cache. The final key must include every selected query,
node/fact/application/environment/container/source revision, trace mode,
source-map revision, authorization namespace, redaction ceiling, budget, source
policy, ordering version, and cursor input exactly where relevant. Define
hit/miss/bypass disclosure, deterministic FIFO eviction, invalidation, stale
cursor behavior, privilege isolation, and whether redacted projections may
share an underlying computed result without sharing projected evidence. Full
evidence cannot be fabricated from a computed-cache hit; `Winners` may
reconstruct retained provenance; `Off` remains free of trace-evidence allocation.

Define stable typed diagnostic code, category, severity, primary range,
related-evidence and label records, canonical key, duplicate policy, redaction
floor, and failure disposition. Message and label text are presentation and
must not affect identity, order, routing, cache keys, or reference validity.
Deleted CSS/Takumi syntax receives no Style-trace or removal diagnostic; it is
outside this contract and remains ordinary current-grammar rejection.

## Fixed native-only substrate

The following existing behavior is already implemented and verified. It is
input to the reconciliation, not a design opportunity:

- Arcweft has one native typed Style language. CSS source, CSS selector
  carriers, raw CSS bodies, external stylesheet paths, Takumi, and CSS-specific
  diagnostics or compatibility paths are absent.
- Native syntax lowers through HIR and semantic checking into a typed,
  sheet-owned `ViewStyleProgram`.
- Static View producers retain ordered `ViewStyleApplicationTarget` values.
  Runtime materializes full `ViewStyleApplication` values from mount, scope,
  order, depth, and View-boundary facts.
- `arcweft-view::style::ViewStyleResolver` is the sole cascade owner.
  Tooling, bundle, player, and trace adapters must not run a second cascade or
  recompute a winner.
- `ComputedViewStyle` retains typed values and winner provenance. Cascade
  priority remains scope depth, application order, predicate specificity,
  element specificity, rule source order, and declaration order, with later
  tuple values winning.
- Inheritance is controlled by `ViewPropertyKind::is_inherited()`. Token lookup
  is sheet-owned. Inline token use requires one unambiguous owner. Nested-View
  traversal requires explicit boundary permission.
- Trace modes are `Off`, `Winners`, and `Full`. `Off` must not allocate trace
  evidence; `Winners` may reconstruct winner evidence from retained computed
  provenance; `Full` must observe the resolver's real branches and bypass a
  computed-cache hit when full evidence cannot be reconstructed.
- Resolver correctness limits remain separate from observability limits.
  Trace budgets must never change the winning computed Style.
- Style source references are typed and merged with their bundle inventories.
  Source content, paths, authorization, secrets, and transport remain injected
  adapter concerns.

The reconciliation is additionally gated by these sequential adaptive-Style
predecessors. Each becomes fixed substrate only after its own implementation
and validation land:

- d.4.1 owns the canonical logical property inventory and axis-aware
  resolver/computed boundary that trace evidence describes.
- d.4.1.1 owns the per-mount axis seed, provider/barrier identity, authoritative
  provider revision, propagation, and invalidation lifecycle. Trace identity
  and evidence must consume that landed revision contract rather than treating
  the d.4.1 core's fixed root default as a complete host lifecycle.
- d.4.1.2 owns final physical box geometry, measured-bound and geometry-revision
  identity, and the layout records consumed by container facts. Trace must not
  infer or serialize a competing provisional geometry model.
- d.4.2 owns the final typed environment-condition records, host snapshot and
  revision authority, resolver outcomes, cache/invalidation behavior, and
  source provenance. Trace must consume those landed types and outcomes rather
  than define parallel environment facts.
- d.4.3 owns the final query-container selection, typed logical-size facts,
  dependency graph, availability/blocking outcomes, revision authority,
  invalidation, and work budgets. d.4.3 is not landed when this request is
  written, so this request intentionally fixes none of those shapes in
  advance. Inspect its landed contract before defining container trace DTOs.

Reconcile against the checkout after all five cuts land, not a copied overlay
from an earlier stage. Do not redesign verified resolver behavior or any landed
logical-axis, environment, or container substrate unless the reconciliation
demonstrates a concrete, reproducible defect. A preference for a different
trace DTO, module layout, or package patch is not defect evidence.

## Required final decisions

Every subsection below is mandatory. The output must state one final contract,
not preserve alternatives as implementation choices.

### 1. Query identity ownership

The normative design put `query_id: StyleQueryId` in `StyleTraceQuery`. The
packaged Rust query type and valid input example omitted it and derived a query
identity inside projection, while the response summary added it back.

Decide whether a caller supplies a query ID or the trusted adapter derives it.
Specify:

- the exact input query and response-summary Rust types;
- the canonical derivation or validation inputs;
- whether the cursor is excluded from the query binding;
- replay, cross-principal, cross-ceiling, and cross-revision behavior;
- the exact JSON fields for input and response.

The prose, Rust definitions, schema, query example, page examples, cursor key,
and tests must use the same answer.

### 2. Node identity and revision inputs

The design required a node identity to include `ViewStyleNodeKey` plus relevant
fact and application revisions. The packaged identity implementation hashed
only mount, path segments, and instruction and placed revisions elsewhere.

Define the exact typed input and domain separation for every opaque identity,
especially node, application, rule, declaration, selector step, source range,
and evidence. State which revisions are part of each ID, which are only page or
cursor bindings, and when an ID must change. Include authorization namespace
and redaction-ceiling isolation without exposing raw keys, paths, revisions, or
display strings.

### 3. Duplicate equivalent applications

The design said an occurrence discriminator is included only when
byte-identical applications coexist and required a structured
`DuplicateEquivalentApplication` diagnostic. The packaged code always included
the application vector index, emitted no such diagnostic, and did not include
that code in its supposedly closed diagnostic inventory.

Choose one stable identity rule for unique and duplicate applications. Define
the occurrence input, its stability under an identical snapshot, whether it is
visible, and whether duplicates are diagnostic, ordinary, or invalid. If a
diagnostic remains, add its exact typed code, category, severity, ordering, and
redaction behavior to every inventory and test it. The discriminator must never
participate in cascade priority.

### 4. Adaptive predicate evidence and revision binding

This request requires explanations for environment and container facts,
predicate mismatch or blocking, and environment/container revisions. The
disputed package projected provisional forms before the complete d.4.2 and
d.4.3 implementation contracts had landed.

After those predecessors land, define exactly how trace evidence represents:

- matched, mismatched, unavailable, blocked, and not-evaluated environment and
  container predicate outcomes, preserving the distinctions owned by the
  resolver;
- typed observed facts and source provenance without a second evaluator,
  property-name strings, or duplicated adaptive enums;
- selected container occurrence and boundary visibility only to the extent
  authorized by the landed d.4.3 contract;
- environment and container revision inputs in node/evidence identities,
  expected-revision checks, page snapshots, cursor bindings, computed-cache
  disposition, and projected-cache keys;
- minimum redaction ceilings, hidden-sequence collapse, observability budgets,
  diagnostics, and completion status for those facts.

Trace must record the sole resolver's actual branch outcomes. It must not
re-evaluate environment predicates, select a container, infer axes, rebuild a
container dependency graph, or define invalidation. If a predecessor lacks a
fact needed for a correct explanation, report that as a concrete upstream
design defect rather than inventing a trace-only surrogate.

### 5. Cache envelope and disclosure

The normative page envelope had two cache fields and combined values such as
`miss_collected`, `hit_winners_reconstructed`, and `full_bypass`. The Rust
model, schema, and examples instead split the envelope into `computed`,
`evidence`, and `projected_page` with different enum values.

Define one exact typed envelope and JSON representation. It must distinguish
computed hit/miss/bypass, winner reconstruction versus full collection, and
projected-page hit/miss wherever the authorized ceiling permits. Define when
each field is withheld and prove that a hidden hit/miss does not alter event
count, order, diagnostics, cursor length, or serialized length through
uncontrolled data.

### 6. Winner placement, event order, and paging

The normative ordering made the winner event last for each property. Packaged
projection used `PHASE_WINNER = 0`, fixtures put winners first, and pagination
required leading winner events to fit on the first page. These models cannot
both be true.

Specify one complete canonical event-order key and direction for:

- property slots;
- inheritance, selector facts, token expansion, assignment, contribution,
  rejection, winner, omitted, and truncated records;
- applications, rules, declarations, selector components, and token depth;
- property-less rule-wide events;
- redacted or collapsed sequences;
- evidence-ID tie breaking.

Then define how property summaries reference winners across pages, whether the
first page must contain all winners, the relation between property count and
page capacity, page offsets, truncation placement, and the last-page cursor
rule. Redaction must happen before order, sequence assignment, paging, cursor
binding, and projected-cache insertion.

### 7. Application tie breaking

The design used opaque snapshot application-ID bytes to break otherwise equal
evidence order without changing cascade priority. Packaged ordering used the
raw application occurrence index.

Choose the exact evidence-only tie breaker. State whether it is computed before
or after redaction, how it remains deterministic across native/web/headless
backends, and why it cannot leak a hidden name, vector length, privilege, or
cache state. It must not affect the computed winner.

### 8. Priority redaction

The redaction table made the six-component priority tuple visible at the
`structure` ceiling. Packaged winner, assignment, and contribution projection
passed priority through an `identities` gate, while `winner_priority` was
unconditionally available. The redacted fixture followed the former behavior.

Assign one minimum ceiling to every priority occurrence. Apply it consistently
to winners, assignments, contributions, comparisons, summaries, diagnostics,
and examples. If any component is sensitive, explain the concrete threat and
revise the field-class table rather than special-casing one event.

### 9. Diagnostic order and privacy

The normative key was category, severity, typed code, primary source-range ID,
and first related evidence ID, explicitly excluding message text. Packaged
validation and projection sorted serialized whole diagnostics, so labels and
redacted or rendered messages changed order.

Define a typed canonical diagnostic key, including zero/absent behavior and
duplicate handling. Message and label text must not participate. Varying a
message or withholding it must not reorder diagnostics. State how related
evidence and labels are reference-validated and sorted.

### 10. Cursor byte layout and authentication

The normative fixed 50-character cursor encoded 37 bytes as version (1), page
index (4), a 16-byte binding tag, and a 16-byte message tag. Packaged code used
an 8-byte query tag, an 8-byte snapshot tag, and a 16-byte MAC.

Select one exact byte layout and document offsets, endianness, tag derivation,
domain separation, truncation strength, canonical base64url form, key rotation,
and constant-time comparison. Define bindings for query, node, complete
revisions, ceiling, authorization namespace, budgets, source policy, and
ordering version. Tests must cover valid-length forged tags, not merely a cursor
with the wrong string length.

### 11. Canonical order and reference validation

Packaged page validation checked contiguous sequence numbers and duplicate
evidence IDs but did not establish the normative event order or all typed
references. Define what a stateless page decoder can validate and what requires
a projection snapshot or cursor context. At minimum decide validation for:

- canonical property and event ordering;
- exactly one relevant winner and summary-to-winner references;
- selector-step, declaration, source-range, diagnostic, and related-evidence
  references;
- page-local versus cross-page references;
- duplicate IDs, duplicate keys, unknown fields/enums, noncanonical IDs,
  invalid ranges/owners, trailing bytes, numeric form, and canonical JSON;
- completion/omission/truncation consistency and serialized-byte budgets.

No invalid reference may be silently ignored, clamped, or converted to a fake
value.

### 12. Schema generation and artifact ownership

The package contained an 851,335-byte, 19,607-line schema but no checked-in
generator, even though its integration note required regeneration from the
final Rust DTO. Define:

- the owning crate or repository tool;
- the deterministic generation command and dependency versions;
- the single Rust/type source of truth;
- canonical output path under repository conventions;
- how generated status and any size exception are documented;
- how CI regenerates and compares the artifact;
- how valid, partial, redacted, and invalid fixtures are produced or checked.

Generated-artifact equality is allowed because the schema itself is the
contract. Searching unrelated source text for expected names or paths is not.
The final schema and examples must agree with the final Rust types byte for
byte; fixture descriptions must describe their actual values, page state, and
cursor state.

### 13. Compatibility seam deletion

The packaged trace overlay explicitly introduced a “Compatibility seam”
`push(mode, entry)` that could mutate recorder mode while richer call sites
were introduced. The format and APIs are unreleased and no compatibility
requirement exists.

The final design must delete that seam rather than rename or deprecate it.
Specify the direct recorder APIs for `Off`, `Winners`, and `Full`, their
visibility, and how all resolver call sites migrate in one root-cause change.
Do not retain dual event types, dual readers, aliases, wrappers, or a branch
that silently accepts the discarded shape.

### 14. Package integration disposition

The supplied patch, whole-file overlays, schema, examples, and validator are
reference evidence only and are not integration inputs. The final design must
state that implementation starts from the checkout after d.4.1, d.4.1.1,
d.4.1.2, d.4.2, and d.4.3 have landed and passed their own validation, applies
small compiling changes, and lets typed compiler errors identify all affected
call sites. It must not prescribe copying a complete old resolver over the
landed logical-axis, geometry, environment, or container work.
