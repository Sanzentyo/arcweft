# Seq05.4.2 Request: CLI REPL Inspection/Debug Command Adapter Package

Date: 2026-06-29
Depends on: seq05.4 REPL host adapter integration

## Sequence Position

This follows the accepted seq05.0 through seq05.4 cuts:

- seq05.0 introduced Agent REPL runtime tiers and dispatch boundaries.
- seq05.1 introduced overlay cell transactions, snapshots, generations, and invalidation tokens.
- seq05.2 introduced typed REPL commands, command results, and Agent runner hooks.
- seq05.2.1 added typed CLI formatting and host adapter follow-up substrate.
- seq05.2.2 added runtime-driver task ownership adapter APIs.
- seq05.3 added VM-first tiering status, `:warm`, and `:codegen` behavior.
- seq05.4 wired the CLI Agent REPL bridge to typed `ReplCommandResult`, runtime-driver task ownership, and the tier command handler.

Seq05.4 intentionally left some CLI-local inspection and debug commands outside the shared `arcweft-agent-repl` command model. The current implementation routes them through a narrow allow-list and the legacy CLI meta-command evaluator. Seq05.4.2 closes that transitional gap by adding a second typed parser and adapter for CLI-owned inspection/debug commands.

## Problem

The command path is almost typed, but not fully. The current flow is effectively:

```text
raw input
  -> shared arcweft-agent-repl typed parser
  -> parse failure
  -> string allow-list for CLI meta command names
  -> legacy CLI meta evaluator
```

That is a transitional parser seam, not a stable architecture. It makes CLI inspection/debug command ownership implicit, gives parse diagnostics different behavior depending on whether the input happens to start with an allow-listed token, and keeps command handling split between typed results and legacy string dispatch.

The intended final shape is:

```text
raw input
  -> shared arcweft-agent-repl typed parser
  -> CLI-owned typed inspection/debug parser
  -> structured parse diagnostic
```

Both parser stages must return typed values. The second stage is not a compatibility shim; it is the stable owner for commands whose behavior belongs to the CLI host because they require filesystem access, debug trace storage, native capture, local compiler inspection, MCP connection management, or other process-facing adapters.

## Request

Produce a zip package that designs and implements seq05.4.2 CLI REPL inspection/debug command adapter integration.

The package must replace `agent_repl_cli_meta_command()` and the legacy meta-command string dispatch with a CLI-owned typed command parser, typed command enum, and typed dispatcher. It must preserve the shared `arcweft-agent-repl` command model as the first parser stage and keep CLI-specific inspection/debug responsibilities out of `arcweft-agent-repl`.

## Required Decisions

1. What CLI-owned command enum should represent inspection/debug commands, for example `CliReplCommand`, `CliInspectionCommand`, or a more precise current-code name.
2. What input enum or adapter result should compose the two parser stages, for example:

   ```text
   raw input -> SharedAgentRepl(ReplInput) | CliInspection(CliReplCommand)
   ```

3. Which commands belong in the shared `arcweft-agent-repl` typed command model and which commands belong in the CLI-owned typed adapter.
4. Whether any currently CLI-local command should move into `arcweft-agent-repl` because it is actually session/transaction/tiering behavior rather than CLI inspection/debug behavior.
5. How the parser reports unknown command names, malformed arguments, and ambiguous command ownership after both typed parsers fail.
6. How read-only trace mode is represented for CLI-owned commands that would mutate trace/capture/query/debug state.
7. How typed CLI command results compose with the existing `ReplCommandResult` formatter without parsing human text.
8. Whether CLI command output should use a new `CliReplCommandResult` type, an adapter into existing `AgentReplCellReport`, or a small shared result envelope.
9. How JSON output remains structured and deterministic for CLI-owned command results.
10. How MCP/LSP follow-up work from seq05.4.1 can consume typed results without inheriting CLI terminal formatting.
11. What exact code is deleted after the migration, including `agent_repl_cli_meta_command()` and the string branch in `agent_repl_eval_meta(...)`.

## Command Ownership Guidance

The package must audit current behavior rather than blindly follow this table, but the expected ownership direction is:

| Command family | Expected owner | Reason |
| --- | --- | --- |
| `:cells`, `:undo`, `:reset`, `:capabilities`, `:generations`, `:bindings`, `:tasks`, `:cancel`, `:warm`, `:codegen`, `:help`, `:quit`, `:load`, `:reload`, `:observe`, `:step` | `arcweft-agent-repl` shared typed command model unless current evidence proves otherwise | These are REPL/session/task/tiering command semantics and should not depend on CLI terminal or filesystem behavior except through typed host adapters. |
| `:ast`, `:hir`, `:bytecode`, `:type`, `:parse`, `:classify`, `:complete`, `:highlight` | CLI-owned typed inspection adapter, or a future shared tooling crate if one already exists | These are local compiler/tooling inspection surfaces, not low-level REPL command semantics. |
| `:trace`, `:actions`, `:capture`, `:query`, `:drop`, `:save` | CLI-owned typed debug/trace/capture adapter | These interact with CLI trace state, debug stores, capture outputs, or project-local artifacts. |
| `:connect` and remote-session management commands | CLI-owned typed host adapter | These manage CLI process connections and transports. They must not live in `arcweft-agent-repl`. |

If the package changes any ownership in this table, it must document the evidence and dependency-boundary reason.

## Required Implementation Scope

Implement the sufficiently designed CLI typed adapter end to end. At minimum:

- Add a CLI-owned typed parser for inspection/debug commands.
- Add a CLI-owned typed command enum with structured arguments, options, and spans or diagnostic anchors where current parser infrastructure can provide them.
- Introduce a two-stage parse API at the CLI bridge boundary:

  ```text
  parse_repl_input(input)
    -> shared typed REPL input
    -> otherwise parse_cli_repl_input(input)
    -> otherwise structured parse diagnostic
  ```

- Replace `agent_repl_cli_meta_command()` with the second typed parser.
- Replace string matching inside the legacy meta evaluator with typed dispatch over the CLI command enum.
- Delete the old allow-list branch once all commands it recognized are covered by the typed CLI parser.
- Keep terminal, filesystem, debug trace, native capture, MCP transport, and process I/O dependencies in `arcweft-cli` or appropriate adapter crates, not in `arcweft-agent-repl`.
- Preserve existing shared `ReplCommandResult` behavior for shared commands.
- Preserve or introduce structured typed CLI command results for CLI-only commands; do not serialize human text and parse it back.
- Ensure JSON mode emits deterministic typed objects for CLI-only commands.
- Ensure human mode formatting is owned by the CLI and remains exhaustive over shared and CLI-only command results.
- Add implementation documentation under `docs/implementation/`.

## Acceptance Criteria

- The CLI Agent REPL input path uses two typed parser stages:
  - shared `arcweft-agent-repl` parser first;
  - CLI-owned inspection/debug parser second.
- `agent_repl_cli_meta_command()` is deleted.
- CLI-only command dispatch no longer depends on a string allow-list after shared parser failure.
- CLI-only commands have typed enum variants and structured argument parsing.
- Unknown or malformed CLI command input produces structured diagnostics after both typed parser stages are considered.
- Shared REPL commands continue to return typed `ReplCommandResult`.
- CLI-only inspection/debug commands return typed, deterministic results suitable for both human and JSON formatting.
- JSON mode does not serialize formatted human text.
- Human formatting remains CLI-owned.
- CLI-specific trace, capture, compiler inspection, debug-store, remote connection, filesystem, and process I/O behavior does not move into `arcweft-agent-repl`.
- `arcweft-agent-repl` remains Sans I/O.
- Product player crates do not depend on REPL, CLI, MCP, LSP, or debug inspection crates.
- The implementation note records any command whose ownership changed during the audit and why.

## Constraints

- Do not redesign seq05.1 transaction/session APIs.
- Do not redesign seq05.2 shared `ReplCommand`, `ReplCommandResult`, or `ReplCommandEvidence` except for narrowly justified command ownership corrections.
- Do not redesign seq05.3 tiering/warm/codegen behavior.
- Do not duplicate runtime task state in CLI.
- Do not move CLI terminal formatting into `arcweft-agent-repl`.
- Do not move CLI filesystem, debug trace, native capture, MCP transport, process I/O, or local compiler inspection dependencies into `arcweft-agent-repl`.
- Do not introduce compatibility aliases, deprecated wrappers, or migration shims.
- Do not keep string fallback behavior after the typed CLI parser is implemented.
- Prefer owned enum behavior, typed contexts, and inherent methods on Arcweft boundary types over ad hoc helper functions.

## Non-Goals

- Implementing MCP/LSP REPL command-result protocol endpoints. That remains seq05.4.1 unless this package finds an already stable endpoint and can wire it without redesign.
- Redesigning Agent runner execution policy.
- Redesigning runtime task ownership.
- Adding JIT/AOT execution beyond seq05.3 tiering status behavior.
- Building persistent compiled artifact caches.
- Changing Arcweft DSL syntax or parser behavior outside REPL command parsing.

## Parallelization Guidance

Seq05.4.2 can be designed in parallel with seq06 and seq07 work because it is confined to CLI/Agent REPL tooling boundaries.

Do not implement seq05.4.2 in parallel with another package that rewrites:

- `crates/arcweft-agent-repl/src/command/`
- `crates/arcweft-cli/src/app/agent/native/repl_command_bridge.rs`
- `crates/arcweft-cli/src/app/agent/native/repl_command_format.rs`
- any shared formatter/result envelope introduced by seq05.4.1

If seq05.4.1 and seq05.4.2 are both being designed, they may run in parallel as design packages. Apply seq05.4.2 first if it deletes the CLI meta allow-list and defines the typed CLI result boundary. Then apply seq05.4.1 against that typed result boundary so MCP/LSP adapters do not inherit legacy CLI string dispatch.

Recommended application order:

1. Apply seq05.4.2 to remove the CLI meta allow-list and establish the two-stage typed parser.
2. Apply seq05.4.1 MCP/LSP command-result adapters after the typed CLI/shared result boundary is stable.
