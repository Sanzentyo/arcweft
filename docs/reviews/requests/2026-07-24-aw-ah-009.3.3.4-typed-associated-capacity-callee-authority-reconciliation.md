## Why this correction is required

The stable language surface includes all of the following:

```arcw
let names = Vec<String>.with_capacity(8)
let text = String.with_capacity(64)
let bytes = Bytes.with_capacity(4096)
```

AW-AH-009.3.3 already selects `CapacityMethodId { receiver, method, arity }`,
uses `CallableFamily::CapacityMethod`, keeps arguments intentionally unchecked,
and places an accepted capacity candidate after environment methods and before
traits/data-last fallback. However, its `CallCallee::Selected` shape owns a
value `receiver_expression: TypeExpressionId`; it does not define how a type
receiver such as `Vec<T>` reaches the resolver.

AW-AH-009.3.1 requires static generic/turbofish callees to be parsed by the
Pratt/path token grammar and prohibits the old source-scanning helper, but it
does not select the typed syntax/HIR payload, resolution rules, or value/type
receiver distinction needed by sema.

Current production therefore succeeds before the shared resolver through
`well_known_static_capacity_method_type(&str)`. That helper reparses
`Vec<...>::with_capacity` text, represents a bare `Vec` with a stringly `_`, and
reduces a generic `T` to a name instead of preserving semantic generic identity.
The early branch also prevents checker facts and signature help from observing
the accepted `CapacityMethodId`. Removing it without a replacement would break
the documented surface and current non-registered type-checking behavior.

The repository cannot truthfully complete the AW-AH-009.3.3 migration row by
either retaining that old success dispatcher or inventing an unreviewed type
receiver carrier.

## Required decisions

1. Select the exact lossless syntax and typed HIR representation for an
   associated callee whose receiver is a type and whose terminal member is
   called. Cover at least `String.with_capacity`, `Bytes.with_capacity`, bare
   `Vec.with_capacity`, `Vec<I32>.with_capacity`, `Vec<T>.with_capacity`, module
   qualified type paths, aliases, generic arguments, and accepted turbofish
   spelling. State which layer owns every delimiter, segment, source range,
   generic argument, and resolved type identity.
2. Define an explicit typed distinction between a value-receiver selected call
   and a type-receiver associated call. Do not use a sentinel expression ID,
   empty range, display label, or reparsed source string. State the final
   `CallCallee` request shape and whether the owning enum belongs to HIR, sema,
   or a lower typed boundary.
3. Define how authored type syntax becomes `TypeKind` while preserving nominal,
   alias, module, and generic-parameter identity. In particular, specify the
   result for bare `Vec`, `Vec<T>` inside a generic callable, and unresolved or
   ambiguous type names without constructing `TypeKind::Named("_")` or parsing
   a display string.
4. Define the single resolver entry for static capacity calls. Preserve the
   accepted `CapacityMethodId`, `CallableCandidateId::CapacityMethod`,
   `CallableFamily::CapacityMethod`, result equal to the selected receiver, exact
   authored argument-count identity, `variadic_unchecked` argument behavior,
   and exactly-once checker/signature work accounting.
5. Define name and collision precedence for the type-receiver path. Reconcile
   lexical values with type names, imported/qualified/aliased types, environment
   callables, traits, data-last callables, and near-miss members. State whether
   the accepted selected-call ordering applies directly or requires a distinct
   typed associated-call phase; do not leave this to implementation guesswork.
6. Define failure and recovery for malformed generic arguments, missing member,
   unknown/ambiguous type receiver, invalid associated member, and a value call
   such as `value.with_capacity(...)`. Every authored argument expression must
   still be checked exactly once where current recovery requires it.
7. Define how registered and non-registered type-check modes converge on the
   same typed seed and capacity schema. A retained legacy fast path, second
   resolver, or non-registered string parser is not an acceptable answer.
8. Specify the compiling authority-switch order: introduce the non-public typed
   carrier and lowering, connect parser/HIR/type resolution, connect the shared
   resolver/checker/signature query, then delete the old import, early success
   branch, and `well_known_static_capacity_method_type` helper in the same
   production switch. List every old reader that must be absent afterward.
9. State exact normative precedence over the relevant AW-AH-009.3.1 and
   AW-AH-009.3.3 rows without changing their already accepted ordinary call,
   capacity candidate, or work-accounting decisions.
