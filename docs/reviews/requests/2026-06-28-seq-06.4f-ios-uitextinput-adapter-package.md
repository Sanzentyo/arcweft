# Request 06.4f: iOS UITextInput Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the iOS platform adapter package and should not redesign
the shared capability, range, batch/serial, or geometry substrate unless current
implementation evidence proves a concrete flaw.

This request can be run independently from the Web, Windows, macOS, Wayland,
and Android adapter requests. Apple API evidence is a first-class gate for this
package because the integration review identified unresolved range, callback,
and coordinate questions.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for an iOS
UIKit `UITextInput` adapter for Arcweft text input.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints.
- Apple SDK, header, and DocC evidence for `UITextInput`,
  `UITextInputTraits`, `UITextPosition`, `UITextRange`,
  `UITextInputTokenizer`, marked text, selection/caret rectangles, callback
  ordering, and coordinate conventions.

## Platform Scope

Implement the iOS adapter in the current mobile/native host owner if one exists.
If none exists, the zip must include a concrete, feature-gated iOS adapter crate
or module plan plus implementation overlay for the Rust/Objective-C/Swift
boundary required by `UITextInput`.

The adapter must:

- pin SDK/header/DocC evidence before upgrading any HostDependent or Limited
  capability;
- keep UIKit objects, `UITextPosition`, `UITextRange`, tokenizer objects,
  attributed strings, native ranges, native view identity, and Objective-C/Swift
  objects adapter-local;
- resolve native opaque positions/ranges through an adapter-local resolver and
  `TextIndexSnapshot` before emitting canonical byte ranges;
- send only checked canonical byte ranges or typed diagnostics into Sans I/O;
- map one UIKit text-input callback to one Arcweft serial unless a
  callback/delegate-observed atomic update includes marked text plus
  selection/replacement;
- keep reconversion unsupported or HostDependent until concrete standard API
  behavior is proven;
- avoid private UIKit commands or private APIs;
- compute UIKit view-local rects from Arcweft viewport/screen geometry in the
  adapter;
- expose caret/control geometry only for secure fields and omit all character
  bounds with `SecureRedacted` capability state.

## Required Decisions

1. The iOS crate/module ownership, target gating, and Rust/Objective-C/Swift
   source layout.
2. The exact SDK/header evidence for `UITextPosition`/`UITextRange` resolution,
   offset semantics, stale range behavior, callback ordering, and coordinate
   conventions.
3. The lifecycle owner for the UIKit view/object implementing `UITextInput`.
4. The native range resolver and conversion path for marked ranges, selected
   ranges, replacement ranges, tokenizer results, invalid ranges, and stale
   snapshot cases.
5. The callback boundary that creates one Arcweft serial.
6. The mapping of marked text update, commit, unmark/cancel, selection,
   replacement, delete, keyboard traits, and input mode facts into Arcweft
   operations and capabilities.
7. The geometry conversion from Arcweft viewport/screen rectangles into UIKit
   view-local caret, first, and selection rectangles.
8. The secure-field policy for surrounding text, marked text metadata, geometry,
   diagnostics, Agent observe, replay, and capture output.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include:

- iOS adapter modules, Objective-C/Swift glue, Rust FFI boundary code, and any
  feature/Cargo/build edits.
- SDK/header evidence fixtures or notes sufficient to unblock implementation.
- Typed capability detection and activation diagnostics.
- `UITextInput` callback conversion into `PlatformTextInputEvent`.
- Native opaque range conversion through shared text-index APIs.
- Geometry adapter code for UIKit view-local rectangles and secure redaction.
- iOS fixture traces for:
  - marked text update;
  - committed insert;
  - unmark/cancel;
  - native range resolution;
  - invalid or stale range rejection;
  - delayed callback after focus generation change;
  - caret, first rect, and selection rect coordinate conventions;
  - secure field redaction.
- Cross-target compile gates so non-iOS hosts do not require UIKit.
- `docs/implementation/seq06-4f-ios-uitextinput-adapter.md`.

## Acceptance Criteria

- SDK/header evidence answers the iOS range-resolution, stale-range,
  callback-ordering, and coordinate-convention questions.
- iOS activation uses typed capability facts and diagnostics.
- Native ViewKit metadata remains adapter-local or fixture-local only.
- All normalized text operations carry canonical byte ranges only.
- Invalid or stale native ranges reject without silent clamp.
- One callback or proven native atomic callback group maps to one Arcweft serial.
- Geometry revisions are separate from input serials.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, selected-range-derived anchor, or native object
  identity.
- If a new iOS adapter boundary is introduced, its crate/layer ownership is
  documented and structurally audited.

## Tests To Specify And Run

- Focused iOS adapter tests for native range resolution, marked text, commit,
  unmark/cancel, callback grouping, geometry, focus generation, and secure
  redaction.
- Non-iOS compile/source-gate tests proving iOS code is correctly gated.
- Shared presentation/runtime-host tests that the iOS adapter relies on, if not
  already present in main.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- iOS target or simulator validation where available.
- `cargo clippy` for changed Rust crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not put UIKit objects, Objective-C/Swift object identity,
  `UITextPosition`, or `UITextRange` in Sans I/O payloads.
- Do not use private APIs.
- Do not store source units in normalized operations or geometry snapshots.
- Do not upgrade HostDependent capabilities by assumption.
- Do not fake iOS support through macOS, desktop, or Web adapter code.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Web, Windows, macOS, Wayland, or Android implementation.
- Full iOS app shell redesign beyond the narrow adapter boundary needed for
  text input.
- Replacing the seq06.3 common contract.
