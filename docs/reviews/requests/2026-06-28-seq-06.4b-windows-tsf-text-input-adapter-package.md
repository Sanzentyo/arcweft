# Request 06.4b: Windows TSF Text Input Adapter Package

## Sequence Position

This follows seq06.3 and the seq06.3.1 through seq06.3.4 common text-input
contract split. It is the Windows platform adapter package and should not
redesign the shared capability, range, batch/serial, or geometry substrate
unless current implementation evidence proves a concrete flaw.

This request can be run independently from the Web, macOS, Wayland, Android,
and iOS adapter requests. If it discovers a shared contract defect, isolate the
finding in a separate integration note and keep the Windows overlay narrowly
scoped.

## Request

Produce a final zip package that contains a concrete design, implementation
overlay, tests, fixtures, validation notes, and apply instructions for a Windows
Text Services Framework adapter for Arcweft text input.

## Required Inputs

- Current Arcweft `main`.
- `docs/reviews/requests/2026-06-27-seq-06.3-platform-ime-adapters-and-textfield-session-integration.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.1-text-input-capability-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.2-text-input-offset-range-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.3-text-input-batch-serial-contract.md`.
- `docs/reviews/requests/2026-06-28-seq-06.3.4-text-input-geometry-contract.md`.
- The seq06.3 integration review package constraints.
- Official Microsoft TSF documentation and current Windows SDK/header evidence
  for `ITextStoreACP`, edit sessions, reconversion, display attributes, and
  layout behavior.

## Platform Scope

Implement the Windows adapter inside the native desktop boundary, expected to
include `crates/arcweft-desktop-native` and, where protocol-only values are
needed, `crates/arcweft-desktop-contract`. If the current checkout has a
different Windows owner, document it in `SOURCE_INVENTORY.md`.

The adapter must:

- keep COM pointers, TSF edit cookies, context objects, thread managers, native
  serials, and function-provider handles adapter-local;
- resolve `ITextStoreACP` ACP/WCHAR ranges as UTF-16 source-unit ranges before
  emitting canonical byte ranges;
- map one completed read/write edit session or finalized TSF command callback
  to one Arcweft serial;
- treat reconversion as available only when runtime TSF function facts prove
  the relevant function is present;
- keep composition segment support HostDependent until display attributes are
  mapped to `TextCompositionSegmentKind` and covered by fixtures;
- consume Arcweft screen-space rectangles and convert them to TSF layout data in
  the adapter;
- represent clipped/no-layout/unavailable geometry with typed availability
  metadata;
- omit all character bounds for secure fields and report them as
  `SecureRedacted`, not plain platform unsupported.

## Required Decisions

1. The Windows crate/module ownership and `cfg(target_os = "windows")` gating.
2. COM apartment/threading assumptions and the safe adapter-local owner for TSF
   objects.
3. The `ITextStoreACP` text store model Arcweft exposes to TSF.
4. ACP/WCHAR to canonical byte range conversion, including surrogate pairs,
   invalid ACP ranges, stale snapshots, and explicit reject/no-clamp behavior.
5. The edit-session transaction boundary that creates one Arcweft serial.
6. The mapping of TSF composition, commit, delete, selection, reconversion, and
   display attributes into Arcweft operations and capabilities.
7. The geometry conversion from Arcweft screen rectangles into TSF layout
   responses, including clipped and no-layout states.
8. The secure-field policy for surrounding text, reconversion, display
   attributes, geometry, diagnostics, Agent observe, replay, and capture output.

## Required Implementation

The package must provide an implementation-ready overlay, not only prose. It
should include:

- Windows-only adapter modules and any feature/Cargo dependency edits needed for
  TSF bindings.
- Typed capability detection and activation diagnostics.
- TSF edit-session event conversion into `PlatformTextInputEvent`.
- Range conversion through shared text-index APIs.
- Geometry adapter code for TSF screen rectangles and availability states.
- Windows fixture traces for:
  - ACP range around a surrogate pair;
  - invalid ACP range diagnostic;
  - composition/preedit update and committed text;
  - read/write edit session grouping;
  - reconversion available and unavailable;
  - display-attribute to composition-segment mapping;
  - clipped/no-layout screen rect;
  - delayed event after focus generation change;
  - secure field redaction.
- Cross-platform compile gates so non-Windows hosts do not require Windows
  runtime objects.
- `docs/implementation/seq06-4b-windows-tsf-text-input-adapter.md`.

## Acceptance Criteria

- Windows activation uses typed capability facts and diagnostics.
- TSF native metadata remains adapter-local or fixture-local only.
- All normalized text operations carry canonical byte ranges only.
- Invalid ACP/WCHAR ranges reject without silent clamp.
- One TSF edit-session boundary maps to one Arcweft serial.
- Geometry revisions are separate from input serials.
- Secure fields expose no original text, original offset, original length,
  character-bound vector, selected-range-derived anchor, or TSF object identity.
- The package compiles on the intended target or documents exact target blockers.

## Tests To Specify And Run

- Focused Windows adapter tests for range conversion, edit-session grouping,
  composition, reconversion facts, display attributes, geometry, focus
  generation, and secure redaction.
- Non-Windows compile/source-gate tests proving Windows code is correctly gated.
- Shared presentation/runtime-host tests that the Windows adapter relies on, if
  not already present in main.
- `cargo fmt --all -- --check`.
- Focused `cargo check`/`cargo test` for changed crates.
- `cargo clippy` for changed crates when feasible.
- Structural audit when the overlay changes a crate boundary, feature, public
  contract, or creates a large module.

## Constraints

- Do not put COM pointers, edit cookies, or Windows object identity in Sans I/O
  payloads.
- Do not add local stringly helper conversions when an Arcweft-owned type can
  own the behavior.
- Do not store source units in normalized operations or geometry snapshots.
- Do not widen reconversion or composition-segment support without TSF evidence
  and fixtures.
- Do not redesign the common text-input contract without a separate,
  evidence-backed integration note.

## Non-Goals

- Web, macOS, Wayland, Android, or iOS implementation.
- Supporting non-TSF Windows text stacks unless the package proves they are
  required for the existing Arcweft host.
- Replacing the seq06.3 common contract.
