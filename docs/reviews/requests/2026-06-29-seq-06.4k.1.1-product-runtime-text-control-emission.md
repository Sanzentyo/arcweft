# Request seq06.4k.1.1: Product Runtime Text Control Emission Package

## Sequence Position

This request follows seq06.4k and seq06.4k.1.

seq06.4k converged native/web text input onto the normal player-owned windowed path. seq06.4k.1 added the renderer/player boundary: `RenderScene::text_inputs`, `RenderTextInputControl`, renderer-backed `PreparedFrame::focused_text_input_target()`, and player-owned live `TextEditorState`.

This request must not redesign those contracts unless current implementation evidence shows a concrete flaw.

## Problem

The normal story/player scene path still passes `text_inputs: Vec::new()`. That means native and web bridges now have a real shared target mechanism, but product/runtime UI controls do not yet feed it.

The missing work is to expose authored/runtime text controls as typed product/runtime data, lower them into `RenderTextInputControl`, and carry player-owned edited values into the next frame.

## Required Output

Produce a zip package with:

- concrete design markdown;
- Rust overlay or patches;
- tests and implementation documentation;
- implementation note;
- validation instructions and any known blocked platform validation.

The package must be independently applicable to the current `main` after seq06.4k.1.

## Required Design Decisions

1. Identify the authoritative product/runtime UI model that owns text-control declarations.
2. Define the typed runtime-facing shape needed to emit:
   - stable `InteractionTarget`;
   - `TextInputSessionId`;
   - current value;
   - current byte selection;
   - `TextInputOptions`;
   - `SemanticRole::TextField`, `TextArea`, or `SecureTextField`;
   - logical viewport bounds;
   - optional label.
3. Decide where session identity is allocated and how it remains stable across frames.
4. Decide how edited player-owned state is committed back to runtime/product state, or explicitly document if the current cut is frame-local only.
5. Specify how native and web scene builders apply `InputController::apply_live_text_control_state` before `SharedFramePlanner::prepare`.
6. Specify secure-field redaction expectations for Agent observation, capture metadata, replay, and visual text blocks.

## Implementation Requirements

- Do not add hidden DOM textarea/contenteditable fallback.
- Do not reintroduce sample-owned text-input sessions.
- Do not create platform-specific native/web text-control paths.
- Do not bypass `PreparedFrame::focused_text_input_target()`.
- Do not use JSON/stringly ad hoc text-control payloads when an Arcweft-owned typed model can be extended.
- Add behavior as inherent methods on Arcweft-owned enums or boundary types when dependency direction allows it.
- Keep lower-level data-format and core crates Sans I/O.

## Tests To Specify And Implement

- Product/runtime text-control declaration lowers into `RenderScene::text_inputs`.
- Focused text field produces a non-`None` `PreparedFrame::focused_text_input_target()`.
- Text input commit updates player-owned editor state and the next planned frame reflects the edited value.
- Selection/caret movement updates the next prepared geometry.
- Secure text field redacts platform snapshot text and character bounds.
- Native and web scene builders use the same lowering path.
- Implementation notes and code comments document that normal native/web scene
  builders use the shared lowering path and do not own separate platform
  geometry or hidden DOM text-entry fallbacks.

## Acceptance Criteria

- A normal Arcweft sample with an authored text field can be run through native and web player paths without a sample-specific IME binary.
- The same runtime text-control data feeds native and web.
- Platform IME activation is driven by `PreparedFrame::focused_text_input_target()`.
- The next frame reflects committed text edits through `InputController::apply_live_text_control_state` or a documented runtime write-back path.
- Focus, caret, selection, secure redaction, and geometry behavior are covered by automated tests where platform-independent.

## Non-Goals

- Do not redesign platform-specific TSF, AppKit, Wayland, Android, iOS, or EditContext adapters.
- Do not promote visual goldens or real IME traces unless required to prove this schema emission path.
- Do not remove legacy native window modules; that remains seq06.4k.2.
