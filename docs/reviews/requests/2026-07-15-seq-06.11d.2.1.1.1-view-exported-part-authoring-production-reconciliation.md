## Accepted substrate that must remain fixed

The correction must preserve all of the following unless the latest checkout
demonstrates a concrete, reproducible contradiction. A different implementation
preference is not defect evidence.

- Arcweft has one native typed Style path. There is no CSS, Takumi, raw
  stylesheet, `::part`, `exportparts`, browser shadow-DOM, or compatibility
  path.
- The sole authored export declaration is
  `export part <private-local-name> as <public-name>` in a leading declaration
  block inside the owning View body. It references an existing `.part(name)`
  static target and does not create the private identity.
- `.part(name)` is the sole private target spelling. The `part = name` named
  argument, string names, attached `.export_part(...)`, shorthand, and
  qualified cross-owner spellings are rejected through structured parser
  recovery and do not lower.
- Private local and public export names are distinct checked newtypes even when
  their text is equal. No implicit conversion, unowned string lookup, suffix
  matching, or source reparse may blur them.
- Local names are unique per owning View static target. Public names are unique
  per owning View. One local target has at most one public export. Equal public
  names in different Views are valid.
- One static target may produce zero, one, or many mounted occurrences through
  conditional control flow and keyed repeat. Occurrence identity remains
  runtime-private and is never a source or product public ID.
- A caller selector keeps the existing `.name` or `Element.name` spelling.
  Same-owner matching uses the private local namespace; one direct crossed View
  boundary uses only the callee public export table. There is no text-equal
  private fallback or structural traversal across the boundary.
- The first cut is direct-only. A `CallView` site may have a private local part
  but cannot be exported. There is no implicit or explicit re-export and no
  transitive capability.
- Product identities are owner-qualified and typed. Export declaration, local
  operand, and public operand provenance is mandatory. Canonical decode is
  Sans I/O, deterministic, bounded, and rejects tampering without consulting
  workspace source files.
- Runtime and trace evidence may identify the owner and public capability but
  must not expose a private local name, part ID, instruction ordinal, private
  ancestry, repeat path, or occurrence key as public identity.
- Local and public definition/reference/rename operations remain disjoint.
  Ambiguous reusable-sheet bindings fail atomically rather than producing a
  heuristic text rename.
- The surface and product are unreleased. Replace provisional types directly;
  add no aliases, legacy readers, dual parsers, deprecated fields, migration
  shims, wrapper APIs, or source gates.

## Required reconciliation decisions

Every item below must have one exact answer, Rust API sketch, owning crate and
module, visibility, error behavior, migration/deletion point, and direct test.
`TBD`, surviving alternatives, “as needed”, and implementation-selected policy
are not accepted.

### 1. Source identity from parsing through checked semantics

Choose one complete source-provenance path. Define the exact types and APIs by
which a parsed View export's source identity accompanies its byte ranges into
HIR, linked HIR, sema, compiler projection, diagnostics, and LSP indexes.

The answer must state whether source identity is stored in each
`HirViewPartOwner`/catalog record, supplied through a project-level checking
context, or represented by another single typed owner. Show constructors and
accessors, module-link rebasing, multi-file merge behavior, cached-module
behavior, and diagnostics for missing/stale source identity. A range without a
source identity is not sufficient, and sema must not depend on filesystem I/O.

### 2. Product source identity and SourceMap contract

Define the complete SourceMap-side model needed by exported-part provenance.
Freeze:

- the canonical typed product source identity and its relationship to
  `SourceName`, source labels, `PublicIdRef`, normalized content identity, and
  bundle section identity;
- the exact `SourceMapSection` and `SourceMapIndex` Rust shapes, constructors,
  accessors, Serde/wire behavior, canonical order, digest algorithm/domain,
  normalized UTF-8 extent, and exact-limit budgets;
- whether normalized source text remains encoded, becomes optional inspection
  data, or is replaced by metadata, and why decode/product validation does not
  require workspace files or unauthorized source bytes;
- how one or many project sources enter the section, how the compiler obtains
  the final `SourceRangeRef`, and how View-section public-ID tables can encode
  and remap those references deterministically;
- section-local validation versus complete-product cross-section validation,
  including which API invokes the latter before runtime mount;
- merge, patch, inspection export, source-only edit, unknown source, digest
  mismatch, extent mismatch, duplicate source, and budget behavior.

Do not hide a second source registry in CLI or runtime adapters.

### 3. Instruction target-kind and checked projection types

Define `ViewPartInstructionKind` or replace it with one other exact existing
type. List every variant and the total mapping among syntax target kinds, HIR
target kinds, checked target kinds, node-producing `ViewProgramInstruction`
variants, in-memory `ViewInstruction` variants, and runtime node facts.

Define the exact `CheckedViewInstructionPartIndex` API, owner/part rewrite map,
instruction index type, canonical ordering, static unreachable-target rule,
and typed invariant errors for missing, duplicate, wrong-owner, unsupported
`CallView`, overflow, and stale post-link targets. No layer may reconstruct
this map by searching encoded strings.

### 4. Fallible in-memory View-program construction

Freeze the final public APIs for `ViewProgram`, `ViewProgramBuilder`,
`ViewPartExport`, and the static local-part inventory. State exactly which of
`new`, `finish`, `with_exported_parts`, and `export_part` remain, which return
`Result`, and which are deleted or made private.

Define the error enum with typed fields and stable ownership; canonical-order
requirements; duplicate/unknown/`CallView` outcomes; overflow; builder
atomicity after failure; and whether validation occurs incrementally, at
finish, or both without conflicting authorities. The only public export API
must accept `ViewPartId` and `ViewPartName`; no string overload or unchecked
constructor survives.

### 5. Product-to-runtime model authority

Choose one authoritative path between `ViewProgramResource`, the in-memory
`ViewProgram`, and `BundleViewRuntime`. Specify whether runtime converts a
validated product into `ViewProgram`, continues to consume a typed resource
through one dedicated validated adapter, or uses another exact acyclic model.

Give the complete `TryFrom`/loader/context API, error owner, validation
preconditions, lifetime/ownership, storage, and deletion of duplicate lookup
tables. Explain which layer allocates compact part IDs, constructs local/public
facts, and is authoritative when sema, compiler, codec, and runtime defensive
checks disagree. Invalid products must fail before any mount or partial runtime
mutation.

### 6. Owner identity and `ViewDefinitionRef -> ViewId`

Define the exact relationship among `CheckedViewId`, `ViewDefinitionRef`,
`ViewId`, `ViewProgramId`, definition index, and mounted View identity. If
boundary capability or trace evidence retains `ViewId`, define its canonical
allocation, checked conversion, order independence, merge behavior, reload
stability, serialization policy, and failure/overflow cases. If another
canonical owner type is selected, update every runtime/boundary/trace sketch
and justify the dependency direction.

No owner identity may be recovered from a suffix, instruction ordinal,
container position, import alias, or incidental vector order. A reload must
state when an owner ID is retained or replaced and how stale indexes are
removed.

### 7. Mounted occurrence and boundary capability construction

Close the runtime construction path from one validated static local target and
export table to zero, one, or many mounted facts. Define the private occurrence
key owner, its exact inputs, repeat-key and conditional behavior, collisions,
limits, and removal.

Freeze the final typed boundary capability and internal trace seam so a local
application, opaque nested location, inherited root, and explicit exported
part cannot be represented inconsistently. Define construction errors and
state how the resolver receives a local name versus public name without an
implicit conversion or runtime string lookup. Preserve d.5.1.1 ownership of
portable query/paging/redaction transport.

### 8. Program revisions, fingerprints, and replacement transaction

Define exact owned types and derivation inputs for the local-part inventory
fingerprint, public export-interface fingerprint, accepted program revision,
mounted generation, and any cache dependency key. State which crate owns each
type, whether it is serialized, how equality works, and what happens on
counter/digest failure or revision overflow.

Specify one public or crate-owned accepted-program replacement API and its
caller. Define prepare/validate/commit/rollback phases, thread/event ordering,
mount iteration, multiple mounts, branch/repeat reconciliation, old fact and
trace/cache removal, new fact publication, frame revision, and error
propagation. Parser, sema, compiler, codec, or runtime-conversion failure must
leave the prior accepted program and every live mount unchanged. A completed
frame must never mix old and new public export tables.

### 9. Targeted invalidation and source-only edits

Define the dependency graph from owner-local inventory and export interface to
direct call edges, contextual Style bindings, mounted occurrences, computed

Do not introduce a sema-to-bundle dependency or an adapter-owned duplicate

### 10. Formatter/LSP metadata ownership after source reconciliation

State how cached or linked documents preserve exact definitions, how stale

## Constraints and non-goals

- Preserve dependency direction: syntax -> HIR -> sema -> compiler/product
  assembly; `arcweft-view` owns canonical View/Style runtime data;
  `arcweft-bundle` owns Sans-I/O product codecs; runtime owns mounted facts;
  tooling/LSP consume typed source/check indexes.
- Keep `arcweft-core`, data formats, sema, compiler, and bundle codecs Sans I/O
  according to their current responsibilities. Source loading, paths, host
  clocks, threads, and transport remain in adapters.
- Do not solve missing identity with strings, suffixes, instruction order,
  extension traits, free-standing endpoint-conversion helpers, or copied
  registries.
- Do not redesign Style properties, values, cascade priority, tokens,
  rendering, View evaluation, d.4.2 environment semantics, d.4.3 container
  semantics, Character registration, RichText, proof concurrency, or public
  trace transport.
- Do not add CSS/browser spelling, compatibility readers, aliases, deprecated
  fields, wrapper APIs, product probing, source reparsing, runtime export-table
  mutation, public occurrence IDs, or transitive re-export.
- Use `thiserror` for new Rust error types unless the corrected design records a
  concrete reason otherwise. Preserve typed owner, target, range, revision,
  and mutation-state fields.
- No new dependency may be proposed without an exact owner, current-version
  evidence, feature boundary, and necessity. Prefer existing primitives.
- Use direct behavioral, type, codec, tamper, compile, dependency, and runtime
  tests. Do not prescribe source gates.
