# Seq-05.2 Request: Typed REPL Commands And Agent Runner Session Integration Package

## Sequence Position

This follows seq05.1. It consumes the REPL overlay/session and cell transaction APIs defined there.

It can be designed while seq05.1 is underway, but implementation should wait for seq05.1's public transaction API or explicitly include an updated compatible seq05.1 API patch.

## Boundary Decision From Seq05.0

Seq05.2 owns user-visible command semantics and deterministic command evidence. It does **not** own transaction internals.

- `:undo` and `:reset` are seq05.2 commands, but their state mutations must call seq05.1 primitives.
- `:warm` and `:codegen` command variants/hooks are reserved in seq05.2, but concrete behavior belongs to seq05.3.
- Command dispatch should be typed and owner-driven, not a stringly CLI match table.

## Request

Design and implement typed user-visible Agent REPL command semantics and Agent runner/session integration on top of the seq05.1 REPL session model.

Return the final work as a zip package with design, Rust implementation overlay, tests, validation notes, and apply instructions.

## Required Decisions

1. Which module owns typed command parsing and dispatch. Expected location is `arcweft-agent-repl::command` unless seq05.1 selected a different owner.
2. How command input is separated from Arcweft source cell input.
3. Exact semantics for:
   - `:observe`;
   - `:step`;
   - `:tasks`;
   - `:cancel`;
   - `:load`;
   - `:reload`;
   - `:cells`;
   - `:undo`;
   - `:reset`;
   - `:capabilities`;
   - `:generations`.
4. Which commands are read-only and which can mutate session state.
5. How read-only trace mode prevents cell execution and mutating commands.
6. How `:undo` delegates to seq05.1 and reports exactly what overlay/binding/tier state was reverted.
7. How `:reset` delegates to seq05.1 and reports return-to-base evidence.
8. How command results expose deterministic evidence for tests and Agent clients.
9. How command errors are typed and stable.
10. Which typed command hooks must exist for seq05.3 `:warm` and `:codegen`.
11. How CLI and future MCP/LSP frontends adapt to the same typed command result model.

## Required Implementation

- Add typed REPL command parsing and dispatch.
- Integrate command execution with the accepted seq05.1 `ReplSession` API.
- Implement read-only trace mode.
- Implement command result/evidence types.
- Implement `:cells`, `:undo`, `:reset`, and generation/capability inspection through seq05.1 APIs.
- Implement `:observe`, `:step`, `:tasks`, and `:cancel` without duplicating runtime-driver or Agent session state ownership.
- Reserve typed command variants/hooks for `:warm` and `:codegen` without implementing concrete tiering behavior.
- Add deterministic tests for command parsing, command execution, command errors, read-only rejection, undo, reset, and trace mode.
- Add implementation documentation under `docs/implementation/`.

## Required Typed Command Surface

Seq05.2 should define typed commands equivalent to:

```rust
pub enum ReplCommand {
    Observe(ObserveCommand),
    Step(StepCommand),
    Tasks(TasksCommand),
    Cancel(CancelCommand),
    Load(LoadCommand),
    Reload(ReloadCommand),
    Cells(CellsCommand),
    Undo(UndoCommand),
    Reset(ResetCommand),
    Capabilities(CapabilitiesCommand),
    Generations(GenerationsCommand),
    Warm(WarmCommand),
    Codegen(CodegenCommand),
    Help(HelpCommand),
    Quit,
}
```

`WarmCommand` and `CodegenCommand` may initially return a typed `UnhandledExtension` or `TieringUnavailable` result until seq05.3 registers handlers.

Command results must be typed before formatting:

```rust
pub struct ReplCommandResult {
    pub command_id: ReplCommandId,
    pub status: ReplCommandStatus,
    pub evidence: ReplCommandEvidence,
    pub diagnostics: Vec<ReplCommandDiagnostic>,
}
```

## Hooks Required For Seq05.3

Seq05.2 must expose an extension point equivalent to:

```rust
pub trait ReplCommandHandler {
    fn handle(
        &mut self,
        context: &mut ReplCommandContext<'_>,
        command: ReplCommand,
    ) -> ReplCommandResult;
}

pub trait ReplBackgroundRequestSink {
    fn enqueue(&mut self, request: ReplBackgroundRequest) -> ReplBackgroundRequestId;
}
```

Seq05.3 should be able to implement `:warm` and `:codegen` by registering or composing a handler, not by editing a stringly command table.

## Acceptance Criteria

- REPL command parsing is typed and does not conflict with source cell parsing.
- Commands execute through the seq05.1 session API, not private state peeking.
- Read-only trace mode never executes cells or mutating commands.
- `:undo` and `:reset` have deterministic state effects and evidence.
- Agent observe/task/cancel commands reuse existing runtime/Agent boundaries.
- `:warm` and `:codegen` have typed extension hooks for seq05.3.
- Product players remain free of REPL dependencies.

## Non-Goals

- No JIT/AOT warming implementation except stable hooks for seq05.3.
- No persistent cache requirement.
- No product-player command surface.
- No live-patch ingress.
- No direct mutation of seq05.1 transaction internals from command handlers.
- No source-level tiering syntax.

## Parallelization Guidance

Design can run in parallel with seq05.1 if it treats seq05.1's API as provisional. Implementation should follow seq05.1. Seq05.3 may be designed in parallel once this request defines command hooks for `:warm` and `:codegen`.
