# Seq-05.2 Request: REPL Commands And Agent Runner Package

## Sequence Position

This follows seq05.1. It consumes the REPL overlay/session and cell transaction
APIs defined there.

It can be designed while seq05.1 is underway, but implementation should wait for
seq05.1's public transaction API or explicitly include an updated compatible
seq05.1 API patch.

## Request

Design and implement user-visible Agent REPL command semantics and Agent runner
integration on top of the seq05.1 REPL session model.

Return the final work as a zip package with design, Rust implementation overlay,
tests, validation notes, and apply instructions.

## Required Inputs

- Current Arcweft `main`.
- Seq05.1 package output or accepted public API.
- `docs/reviews/requests/2026-06-24-seq-05-agent-repl-runtime-tiers.md`.
- `crates/arcweft-agent-runner/src/runner.rs`.
- Current Agent observe/capture/query/action/resource surfaces.
- Current runtime-driver task/cancel/step semantics.

## Required Decisions

1. Which module parses and dispatches REPL commands.
2. How command input is separated from Arcweft source cell input.
3. Exact semantics for:
   - `:observe`;
   - `:step`;
   - `:tasks`;
   - `:cancel`;
   - `:load`;
   - `:reload`;
   - `:cells`;
   - `:undo`;
   - `:reset`;
   - `:capabilities`;
   - `:generations`.
4. Which commands are read-only and which can mutate session state.
5. How read-only trace mode prevents cell execution and mutating commands.
6. How `:undo` rolls back only the latest committed cell effects.
7. How `:reset` returns to the base project snapshot.
8. How command results expose deterministic evidence for tests and Agent
   clients.
9. How command errors are typed and stable.
10. Which command hooks must exist for seq05.3 `:warm` and `:codegen`.

## Required Implementation

- Add typed REPL command parsing and dispatch.
- Integrate command execution with Agent runner state.
- Implement read-only trace mode.
- Implement command result/evidence types.
- Implement `:cells`, `:undo`, `:reset`, and generation/capability inspection
  through seq05.1 APIs.
- Implement `:observe`, `:step`, `:tasks`, and `:cancel` without duplicating
  runtime-driver state ownership.
- Add deterministic tests for command parsing, command execution, command
  errors, read-only rejection, undo, reset, and trace mode.
- Add implementation documentation under `docs/implementation/`.

## Acceptance Criteria

- REPL command parsing is typed and does not conflict with source cell parsing.
- Commands execute through the seq05.1 session API, not private state peeking.
- Read-only trace mode never executes cells or mutating commands.
- `:undo` and `:reset` have deterministic state effects and evidence.
- Agent observe/task/cancel commands reuse existing runtime/Agent boundaries.
- Product players remain free of REPL dependencies.

## Non-Goals

- No JIT/AOT warming implementation except stable hooks for seq05.3.
- No persistent cache requirement.
- No product-player command surface.
- No live-patch ingress.

## Parallelization Guidance

Design can run in parallel with seq05.1 if it treats seq05.1's API as
provisional. Implementation should follow seq05.1. Seq05.3 may be designed in
parallel once this request defines command hooks for `:warm` and `:codegen`.
