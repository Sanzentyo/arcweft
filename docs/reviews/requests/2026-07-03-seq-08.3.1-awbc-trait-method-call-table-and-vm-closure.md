# Request: seq-08.3.1 AWBC Trait Method Call Table And VM Closure

## Sequence Position

This follows seq08.3. Do not redesign the trait catalog, associated type
substrate, standard `Iterator` / `IntoIterator`, or runtime-plan
`RuntimeTraitMethod` model unless current evidence proves a concrete flaw.

## Problem

Seq08.3 makes trait method witness dispatch executable in the Sans I/O runtime
engine, but AWBC still rejects witness-backed `for` lowering. The missing piece
is a typed AWBC representation and executable VM/product-step path for trait
method callables.

This must not be represented as stringly `trait.method.N` intrinsics.

## Required Design

Specify the final AWBC model for runtime trait methods:

- `AwbcTraitMethodId` and `AwbcTraitMethod` table ownership;
- receiver mode encoding for `self`, `&self`, and `&mut self`;
- callable signature and frame layout for trait method bodies;
- how trait method bodies share or differ from normal AWBC function bodies;
- `CallTraitMethod` instruction shape and verifier rules;
- VM/product-step behavior for owned and mutable receiver calls;
- how updated mutable receiver state is returned to witness-backed iterators;
- canonical codec ordering, budget accounting, and schema version impact;
- structured diagnostics for unsupported receiver/body forms.

## Required Implementation

- Add typed AWBC schema items for trait methods and call instructions.
- Encode/decode the new table and instruction canonically.
- Add structure verifier checks for trait method table references.
- Add code verifier checks for receiver, args, destination, and signature
  compatibility.
- Lower `RuntimePlan.trait_methods` into AWBC trait method entries.
- Lower `RuntimeExpr::TraitCall` to `CallTraitMethod`.
- Replace witness-backed AWBC `for` rejection with executable lowering when
  `RuntimeIteratorWitnessExecutable::TraitCalls` is available.
- Implement VM/product-step execution or an equivalent existing AWBC call-frame
  reuse path.
- Keep built-in range/seq/vector/array/slice iterator paths unchanged.

## Constraints

- Do not add compatibility shims or stringly intrinsic fallback.
- Do not make `arcweft-core` depend on syntax, HIR, sema, verifier, CLI, LSP,
  filesystem, network, or platform adapters.
- Keep AWBC deterministic and Sans I/O.
- If schema version must change, include migration and fixture regeneration
  requirements explicitly.

## Tests To Specify

- AWBC round-trip for a program containing trait method table entries.
- Verifier rejects out-of-range trait method ids and signature mismatches.
- VM/product-step executes a simple trait call returning `.Some(value)`.
- Witness-backed user-defined `IntoIterator` lowers and verifies as AWBC.
- Built-in range and vector loops still use their existing non-materialized
  paths.
