# Seq-02.7 Signing Policy Redesign

## Sequence Position

This request follows seq-02.5 patch v2 and should coordinate with seq-02.6 AWFR
release archive design. It owns the typed signing-policy model for product
bundles, patch artifacts, materialized targets, and release archives.

Do not finalize release trust behavior without checking the AWFR/external
payload carrier contract from seq-02.6.

## Why This Split Is Needed

Seq-02 first cut added signature-policy-aware patch decode/apply entrypoints
for patch artifacts, but it did not redesign the full product signing policy.
Product-grade patch materialization must make base signature invalidation,
target signature regeneration, release trust, local dev behavior, CI behavior,
and offline inspection explicit.

## Required Decisions

1. Define the typed signing policy model for local dev, CI, release publish,
   release consume, offline inspection, and test fixtures.
2. Define the signing digest transcript for AWFB bundles, patch v2 artifacts,
   materialized target bundles, and AWFR release archives.
3. Define how bundle kind, content root, artifact identity, manifest digest,
   whole-file digest, target root, key epoch, signer id, and release channel
   are bound.
4. Define base signature disposition when patch materialization changes target
   bytes: preserve for provenance only, strip, invalidate, or record as base
   evidence.
5. Define target signature regeneration rules and adapter boundaries for key
   access.
6. Define release trust validation for signed base, signed patch, materialized
   target, external payloads, and AWFR manifest.
7. Define error types and inspection states for unsigned, invalid, expired,
   wrong-key, wrong-channel, and metadata-only artifacts.
8. Define how runtime-driver, project-loader, CLI, and players consume signing
   results without duplicating policy logic.

## Implementation Order To Specify

1. Add typed signing policy and verification result data models.
2. Add deterministic digest transcript tests for AWFB, patch v2, and AWFR
   artifacts.
3. Wire patch materialization to mark base signatures invalid for changed
   target bytes and to request target signing through adapters.
4. Implement CLI/local-dev/CI/release policy modes.
5. Wire project-loader and player release verification through shared typed
   results.
6. Add offline inspection states that are explicit about missing keys or
   missing external payload bytes.
7. Update docs and source gates to prevent raw signature passthrough policy.

## Tests To Specify

- base signature is not reported valid after target bytes change;
- unchanged target preserves or records base signature exactly according to the
  policy decision;
- target signature regeneration validates with the selected key epoch;
- signed patch plus signed materialized target release policy succeeds;
- unsigned local-dev patch behavior is allowed only under local-dev policy;
- wrong key, wrong epoch, wrong channel, and expired signature diagnostics;
- external payload digest/signing interaction with AWFR release manifest;
- offline inspection states for missing keys/payloads;
- source gates against raw opaque signature passthrough in release paths.

## Constraints

- Keep signing-key access, clocks, secure storage, and platform trust stores in
  adapters.
- Keep data-format crates deterministic and Sans I/O.
- Treat signatures, policies, key epochs, channels, and verification results as
  typed data.
- Do not imply base signatures remain valid for changed target bytes.
- Do not weaken release verification to make local dev patching easier.

## Non-Goals

- Choosing a production key-management backend.
- Implementing remote signing services.
- Redesigning AWFR archive layout except for required signing transcript
  fields.
- Seq3 live-patch scheduling or runtime apply policy.

## Expected Output

Return a design or implementation package with:

- typed signing policy schema;
- digest transcript definitions;
- signature disposition state machine;
- crate and adapter ownership map;
- test matrix and CLI smoke commands;
- release/offline/local-dev policy examples.
