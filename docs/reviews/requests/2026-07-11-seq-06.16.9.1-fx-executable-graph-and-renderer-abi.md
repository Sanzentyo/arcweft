# Request: executable Fx graph and renderer ABI

## Position and reason for the split

This is sequence 06.16.9.1 and follows the 2026-07-11 replacement of provisional `decoration` syntax by
`#[fx] fn ... -> Fx`. The language, identity, graph, View application, and
RichText static expansion substrate already exists. This request must not
redesign that verified substrate unless implementation evidence demonstrates a
concrete flaw.

The remaining work is split because a correct solution needs one shared design
for bundle serialization, reactive parameter binding, typed sampler execution,
renderer capability negotiation, and external Rust/WASM implementations.
Choosing any one of those independently would create incompatible ABIs.

## Required decisions

- Define the canonical bundle section/inventory for `FxDefinition`, including
  `FxId`, `FxAbiHash`, `FxSemanticHash`, parameter schemas, graph nodes,
  resources, and required renderer interfaces.
- Define a typed, bounded, deterministic expression program for sampler
  closures. It must cover `FxSampleContext`, `Transform2D`, numeric intrinsics,
  captured Fx parameters, instruction/stack budgets, NaN policy, and exact unit
  representation without storing source strings as executable code.
- Define how View reactive sources bind to graph parameter slots without
  rebuilding graph structure every frame.
- Define native, Web, and headless evaluator contracts and how unsupported
  renderer interfaces produce structured diagnostics.
- Define external Rust/WASM declaration and registration records using the same
  `FxId` and ABI hash contract, including mismatch and duplicate-provider
  errors.
- Define save/load and observation records for retained Fx instance state,
  transitions, deterministic seeds, and nested graph child ordinals.
- Close the constructor property inventory for Style, Text, Color, Transform,
  Mask, Filter, Shader, Transition, Conditional, and Stack.

## Implementation order

1. Add the shared typed expression and renderer-interface model.
2. Serialize complete Fx definitions and verify codec budgets/tampering.
3. Connect View bindings and RichText instance identities to graph instances.
4. Implement the headless reference evaluator.
5. Connect native and Web renderers with capability diagnostics.
6. Add Rust/WASM provider registration and ABI mismatch checks.
7. Add save/load, observation, and deterministic replay evidence.

## Tests to specify

- deterministic graph and sampler round trips;
- malformed, oversized, cyclic, and tampered graph rejection;
- `sin(ctx.time * speed + ctx.ordinal_phase()) * amplitude` parity across the
  reference, native, and Web evaluators;
- reactive View values change samples without changing graph identity;
- same `FxId` with a different ABI hash is a build error;
- unsupported renderer interfaces remain visible and never alias a builtin by
  basename;
- stable keyed-repeat and RichText span instance identities across reorder and
  save/load;
- exact native/Web visual evidence for static, transform, mask, shader,
  transition, conditional, and stacked graphs.

## Expected output

A design update, typed codec/runtime APIs, renderer connections, tests, and an
implementation evidence note proving end-to-end execution. Source-text gates
are prohibited; verification must use typed codecs, public behavior, runtime
diagnostics, and rendered output.
