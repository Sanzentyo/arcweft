# Request: seq-06.11d.4.1.3 native logical scroll anchoring contract

Date: 2026-07-14

## Sequence position and reason for the split

This request follows the d.4.1 core and finalized physical box geometry. The
core maps `overflow-inline`/`overflow-block` to physical X/Y, but it does not
define a logical scroll-start API, negative-axis range representation, initial
offset, focus reveal, restoration, or behavior when axes change.

Those decisions are observable state and persistence contracts. They cannot be
inferred safely from overflow mapping alone. This request is independently
throwable and must not redesign the verified axis mapping or physical box
contract absent a concrete flaw.

## Fixed substrate

- Positive logical displacement is toward logical end.
- Horizontal RTL inline and Vertical RL block have negative physical
  displacement signs.
- Overflow is canonicalized to physical X/Y before scroll consumers.
- Current scroll state remains physical and gains no guessed logical-start API
  in d.4.1 core.

## Required decisions

1. Typed coordinate/range model for physical offsets and logical start/end,
   including negative-axis ranges and zero origin.
2. Initial position for each mode and explicit programmatic scroll APIs.
3. Wheel, touch, keyboard, controller, page, home/end, and accessibility action
   mapping between logical intent and physical deltas.
4. Focus/selection scroll-into-view and nested scroll-region arbitration.
5. Save/restore, remount, content resize, viewport resize, and clamping rules.
6. Axis-provider change behavior for current offsets and pending scroll motion.
7. Event/trace payloads, revision identity, budgets, and redaction.

## Implementation order to specify

1. Freeze normative range/offset diagrams for all four modes.
2. Define typed scroll coordinates, commands, snapshots, and errors.
3. Implement range construction and input-command mapping.
4. Integrate focus reveal, nested arbitration, save/restore, and resize.
5. Add axis-change behavior and native/headless/web parity evidence.

## Required tests

- Start/end/range/delta behavior for all modes, especially Horizontal RTL and
  Vertical RL negative axes.
- Empty, smaller-than-viewport, exact-fit, oversized, resized, and nested content.
- Wheel/touch/keyboard/controller/accessibility commands and focus reveal.
- Restore/clamp/remount/provider-change behavior and simultaneous content change.
- Exact-limit/budget/tamper tests and deterministic event ordering.
- Native/headless/web state and capture parity.

## Constraints and non-goals

- No CSS scroll semantics, browser-coordinate adapter, sign guessing in the
  player, or duplicate logical-axis table.
- Do not redesign physical layout, cascade, or provider propagation.
- Provider-revision transition disposition is specified separately.

## Expected output

Produce a standalone final contract containing exact Rust APIs and ownership,
four-mode diagrams, coordinate math, lifecycle/persistence/event behavior,
errors and budgets, implementation order, and a complete interaction/state/
parity test matrix.
