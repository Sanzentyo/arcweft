# Request: Typed Stream runtime and wire model

## Sequence position

This is Lang-01.3.1.2. It is a narrow implementation-contract completion
required before Lang-01.3.1 changes public core types, RuntimePlan, AWBC,
bundle, save, or host boundaries.

It follows the Lang-01.3.1 Source-elimination decision and can be designed in
parallel with Lang-01.3.1.1's author-surface reconciliation. It must consume
the final callable evidence selected by Lang-01.3.1.1 but must not choose
function syntax itself.

## Why this split is required

The returned Lang-01.3.1 package fixes high-level behavior but does not define
the concrete owned types and serialized shapes needed for its compile-clean
Cuts 3 through 5. In particular, it names but does not structurally define:

- static Stream definition identity;
- generation-aware runtime Stream instance identity;
- typed affine Stream handles;
- generator, external, and derived origin records;
- the exact `StreamPolicy` split and validation;
- external lifecycle events and terminal state;
- typed open/close Sans I/O requests;
- RuntimeStep ingress/egress changes;
- AWBC table records, runtime types, instructions/terminators, and tags;
- snapshot state, save blockers, schema version, and restore validation; and
- bundle/hot-swap fingerprints and generation pins.

Current `SourceId` conflates declaration identity with runtime state identity.
Current Stream state imports `SourceEventKind`; RuntimeStep exposes separate
source and stream event collections; AWBC serializes both tables and fiber
states. A mechanical rename would preserve the duplicate model and cannot
satisfy Lang-01.3.1.

## Required decisions

1. Define the exact newtypes and fields for immutable Stream definition
   identity and generation-aware runtime instance identity. Specify ordering,
   hashing, serialization, display, allocation, overflow, and stale-generation
   rejection.
2. Define the exact typed runtime Stream handle, including item/error runtime
   type identity, ownership/move behavior, drop cleanup, and snapshot layout.
3. Define one closed Stream origin enum with at least authored generator,
   external capability operation, and derived Stream variants. State which
   fields affect definition identity, runtime layout, provider ABI, cache
   invalidation, and hot-swap compatibility.
4. Define the final closed `StreamPolicy` and nested enums. Include
   backpressure, capacity, overflow, replay, privacy, permission, retention,
   terminal-error, restart, and provider-replacement behavior. State which
   values are authored/composed, profile-selected, or runtime-only.
5. Define policy validation and defaults without silently changing the
   existing verified behavior. Cover zero capacity, incompatible
   privacy/replay, unsupported blocking, redaction, queue retention at
   terminal state, and policy changes during hot swap.
6. Define the exact lifecycle state machine for create, open request, opened,
   progress/control observation, item, recoverable error, terminal error,
   disconnect, permission revocation, end, close request, close
   acknowledgement, cancel, restart, and provider replacement.
7. Decide the exact representation of progress/control notifications. They
   must not become ordinary `T` items or unstructured strings consumed by
   application Stream iteration.
8. Define the canonical inbound Stream host event enum and envelope. Include
   instance ID, generation, per-instance sequence, payload/runtime type
   evidence, and every rejection result. Unknown, closed, wrong-generation,
   duplicate, retrograde, and wrong-typed events must not mutate state.
9. Define exact typed Stream-open and Stream-close request structures. Include
   capability, operation, arguments, instance, generation, policy, reason, and
   idempotence/acknowledgement semantics without debug-string protocol IDs.
10. Define the exact `RuntimeStepInput`, runtime effects/output, statistics, and
    diagnostic changes that leave one Stream event/request boundary.
11. Define the exact Stream instance state, queue entry, terminal state,
    sequence cursor, last-error, overflow counters, provider state, and
    generation owner. Terminal transitions must preserve already-queued items.
12. Define deterministic normalization and scheduling rules across multiple
    definitions/instances/events, including the stable sort key and budget
    interaction.
13. Define the exact RuntimePlan Stream definition/origin representation and
    checked lowering evidence consumed from sema. No field may be recovered
    from source text or debug labels.
14. Define the sole AWBC Stream metadata table, typed runtime-handle type,
    instance/fiber state, open/wait/yield/fail/complete/close operations,
    resume-point contract, canonical string remapping, verifier budgets, and
    numeric tags.
15. Rebase the package's proposed ABI 2/codec 8 values against current main and
    allocate the next unused breaking values. Product code must have one
    reader/writer and reject the removed Source layout.
16. Define branch, match, and `for await` lowering so exactly one selected
    control path executes and iteration suspends/resumes in item order.
17. Define exact bundle fingerprints for Stream handle layout, item/error
    types, external capability/operation ABI, Stream state, and generator frame
    layout.
18. Define the save schema, external-live save blocker type and reporting,
    closed/generator snapshot rules, restore validation order, and atomic
    failure behavior. Do not invent a portable host resume token.
19. Define content-only, code-compatible, code-generational, and
    restart-required Stream hot-swap classifications plus generation pinning.
20. Provide a field-by-field and event-by-event deletion mapping for
    `SourcePlan`, `SourcePolicy`, `SourceRuntimeState`, `SourceEventKind`,
    runtime Source requests/events, AWBC Source records/opcodes/fiber state,
    bundle facts, and save fields.

## Implementation order

1. Freeze exact core identity, handle, origin, policy, event, request, and
   instance-state types with positive/negative deterministic tests.
2. Replace RuntimePlan Source ownership with the sole checked Stream
   definition/origin model.
3. Make the atomic AWBC ABI/codec cut, remove all Source tables/tags/fiber
   state, and fix branch/match/iteration lowering.
4. Replace RuntimeStep and native/web/Agent host boundaries atomically with
   typed Stream open/event/close structures.
5. Replace bundle, save, restore, and hot-swap facts and schemas with one
   reader/writer.
6. Remove the remaining Source runtime modules and direct tests only after
   every useful invariant has direct Stream-owned evidence.

## Tests to specify

- identity allocation, ordering, overflow, two calls to one definition, and
  wrong-generation rejection;
- typed handle move/use-after-move, duplicate consumer, drop/close
  idempotence, and terminal suppression;
- origin validation for generator, external, and derived variants;
- every policy default, invalid combination, capacity/overflow branch,
  replay/redaction/privacy boundary, permission transition, and queue counter;
- every lifecycle transition and every invalid transition with byte-for-byte
  state non-mutation;
- deterministic event normalization, duplicate/retrograde/wrong-type
  rejection, and cross-instance scheduling;
- exactly one `if` branch and `match` arm, ordered multi-item iteration, empty
  suspension, resume, and terminal queue drain;
- RuntimePlan and AWBC canonical round trips plus bounds, budget, type, resume,
  opcode, table, and removed-layout tampering;
- VM/product/compiled-region parity through the shared `FiberState`;
- generator safe-point save/restore, external-live typed blocker, closed
  external round trip, corrupt snapshot rejection, and atomic restore failure;
- content-only, compatible, generational, and restart-required hot swap with
  active old/new instances; and
- native/web/Agent host contract parity using the same serialized typed
  requests/events.

## Constraints

- Preserve `arcweft-source`, source documents, source anchors/ranges, and AWBC
  debug source maps.
- Keep core and every data-format crate Sans I/O; adapters perform provider
  acquisition.
- Do not retain Source-named compatibility types, serde aliases, dual event
  fields, dual tables, dual readers, deprecated tags, or a migration schema.
- Do not use source gates. Test observable behavior, typed public APIs,
  serialization, tampering, save rejection, and Cargo dependency structure.
- Extend behavior on the owning Arcweft types/enums and contexts. Do not add
  endpoint-named conversion helpers, extension traits, sidecar maps, or
  stringly wrappers.
- Do not redesign the existing deterministic scheduler, verifier budgets,
  accepted `FiberState` exchange, atomic hot-swap transaction, or callable
  catalog unless concrete production evidence identifies a defect.
- Do not introduce CSS or Takumi paths.

## Expected output

- one implementation-ready contract with `OPEN_QUESTIONS=0`;
- exact Rust-like owned type definitions and invariants;
- exact RuntimePlan, RuntimeStep, AWBC, bundle, save, and host wire shapes;
- exact numeric version/tag allocation against current main;
- a complete Source-to-Stream deletion/equivalence table;
- ordered compile-clean cuts; and
- a direct positive, negative, tampered-input, persistence, hot-swap, and
  cross-host test matrix.
