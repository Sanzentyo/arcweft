# Seq-06.5 Request: Selected Capture Resource Metadata Package

## Sequence Position

This follows the seq06 layout/capture contract applied in
`docs/implementation/seq-06-layout-capture-visual-goldens-2026-06-28.md`.

It should be designed after seq06's shared `arcweft-layout` capture metadata
types exist, and before exact visual golden fixture work depends on selected
object/layer capture resources.

## Problem

Seq06 added shared Sans I/O capture metadata types in `arcweft-layout`, but the
selected object/layer metadata is not yet wired into `arcweft-agent-protocol`
resources or the native/WebGPU adapter constructors. Current capture refs and
image resources can identify color/object-id/mask resources, but they do not
carry one typed protocol schema for:

- capture scope;
- crop bounds;
- mask metadata;
- composition policy;
- renderer kind;
- coordinate-space basis;
- source object/layer identity.

Without this cut, clients must infer selected capture meaning from resource URI
spelling, image kind, or adapter-specific JSON.

## Request

Produce a final zip package containing design, implementation overlay, tests,
fixtures, validation notes, and apply instructions for selected object/layer
capture resource metadata.

The package must connect `arcweft-layout::CaptureMetadata` to
`arcweft-agent-protocol` and native/WebGPU capture resource construction without
moving renderer/GPU/filesystem I/O into `arcweft-layout`.

## Required Inputs

- Current Arcweft `main`.
- `crates/arcweft-layout/src/lib.rs`.
- `crates/arcweft-agent-protocol/src/image.rs`.
- `crates/arcweft-agent-protocol/src/object.rs`.
- `crates/arcweft-agent-protocol/src/resource.rs`.
- `crates/arcweft-agent-protocol/src/observation.rs`.
- Native Agent capture/resource code under
  `crates/arcweft-cli/src/app/agent/native/`.
- Existing protocol tests in `crates/arcweft-agent-protocol/src/tests.rs`.
- Existing native capture tests under `crates/arcweft-cli/tests/check/`.
- `docs/implementation/seq-06-layout-capture-visual-goldens-2026-06-28.md`.

## Required Decisions

1. Which protocol type owns serialized selected capture metadata.
2. Whether metadata lives on `AgentImageResource`, capture refs, resource body
   JSON, or a dedicated sidecar resource, and why.
3. The exact serialized field names for scope, renderer, composition, crop,
   mask, coordinate spaces, and object/layer identity.
4. How `CaptureMetadata` from `arcweft-layout` maps into protocol types without
   introducing layout-to-protocol dependency cycles.
5. How viewport, object, rich-text proxy object, rich-text child element, and
   layer captures each populate metadata.
6. How native/WebGPU adapters represent unsupported metadata or unavailable
   masks.
7. How metadata remains deterministic across png/raw-rgba/object-id/mask
   resource kinds.
8. How resource privacy classification treats selected capture metadata.
9. How Agent observe, MCP resource listing, `resources/read`, and script/repl
   capture APIs expose the same metadata.

## Required Implementation

- Add typed selected capture metadata to `arcweft-agent-protocol`.
- Add conversion or builder APIs at the correct owner boundary; do not add
  stringly helper shims.
- Thread metadata through native Agent observe image resources and capture refs.
- Thread metadata through WebGPU/native capture adapter constructors where the
  current checkout has concrete constructors.
- Preserve lazy MCP capture rendering; listing capture refs must not render
  every selected capture image.
- Add protocol serialization tests for object and layer capture metadata.
- Add native Agent observe tests that read selected object/layer resources and
  assert metadata matches rendered/cropped geometry.
- Add source gates preventing adapter-local ad hoc metadata JSON from
  reappearing after the typed schema exists.
- Add implementation documentation under `docs/implementation/`.

## Acceptance Criteria

- Selected object and selected layer capture resources carry typed metadata.
- Metadata includes renderer, scope, composition, crop bounds, coordinate basis,
  and mask details when a mask is available.
- Object, rich-text proxy, rich-text child element, and layer captures report
  stable identity and crop information.
- Agent observe JSON, MCP resource reads, and script/repl capture APIs expose
  the same metadata shape.
- The metadata is generated by typed builders/conversions, not stringly
  resource-name parsing.
- `arcweft-layout` remains Sans I/O and does not depend on protocol, renderer,
  CLI, or MCP crates.
- Existing lazy capture resource behavior is preserved.

## Non-Goals

- Do not add exact visual golden image comparisons in this cut.
- Do not change the default Agent observe coordinate behavior from raw to fit
  mode.
- Do not move capture I/O into `arcweft-layout`.
- Do not redesign text-input capture metadata.

## Parallelization Guidance

should land before seq06.6 starts adding selected object/layer golden fixtures.
Seq06.6 may consume the metadata schema from this cut as a stable input.
