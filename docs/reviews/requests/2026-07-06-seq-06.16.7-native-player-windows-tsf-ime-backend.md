# Request: seq-06.16.7 native-player Windows TSF IME backend

## Sequence Position

This request follows seq06.16.3 native interactive smoke, the 2026-07-06 native
IME focus-loss fix, and the upstream comparison investigation request:

- `docs/reviews/requests/2026-07-06-seq-06.16.7.1-windows-ime-upstream-handling-investigation.md`

It must not redesign the existing player-rendered text-control editing,
selection, focus navigation, style, or write-back contracts unless current
evidence shows a concrete flaw.

## Why This Split Exists

The normal native player currently uses winit window IME as the single live text
source. That path is enough for preedit, commit, delete-surrounding, cursor
area, hint/purpose, and surrounding text, but current evidence has not yet
proven whether the duplicate white composition UI requires TSF, a smaller
winit/IMM adjustment, or an upstream fix. The seq06.16.7.1 investigation must
answer that before this implementation request is executed.

The repository already contains Windows TSF substrate and diagnostic samples in
`arcweft-desktop-native` / `arcweft-player-native`, but source gates explicitly
keep `WindowsTsfImeBridge` out of the normal scene loop. A production backend
selection contract is needed before replacing or augmenting `WinitWindowIme`.

## Required Decisions

- Define the backend-selection contract:
  - default backend on Windows;
  - fallback behavior when TSF initialization fails;
  - trace-safe backend identity;
  - interaction with `arcweft.toml`, runtime settings, and future in-game
    settings.
- Decide whether Windows TSF replaces winit IME entirely on Windows or acts as a
  layered backend that consumes only composition/candidate control while winit
  remains the window/event loop owner.
- Define how TSF focus, blur, document manager lifetime, and COM apartment
  lifetime map onto the native player window lifecycle.
- Define explicit composition UI policy:
  - Arcweft-rendered preedit only;
  - native candidate UI still positioned from Arcweft caret geometry;
  - no duplicate native white composition popup.
- Preserve privacy behavior for secure fields and redacted traces.
- Preserve existing text-control contracts: selection, caret geometry,
  shortcut policy, tab policy, multiline Enter, action-button submit, and focus
  navigation.

## Implementation Order

0. Complete seq06.16.7.1 and record the evidence-backed recommendation in the
   implementation note before choosing TSF over a smaller fix.
1. Add a typed native text-input backend selection payload and trace identity.
2. Add Windows-only TSF backend wiring behind a platform-specific adapter
   boundary; keep non-Windows builds on winit.
3. Move HWND/COM-specific code into the Windows adapter boundary and keep shared
   player-scene/presentation crates free of platform identities.
4. Route focus, blur, geometry updates, preedit, commit, delete-surrounding, and
   composition end through the selected backend.
5. Add fallback to `WinitWindowIme` when TSF is unavailable, with a structured
   trace record and diagnostic.
6. Update native interactive smoke tests and source gates to cover both the
   selected backend and the fallback boundary.
7. Add a real Windows IME manual/recorded evidence path for Japanese IME
   duplicate-composition suppression.

## Tests To Specify

- TSF backend selection appears in redacted trace metadata without leaking HWND
  or COM object identity.
- Secure field focus redacts text, surrounding text, and composition in traces.
- Focus loss during preedit clears composition state and does not freeze the
  player after focus return.
- Japanese IME preedit is rendered once by Arcweft and not duplicated by a
  native white composition popup.
- Candidate UI remains positioned near the Arcweft caret for single-line and
  multiline controls.
- Fallback to winit preserves existing behavior when TSF initialization fails.
- Shared crates still reject Windows platform identities in source gates.

## Constraints

- Do not put HWND, COM, TSF, AppKit, Android, Wayland, or web platform identity
  into shared presentation, scene, runtime-plan, or core crates.
- Do not make `arcweft-core` depend on platform, windowing, filesystem, or GPU
  APIs.
- Do not replace player-rendered text controls with native widgets.
- Do not hide candidate UI as a workaround for duplicate preedit; candidate
  selection must remain usable.
- Do not silently change Windows IME backend defaults without trace evidence and
  fallback diagnostics.

## Expected Output

Return a design package with the Windows TSF native-player backend contract,
backend-selection and fallback rules, platform boundary audit, source gates,
interactive smoke plan, and real Japanese IME evidence requirements.
