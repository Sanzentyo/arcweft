# Identity and mapping model

## 1. Canonical identifier grammar

Unless a row says otherwise, identifiers are exact UTF-8 strings, are not
trimmed or Unicode-normalized, and serialize as transparent JSON/TOML/string
values. Ordering and hashing use the exact validated bytes.

### Shared local grammar

`PUBLIC_LOCAL` is:

```text
first component: [A-Za-z_][A-Za-z0-9_-]*
later components: [A-Za-z0-9_][A-Za-z0-9_-]*
components separated by one '.'
no empty component
```

`LOWER_LOCAL` is:

```text
first component: [a-z][a-z0-9_-]*
later components: [a-z0-9][a-z0-9_-]*
components separated by one '.'
no empty component
```

Reserved compact roots for public TTS semantic IDs are `crate`, `self`,
`super`, `parent`, `character`, `speaker`, `device`, `bus`, and `provider`.

## 2. Exact nominal types

| Type | Owner / visibility | Canonical form and limit | Classification | Traits and redaction |
|---|---|---|---|---|
| `TtsSpeakerId` | `arcweft-audio-tts::identity`, public | `tts_speaker.` + `PUBLIC_LOCAL`; 1–256 bytes after full prefix; at most 256 scalars | Public semantic identity | `Clone, Eq, Ord, Hash, Serialize`; validated `Deserialize`; visible `Display/Debug` |
| `TtsVoiceProfileId` | same, public | `tts_voice_profile.` + `PUBLIC_LOCAL`; max 256 bytes/scalars | Public semantic resource identity | same as speaker |
| `TtsProviderId` | same, public to adapter/catalog APIs, not source-constructible | `tts_provider.` + `LOWER_LOCAL`; max 96 bytes and 96 scalars | Accepted artifact identity | `Clone, Eq, Ord, Hash, Serialize`; visible only in privileged adapter diagnostics |
| `TtsProviderBindingId` | same, catalog public API only | `tts_binding.` + `LOWER_LOCAL`; max 192 bytes/scalars | Accepted artifact identity | standard exact traits; privileged diagnostics only |
| `TtsProviderSpeakerKey` | `identity`, constructor public; raw accessor restricted to host integration | 1–256 UTF-8 bytes, at most 128 scalars; no NUL, control, CR/LF, leading/trailing whitespace; no normalization | Opaque provider-owned restricted value | `Clone, Eq, Ord, Hash, Serialize`; validated `Deserialize`; `Debug` is `<redacted-provider-speaker-key>`; no `Display`; raw access through `expose(ProviderKeyAccess)` |
| `TtsLocaleId` | `locale`, public | canonical BCP-47 subset; max 64 bytes/scalars | Public request/profile metadata | exact traits; visible |
| `TtsStyleId` | `identity`, public | `LOWER_LOCAL` without a family prefix; max 64 bytes/scalars | Public synthesis option identity | exact traits; visible |
| `SecretRef` | `arcweft-manifest-model`, restricted | `secret.` + `LOWER_LOCAL`; max 128 bytes/scalars | Secret locator, never credential value | exact traits; `Debug` redacts after `secret.`; no Agent/public facade export |
| `TtsRequestFingerprint` | `request`, public to runtime/host only | 32 bytes; text form 64 lowercase hex only in privileged traces | Deterministic request identity | `Copy, Eq, Ord, Hash`; redacted to first 12 hex chars in ordinary debug |
| `TtsAdapterCallId` | `protocol`, host-only | 16 opaque bytes, generated by host from task generation + sequence, not random semantic identity | Ephemeral adapter correlation | `Copy, Eq, Ord, Hash`; never serialized to save/source/Agent |
| `TtsProviderKeyDigest` | `identity`, restricted | BLAKE3 context digest of provider ID + key bytes | Restricted equality signal | 32 bytes; privileged traces only |

### Constructors and errors

```rust
impl TtsSpeakerId {
    pub fn try_new(value: impl Into<String>) -> Result<Self, TtsIdentityError>;
    pub fn as_str(&self) -> &str;
    pub fn as_public_id(&self) -> PublicId;
}

impl TtsVoiceProfileId { /* same method set and profile family */ }
impl TtsProviderId { /* try_new/as_str, lower grammar */ }
impl TtsProviderBindingId { /* try_new/as_str, lower grammar */ }
impl TtsProviderSpeakerKey {
    pub fn try_new(value: impl Into<String>) -> Result<Self, TtsProviderKeyError>;
}
```

`TtsIdentityError` variants are `Public`, `WrongFamily { expected, actual }`,
`TooLong { maximum_bytes, actual_bytes, maximum_scalars, actual_scalars }`,
`InvalidFirstComponent`, `InvalidComponent { index }`, and
`ReservedCompactRoot { root }`. `TtsProviderKeyError` variants are `Empty`,
`TooLong`, `ContainsControl { scalar_index }`, and `SurroundingWhitespace`.

Serde deserialization always calls the public constructor. There is no unchecked
serde path and no `From<String>` implementation.

## 3. Locale grammar

`TtsLocaleId` accepts the following canonical subset:

```text
language = 2*3 lowercase ASCII letters
script   = 4 ASCII letters, title case
region   = 2 uppercase ASCII letters / 3 ASCII digits
variant  = 5*8 lowercase ASCII alnum / DIGIT 3*7 lowercase ASCII alnum
locale   = language ["-" script] ["-" region] *("-" variant)
```

Extensions, private-use subtags, underscores, repeated variants, and
noncanonical case are rejected. This is nominally distinct from dialogue
locale. A higher integration may use an explicit fallible conversion only when
the exact canonical text is valid in both domains; there is no blanket `From`.

## 4. Profile records

```rust
pub struct TtsVoiceProfile {
    pub id: TtsVoiceProfileId,
    pub tts_speaker: TtsSpeakerId,
    pub locales: NonEmptyTtsLocales,       // 1..=16, ordered, unique
    pub default_style: Option<TtsStyleId>,
    pub rate_milli: TtsRateMilli,          // 500..=2000, default 1000
    pub pitch_cents: TtsPitchCents,        // -1200..=1200, default 0
}

pub struct CharacterTtsProfileBinding {
    pub character: CharacterId,
    pub profile: TtsVoiceProfileId,
    pub default_for_character: bool,
    pub selection_priority: u16,
}
```

A profile exists independently of a Character and independently of provider
deployment. A profile may have zero or one Character binding. One Character may
have one or more profiles. `TtsProfileCatalog` may publish with an empty provider
catalog so dialogue/presentation metadata remains valid without TTS. Provider
mapping completeness is required only for a launch topology that authorizes or
contains an executable `tts.synthesize` call; even then failure is a TTS
launch/call error and never invalidates dialogue View projection.

### Character binding invariants

For each Character:

1. profile IDs are unique;
2. priorities are unique;
3. if the Character has at least one profile, exactly one has
   `default_for_character = true`;
4. every referenced profile exists in the same accepted profile catalog;
5. no profile is bound to a second Character;
6. the profile's first locale is its default locale;
7. no display name, declaration name, alias, variable name, or Character ID text
   participates in TTS selection.

## 5. Provider records

```rust
pub struct TtsProviderCapabilities {
    pub locales: Vec<TtsLocaleId>,             // sorted unique, 1..=128
    pub styles: Vec<TtsStyleId>,               // sorted unique, 0..=64
    pub output_formats: Vec<AudioFormat>,       // canonical enum order, nonempty
    pub extension_options: Vec<TtsProviderOptionSchema>, // sorted unique, 0..=32
    pub rate_milli: InclusiveRangeU16,          // within 500..=2000
    pub pitch_cents: InclusiveRangeI16,         // within -1200..=1200
    pub max_text_bytes: u32,                    // 1..=65_536
    pub max_text_scalars: u32,                  // 1..=16_384
    pub max_concurrent_requests: u8,            // 1..=32
    pub progress: bool,
    pub cancellation: TtsCancellationCapability,
    pub idempotency: TtsIdempotencyCapability,
}

pub struct TtsProviderSpeakerBinding {
    pub id: TtsProviderBindingId,
    pub tts_speaker: TtsSpeakerId,
    pub provider: TtsProviderId,
    pub provider_key: TtsProviderSpeakerKey,
    pub locales: Vec<TtsLocaleId>,              // sorted unique, 1..=32
    pub styles: Vec<TtsStyleId>,                // sorted unique, 0..=32
    pub priority: u16,
}

pub struct TtsProviderOptionSchema {
    pub id: TtsOptionId,
    pub value_kind: TtsOptionValueKind,
    pub numeric_range: Option<InclusiveRangeI64>,
    pub string_values: Vec<Arc<str>>, // sorted unique; empty means any bounded string
}
```

Provider option schemas are closed and type-specific: numeric ranges are allowed
only for I64/U64/Milli, string finite enums only for String, and Bool has no
constraint payload. A provider candidate is eligible only when every requested
extension option exists and its value validates against that schema.

The accepted provider instance also retains module import ID, generated export,
raw metadata hash, metadata payload hash, ABI hash, artifact identity,
capability digest, public-config digest, and `SecretRef` without a credential
value.

### Duplicate and conflict rules

The accepted join rejects:

- duplicate provider ID;
- duplicate binding ID;
- duplicate provider/export pair;
- two bindings for the same speaker with the same priority;
- the same `(provider, provider_key)` bound to different logical speakers;
- repeated locale/style within a record;
- binding locale/style not advertised by the provider;
- profile default style unsupported by every eligible binding for each profile
  locale;
- manifest provider identity that differs from generated metadata identity;
- an artifact, package, export, ABI, protocol, or metadata digest mismatch.

A byte-for-byte repeated record is still a duplicate and is rejected; it is not
silently coalesced.

## 6. Source selectors

```rust
pub enum TtsProfileSelector {
    Profile(TtsVoiceProfileId),
    Character {
        character: CharacterId,
        profile: Option<TtsVoiceProfileId>,
    },
    Speaker(TtsSpeakerId),
}
```

The source APIs never carry `TtsProviderId` or `TtsProviderSpeakerKey`. Each
accepted profile registers its `tts_speaker` in the project TTS speaker index.
An `@tts_speaker.*` source value is valid only when that exact ID is registered
by at least one accepted profile; this is a typed catalog reference, not a new
top-level declaration family. Direct speaker calls therefore cannot name an
unaccepted free-form ID.

## 7. Deterministic profile selection

Given a `TtsSynthesisIntent`:

1. `Profile(id)`: require the profile. If an originating Character was supplied,
   require its explicit binding to that Character.
2. `Character { character, profile: Some(id) }`: require that exact profile and
   exact Character binding.
3. `Character { character, profile: None }` with no locale: select the one
   default Character profile.
4. `Character { character, profile: None }` with a locale: filter the
   Character's profiles by exact locale; select the lowest unique
   `selection_priority`; if no candidate, reject. The default marker does not
   override an explicitly requested unsupported locale.
5. `Speaker(id)`: use the speaker directly; locale is mandatory.
6. If locale is absent after profile selection, use the profile's first locale.
7. Apply explicit options over profile defaults. No locale language fallback,
   style fallback, or option clamping is permitted.

Missing and ambiguous selection are errors; they never pick a lexical first
candidate.

## 8. Deterministic provider selection

The inherent `TtsAcceptedCatalog::prepare_request` method takes exactly one
accepted catalog generation and one host-provided availability snapshot. It
then:

1. filters bindings by exact logical speaker;
2. filters by exact locale;
3. applies the explicit output format, or for each candidate chooses the first
   supported format in the fixed order WAV, FLAC, OGG_VORBIS, MP3, AAC_MP4;
4. filters by exact requested style and rate/pitch/chosen-format support;
5. filters by accepted artifact/ABI/protocol match;
6. filters by launch policy and manifest-authorized `tts.synthesize`;
7. filters providers marked unavailable in the snapshot;
8. orders by `(binding.priority, provider_id, binding_id)`;
9. selects the first candidate together with its chosen format.

Priority uniqueness per speaker means the provider/binding tie-breakers are a
canonical defense, not a normal ambiguity mechanism. If the unique minimum is
not available, the next available candidate may be selected before dispatch.
After selection, the task remains bound to that snapshot and provider. The host
adapter does not reselect against a newer live availability state; if the
selected provider becomes unavailable before external I/O starts, the task
fails `ProviderUnavailable`. After dispatch, retries use the same provider and
provider key; a provider failure never silently changes provider.

Selection evidence, catalog digest, availability snapshot generation, artifact
and ABI identities, and provider-key digest are sealed into the request. The
raw provider key is not part of public evidence.

The host supplies one immutable `TtsProviderAvailabilitySnapshot` before request
preparation. It contains `epoch: u64` and exactly one entry per accepted
provider, sorted by provider ID, with state `Available=0` or `Unavailable=1`; a
missing entry is invalid rather than implicitly unavailable. Its digest is
BLAKE3 context `arcweft-tts-availability-v1` over the canonical epoch and
entries. Availability reasons are host-private and do not participate in
selection identity or diagnostics beyond a sanitized class.

`TtsProviderKeyDigest` is BLAKE3 context
`arcweft-tts-provider-key-v1` over the canonical provider ID string followed by
the exact provider-key bytes. `TtsAdapterCallId` is the 16-byte concatenation of
accepted task generation `u64` little endian and host adapter call sequence
`u64` little endian. Neither value is public semantic identity.

## 9. Hot reload

- Dispatched requests pin the accepted generation and continue on its provider
  executor until completion, cancellation, or timeout.
- A queued request not yet submitted may migrate only when the selected binding
  ID, provider ID, provider-key digest, capability digest, artifact identity,
  ABI hash, public-config digest, and credential reference are all unchanged.
- Any other provider/profile change cancels the queued request with
  `TtsError::CatalogChanged`; it is never silently reselected.
- New requests use only the newly published complete generation.
- A rejected candidate publication leaves the prior accepted generation
  untouched through the existing atomic overlay rule.
- Dialogue presentation state is not invalidated or rewritten by any TTS reload.
