# Dynamic value execution

## Ordinary AWBC lowering

Each `CheckedViewValue` is submitted to the existing ordinary function lowering
with a generated owner `ViewValueSemanticId`. The result is one
`AwbcFunctionKind::Synthetic` function in the normal AWBC program. Its parameters
are exactly the canonical `ViewValueInputBinding`s; captures are not reconstructed
from runtime names. Pure programs use `ViewValueProgramRole::Pure`, direct await
uses `DirectAwait`, and event handlers use `Handler`.

The compiler does not create a View evaluator bytecode, an expression AST in the
bundle, or a fallback interpreter. The AWBC function and its required
`CrossSectionRef` are emitted in the same product transaction.

## Invocation contexts

- **Pure render:** may read parameters, locals, repeat item/index, and accepted
  environment bindings whose effects are valid for render. It may not suspend or
  perform handler effects.
- **Direct await:** may suspend only according to the accepted direct-suspension
  role. Runtime resumes through the existing AWBC continuation; View owns pending,
  ready, error, and denied instruction ranges, not a second future.
- **Handler:** receives an exact typed handler-input record and may execute the
  accepted action/effect set. It is never called during static proof or render.

Role mismatch is a product-validation error before runtime publication.

## Projection

Execution returns `RuntimeValue`. The instruction's `ViewValueProjection` then
validates and consumes it:

- Bool requires the exact Bool runtime type.
- StableKey accepts only the semantic key type and canonicalizes to
  `ViewStableKey`; String/debug hash fallback is forbidden.
- PlainText accepts only String or an accepted typed plain-text nominal
  projection.
- RichText accepts only the accepted RichText nominal/document projection.
- Fx requires the exact `FxRuntimeType` and constructs `FxRuntimeValue`; String,
  nominal, resource, and arbitrary numbers are not coerced.
- ResourceRef uses `ResourceRefValue::try_from_runtime_value` with the expected
  exact `ResourceTypeId` and runtime nominal layout.
- Length, LogicalRect, integer widths, and enum policies validate exact semantic
  type/contract before conversion.

Projection failure contains program ID, expected projection, actual
`RuntimeCheckedType`, instruction/node source, and value path. No default is
substituted.

## Text

Literal, localized, RichText document, display frame, and typed Dialogue sources
retain their current owners. All other computed text is `RuntimeProgram` with
PlainText or RichText projection. The following helpers/behaviors are forbidden and
deleted:

- `runtime_scalar_text`;
- `fx_scalar_text`;
- `format!("{value:?}")` or Display fallback;
- source path traversal;
- local lookup by serialized name.

## Resource nominal projection

The ordinary nominal layout for `ResourceRef<T>` is generated by type lowering.
`ResourceRefRuntimeLayout` records the exact nominal owner/layout and typed field
coordinates. `ResourceRefValue`'s inherent methods encode/decode against that
layout. The runtime projector additionally compares the resulting triple against
the validated `ViewResolvedResourceRef` table and the active registry digest.

This uses the sole `RuntimeValue` model while preserving `ResourceRefValue` as the
resource identity owner. No core dependency on `arcweft-resource-model`, no copied
resource enum, and no source-string lookup is introduced.

## Atomic evaluation

A frame evaluates into a scratch `ViewFrameTransaction` containing candidate
bindings, mount mutations, text, image/resource leases, input changes, handler
registrations, semantic targets, Fx applications, and diagnostics. Programs are
evaluated and projected in deterministic instruction order. Any program,
projection, budget, resource, handler, or generation failure discards the complete
candidate. Only a fully validated transaction mutates retained mount state and
publishes a frame.
