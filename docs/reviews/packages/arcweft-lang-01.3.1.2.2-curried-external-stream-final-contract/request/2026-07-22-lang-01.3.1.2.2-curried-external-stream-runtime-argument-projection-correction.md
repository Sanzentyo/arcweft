# Lang-01.3.1.2.2 — curried external Stream runtime argument projection correction

## Sequence position

This is Lang-01.3.1.2.2. It follows the returned Lang-01.3.1.2.1 typed Stream
runtime/wire contract and must be resolved before implementing its RuntimePlan,
AWBC ABI 2 / codec 8, host-open, bundle, or save-schema-2 cuts.

This request is intentionally narrow. It consumes the final shared callable
resolver from AW-AH-009.3.3.1 and Lang-01.3.1.1, plus the Stream lifecycle and
single-owner decisions from Lang-01.3.1.2.1. It must not redesign those
implemented and verified substrates unless current production evidence shows
a concrete defect.

## Why this correction is required

The shared callable resolver identifies a parameter by both group and position:

```rust
CallableParameterCoordinate {
    group: CallableGroupIndex,
    parameter: CallableParameterIndex,
}
```

The returned Stream runtime contract instead projects one flat parameter
vector and states that only the final selected group is projected. For a
curried external operation, values supplied to earlier groups therefore have
no typed carrier into `RuntimeStreamRequest::Open`. Partial application cannot
open the external Stream, while final application must not lose, reorder, or
re-resolve the captured earlier-group values. Implementing the returned shape
would silently drop arguments at the compiler/runtime/host boundary.

## Required decisions

1. Define the exact group-aware runtime parameter and argument identity.
   Preserve group boundaries and the shared resolver's parameter coordinates;
   do not flatten by source text or rebuild a second resolver.
2. Define partial-application state for an external Stream callable.
   - Non-final group application evaluates and captures its arguments exactly
     once and emits no open request.
   - The capture has one typed owner and participates in function-value,
     snapshot, generation, and affine-value rules.
3. Define final application.
   - Join earlier-group captures and current-group arguments into one checked,
     canonically ordered product.
   - Reject missing, duplicate, stale, foreign-declaration, or out-of-order
     coordinates before any host request or runtime mutation.
4. Define the exact RuntimePlan and AWBC carriers.
   - The public callable signature, partial function value, `OpenStream`
     instruction/request, verifier, and host JSON must preserve the same group
     identity.
   - State whether the wire is nested by group or uses a canonical coordinate
     table plus value vector, including all tags and bounds.
5. Define effect and evaluation timing. Earlier groups contribute argument
   evaluation effects when applied; the external open effect occurs only on
   final application. Resume/restore must never replay earlier evaluation.
6. Define canonical hashing/fingerprints and hot-reload compatibility for
   group shape, passing mode, presence/default, type, and captured values.
7. If the selected resolution is to forbid currying on external Stream
   operations, explicitly reconcile and supersede the existing
   Lang-01.3.1.1 currying requirement and provide a typed declaration error.
   Do not let implementation infer this policy.

## Required implementation order

1. Freeze the group-aware checked signature and captured-argument product.
2. Project the accepted shared-resolver result into RuntimePlan without a
   second lookup path.
3. Implement non-final partial application and final checked product assembly.
4. Include the final model in the single Lang-01.3.1.2.1 Stream ABI 2 /
   codec 8 migration; do not create a provisional opcode or reader.
5. Carry the same product through native, Web, Agent, save/restore, and
   hot-reload boundaries.
6. Delete any flat final-group-only projection before the cut is reviewable.

## Tests to specify

- two- and three-group external Stream operations with positional-only,
  positional-or-named, named-only, defaulted, and rest parameters supported by
  the selected shared resolver;
- partial application emits no open request and evaluates each supplied value
  exactly once in source order;
- final application emits exactly one open request containing every group and
  parameter in canonical coordinate order;
- equivalent direct and staged applications produce the same checked request;
- missing group, duplicate coordinate, reordered group, wrong declaration,
  stale generation, wrong type, and malformed rest products fail atomically;
- suspension between groups and snapshot/restore preserve captures without
  replaying evaluation or opening early;
- AWBC encode/decode/re-encode parity and verifier rejection for tampered group
  metadata or value vectors;
- native/Web/Agent host JSON parity, including strict duplicate/unknown-field
  rejection and the existing decimal-string integer policy;
- hot reload accepts an identical group layout and treats group/parameter
  layout changes according to the existing generational compatibility policy.

## Constraints

- Preserve the existing shared callable declaration identity, group-aware
  resolver, accepted-HIR lifecycle, query budgets, and external binding path.
- Preserve ordinary `fn -> Stream<T, E>` and do not restore `stream fn`,
  `source`, or a role attribute.
- Do not add a flat compatibility projection, dual reader/writer, migration
  shim, endpoint DTO, source-text recovery, hard-coded function-name rule,
  source gate, CSS path, or Takumi path.
- Keep syntax, HIR, sema, RuntimePlan, verifier, core, bundle/save, and host
  dependency directions intact and keep data/core crates Sans I/O.

## Expected output

Return an independently usable final-contract package with `OPEN_QUESTIONS=0`
containing exact Rust-shaped types and owners, wire tags and canonical order,
evaluation/effect/snapshot rules, a delta against Lang-01.3.1.2.1, an ordered
implementation plan, and a complete positive/negative/tamper test matrix.
